# L5 Lowering

L5 turns an L4 prepared package into target-neutral Psi machine bodies and the declarations those bodies use. L4 supplies the selected declaration, operand occurrences, frozen constants and closed signature types. L5 assigns identities to machines, types, blocks, operations, values, places and edges. The lowered-form checker owns the verdict about the resulting program. [Psi product](../../../wiki/spec/terminal-psi/product.md) · [Control flow](../../../wiki/spec/terminal-psi/control_flow.md)

Consumers import `omega-psi` to inspect the owned package. Preparation and Psi replay use the same selected-target contract with their respective subject types. Replay reads a receiver built from independent target selections and compares each saved observation, including the selected plan. The consumer fixture builds against Psi alone. [Product manifest](../../representations/psi/Cargo.toml) · [Target contract](../../contracts/target/src/lib.rs) · [Consumer manifest](tests/psi-consumer/Cargo.toml)

A wholly anonymous numeric comparison supplies one prepared Boolean. A machine body emits a Boolean constant, and a clause retains a Boolean predicate step even when it is false. [Lowering and clause reader tests](tests/ieee_predicates.rs)

## First handoff

The initial implementation lowers single-block machines with a unit return, a scalar constant or parameter return, or a fixed array returned by value from a parameter. The type table records the exact signedness and width of each integer and the element type and count at each array dimension. An absent result has no carrier. Machine declarations retain their source identities and effective contract ceilings. A machine’s public flag comes from its resolved export status. A nested helper stays private even when written with a public modifier. [Machine visibility test](tests/calls.rs) Typing supplies the published defaults. An omitted public crash clause and an explicit empty crash clause therefore produce the same ceiling. Numeric and Boolean constants define scalar values in the entry block. Recursive arrays of the supported scalars permit copying. Nothing in these types requires a target layout to lower. [Type table](../../representations/psi/src/types.rs) · [Entry blocks](src/machines/body.rs)

A quoted literal in an owned byte-array result uses the bytes published by typing. Direct and named literals establish the same byte values in the same order, including for an empty array. [Byte-array results](tests/array_values.rs)

An explicit discard of a supported copyable value preserves the operations that produce it, including their call requirements. The caller continues after those operations. [Discarded calls](tests/calls.rs)

An indexed store uses the original mutable array place. Each selected core mutable-element access supplies its selector and its own bound. Psi retains them at that dimension, including when the destination is a scalar field inside an affine element. The destination is evaluated before the replacement. A dynamic bound that cannot be established before a call on the right-hand side stops lowering. [Indexed store handoffs](tests/indexed_stores.rs)

Reading a scalar field such as `cells[i].value` in an affine fixed array keeps the array in its original storage. The operation carries the shared element selection's selector and bound, then reads the selected field. An array constructed in a local binding supplies its own type row and retains its remaining cleanup obligations. [Indexed field reads](tests/indexed_field_reads.rs) and [owned array cleanup](tests/owned_arrays.rs)

A return carries the identity of its scalar value or structural source place. Two parameters of the same fixed-array type still have different places. For example, changing the body of `choose(a, b)` from `a` to `b` changes the source place on the return edge. Changing a static width instead changes the corresponding shape in the type table. The consumer can make both observations after the prepared trees and source text are dropped. [Handoff tests](tests/handoff.rs)

`omega source lower <package-relative files>` runs preparation and lowering and reports the first refusal with a source location. The Rust API returns the owned package. Its IDs are scoped to the produced package or machine. Artifact encoding, publication and execution are later consumers. [Source command](../../application/src/source.rs) · [Encoding](../../../source-rust/subsystems/compiler/psi/artifact/wire/encoding.md)

A bodyless trait requirement publishes its synchronous entry ceiling. Each `invokes` occurrence names its applied entry, runtime parameter or static binder and retains its source span. Omission gives a bodyless requirement an empty ceiling. A closed machine publishes its own written clauses alongside the entry set typing propagated through its calls. Service reach and pause effects retain their separate meanings. [Entry handoff tests](tests/requirement_interfaces.rs) · [Synchronous entries](../../../wiki/spec/language/effects.md)

## Operations and declarations

A local without an initializer takes its type from L4's `ZeroValue` obligation at the binding. An unqualified primitive receives a typed zero constant. Taking its address establishes one storage home shared by subsequent borrows, assignments and reads. A structural local uses the same zero construction as an omitted field: nested records retain their declared fields, and only the first case of a sum supplies a payload. A zero-initialized scalar-leaf record local retains its existing whole-record establishment and any selected scope cleanup. The establishment operation names its storage at the binding site. Discarding that local at return identifies the same storage. A `requires` clause on the record does not stop the local: the schema keeps the clause, and the checker judges the binding's `ZeroValue` obligation by evaluating that clause with every field zero, so `Nonzero` and `Small` lower alike. When L4 supplies a `ZeroField` obligation for an omitted field, the constructor puts the zero of that field's declared type in its declared slot. Written initializers still execute in source order, and every zero is established after them at the literal's site. A Boolean, fixed-width integer or float field receives a zero constant of its carrier; a float's zero is the all-zero bits of its format. A record or fixed array whose every leaf is a scalar receives one `EstablishZeroedStructural` whose result names the whole type, so its extent never sizes the output: `bytes:[u8;65536]` and a `[Cell;4294967296]` of scalar-leaf records each take one operation. This compact form applies when the complete record has the supported scalar-leaf representation. Any other structural field is built from the operations its own all-omitted literal would use: a record is `EstablishRecord` over the zeros of its fields, a sum is `EstablishCase` of its first declared case over the zeros of that payload, and a fixed array establishes one zero per element. [Operation 94](../../../source-rust/subsystems/compiler/psi/artifact/wire/encoding.md#operation-rows) lists records and fixed arrays, not sums, so a sum is never zeroed whole. For example, with `data Slot{case Empty; case Entry(value:u8);}`, an omitted `[Slot;2]` field is one `EstablishStructuralArray` over two separate `EstablishCase` places for `Slot::Empty`, and `Entry` is never established. `..` supplies no borrowed reference and no callable. An omitted field whose type borrows one referent, such as `@u8`, therefore makes the literal invalid, and so does a structural field whose zero would hold one in a record field, an array element or the first case's payload; lowering rejects both at the literal and names the field that needs the borrow. A reference in a case other than the first does not stop the sum's zero. Lowering stops, without calling the program invalid, where it has no operation for the zero: a domain-qualified value, an empty borrowed view or by-value sequence, a linear record, and a record with authored cleanup. No source extent stops a zero. An element-by-element zero counts its operations with checked arithmetic and reserves their storage before emitting any; lowering refuses it only when that count does not fit the host's address space or the host cannot allocate it. [Explicit field omission](../../../wiki/spec/language/data_and_literals.md#explicit-field-omission) [Omitted field handoff](tests/formation_handoff.rs) [Omitted structural fields](tests/omitted_structural_fields.rs) [Zero-value handoff](tests/obligation_outputs.rs)

An executable record or case constructor owes every `requires` clause of its structural result's nominal data schema. At that operation, `self` is the value formed by the selected case (if any) and the complete, declaration-ordered field operands, including any zero supplied for an omitted field. A zero operand does not discharge a clause about that field. The record or case established for an omitted structural field is such a constructor too: it owes its own schema's clauses over its zero operands, so an omitted `holder:Holder` under `data Holder requires self.n<=2 {slot:Slot; n:u64;}` owes that bound with `n` bound to the zero constant. A record zeroed whole by `EstablishZeroedStructural` owes the same clauses, and those of every schema inside it, for the all-zero value. L6 checks the clauses under this substitution; an `EstablishRecord` or `EstablishCase` operation in unchecked Psi is not a validity verdict. This handoff does not establish frozen constants or admit omitted reference fields without backing storage. [Formation inputs and Psi](tests/formation_handoff.rs) · [Record construction](tests/nominal_construction.rs)

An IEEE comparison in a requirement, guarantee, crash guard or domain predicate is a typed proposition, not an executable operation. It consumes its two terms and names the format and one canonical kind: `Equal`, `NotEqual`, `LessThan` or `LessOrEqual`. `a > b` and `a >= b` read their operands in reverse, so they state the same proposition as `b < a` and `b <= a`; `!=` keeps `NotEqual`, and `!(a < b)` stays a Boolean negation of `LessThan`. A qualified float formal retains its exact domain in the signature. Explicit domain removal presents its unchanged float carrier to the comparison. A term may also be an unqualified float formal, `result`, `self`, a float field of a record subject, a frozen float constant, or the exact bits that preparation landed for a literal or anonymous number. Integer order laws and mathematical or `FloatMeaning` equality do not apply to these propositions. A user-selected operator remains a call, which a contract predicate refuses, and never becomes an IEEE comparison. The checker judges each proposition; lowering keeps a false premise or a broken guarantee exactly as written. A compiler caller can supply its selected target’s instruction catalog when resolving a package. Typing selects an executable instruction variant and preparation preserves that selection. A machine with only region binders retains their ordinals separately from runtime specialization. For direct scalar or nominal references, each binder lists its annotated parameter slots and whether it annotates the result. A region can also sit inside a record or sum that this package lowers and whose binders are all lifetimes. With `data Schema<'t> { storage: @'t [u8]; }`, `forward<'t>(schema: Schema<'t>) -> Schema<'t>` has one body for every `'t`. Its region lists the pair of parameter 0 and data binder 0, and data binder 0 of the result. `Schema` keeps one type row whatever region is applied, and its stored view names the binder it lives at. The body returns the formal the source names, so `pick<'a, 'b>(left: Schema<'a>, right: Schema<'b>) -> Schema<'b>` publishes the result under `'b` only and returns `right`. Typing refuses a body that returns `left` there. A record that passes its lifetime on is concrete data too. In `data Plan<'t> { schema: Schema<'t>; slots: [Slot<'t>; 2]; count: u64; }` each field that stores a record lists, for every lifetime binder of that record, the binder of `Plan` that fills it. The element of a fixed array counts as stored. `swapped: Span<'y, 'x>` in a record over `'x, 'y` lists binders 1 and 0, and `twice: Span<'x, 'x>` lists binder 0 twice. The field's row is the stored record's one row, so this list is the only record of the arguments. The element of an owned sequence counts as stored too, so `routes: [CallableInfo<'t>]` lists binder 0. A field can also store one shared reference to such a record. In `data Schema<'t> { storage: @'t Bytes<'t>; }` the field's row is the reference to the one row of `Bytes`. Beside it the field keeps two separate facts: `lifetime` is binder 0 of `Schema`, where the reference is held, and the list fills binder 0 of `Bytes` from binder 0 of `Schema`. `first: @'r Bytes<'v>` in a record over `'r, 'v` has `lifetime` 0 and lists binder 1. `forward<'t>(schema: Schema<'t>) -> Schema<'t>` then has one body, which runs no operation and returns its formal: the stored reference travels inside the record and nothing crosses it. The row states the declared type of the record referred to. It gives a body no claim on a borrow held behind the reference. A body that does read through it, as `$schema.storage` does, is lowered as that read: a copy whose path is the stored field and then `Referent`. Lowering does not judge the read, and L6's constructor judgment refuses a constructor that makes it. A record with a field that names a binder in any other form stays a data template: a record behind an exclusive reference, a second reference or an array of references, or a record of the toolchain or a dependency. L3 rejects a stored reference that omits its own lifetime, including `storage: @Bytes<'t>`. The argument `'t` belongs to the referent.
