# Error correcting telemetry (NEW084)

A complete bounded console application for a declared synthetic RS(4,2) code
on F5. Two ordinal telemetry fields (`intercept`, `slope`, each 0..4) are encoded
as evaluations of intercept + slope*x at x=0,1,2,3. These are synthetic records,
not a real sensor calibration or a production transport. No numerical libraries
or worker code are required. Private field operations and exhaustive bounded
candidate search live in `codec/`.

Input is ASCII, one command per LF-terminated line:

- `E23` encodes record (2,3), emitting `C 2031`.
- `D2131` recovers it, emitting `R 23 L 0100 S 31`.
- `D_0_1` recovers two erasures, emitting `R 23 L 1010 S 01`.
- `D____` emits `U S 00`: outside the declared decoding radius.

`L` has one bit per symbol in evaluation order, marking both corrections and
erasure fills. `S` contains the two second-difference syndromes, with erased
symbols replaced by zero. Zero-fill syndromes are diagnostics, not an acceptance
criterion. The decoder admits exactly one codeword satisfying 2*errors+erasures
<= 2. Distance three proves uniqueness. Three or more erasures reject. Some
beyond-radius corruptions lie in another codeword's radius and can miscorrect:
without external redundancy the application cannot infer the transmitted record.
`U` means no candidate in the declared radius, not detection of every possible
out-of-radius channel error.

Digits outside 0..4, unknown commands, bad sizes, CRLF and missing final LF emit
`M`. The line buffer has eight bytes; filling it without a terminating LF stops
with `LIMIT`, exit 3, without interpreting its tail. LF in the eighth slot
completes a malformed line and emits `M`. At most 2000 LF-terminated records are processed;
reaching that cap also emits `LIMIT`, exit 3. Normal EOF exits 0. The bounded
storage and record count do not promise a bound on waiting for console input.

The exhaustive oracle was frozen before the first Omega check. `reference.py`
uses interpolation of pairs of observed points, independently of the Omega
25-candidate scan. It proves codebook size 25, minimum distance 3, both parity
rows for every codeword, and recovery of all 675 within-radius transmissions.
`data/oracle.json` freezes exact input/output SHA256 identities: 25 encodings,
1296 received frames (675 recoveries, 621 failures), nine malformed commands,
and empty, truncated, oversized and record-limit streams. Tolerance is zero.
The complete `controls/out_of_bounds` program must reject specifically for
index 4 outside a length-four array; package or syntax rejection is no pass.

Existing population-count, Fletcher checksum and wire-protocol samples were
compared before authoring. They count bits, detect checksums, or serialize
records; none performs field-code recovery, error/erasure radius admission,
correction masks or exhaustive received-frame decoding. This sample adds that
workflow rather than renaming their constants.

The generated host is validation equipment, not a substitute application. It
compiles this real entrypoint through ordinary accepted-package preparation,
then replays all five frozen streams serially against one genuine Terminal
artifact. It requires exact stdout, empty stderr, explicit process-exit completion
and the frozen statuses 0/0/0/3/3. No clock or filesystem guest grant is supplied.
The fixed sponsor allowance is 100 million fuel units per bounded stream;
exhaustion fails validation. Its successful build receipt binds generated source,
manifest, lock, toolchain and executable hashes. Actual stream captures, typed
status and artifact identity are retained under ignored `build/terminal-validation`.
