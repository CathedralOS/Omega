# Named constant compositions

These programs extend the existing `LIBRARY-REPRESENTATION-FAMILIES` fixed storage fact at its named-constant place. They do not add a second nine-place row or close the parent task.

The original [constant](main.omg) and [Delivered=41 twin](invalid/main.omg) remain unchanged. Both compositions keep the same Delivered bound, `value.lo - 42u64` operation, and exact byte oracle: lo at byte8, hi at byte0, and hi equal to9.

- [Generic policy](generic_policy/main.omg) retains the selected `PairLayout<ZERO>` application through the completed constant. Its [twin](generic_policy/invalid/main.omg) requests `PairLayout<EIGHT>` without a representation conversion. Identical plan geometry does not erase the policy's own Const argument.
- [Imported policy and semantic data](imported_policy/main.omg) retain the full dependency-owned Pair and generic policy. The [own-Const twin](imported_policy/invalid/main.omg) breaks only that application identity. The [private-policy control](imported_policy/invalid/private_policy/main.omg) changes only the dependency policy's visibility; it must reject the caller's explicit private conformance name.

The dependency sources and ordinary Build edges are retained in each imported project. The original full imported witness has not been replaced by a smaller local-data case. These programs bind all four required hosted targets, plus macOS x86-64. Runtime qualification requires fresh native and Terminal execution on their pinned project paths; the implementation's exact producer87 control observations precede that replay.
