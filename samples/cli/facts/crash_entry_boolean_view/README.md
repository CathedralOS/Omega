# Crash-entry Boolean view

Owning requirement: **CRASH-CONTRACT**, entry-operand normalization.

Fact: a checked Boolean view of an entry `u8` equal to `1` discharges `maybe_clear`'s `value == false` `Trap` crash guard without a caller crash ceiling.

An integer-to-Boolean view is not a total representation view. Structural access keeps a proved 0/1 landing on the scalar observation route. The entry byte's proved value is that observation. The view records it, and a local copy, a call whose result is ensured equal to that observation, and a match whose arms agree all read the same observation. `true == false` is closed false, so the callee's Trap route does not survive. A missing entry equality, and an entry byte proved equal to `0`, still leave the route uncovered.

On main `d6a282e29dad11509f280c3f4bc2ddbe028c922b`, before the local repair, the root rejected with `call from read_flag to maybe_clear at statement 2 call 0 has an uncovered Trap crash route`. On main `ce4681e434c766c619ebaebc2b372510d7b92ac8`, before the call and match transport, `call_result` and `match_join` rejected with `call from read_flag to maybe_clear at statement 3 call 0 has an uncovered Trap crash route`. After that transport, `omega run --both` on Windows x86-64 reports native exit 0 and interpreted exit 0 for every place.

On base `2ece6cb7889b8ca67e43f2317d9d14c062f928e5` the writable local carrier was refused: `local/main.omg` rejected with `call from read_flag to maybe_clear at statement 2 call 0 has an uncovered Trap crash route`, while the same program with an immutable local (the root) exited 0. The Boolean-view route refused every writable local instead of proving that its storage still held the recorded observation, although the shared entry-provenance law already admits a pristine writable local: the `crash_entry_nonempty_path` local carrier with `let mut observed: u64 = packet.leaf.bits` exits 0 on both engines on that same base. The route now reads the local carrier rule from `crash_entry_values`, so a writable local keeps the observation across a pristine write window and an overlapping write ends it. On the repaired tree that landed as `1bd52dbc0ce` (opt-level 1, host macOS x86-64; `2ece6cb7889b` above is the base that tree sat on, not the producer's revision) `local/main.omg` exits 0 natively and in Terminal Psi, `local/invalid` and `local/proved_false` reject at statement 2 call 0, and `local/written` rejects at statement 3 call 0. The 31-program sweep re-measured unchanged (31/31) on the later integrated revisions `598e8c85bf6` and `94247f98323`. With the write window removed for measurement, `local/written` was accepted and both engines took the Trap (`native signal 4`, `interp crash: Trap`).

## Execution

Every positive place and the root bind `ProgramEntry` for all four hosted targets (`windows_x86_64`, `linux_x86_64`, `macos_arm64`, `linux_arm64`) and declare `Expected exit: 0`. Those four targets exclude this host's catalogued `macos_x86_64`, so bare `omega run --both <place>/main.omg` refuses with `selected target macos_x86_64 has no bound required root slot macos_x86_64::ProgramEntry`; that is host pinning, not a program failure. Runtime evidence on this host therefore runs a scratch copy whose `build.omg` additionally binds `macos_x86_64::ProgramEntry` (and, for `target_body`, carries an identical `macos_x86_64 machine forward(...)` body); the fact sources keep their four hosted bindings. Every positive place then reports `native exit 0` and `interp exit: 0`.

Corpus pins: `pass/facts/crash_entry_boolean_view_exit`, `pass/facts/crash_entry_boolean_view_local_exit`, and `pass/facts/crash_entry_boolean_view_<place>_exit` for the eight other places; `fail/facts/crash_entry_boolean_view_rejected`, `fail/facts/crash_entry_boolean_view_false_rejected`, `fail/facts/crash_entry_boolean_view_local_rejected`, `fail/facts/crash_entry_boolean_view_local_false_rejected`, `fail/facts/crash_entry_boolean_view_local_written_rejected`, and the same pair for each of the eight other places.

## Requirements and Evidence

- **Establishment:** `requires byte.value == 1` (or `packet.flag.value == 1`, `byte.value == ONE`, or the successor machine's same requirement) establishes the entry byte before `&...value as &bool` observes it. Each reject twin omits only that requirement. The local place's own reject twin omits it in front of the same writable local.
- **Identity and lifetime:** the observation is the proved scalar value of the entry byte, not a total representation-view identity. The source place keeps its `u8` carrier. Field nests `Byte` in `Packet.flag`. The local place records it in a writable local: the local carrier rule is the shared write window, so the observation survives while nothing between the declaration and the read can overwrite the local or lend it exclusive access, and `local/written` pins that an overlapping write ends it.
- **Composition:** the observed `bool` reaches `maybe_clear` as a writable local, a direct parameter, a call result ensured equal to the view, or a match join of that view. `other_machine` and `target_body` pass it to `forward`, which publishes the same `value == false` ceiling and calls `maybe_clear`. No caller crash ceiling is added on `read_flag`, and no twin adds a caller equality guard.
- **Soundness boundaries:** a byte outside `{0, 1}` establishes no Boolean. An entry proved `0` keeps the false Trap route uncovered, including through a call result and a match join. A writable local that is overwritten before the call no longer carries the observation, so the route is uncovered rather than discharged from the stale snapshot.
- **Checked-to-Terminal Psi lowering (`Psi 05–07`):** each positive executes with exit 0 in the Terminal Psi interpreter (`omega run --both`), including the writable local, whose carrier rule is resolved in checking and erased into the same scalar observation.
- **Provider settlement through native emission (`Omega 00–09`):** `Build::bind` settles `ProgramEntry` for all four hosted targets, the Windows x86-64 image exits 0 in agreement with Terminal Psi, and on this host the `macos_x86_64` scratch image exits 0 in agreement with Terminal Psi.
- **Known precision difference (recorded, not repaired):** the three view routes scan the consuming statement for a possible overwrite or exclusive lend, while the entry/call-substitution path authenticates that statement's prefix. A call that reads a writable local as argument 0 and lends the same local `&mut` as argument 1 therefore refuses in the view routes (`call from read_flag to maybe_clear at statement 2 call 0 has an uncovered Trap crash route`) and is admitted on the entry path — `crash_entry_nonempty_path`'s shape with `maybe_zero(observed, &mut observed)` exits 0 natively and in Terminal Psi. Named arguments evaluate left to right ([expressions](../../../../wiki/spec/language/expressions.md#evaluation-schedule)), so the read precedes the lend and the admission is sound; the refusal is precision, not unsoundness. The admission does not come from the shared local carrier rule, whose pristine window ends at the declaration: it comes from the prefix the entry path authenticates. The writable-carrier pins for the other two consumers are `pass/facts/crash_entry_signed_zero_local_writable_exit` / `..._written_rejected`, `pass/facts/crash_entry_nan_equality_local_writable_exit` / `..._written_rejected`, and `pass/facts/crash_entry_nonempty_path_local_writable_exit` / `..._written_rejected`.
