# Local content reunion

One owned root may be partitioned and reconstructed from its complete live
descendant claims; equal geometry alone supplies no ownership.

Run `omega run --both samples/cli/facts/content_reunion/main.omg`.
Both engines must exit 0. The program checks base 10 and length 48 after
empty, interior, and full partitions through local storage, an aggregate field,
a named state, nested partitioning, a returned helper result, and a returned
local carrier, and a direct projection from an anonymous aggregate into sibling
aliases.

The numeric carrier exercises general content custody without claiming physical
memory authority. Cathedral separately exercises the same operation on its
retained firmware-provided memory before its resident write/read lifecycle.
This is a bounded Cathedral prerequisite, not a complete nine-place fact row
or a finished allocator.

The matching runnable fixture is
[`content_reunion`](../../../../tests/omega/run/core/content_reunion/main.omg).
Public rejection controls under `tests/omega/fail/core/` cover:

- `content_reunion_fresh_callee`: replacing an input with an independently issued
  root of equal geometry cannot establish the caller's lineage.
- `content_reunion_mixed_origin`: every normal return needs the same ancestry;
  one forwarding branch cannot authorize a fresh-root branch.
- `content_reunion_exchanged_empty`: zero-length children from independent
  partitions remain distinct claims.
- `content_reunion_mutated_result`: restoring numeric geometry after a write
  does not restore a returned ownership qualification.
- `content_reunion_anonymous_mutation`: the same invalidation applies to
  children projected from an anonymous aggregate.

Independent formal-root reunion remains separate from this local common-root
case; it does not gain authority from these examples.
