`total - 1000` preserves the selected provider result.

Owner: [BUILD-OWNED-TARGET-SELECTION](../../../../TASKS.md). This row establishes
that a dependency’s executed target keys select its private ordinary named
implementations, while the application imports only the public boundary and
retains its contract. Each private implementation has a complete type/const application: its private `[Holder<u64>; 2]` or `[Holder<u32>; 2]` type actual remains distinct while an ordinary Build helper forwards const tag 17. Dependency defaults remain below explicit root overrides.
The same complete Build handoff carries generated source and these choices; it does not close the
remaining target-family retirement or native-binding migration.

## Package and author controls

The smaller [package-owned witness](package_owned/main.omg) isolates private

selection into a dependency helper with two closed ordinary Boolean applications.
Only the selected branch executes; its generated instance retains the original
helper declaration as author. The [root helper](root_cross_file/main.omg)
pins the distinction between an activation and a helper authored in another
file. Each has a bound-only reject twin under its `invalid/` folder.

The [generated-provider witness](generated_dependency/main.omg) gives package A
the choice and package B the generated declarations. The application imports
B’s public requirement and depends on both packages; A also depends on B. A
separate marker service has two providers and B’s own default, so losing or
re-exporting inherited choices cannot silently fall back to a unique candidate.
Its reject twin weakens only Reading’s public lower bound. This remains the same
subtraction fact, with generated-source custody as a composition control.

visibility, conflicting and missing defaults, invalid unselected bodies, and a

## Requirements and evidence

- **Establishment:** `Reading::total` promises the lower bound; every provider
  independently proves it. No caller equality guard supplies the arithmetic premise.
- **Identity and lifetime:** the bound follows the exact returned scalar through
  each transport place. Each Build row retains the exact complete requirement and implementation
  applications, original type/value input occurrences and evaluated catalog
  target under the original Build activation. Phantom type actuals, nested
  generic arguments, structural array element/extent identities and const values participate in identity; compact
  conformance commitments and outer declaration names cannot replace them.
  The activation and lexical helper author remain separate retained declarations;
  neither acquires a runtime declaration in a receiving application.
- **Composition:** forwarding and arrival contracts preserve the bound, match
  joins preserve only the public fact, and subtraction consumes that bound directly.
- **Soundness:** the controls must refuse even though each selected implementation
  happens to return a sufficient number. Selection grants no access or trust authority.
- **Psi 05–07:** ordinary boundary calls and checked provider bodies lower to one
  target-neutral Terminal program. The Build companion retains target-keyed selection
  separately from source checking. Actual `run --both` observations require agreement.
- **Omega 00–02:** whole-provider selection filters exact deployment profiles before
  duplicate/default arbitration and publishes through the existing provider companion.
  Exact supplier source and declaration anchors rejoin receiving symbols; the
  handoff preserves package/purpose custody and the original Build observation.
  Catalog target values are ordinary checked data, not a selected-host observation.
- **Omega 03–06:** scalar calls, return homes, subtraction and result comparisons
  pass through ordinary ABI, instruction, register and activation-frame realization.
- **Omega 07–09:** the authored result is observed after native image emission and
  compared with Terminal interpretation; a wrong provider has a different result.
