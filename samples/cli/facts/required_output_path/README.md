# Required output path

An issued required-output path survives ordinary byte-view transport, so Build seals that exact reserved member and selects the product from its observed bytes.

Owner: [TERMINAL-BUILD-SEED](../../../../TASKS.md). `RequiredOutput::path` crosses
an authenticated host-result boundary. Build carries its read-only view, resolves
that path under its issued Output facet, writes and closes the file, and completes
the original linear obligation against that sealed member. Observing the expected
first byte selects the normal product entry; another byte selects a trapping
entry. Every positive binds all four hosted targets and expects exit zero in
native and Terminal execution.

This differs from `build_activation_borrow`, which carries a loan of the original
Build activation, and `recorded_build_role`, which consumes an executed package
name. Neither exercises a host-produced byte view from a linear output marker.

| Place | Transport |
| --- | --- |
| Local | A local read-only view. |
| Field | A lifetime-bearing record field. |
| Parameter | The query result directly enters a borrowed parameter. |
| Call result | An ordinary relay returns the exact view. |
| Match join | The returned view joins a distinct alternate path. |
| Const name | A named byte-array constant supplies the logical name before issuance. |
| Nested machine | A nested helper queries the borrowed obligation. |
| Other machine | The view crosses two ordinary helpers. |
| Selected implementation | Build selects an ordinary named implementation for the product entry. |

Each readonly reject twin changes only the consumer parameter to `&mut [u8]`.
The [wrong-join control](controls/wrong_join_path/build.omg) selects the alternate
path: its file cannot satisfy the original obligation. Thus an inverted join arm
cannot silently pass. Sealing and exact settlement check the complete path, in
addition to the product selection's first-byte observation.

The fixed optimized producer `574f0fdb85592dec7ee4ea046e8517efca3185ed` reaches
`Terminal Build required-output path byte results are not installed`. Replacing
only the query with the literal `"answer.dat"` makes the initial control run with
native/Terminal exit zero. The repair authenticates the issued marker, asks the
filesystem owner for a still-pending obligation's canonical path, then uses the
existing invocation-accounted immutable byte-sequence carrier. The snapshot's
lease follows the guest view; its bytes confer neither filesystem authority nor
mutable access. Completed obligations cannot be queried through this runtime API.

## Requirements and evidence

- **Establishment:** only the activation-issued marker identifies an obligation;
  raw ordinals and equal path bytes supply no guest authority.
- **Identity and lifetime:** the original obligation owns the logical path; the
  immutable returned backing retains its invocation storage account through use.
- **Composition:** the same path query and exact settlement survive all nine
  carriers; no place substitutes directory spelling or a literal for the query.
- **Soundness:** readonly twins reject mutable access; the alternate path cannot
  complete the obligation; a sticky failed Build cannot publish a product set.
- **Psi 06–08:** the actual Build boundary returns materialized byte storage, and
  ordinary byte-view calls/projections/joins preserve its read-only access.
- **Omega 00–09:** Build's observed byte chooses the source entry that reaches
  native realization and execution; a wrong selected entry traps.

The row and its controls are pinned under `tests/omega/{pass,fail}/facts/required_output_path`.
Matching-host execution outside Linux x86-64 remains unmeasured. Parent acceptance
still includes default-source Build execution, remaining operations/accounting,
opaque-provider reference carriers and staged dependency/provider preparation.
