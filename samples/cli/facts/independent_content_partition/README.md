# Independent content partition

Fact: Two independent routed interval claims on one owned region remain independently conserved by one checked split.

Parents: `BUMP-ALLOCATOR-CANARY` and `BUILD-OWNED-TARGET-SELECTION`.
The migration requirement is to preserve this same split through an ordinary
selected implementation without claiming that its public requirement can issue
private qualifications. A backing grant and vacancy describe different
facts about one allocation. Their projections may use the same interval algebra;
neither equation substitutes for the other. This row exercises that independent
conservation mechanism using a numeric model, not physical backing.

Each place issues a 48-unit region at 10, partitions 16 units, and observes
children (10, 16) and (26, 32). Both selector values execute. The nine places
are local, field, parameter, call result, match join, const name, a nested machine,
another machine, and another target body. Run
`omega run --both samples/cli/facts/independent_content_partition/<place>/main.omg`.
Each `invalid/main.omg` removes only the second owner's conservation equation.
The corresponding corpus fixtures are pinned as
`tests/omega/pass/facts/independent_content_partition_through_<place>_exit` and
`tests/omega/fail/facts/independent_content_partition_through_<place>_rejected`.

## Requirements and evidence

- Establishment: each domain names its authorized issuer. The checked partition
  derives its children from existing inputs rather than issuing either domain.
- Identity and lifetime: the two projection owners remain distinct despite
  identical algebra and geometry. Linear custody follows the actual returned
  regions; branch-local claims bind to the checked destination at a value join.
- Composition: one operation and oracle cross all nine places. The two independently
  proved equations participate in one transaction consuming the parent once.
- Soundness boundaries: every twin omits one conservation law and must reject.
  Additional controls cover repeated owner equations, absent input membership,
  and overlapping output geometry.
- Checked-to-Terminal Psi (Psi 05–07): normalized independent derivations survive
  proof erasure, structural result lowering and exact claim transfers. Terminal
  execution checks actual custody through calls and both match arms.
- Provider settlement, layout and ABI (Omega 00–02): Build companions bind all
  four hosted ProgramEntry targets plus macOS x86-64. The target place uses
  ordinary `ArmProbe`/`X86Probe` implementations selected by Build; distinct
  body checks make a mismatched provider observable as a Trap. One checked
  Terminal artifact is installed against the five target companion rows.
  Ordinary aggregate arguments, returned
  records and field observations use the normal layout and call-plan machinery.
  This numeric model admits no physical-memory provider.
- Instruction selection and activation frames (Omega 03–06): both children
  survive calls and field observations under native register/frame realization;
  the runtime oracle checks all four scalar fields.
- Encoding and native emission (Omega 07–09): the host's native image and Terminal
  interpreter must both exit zero. Other target bodies are source-checked;
  this row does not claim execution on unavailable hosts.

The bundled core split applies both laws to actual `Granted & Vacant` inputs;
`alloc::bump` uses it instead of an abstract split provider. Its compile-only
canary still has abstract merge and resident services. Real backing admission,
initialization under an admitted Stable profile, placed reads, retirement, and
exact vacant return remain unfinished parent acceptance.

A provider with no owned content inputs can return independently established
claims. Those fields do not partition caller content, so the bodyless
requirement needs no invented input conservation equation. This does not grant
issuance: checked providers still establish each returned field's qualification
and custody. The factory compositions under `tests/omega/pass/core/` cover both
an ordinary checked call and a selected boundary provider, each returning two
privately issued fields. They supplement the original split row; they do not
replace its operation, bound, or reject twins.

Opaque native supply is checked separately against the retained signature.
Each routed output needs its own consumed qualification or its exact authorized
issuer route. A borrowed occurrence, unrelated owned domain, matching algebra,
or another legitimate forwarded output cannot authorize a fresh claim. The
`independent_content_native_*` fail controls stop at native admission; their
foreign locator deliberately makes no matching aggregate ABI assertion and must
never execute. Raw checked construction, duplicated owned values, and a borrowed
source retain their existing provenance, move, and retained-custody rejections.
A diagnostic probe that ignores a borrowed input and independently issues fresh
outputs still reaches the existing conservative borrowed-source refusal; this
change does not establish that separate capability.
