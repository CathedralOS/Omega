# Independent content partition

Fact: Two independent routed interval claims on one owned region remain independently conserved by one checked split.

Parent: `BUMP-ALLOCATOR-CANARY`. A backing grant and vacancy describe different
facts about one allocation. Their projections may use the same interval algebra;
neither equation substitutes for the other. This row exercises that independent
conservation mechanism using a numeric model, not physical backing.

Each place issues a 48-unit region at 10, partitions 16 units, and observes
children (10, 16) and (26, 32). Both selector values execute. The nine places
are local, field, parameter, call result, match join, const name, another state,
another machine, and another target body. Run
`omega run --both samples/cli/facts/independent_content_partition/<place>/main.omg`.
Each `invalid/main.omg` removes only the second owner's conservation equation.
The corresponding corpus fixtures are pinned as
`tests/omega/pass/facts/independent_content_partition_through_<place>_exit` and
`tests/omega/fail/facts/independent_content_partition_through_<place>_rejected`.

## Requirements and evidence

- Establishment: each domain names its authorized issuer. The checked partition
  derives its children from existing inputs rather than issuing either domain.
- Identity and lifetime: the two projection owners remain distinct despite
  identical algebra and geometry. Linear custody follows the actual returned
  regions; branch-local claims bind to the checked destination at a value join.
- Composition: one operation and oracle cross all nine places. The two independently
  proved equations participate in one transaction consuming the parent once.
- Soundness boundaries: every twin omits one conservation law and must reject.
  Additional controls cover repeated owner equations, absent input membership,
  and overlapping output geometry.
- Checked-to-Terminal Psi (Psi 05–07): normalized independent derivations survive
  proof erasure, structural result lowering and exact claim transfers. Terminal
  execution checks actual custody through calls and both match arms.
- Provider settlement, layout and ABI (Omega 00–02): Build companions bind all
  four hosted ProgramEntry targets. Ordinary aggregate arguments, returned
  records and field observations use the normal layout and call-plan machinery.
  This numeric model admits no physical-memory provider.
- Instruction selection and activation frames (Omega 03–06): both children
  survive calls and field observations under native register/frame realization;
  the runtime oracle checks all four scalar fields.
- Encoding and native emission (Omega 07–09): the host's native image and Terminal

  this row does not claim execution on unavailable hosts.
