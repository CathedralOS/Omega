`e9f492c5ccc6f84731ce0e65eb9a9d4f56fdb067`. The failing consumer is historical

with the source-acquisition SDK's `resolve_local_source_snapshot_in_lane`, run

## Requirements and evidence

- **Establishment:** one executed Build declaration establishes the package
  name; source directory spelling supplies no identity.
- **Identity and lifetime:** the accepted subject owns historical metadata at
  the immutable content pin. Resolver origin and content verification remain
  required before the recovered bytes can be consumed.
- **Composition:** name views pass through nine ordinary value/call routes.
  Recovery reads the produced description, rather than recognizing those routes.
- **Soundness boundaries:** wrong-name imports reject; recorded metadata cannot
  authorize tampered bytes. Product/build dependency ordering and scope remain
  separate. Source diff remains an audit aid, not acceptance authority.
- **Psi 06–08:** Build name computation and the imported product execute through
  Terminal Psi; product bodies are not evaluated to infer package names.
- **Omega 00–02:** the exact declared alias supplies package lookup and Build
  binds each hosted entry. Ordinary field/view/call layout carries the name.
- **Omega 03–06:** the product's imported answer and trap guard reach native
  instruction, register and activation realization.
- **Omega 07–09:** Linux x86-64 native exit zero agrees with Terminal execution.
  Four authored target bindings are source coverage; other matching hosts remain
  unmeasured.
