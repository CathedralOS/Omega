# Scalar domain introduction from a completed call

A completed query guarantees a nonnegative result; routed domain introduction
preserves that fact. Every place uses that same fact and operation. The selected
checked provider returns the larger of its input and `FLOOR`. Positive programs
use `FLOOR = 0`; each reject twin changes only that constant to `-1`, which no
longer supplies the domain's nonnegative predicate. Issuer identity is unchanged.

This is a prerequisite repair for **FILESYSTEM-PLATFORM-SERVICES**: the private
Windows buffer-transfer leaf needs an explicit, privately issued synchronous
handle classification. These programs test ordinary scalar predicate evidence,
not the truth of Windows mode bits or foreign completion/lifetime promises.
`TASKS.md`'s **DOMAIN-ISSUER-ROUTES** names this row's checked scalar result
transport as the behavior its ordinary/boundary call lowering must preserve.

The places are [local](local/main.omg), [field](field/main.omg),
[parameter](parameter/main.omg), [call result](call_result/main.omg),
[match join](match_join/main.omg), [const name](const_name/main.omg),
[another state](other_state/main.omg), [another machine](other_machine/main.omg),
and [target body](target_body/main.omg). Each has `invalid/main.omg`; the
positive place is pinned as `tests/omega/pass/facts/scalar_domain_call_guarantee_through_<place>_exit`
and its twin as `tests/omega/fail/facts/scalar_domain_call_guarantee_through_<place>_rejected`.

Each program binds all four hosted targets and expects exit zero. Run a place
with `omega run --both <place>/main.omg`; check its twin with `omega --check`.
The query boundary has an ordinary checked provider, so both engines can execute
without an OS foreign binding. No caller guard reconstructs a missing result fact.

Requirements exercised:

- Establishment: only a completed, authenticated query guarantee supplies the
  numeric predicate; the authorized issuer supplies separate provenance.
- Identity and lifetime: the exact captured scalar survives the named transport;
  unrelated calls and invalidated storage cannot supply it.
- Composition: record projection, calls, joins, constants and state arrivals
  retain the same predicate; a weaker query ceiling must reject.
- Soundness: qualification neither grants native storage authority nor proves
  provider compliance, ownership or the validity of a copied OS handle.
- Psi lowering and Terminal execution: preserve the resulting scalar and erase
  proof-only classification without changing its value.
- Omega settlement, layout and ABI: select the complete checked query provider;
  domain qualification does not change the integer carrier.
- Selection, register homes and frames: the same value crosses ordinary and
  boundary calls, including target-scoped bodies, without corruption.
- Encoding and native emission: direct native execution must agree with Terminal
  execution at zero; producer/target receipts remain in the qualification record.

All nine places execute at zero in both native and Terminal engines on macOS
ARM64; their nine fact-sensitive twins reject. The baseline first refused the
completed helper's predicate, then refused scalar result-contract lowering.
The repair retains the source checker's exact return decisions, the domain's
independent predicate and issuer catalog, and the actual completion/return
bindings. Mixed forwarding/issuance, generic issuers, saved-call snapshots and
nominal cleanup have separate regression controls. Codec controls reject
detached, moved or forged result-formation associations.

This evidence covers the closed scalar theory exercised here, not every domain
theory or issuer route. Other hosted targets are bound but have not executed in
this record. The Windows provider and its actual runtime acceptance remain
unfinished under the parent task.
