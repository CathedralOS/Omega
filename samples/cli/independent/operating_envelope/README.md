# Operating envelope (IND08)

Compute a two-dimensional operating region from runtime linear inequalities
`a*x + b*y <= c`, intersected with a symmetric safety window `[-B,B]^2`.
The private Omega implementation owns packet parsing, Sutherland–Hodgman
polygon clipping, counterclockwise vertex order, segment intersections,
shoelace area, constraint residuals and active-constraint reporting. It uses
only existing standard console and core scalar facilities.

Run from the repository root:

```sh
omega --check samples/cli/independent/operating_envelope/main.omg
omega run --both --keep samples/cli/independent/operating_envelope/main.omg < samples/cli/independent/operating_envelope/data/rectangle.txt
python3 samples/cli/independent/operating_envelope/validate.py --omega /absolute/path/to/omega
```

First prepare the ordinary std dependency with `omega update --project
samples/cli/independent/operating_envelope`, inspect its review and explicitly
accept the required decisions, then `omega update --resume --project ...`.
No candidate or in-progress numerical library is required.

Input is one newline-terminated line containing signed decimal integers:
`B N a0 b0 c0 a1 b1 c1 ...`. B is 1..100, N is 0..8, coefficients
are -100..100 with nonzero normal, and each c is in micro-units
(-100000000..100000000). For example `10 1 1 1 6000000` means
`x+y <= 6`. Each integer must be present; extra integers, malformed bytes,
truncation and a packet filling the 256-byte reader are invalid. Exit 2
means invalid runtime input; exit 3 means an internal capacity failure.

Output lists the status, vertex count, area integral and fractional micro-unit
parts, vertices in micro-units, one certificate per vertex/constraint pair
(residual in units of 0.0001), and active pairs. Indices are zero-based.
Clipping preserves counterclockwise order; the first vertex may rotate.
Area parts reconstruct as `area_whole + area_fraction_micro/1000000`.

The safety window is an explicit domain bound, not a guessed infinity.
`empty-in-window` claims no feasible point inside it, not global
inconsistency. `bounded` means a polygon enclosed strictly inside the window.
`window-limited-unboundedness-undetermined` means a window edge survived;
the original feasible set may be unbounded or simply extend beyond this
window. The application deliberately refuses to infer global unboundedness
from a finite clip. No constraints returns the window with that status.

The inside decision uses residual <= 1e-9, and intersections use that
same admitted boundary. Active constraints have |residual| <= 1e-8.
Input coefficient scaling therefore matters to the absolute tolerance.
`data/expected.json` freezes exact rational original-boundary results and
2e-6 vertex/area tolerances before execution; emitted numbers truncate.
`reference.py` independently enumerates pairwise line intersections and
orders the hull, rather than implementing polygon clipping. The validator
also checks every certificate, every active pair, order, area and status.
Its coordinate-dependent certificate tolerance accounts for text truncation.
Expected results are not generated by running the Omega application.

A verified native executable can be reused across all input fixtures with
`validate.py --mode native --executable /absolute/path/to/program --omega
/absolute/path/to/omega`. Use `--mode both --only rectangle` (or another
fixture name) for a serial public Terminal comparison. The public comparison
checks host-presented exit status; the validator independently checks native
output. Validation logs and their executable hashes live under `build/validation/`.

Ten valid fixtures cover analytic rectangles, triangles, scaled normals,
a diamond, eight active edges, redundant constraints, inconsistency,
micro-unit boundary separation and window truncation. Twelve invalid
runtime inputs exercise parser/admission limits. `intended_invalid/` is a
separate complete application requiring -1 to inhabit a positive radius
type; check must reject it independently of the runtime-invalid cases.

Existing `stats_compute` provides arithmetic pressure and `maze_flood`
provides array/state-loop pressure. Neither computes a feasible region,
clips polygons, reports active inequalities, or emits geometric certificates.
The sample therefore adds a new domain workflow rather than changing their
constants. Generated compiler and validation outputs remain under `build/`.

The complete `evidence/float_reproduction/` application reproduces the original
main compiler gap: a module-owned float conversion causes 240 early satisfaction
errors. The candidate includes a general source-scope repair for visible named
operator families and exact typed satisfaction, with a module result-domain
fixture and a hidden-signature rejection fixture under `tests/omega/`. It
changes no core float contracts, custody guards or provider primitives.


## Compiler recovery evidence

The sample exposed scoped named-operator satisfaction, indexed call-result
storage and fixed operand occurrence recovery gaps. The candidate includes
the owning repairs and complete positive and negative language controls.
The fixed occurrence repair establishes real typed, target-admitted copies
at operations while retaining resident values across every original CFG
transport. It does not infer a fragment tree from the formatter's source.

`evidence/allocator_diagnosis/` preserves the earlier current-main failures,
complete minimized programs, frozen outputs and an independent all-predecessor
range audit. `evidence/fixed_occurrence_repair/` explains the resulting
recovery and its complete compiler regression fixtures. Geometry fixtures,
reference calculations and tolerances remain independent of those repairs.

Run the public validator after the ordinary package review is prepared.
Its successful native and Terminal results, actual output files, binary
identities and command records are required acceptance evidence. The review
bundle retains scoped compiler gates and strict Clippy baseline attribution.
