# Executed workspace source acquisition

Owning acceptance: `PIPELINE-ARCHITECTURE-ENFORCEMENT` and `TERMINAL-BUILD-SEED`.

The Git SDK publishes these authored sources into a temporary real repository.
The root's helper emits three members. The selected member computes its name,
then requests a declared sibling through a relative Path. The client selects
two different names from the same repository and aliases one member twice.
Its authored result is native exit 0 and Terminal Unit/exit 0.

The unselected member awaits an explicitly named provider from a separate Git
repository and uses its result to choose its catalog name. Its missing Product
dependency must never acquire, and its deliberately invalid Product body must
never be prepared. Six actual Build activations cover the client, catalog,
three declaration observations and the helper; selected members reuse their
original returns. The helper's complete source graph remains attached to the
catalog observation and reconciles at the final join, outside Product routing.

The same journey publishes an accepted lock, changes the helper's Git selector,
then compiles offline and executes native/Terminal with exit 0 using the pinned
helper. Read-only offline audit neither fetches nor changes the lock. Explicitly
refreshing the changed helper must reject its duplicate catalog name and leave
the previous lock untouched. The wrong result is authored in
`catalog-helper/wrong_result.omg`, not synthesized by the compiler or harness.

The same journey rejects private member access and a requested name absent from
the executed catalog. Focused path-normalization controls reject escaping the
registered workspace and selecting its root instead of a member.

Run `cargo run -p compiler --example executed_git_source`. The existing test-owned
Git proxy routes the inert HTTPS locator to real local Git objects; production
acquisition/custody and compiler behavior remain unchanged. This data fixture is
not a network-dependent generic corpus entry.
