# Executed Git source acquisition

Owning acceptance: `PIPELINE-ARCHITECTURE-ENFORCEMENT` and
`TERMINAL-BUILD-SEED`.

The application resolves two executed Git requests to one authenticated source
and one dependency Build activation, then joins its helper-computed declaration
before Product checking. The authored main must complete with exit 0 in native
and Terminal execution, using the originally acquired answer even when the
test moves the repository selector before Product completion.

Run the application SDK journey with:

```sh
cargo run -p compiler --example executed_git_source
```

The Unix test harness selects a test-owned Git transport proxy through ordinary
operator executable selection. The proxy maps this fixture's inert HTTPS locator
to a temporary local repository; real Git creates and verifies its objects and
the production source owner enforces normal snapshot custody. No public server,
language recognizer, production transport exception, or synthetic package key is
used. Windows transport-harness coverage remains open.

Controls retain rejection of an unaccepted offline selector even when cached,
private dependency calls, and acquisition policy from another project; the
offline and foreign-policy refusals precede transport. The private-call source is
the existing `fail/build/executed_dependency_private_call/main.omg`.
`controls/changed_library.omg` is the committed selector-drift input, not a second
program oracle. The shared Build SDK separately retains local acquisition,
generator outputs, target fanout and mandatory dependency joins.

The generic corpus/production CLI still needs the retained-Build scheduling
cutover. Accepted-lock round-trip qualification, named workspace selection,
Git-relative Path navigation, and provider/query suspension remain open; this
journey does not establish those requirements.
