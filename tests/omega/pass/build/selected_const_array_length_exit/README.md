# Selected constants in Build

Build uses computed array lengths whose helpers invoke selected floating-point
operators and an ordinary checked named requirement. Its own provider context
must settle those constants, then the evaluated Build program must be checked
before execution. A computed generic argument also creates a concrete data
instance whose identity must survive deferred Product-body completion.
Build writes and reads the last element of each array, including the generic
instance's nested field, and binds the Product entry only on the authored result.
An initializer helper also reads a later computed constant. Build observes its
result, exercising dependency order and retained constant declarations after
substitution. The anonymous arithmetic must keep exact-rational meaning despite
the imported floating-point operators; the initializer's destination does not
choose its intermediate operations.
Build also calls a helper that recovers a capacity from a fixed-array equation,
and an equation that synthesizes a previously absent `Buffer<13>` argument.
The new instance and its attached method must join the retained declarations;
their generic-origin records still undergo independent identity validation.
An `Optional<BuildToken>` is instantiated from the toolchain's generic template
and inspected inside Build. Its exact use must retain the concrete instance in
Build context, while Product-only instances of that same template stay out.
Build also calls a four-target helper family. Every sibling has a local array
whose length needs the Build-only checked provider; all bodies must settle and
check in Build context, although only the admitted execution-profile member
runs. The Product's selected target must not supply that provider authority.
The emitted program exits 0.

Run the full package and Build route with `omega update --project
tests/omega/pass/build/selected_const_array_length_exit --offline`, then
`omega run tests/omega/pass/build/selected_const_array_length_exit/main.omg`.
