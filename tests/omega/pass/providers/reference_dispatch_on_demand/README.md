# Reference dispatch ownership

`PIPELINE-ARCHITECTURE-ENFORCEMENT`: optional checked-tree interpretation prepares
its selected adapter and implicit IEEE comparison bindings at its own entrance.
Ordinary Product installation does not build or retain that reference-engine
table. Terminal/native provider admission still uses exact portable demand and
selected provider identities.

The program selects an ordinary named checked provider, calls it for a runtime
float, and matches that result against a value pattern. A wrong provider or
comparison branch traps. Expected exit is 0 in native, Terminal, and explicitly
requested checked-tree interpretation. The checked engine is a separate oracle,
never a fallback for Terminal refusal.

`fail/providers/provider_type_slot_ambiguous` retains the duplicate-selection
control; `fail/float/x86_fma_missing_deployment_features` retains native feature
admission. This witness covers the assigned ownership repair, not all provider
selection or a complete fact row. Actual producer/host observations are recorded
in the qualification record and landing PR.
