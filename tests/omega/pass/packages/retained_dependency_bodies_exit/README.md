# Retained dependency bodies

`CHECKED-PACKAGE-REUSE`: dependency bodies keep one declaration, state and
expression correspondence when a consumer extends the prepared frontend.

The vendor publishes no result guarantees. `project` must preserve the returned
reference origin so the live view keeps borrowing its original cell; `count`
must preserve its arrival interval under the actual argument so subtraction is
proved; `equal` must remain available for observation-free denotational
admission of `require_equal`. The program traps if either runtime observation
changes. All four hosted entry bindings name this same program.

The reject control in `fail/packages/retained_dependency_body_loan` changes only
the mutable backing and adds a write while the returned view remains live. It
must reject for that loan. `fail/proofs/structural_ensures_unjudged_rejected`
remains the independent proof control. These protect the reuse operation;
persistence and the parent task's performance bounds remain separate acceptance.
