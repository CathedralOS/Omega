    psi: check each write once when replaying a state's current values (#1718)
    
    Checking a std program spent about 4 s re-walking the same storage
    history while proving index bounds and call requirements. Each value now
    walks only the writes it has not been checked against yet. On
    samples/cli/basics/print_number, runtime index checking drops from about
    4.8 s to 2.3 s, call-contract checking from about 4.6 s to 2.8 s, and a
    cold compile from 87.7 s to 84.1 s, with a byte-identical image.
    
    To prove a call's requirements or an index's bound, the checker replays
    the state's statements up to the call and tracks what it knows about
    each scalar: a parameter's value, a field, a condition, a length. At
    every statement that can write, it asks whether a write reached each
    tracked place since the value was recorded there (the place's anchor),
    and forgets the value if one did. Answering means walking the storage
    graph back from the current statement to the anchor. Parameters are
    anchored at the start of the state, so every write point walked the
    whole prefix again, for every tracked place, in every replay. A replay
    cost grew with the square of the state's length, and the checker
    replays once per call it examines.
    
    A value that survives at a write point is now re-anchored there, so the
    next write point only walks the writes after it. When the earlier point
    lies on every path to the later one, which is how a state's statements
    follow each other, the answer is unchanged. When it does not, the shorter
    walk runs past the anchor to the state's start and the value is
    forgotten: less precise, never unsound. An entry that already holds no
    value is also skipped, since there is nothing left to forget.
    
    Validation: five interleaved cold compiles each of main 18fc751d0 and
    this change (release build, 4-core Linux, fresh cache per run). Wall
    times were 84.4/91.0/85.1/90.2/87.6 s before and
    83.5/81.1/88.0/86.2/81.8 s after; Psi 05 averaged 65.2 s before and
    60.2 s after. All ten native images had the same SHA-256 (2aa504cb…).
    A corpus compare against the base over the 185 fixtures in
    pass/contracts and pass/dependent lost none; one fixture
    (data_where_ranged_param_constructs) that timed out at the base now
    checks.
