A valid table check must keep every field comparison when it is returned through a Boolean policy. Cathedral exposed a refusal when its validator checked 33 gates: the finite expression exhausted a recursion limit even though the same comparisons checked when parenthesized differently.

The positive keeps the original flat 132-comparison policy and checks its result for a matching table and wrong fields near the start, middle and end. Fixed values outside the table must stay unchanged. The reject twin changes only the validator result to unconditional true, which cannot establish the policy for an arbitrary input table. Both use ordinary records and calls; no interrupt execution is involved.

This pins the finite-expression proof repair, not full Cathedral interrupt or timer acceptance.
