# Canonical native-layout catalog

Orchestration migration / `PROVIDER-SELECTION-AFTER-TERMINAL`: one published
artifact must preserve complete normalized layout reports, exact private-slot
selections and nominal record/field identities without Source reconstruction.
This witness carries invariant and target-member policy layouts under a natural
record. Windows uses 24 bytes for the variable member; other hosted targets use
16. The entry checks both fields, a nonzero neighbor, and the selected target's
size independently of the layout policy. All four hosted entries are bound.

The existing [wrong-owner control](../../../fail/layouts/private_callback_slot_wrong_layout/main.omg)
removes the exact slot/layout-owner correspondence and must still reject.
Artifact transport, Source-free consumption and mutation controls are acceptance
for the metadata migration; ordinary source checking alone does not close it.

The frozen baseline first lost the layout constructor during demanded-premise
closure, then refused publication because private callback demands could not be
discarded. The inspection now consumes retained and decoded artifacts without
Source, selects all four target alternatives, and rejects removed records,
changed extent, corrupt application preimage, wrong slot owner, changed target
geometry and missing nominal fields at receiving ingress. Full callback-path
closure and source-free ABI planning remain separate orchestration acceptance.
