# Select the kernel's code and data descriptors

This Omega body asks the CPU to use code and data descriptors from the table the caller retains. It selects different entries from the bootstrap defaults, checks the selectors after returning, and refuses a different table, a descriptor of the wrong kind and an out-of-table selector. Both tables and every observed selector must remain unchanged after the refused calls. Build selects the ordinary x86-64 implementations.

The [CPU harness](../../../../../tools/native_entry_cpu/README.md) owns the table until shutdown. Capture this fixture, extract its `CallReturn` entry, and use `--oracle segment-selector-call`. It calls the compiled Omega entry eight times and independently checks CS=24, DS/ES/SS=32, FS/GS=0, all three FS/GS base registers, only the expected descriptor accessed-bit changes, untouched neighboring words, RSP, callee-saved registers and IF/DF. The base values have nonzero upper halves and are canonical; the program never dereferences them. Expected output is `B........P`, with QEMU exit33. The same payload with `--corrupt-neighbor` must fail. The hosted entry only demands this callback and is never executed.

Source controls reject a shared table loan, a caller that excludes MachineControl and reuse of a descriptor value as proof that it survived a possible hardware write. Saved operations retain the checked table extent and operand access. Terminal interpretation explicitly refuses these privileged hardware operations.

The admitted scope is one CPU in long mode at CPL0, interrupts masked, CET disabled for code reload, no asynchronous or debug arrival, no firmware calls and no concurrent table/GDTR change. Storage stays mapped and live. False reports a preflight refusal; architectural faults are neither caught nor rolled back. The code and data calls are separate changes. This witness does not install IDT roots, deliver a timer, issue Pending acknowledgements or wake ordinary kernel work.

QEMU 11.0.2 does not write the code descriptor’s accessed bit on its same-privilege far-return path. The first strict run observed CS=24 with the original code word unchanged and failed the mandatory accessed-bit check. The harness therefore checks CS independently and allows only that one bit to differ in the selected code descriptor; all other descriptor bits, the data accessed-bit update and neighbors remain exact. This is an emulator limitation, not permission from the ISA or proof that real hardware’s CS accessed-bit write occurred. The compiler still requires a mutable table and invalidates its prior contents. See [QEMU’s pinned return helper](https://github.com/qemu/qemu/blob/v11.0.2/target/i386/tcg/seg_helper.c) and [Intel’s descriptor contract](https://cdrdv2-public.intel.com/671190/253668-sdm-vol-3a.pdf).
