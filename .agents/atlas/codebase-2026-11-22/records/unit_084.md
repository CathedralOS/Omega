## Five things a maintainer most needs to know about this unit

1. Git acquisition recomputes every object hash itself. Cached repository bytes are never trusted: commit, tree graph and blobs are rehashed (`git/objects/authentication.rs:57-158`), published snapshots are re-verified byte for byte on reuse (`git/snapshot.rs:334-376`), and a pin or exact revision never refetches a selector (`git/resolution/selection.rs:56-131`). An error that keeps or deletes a cache entry is decided in `acquisition.rs:261-299` using `may_preserve_cache`, which lives outside this unit.
2. Two different file-name policies exist. Git trees reject `.git` in any case, `.gitmodules` in any case and Windows reserved names (`git/objects/tree.rs:222-287`, `object_rows.rs:77`); local capture excludes `.git`, root `build` and root `omega.lock` by spelling (`tree/capture/traversal.rs:143-152`) and has no reserved-name check in this unit. Windows never records the executable bit (`tree/filesystem.rs:226-229`).
3. A public Git workspace-member API has no non-test caller. `GitWorkspaceProjectionPlanner` has no implementation outside `SA` and the two `resolve_git_workspace_member_*_in_lanes` functions are used only by tests; the package manager goes through `GitWorkspaceSession`/`GitWorkspaceCatalog` (`git/resolution/tree_session.rs`). The non-"selected" `stage_local_source_replacement_in_lane` is likewise test-only.
4. Several mechanisms are written twice: the request-file create/verify/remove/reconcile sequence (`availability.rs:57-78` and `transfer.rs:55-67`), the two snapshot metadata parsers (`git/snapshot_metadata.rs` and `snapshot/metadata.rs`), and the four hand-rolled loops feeding `SourceIdentityHasher`.
5. The Omega construction application never publishes for a packet that carries Build sources. `check_build_input` ends in `exit_process(246)` for valid Build evidence and 253 for invalid evidence (`construction/build_sources.omg:184-196`); only packets without Build sources reach the compiler. The Omega library files `alloc`, `blocking-executor` and most of `core` here are contracts or sealed declarations; the `alloc` machines and `blocking-executor` have no user in `source/` or `samples/` by grep.
