## Five things a maintainer most needs to know about this unit
1. Stage 07's selection packet (`source_selection_publication.rs`) is a join builder: every emitted machine, operation, edge, boundary and record gets joined back to a source declaration by identity (`MachineId`+`InvocationSite`, `ContractId`, `StructuralTypeId`), but many checks inside it compare computed identity strings (callable identity text, operand identity text, `application` strings, `intrinsic_identity` hex with version tags). Any change to how identity text is computed in the typed source breaks these compares at `source_selection_publication.rs:438, 581, 612-616, 653`, `provider_choice_inputs.rs:115, 133`, `provider_supply/demand.rs:236`.
2. Provider supply is two-phase: `PreparedTargetSupply::prepare` follows the call graph and may leave a requirement with a `None` realization; `settle` is what rejects none/competing supplies. `prepare` returns `Ok` with unsettled requirements by design (`provider_supply/mod.rs:10-12`, `298-319`, `400-451`), so "prepare succeeded" is not an acceptance.
3. Capability-by-issuer pattern: `CheckerIssuer` (stage 06), `LoweringIssuer` (stage 05), `PreparationIssuer` (stage 04) are zero-sized values whose only purpose is to make a constructor uncallable from other crates; enforcement is `mbx xtask check-boundary` (comment at `checked_program.rs:29-31`, `lowered_source_publication.rs:51-54`, `prepared-source/lib.rs:42-44`), which was not read. Separate seals use weak pointers (`demand.rs:24`), custody identity (`source_selections.rs:16`) and manifest identity (`published-target-providers/publication.rs:32`).
4. The lowered-program tables are dense `IdTable`s keyed by machine-local identities; `row()` cannot detect a foreign identity that is in range (`tables/mod.rs:308-314`, stated). Places are identities with parents, and unequal identities are not disjoint (`tables/bindings.rs:7-9`). `Refusal.detail` is diagnostic only (`tables/mod.rs:283-284`); only `NoRuleForGoalForm` yields `Incomplete`, every other cause rejects (`:246`).
5. Several hand-maintained lists sit beside enums: `BuildOperation::ALL` has 15 entries but the enum has 17 variants (`declaration_selection.rs:1108-1124` vs `1051-1073`), so `from_call_target` cannot return `ParameterDescription` or `FieldDescription`; `unplanned_demands` is a fixed list of five unsupported demand kinds (`provider_supply/mod.rs:563-594`); `product_operand_count_valid` is closed with `_ => false` (`declaration_selection.rs:285`).
