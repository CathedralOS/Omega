# Five things a maintainer most needs to know about this unit

1. **Conformance rows are built by name and result-domain *strings* in S02 and re-derived in S03.** `normalize_one` (`conformance_blocks.rs:855`) matches slots by requirement-name equality plus a qualifier/ordinal, and breaks overload ties with `result_dispatch_shape`, a string like `"arithmetic:Saturating&declared:Tagged"` (`:1140-1151`); S03's `constructor_applications.rs:513-517,770` asks the same question again with `normalized_result_dispatch_set`. Two implementations of "result-domain set" exist (S02 string, typed `type_identity.rs:7582`).
2. **Token-binding checks are decided on rendered shape strings and on source custody that may be absent.** `machine_token_bindings.rs` compares `operand_shape` strings built by `ShapeNormalizer` (`:1028-1317`); a callable operand with an unresolved machine parameter sets `has_dependent_callable_operand` and the pair is deferred to `pending_token_shape_comparisons` (`:155-200`, `:1184-1187`). The primitive-family and foreign-home rules silently do not apply when a symbol has no source origin/package identity (`:333`, `:429`).
3. **Several S03 recognitions are keyed on literal names and origin.** `installed_interrupts` requires state name `"run"` + data `"X86StaticInterruptScope"` + Toolchain origin (`call_and_product_selections.rs:3368-3377`); Product queries match `"BuildProduct"/"ProductTypeSchema"/"ProductProviderRef"` module names and `"entry|schema|provider|path"` (`:3613-3618`); Build helpers by `"build_selection_*"` names (`:238-253,313`); provider defaults by suffix `"::provider_defaults"` (`declarations.rs:1778`); atomic members by `Operation::from_name` strings (`atomic_calls.rs:70`).
4. **Deferred refusals and `Ok(false)`/`continue` paths carry a lot of the S03 "refusal" load.** `construction_destinations::prepare` lands expected types on literals/calls and, when it cannot, records a `DeferredRequest` on the holding declaration (`:1597-1603,1734-1740`, `defer_to_holders :1765`) so a program fails only if that declaration is demanded; `land_one` returning `Ok(false)` and `continue` on `binders.len() != static_arguments.len()` (`:1618-1620`) leave no record at that site. `contracts_and_signatures.rs::domain_selections::normalize` and `constructor_applications.rs::expression_owner` follow the same style.
5. **Same-job duplication inside this unit.** Four separate type-reference walkers that look for domain constraints (`domain_establishment.rs :457`, `domain_operator_homes.rs :197`, `machine_token_bindings.rs :624`, `conformance_blocks.rs :1153`), three domain-spelling resolvers (`domain_named :803`, `domain_name_reaches` via `domain_establishment.rs :571`, `DomainHeaders::candidates :64`), and `peel` defined in both S03 (`call_and_product_selections.rs:484`) and S02 `names/expression_paths.rs:178` (definition only grepped). The `signature_free_requirements.rs` header (`:7-8`) says "lookup" also resolves through it; grep shows no use in `names/lookup.rs` (only `domain_establishment`, `machine_parameter_requirements`, `static_arguments`).
