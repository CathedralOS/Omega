## Five things a maintainer most needs to know about this unit
1. `references.rs` is one 4,538-line file that holds four inline modules plus the main impl; `capture_reference` (2325-3078) and `resolve_reference_view_path_with_leaf_type` (3709-4070) carry most of the logic, and every returned reference is matched against captured backings only in `validate_reference_return` (4296).
2. In `capture_reference`, shared-borrow memberships requested by the result type are added to the referent when the domain passes a local "observable" test (2765-2812), and the contract check after it then compares against what was just added.
3. The package-manager lock acceptance is split: activation admission (`admit_locked_build_activation`, `accepted.rs:94`) is only applied on the compile route (`require_locked_activations`, `prepare_project.rs:498`); inspection uses `require_locked_graph` (`inspect_packages.rs:252`) which leaves activations unchecked (`acquisition.rs:101-108`).
4. `CanonicalSourceClosureSubject` has two encodings of the same data (binary for the fingerprint, text version 5 for `omega.lock`), plus two graph validators (`ResolvedPackageClosure::new` and `validate_subject`); a field added to the subject must change both encoders and both validators.
