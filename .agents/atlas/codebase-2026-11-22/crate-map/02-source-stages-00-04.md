Counts of files and lines come from `crates.tsv` (6 rows for this area) and `units.tsv` (287 files, 152,667 lines, summed with awk). Pipeline directory = `S/pipeline/`.

## What the area does

Stages 00 to 04 of the Rust source compiler turn loaded Omega source text into the typed, prepared program that stage 05 lowers. 00 lexes a file into tokens. 01 parses tokens into syntax trees. 02 resolves every name to a declaration and keeps machine bodies pending until asked for. 03 attaches types, signatures and selected calls. 04 specializes static applications and attaches domain and record facts, then issues the `PreparedTypedTrees` snapshot that stage 05 accepts. In goes `LoadedSources` (`S/representations/source-files/source_files.rs:50`); out comes `PreparedTypedTrees` (`S/representations/prepared-source/lib.rs:32`). The driver in `S/driver/` (not in this area) runs the stages; the six crates are libraries with no binaries. Each stage is a separate crate; the shared data types live in `S/representations/` (another area).

Per `S/README.md` (read) steps 00-01 are run by `driver/parse_source_batch.rs`, 02-03 by `driver/resolve_and_type.rs`, 04 by `driver/prepare_typed_source.rs`.

## How data flows through the area

1. `S/driver/parse_source_batch/batch.rs:141` calls `source_lexer::lex_file` for each `LoadedSource`, getting a `LexedSource` and reusing the token buffer.
2. The same loop (`batch.rs:149`) calls `source_parser::parse_file`, which runs `parse_into` and adds the file's root items to a shared `SyntaxTrees`.
3. `S/driver/resolve_and_type.rs:139-262` builds a `ResolutionRequest` (syntax, source map, top-level bindings, optional retained base) and calls `resolution::resolve_deferred`: syntax-to-syntax preparation (`declarations::prepare`), declaration indexing, symbol assignment, operator homes. The result is a `DeferredResolvedFrontier` with machine bodies pending.
4. The driver picks bodies by scope (`pending_machines_in`, `resolve_and_type.rs:218,266,296,331`) and calls `complete_machine_bodies`; generated source goes through `resolve_deferred_extension`.
5. `typing::lower_symbol_resolved_trees_to_seeded_base` (`resolve_and_type.rs:209`) types the resolved trees into a `SeededTypingBase`; later completions go through `SeededTypingBase::complete_bodies` and `append_resolved`.
6. `SeededTypingBase::into_typed` yields `TypedTrees`; `S/driver/judge_lowered_source.rs:44` calls `prepare_typed_trees`, which returns `PreparedTypedTrees` for stage 05 (outside this area).
