## 1. What this area does

This area holds the data forms that the source half of the compiler passes from stage to stage: captured source bytes, tokens, syntax trees, symbol-resolved trees with their symbol table, typed trees, prepared typed trees, the lowered program the checker reads, the checked program, and the side records published beside them (lowered-source publication, provider demand for one target, provider choices retained from a dependency's Build, compile-time evaluation accounting). Input is `LoadedSources` (`R/source-files/source_files.rs:37`); output is `CheckedProgram` (`R/checked-program/checked_program.rs:17`), which stage 07 turns into Psi. Three products can be built only with a zero-sized "issuer" value that only the producing stage links (`PreparationIssuer`, `LoweringIssuer`, `CheckerIssuer`); `tools/xtask/src/boundary/linear_pipeline.rs:112-139` enforces who links them (crate map, read). The area is about 136,000 lines in 20 crates. It is not only row types: `typed-trees` (92,647 lines) holds the type-identity, callable-application, operator-selection and service-catalog algorithms, and the symbol table holds all name lookup.
