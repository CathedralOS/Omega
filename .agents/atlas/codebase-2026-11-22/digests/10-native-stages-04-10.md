# Digest: 10-native-stages-04-10

Paths are relative to `source-rust/subsystems/compiler/psi-to-native/pipeline/`. Short forms:
`S04` = `04_abstract-operations-to-target-operations/src/`, `S05` = `05_target-operations-to-selected-instructions/src/` (`SG` = its `instruction_selection/selection_scalar_graph.rs`, `ST` = `selection_structural.rs`, `VB` = `selection_views_and_bytes.rs`), `A06` = `06_selected-instructions-to-selected-instructions/analyses/src/`, `S06` = `06_.../src/selected_rewrites/`, `S07` = `07_selected-instructions-to-register-homes/src/allocation/`, `S08` = `08_register-homes-to-post-allocation-machine/src/machine/`, `S09` = `09_post-allocation-machine-to-framed-machine/src/`, `EP` = `09_.../entry-planning/src/`, `S10` = `10_framed-machine-to-bound-framed-machine/src/`.

Words used below. A **target row** is one `TargetUnitOperation` or `TargetControlTerminator` that stage 04 lowering writes. The **audit** is stage 04's independent validator: it re-derives each target row from the abstract operation and the optimization unit and compares. A **custody error** is `LegalizationError::custody()`, the one error the audit raises for almost every mismatch. A **home** is the physical register view (or stack slot) a virtual register is given. **Fail-open** means the code accepts, or skips a check, when a lookup finds nothing.

## 1. What this area does

These nine crates turn one function body from target-neutral abstract operations into a body with machine instructions, physical registers and a stack frame, ready for stage 11 to encode. The driver `driver/compile_body.rs` calls them in order: stage 04 at `:38`, 05 at `:116`, 06 at `:134`, 07 at `:137`, 08 at `:140`, 09 at `:143`, entry-planning at `:159`, stage 10 at `:98` (crate map, read). The input is `OptimizedAbstractBody` from stage 03; the output is `BoundFunctionBody`. Every stage refuses what it does not recognise with a mostly cause-less error, and most stages are an admit-then-rewrite-then-seal pattern whose independent re-check runs only on explicit validator request or in tests.

Out: `NativeBodyPlan` wrapping a `PreparedExecutionPlan` that stage 05 reads alone. ## 2. How it decides

**Identity (most judgments, every crate).** Keys are `PlaceId`, `ValueId`, `OperationId`, `BlockId`, `EdgeId`, `MachineId`, `BoundaryMachineId`, `StructuralTypeId`, virtual-register id, register-unit id and view id, never display names, except where listed under spelling.
- Stage 04 lowering: settlements and installations keyed on `(MachineId, InvocationSite, BoundaryMachineId)` (`S04/target_lowering/coordination.rs:440-475`); every `ValueId` and `PlaceId` defined once (`control_flow.rs:2876-2986`). Refusal is `LoweringError::unsupported_control_flow(machine)` (`model.rs:380`), which records only the machine and Rust call site: 152 uses across the three `control_flow*.rs` files (79+49+24, unit_010).
- Stage 04 audit: proof facts looked up by exact `(machine, owner, obligation)` binary search (`legalization.rs:259-262`); rows compared whole with a re-derived expectation (`legalization_target.rs:35-43`, `:313-315`); 186 custody errors in `legalization_target.rs` (grep, unit_010). `ModuleTypes` accepted only if Psi identity and `std::ptr::eq` on the module owner hold (`S04/preparation/mod.rs:76-77`). Reference custody keys occurrences on `(place, path, formation)` (`legalization_reference_custody.rs:1977-1989`).
- Stage 05: `BoundExecutionPlan::bind` compares Psi, target and entry machine (`S05/input.rs:39-53`); values resolved by linear scan of `Builder.definitions` by `ValueId` (`SG:7917-7930`); places by linear scan of `transport.pointers` by `PlaceId` (`ST:5490-5495`); "take `next()`, require `next().is_none()`" uniqueness idiom throughout `selection_inputs.rs` (`:96-97`, `:1606-1609`, `:3203-3204`).
- Stage 06/analyses: candidate views keyed on architectural-unit masks, block id and point number (`A06/allocation_legality.rs:798-803`); machine-effect declaration keyed on `(machine_semantic_kind, constraint)` with duplicates refused (`A06/machine_effects.rs:129-139`); per-function reuse keyed on `Arc` pointer equality then value equality (`A06/lib.rs:870-876`, `:963-996`).
- Stage 07: selection order `(viable count, Reverse(degree), first_point, leader vreg, domain_index)` (`S07/home_assignment.rs:980`); conflicts by physical-unit overlap (`:2105-2108`).
- Stage 08: about 25 identity fields compared in `validate_roots` (`S08/plan.rs:255-331`); exactly one applicable alternative (`:626-630`).
- Stage 09/EP/10: memory-access rows by `(instruction, origin, place, offset, role)` (`S09/foreign_call_plans.rs:562-598`); guard rows by `(MachineId, OperationId, placement_index)` (`S10/lib.rs:89-126`).

**Place and path.** Facts, loans and homes are tracked at field paths. `legalization_reference_custody.rs` keeps `leaves: BTreeMap<(PlaceId, Vec<StructuralPathSegment>), Leaf>` (`:3854`) and decides overlap with `reference_origin_paths_may_overlap` (`:983`, `:3763`); `references.rs` does the lowering-side equivalent with the `Referent` segment as the crossing point (`S04/target_lowering/references.rs:257,593,841,1113`). `runtime_storage_projection` walks each segment and refuses `AllElements`, `RepresentationView`, `Referent`, `FixedRange` (`S04/target_lowering/structural_layout.rs:868-906`). Stage 05 place-backed homes: incoming pointer, else exactly one local slot for the place (`ST:5496-5514`).

**Value.** Integer types and widths, overflow policy, literal values and offsets decide many cases (listed in section 4). Examples: exact-policy arithmetic always needs an accepted fact (`S04/preparation/legalization_instruction.rs:1010-1012`); proof-bearing arithmetic is never constant-folded (`S04/target_lowering/scalar.rs:2586-2592`); shifts fold only under `Wrapping` with two immediates (`scalar.rs:2964-2980`); aarch64 address folding needs `combined / scale <= 4095`, x86 `<= i32::MAX` (`S06/address_and_load_rewrites.rs:61-72`); literal fold bound `Encoding(4095)` is applied on every target including x86_64 (`S06/literal_fold_rewrites.rs:3757-3763`, all 23 rows `TargetIndependent`).

**Position.** Joins by position rather than identity, with an identity check beside them:
- Stage 04 audit joins functions by position plus machine check (`legalization_source.rs:47-50`), blocks and instructions by position (`:3491`, `:3516`), target blocks to source blocks by `zip` then id check (`legalization_target.rs:1416`, `:1449`).
- Cleanup rows split at "first `CleanupCall`" (`legalization_source.rs:3501-3515`; `function_contract.rs:30-33`; `legalization_control.rs:397-401`).
- Static-interrupt installation takes its two helper calls from argument positions 0 and 5 in four places (`legalization_source.rs:2155`, `legalization_scalar_graph.rs:3951-3956`, `legalization_instruction.rs:106`, `control_flow_operations.rs:1045-1056`); selection indexes a six-argument roster by position (`S05/instruction_selection/selection_interrupts.rs:916`, `:1552`).
- `literal_compare_input::folded_literal` requires the literal directly before the compare (`S05/instruction_selection/selection_inputs.rs:2951-3002`); `block_order::ordered_blocks` prefers the lowest-index ready block (`S05/instruction_selection/selection.rs:148-207`); register argument order sorts floats last (`selection_call_abi.rs:1750-1752`); `before_fixed_use` picks the first fixed-view use in block order (`S07/runtime_spill_and_split.rs:5273-5298`); publication sites are `(provenance, ordinal)` (`S04/preparation/publication.rs:69-72`).

**Spelling (display names or strings).**
- `coordination.rs:666-667` compares `reason == "view discard has no affine descriptor carrier"` (debug trace only).
- `selection_access_lifecycles.rs:6538` joins layout placements by `entry.field == slot.field()`, where `LayoutFieldEntryReport.field` is a `String` (`psi/layouts/geometry/layout_reports.rs:55`, checked); the schema field itself is found by id (`:6530`).
- `A06/legality.rs:170-186` selects rematerialization views by the names `"rax"`, `"rcx"`, `"x0"`, `"x1"`.
- `EP/bridge_values.rs:244-267` and `S09/frame_protocol.rs:129-176` map machine registers to register-model views by formatted names (`x{n}`, `d{n}`, `xmm{n}`, a 16-name x86 table).
- Windows imports are chosen by literal names (`EP/hosted_entry.rs:329-345`); `model.rs:363-375` uses a display name only in a message.
