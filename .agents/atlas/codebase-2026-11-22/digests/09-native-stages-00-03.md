Words used below. **Psi** is the portable compiled program; **Terminal Psi** is its last portable form, which these stages read as a `TerminalModule`. A **boundary** is a point where the program calls something it does not define (a provider, foreign function, syscall or compiler primitive). A **provider** is the body or binding that supplies a boundary. **Identity text** is a string stored in the module's identity table and compared with `module.identities.text(id) == Some(..)`. A **rule** in stage 03 proposes rewrite candidates; the **pass manager** validates and commits them.

## 1. What this area does

This is the front of the native compiler. It takes a Psi program the receiving host has authorized, decides which providers serve each reachable boundary on one target, lowers the reachable checked bodies into target-neutral abstract operations, and optionally optimizes them. In: a `CanonicalTerminalArtifact` with its `AuthorizedTerminalArtifact`, a provider demand, the host's provider installation and a target profile. Out: a `ValidatedOptimizedAbstractPlan` (`S3/publication.rs:233`) that stage 04 lowers further (`DRV/compile_body.rs:30-38`). The area is 74 files and 38,911 lines in 8 crates; stage 03 alone is 21,989 lines. The driver calls each stage; the stages do not call each other except through their output types (crate map §1).

**Stage 00 root, `psi-to-admitted-native-inputs` (1 file, 98 lines).** In: an `AuthorizedTerminalArtifact` and an `IssuedProviderDemand`. Out: `AdmittedProviderDemand`. `admit` (`S0/admit.rs:13`) picks the artifact the demand names and calls `authorization.require_artifact` (`:21`), which compares manifests; a changed debug map is refused (test `:92-96`).

**Stage 00, `host-provider-inputs` (1 file, 210 lines).** Holds what the host supplies per program and target: Build binding results, package permissions, accepted semantic bindings. `TargetProviderInstallation::attach` (`S0/host-providers/installation.rs:94`) refuses a different manifest identity (`:99`) or profile (`:102`).

**Stage 00, `provider-demand` (1 file, 176 lines).** The closed set of logical provider choices for one program, `Unscoped` or `Target` (`S0/provider-demand/demand.rs:17`).
