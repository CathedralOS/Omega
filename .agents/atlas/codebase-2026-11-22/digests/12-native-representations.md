## Verified follow-ups

- **Saved memory fences.** Section 10, finding 6 predicted that the shared tag would cause a refusal. Reopening a valid saved plan showed that the reader could instead accept a fence as a table read. Format v52 gives these effects distinct tags. A saved fence now reopens as a fence, and the reader rejects v51 plans. [#5185](https://github.com/CathedralOS/Omega/pull/5185)
- **Register and spill-slot identity.** The prefix reuse described under section 5 allowed an edit to an existing slot to keep its old digest. Changing a slot from 8 to 16 bytes reproduced it. The allocator now uses append-only access when preserving a prefix. Editing an existing row invalidates the cached digest, and the regression checks it against a fresh encoding. [#5190](https://github.com/CathedralOS/Omega/pull/5190)

## 1. What this area does

This area holds the data forms the native half of the compiler (`psi-to-native`) hands from one numbered stage to the next, plus the independent checkers that judge some of those forms. The forms run in pipeline order: a target-bound program (stage 01 output), the abstract operation plan and its verified wrapper (stage 02), the optimization unit and its checker (stage 03), target and legalized operations (stage 04), selected instructions (stages 05-06), register homes (stage 07), the post-allocation machine (stage 08), frame recipes and the framed, bound, encoded, resolved and fragment forms of machine code (stages 09-13). Beside them sit shared record crates: operand and evidence records, optimization rule and identity records, the structural type catalog and its queries, function identity, and program-entry contracts. Input is a published Psi artifact plus target and provider choices; output is a `FunctionFragmentEmissionPlan` (`MC/fragments.rs:41`) and a `RelocationFreeTextSectionPlacement` (`MC/layout/text_section.rs:53`) that stage 13/14 place into objects. The area is 30 crates (crate map). It is not only row types: about 46,000 lines sit in one checker crate (`optimization-unit-semantics`), and most other crates carry a hand-written canonical byte encoder, a SHA-256 identity and often a versioned wire codec for each form.
