## 1. What this area does

The package manager turns the dependency rows a project's `build.omg` declares into an exact, read-only source graph, collects the compiler's findings about each package, records the owner's accept or reject decision for each finding, and writes `build.omg` and `omega.lock` together as one pair. It does not run Build or the compiler: the caller (`omega` application, `project-build`) runs each Build and compilation while the package manager holds the project lock, and hands the results back. Input is a project directory, local, workspace and Git dependency declarations, and during install or update the Build results and compiler review facts. Output is captured read-only source trees, a resolved package closure, one lock section per target (`PackageLockTarget`), editable review files, and prepared products for compilation. The area is six crates under `PM/` plus two compiler test files. Its central rule is that every recovery of stored bytes (lock text, policy baselines, Git objects, snapshots) re-derives the value and compares it byte for byte with what was stored; the compiled-review cache is the one store whose integrity is only a self-hash (082, five things #1).
