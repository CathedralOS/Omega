## Front-half handoffs

The [boundary survey](../boundaries/front_half.md#handoffs-where-nothing-independent-checks-the-value) identifies seven handoffs with limited independent validation. Those are leads. For each, test whether a reachable producer or a supported artifact reader can supply a bad value, and whether the owning consumer relies on that value.

| Handoff | Candidate case |
| --- | --- |
| 00 → 01 | Change a token span or kind and check which producer or consumer owns detection. |
| 01 → 02 | Distinguish a stale syntax handle read from an invalid but supported optional handle. |
| 02 → 03 | The binder-position regression above covers the shared lookup. Reach rows and selection identities need separate cases. |
| 03 → 04 | Apply specialization twice to a state that needs specialization and check whether the ordinary route can present it twice. |
| 04 → 05 | Change a typed state reference while keeping value inputs valid. Trace the first stage whose contract requires a refusal. |
| 05 → 06 | Change an owed row and a suspension frontier independently. Compare each checker judgment with the original. |
| 06 → 07 | Change a provider or selection identity while preserving counts. Check publication admission and companion validation independently. |

### Additional dispositions at `dba3c24f0521`

- **Unknown service reach row, [05:130](../digests/05-source-representations.md?plain=1#L130).** The accessor returns an empty slice for an unknown ID. Two release paths reject a nonzero out-of-range row before the accessor matters: stage 05's `read/services.rs::finite_reach` and typed callable identity's `runtime_callable_identity.rs::reach`. The latter preserves zero as the explicit open-row case. Other callers, including `service_declarations.rs::service_reach_names` if handed an invalid row, still require producer-to-consumer review.
- **Empty completion account, [05:150](../digests/05-source-representations.md?plain=1#L150).** The only production use of `has_complete_usage` controls retention of a completed source input. The driver independently matches the completion input, validates every charge before retention and validates it again on reuse in `resolve_and_type/authored_completion.rs`. An input that performed no evaluated work can have zero receipts. A missing charge for work actually done would be a separate producer defect and needs a reproducer.
- **Retained span candidates, [05:130](../digests/05-source-representations.md?plain=1#L130).** `rejoin_declaration` rechecks each candidate's kind, exact span and source capture. Even if the candidate cache were stale, this call could report a missing valid candidate; the stale list alone cannot authorize an unrelated declaration.

### Additional dispositions at `6223a0344397`

- **Stage 05 empty refusal vector, [03:203](../digests/03-source-stage-05.md?plain=1#L203).** Closed for the production `prepare_compilation` route. `elaborate_source_for` wraps individual errors in a one-element vector, checks that collected diagnostics are nonempty, and starts finalization errors with the first refusal before appending the rest. The caller's `remove(0)` therefore has an element on every error path.
- **Trait parents dropped from a walk, [05:190](../digests/05-source-representations.md?plain=1#L190).** Stage 05's selected service reader propagates `parent_scopes` errors. The separate `collect_boundary_signatures` path in `typed-trees/definitions/service_declarations.rs` uses `visit_parents_first`; that walk continues past a failed parent substitution. The remaining probe is a reachable incomplete generic parent at the calling-policy census and whether the whole product can finish with that parent's signature absent.
- **Boundary results with qualified fields, [04:251](../digests/04-source-stages-06-07.md?plain=1#L251), also [06's package audit](06-15-build-packages.md).** The audit of a package returning an Envelope with differently qualified Ticket fields stopped in stage 06 with `boundary call needs its structural qualification proof`. The call formation judgment compares each result path and domain to the boundary, `structural_qualifications.rs` checks each body's structural return against its declared result, and `BoundaryMachineResult::accepts_provider_result` requires every declared field/domain pair on a provider candidate. Stage 06 now admits projected result domains. The source fixture `boundary_results_preserve_domains_on_the_declared_fields` accepts the forwarding call and rejects exchanged domains on a caller result and on a provider candidate. All 81 boundary-call tests passed. Whole-result domains have distinct establishment-authority rules. Additional input obligations and normal qualification changes also retain their own restrictions.
- **Installation-bound reach, [04:296–297](../digests/04-source-stages-06-07.md?plain=1#L296-L297).** `fixed_refinement_reach` can replace an exceeding reach only for the designated refinement caller. It keeps an ordinary boundary's published ceiling, preserves explicit machine contracts and returns an error for missing declarations. A discriminating case is an inferred helper that reaches both a fixed service and an installation-bound child: the fixed service must still exceed a smaller caller ceiling. The conditional child needs a separate installation check.
- **Visible trait selection, [02:307](../digests/02-source-stages-00-04.md?plain=1#L307).** `select_visible_trait` prefers the reference file, then a visible declaration in the same stratum, then the first visible candidate. Its production consumer seeds a generic evidence binder's children via `insert_evidence_children`. The later constant evidence lookup checks the resolved symbol. Give two visible same-named traits different requirements, reverse file order, and inspect whether the binder gains the wrong child before the later exact lookup.

- **Typed program identity equality, [05:182](../digests/05-source-representations.md?plain=1#L182).** The equality implementation omits transient identity from structural comparisons of typed trees. Prepared value lookup and both constant-invocation checks use the underlying number via identity.get() to reject values from another program. The constant equality result does not authorize cross-program reuse on those paths.
