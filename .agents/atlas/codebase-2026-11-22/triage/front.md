## Front-half handoffs

The [boundary survey](../boundaries/front_half.md#handoffs-where-nothing-independent-checks-the-value) identifies seven handoffs with limited independent validation. Those are leads. For each, test whether a reachable producer or a supported artifact reader can supply a bad value, and whether the owning consumer relies on that value.

| Handoff | Candidate case |
| --- | --- |
| 00 → 01 | Change a token span or kind and check which producer or consumer owns detection. |
| 01 → 02 | Distinguish a stale syntax handle read from an invalid but supported optional handle. |
| 02 → 03 | The binder-position regression above covers the shared lookup. Reach rows and selection identities need separate cases. |
| 03 → 04 | Apply specialization twice to a state that needs specialization and check whether the ordinary route can present it twice. |
| 04 → 05 | Change a typed state reference while keeping value inputs valid. Trace the first stage whose contract requires a refusal. |
| 05 → 06 | Change an owed row and a suspension frontier independently. Compare each checker judgment with the original. |
| 06 → 07 | Change a provider or selection identity while preserving counts. Check publication admission and companion validation independently. |

### Additional dispositions at `dba3c24f0521`

- **Unknown service reach row, [05:130](../digests/05-source-representations.md?plain=1#L130).** The accessor returns an empty slice for an unknown ID. Two release paths reject a nonzero out-of-range row before the accessor matters: stage 05's `read/services.rs::finite_reach` and typed callable identity's `runtime_callable_identity.rs::reach`. The latter preserves zero as the explicit open-row case. Other callers, including `service_declarations.rs::service_reach_names` if handed an invalid row, still require producer-to-consumer review.
- **Empty completion account, [05:150](../digests/05-source-representations.md?plain=1#L150).** The only production use of `has_complete_usage` controls retention of a completed source input. The driver independently matches the completion input, validates every charge before retention and validates it again on reuse in `resolve_and_type/authored_completion.rs`. An input that performed no evaluated work can have zero receipts. A missing charge for work actually done would be a separate producer defect and needs a reproducer.
- **Retained span candidates, [05:130](../digests/05-source-representations.md?plain=1#L130).** `rejoin_declaration` rechecks each candidate's kind, exact span and source capture. Even if the candidate cache were stale, this call could report a missing valid candidate; the stale list alone cannot authorize an unrelated declaration.
