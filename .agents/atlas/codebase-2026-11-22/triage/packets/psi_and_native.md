# Psi and native boundary packet

This packet gives every claim in [the Psi/native boundary note](../../boundaries/psi_and_native.md) a disposition. It found one latent miscompile in native stage 08, repaired in this PR. It also found that `main` did not compile two native crates after #5393; this PR repairs those too. Every other lead is intended behavior, a duplicate of an earlier ledger row, a tracked feature gap, or one of four items listed under "Still open" below.

The note was written at `4f3c255d`. Every code check below was made at the common baseline `24ad2700685e6cc6062026c87ed5fd24ed415265` unless a row names another revision. This packet joins the rows already in the [Psi and native ledger](../07-13-psi-and-native.md) rather than repeating them.

Outcomes: **fixed** (repaired, here or in a named PR), **intended** (the code does what its contract says), **duplicate** (another ledger row already settles it), **feature gap** (missing behavior that a spec page or `TASKS.md` tracks), **reproduced** (a fixture shows the defect), **still open** (not settled; the next check is named).

## Fixed in this PR

### Stage 08 read liveness for the wrong unit set (handoff 10)

Stage 08's declared-form rule could rewrite an instruction into a form that clobbers a register unit, such as the flags, while a later instruction still reads that unit. `rewrite_declared_forms` (`PN/pipeline/08_register-homes-to-post-allocation-machine/src/machine/optimization.rs:283-366`) builds one liveness table per function, for the units the *first* candidate's form adds. It reused that table for every later candidate. The only guard was `debug_assert_eq!(*units, extra)`, which release builds do not compile. The added units depend on the instruction: `extra_units` removes the units the instruction already writes. So two candidates for the same rule can add different units.

- **Original claim:** note handoff 10, "What stage 09 trusts"; digest 10 line 188 and §10 item 14 (records `unit_015`), status "open".
- **Contract:** a declared form may be selected only when the units it adds are dead after the instruction (the doc on `UnitLivenessTable` and the existing fixtures `a_later_flag_reader_in_the_block_keeps_the_baseline` and `flags_live_into_a_successor_block_keep_the_baseline`).
- **Reproducer:** fixture `each_candidate_is_judged_by_the_units_its_own_form_adds` in the same file. Instruction 1 is a zero materialization that already writes the flags, so its x86 xor-zero form adds no units. Instruction 2 is a zero materialization whose form adds the flags, and instruction 3 reads the flags. Instruction 1 must take the xor form; instruction 2 must keep the baseline.
- **Before:** the debug test build stops at the `debug_assert_eq!` (`left: []`, `right: [RegisterUnitId(99)]`); the other 9 tests in the module pass. Reading the code, a release build skips the assertion and asks the table built for the empty set about instruction 2. An empty set is never read and never fully rewritten, so `live_after` reports it dead, and the rule commits the flag-clobbering form ahead of the flag reader. The release build was not run.
- **After:** all 10 tests in `machine::optimization` pass.
- **Repair:** the cached table now records the units it was built for. A candidate that adds different units rebuilds the table. The xor-zero rule normally adds only the flags, so the common case still builds one table per function.
- **Reach:** the only in-tree rule, `X86SelectXorZeroI64MaterializationV1`, adds `{flags}` unless the instruction already writes them. No shipped selection was shown to produce the first instruction's shape. The repair removes the dependence on that accident.

### `main` did not compile two native crates after #5393

#5393 added `Proposition::DeclarationIdentity` without extending two exhaustive matches. While building the stage 08 fixture, `mbx test` stopped with E0004 in `optimization-unit` (`src/identity.rs`, `encode_proposition`) and then in `optimization-unit-semantics` (`src/unit_validation.rs`, `collect` in the claim-root walk). Every crate that depends on them, including native stages 03 to 15, failed to build on `main` at `a0152d26`.

- The unit identity encoder now gives the new proposition its own tag (23) and encodes every clause value, carrier, operand and side index. Portable Psi refuses this proposition (`declaration-encoding/src/terms/proposition.rs`: "unpublished declaration Identity in a portable proposition"). A distinct encoding still keeps the identity total and stops it colliding with another proposition.
- The claim-root walk now collects the roots of the clause's scalar and input operands, as `semantic-records` does when it validates the same clause.
