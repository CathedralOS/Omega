# Atlas packet unit_023: object and image emission in native stage 15

Packet complete. Every claim in `records/unit_023.md` has a disposition below. One claim was a
real wrong result. The PE writer turned a section larger than the 32-bit PE address space into a
smaller one instead of refusing it: a 4 GiB `.bss` produced an image whose `.bss` header and
`SizeOfImage` described zero bytes of zero-fill. The writer now refuses that image, with a
boundary fixture (claim 1). Four claims stay open, listed individually under **Open claims**.
None of the four is a demonstrated wrong result.

Evidence baseline: the assigned common baseline is `24ad2700685e6cc6062026c87ed5fd24ed415265`.
That revision and the next `main` both failed to compile `optimization-unit`. The fix and the
surrounding checks therefore ran on `origin/main` at `7105e9e3` (#5435). Since the survey, merged
changes touched three of the unit's files. [#5392](https://github.com/CathedralOS/Omega/pull/5392)
changed the `image/src/lib.rs` patch-bounds messages. Windows ARM64 support changed `image-pe/src/lib.rs`
and `image-emission/src/image.rs` (`can_emit_executable_image` now also lists COFF AArch64). Line
numbers in `image-macho/src/dyld_linking.rs` are about 80 lower than the record's (2,623 lines,
not 2,702). `units/unit_023.tsv` lists 40 whole files. `second_pass_ranges.tsv` has no gap packet
for unit 23, so this packet covers the whole unit.

Paths: `P15` = `source-rust/subsystems/compiler/psi-to-native/pipeline/15_objects-to-image`,
`R` = `records/unit_023.md` (section and item, for example `R` A8.9 is section A8, item 9).

## Validation

- Before the fix, on `origin/main` `885c06d0`: `mbx test -p image-pe --lib image_extent_beyond` failed. With
  the order in the committed fixture, the case one byte past the last page panicked with
  `attempt to multiply with overflow` at `align_to_u32`. With the `1 << 32` case first, the call returned
  `Ok(ExecutableImageOutput { …, bss_bytes: 4294967296, … })`, with a zero `.bss` virtual size and
  `SizeOfImage = 0x2000`.
- After the fix, on `origin/main` `7105e9e3`: `mbx test -p image-pe` passed 29 of 29, including the new
  fixture. `mbx clippy -p image-pe --all-targets -- -D warnings` was clean, and
  `rustfmt --edition 2024 --check` on the crate's sources passed.
- The small surrounding check is blocked by `main`. `mbx clippy -p image-emission --all-targets` cannot
  build `optimization-unit` on `7105e9e3`: `error: unreachable pattern` for a duplicated
  `Proposition::DeclarationIdentity` arm (`optimization-unit/src/identity.rs:382`, `:472`). That arm came
  from two separate merges, and open PR #5432 says it restores the optimization-unit build. This PR does
  not touch that crate. The public signature of `emit_pe_executable` and `emit_pe_shared_component` is
  unchanged; only crate-private functions now return `Result`.
- `mbx xtask fmt --check` reports existing drift in `source-rust/application/tests/*.rs`, none of it in files
  this PR touches.
- Open PRs were searched (`gh api search/issues`, `is:pr is:open` for `PE`, `atlas` and `unit_023`), and so were
  the claims board entries for `image-pe`. Neither overlaps this repair.
