# Triage packet: unit 027, gap 012

The unit validator in `optimization-unit-semantics` refused every valid optimization unit containing a range-checked primitive local, a range-checked write-only primitive store, or an atomic event with a resident obligation. It rebuilt the function's fact index from its own, shorter list of obligation-bearing operations. Unit construction indexes those obligations, so the two indexes differed and validation failed with `FactIndexMismatch`. After a rewrite, `revalidate_rewrite_output` also replaced the constructed index with the shorter one, dropping those facts. This packet's repair makes the validator rebuild the index with the constructor's own `collect_fact`.

This packet settles the claims in [records/unit_027_gap_012.md](../../records/unit_027_gap_012.md), the second-pass read of `unit_validation.rs` lines 3601-9600 in area 12 (native representations). Baseline: `24ad2700685e6cc6062026c87ed5fd24ed415265`. The file is unchanged from the baseline through `origin/main` at `08a667b1`, so every line number below is the baseline's. Paths without a directory are in `source-rust/subsystems/compiler/psi-to-native/representations/abstract-operations/optimization-unit-semantics/src/`.

Packet complete. Every claim in the record has a row below. Four remain open and are listed under [Unresolved claims](#unresolved-claims).

## Unresolved claims

1. **Stale length on a whole bounded owner** (record §4 item 4; "five things" item 2). No freshness walk was found for `ByteSequenceRead`, `ByteSequenceWrite` or the store pair after a `ByteSequenceStore` replacement. Next action: build the fixture described in the ledger row, then extend `validate_whole_freshness` if the fixture is accepted.
2. **Places the availability check skips** (record §14a). First, `reconstruct_declared_places` adds `AtomicEvent::place()`, the root of the atomic location being used, to the known places, and the event gives that root no availability producer. Second, the producer table takes operation results from `structural_operation_result_contract` (7010-7020), which returns `None` for a view result (`ViewRecipe` role) when `view_access` fails. Such a place is skipped rather than refused. Neither case was traced to another validator that refuses it.
3. **Unlisted operations in `validate_structural_root_operations`** (record §14d, `_ => {}` at 8833). Needs a per-operation trace to the validator that checks each one.
4. **Duplicated transfer rules** (record §15 item 5) and **linear producer scans** ("five things" item 1). These are cleanup and cost items with no wrong verdict.
