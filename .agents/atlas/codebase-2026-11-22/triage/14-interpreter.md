| Section 5 item 14 and section 6 describe the same RFLAGS write. | The wire validator checks the declared U64 operand. Execution now also reads the register image through the existing typed unsigned operand reader. Missing, noninteger, wrong-width and overflowing runtime values stop the operation before it changes the flags. | A direct interpreter-frame fixture completed normally with no operand before the fix. It now refuses each malformed frame, preserves flags on error, and sets or clears the carry bit from a valid U64 while retaining the interrupt-enable bit. These tests exercise instruction execution with controlled frame values. |
| Digest line 173. The implementation selector wrote an unsigned table index into any declared integer result. | Psi now requires the same fixed unsigned 64-bit result as native selector validation, and still requires an existing table. | The instruction fixture previously accepted table 2 in a one-bit result. It checks the returned table for u64 and absence of a result for a narrow, signed or address type and for a missing table. The operation is the legacy wire selector described in the [Psi encoding](../../../../wiki/spec/terminal-psi/encoding.md). |
| Digest line 175. The survey record said a structural leaf copy whose source and result types differ falls through to checks that refuse it. | That record was wrong at the survey commit. A mismatch that is not a quotient or shared-descriptor copy goes to `byte_carrier_leaf_copy`, which reads a scalar record out of a u8 array. That function now refuses a result with qualifications or projected qualifications, and checks each decoded leaf with `satisfies_field`. Before, it decoded `BoundedInteger` fields without a range check and published the record with no qualifications whatever the result declared. The [recast spec](../../../../wiki/spec/layouts/recasts.md#shared-and-mutable-views) says raw bytes establish no typed predicates. | The instruction fixture `byte_carrier_leaf_copy_tests` reads `record { digit: u8 in 0..=9, raw: u8 }` from bytes. On the parent, the copy accepted digit 10 and a declared domain (two of three tests failed). With the fix, all three pass and 9 and 200 still read back. Open: native admission has the same gap (code repair queue). Also open: which source construct emits this copy, and whether a type-level `requires` on the record needs the same refusal. |
| Digest line 188. A UTF-8-only byte store checked the previous backing for ASCII. | The interpreter now validates the resulting byte sequence before making the write, using at most four bytes of UTF-8 decoding state. An ASCII-only domain separately constrains the new byte through the scalar restriction. | The primitive-store instruction fixture previously accepted replacing B in ASCII ABCD with a lone continuation byte. Its cases compare the actual write and retained backing with standard UTF-8 validation, including multibyte replacements, invalid sequences and truncation. An authored multibyte control with a constant index passed both engines before this repair. This regression isolates the instruction path. |
| Section 5 item 8 and section 6 describe the same continuation handoff. | Checked continuation now refuses a call observer or issued layout target on either frame. Replacing the receiving frame previously discarded its observation request. Keeping the parked frame also carried its issued target into the successor. | The fixture records an integer argument on uninterrupted execution and refuses the same selector on the receiving frame. Layout-target fixtures test both directions and the ordinary unconfigured continuation still completes. |
| Section 5 item 1. A readiness poll defaults to ready. | The digest traces completion separately through the effect handler and `commit_boundary_result`. | The readiness default alone does not demonstrate acceptance of an invalid result. Any proposed defect needs a failing completion case. |
| Host services, digest line 201. The Windows descriptor adapter accepted arbitrary translation modes. | The adapter now returns -1 without changing the descriptor for invalid modes. It reports wide text as the previous mode for all three Unicode selections. Two regression tests cover both state transitions, including independence between descriptors. The installed Windows msvcrt.dll supplied the comparison. | This covers standard descriptor mode state. The public native fixture did not complete successfully on the host. |

## Findings traced to their consumers

| Digest lines | Disposition and evidence |
| --- | --- |
| 160, 213 | Build's source invocation matches a normal completion and projects its value before calling `take_call_observations`. Any other status returns an error. On completion, `invoke_to` first charges result custody through `CallObservations::finish`. The call observation fixture checks the empty drain before execution, actual records on completion, an empty drain after taking them, and an empty drain following a crash. The drain alone does not encode the status. `close` drops the execution frame and its established erased fields; the instance separately exposes `is_closed`. |
| 165 | Entry-result observations name operations in one entry activation. The test `entry_results_ignore_recursive_activation_and_capture_restored_caller` covers the identical operation in a recursive activation and after the caller resumes. `entry_results_missing_occurrence_cannot_use_final_return` checks an absent requested occurrence. |
| 174 | An owned component input that is already a host atom forwards its host identity. `forward_host_atom` sets `opaque_identity` and clears the path, and `ComponentInputCustody` adds no contents. The provider instance records that identity as an `Opaque` payload at the parameter's home in `retain_host_structural_payloads`. That is the carrier. Only unchanged atoms forward. A write marks the payload `Modified` (`invalidate_stored_provenance`). `Materialized` and `Modified` payloads go through `capture_component_contents`, and an owned source with a live loan is refused earlier. Types that need materialized custody never hold an `Opaque` payload. Traced in code only: no interpreter-crate test invokes a component with an owned forwarded atom; component execution is exercised only by the CLI native test `application/tests/independent_component.rs`. |
| 176 | Rechecked on main 81fb091add3: unchanged since the survey. Re-establishing a byte literal in its own activation reuses its existing storage only after checking its allocated identity, structural type, root path, qualifiers and immutable bytes. The instruction test `repeated_literals_keep_their_home_but_nested_calls_get_distinct_storage` distinguishes repetition from a new activation, and passed in this run. The repeat check does not compare `projected_qualifications`, but the literal is minted without them, and the only in-place rewrite of stored values is continuation relocation (`relocate_frame` in `embedding/continuation.rs`), which remaps coordinates into a successor program. Whether relocation can give a literal projected qualifications was not traced. Separately, the interpreter ignores the operation's own `qualifications`: it mints the literal with none. Native admission instead checks them with `byte_literal_qualifications_hold_in`. This fails closed: byte-predicate domains are retested from the bytes at descriptor checks, and other domains are refused for lack of membership. A literal carrying a non-predicate domain would therefore run natively but be refused in Psi. That disagreement needs a failing program before it counts as a defect. |
| 188 | An `AsciiOnly` domain constrains the **new** octet through `primitive_store_restriction` and the interpreter's `satisfies_field` check, with an upper bound of 127. The previous `ValidUtf8` backing scan checked the **existing** bytes. The L6 fixture accepts an ASCII buffer update and refuses replacing an ASCII byte with a lone continuation. Changing only the initial two bytes to the UTF-8 for é in the same 28-byte source buffer caused the source checker to refuse even the unchanged ASCII write at position 13. The primitive-store fixture above covers the resulting bytes. The source refusal depends on loading the index from a sibling field. |
| 197 | `admit_c_word_record` independently checks the native result extent and alignment, the exact field count, each field offset against its ordinal times eight, and the leaf class, size and alignment. An absent authored storage row alone cannot admit the original example with an incorrect **native** offset. |
| 221 | The extent owner test `borrowed_mapping_retains_source_loan_and_shared_polarity` follows a shared mapping through activation and unmapping. It verifies that the destination is returned and that the borrowed source is never yielded as owned. The owned mapping has a separate two-authority round-trip test. |
