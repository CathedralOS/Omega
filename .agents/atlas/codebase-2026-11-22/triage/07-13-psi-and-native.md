## Boundary follow-ups

The [17 handoffs](../boundaries/psi_and_native.md) describe several different contracts. These are candidate fixtures drawn from the survey. The stage 13 case above has a red-to-green result.

| Handoffs | Receiver question for the next fixture |
| --- | --- |
| 1–3, Psi authorization and provider scope | With the same semantic payload, do fresh publication and saved-artifact admission disagree? Exercise the field named by the report. For target scope and evidence seals, vary the target or seal alone. |
| 4–6, abstract operations and target lowering | Given one admitted operation and one selected rewrite, which source fact or runtime-evidence context does the receiving check compare? A mismatch in that fact should identify the responsible receiver. |
| 7–10, instruction selection through frames | For one selected function, vary a live register home or instruction constraint while retaining the other inputs. Check the documented allocator or audit invariant and the observing stage. |
| 11–14, entry planning through placement | Compare a private reference, encoded row or branch displacement with its originating instruction. Record whether construction, ordinary admission or an explicit audit detects the disagreement. |
| 15, placed functions to objects | The stage 13 fixture above covers foreign-call fragment evidence. A second defect let a changed callback section offset retain the same text-section identity. [#5280](https://github.com/CathedralOS/Omega/pull/5280) binds callback materializations and rejects the one-byte change during placed-call replay. |
| 16–17, object publication and final images | Trace the specific relocation under review through object publication and the format writer; a fixture must distinguish an illegal field or emitted byte from a valid case with limited optional audit evidence. |
