# Boundary note: source stages 00 to 07

This note says, for each handoff between consecutive source stages, what crosses, what the receiver takes on trust, what is checked and by whom, and where information reaches a later stage by some other way than the handed-over value. The source driver (`S/driver/`) sits between every pair of stages, so several handoffs pass through driver code that changes the value on the way.

Path shorthands: `S/` = `source-rust/subsystems/compiler/source-to-psi/`; `P00/` to `P07/` = `S/pipeline/00_source-files-to-tokens/` ... `S/pipeline/07_checked-program-to-psi/`; `R/` = `S/representations/`; `PSI/` = `source-rust/subsystems/compiler/psi/`.

Marks: "(code `file:line`)" means I opened that line at this commit. "(record: name)" means the claim comes from the named digest, crate map or record and I did not reopen it. "Suspected", "inferred" and "not traced" keep the readers' meaning: suspected and inferred are not confirmed in code; not traced means nobody followed the value to its consumer.

Words used here:
- **Independent check**: a check written in a different crate or module from the code that produced the value, deciding from the value alone. A check that calls the same shared helper the producer called, or the producer's own type's equality, is marked **same helper** instead.
- **Issuer**: a zero-sized capability value; only the producing stage links the crate that supplies it, so only that stage can construct the product. It guards who builds a value, not what the value contains.

## 00 to 01: lexer to parser

1. **What crosses.** `source_lexer::lex_file` returns a `LexedSource` with `source_id`, `path`, `origin`, `scope` and `tokens: TokenStream<'static>` (code `P00/lexer.rs:48-65`). `TokenStream` holds the source text, a `Vec<Token>` of kind plus span, and decoded string-literal bytes (code `R/tokens/token_stream.rs:15-21`). The driver calls `lex_file` then `source_parser::parse_file` on one file at a time, recycling the token buffer (code `S/driver/parse_source_batch/batch.rs:139-155`).
2. **What the parser trusts.** That the text is UTF-8: the lexer's comment says source loading has already admitted it, and the type is `&str` (code `P00/lexer.rs:83-84`, `:68-71`). That every token span lies inside the text: `spelling` slices `&source_text()[span.start..span.end]` with no check of its own (code `R/tokens/token_stream.rs:161-165`). That the token kinds and their order are right; the parser consumes them as given (code `P01/parser.rs:57-85`).
3. **What is checked.** `retain_source` asserts that the retained text is the exact pointer the stream was lexed from (code `R/tokens/token_stream.rs:130-134`), and `push_source` asserts that a string literal carries decoded bytes (code `:99-104`). Both run inside the lexer's own call, in the representation crate the lexer writes through, so they are the producer's own guards. The driver reports a lexical error before any parse error on the same page (code `S/driver/parse_source_batch/batch.rs:100-114`). The lexer reports only the first lexical error (record: digest 02, `P00/lexer.rs:231`). Nothing independent re-checks the token stream.
4. **Other routes.** A retained parse skips stages 00 and 01 for a file whose text equals the retained unit's text (code `S/driver/parse_source_batch.rs:36-43`). The retained page is relocated to new coordinates by `at_coordinates`, and a failure becomes a reuse error (code `S/driver/parse_source_batch/batch.rs:53-75`). Syntax-tree relocation leaves a handle of another page generation unchanged (record: digest 05, `R/syntax-trees/storage/relocation.rs:21,35`, open). The parser also reads the source text through the tokens, for example in `check_file_aliases` (code `P01/parser.rs:83`), and copies the shared text into `ParsedSource.source` for later stages (code `P01/parser.rs:254-262`).

## 01 to 02: parser to name resolution

1. **What crosses.** `parse_file` returns a `ParsedSource` (`source_id`, `path`, `source`, `origin`, `root_items`, `import_root_range`, `scope`) and adds the file's items to a shared `SyntaxTrees` page (code `P01/parser.rs:232-262`). The driver wraps the forest in a `ResolutionRequest { syntax, sources, top_level_bindings, retained_base }` (code `P02/resolver.rs:59-73`; built at `S/driver/resolve_and_type.rs:141-146` and `:196-203`) and calls `resolution::resolve_deferred` (code `S/driver/resolve_and_type.rs:262`).
2. **What the resolver trusts.** The syntax forest as the parser left it: its handles, pages and root list. `resolve_deferred` begins indexing the syntax with no structural check of it (code `P02/resolver.rs:91-130`). Without a source map, visibility and stratum checks "stay permissive" (code `P02/resolver.rs:61-64`; record: digest 05 lists the symbol-table functions that return `true` without sources, stated).
3. **What is checked.** `validate_logical_filenames` runs on the driver's source map (code `P02/resolver.rs:94-98`); it checks the map, not the parser's trees. The parser records many forms without judging them and leaves the judgment to later stages, for example asm mnemonics and positional pattern fields (record: digest 02, `P01/assembly/parse.rs:2`, `P01/patterns/positional.rs:1-10`). Nothing independent checks the syntax trees at this handoff.
4. **Other routes.**
   - The driver edits the forest between the two stages: `with_build_entry` removes a Build entry root found by name-span equality (code `S/driver/resolve_and_type.rs:83-127`), and source activation removes retained syntax (code `:167-169`).
   - Resolution rewrites syntax into syntax before any symbol exists (record: digest 02, `P02/declarations/mod.rs:63-102`), and later writes generated syntax back after symbols exist: `machine_equations::complete` mutates the retained forest inside the resolution loop (code `P02/resolver.rs:116-125`) and inside body completion (code `P02/deferred_bodies.rs:422-431`).
   - The resolver keeps the whole syntax forest in its output, `DeferredResolvedFrontier.syntax: Arc<SyntaxTrees>` (code `P02/deferred_bodies.rs:152-153`), and lowers pending machine bodies from it when the driver asks (code `P02/deferred_bodies.rs:434-437`). Stage 01's product therefore stays live until all bodies are completed.
   - The symbol table built here keeps the source map. `SymbolTable::name` returns a stored spelling or, when the name is stored only as a span, reads the text at that span from the source map, with `""` as the fallback (code `R/symbol-resolved-trees/symbol-table/source_symbols/table.rs:3252-3264`; the span-only variant is `SymbolNameStorage::Source(SourceSpan)`, code `source-rust/subsystems/compiler/foundation/declaration-identity/src/symbol.rs:91-105`). Which authored names take the span-only form in production is not traced.

## 02 to 03: name resolution to typing

1. **What crosses.** The first typing call receives `Arc<SymbolResolvedTrees>` from `DeferredResolvedFrontier::shared_trees` (code `P02/deferred_bodies.rs:250-252`) through `typing::lower_symbol_resolved_trees_to_seeded_base` (code `P03/src/lowerer.rs:832-841`; called at `S/driver/resolve_and_type.rs:209`). After that the two stages alternate: the driver asks resolution for a batch of pending bodies (`complete_machine_bodies`, code `P02/deferred_bodies.rs:372-463`), which returns a `ResolvedBodyCompletion { successor, predecessor, frontier, selected }` (code `:512-518`); the driver rebases it onto typing's selection ledger and hands it to `SeededTypingBase::complete_bodies` (code `S/driver/resolve_and_type.rs:348-369`). The loop runs until no pending body is left in scope (code `S/driver/resolve_and_type.rs:397-429`).
2. **What typing trusts.** Typing copies the resolved symbol table, service reach rows, semantic domains, external bindings, authored declaration selections and evidence forwardings into its own product without checking them (code `P03/src/lowerer.rs:1592-1621`). Resolution defers dependent token-binding shapes to typing, which reads them at `T/runtime_callables.rs:1350` (record: digest 02 §5 and §9, from `unit_057_gap_029`). Typing keys about 30 decisions on spelling rather than symbol handles (record: digest 02 §2).
3. **What is checked.**
   - `validate_resolved_semantics` runs first (code `P03/src/lowerer.rs:1588`). It checks equality operands and case-dispatch exhaustiveness (code `:1567-1583`): these are language rules, not a check that the resolver's output is well formed.
   - On every continuation typing compares the value it receives with the value it kept. `with_prepared_allocations` refuses unless the frontier's trees equal the predecessor typing reserved against (code `P02/deferred_bodies.rs:284-296`). `activate_body_completion` refuses unless the activation's predecessor equals typing's retained resolved trees (code `P03/src/lowerer.rs:664-679`). `lower_seeded_extension` refuses a different base, a changed root prefix or a changed selection-ledger prefix (code `P03/src/lowerer.rs:843-859`). The rebase of authored selections fails as "could not join its retained typed selection ledger" (code `S/driver/resolve_and_type.rs:358-362`).
   - These are pairing checks done with the representation's own equality. They show the two stages hold matching snapshots; they do not judge the content. I class them **same helper**, not independent.
4. **Other routes.**
   - Typing sends information back to resolution: `typing.prepare_allocations()` builds a `ResolvedAllocationExtension` from typing's symbol table, semantic domains and service reach rows (code `P03/src/lowerer.rs:791-806`), and the driver installs it into the resolution frontier before each completion (code `S/driver/resolve_and_type.rs:223`, `:410`).
   - The driver writes fields of typing's product: `partial_build_entry`, `partial_build_can_return` and `parked_build_locals` (code `S/driver/resolve_and_type.rs:233-236`).
   - Names reached through the copied symbol table can still read source text through its source map (see 01 to 02, item 4). A grep of `symbols.name(` outside `tests` directories gives 57 lines in `P02/` and 15 in `P03/` (my grep; it does not say which calls take the span branch).

## 03 to 04: typing to preparation

1. **What crosses.** `CompletedSource::finish` yields `TypedTrees` through `SeededTypingBase::into_typed` (code `S/driver/resolve_and_type.rs:436-441`; `P03/src/lowerer.rs:827-829`). The driver's `SourcePreparationRequest::settle` then works on that program (code `S/driver/prepare_typed_source.rs:76-136`) and hands a `SettledSource { program, values, selected_providers, accounting }` to `SettledSource::freeze`, which calls `prepare_typed_trees(program, values, selected_providers)` (code `S/driver/judge_lowered_source.rs:24-56`).
2. **What preparation trusts.** That the typed program has not been specialized before: the request's comment says "Preparing an already specialized frontier again is not part of this boundary" (code `S/driver/prepare_typed_source.rs:49-50`), and no code at this point checks it. That typing recorded every construct it could not finish as a deferred refusal on the holding declaration; the absence of a row means "served" (record: digest 05, `R/typed-trees/proofs/deferred_refusals.rs:15-20`, open). `record_patterns` leaves unresolved subjects and ambiguous names in place and says the checker refuses them where a program reaches the pattern (record: digest 02, `P04/passes/record_patterns.rs:7-9`, stated, checker not traced).
3. **What is checked.** Before preparation the driver refuses external roots, declaration authority and wire demands as "no product route yet" (code `S/driver/prepare_typed_source.rs:81-88`). It re-derives the opaque representation choices from the typed program and refuses if they differ from the ones the Build execution retained (code `:34-46`, `:89-91`); this re-runs the same function, `collect_opaque_representations`, on the current program (code `:38-39`), so it is **same helper**. After compile-time evaluation it joins constant receipts with `validate_constant_evaluations` (code `:105-114`). `prepare_typed_trees` itself runs its five steps with no entry check (code `P04/prepare.rs:33-48`).
4. **Other routes.**
   - Between typing and preparation the driver evaluates every demanded compile-time value and writes the results into the typed program (`evaluate_demanded_values(&mut program, ...)`, code `S/driver/prepare_typed_source.rs:95-104`).
   - Each compile-time call is itself prepared, lowered, checked and published by stages 04 to 07 (`SettledSource::materialized_call(source).judge(...)`, code `S/driver/compile_time_invocations/calls.rs:235-253`) and then run in the interpreter (`build_invocation::ArtifactInvocation::bind`, code `S/driver/compile_time_invocations/calls/execution.rs:331`). So stage 04's input already contains values produced by running later stages; this is a call from between 03 and 04 into 04 to 07 and back.
   - The request type of this step is a stage 07 type, `checked_program_to_psi::production::TerminalSourceCompilation` (code `S/driver/prepare_typed_source.rs:51-57`).

## 04 to 05: preparation to lowering

1. **What crosses.** `PreparedTypedTrees { typed: Arc<FrozenTypedTrees>, values: Arc<[ValueInputs]>, constants }` (code `R/prepared-source/lib.rs:31-36`), built by `PreparedTypedTrees::new(PREPARATION, program, values)` at the end of `prepare_typed_trees` (code `P04/prepare.rs:47`). The driver passes it with a `Compilation` or a roster to `lower_for_publication` or `lower_roster` (code `S/driver/judge_lowered_source.rs:111-118`).
2. **What lowering trusts.** The typed trees' contents. The constructor says so: "Preparation passes remain the producer's responsibility; this constructor does not run them" (code `R/prepared-source/lib.rs:39-41`). Lowering trusts that no deferred-refusal row means the declaration was served (code `P05/src/read/machine.rs:1435-1445`, which returns `Ok` when no row is found).
3. **What is checked.**
   - At construction, `constant_inputs` refuses value inputs that name another source program, static arguments whose declaration, type reference or expression handle is not in the program, a deferred static argument that lost its evaluation context, and a demanded constant with no declaration (code `R/prepared-source/values.rs:63-144`). This code lives in the representation crate, apart from the stage 04 passes, but it checks only the value inputs, not the trees.
   - The issuer limits who can build the product: only stage 04 links `prepared-source/issuer` (code `R/prepared-source/lib.rs:42-44`; enforced by `SOURCE_PRODUCT_ISSUERS`, code `tools/xtask/src/boundary/linear_pipeline.rs:107-137`). Two `compile_fail` doctests pin that lowering cannot take a bare `FrozenTypedTrees` or mint the issuer (code `P05/src/compilation.rs:26-44`).
   - Lowering's own entry checks: `check_bound_callable_shapes` compares each bound slot's calling shape with the machine it names and stops on a mismatch (code `P05/src/compilation.rs:89-103`); each binding's requirement is rejoined to its declaration and a failure is a `ForeignIdentity` refusal (code `:105-124`); every machine read passes `served`, which raises the deferred-refusal rows typing and preparation recorded (code `P05/src/read/machine.rs:1425-1464`); the reader refuses a name with no valid symbol as a spelling (code `P05/src/read.rs:1-22`). All of these are stage 05 code reading stage 04's product, so none is an independent validator.
4. **Other routes.** Lowering reads the typed trees directly, including the symbol table and its source map; my grep finds 16 `symbols.name(` lines in `P05/` outside `tests` directories. Stage 05 also prepares what stage 06 needs "while typed source is still available" (code `P05/src/compilation.rs:1-3`), so stage 06 never reads typed trees itself.

## 05 to 06: lowering to the lowered-form checker

1. **What crosses.** `LoweredSourcePublication { program: TerminalCompilation, source: PublicationSource }`, where `PublicationSource` holds `owner: PreparedTypedTrees`, `publication`, `correspondence: SourceCorrespondence` and an optional roster (code `R/lowered-source-publication/lowered_source_publication.rs:30-40`). `bind_source` builds it with `from_lowering(LOWERING, ...)` (code `P05/src/compilation.rs:56-72`). `TerminalCompilation` is `FormationFailures`, `FormationDefect` or `Prepared(PreparedCompilation)` with `closure`, `further`, `arrivals`, `forms`, `witnesses`, `specializations` and `selection_witnesses` (record: crate map 05, `R/lowered-program/lowered_program.rs:14-21`). A stage 05 refusal travels inside it as `closure: Err(first)` plus `further` (code `P05/src/compilation.rs:154-176`).
2. **What the checker trusts.**
   - `from_lowering` checks nothing (code `R/lowered-source-publication/lowered_source_publication.rs:55-61`); the checker relies on the issuer for where the value came from.
   - Stage 05's formation failures become a `Rejected` verdict as given (code `P06/src/verdict.rs:1549-1558`), and stage 05's own refusals are turned into verdicts by their recorded reason (code `P06/src/verdict.rs:1616-1618`, `:1640-1645`). The checker does not re-derive why lowering refused.
   - Table identities are machine-local integers; `row()` cannot tell an in-range identity from another machine's table, and the comment says the rule that prevents this is structural, not checked (code `R/lowered-program/tables/mod.rs:306-314`).
   - The source half is not read: `judge_publication` splits program from source and returns the source untouched beside the checked program (code `P06/src/publication.rs:23`, `:67-68`).
3. **What is checked.**
   - **Independent:** `minted.rs` recomputes from the lowered form alone which obligations, invocation rows and edge rows each machine owes, and where, and refuses tables that differ (code `P06/src/minted.rs:1-47`). For operation safety it asks `terminal_semantics::proof_bearing_scalar_leaf_semantics` for the obligation (code `P06/src/minted.rs:883-895`), while stage 05 mints those rows through its own `Lowering::obligation` calls (code `P05/src/lower/operations.rs:30`); a grep finds no `proof_bearing_scalar_leaf_semantics` call in `P05/`. The write log is re-derived and checked against the tables by `log_is_stated`, and every certificate is re-decided by the proof kernel (record: digest 04 §1, `P06/src/places/log.rs:704`, `P06/src/lib.rs:2566`).
   - **Same helper:** some checks re-run the shared `terminal_semantics` function that stage 05 also called. Static reach: stage 05 fills `static_reach_summaries` with `terminal_semantics::static_reach::derive` (code `P05/src/declare.rs:222`), and stage 06 calls the same `derive` and refuses if the result differs (code `P06/src/static_reach.rs:130-155`). Suspension: both build `terminal_semantics::suspension_frontier::MachineFrontiers::new(module, machine)` (code `P05/src/suspension.rs:18`, `:49`; `P06/src/operational.rs:361`, `:388`); the semantics header says the checker rebuilds the live list instead of trusting the producer's row (record: `unit_050` A2). Claim planning: stage 05 runs `terminal_semantics::plain_affine::plan_in` (code `P05/src/lib.rs:2019`), and stage 06 maps `plain_affine::Error` into verdict text (record: digest 04 §3, `P06/src/verdict.rs:1034-1052`). A defect inside one of those shared functions would appear on both sides of the comparison (inferred).
4. **Other routes.** The typed source rides beside the checker inside `PublicationSource` and reaches stage 07 without passing through the check (code `P06/src/publication.rs:23`, `:67-68`). The `lowered-source-publication` manifest says the checker must never link that crate because it names typed trees (record: crate map 05).

## 06 to 07: checker to publication

1. **What crosses.** `CheckedPublication<LoweredSourcePublication> { source, program: Arc<CheckedProgram>, further_forms }` (code `R/checked-program/checked_program.rs:84-105`), where `CheckedProgram` holds the accepted `Elaboration`, one evidence seal per discharged operation obligation and the optional optimization record (code `:17-39`). `judge_publication` builds both with the `CHECKER` issuer after every form was accepted (code `P06/src/publication.rs:61-68`, `:83-165`). The driver hands it to `AcceptedTerminalSource::from_judgment` or `SourcePublication::from_judgment` (code `S/driver/judge_lowered_source.rs:136`, `:162-164`).
2. **What publication trusts.** That the elaboration is what the checker accepted; both constructors only store their arguments (code `R/checked-program/checked_program.rs:28-39`, `:94-105`) and the issuer limits who can call them. The requirement reviews and source correspondence stage 05 wrote, which stage 07 takes from `source.correspondence` without re-deriving them (code `P07/src/accepted.rs:230-249`).
3. **What is checked.**
   - `accept_judgment` refuses unless the correspondence has exactly `1 + further_forms` forms and none is missing (code `P07/src/accepted.rs:222-229`): stage 07 code comparing a stage 05 record with a stage 06 count.
   - `CheckedProgram::prepare_publication` runs `validate` (code `R/checked-program/checked_program.rs:233-238`), which refuses an installation-bound refinement, any generic check-form roster, rigid values and undeclared machines (code `:262-331`), then runs `terminal_semantics::activation_storage::validate_module` (code `:332-333`). That function is a shared semantics helper; the wire crate's foundation validation also calls it (code `PSI/artifact/wire/src/foundation_validation.rs:12225`). Whether stage 05 or 06 runs it earlier on the same module is not traced.
   - `build_bindings::validate_companions` checks the Build companions against the published program (code `P07/src/accepted.rs:96-103`); the companions come from stage 07's own `build_companions::produce` (code `:315-316`), so this is the producer checking its own output.
4. **Other routes.** Stage 07 reads the typed source to build provenance, companions and selection questions: `self.source().symbols` for machine spans (code `P07/src/accepted.rs:296-308`) and `source_selection_publication::prepare(self, ...)` (code `:290-295`). The module header says the selections and source coordinates are captured "while their typed owner is available" (code `:278-279`). Stage 07 thus takes information from stages 03 and 04 that did not pass the checker.

## Handoffs where nothing independent checks the value

- **00 to 01.** Only the lexer's own assertions in the token crate run (pointer identity, decoded literal bytes); token spans and kinds are not re-checked.
- **01 to 02.** The syntax trees are not checked; only the driver's source map is (`validate_logical_filenames`).
- **02 to 03.** Typing copies the resolver's symbol table, reach rows, domains, bindings, selections and forwardings unchecked; the continuation checks compare snapshots by equality and do not judge content.
- **03 to 04.** The typed trees are not checked; the opaque-choice check re-runs the same function, and "not already specialized" is a comment, not a check.
- **04 to 05.** The constructor checks only the value inputs; lowering's entry checks are stage 05's own code. No independent check of the typed trees.
- **05 to 06, in part.** `minted.rs` re-derives owed rows independently, but static reach, suspension frontiers and claim planning are compared against the same shared helpers stage 05 called, and stage 05's refusals and formation failures are accepted as stated.
- **06 to 07, in part.** `accept_judgment` and `validate` check counts and rosters; the companions check is stage 07 checking its own output; the typed-source half reaches stage 07 without any check.
