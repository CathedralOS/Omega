### construction.rs (1050 lines, read)
**Purpose.** Projects a flat `AbstractOperationPlan` into a bare `PsiOptimizationUnit` "seed": per function, slices the operation stream into blocks and extracts per-node definitions, uses, successor edges, provenance, work and ownership events (construction.rs:1-9, 43-82, 84-281).
**Shape.** `OptimizationUnitBuildError` (7 variants, :22-30); `reconstruct_psi_optimization_unit_seed` (:43), `reconstruct_psi_optimization_function_seed` (:84); per-operation extractors `operation_edges` (:283), `collect_fact` (:345), `operation_obligation` (:406), `operation_node_provenance` (:492), `operation_definition` (:527), `operation_uses` (:612)/`direct_uses` (:623), `collect_places` (:745), `collect_operation_structural_places` (:914), `operation_ownership` (:998).
**In/out.** Reads `AbstractOperationPlan`/`AbstractFunction` (abstract-operations crate). Produces `PsiOptimizationUnit` whose `structural_domains`, `services`, `root_service_reach`, `accepted_obligation_facts`, `proof_questions`, `ownership_frontier_facts`, `pruned_machines`, `runtime_evidence` are empty/None (:66-77) and per-function `verified_contract`, `content_entry_claims`, `declared_service_reach`, `evidence_contract_lanes` are empty/None (:268-277), to be filled later by `attach_verified_module_context` (proof.rs:479).
**How it decides.** Keyed on IDs and ordering: machines strictly increasing (:52-59), block ids strictly increasing and first block at offset 0 (:90-110). Effect tokens are a running counter `effect_token` per function, input=n, output=n+1 (:154, 237-246), i.e. every node is a distinct effect step (position-keyed, not operation-class keyed). Block of a node is the slice between `block_entries[i].operation_offset` and the next (:168-178). Work units are always `1` per provenance site (:204-207, 299-302).
**Cases by shape.** All of `operation_definition`, `direct_uses`, `collect_places`, `collect_operation_structural_places`, `operation_obligation`, `operation_ownership` are `match`es with `_ =>` fallthrough to "no definition / no uses / no places / no obligation / no ownership event" (:608, :741, :910, :994, :488, :1048). **Same job elsewhere.** The per-variant enumeration of operands/definitions/places is also done in `observation.rs:335-440` (observation classes), `identity.rs` `operation_encoding` (:3060-5108, byte encodings), and in the abstract-operations crate `operations.rs` (see part 2). `operation_definition`/`operation_uses`/`operation_ownership` are `pub`; grep `\b(operation_definition|operation_uses|operation_ownership)\(` over omega-rust: 10 hits in 3 files: construction.rs (6, own file), optimization-unit/semantics/src/unit_validation.rs (2), and psi/.../06_checked-trees-to-lowered-psi/src/emission_cleanup.rs (2; not read, name collision suspected).

### dominance.rs (291 lines, read)
**Purpose.** Packed bitset dominator sets for all declared blocks including unreachable ones.
**Shape.** `DominatorSets` (:7), `DominatorSet` (:22), `solve` (:53, `pub(super)`), `reverse_postorder` (:113). Tests :140-290 compare against a naive set-based fixed point on all graphs up to 4 blocks and chains up to 8192 blocks.
**How it decides.** Greatest fixed point: non-entry rows start as the universe, entry row = {entry} (:66-77); a block with no predecessors gets the empty set plus itself (:88-98). Keyed on block position in a sorted roster; lookup by `binary_search` (:14, 29). Comment :1-3: "the equations retain the original greatest fixed point"; :210-211 (test): "An absent entry is intentional too: the old equations do not impose reachability".
**Fail-open risks.** Unreachable blocks keep dominator sets that can be larger than their reachable-only sets (universe rows survive when no path from entry lowers them; :66-72 only lowered by iteration over `incoming`). A consumer asking "does D dominate unreachable block U" can get `true` for many D. Whether consumers filter unreachable blocks: "open" (callers `forwarded_field_value` structural_places.rs:1498-1519 query `dominators.get(&use_block.id)` for every block with a use, including possibly unreachable ones).
**Same job elsewhere.** `dominators(` is also called in psi pipeline 07 `scalar_and_value_passes.rs` (2), psi terminal-psi semantics `control_graph.rs` (1), pipeline 01 `analyses.rs` (2) etc. (grep `\bdominators\(`: 22 hits in 14 files; not read: suspected separate dominator implementations or users).
