## Section B: compiler/tests/support/*.rs (test-harness helpers). All paths `compiler/tests/support/<file>`. All read in full unless noted.

General shape (read): most files are `pub(super) fn inspect/produce/observe(...)` that take a compiled report/artifact, then (1) read an optional oracle file beside the fixture (`expected_*.txt`), returning `Ok(())` when the file is absent, (2) clone the `TerminalModule`/object, mutate one field, (3) assert the receiver refuses with a specific substring. ## Five things a maintainer most needs to know about this unit
1. About 15,000 of the 21,642 lines are test harness, not compiler: `compiler/tests/support/*` mutates real compiled artifacts (clone a `TerminalModule`, change one field, expect `terminal_codec::decode_module` or a receiver to refuse with a specific substring) and drives the corpus runner; its fixtures, machine names, numeric constants (e.g. stack 64/8 at task_activation_controls.rs:78, extents 16/24 at native_layout_controls.rs:88-95, ABI registers X0/X1 at terminal_calling_policy.rs:277) and oracle-file formats are all fixture-bound.
2. Almost every control reads an optional `expected_*.txt` beside the fixture and returns `Ok(())` when it is absent, so a control silently does not run for fixtures without its file; pass/fail of controls depends on the oracle strings matching exact error substrings (`format!("{error:?}").contains(reason)`), so rewording a diagnostic breaks controls without any semantic change.
3. `checked_interpreter_dispatch/boundary_dispatch/*` (1,500 lines) is the oracle-side settlement of selected provider rows into adapter dispatch rows for the checked-tree interpreter (not product compilation: mod.rs:3-8); it resolves rows by symbol identity plus identity-text equality and has three row shapes (trait requirement, top-level requirement, generic top-level requirement via roster) plus finite-family tuples; `exact_checked_body_entry` is the single verifier used by all three (adapter_rows.rs:552,:714,:778).
4. `native-compiler/src` is a thin coordinator: `prepare` (preparation.rs:41) -> scalar completion by the caller -> `compile`/`admit_runtime` (compile.rs); all real lowering is in other crates, sequenced in `pipeline.rs` (Omega 01-09). `pipeline_boundary.rs` pins that sequencing by `include_str!` text searches. Component exports and callback thunks reuse the same callable pipeline and refuse private-callback companions (component_exports.rs:243-255).
5.
