## 3. representation-planning/src/representation_selection.rs (1-492)

**Purpose.** Turns a build-declared `Build::select_representation<Opaque, Conformance>` request into a validated `OpaqueRepresentationSelection`, checks that the carrier data is inert, harvests selections from executed build events, and re-derives them against the final typed graph to detect stale or forged retained rows.

**Shape.**
- `carrier_closure::validate_inert_carrier` (rs:32-52) -> `CarrierClosure` struct (rs:54-61) with `visiting`, `validated` (Vec<TypeIdentityId>), `scopes: validation::DeclarationScopes`, `applications`. `validate_definition` (rs:64-127), `validate_type` (rs:129-215), `reject` (rs:217-221).
- `FormedOpaqueRepresentation` (rs:225-233), `activate` (rs:236-248) always uses `Inert` lifecycle and `NamedConformance` origin.
- `form_opaque_representation_request` (rs:251-384).
- `collect_opaque_representation_selections` (rs:386-465).
- `rederive_opaque_representation_selections` (rs:467-492).

**Inputs/outputs.** Reads `TypedTrees`, `ProductDeclarationRequest`, `ExecutedProductSelection`; calls `validation::conformance_applications::close_conformance_application` (rs:319). Outputs `Vec<OpaqueRepresentationSelection>` or diagnostics.

**How it decides.**
- Copy disposition: `Multiplicity::Unrestricted` opaque => `CheckedSemanticCopy`, else `PlacementOnly` (rs:37-41). Keyed on declared multiplicity of the opaque definition.
- Carrier closure rejects (rs:77-96): non-`CheckedShape` supply mode, `Linear` multiplicity, affine member when copy requested, any `cleanup_selection`; recursion by identity (`visiting`), recursive family by definition symbol (rs:186-192). Types: primitives, `BuiltinType` named symbols and `Unit` are accepted (rs:136-142, 160-164, 213); `Reference`, `Slice`, `DynamicTrait`, `ConstExpression` rejected (rs:200-212); `FixedArray` needs `Literal` length (rs:155-157); erased fields skipped (rs:101, 110).
- Operand check: `request.operation == BuildOperation::RepresentationSelection` and exactly two operands (rs:255-264); the opaque must be `DataSupplyMode::BoundaryOpaque` (rs:307); conformance symbol kind must be `Conformance` (rs:313); trait must be compiler-owned (rs:326); trait args exactly two (rs:337); first arg's `type_symbol == opaque` (rs:343-347); carrier must be a `CheckedShape` data definition (rs:357-369).
- Duplicate selection: any earlier selection with same `opaque` symbol -> error (rs:443-454). Executed event matched to its formed request by `Arc<ProductDeclarationRequest>` equality (`request.as_ref() == event.request.as_ref()`, rs:432-434).
- Rederive: retained rows must have `selecting_machine == activation` and stored commitment == recomputed (rs:474-478); then whole-vector equality `derived != retained` (rs:484).

**Cases by shape.** Two-operand request only (rs:260); carrier must be a single concrete named data declaration (`data_definition_by_symbol`, rs:357). Quote rs:219: "v1 carriers must be inert storage".

**Same job elsewhere.** Type-walk over data definitions with a visiting stack resembles other recursive checkers in the crate; not compared.

**Unused/one-caller.** `form_opaque_representation_request`: grep (excluding representation-planning dir) shows 0 external call sites; one internal (rs:417). Re-exported at lib.rs:72. `collect_opaque_representation_selections` external: `psi-compiler/src/source_compilation.rs:440` (plus `omega/.../compiler/src/product_boundary.rs:64,83` which are string literals "collect_opaque_representation_selections(" i.e. source-text matches - inferred a boundary test). `rederive_opaque_representation_selections` external: `psi-compiler/src/source_checking.rs:630`, `review-evidence/.../policy/selections.rs:40`, string at `product_boundary.rs:37`.

## 4. src/access_views_and_borrows.rs (1-3931)

**Purpose.** Two modules in one file (header comment ab:1-4). `access_views` checks that the retained access-view plans (synthesized "accessor" data/machines for placed, atomic, region and external fields) still match the typed program, that custody conformances agree with the layout plan, and that uses of accessor fields respect atomic permissions and binding-private exposure. `write_only_borrows` checks the `&write` (write-only reference) discipline: which referee types are admitted, that write-only roots are only replaced/forwarded and never read, and that formations/subloans keep the same stored type.

**Shape (access_views, ab:5-1579).**

- `plan_replay` (ab:868-1165): `RetainedFieldIdentity {Numbered(u64), Positional(String)}` (ab:875), `exact_access_entry_for_field` (ab:887), `validate_plans` (ab:915-1164) re-verifies each `AccessViewPlan` against data/machine tables.
- `validate_plans` (ab:1168), `validate_statement` (ab:1173), `assignment_is_access_atomic_operation` (ab:1194), `validate_assignment` (ab:1208), `validate_expression` (ab:1259), `statement_call_target` (ab:1465), `validate_binding_private_use` (ab:1484), `statement_expression_roots` (ab:1562).

## 5. src/arithmetic_domains.rs (1-13443)

**Purpose (file-level).** Header comment ad:1-5: "Shared integer interval domain, premise-ordering oracle, guard narrowing, ordered values, and mixed-domain and exact-overflow validation (`proof_contracts::arithmetic_domains`)". It is a single flat file of `pub(crate) mod` blocks (not separate files). The central state is `ValueEnvironment` (defined later) keyed by place-path STRINGS (e.g. "packet.cells[0].field"), holding `Interval {low: Option<i64>, high: Option<i64>}`, float intervals, known-u64 values, etc. Checks are proof obligations: exact arithmetic overflow, narrowing stores, shift counts, casts.

**Sub-modules read so far (ad = arithmetic_domains.rs line numbers).**
- `atomic_observations` (ad:6-43): `atomic_resident_interval` = primitive range intersect declared range (`enforced_declared_range`) intersect a where-fact interval for the stored field; `atomic_result_interval` finds the local's `atomic_result_placeholder` event and reuses the resident interval of its place.
- `abstract_shift_count` (ad:45-125): for abstract-specification expressions with `<<`/`>>`, under `ShiftCountLaw::MustBeWithinWidth`, errors unless the count interval is provably in `[0,width)`. Message ad:119 "exact shifts prove `count < {width}` before the term forms". Skips silently when not builtin arithmetic, no direct abstract operand, or width unknown (ad:74-94).
- `declared_integer_facts` (ad:126-327): `record_admitted_integer_fields` walks a data type's `where` facts (And-conjunctions only, ad:215-227) and its fields recursively (active-stack cycle guard ad:161-164), turning comparisons between literals/fields into environment facts through `contribute_projected_comparison`. ## Five things a maintainer most needs to know about this unit

1. `arithmetic_domains.rs` is one 26,000+ line file of nested inline `mod` blocks; this unit is its first 13,443 lines and ends inside `guard_narrowing::requirements` (ad:13442).
