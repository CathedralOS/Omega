## `literal_fold_rewrites.rs` (Omega 04, "SelectedLowering" phase)

**Purpose.** The file header (1-6) says it implements the `SelectedLowering` optimization phase: it folds a literal `MaterializeI64` into the one instruction that consumes it, where a rule table (the "pair-rule catalog") says the consumer has a cheaper or simpler form for that literal. For example `add x, <lit>` becomes `add x, #imm`, `x & 0` becomes `materialize 0`, `zero_extend(<lit>)` becomes `materialize <masked lit>`. It repeats this until nothing applies, and writes a receipt chain that a second function can replay step by step. The file is one big nested-module tree (`pub(crate) mod literal_folds` 11-994, `pub(crate) mod selected_lowering` 996-4575) re-exported through `rewrites.rs` by `pub(crate) use crate::rewrites::*` (9). ### How it decides (what each judgment is keyed on)
- **Which literal is a candidate** (`derive_actions` 1214-1268): instruction kind is `MaterializeI64` with `IntegerValue::Unsigned` (1221-1226) and `u64::try_from` succeeds (1230). Judgments after that are on register identity and shape: single `Def` operand with no fixed view/tie/early clobber (1270-1279); producer record has no implicit uses/defs/clobbers and a provenance of exactly one operation, one value, no edges/obligations (1281-1296); the victim register is an integer, not address-typed, admits the value, has no `entry_fixed_view`, and its origin is `InstructionResult` of this literal instruction (1298-1321).
- **Which use** (`sole_use` 1323-1422): scans the whole function by register identity. Any def of the victim other than the literal's own, a second use, or the victim appearing in any successor binding / case payload / value transport (1368-1411) returns `None`. The single use must be in the same block, in the body (not the terminator), after the literal (1414-1421). One action per consumer instruction (1244-1248).
- **Which rule** (`AdmittedPairs::for_consumer` 1597-1613): keyed on `machine_semantic_kind(consumer kind)` (via `matches_consumer` 3873), the victim operand index, and the literal's numeric value fitting `immediate_bound` (3833). If two rules match, it returns `None` (1609-1611). For replay, `for_consumer_row` (1626) is keyed on consumer kind plus the register-constraint row key, first match wins; `for_position` (1615) is keyed on kind plus operand index, first match wins.
- **Admission beyond the rule** (`admit_candidate` 1425-1566): operand roles by index from `PairOperandShape` (1448-1476); tail operands (`PairTailCustody::admits` 3675: `Bare` = none; `AuxiliaryUses` = all uses of registers whose only definitions are `MaterializeI64 0`, 2654-2674; `ScratchDefs` = all defs whose register occurs once in the function, via `register_occurs_once`, 2676-2681; `AuxiliaryUsesOrScratchDefs` = either per operand, 2639-2652); rewritten constraint row shape and register class match (1477-1513); effect checks (`PairUnitEffects`, `PairMachineEffects`) on the instruction records and on the machine-effect declarations looked up by constraint key (1514-1551).
- **Register-class and identity checks use indices**, not names. No string compares or `display_name` anywhere in the file (read in full; the only strings are `expect`/`assert!` messages and the byte-domain labels).
- **Immediate computed** (`fold_immediate` 3841-3867): `SurvivingOperand | SwappedOperand` keep the literal; `ConstantOfLiteral` gives `carrier.maximum_bits()` when the consumer is `SaturatingAdd`, else `0` (3846-3849); `LiteralRecompute` masks or sign-extends per consumer kind (3850-3865), and `_ => return None`.
- **Rewritten kind** (`rewrite_consumer` 3898-3990): a match on (`self.rewritten`, consumer kind); the results of constant/recompute folds are produced by `scalar_materialize_value` (3993-4003), which refuses address or >64-bit integers and values the result register's type does not admit.
- **Iteration stop**: `applied_count == 0` (359), bounded by the starting virtual-register count (342, 362), and each step must lower the register count by exactly `applied_count` (`charge_step_measure` 685).
- **Budget**: `fold_usage` (2209-2335) charges rule evaluations (one per function), candidates and commits (applied count) and validation steps; `ensure_budget` rejects when usage exceeds budget (2337).

### Fail-open risks
1. `fold_usage` (2267-2292): when an action's consumer, victim position, or pair row cannot be found it does `continue`, adding no validation-step charge for the swapped-compare scan. Effect is on the work budget only (under-charging), not on which program is accepted; the transformation itself is already done in `compute_terminal_literal_fold` before this runs (2381-2382). Status: "traced" for the accept path (charging cannot change the transformed program); "open" for whether the budget is relied on as a safety bound.
2. `admits_consumer_obligation` (3508-3524): returns `true` for any rule whose `fault` is not `DischargedByObligation`, with no check. By design, those rules do not claim a fault is covered by an obligation. Status: "traced" in-file (the field is a per-rule enum set at constant definition).
3. `fold_immediate` `ConstantOfLiteral` arm (3846-3849): any consumer other than `SaturatingAdd` gets the constant `0`. Every rule that uses `ConstantOfLiteral` today (`WRAPPING_REMAINDER_*`, `BITWISE_AND_ZERO_*`, `EXACT_DIVIDE_ZERO_*`, `SATURATING_SUBTRACT_ZERO_MINUEND`, `SATURATING_SUBTRACT_UPPER_BOUND`, `SATURATING_DIVIDE_ZERO`, `SATURATING_ADD_UPPER_BOUND`) gets the intended value (0, or the carrier maximum for saturating add upper bound). A future rule added with that shape on a different consumer would silently fold to 0. Status: "traced" for the current table (read each rule); no code guards the future case.
4. `WRAPPING_REMAINDER_MINUS_ONE_MATERIALIZE` (2891-2913): rewrites `x % <u64::MAX literal>` to constant 0 for `WrappingRemainderI64`. In this file the only guard on the literal is that it is a `MaterializeI64{Unsigned(u64::MAX)}` whose register type admits `Unsigned(u64::MAX)` (1311) and `Exactly(u64::MAX)` (2897). The file does not check whether the consumer's operands are signed. If `WrappingRemainderI64` can take an unsigned 64-bit register, `x % 0xFFFF_FFFF_FFFF_FFFF` is not 0 for general `x`, so the fold would be wrong. Whether that consumer is signed-only (so a register admitting `Unsigned(u64::MAX)` cannot hold -1) is defined in `selected-instructions` and I did not read it. Status: "open".
5. `swapped_unit_readers_equality_only` (2579-2617): the compare-with-left-literal rules swap operands, which is only valid when every reader of the flags unit tests equality. A reader counts as equality-only if its kind is `MaterializeBooleanEqual` or `ConditionalBranchNonZero` (2571-2577), with no comment saying why `ConditionalBranchNonZero` is equality-only. A reader that is some other kind returns false (refuses). A missing successor block index returns false (2610-2612). The walk stops at a def or clobber of the unit (2599-2604) and ends true when a block has no successors (e.g. a return), so a flags value live out of the function by some other route would not be seen. Status: "open" for `ConditionalBranchNonZero` and for live-out; `block_instructions` (2566, 2593) is imported from `rewrites::block_edges` and was not read, so I do not know whether it includes the terminator instruction.
6. `admits_dead_consumer_defs` (3526-3541): for `RetiredWhenDead` a consumer's implicit defs may be dropped if no instruction in the function lists that unit in `implicit_uses` (2561-2569). It does not look for readers that are not recorded as `implicit_uses` (for instance a terminator via another field, or a unit live out through an ABI return). ## Five things a maintainer most needs to know about this unit
1. 2. A fold only fires on `MaterializeI64{Unsigned}` whose register has exactly one use, in the same block body after it, with no successor-binding carry (1221-1422); the decision is keyed on register identity, instruction kind (`MachineSemanticKind`) and the literal's numeric value against the rule's bound, never on names.
3. Spill-choice and recovery analyses are computed and accounted every attempt (558-607) but do not influence which folds are applied; `derive_function_folds` uses `recovery` only to check the machine id (2120-2130).
4. `redensify` (1901) is a second implementation of "delete and shift all later ids", alongside `copy_and_extension_rewrites.rs:1058`; `apply_actions` also separately shifts `boundary_settlements` (1769-1784). Any new per-function table holding instruction positions or register ids needs adding in this file's list.
5. Safety of each rule is carried by per-rule enums (`PairFaultDischarge`, `PairUnitDefRelation`, `PairTailCustody`) plus `assert!`s in the `const` rule definitions; the points where soundness rests on code outside the file are the compare-swap reader test (2571-2617, 3543-3568) and the signedness of the `WrappingRemainderI64` minus-one rule (2891-2913).
