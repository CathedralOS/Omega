### How it decides
- Exactness of a definition is by identity: a domain/data definition is "exact" when exactly one definition row has that `symbol` and equals the passed value (dp:154-166 for domains, dp:53-62 for data).
- Case-membership meaning (dp:1073-1126): operator must be `Equal` or `CaseMembership` (dp:1082-1086); right side must resolve (dp:1128) to a variant whose owner is a data definition; left subject's type is matched by symbol to the owner (dp:1239-1254: `data_constructor_definition`, or `Named.symbol == owner.symbol`, or `Generic.base_symbol == owner.symbol`). For `CaseMembership` that is enough (dp:1095). For `Equal` it additionally demands the authored selection occurrences of that expression contain exactly one `CaseReference` selecting the owner and one `CaseMembership` selecting the case, and nothing else (dp:1101-1125).
- Case reference owner (dp:1158-1199): single-segment path must have `data_variant_position_for_symbol` whose owner's symbol equals the variant's `parent` (dp:1169-1175); qualified paths must be `Module...Carrier.Variant`, every non-final prefix member a `Module` symbol and each consecutive pair parent/child (dp:1176-1198). Keyed on symbol identity.
- Float comparisons (dp:834-894): a comparison is a "sealed float comparison" only when no trait operator meaning is selected (dp:842-851), exactly one candidate resolves (dp:858-861), it is a `is_boundary` operator whose `primitive_float_binary_semantics` operation equals the comparison (dp:867-874), `is_sealed_toolchain_float_operator`, and every authored selection occurrence is either late-bound `CheckedOperator` or resolved to that operator's symbol (dp:877-892).

### Purpose
`pub mod default_domains` (dp:7278 onward) tracks "default-domain invariant windows": after a write into a data value whose type has `where` facts (a "domain" the zero/default value may not satisfy), the place is "established" only when the facts are proved; reads while a window is open or before establishment are rejected with diagnostics.
