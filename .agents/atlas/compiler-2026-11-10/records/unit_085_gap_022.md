## Five things a maintainer most needs to know about this unit
1. `declarations.rs` is a bundle of declaration record types plus a few "authentication" checkers; the checkers recognise toolchain declarations by exact file path and, in two of four places, exact file bytes (`include_bytes!` at declarations.rs:133-140, `language_core::layout_storage::SOURCE` at 2282), together with spelling checks on names such as `exit_process`, `ProcessExit`, `Console`, `NativeFloats::`, `FloatNativeOperations`, `layout_target_facts`, `FixedLayout`.
2. Indexed-domain instance names are built as strings (`Base<type:...,integer:T:v,...>`, 913) and constants are recognised from the `Named` type reference's name string (parse as canonical atom or `i128`, 1080-1087); only `Type` and `Const` parameters are allowed (887-906), and an unknown name becomes an open `binder:` identity rather than an error (1088-1096).
3. `declaration_visibility` is fail-closed (empty or conflicting retained rows give None, 2842-2850); `authored_selection_visibility` follows specialization/capture origins and refuses ambiguity (2745-2747, 2756); the only default-true is `owning_machine_is_retained` with no machine ancestor (2691).
4. `type_multiplicity` (declaration_tables_and_index.rs:6107) resolves named data by symbol first and then by NAME (6148-6153, 6167-6171), and returns `Affine` on a miss; `Reference` is `Unrestricted` there and only becomes `Affine` through `stored_value_multiplicity` (6185-6189).
5. `same_static_machine_operand` (5985-6029) is the operand equality used by `static_binding_matches_argument` (5972) and by the requirement-instance dedupe (`callable_applications.rs:4361`); it compares path identifiers and symbols directly and type references by `applied_type_identity` in each operand's own owner.
