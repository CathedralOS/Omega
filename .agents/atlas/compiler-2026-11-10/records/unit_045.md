## constructed_results.rs (1-1162)

1. Purpose. After elaboration, assigns each array literal, struct (constructor) literal, borrow, call and recast expression a completed result type reference (`constructed_value_type_reference`), derived child-before-parent. For generic constructors it infers type, const and lifetime arguments from the fields, declared types of math facts, and `==`/`!=` peers. (read)
2. Shape.

 - `occurrences` :594 collects `(owner, expression)` for the selected expression kinds over (a) every state's contracts + statement roots, (b) every callable contract scope that is not an entry state (:640-675). Also builds `ConstructorPeers` map.
 - `mod call_results` :18: `retain` :117 (call result type), `region_application::bindings` :36 (lifetime bindings for a call), `retain_access_result_type` :191, `apply_result_type` :269, `apply_runtime_result_operands` :287.
 - `mod identity_context` :347: `ConstructorContext {Peer, Declared}`, `ConstructorPeers = HashMap<(ValueTypeOwner, ExpressionHandle), Vec<ConstructorContext>>` :369, `append` :372, `argument_tuples` :440, `application_arguments` :461.
 - `retain_borrow_result_type` :679, `retain_constructor_result_type` :935, `constructor_byte_literal_observations` :873, `selected_constructor_field` :854.
3. Inputs/outputs. Reads typed trees tables, `validation::*` (place resolution, `join_result_type_references`, `callable_contract_scopes`), `crate::monomorphization::{BindingContext, StaticProposals, infer_static_bindings, finalize_type_domain_instance_identities, for_each_type_reference}`, `crate::conformance::conformance_application_lifetimes::*`. Writes `set_constructed_value_type_reference` on expressions and inserts type rows.
4. How it decides.
 - Which expressions to visit: node variant match `ArrayLiteral | StructLiteral | Borrow | Call | Cast if is_recast` (:766-774).
 - Call results: dispatch order requirement signature -> `validation::find_state` -> machine-parameter signature (:136-161); calls with `native_code_layout` or `layout_query` keep the previously retained type (:126-129).
 - Constructor type arguments: proposals from the literal's own `application_type`, from peers (`==`/`!=` operands, :416-436; math-call argument declared types :393-415), and from field value types via `infer_static_bindings` (:1035). A parameter is accepted only if every proposal has the same `applied_type_identity` (:1111-1118); disagreeing proposals yield `None` (type not retained).
 - Default "unused coordinate" const parameters get a synthetic named reference `"0"` with an invalid symbol (:947-961, :1101-1110). Keyed on `unused_coordinate_widths` (validation) and a string name `"0"` (`name == "0"` at :949).
 - Byte-string literal fields: a `String` expression assigned to a field typed as fixed array of `u8` yields `FixedArray{u8, Literal(bytes.len())}` (:884-909). Keyed on `builtin_type_atom == U8`.
5. Cases by shape.
 - Array literal: result is `FixedArray{join of element types, Literal(len)}` only if `join_result_type_references` succeeds (:808-835).
 - Borrow: needs `reference_formation_source`; for a state it uses a unique non-inferred local with a matching declared reference type if exactly one exists, and returns `None` if two or more match (:693-725).
 - `retain_access_result_type` :191 only rewrites `Generic` types with exactly two arguments `[policy, schema]` that are both `Named`, and matches an `access_view_plans` entry (:229-250). Comment-free; any other shape is returned unchanged.
 - `apply_runtime_result_operands` :287 substitutes call arguments into a return type only if the return type mentions a parameter symbol (Named, ConstExpression naming a parameter, or FixedArray const parameter) (:312-329); otherwise returns unchanged.
6. Same job elsewhere. Lifetime-binding collection by walking required vs actual type refs: `region_application::bindings` :36 calls `conformance_application_lifetimes::visit_lifetime_bindings` (conformance.rs:801). `retain_constructor_result_type` :1049 calls `collect_declared_field_lifetime_bindings` (conformance.rs:755). `ValueTypeOwner` (State/Declaration) mirrors `InvocationScope` (contextual_and_requirement_calls.rs:1061) (read both): same two-way split with own `result_type` method.

Unused/one-caller. `retain_constructed_result_types` has 5 call sites in preparation.rs (1984, 2002, 2022, 2082, 2117) plus monomorphization.rs:3756, 3774 (grepped). `Diagnostic`-returning `region_application::bindings` is used only inside this file (`call_results::retain`) (read; one call at :165).

### `data_applications` (:6-884)
1. Purpose. Instantiates generic data definitions for each applied generic type reference (so each `Generic{base, args}` gets a closed `DataDefinition` with substituted field types) and elaborates projected receivers; also scopes declared fields' lifetime regions to their owner. (read)
2. Shape. `field_scopes::retain` :35 (alias `retain_declared_field_scopes` :110); `elaborate` :112; `elaborate_new_types` :126; `elaborate_projected_receivers` :142; `elaborate_value_fields` :195 (recursive with an `active` ancestor stack); `elaborate_application` :300; `closed_type` :457; `instantiate_type` :596 (structural substitution over `TypeReferenceNode` variants); `instantiate_lifetime` :875; `FieldApplicationScope{declaration,supplier}` :591.
3. Inputs/outputs. Reads `type_reference_table` (all rows), data definitions, trait/conformance definitions for telescopes. Writes `retain_data_application_definition(reference, definition, is_closed)`, new type rows, operand-lifetime owners.
4. How it decides.
 - Recursion cut: `active.iter().any(|(ancestor,_)| *ancestor == owner)` (:234) keyed on base symbol identity; ancestors that contain the current reference as an argument are dropped first (:220-233).

 - "Closed" classification `closed_type` :457: `Named` is open if its symbol kind is `TypeParameter|Parameter|Local` or names a data/trait that still has type parameters (:470-488); `FixedArray` needs `declared_array_extent` (:503); `ConstExpression` needs `declared_constant_extent` (:580); `Generic`/`DynamicTrait` need an exact telescope-length match.

 - FixedArray const-parameter substitution: a `Named` actual with an invalid symbol is parsed as `usize` from its NAME text (`name.as_str().parse::<usize>()`, :767-770), i.e. keyed on source spelling.
5. Cases by shape. `elaborate_value_fields` returns without descending for `Reference` and `Slice` (:201) (value fields only); `Constrained` and `FixedArray` descend to their base/element; everything except `Generic`/`Named` returns (:214-217). ### `explicit_requirement_calls` (:1121-2285)
1. Purpose. Rewrites calls to trait requirements that name an explicit implementation (either `Impl::requirement(...)` qualified or a trailing static argument naming the implementation) into direct calls to that implementation's realization state or to the evidence binder's placeholder. Also refreshes the closed-application commitment on live occurrences. (read)
2. Shape. `route_explicit_requirement_calls` :1362; `qualified_selection_arguments` :1598; `retained_qualifier_selection` :1731; `explicit_requirement_rewrite` :1780; `struct ExplicitApplication` :1856 with `through_implementation` :1870 and `through_binder` :1988; `application_arguments::{ApplicationScope, ApplicationArguments, matches_declaring_application, argument_identities}` :1139-1333; `retain_prepared_conformance_views` :2129; `refresh_occurrence_selections` :2168.
3. Inputs/outputs. Reads all traits' machine signatures, all expression-table calls, all state statement calls. Rewrites `call.target_symbol/target/receiver/machine_arguments/static_requirement_dispatch` in place (:1550-1593).
4. How it decides.
 - A call is considered only if its target symbol is in the trait-requirement list (linear `find` :1385-1388).
 - "Qualified" means the receiver NAME PATH resolves to a symbol that is a conformance (`conformance_by_symbol(qualifier).is_some()` :1391). "Has selection operand" means the last static argument `names_implementation` and the matching parameter is not of kind `Implementation` (:1393-1400).
 - Arity check: `(qualified || !has_selection_operand) && arguments.len() > invocation_arity` -> error (:1401-1424).
 - Binder vs implementation: symbol kind `ConformanceParameter` goes through `through_binder`, anything else through `through_implementation` (:1847-1853).
 - Binder path picks the placeholder as the N-th child of the binder symbol where N is the requirement's position in the evidence requirement closure (`closure.position` :2015, `.nth(position)` :2021-2027): keyed on POSITION in the closure.
 - Realization row chosen by `row.requirement == self.requirement` (:1923-1926); target name is the last `::` segment of `row.realization_name` (:1965-1971): spelling-derived name.
 - Trait-argument agreement by `NormalizedTypeIdentity` equality over ancestor traversal (:1202-1274).
5. Cases by shape. Rewritten call sites: expression calls and statement calls only (:1440-1474). Binder call with `application` already present is refused: "an implementation evidence binder is already selected and takes no application arguments" (:1989-1991). Direct-conformance selection requires an authored application and an explicit operand (:1934-1946).
6. Same job elsewhere. Another entry to this pass in contextual_and_requirement_calls.rs:4048 (`route_explicit_requirement_calls` called from the other file). `refresh_occurrence_selections` is called from monomorphization.rs:3755.
7. Unused/one-caller. `route_explicit_requirement_calls`: 2 calls (preparation.rs:2132; contextual_and_requirement_calls.rs:4048). `refresh_occurrence_selections`: 1 call (monomorphization.rs:3755) (grepped).

9. Fail-open.
