## 3. legalization_source.rs (S)

### Purpose
Turns each validated target function (a `TargetFunction` from the target-operations plan) plus its abstract-operation and optimization-unit counterparts into a `LegalizedScalarFunction`: one `LegalizedScalarInstruction` per optimization node and one `LegalizedScalarTerminator` per block, which instruction selection consumes (header comment S:1-5). It is a projection layer: it re-checks that the three plans agree and copies/repackages fields; very little new analysis happens here (read).

### Shape
- Top-level: `SourceFunctionRosters { scalar_functions: Vec<LegalizedScalarFunction> }` S:3068; `derive_source_function_rosters(target, abstract_plan, unit)` S:3072-3088 (calls `validate_source_custody`, `normalized_foreign::validate_native_callback_roster`, then `ordinary_roster::derive_remaining`).
- `custody::validate_source_custody` S:17-32: only checks `psi` ids equal across the three plans, `entry` equal, and function counts equal. Everything else returns `Error::custody()`.
- `ordinary_roster::derive_remaining` S:40-68 loops `target.functions`; `derive_one` S:70-106 finds exactly one abstract and one optimized function with the same `machine` (`let ([abstracted],[optimized]) = ...` S:91-95) and calls `scalar_graph::derive`. Errors are re-attributed with `.attributed(target_function.machine, current_operation)` S:64. A `OnceCell` graph cache for `CallDescriptorOrigins` is created once per roster S:46-53.
- `scalar_graph::derive` S:2966-3065: builds parameters by zipping `optimized.parameters` with `call_plan.parameters` (S:2980-2992), requires equal block counts (S:2993), then per block zips `optimized.blocks` with `target.graph.blocks` (S:2997-3045). For each block: last node is the terminator, the rest ("body") must equal in count the target rows that come BEFORE the first `CleanupCall` row (`split_at(position of first CleanupCall or len)`, S:3004-3021). Instructions via `instruction::project` (S:3026), terminator via `terminator::project` (S:3042). `ownership_frontier_facts` are filtered by machine (S:3058-3063); `structural` contract from `scalar_graph_input::structural_contract` (S:3053).
- `scalar_graph::instruction::project` S:1535-2510: single large dispatcher. Sub-modules: `call_instructions` S:129-339 (`project_call` S:142, `project_boundary_call` S:242, `project_normalized_foreign_call` S:277), `scalar_instructions` S:340-767 (exact cast, integer arithmetic table, saturating/wrapping division, trapping, shift, boolean/integer comparison), `storage_instructions` S:768-1529 (structural case membership, leaf copy, borrowed window, primitive read/store, byte-sequence and element-view ops, storage address, global descriptor table).
- `scalar_graph::structural_case::project` S:2521-2610, `terminator::project` S:2621-2936, `terminator::successor` S:2937-2964.
- Helper macro `o!` S:784-790 wraps `runtime_indices::operands`.

### Inputs and outputs
Reads `TargetOperationPlan`, `AbstractOperationPlan`, `PsiOptimizationUnit`, and many helpers in `crate::legalization::scalar_graph_input::*` (that is module `G` plus siblings), `crate::legalization::runtime_indices::{projection, operands, collection_view, reference_source}`, `crate::structural_inputs::structural_reference_input::*`. Produces `LegalizedScalarFunction` values pushed into `rosters.scalar_functions` (S:65). No mutation of plans.

### How it decides
- First by the TARGET row type, then by the abstract operation (S:1552-1744 vs S:1745-2496): if the target row is `Call` -> `project_call`; `StructuralLeafCopy` + abstract `BoundaryCall` -> `project_structural_leaf_copy`; `InstallStaticInterrupt`, `StaticInterrupt`, `AccessLifecycle`, `ProgramImageAddress`, `AccessorScalarAccess` each have an inline branch; otherwise `match &node.operation` (S:1745). Judgement is keyed on enum variant, not on names.
- `BoundaryCall` has four guarded arms in order (S:2151-2248): (1) a `NormalizedForeignCall` target row exists for that operation, (2) an IEEE-float-arithmetic row exists, (3) `hosted_realization(..)` is `HostedReadByte`, (4) fallback `project_boundary_call`.
- Integer arithmetic is a table on `(overflow policy, operator)` S:405-426. Exact policy requires an accepted obligation fact AND that the operation references the obligation (S:703-707). Wrapping/saturating division require exactly one accepted non-zero-divisor fact (`accepted_nonzero_divisor_fact` S:560-575, "facts.next().is_some()" -> error).
- Operand type checks compare `scalar_graph_input::value_type(optimized, v)` to `ScalarType::Integer(t)` (S:442-446, 531-535, 619-623, 647-653).
- Terminator `InvokeNoNormal` is re-verified against the target row: unique matching row by `psi_edge` and callee, equal claim transfers, requirement obligations, crash continuations, argument counts and sources, `declared_result` equals the callee's result, and `call_plan == callee_plan(...)` (S:2646-2733), then `validate_no_normal_shape` and `validate_source` (S:2748-2751).
- `ReturnStructural` classification: descriptor return -> `SharedDescriptor`; structural parameter -> `StructuralParameter`; otherwise `Structural{source_owner}` (S:2819-2833). `Return` is accepted only if `scalar_shape(scalar_type)` exists (S:2859).
- Cleanup calls from `cleanup_calls::expected` are attached to `Return` (-> `ReturnCleanup`) or to the successor whose edge equals `owner.edge()` (S:2895-2934).

### Cases by shape
- `project_boundary_call` accepts only a boundary call with EXACTLY ONE argument whose realization is `HostedWriteByteI32`; anything else `Error::custody()` (S:257-272).
- `InstallStaticInterrupt`: calls list is mapped with `arguments[if position == 0 { 0 } else { 5 }]` (S:1594) and the `indices`/`calls` Vecs are `try_into()`-converted into fixed-size arrays (S:1587-1589, 1625-1626); so it is limited to a fixed two-call shape with six arguments (inferred from the index 0/5 and `try_into`).
- `ActivateTaskRegister` uses `[gdt, task_state, scratch]` -> `[Vec;3]` (S:2067-2084); `ReloadSegmentDescriptors` uses `[gdt, scratch]` -> `[Vec;2]` (S:2108-2123).
- `ByteSequenceLength` returns a `Constant` if a fixed byte length is known, else uses `length_byte_offset: 8` for `BorrowedView` carriers and `0` otherwise (S:2337-2371); `ElementViewLength` always `length_byte_offset: 8` (S:2392). No comment explains the numbers.
- `IeeeFloatConstant`/`BooleanConstant` are lowered to `Constant(IntegerValue::Unsigned(bits))` (S:2450-2465).
- `IntegerShift` with a non-`Exact` policy is lowered to wrapping shift without any further obligation (S:656-665).
- Unlisted abstract operations: `_ => return Err(Error::custody())` (S:2495); unlisted terminators `_ => Err(Error::custody())` (S:2893).

### Same job elsewhere

### How it decides (keys)

- A "definite" overlap is required for rejecting duplicate call arguments (`roots_definitely_overlap` C:3735, used C:5435-5439); a "may" overlap (`roots_overlap`, C:3718) is used for access conflicts and dependencies (C:5453, 5465).

- Call arguments (`call_arguments` C:5244-5472): reference-bearing carriers are only accepted if every path segment is Case/Field/FixedIndex/RuntimeIndex (C:5286-5296), a reference-containing selection may not use RuntimeIndex (C:5278-5285), conflicts via `storage_access_conflicts` (C:5298-5317), pairwise overlap between arguments (C:5399-5446), and dependency checks (C:5447-5470).
