## Five things a maintainer most needs to know about this unit

1. `rewrites.rs` is the hub for ten pre-allocation families, and each family is enumerated ten separate times in this file (catalog rows 693-774, policy bits 2188-2207, transformation enum 2297, identity enum 2362, `instruction()` 2321, `identity()` 2336, `From` forward 2375, identity-encoding tags 2119-2122, custody error enum 2618-2629, `transformation_accessors!` 2275). Adding or removing one family means touching all of them; the seventeen-variant `PostAllocationSelectedTransformation` in `assignment.rs:383-433` is an eleventh place with its own hand-numbered tags (1-17, not in declaration order).
2. The pre-allocation loop is keyed on a hand-built numeric `measure` (1313-1349) that must strictly decrease after every applied rewrite (1838-1845), and the pass count is capped at the initial measure (1823). A new rewrite that does not lower `measure` is rejected at run time with `PreAllocationMeasureMismatch`, not at compile time. Every family refusal other than three named retryable errors is collapsed into "declined" (1197, 1692, 1757).
3. `validate_pre_allocation_optimization_custody` (1934-1984) validates by replaying the whole `run_passes` loop on the stored source and comparing; there is no separate checker. Its step-mismatch error always says step 0 (1963).
4. `assignment.rs` register recovery (`runtime_spill::recovery::recover_over`, 1681-2024) is one ~340-line loop that picks a victim, tries split, then rematerialization, then spill, re-analyzes only changed functions and re-probes home assignment each round; it publishes only when `probe_all` succeeds (2002-2010). Its production victim-ranking (`select_roster_candidate`, 1454) differs from the test-only `candidate_position` (1356) that the in-file unit tests exercise.
5. The `transformed` module (2761-3052) and the pre-allocation/selected-lowering halves of `recovery` (691-743) are line-for-line parallel pairs over `PreAllocationResult` and `SelectedLoweringResult`; `RuntimeSpillAllocationError::RecoveryNotRequired` (2632) is never constructed (1 grep hit, its declaration); `AllocationRecovery` rows are in the stage-04 catalog (104-107) but not resolved by anything in `rewrites.rs`.
