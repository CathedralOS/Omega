# FILE 1: P05/checks_borrows_resources.rs (7148 lines, all read)

## 1. Purpose
Builds the "resource rows" of the borrow checker once, so execution planning and Psi 06 consume them instead of rebuilding them (header comment, :1-8). It joins loan ancestry and lifetime events already recorded by earlier phases, checks that each reborrow only attenuates access, builds the parent graph between loans, and produces "disposition events" (what happens to a parent's authority when a child reborrow ends). The file is a single entry function (`initialize_checked_direct_borrow_resources`, :7073) that runs about ten sub-passes in a fixed order and writes the result into `CheckFacts.borrow` arenas. It is a file of inline `mod`s; the file itself has no types of its own apart from the helpers listed below.

## 4. How it decides (what each judgment is keyed on)
- Parent of a reborrow: matched by loan handle equality `resource.loan == child.parent_loan` across direct, earlier reborrows and supplied outputs; zero or more than one match is a "drift" error (:2812-2836). Keyed on identity (loan handle).
- Direct vs reborrow vs ignored: keyed on `loan.lineage` (:2954-3217). `LifetimeDependency | UnretainedDerived | SuppliedOutput` are skipped here (:3215-3217).
- Access attenuation: `parent.kind.direct_reborrow_effect(&loan.kind)` returning `None` is the error (:3033, :2962); the allowed pairs are quoted in the diagnostic text (:7136): "Read->Read, Mutable->Read, Mutable->Mutable, Mutable->WriteOnly, and WriteOnly->WriteOnly".
- Lifecycle ordering: `LifecycleBoundaryKey` derives `Ord` on `(statement_index, phase)` (:2464-2468); events are sorted by `(boundary, loan_order)` (:546) and applied in batches of equal boundary (:548-579). Keyed on statement position and phase.
- Exactly-one rules: `exact_loan_lifecycle_rows` requires exactly one activation and one weakening per loan and that the activation source is `Statement{statement_index: loan.statement_index}` (:2590-2617). Parent weakening must be exactly one (:3120).
- Restored-call binding: keyed on statement index of `child.weakening_source` (:913), `call.statement_index` equality (:927), `borrow_call.{statement_index, call_ordinal, target_symbol, receiver_symbol, has_receiver, accesses}` equality (:969-976), exactly one parameter that is `Mutable` reference (:989-1003), exact constraint roster counts (:1058-1078), and `call_write_accesses` returning exactly one whole-root place equal to the parent owner (:1089-1096).
- Permission supplier selection (`permission_sources::collect`, :3617-4022): chooses among rules in a fixed priority order: completed invocation, completed output, frozen-reference-unavailable, formed projection, selected alternatives, entry invocation accesses, completed formations, descriptor captures, frozen endpoint, retained suppliers, reborrow sources, binding observation, invocation accesses. Keyed on `capture.completion`, `capture.descriptor_permission`, frozen-leaf classification and retention profile, not on names.
- `returned_projections` and `stored_call_inputs` compare `formation_expression`, `statement_index`, `storage_owner` and owner path (:1501-1506, :5838-5862) by value equality.
- Source spelling: `format!` of debug values appears only in diagnostics (:1313-1325 uses `{:?}` of symbol names, state, call target; :2591-2607; :3386-3390; :5925-5936). The `PermissionFailures` rule strings (`&'static str`) are the only per-rule labels; nothing branches on them.
- `has_captured_entry_reference` (:3520) keys on `IncomingReferenceOrigin::{ParameterReferent, Parameter}` (:3584-3588) and type compatibility (`direct_reborrow_effect` + `storage_origin_types_match`, :3601-3612).

## 9. Fail-open risks (accept / keep / skip on an unknown)
All traced only by reading this file; callers outside the file were not read except where stated.
1. `call_operands::install` discards the result of `install_resource` (`let _ =` :72). `install_resource` returns `None` when the owner operand is invalid (:86-93), `carrier_path` is `None` (:99) or the backing root differs from the parent-lifetime root (:100). Status: "stated" for the missing-provenance case (comment :17-18, "Missing provenance produces no resource"), but the root-mismatch drop at :100 has no stated reason: "open". 2. `call_operands::collect` returns silently (no resource) if `view_link::borrow_carrying_owner_paths` is `None` or empty (:133-140), if an alternative branch has an invalid `source_arm` (:151-153) or does not cover every leaf (:167-173), or `place_at` is `None` (:279-286). ## 1. Purpose
Checks "content-bearing" custody: some owned linear values carry a qualified quantity (a content projection such as a counted quantity or interval set, with a conservation algebra). This file decides whether (a) a body that returns such a value has proved its conservation equation at each normal return, (b) each call result's qualification is justified by an issuance route, a consumed input claim or a conservation equation, (c) retained content in a declaration has an owned source or a lifetime-bound borrow, and (d) partition equations can be composed through wrappers. It publishes rows into `facts.qualifications.content.*` and returns `Vec<Diagnostic>` for failures. Header comment :1-21.
