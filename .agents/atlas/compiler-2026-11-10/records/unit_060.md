## 1. flow_call_phases.rs (2370 lines) — read in full

**Purpose.** Header (FCP:1-6) says this holds the phases `calls::build_call_flow_fact` runs: entry contexts with the call's borrow constraints, `requires` contexts, invalidation over the call's written places, `ensures` exit contexts, and field facts re-seeded on readable `&mut` referents. In effect: after a call, decide which previously known facts (domain memberships, contract facts) survive the callee's writes, which borrow-loan constraints remain, and which new facts the call hands back.

**Shape.** Everything is in nested inline modules, re-exported at the bottom (FCP:2194-2200).
- `mod copied_guarantees` (FCP:20): holds
  - `struct ArgumentSources<'program,'writes>` (FCP:376) fields: program, state, statement, parameters, arguments, `writes: Option<&[CanonicalPlace]>`, `captures: Vec<CapturedSource>`.
  - `struct CapturedSource` (FCP:390): operand, position, destination path, expression, type_reference, `later_writes: Option<Vec<CanonicalPlace>>`, `referents`.
  - `ArgumentSources::new` (FCP:579) builds captures from `captured_operands` and requires `parameters.len()==arguments.len()` and captured expressions to equal receiver+arguments, else returns `None` (FCP:603-610).
  - `retain_capture` (FCP:441) recursive over operand children; `writes_after_capture` (FCP:400).
  - `referent_places` (FCP:524), `inline_write_places` (FCP:541), `retained_sources` (FCP:647), `completed_calls` (FCP:697), `observation_survives` (FCP:721), `source_survives` (FCP:798).
  - `retain_guarantees` (FCP:814): drops contract-derived facts from the call's ensures contexts whose referenced parameter occurrence no longer survives.
  - sub-mod `captured_aliases` (FCP:27): `mutation_observation_aliases` (FCP:46). sub-mod `captured_writes` (FCP:163): `confined_write_parameter` (FCP:179), `captured_write_enclosures` (FCP:205), `intersect_captured_enclosure` (FCP:246) + 3 unit tests (FCP:304-359).
- `mod instruction_effects` (FCP:895): `append` (FCP:907) adds one `FactPayload::InstructionEffect` (if the callee is a builtin asm-register intrinsic that `is_admitted()`, FCP:916-921) or `FactPayload::CallCompletion` otherwise, at `ProgramPoint::CallEnsures`, with `FactPlace::Unknown`.
- `mod invalidation` (FCP:949): `CallInvalidationResult` (FCP:966), `CallStorageWrites` (FCP:978; fields `observation_places`, `contributions: Vec<ObservedCallMutation>`, private `binding_places`), `ObservedCallMutation` (FCP:1030: write + observations), `call_storage_writes` (FCP:1095, memoized in `build.call_sites[..].storage_writes`), `call_storage_mutations` (FCP:1156), `apply_call_invalidations` (FCP:1235).
- `mod reference_custody` (FCP:1324): `install_returned_reference_custody` (FCP:1339), `incoming_reference_survives_call` (FCP:1386), `finish_statement_reference_custody` (FCP:1435).
- `mod referents` (FCP:1453): `append_call_referent_field_domain_facts` (FCP:1682); inner `batches::append_place_contexts` (FCP:1486), `guarantees::{ReturnedGuarantee, PreparedGuarantees}` (FCP:1532, 1548), `completed_return_keeps_byte_class` (FCP:2169).
- Free functions: `CallFlowContexts` (FCP:2202), `build_call_entry_contexts` (FCP:2207), `build_call_requires_contexts` (FCP:2248), `build_call_exit_contexts` (FCP:2267), `build_call_contract_contexts` / `append_call_contract_contexts` (FCP:2341, 2355).

**Inputs/outputs.** Reads `CheckingInput` program tables, `BorrowFacts`, `ProofFacts`, `FactPlan` (semantic), `FlowControlFacts` operand tables, `build.call_sites`, `build.call_frames`, `state_mutation_summary_cache`. Mutates `FactPlan` (appends facts/places/refs), `build.contexts.{semantic_context_refs,constraint_refs}`, `build.invalidations.*`, and returns span handles.

**How it decides.**
- Whether a callee write invalidates a fact: `apply_call_invalidations` passes a closure to `domain::filter_contexts_after_mutations` (FCP:1262-1306): first `region.preserves_owner_qualification(...)` (FCP:1275), then `domain::matching_mutation_for_fact_place` against `contribution.observations` (FCP:1296). Keyed on canonical places (root + segments), not names. Empty `contributions` => nothing invalidated, early return (FCP:1245). `writes == None` => `HandleSpan::empty()` post contexts i.e. all facts dropped (FCP:1261).
- Whether a copied/ensures contract fact survives: `retain_guarantees` -> `observation_survives` (FCP:721) keyed on the argument's literal projection, capture identity (exactly one candidate capture at the same destination, FCP:756-761), whether the capture binds a live view (FCP:762), and `source_survives` (no overlapping write in callee writes + later writes, FCP:798-811).
- Whether a returned reference loan stays: `install_returned_reference_custody` filters `BorrowLoan` by `replaces_reference_loan` and `BorrowIncomingReference` by `incoming_reference_survives_call` (FCP:1355-1373). Keyed on loan/identity handles and canonical owner paths.
- Re-seeding field facts on `&mut` referents (FCP:1682-2161): per parameter, finds exclusive referent type, declared result field-domain paths, authored claims; creates `ReturnedGuarantee` rows with `proven_at_exit` true/false (FCP:1788-1862); decides restoration of preexisting memberships through `PreparedGuarantees::restores` (FCP:1581) keyed on formal parameter symbol + domain symbol + domain instance id + place equality (exact bucket hash for static-identity places, FCP:1609-1616) or `same_occurrence_when_selected` (FCP:1625).
- Source spelling: `intersect_captured_enclosure` compares `PlaceSegment` values; no names. `ensured_parameter_position` is in FC. `parameter.name` string compare is not used in FCP (grep of `name.as_str()` not run; none seen in read).

**Cases by shape.**

**Same job elsewhere.**
- `call_storage_writes` is memoized through `build.call_sites` (FCP:1109-1115, 1148-1152); `flow_calls.rs` has three more memoizers for call info (`memoized_call_target_return_type` FC:271, `memoized_call_target_parameters` FC:282, `memoized_find_call_site` FC:293). `append_call_referent_field_domain_facts` also uses `build.referent_type_paths` (FCP:1739) and `build.call_parameter_identities` (FCP:1731).

## 2. flow_calls.rs (1071 lines) — read in full

**Purpose.** Builds the one `FlowCallFact` for a borrow-checked call (FC:1-7): runs the call phases from flow_call_phases.rs in order and fills the fact. The functions after it work out which domain memberships a callee promises on its result and on its out-parameters.

- Memoizers: `memoized_call_target_return_type` (FC:271), `memoized_call_target_parameters` (FC:282, pub(super)), `memoized_find_call_site` (FC:293, pub(super)).
- Result-domain vocabulary: `append_call_result_field_domain_facts` (FC:459), `result_identity_is_available` (FC:538), `checked_realization_result_identities` (FC:595), `call_result_qualification_identities` (FC:810, pub(crate)), `call_result_qualification_identities_indexed` (FC:849), `result_identity_rows` (FC:887), `visit_qualified_ensures` (FC:908), `append_ensures_result_rows` (FC:939).

**Inputs/outputs.** Reads program tables, `ProofFacts::contract_call_at`, `BorrowFacts`, `FactPlan`, `FlowBuildContext` caches. Appends facts (`DomainMembership`, `CarryPermission`, `CarryOrigin`) at `CallEnsures` points and contexts to `exit`; mutates `active_contexts/active_constraints` to the exit set (FC:185-187).

**How it decides.**
- Carry transfer (`append_one_to_one_call_carry_facts`, FC:317-445): applies only when return type multiplicity is `Linear` (FC:332), there is exactly ONE argument whose parameter type carries a linear obligation (FC:373 `let [source_argument] = linear_inputs.as_slice() else { return }`), and every linear-carrying parameter type is itself `Linear` (FC:363). Matches an existing carry fact to the source argument by `semantic.places_match(...)` OR by label equality `fact_label != source_label` (FC:420-424; labels from `program.expression_table.display_name` FC:388 and `semantic.place_label` FC:419) — a source-spelling comparison. Copies only facts with evidence origin != None (FC:401).
- Result facts (FC:459-531): skips reference returns (`reference_shell`, FC:483); rows filtered by `result_identity_is_available` (FC:538), keyed on domain identity `(SymbolHandle, SemanticDomainId)` and, for bodyful checked realization adapters, on `selected_call_result_domain_matches` (FC:568). Rows are domain definitions with a `BoundaryRequirement` establishment route (FC:553-559).
- Parameter facts (FC:635-723): skip if the arg has `referent_places` or does not survive (`observation_survives(position,&[])`) (FC:686-689); require `domain_requires_provenance` (FC:691). Position found by `ensured_parameter_position` (FC:1050): matches parameter by `parameter.name.as_str() == name.as_str()` OR symbol equality (FC:1066-1069) — name string compare present as one disjunct; skips `names_reserved_result`.

## Five things a maintainer most needs to know about this unit

1. All five files are pieces of one stage (the "flow" builder in crate 05): `flow_call_phases.rs` + `flow_calls.rs` build one `FlowCallFact` per call (FC:39), `flow_exits.rs` builds guard/exit/outgoing facts (FE exits:1551, :1398, :1367), `flow_context.rs` holds the shared mutable `FlowBuildContext` (flow_context.rs:198), and `flow_expression.rs` is the per-statement evaluator `Execution` (FE:9366) that calls all of them. `append_statement_calls` (FE:9410) is called once, from flow.rs:5081.
2. "Unknown" is encoded by sentinel values rather than by `Result`: `Handle::invalid()` (99 occurrences in flow_expression.rs), empty `HandleSpan`, `Option<Vec<..>> == None` for unknown writes (`OperandMutation`, FE:9361), and `Some(None)` for "prepared unknown" (flow_context.rs:55-60, :917-956). Consumers outside this unit decide what an empty/invalid value means; inside the unit the convention is that unresolved addresses/lifetimes drop to empty rather than being reconstructed (stated FE:13-14).
3. Decisions are keyed on identities (symbol handles, `CanonicalPlace` root+segments, expression handles, loan handles, domain `(symbol, SemanticDomainId)` pairs), with a few source-spelling exceptions: label equality in `append_one_to_one_call_carry_facts` (FC:420-424), parameter-name compare in `ensured_parameter_position` (FC:1066-1069) and `signature_reserves_result` (FC:949-953), `"result"` string compares in `contract_returned_value` (flow_context.rs:1120, :1127), and `"{subject_label}.{field.name}"` substitution strings in `append_case_constraint_context` (flow_exits.rs:500-517).
