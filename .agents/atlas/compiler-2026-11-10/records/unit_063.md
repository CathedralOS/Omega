## File 2: published_facts_boolean_predicates.rs (1-2576)

**Purpose.** "True relational formulas over exact current storage" (1-5). Holds `BoundPredicate` (a checked Boolean expression plus a list of observations, each bound to a `CanonicalPlace` and a type reference). It builds them from guards, contracts, domains and matches, publishes them as `BooleanPredicate` facts, retains them from fact contexts, rebases them onto invocation entry values, and runs a small finite truth-propagation closure (prove / truth / unsatisfiable / infer Boolean at place / integer interval at place / constant at place).

## Five things a maintainer most needs to know about this unit
1. `published_facts.rs` is an aggregator of about 30 inline modules plus the fixed-point driver `build_check_facts` (10963-11145) and `finish_check_facts` (11148-11486); the crash-related parts span all three files (`crash_plan_facts` 3722, `contract_plan_facts` 2462, `operator_crashes` 7882, `static_callable_crashes` 10685, and all of `published_facts_crash_calls.rs`). Comments name files that are actually inline modules.
2. The crash pipeline works by DROPPING routes proven impossible. Drop sites are enumerated under file 3 "Fail-open risks" and file 1 (`retained_operator_crash_routes` 8583-8629). Route identity is a structural `CrashPredicateExpression` that still contains strings: parameter names (4983-4991), call target text (5017), member/name text (4992-5006), `Opaque(display_name)` (5027), and `Variant::field` via `format!` (5492).
3. `published_facts_boolean_predicates.rs` owns bound Boolean predicates over exact `CanonicalPlace`s. Normalisation keys on (place, primitive/type_reference), the closure only propagates through `And/Or/Not/Equal` and integer `Equal`, and `unsatisfiable` only fires on a contradiction between already-established truths. `map_observations` refuses `ErasedParameter`, IEEE comparison, structural identity and byte-sequence forms, so those never become bound predicates.
4. Contextual cleanup requirements are inferred in a fixed point between flow construction and permission events (11059-11129), with `selected_requirements` (1148) shared by inference (871) and final checking (1396); inference `continue`s are backstopped by the final check.
5. There are several parallel hand-written walkers and duplicates: identical bodies for `canonical_crash_path_predicate`/`canonical_crash_contract_predicate` (4413/4475), the invocation-target string encoding twice (3856, 7826), `build_blocking_facts`/`build_suspension_facts`, and at least five Boolean-expression walkers across files 2 and 3.
