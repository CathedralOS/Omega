3. `bounded-process` limits are applied unevenly: Unix sets Core/Cpu/As(Linux)/Fsize/Nofile only; `active_processes` and both memory ceilings exist only in the Windows Job Object (limits.rs:22-29, process_child.rs:74). The Unix `capture_private_observation` runs the child with plain `command.output()` while the Windows one runs under the bounded runner (private_observation.rs:132 vs windows.rs:196-243).
4. `optimization-core` is the single registry for the 55 optimizations and all canonical wire records; encoders/decoders are strict (unknown tags, trailing bytes, order). The one asymmetry is `BaselineDecisionLog::decode`, which accepts any self-consistent roster/choice and allocates from an unverified count (baseline.rs:155-178).
5. `terminal-runtime` host binding is a fixed ordered chain of per-C-function adapters (host_imports.rs:455-606) keyed on normalized foreign locators; everything else is refused with "no trusted host implementation". `absolute_value.rs` carries its own copy of the locator-matching logic and the allocation/abs adapters repeat the same owned-cell check three times.
