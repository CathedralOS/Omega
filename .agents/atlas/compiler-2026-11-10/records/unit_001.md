# Five things a maintainer most needs to know about this unit
1. The Build lifecycle is a poisoned-on-failure state machine: `TerminalBuildActivation` sets `Refused` before every fallible transition and only restores `Running`/`Returned` on success (activation.rs:350, :393, :457), so any failed `advance`, `install_provider` or `answer_query` kills that activation permanently; `orchestration` drives it (`execute_build` build_execution.rs:142, `ReadinessScheduler::drive_work` readiness.rs:171) and the compiler crate must not (build_boundary.rs:186-197 enforces this with substring tests).
2. A completed `Pure` Build result is reused inside a session when 13 inputs are equal (completed_pure_build.rs:116-130) and only if the run touched no filesystem, produced no outputs and no generated sources (:224-243); reuse charges the recorded usage to the current sponsor (build_evaluation.rs:330-349), and `source_join` is reset to None on reuse (:353).
3. Several structural rules are enforced by source-text substring tests, not types: build_boundary.rs reads other crates' source with `include_str!` and fails if a call name moves or an order changes (e.g. `fn drive_work(` / `fn build_request(` anchors :45-51).
4. Native artifact validation refuses any module with a nearest-FMA operation (native_artifact.rs:1076-1090, called at :546 and dynamic_elf.rs:137), and the component-description wire format cannot round-trip a description that has both register-access and service-ceiling outgoing rows (component_description.rs:121-134 vs :1246-1251) (both read-only inferences; neither executed).
5. CLI exit-status policy is split across three tables: parse errors 64 (arguments/mod.rs:57), compile refusals 1 or 2 with batch unanimity (commands/compile.rs:219-229), and `omega run` 200/201/202/203 with guest codes passed through (commands/run.rs:31-51, :311-323); `--both` with `--target` silently skips the interpreter comparison (execution/mod.rs:215) and a `Declined` comparison leaves the native exit code unchanged (commands/run.rs:109-121).
