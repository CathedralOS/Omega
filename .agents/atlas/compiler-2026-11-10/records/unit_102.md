## FILE 1: program_validation.rs (4993 lines, read in full)

**1. Purpose.** Whole-program semantic validation coordinator. `validate` (4067) runs a declaration prologue, then per-machine statement validation in parallel (rayon), merges the results, and either fails with diagnostics or returns `ProgramValidation`. A second phase, contract entailment (`judge_machines` 4727), is deferred and can reuse prior judgments through a body-hash cache. Public entries: `validate_program` (3946, validate + entailment), `prepare_specialized_program` (3970, validate with `QuotientRequestAdmission::AfterCheckedFacts` + `EffectAdmission::AfterOwnership`), `judge_contract_entailment` (4668), `admit_prepared_program_effects` (4839).

## Five things a maintainer most needs to know about this unit
1. `program_validation.rs` has two validators for the same statements: the per-machine statement pass (`validate`, parallel by machine) and the deferred entailment pass (`judge_machines`); the latter can skip work by reusing a prior judgment keyed on hashed SOURCE TEXT of statements and contract facts plus a dependency context (1216-1276, 860-887). A machine with no authored span is never reused.
2. The prologue runs ~40 validators in parallel only when nothing has failed and no two share an integer obligation; any failure or overlap makes the whole prologue re-run serially (595-641), so every validator runs twice on failing or overlapping programs.
3. Exact-arithmetic overflow errors are separated from other errors by matching message text (4645-4649) and deferred; they only fail the program once `discharge_storage_formations` / the caller surfaces `deferred_overflow` (3897-3920, 3957-3966).
