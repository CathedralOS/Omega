## CC: checks_contracts.rs

### Purpose
Root module of the contract checker (`checks::contracts`). It proves, from checked flow facts, each call's `requires`, each exit's `ensures`, self-transition arrival requirements and writes into domain-refined fields (CC:1-34). The file is mostly inline `mod` blocks; five children live in sibling files via `#[path]`: `calls` (CC:579-580, = CCC), `exits` (CC:1464-1465), `writes` (CC:1828-1829), `prover` (CC:3925-3926), and others later in the file. Entry points named in the header: `bind_call_evidence_arguments` (runs first) and `check_flow_call_contracts` (after borrow check), both called from `checks::check_checked_facts_recording` (CC:6-12).

## Five things a maintainer most needs to know about this unit
1. `check_flow_call_contracts` (CC:11607) is the driver: per-state work runs in a rayon `par_iter` (CC:11681), and a call's `DecidedCallRequires` is recorded only if no new diagnostic was pushed for it (CC:11735-11743). Exit checks run sequentially afterwards and de-duplicate diagnostics per exit (CC:11843-11847).
2. A call requirement is proved by a chain of about twenty OR'd routes (CCC:3270-3372, CCC:99-186) that mix identity-based judgments (captured operand epochs, canonical places) with source-spelling routes (display-name label equality, text scanning of labels: CCC:1889-2036, 2910-2977, 3146-3149; CC:2617-2651, 10442-10443, 11305). When `captured_boolean::judgment` returns `Some`, it is final and no spelling route runs (CCC:233-236, 3304-3314).
3. Unproved Boolean requirements with builtin operators are not always errors: they can become retained `ConstantRecipeObligation` / `ConstantPredicateObligation` rows (CCC:3407-3474) for later discharge; the error appears only if both conversions fail.
4. Several judgments return `Option<bool>` where `None` means "unknown, try other routes" and `Some(false)` means "capture-owned refusal" (CCC:233-236; CC:3190-3193). Callers that collapse with `.unwrap_or(false)` (CC:3821, 4260, 4955) are fail-closed; `call_site_boolean_contract_expression_value` returns `None` for unknown so crash routes are kept (stated CC:3190-3193).
5. Large parts are bounded recursive walks with ad hoc caps (64 depth / 4096 nodes in `Denotations`, 64 in `positive_comparison_expression`, 8 in `projected_case_requirement_labels`, 256 in `bound_contract_predicate`), each returning "no proof" at the cap.
