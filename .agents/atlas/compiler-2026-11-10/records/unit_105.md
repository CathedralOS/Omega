## File 3. `terminal-installation/src/evaluation_and_synchronous_calls.rs` (1402 lines; read in full)

**Purpose.** Two modules. `compiler_evaluation` decides whether a compile-time ("build-time") invocation of a root declaration may be run: its crash routes must be provably impossible, its call closure must terminate, effects must be inside a floor, and package custody must allow selection. `synchronous_calls` walks the synchronous call graph (machines, boundaries, dynamic dispatch, cleanup machines) from a root.

**Shape.**
- `compiler_evaluation::failures::require_root_failure_admission(module, root)` (evaluation:24-63); helpers `exclude_failure_routes` (65-128), `require_formed_operands` (130-158), `require_formed_scalar` (160-234), `require_formed_integer_math` (236-272), `closed_guard` (274-331); a large `#[cfg(test)] mod tests` (333-791).
- `AdmittedCompilerEvaluation {providers, artifact, target, declaration}` (795-800), `require_invocation` (806-827), `admit_compiler_evaluation` (830-974), `CompilerInvocationScope` + `compiler_invocation_scope` (976-1033), `header`/`declaration` lookups (1035-1060), `require_selection` (1062-1086), `covered_recursive_edge` (1088-1113).
- `synchronous_calls`: `SynchronousCallClosure {machines, boundaries}` (1126), `SynchronousCallGraph {module, machines: BTreeMap<MachineId,&TerminalMachine>, target_members, entry_bridge, boundary_calls}` (1131); methods `new` (1147), `with_boundary_calls` (1170), `boundary_callee` (1194), private `boundary_call` (1201), `from_root` (1226), `dynamic_callees` (1300); one test (1349-1400).

**Inputs/outputs.** `admit_compiler_evaluation` reads `artifact.module().scalar_applications.proof_scope` (headers, callables, plan, `pending_evaluation_conditions`, `recursive_components/members/calls`) and the `AdmittedProviderSelections`; it returns `AdmittedCompilerEvaluation` or `String`. It calls `semantic_vocabulary::compiler_evaluation::require_compiler_evaluation_floor` and `require_compiler_evaluation_failures` for the final verdicts (evaluation:59-62, 962-967).

**How it decides.**
- Root failure admission: exactly one `ProofCallableAssociation::Callable{declaration==root}` mapping to a `TargetMachineCallable::Machine` (evaluation:31-51). The crash summary (`machine.contract.crash_routes`) must be well-formed (sorted by cause, alternatives non-empty, sorted, `Truth` only alone; 69-81), within evaluation size (82-90), each predicate valid in the machine's entry proposition context (94-98) and with no undefined closed operand (99). Then every alternative must evaluate to `Some(false)` via `closed_guard` (102-126); `Some(true)` is "can occur" and `None` is "cannot be proved impossible". Keyed on proposition structure and closed integer/boolean values, not names.
- `closed_guard` (274-331): `Truth/Falsehood`, Boolean `Equal` over closed values, integer comparisons only when both operand types are equal (`left_type == right_type`, 290), `IntegerMath*` via `ClosedIntegerEvaluator`; `Conjunction/Disjunction` short-circuit on a decided child and return `None` if any child is unknown and none decided; `Implication` handles `Some(false)` premise as true, otherwise conclusion (with `None` premise only a `true` conclusion counts, 327). Anything else returns `None` (329) i.e. not provably impossible (fail-closed here).
- `admit_compiler_evaluation`: rejects an authored `requires` premise (849-854); runs root failure admission (855); computes the invocation closure (856); rejects assumed bindings whose required or supply-path boundary is in the closure (862-873); rejects if `pending_evaluation_conditions` owner is 0 or in `dependencies` (874-878); accumulates effects (services, may_suspend, may_block; 884-892); records first `static_application` or `linear_carrier` text as `closure_violation` (893-898); requires `local_terminates` unless the machine is a `selected` provider target (899-909); checks `require_selection` custody for each machine request and each non-provider, non-static-delegation edge (910-934); detects recursion by DFS over `closure.invocations` (937-956) and requires `covered_recursive_edge` (957-960).
- `require_selection` (1062-1086): `Toolchain` custody on either side passes; `Package/Package` passes if `authority.allows_declaration_selection`; `UnownedUser` or anything else errors.
- `covered_recursive_edge` (1088-1113): requires `call_ordinal` on the edge, `!edge.provider`, and a recursive component whose members contain both endpoints and whose `recursive_calls` contain the exact (caller, callee, ordinal).
- Synchronous graph: `boundary_call` (1201-1224) resolves a boundary first via the `entry_bridge`, then via `admitted_boundary_member`, else via the `boundary_calls` table (binary search); `from_root` pushes module invocations, boundary invocations, nominal cleanup machines, and `CallDynamic` callees; `dynamic_callees` (1300-1339) picks the exact slot, or for `finite_family` all following slots with non-empty `family_tuple` and equal `requirement_identity`, then every table of that interface.

**Cases by shape.**

### storage_contents (9774-10626)
- **Purpose.** The single "what does this type contain" query: `has_contents(program, reference, substitutions, ContentsRequirement)` (9944) and `data_has_contents` (9953). ## Five things a maintainer most needs to know about this unit

1. **Many judgments are keyed on source names and toolchain file paths, not identities.** Examples: sealed activation/fence recognition by `"toolchain::..."` identity string plus relative source path (value_custody_core.rs:28-37, 601-610); `"ConsoleNativeProvider::write_byte"`, `"ProcessExitNativeProvider::exit_process"`, `"ConsoleNativeProvider::read_byte"`, `"ByteRead"`/`"Eof"`/`"Byte"`/`"value"` (5207-5215, 5107, 5262-5272); `"Extent"`, `"Granted"`, `"Resident"` and `extent.omg` (8830-8879); `PreservingDecode`/`decode_preserving`, `FormatMigration`/`migrate` (type_references_and_wire.rs:5777-5780, 5980-5983); `"compact_binary"` codec string (5633). `destructure` exhaustiveness is decided from marker prefixes in synthetic local names (`"__destructure#"`, `"__arm_destructure#V="`, value_custody_core.rs:4262-4263).
2. **A repeated `!program.symbols.has_source_metadata() && name == ...` fallback** appears at least eight times in type_references_and_wire.rs (1488, 1554, 5195, 5231, 5374, 5422, 6752, plus `symbols.has_type(name)` at 5205, 5454): name lookup is used only when the program carries no source metadata, otherwise only symbols.
3. **`storage_contents::has_contents` is the one shared "what is inside this type" query** with 13 requirement kinds and many per-requirement `matches!` lists (value_custody_core.rs:9928-10450); other modules in the file (`content_classes`, `cleanup`, `owned_value_source`, `scalar_case_constructor`) call it instead of re-walking types.
