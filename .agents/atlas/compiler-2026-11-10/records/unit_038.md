## 4. evaluation_accounting.rs (702 lines)

**Purpose.** Keeps receipts of every build-time evaluation run during source completion (one receipt per invocation), and checks afterwards that each receipt's work charge is consistent (schedule identity, budget, attribution sums). Receipts are `Record`s so they can be stored and replayed.

**How it decides.**
- Receipt validity is keyed on identities and numbers: schedule identity equals `WorkSchedule::CURRENT.identity()`, `total_units <= budget`, attribution rows sum to `total_units` (:160-173, :408-422); checked receipts compare `semantics` to `CURRENT_EVALUATION_SEMANTICS` and usage schema/schedule/work budget to the interpreter's current constants (:298-315).

- Scalar receipt: the receipt must name an `Evaluate` entry in the artifact's `scalar_applications` (:174-182). `capture` demands the selected-provider count to equal `providers.providers().count()` (:90).
- Terminal receipt `validate_charge` also demands `program.is_some()` and the machine to exist in the typed program only when the outcome is `Returned` (:423-443).

**Cases by shape.** `evaluate_terminal` only accepts `Checked` / `CheckedClosure` program input: "Terminal source-completion accounting requires checked input" (:558-563).

## Five things a maintainer most needs to know about this unit
1. Folded values are written back as named type references / literals by spelling: type arguments become `TypeReferenceNode::Named{symbol: invalid, name: generated("<digits>")}` (const_evaluation.rs:855-858, const_generic_expressions.rs:5994-5997), and several downstream checks treat an invalid-symbol `Named` as closed (const_evaluation.rs:307-309) or compare it by name (:693-697).
2. A "probe" is a synthetic one-state private machine appended to a cloned tree (`append_named_probe` const_generic_expressions.rs:6116, `append_probe` const_initializers.rs:1321, const_evaluation.rs:3044).
