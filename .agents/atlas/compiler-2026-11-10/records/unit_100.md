# File 1: `literals_and_struct_literals.rs` (6019 lines)

## 1. Purpose
The file is two nested modules inside the validation crate. `pub mod literals` (5-2979) is the numeric-literal side of checking: it checks that width suffixes agree with the place a literal lands in, lands anonymous (unsuffixed) integer and float literals and literal-only arithmetic onto the type of their destination (rewriting the expression table), folds anonymous comparisons to booleans, evaluates "closed" constant arrays and records (literals that can be projected at compile time), and expands quoted byte strings into `u8` array literals. `pub mod struct_literals` (2981-6018) is construction checking: for every struct/case literal it checks field names, case selection, quotient/opaque restrictions, `requires` facts of the default domain and of the case, field type/range obligations, stored-integer-write records, array literal element shape, and array-window (`a[x..y] = [..]`) replacements.

## 4. How it decides (keys)

- Suffix vs destination :2780-2813: keyed on the identity of the landed integer type (`declared_type != suffix_type`) and float format enum; the message text uses `display_name`/`name()` only for printing.
- Float landing :350-566: by identity (expression handle, destination `TypeReferenceHandle`); destination found by walking statements and the expression table. Comparison landing :413-437 and :598-630: an anonymous operand takes the declared type of the other operand when the other operand is a name path (`name_path_node` :427) or has a result type via closure.
- `land_float_tree` :730: exact value first as an integer tree (`anonymous_integer_literal_tree_value`), else `anonymous_exact_float_tree`; rounds with `FloatSemantics::round_exact`; if neither evaluates and `numeric_literal_tree` is `None`, `stamp_float_tree` stamps format onto leaf float literals only.
- `has_anonymous_operator_meaning` (from `typed_trees::closed_numeric`) is the test that a binary node is builtin anonymous arithmetic (:209, :736, :783, :898).
- Constant array closedness :974-1012: keyed on the shape FixedArray with `FixedArrayLength::Literal` repeated, ending in a `Named` primitive from the list Bool/I8-I64/U8-U64/F32/F64 (:994-1004); anything else is `false`.
- Closed records :1882-1993: keyed on symbol kind `Data` (:1891), no type parameters, no `quotient`, no `cleanup_selection`, not `Multiplicity::Linear` (:1896-1899); fields matched by `field_symbol` and `name` both (:1979).
- Integer landing destinations :2328-2478: keyed on statement node kind and callee symbol; a named transition target is only a destination when `authored_call_selection` resolves to the same `path.symbol` (:2369-2375).
- Construction validity :5820-5962: keyed on `literal.type_symbol`, `data_definition.quotient`, `supply_mode == BoundaryOpaque` (:5865), selected definition, `case_name`/`case_symbol`. Field names are compared as strings: `seen.contains(&name)` :5835, `data_declares_field` compares `field.name.as_str() == field_name` :6016, case payload fields by `payload_field.name.as_str() == field.name.as_str()` :5951. - `case_predicates_admit_zero` :3069: abstract evaluates the case's `where_facts` with every field at 0 (point interval) and returns true only if all facts are `Truth::True`.
- `Bounds` interval truth :3054-3067 and `to_truth` :3368-3374 are the same rule ("low>=1 => True, high<=0 => False").
- `validate_literal_facts` :3541-3760: each `requires` fact gets a `StructuralJudgment` from `construction_predicate_judgments` (`Proven` accepts; `Refuted` error; `Unknown` -> try `construction_conditions` as a retained range obligation (:3633-3646), else a pending predicate (:3647-3659) that is discharged later or turned into an error). ## 4. How it decides (keys)
- Assembly services :56-84: keyed on `symbol_toolchain_relative_path == "assembly.omg"` (:57-58), file `dependency_scope`, and the normalized identity STRING `"toolchain::MachineControl"` / `"toolchain::PortIo"` (:77-80); `resolve` keyed on the service name string `"MachineControl"`/`"PortIo"` (:104-107).
