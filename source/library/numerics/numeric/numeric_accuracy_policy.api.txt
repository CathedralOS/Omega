Symmetric alternative semantics:
Tolerance validation precedes operands: both bounds must be finite and >= 0.
NaN operands always yield Different. Equal operands, including opposite signed
zeros and same-signed infinities, yield Close. Other infinite operands differ.
Finite operands use absolute OR relative error. Absolute: abs(a-b) <= absolute,
only if the subtraction stays finite. Relative: abs(a/s-b/s) <= relative,
s=max(abs(a),abs(b)); this scaled floating computation avoids overflow.
These are format-rounded computations, not an exact-real error certificate.
Nonzero subnormals are Finite. Classification preserves zero/infinity signs.
No heap allocation, array materialization, hidden format conversion, or globals.

Operation tolerances are caller supplied. Exact widening/representable dyadic
arithmetic: absolute=0, relative=0. The consumers freeze f32 addition at
absolute=2^-22, relative=0; f64 addition at absolute=2^-51, relative=0.
Their sqrt(4)=2 control is exact. General sqrt or transcendental operations need
operation/domain/format-specific error budgets supplied by their owner; this
module promises no universal correctly rounded transcendental implementation.

Numeric destination rule: an explicit literal suffix retains its carrier.
Assigning 1.0f64 to f32 rejects absent an allowed explicit named conversion.
Anonymous integer 1 may land exactly in either float format; i32 value 1 through
round_i32_to_f32 then widen_f32_to_f64 remains exactly 1.

Reference-oriented additive semantics (the wave acceptance contract):
  abs(actual - reference) <= atol + rtol * abs(reference).
Validate tolerance first: atol and rtol must be finite and nonnegative;
otherwise InvalidTolerance, even for equal or nonfinite operands.
Next, reject every NaN/infinite operand as Different, including equal infinities.
Both signed zeros and subnormals are admitted as finite. A negative zero budget
is valid zero. Argument order matters; reference supplies the relative scale.

Let RN be one nearest-ties-to-even rounding in the selected format per ordinary
operation, including gradual underflow and overflow to infinity. No implicit
f32/f64 conversion and no FMA contraction is selected. For finite operands:
  d = magnitude(RN(actual - reference)).
If d is finite:
  b = RN(atol + RN(rtol * magnitude(reference))); Close iff d <= b.
If d overflowed:
  ah = RN(actual * 0.5); rh = RN(reference * 0.5);
  dh = magnitude(RN(ah - rh));
  bh = RN(RN(atol * 0.5) + RN(rtol * magnitude(rh)));
  Close iff dh <= bh.
Halved operands have magnitude <= maximum_finite/2, so dh cannot overflow.
A finite d/dh may compare against an overflowed positive bound and be Close;
that bound exceeds every finite difference. No infinity-to-infinity comparison
is used. Every return after a valid finite admission is Close or Different.

The halved real inequality is algebraically identical to the additive formula.
Its separately rounded evaluation at overflow can differ at rounding boundaries
from a wider/exact-real evaluation. Subnormal budget operations likewise round
normally; no implicit minimum tolerance is added. This API promises the stated
format evaluation, not exact-real certification or a universal operation budget.
The symmetric comparator remains a distinct convenience for undirected matching;
it is not used as a substitute for the wave acceptance predicate.

Exact discriminating dyadic examples (not executions):
  actual=1.125, reference=1, atol=0.0625, rtol=0.0625:
    additive bound=0.125, difference=0.125 -> accepted;
    symmetric absolute difference exceeds 0.0625 and scaled difference
    is approximately 1/9, exceeding 0.0625 -> Different.
  actual=2, reference=1, atol=0, rtol=0.5:
    additive bound=0.5, difference=1 -> rejected;
    symmetric scaled difference=0.5 -> Close.
All operands and tolerance bounds here are exactly representable in both formats.
