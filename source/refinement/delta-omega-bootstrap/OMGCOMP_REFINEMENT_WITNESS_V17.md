OMGRFN17 is the fresh lower-rooted carrier for CKIR15's generalized guarded
shared-byte-view relation. Its exact 40-byte little-endian header uses magic
`OMGRFNH\0`, outer version 17, flags 1, component extents, a complete `u32`
result, and its low-byte exit projection. The components are exact OMGCOMP1,
canonical OMGRSW4, CKIR15, and conservative Linux x86-64 ELF, in that order.
Every component is nonempty and the inherited per-component and 4,497,544-byte
whole-frame ceilings apply.

OMGRFN17 frames are successful entry propositions. Library-shaped CKIR15
carriers without `StaticByteView` remain required structural evidence that a
guarded view may originate from runtime machine parameters, but they are not
silently encoded as entry frames with a fabricated ELF or result. Executable
profiles enter the selected authored states through parameters, so the guarded
occurrences themselves retain runtime parameter origin even when the initial
view is supplied by one static literal.

The exact source relation is CKIR15's parameterized vector:

```text
transition v.len > 0 {
    true  -> T(P[0:a], v[0], P[a:b], v[1..], P[b:n])
    false -> F(P)
}
```

There are at least two selected occurrences. `v` and every member of `P` are
direct typed machine/state binders; `P` is pairwise distinct and ordered; the
head and tail occur exactly once with head first; removing them from the true
vector yields the false vector exactly. The complete CKIR15 synthetic owner,
predecessor, condition, type, operation-order, jump-vector, and local-custody
rules remain those of the CKIR15 contract. `StaticByteView` is optional. The
complete inherited CKIR14 arithmetic family is also optional and cannot weaken
or select the view relation. OMGRSW7 composition is deliberately outside this
carrier.

- R3 reconstructs CKIR15's producer-facing complete guarded-view family,

- R4-lowering reparses the selected source independently, validates direct
  binder/type/order vectors and joins selected occurrences and literal bytes

  reading CKIR or ELF and owns the exact result.
- R5-structure directly invokes the frozen independent CKIR15 semantics.
  R5-result owns independent CKIR execution and result publication. R5-ELF
  owns exact conservative artifact bytes and EOF without invoking the
  production backend.

Acceptance is the conjunction of these conclusions over one immutable frame.
No owner imports another owner's verdict.

## Conservative artifact reuse boundary

The CKIR15 R5-ELF adapter passes a freshly CKIR15-decoded module to the frozen
independent conservative reconstruction engine already used by OMGRFN16. It
does not invoke OMGRFN16's frame checker, CKIR14 decoder, top-level acceptance
function, or the production backend. This is reuse of an artifact-emission
algorithm whose opcode-22 through opcode-25 templates are unchanged, not
relabeling an OMGRFN16 acceptance conclusion. The OMGRFN17 precise cache names
that dependency explicitly. Copying the roughly 450-line engine into a new
historical file would reduce neither trust nor coupling; extraction to a
schema-neutral shared module may occur later under a separately authorized
shared-file change.
