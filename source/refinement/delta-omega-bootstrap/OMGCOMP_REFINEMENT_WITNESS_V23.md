# OMGCOMP refinement witness v23

Status: private lower-rooted closure for the complete focused
`TokenStream::push` slice. The modular reference/Beta lane and the separate
actual-producer native/self same-frame lane pass. Product, package,
accepted-lock, provider, and compilation authority remain separate.

OMGRFN23 owns the eight-record/five-sum source closure needed to retain one
complete token and one observation. Its copyable graph is `SourceId`, `Span`,
`SourceSpan`, `Token`, `LexDiagnostic`, `Observation`, and all five sums,
including the complete nine-case `TokenKind`; `TokenStream` and `Main` remain
noncopy. It owns whole-value `TokenKind` and nested `SourceId` copies into the
indexed token, 13 scalar assignments, the copied `source.value` projection
into the indexed observation, the guarded Exact count increment, retained
status, and indexed `TokenKind` readback. The canonical root calls `push` with
ten arguments, including the two structural values `SourceId { value: 4 }`
and `TokenKind::Float { true, false, true }`, then calls `read_kind(0)` and
returns 70 jointly from observation tag 70 and that Float payload.

The exact 40-byte little-endian outer header uses magic `OMGRFNN\0`, major 23,
flags 1, four component lengths, result 70, and exit projection 70. Components
are exact OMGCOMP1, OMGRSWC major 12, CKIR major 20, and conservative Linux
x86-64 ELF, in that order. Every component is nonempty; component ceilings,
extents, the inherited whole-frame ceiling, and EOF are exact. The canonical
frame is 43,870 bytes.

## Admitted relation and erased facts

OMGRSWC12 independently reconstructs one unit, 22 types, eight records, 29
fields, five sums, 105 cases, eight payloads, three machines, 11 machine
parameters, 14 blocks, 11 block parameters, two calls, 15 data assignments,
20 assignment-path fields, and 11 call arguments. It preserves the recursive
copy bits for the first six records and all five sums, noncopy stream/root,
authored trapping arrays, the Exact count interval `0..=16,384`, source spans,
partitions, identities, carriers, guards, calls, and bodies. The three relevant
array capacities are 16,384 tokens, 16,384 observations, and 65,536 decoded
bytes. Authored policies remain source facts; CKIR scalar and aggregate
operations own their runtime checks.

The writer first clears retained status and evaluates the direct count leaf
against literal 16,384. Only the true block indexes both arrays at the same
full-width count, performs two structural copies and 13 scalar stores, reloads
the copied nested `SourceId.value` for the observation, evaluates the Exact
expression `count + 1`, and sets retained status. The false block performs no
array access or increment and leaves retained false. The true-edge fact is
`count <= 16,383`: both record indexes are in bounds, unsigned addition cannot
carry, and the result remains in `0..=16,384`.

The reader evaluates its full-width `u64` parameter against the direct count
leaf. Only the true block indexes the token array, dispatches exhaustively over
all nine `TokenKind` cases, binds every payload, and for Float reads the three
Boolean leaves. The canonical `true, false, true` chain retains observation tag
70. Index `N-1` is admitted; index `N` and nonzero-high-half indexes reach the
defensive bounds trap. A separate CKIR positive owns high-half call transport
and is deliberately rejected as a source/CKIR cross-pair for the canonical
OMGRFN23 frame.

CKIR20 independently reconstructs 24 types, eight records, 29 fields, five
sums, 105 cases, eight payloads, three machines, 11 machine parameters, 14
blocks, 11 block parameters, 183 operations, 180 operands, 14 terminators,
nine case arms, eight arm arguments, 67 values, 118 places, and no constants.
Private layouts are `SourceId` 4, `Span` 16, `SourceSpan` 24, `TokenKind` 12,
`Token` 56, `LexDiagnostic` 32, `Observation` 40, and both `TokenStream` and
`Main` 1,638,456 bytes. The conservative BSS is 1,642,496 bytes. The selected
owner must not exceed 2 MiB.
