# Symbol-resolved trees to typed trees: generated-source continuation

The contract is [build execution](../../../../../../wiki/spec/build/execution.md).
This note maps its Rust implementation. Limits on which appended cohorts
(groups of declarations) work are compiler limits, not a separate language.

## Source layout

[`src/lib.rs`](src/lib.rs) exposes the stage API; [`src/lowerer.rs`](src/lowerer.rs)
runs fresh typing and generated-source continuation through the same cohort operations.
The remaining source is grouped by the work it owns:

- [`declarations/`](src/declarations/) lowers declaration families, their contracts,
  signatures, constructors and constant initializers.
- [`expressions/`](src/expressions/) lowers expression meanings and selects calls,
  operators, products and operand owners.
- [`patterns/`](src/patterns/) resolves data patterns, case equality and exhaustiveness.
- [`statements/`](src/statements/) lowers statements and their retained assignments.
- [`types/`](src/types/) lowers type references and handles qualification, borrow
  requests and declared-type queries.
- [`tests/unit/`](tests/unit/) holds the stage-wide unit tests; local helper tests
  stay with their owning module.

## Entry points

- Package capture supplies the files and grants for the invocation. [Filesystem scope](../../../build/inputs/build_execution/filesystem_scope.rs)
- The source compiler resolves, types and judges the selected Build invocation. [Build invocation](../../driver/compile_build.rs)
- The Build driver holds the activation across a dependency request and resumes with the admitted answer. [Build planning](../../../build/project_build.rs) · [Execution](../../../build/evaluation/build_evaluation.rs)
- Source assembly retains the generated bytes, logical paths and producer records. [Source assembly](../../../build/inputs/source/assembly/generated.rs)
- [seeded resolution](../02_syntax-trees-to-symbol-resolved-trees/src/resolver.rs)
  appends the new declarations and rebases only the extension's selections.
- [typed continuation](src/lowerer.rs)
  checks appended cohorts and leaves the base unchanged. It reads the
  [continuation records in the representation](../../representations/symbol-resolved-trees/src/continuations.rs),
  which retain the identity of the resolved declarations. The source driver keeps
  pending syntax and runs resolution, source activation and typing. The
  [source continuation tests](../../driver/resolve_and_type/tests.rs)
  check their exact pairings.

## Data patterns

A positional pattern, `(first, _, ..)`, names no field, and a final `..` in
any data pattern stands for the fields it leaves out. Typing is the first
stage that knows the subject's record, so [data_patterns.rs](src/patterns/data_patterns.rs)
gives each such row its declared field there: a place selects the field at
that position in declaration order, and `..` becomes one waived row per
remaining field of a `let` pattern. The read of a positional binding becomes
an ordinary member with that field's symbol and name. A `let` pattern that
names a record, `let Pair { .. } = pair;`, is checked against the subject's
own record. Preparation and lowering then receive the same named roster and
field reads that `let { first as _, second } = pair;` gives them. A pattern
whose subject has no record declared at that point is refused at the pattern.
[tests/positional_patterns.rs](tests/positional_patterns.rs) asserts the
selected fields and the refusals.

## One typing route

Every appended declaration kind uses the ordinary
`type_resolved_cohort` and `close_typed_cohort`: data, domains, machines,
mathematical declarations, propositions, measures, operators, traits, named
implementations and wire schemas. Constants keep their initializer and
selection records on the declaration. No allowlist of generated-source shapes
or recursive type checker exists. Unsupported source is rejected by the usual
resolution, typing, proof, ownership or realization code.

Within a cohort, [expression meanings](src/expressions/expression_meanings.rs) prepares
domain casts and selected operator calls from operands outward. A cast can
give an operator its operand type, and an operator can give an enclosing cast
its result type. The selected call keeps its static arguments and the
author's declaration choice; typing adds no checking evidence. Closed type
and const applications go to ordinary specialization; the lowered-form checker
refuses unsupported domain applications.

The continuation keeps the exact resolved and typed base. Resolution may
append semantic domains, service definitions and rows, external binding
identities and evidence forwardings; every existing ID keeps its meaning.
The typed join keeps prepared domain instances, appends declaration ceilings
by owner, and translates only new evidence forwardings after typing records
erased proof calls.

A signature-free static requirement operand keeps resolution's selected
trait, declaring trait and exact requirement, or its refusal. Typing uses that
result instead of resolving the path again in another context.

Both the continuation and fresh typing finish with `close_typed_cohort`.
On a continuation, runtime call binding
([runtime callables](src/expressions/runtime_callables.rs)) and static
argument contexts for expression calls
([operand owners](src/expressions/operand_owners.rs)) walk only the cohort's
declarations. Each then checks that its walk reached every call created since
the cohort began, and walks the whole program if it did not. Two passes still
walk the whole program because typed trees has no cohort form of them: static
argument contexts when a cohort machine has a statement call that needs one,
and `prepare_applied_callable_signatures` when the cohort adds a declaration,
scope or application that could need an applied signature. Either may rewrite
retained declarations, so the second runtime call binding then walks the whole
program too.
Every `close_typed_cohort` pass that reads operand owners gets a table built
from the program as it is where the pass reads them; a fresh cohort walks the
whole program for each, a continuation only the cohort's declarations. Passes must not share
one table: the owner walk reads nearly every typed-trees field, each of these
passes writes some of them, and typed trees keep no revision, so a reused
table misses owners and the deferred refusals those owners carry.
Declaration identities, written contracts, progress premises, domain
constraints and literals' concrete types stay typed data and judge no body.
Requests that depended on the removed checker refuse with
`no product route yet` until a current owner supplies their judgment or mapping: closed const admission and replay, unresolved membership carriers,
domain-entry accounting, legacy target-family contracts, projected or dynamic
call binding, and callable transition normalization. Typing does not create
empty facts or reuse an old checker verdict.

Assignments retain their exact target and value. One declared-place query reads
the state's unique binding and its selected fields or elements, so literals and
named machine values retain the actual constructor application. An unresolved
literal destination stays intact and records an unserved request on its owning
declaration. The lowered reader independently reconstructs the destination,
checks write authority and proves the replacement's obligations; constructor
type metadata is not an assignment judgment.

Source activation (`SeededTypingBase::activate_sources`) narrows a retained
typing to the program written in the selected sources. It reads no verdict: the
typed representation's own
[declaration projection](../../representations/typed-trees/storage/declaration_projection.rs)
keeps the selected files' declarations and the declarations the compiler derived
for them, and the resolved roots follow what remains.

The post-typing evaluator reads the completed result; wire-plan publication
starts at the extension's first wire schema. A failed structural-prefix check
returns the base unchanged, and orchestration rejects. Admission compares kept
resolved declaration roots and shared semantic IDs; each typing operation
keeps its own storage intact. Compilation does not recompare whole typed trees.

Legacy target-scoped units finish their own pre-resolution evaluation before
the ordinary target filter. The filter merges the kept base selection
into a combined selection, then settles selected origins and target-owned
`provider_defaults` against the final typed continuation. Only extension
declarations may change. This is temporary migration code, not accepted syntax.
`BUILD-OWNED-TARGET-SELECTION` in [the task board](../../../../../TASKS.md#pipeline-route)
replaces target prefixes and family selection with ordinary named implementations
and explicit target-keyed Build provider rows.
Units share one immutable package selection for this continuation; sharing
it neither makes sibling declarations visible nor admits packages reached only
transitively.

No switch rebuilds combined syntax, no second frontend exists, and nothing
recovers the admitted entry from source spans or names. New cohorts must
extend this all-or-nothing continuation instead.

Constant initializers stay detached roots in the resolved base, not runtime
constant storage or decoded review strings. Only new initializers are
name-resolved; later imports cannot reinterpret existing constructors. Typing
drops the initializer link but keeps the declaration and use records.
