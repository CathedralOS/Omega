# Normalized policy baseline

This page specifies the full policy record the compiler derives for fresh
checking and audit. It is reference, not steps install or update must pass. The project trusts
whoever lands accepted policy; these records neither certify acceptance nor
prove an audit.

The [evidence entrance](README.md) describes capture and encoding.
The [lock owner](../package-manager/src/lock/README.md) joins sources to targets,
frames historical decisions and sets overall recovery limits. The
[lock specification](../../../../wiki/spec/packages/locks.md) defines what users see.

## Compiler projection and component recovery

Review exposes bounded, inert (never executed) policy components apart from
its replay encoding.

A closed conformance component records the exact
source-qualified declaration, the instantiated subject and trait, the type,
const and machine arguments in declaration order, lifetime relationships, and
which realization meets each requirement. It uses resolved arguments,
including private named layout slots, never diagnostic spellings. Lifetime numbers index the
containing lifetime list (telescope), which the enclosing policy keeps, so
changing the selected caller lifetime stays visible.

A physical calling component records the evaluated placements,
clobbers, entry control and every machine-state promise. The full calling
component joins that to the exact boundary-trait application, the declaring
requirement's application and lifetime lists, the semantic parameter and
result types, and native parameter names and origins in order. An inherited
requirement keeps its declaring trait apart from the trait selecting its
calling policy. Supplied type operands keep the regions of the conformance
that supplied them, ahead of the requirement's own binders. Explicit trait
lifetime arguments use the same numbering, so two root arguments can name one
supplied region without merging a method binder. Open declarations have no
supplying lifetime list and keep their authored crash limits apart from
executable applications. Nested static contracts keep their lexical lifetime
scopes even when an inner binder shadows an outer name; expression projection
maps those scopes without rewriting checked proof or expression handles.
Callback rows record exact static binders, requirements, destinations, authored
layout-policy and schema applications, named inline fields, slot applications
and target-closed geometry. Opaque uses record selected meanings, exact shape
paths and placements; unused selections belong to representation policy,
not to invented calling occurrences.

Capture checks the live compiler associations and
replays their validation before dropping report coordinates and commitments. No evaluator machine name or native compact ID enters the calling
component. Recovery (reading a stored record back) shares one byte,
element and allocation budget across nested components and checks structure
without recovering compiler or native evidence.

Representation policy separately records package-owned
opaque declarations, the full public surface of producer conformances, every
selected application (including unused placement-only choices), and actual
demands with their full calling applications. A producer's availability keeps
its uninstantiated public lifetime list and invents no selected application.
Selection capture reharvests the exact authoritative build even when no
selection was kept. That build has no static or lifetime list, so selected
conformance lifetimes cannot bind to a called requirement's list. Recovery
checks selection ownership, producer associations and that every application's
opaque demands are covered.

Selected-provider policy rejoins all selected plans
to their checked typed schema and realization origin. It reharvests the authoritative build's provider selections and grants
before replacing links that depend on receipts. Every service keeps its
structured signature and contract-bearing static parameters, even without a
calling plan. An inherited requirement keeps its declaring
owner and arguments apart from the selecting schema. Service reach, direct
invocations, progress profiles, subject projections and establishment
requirements keep exact source owners, so equal names from different packages
never make policy equal.

Domain establishment routes tell checked and boundary
requirements apart from exact machines. Each machine route keeps its package
owner and full normalized callable declaration identity. Public routes can be
recovered as inert policy. Private issuer references use the source-selection
metadata exception without publishing ordinary call, conformance or
private-type access. Private admission claims keep their own policy
obligations. Recovery does not establish where a result came from.
Evaluated bindings keep their exact producer and physical
locator or syscall meaning, without evaluator accounting. Plain and evaluated
syscalls stay distinct. Table bindings keep the exact data declaration their
leaf's first parameter borrows. Grants and provider selection stay scoped to
the activation target. Callable and external-supply rows record, through
exact family-member handles, whether code is target-independent or an authored
target member, even when selection clears a machine's target marker. Every inactive private external leaf stays disclosed, and its
normalized binding names its authored profile, not the activation's. Supply and
callable contexts must agree. Unknown authored tags are valid for pure bodies,
but physical external bindings need a catalogued profile. This context is part
of acceptance keys and readable meanings; older schemas cannot recover it and
require fresh review. Grants belong to their full normalized plan, and atomic
family coordinates point at the canonical plan index, not a compiler report or
receipt digest. Generic family declaration coverage invents no actual
application or standalone D29 realization claim. Recovery checks this under
the same budget.

This policy records the exact service, its full
method schema and generic declaration lifetime list, and each requirement and
disposition supplied explicitly. Unused permissions and unpermitted schema
siblings stay visible; an explicit empty disposition is not absence.
Declaration parameters stay symbolic until a checked application exists.
Accepted-service schema checks run first, including UEFI's separation of
semantic permission identity from target-owned calling authority. The full
checked calling context is reviewable baseline meaning, not a new permission
key or a substitute for receiving-policy containment.
Callable policy keeps full static and lifetime signatures and
exact overload identities for public, boundary, selected-build, private
admission-claim and private external-callable surfaces. An unused external
leaf keeps its own outer contracts and operational promises apart from the
requirement it implements; if it omits a suspension or blocking clause, it
publishes the limit inherited from that requirement, not an empty one. Actual
conformance lifetime arguments stay separate from their equality partition.
Published reach, invocation and operational promises stay distinct from the
checked summaries kept beside them; public suspension and blocking summaries
use their published limits. Typed crash guards keep foreign owners, even in
nested static signatures. Progress premises keep their entry-relative subject,
projections and establishment requirements. Nominal membership keeps a
recursive subject and exact case classifier apart from construction and
selected equality. Source-free recovery checks the subject's lexical scope
and classifier identity; it neither rebuilds the foreign data declaration nor
proves membership. Inferred crash causes come from the checker's
conservative body summaries; a closure without a summary stays unknown, never
crash-free. The entry mutation frame records completeness without private
state coordinates. Caller-local flow facts and the union of flows over
reachable machines stay separate; the union keeps private helper Uses/Stores,
excludes unreachable helpers and leaves caller-flow propagation unchanged. Recovery keeps these meanings, not compiler proof or
crash-derivation tables.

Package policy joins these components with all seven
public declaration families, every external supply the package owns, rows for
dangerous authority and slack, and source-semantic dependencies. Private
implementation consumers are grouped under their package, keeping exact
dependency identities, kinds and exposure. Public and nested static signatures
keep "no result" distinct from a declared data result, typed crash guards and
complete progress establishment routes.
D29 symbolic demands keep exact producer callable coordinates and direct
type-binder mappings. Closed applications keep their exact operator and
application, canonical selected-plan index, and authored realization or closed
intrinsic meaning, not generated specialization state or execution commitments.
A named requirement is identified by its callable overload in the declaring
owner's namespace (package digest or toolchain); recovery joins it to the
operator coordinate by that namespace, never by the unqualified path.
Closed realization rows cover only the selected activation. Boundary calls in
an inactive target-member body stay checked semantic input, not claims about
this activation's selected plans; their callable and external-supply disclosure
stays complete. The use's exact machine origin sets this scope and must agree
with immutable source custody. An unknown origin never justifies omission.

One bounded envelope accounts for the whole baseline's resources and checks
package, target and structural associations without an old checkout. The
baseline excludes source graph pins and historical decisions, which belong to
lock composition, and source-location sidecars and compiler stand-down or
discharge certificates. Fresh admission still runs the compiler's
obligation and discharge checks. Recovering a component or a baseline is never
an acceptance decision.

The compiler writes the baseline in a binary and a named text form from one
pass over its meaning. The text spells out fields and variants, optional
values, ordered sequences, quoted values and decimal scalars instead of one
opaque payload. Recovery validates the typed meaning and requires the text to
rerender exactly, field names and framing included. The text format has its
own version and expansion limit; binary reconstruction and typed recovery share
one storage budget. The manager composes source graph, pins and
historical decisions.

The manager's lock instead keeps one inert `PackagePolicyAcceptance` per source
package: exact canonical rows for admission-claim and external-realization
callables, external supplies, dangerous capabilities and terminal permissions.
Readable row meanings survive, but the full public API, ordinary
callables, selected providers, representation policy, source-semantic
dependencies and symbolic demands do not; those stay fresh compiler and audit
facts. Lock recovery neither rebuilds this model nor compiles old source; past
acceptance never becomes fresh compiler evidence. The lock owner
specifies its framing, source joins and accounting.

Decision history records the exact comparison identity, the candidate's
source-subject association, any prior source association, and each choice about a row, root role or source replacement. Decisions
about removed packages do not index the candidate-only graph. Version 2 stores
a decision as bounded LF text with a fixed vocabulary; subjects are strictly
ordered and each is accepted or rejected once. Capture checks the supplied
completed resolution against the comparison and candidate source, without
rerunning the compiler. Recovery trusts the project author and checks only
record structure, resource limits and candidate source association, without old
source or the old comparison. A rejection stays a
rejection. Version 1 indexed history stays readable as written, with no invented comparison. Neither format authorizes a later changed
candidate or proves an audit happened.
