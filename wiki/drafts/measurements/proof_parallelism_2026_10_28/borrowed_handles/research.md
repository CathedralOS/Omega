Question: can a borrowed handle survive containment without an atomic reference-count update, becoming owned only when the actual append consumes it? Query: `site:doc.rust-lang.org std borrow Cow into_owned borrowed cloned owned moved`. Read the official https://doc.rust-lang.org/std/borrow/enum.Cow.html#method.into_owned (displayed std 1.99.1), including the variants and into_owned examples. Cow::Borrowed holds a reference without cloning. Into_owned clones a borrowed value and moves an owned value. Here that value is an Arc<Proposition>, so the clone acquires the immutable existing fact, not a reconstructed tree. These longstanding APIs exist on the pinned toolchain; no nightly feature is needed. The documentation establishes ownership behavior, not speed.

Followed the implementation link to https://doc.rust-lang.org/src/alloc/borrow.rs.html and read Deref, into_owned, Ord and PartialOrd.
