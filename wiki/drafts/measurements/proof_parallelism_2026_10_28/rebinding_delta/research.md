# Rebinding delta experiment, 2026-10-29

Existing evidence: cache_diagnostics/README.md proves 24 real hits / 7,683 hot requests, so complete-roster caching was rejected. Its bypass still appended 1,462,923 owned propositions to current scalar rosters when only part of a rebound batch was new. It normalized the whole union afterward. The baseline already avoids appending when every row is present; this experiment preserves that behavior and filters exact known rows when only some are present.

Question: can an in-place delta filter reduce Arc allocations and repeated canonicalization work without omitting any substitution or proof context? Query: `site:doc.rust-lang.org std vec Vec retain original order visits each element exactly once`. Read the official retain contract at https://doc.rust-lang.org/std/vec/struct.Vec.html#method.retain (displayed std 1.99.1). It visits in original order, retains order and operates in place; its longstanding API exists on the pinned compiler. This establishes API behavior, not performance.

Scope: one caller and its private helper in payload_history.rs, plus a pure source-free canonical-union test. No source syntax, public API, cache, proof rules, invalidation, substitutions or normalizer changes. The append still owns current-arrival storage and the existing canonicalization still runs.

Invariant: for canonical retained roster R and full transformed roster B, filtering B to rows absent from R preserves canonical(R ++ B). Sorted B uses the original ordered cursor; unordered IEEE/math results retain exact binary searches. Duplicates among new rows keep their original order and are still normalized by the original canonicalizer. Existing equal rows keep the old Arc identity, matching stable append/sort/dedup. The empty delta leaves the published allocation untouched. The bounded 1,024-case pure test checks all four-value retained subsets and three-row input permutations/duplicates, plus empty input, against full append/sort/dedup and checks retained allocation/row identity.

Hypothesis: wrapping only missing rows reduces baseline append allocations and sort input, particularly on the 762 hot requests that previously appended the whole rebound roster. The extra full filter can cost more than the saved allocation/normalization; reject an unsupported gain. Use matching outer probes, exact frozen producers, unchanged 203 authored files, normal accepted locks and fresh private caches. Counter tracing is disabled for primary alternating A/B runs. Require unchanged native image, authored EOF oracle and explicit native/Terminal stdout agreement; retain only after focused final-source qualification.

Refinement after the first four valid pairs: the in-place filter removed 95.8% of hot append allocations, but replay timings were mixed (two faster, two slower). Unordered rebound inputs require a full binary-search pass, unlike the original containment check that could stop at the first missing row. The next variant stably sorts an unordered transformed roster once, then uses the same linear subtraction for every input. It preserves all normalized propositions and the final canonical union; the same 1,024-case test passes. This is an alternative strategy within the same delta experiment, not a new cache. Do not infer a measured search-time cause from this hypothesis alone.
