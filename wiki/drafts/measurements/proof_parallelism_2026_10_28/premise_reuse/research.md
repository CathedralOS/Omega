# Exact per-premise reuse diagnostic, 2026-10-29

Existing records: complete-roster caching avoided only 98 input rows in 7,683 hot requests; delta filtering still transformed all 3.14 million incoming rows. Read the cache diagnostics and rebound-delta ledgers before this experiment. The new question is whether individual immutable input propositions recur under the same edge bindings within one payload replay query, even while their enclosing rosters change.

Query: `site:doc.rust-lang.org std sync Arc as_ptr ptr_eq make_mut`. Read the official [Arc documentation](https://doc.rust-lang.org/std/sync/struct.Arc.html#method.as_ptr), displayed std 1.99.1, including `as_ptr`, `ptr_eq`, and `make_mut`. A raw pointer remains valid while a strong owner exists; pointer identity is allocation identity, not value equality. These APIs are present on the pinned toolchain. This establishes identity semantics, not a speedup.

The temporary observer holds a strong input Arc for every distinct `(source position, successor ordinal, input allocation)` within one `payload_contract_at_cut` invocation. That invocation borrows one immutable descriptor machine, so its edge bindings and retired formal set do not change. A separate invocation always starts a new table. This is a bounded query scope; it does not count reuse across queries, machines, compilation processes, or contexts with changed bindings. Equal propositions in distinct allocations remain misses. No transformed output is reused and no semantic check is bypassed.

The original full rebinding path still runs before the count observer. The observer duplicates the exact retirement classification solely to associate input identities with the surviving output prefix and asserts the full prefix/equality-tail length. It counts unchanged output rows and changed rows with no referenced substitution key; it never assumes that an empty substitution map permits omitting normalization. The small identity test covers repeated input ownership, equal-but-separate allocations, distinct successor ordinals and retained strong ownership.

A separate diagnostic mode times substitution-map setup, each original retirement check, each surviving proposition transform, and the final binding-equality loop. These are gross instrumented durations: timer calls, per-row accounting, logging, scheduling and Vec growth can perturb the result. They are not a prediction of cache savings, an exact net overhead measurement, or a baseline/candidate speed comparison. Count mode retains identities and performs extra visits; its elapsed time is excluded from performance conclusions.

The smallest decisive experiment uses two count runs for reproducibility, two cost-attribution runs, one original-outer-probe control, one disabled-observer control, and an explicit native/Terminal Psi comparison. It retains the fixed Dungeon source, accepted producer-specific locks, optimized compiler profiles, fresh private caches for compilation, native image digest and EOF oracle. Reject a cache proposal if exact-context row reuse is negligible. High reuse establishes only an opportunity: a production cache would still need output ownership, cleanup/memory accounting, focused invalid controls and a repeatable complete-workload improvement.
