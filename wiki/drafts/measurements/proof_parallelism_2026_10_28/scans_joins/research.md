# Remaining replay scans and joins, 2026-10-29

Previous experiments avoided most proposition reconstruction and many temporary Arc ownership operations, but did not establish a repeatable whole-compilation speedup. Earlier transfer probes put about 75% of source replay inside edge processing, including joins; they did not resolve predicate retention, contract materialization, publication and internal intersection scans. This assignment measures the original implementation without promoting an optimization.

Read the existing payload_replay, cache_diagnostics, unchanged_sharing and borrowed_handles records first. Local code audit: State::publish_requirements, State::contract, State::meet, payload_contract_at_cut, ordered union/intersection/containment helpers, scalar retirement and payload predicate closure. Publication can walk an ambient roster separately for each payload-local premise; predicate retention checks the same shared roster for multiple payloads; snapshot intersection can scan to detect a loss and scan again to apply it. These are measured hypotheses, not assumptions that those operations may be removed. In particular, joins retain all local/shared cross terms and payload retirement differs from ambient retirement.

Primary timing source: https://doc.rust-lang.org/std/time/struct.Instant.html, read the timing, underlying system call and monotonicity sections. It documents elapsed time and Windows QueryPerformanceCounter, not process CPU accounting. Scope times here are gross wall intervals, including scheduling pauses and instrumentation; process CPU comes separately from the existing Win32 harness. Nested inclusive durations must not be added as if disjoint work. Exclusive duration is parent elapsed minus nested-child elapsed, and checked bookkeeping plus a source-free unit validates the partition. No per-proposition timer, global profiler mutex or semantic-state retention is introduced.

One thread-local batch owns fixed-label arrays, a small timer stack and numeric query summaries. Only the existing source-query windows activate it. Coarse mode times replay regions and the whole contract/publication/retirement/meet operations; fine mode additionally brackets scan helpers. Counts mode uses local numeric counters and no timers. Actual visits/comparisons/cursor advances are distinguished from input row lengths; clone units differ between owned propositions and Arc roster handles and must be interpreted by family. Exact nonempty snapshot-slice aliases are counted without retaining another owner. Counts may be intrusive and their elapsed times are not performance results.

Pre-scheduled observations: three rotating triples of original outer-probe producer, disabled new producer and coarse profiling (each in each position once); two fine observations; two exact count observations; and one explicit native/Terminal comparison. Every timed compilation has a fresh private compiler cache and the same 203 authored inputs, normal accepted producer-specific lock and optimized profile. The original/off controls examine disabled-hook effects; off/coarse controls and coarse/fine differences bound attribution overhead only to the extent the shared host permits. Preserve all valid results. Require unchanged work rosters, native image/oracle and engine stdout agreement. Report largest repeatable gross categories and remaining residual explicitly; do not relabel diagnostic spans as exact baseline CPU costs or claim an optimization.
