Slices read in full: 127 (`recasts.rs`), 128 and 129 (`reference_result_custody.rs`, cited `rrc`), 130 (`structural_call_custody.rs` S, `trace_flags.rs` T), 131 (`traits.rs`), 132 (`type_references_and_wire.rs` F), 133 and 134 (`value_custody_core.rs` VC), 135, 136 and 137 (`other_changes.diff` d). Claims I checked in the old source are marked [checked].

## What this code was

These files were the back half of the deleted `validation` crate, plus the plumbing in other crates that fed its output into Build, product selection and Terminal publication. `recasts.rs` judged `&x as &T` re-views of storage by comparing flat leaf inventories of source and target types (127). `reference_result_custody.rs` worked out, for every reference a state returns, which input or call result it points into, through calls and recursion (128, 129). `structural_call_custody.rs` turned `data` `requires` facts into per-parameter rows and checked which linear claims cross a call and come back (130). `traits.rs` checked conformances, named implementations, `dyn` selectors, refinement fit and effect ceilings (131). `type_references_and_wire.rs` checked every written type, closed const arguments, domains, open index algebra, and wire schemas with their compatibility and migration demands (132). `value_custody_core.rs` held about 40 small modules on ownership: linear claim frontiers, `dropped by` cleanup, constants, establishment, record patterns, reference access, contents capability, plan-laid layouts and sealed toolchain shapes (133, 134). The diff slices show the caches and route plumbing around the old checker being deleted and replaced mostly by refusals that say "no product route yet" (135-137). Every judgment the reports found is the code's own `bool`, `Option`, `&'static str` or pushed `Diagnostic`.

## Mechanisms

- **Leaf inventory and implication** (recasts.rs:3471-4035). Flattens a type into (offset, size, scalar fact set, bit fragments) leaves per layout alternative, with budgets of depth 256 and work 16384 (2772-2795). Implication uses a binary search of source leaves by offset, and a merged bit-range coverage table (2674-2767). Scalar fact sets are u64 bit-pattern interval lists and float min/max (4585-5017). Serves recasts and exports projection geometry to later stages (2868-3320).
- **Offset bounds** (recasts.rs:308-581, 1332-1397). Bounds the upper end of `+ - * <<` over standing intervals, with a syntactic divisibility test for slice tiling.
- **Return-origin fixed point** (rrc:3723-3973). A worklist over per-state rows with an optimistic empty start, checked for monotone growth, and an SCC pass that keeps each cycle inside the frontier built from returned loans. Productivity is a least fixed point over AND/OR coverage graphs (rrc:827-1027). There is no iteration cap; only per-evaluation leaf caps (rrc:3801-3806, 128).
- **Origin composition** (rrc:2307-2747). Substitutes callee-parameter origins with caller-argument origins, composing presentation paths and extents (`Projected` or `WithinRegion`).
- **Carrier inventory** (rrc:7034-8058). Budgeted type expansion (8192, 4096, 128), with per-application scopes so a const argument fixes an array's length.
- **Three-valued interval evaluation** of `requires` against field carriers (S:47-251), and **predicate spelling**, which translates the whole fact or nothing (S:906-1443).
- **One-way trait binding matcher** (traits.rs:2734-3200): binds a requirement type parameter on first sight, with no backtracking, and leaves bindings behind on failure (2780-2786). **Region correspondence** filters candidate lifetime assignments until exactly one remains (traits.rs:7109-7286). **Closed conformance identity** hashes rendered text (traits.rs:4429-5202).
- **Closed const normalizer and evaluator** (F:305-504, 1132-1403): depth 128 plus node caps, with revalidation against the carrier. **Open index normalizer** picks one conformance operation per operator and writes it into the program (F:3266-3634).
- **Migration route search** (F:6049-6078): DFS that returns the first route, not the shortest.
- **Contents walker** (VC:9992-10720): one resolver parameterized by 13 requirements, with an active-size cycle guard. **Partial-affine residuals** (VC:6456-7249): a count pass, then an emit pass, under `max_residuals`. **Establishment** and **cleanup answers** use sorted memo tables searched by (arena index, generation) (VC:1871-1967, 3994-4203, 10968-11091).
- **Domain-cast accounting** (d:10003-10610): a running set of carried domain atoms with ancestor implication.
- **Target-family comparison** (d:11044-11337): binders renamed to `$N{scope}G{pos}`, then contract bytes compared.
- **Caches** (d:570-871, 2832-2971; d:13746-14896): append-only Pure Build list, a content-addressed disk store with a 4 GiB cap, and a library-slice digest.

## The three properties, tested

**1. Acceptance was the code's own yes or no.** Evidence for: readers of 127, 129, 130, 131, 132, 133 and 134 each searched for `proof_admission|ProofNode|verify_obligation|certificate` and found 0 hits (127 Surprises; rrc 129 Surprises; S 130; traits.rs 131 header; F 132; VC 133, 134). The deleted `pipeline.md` says it outright: "Contract automation remains trusted wherever it accepts an obligation without kernel-checked evidence" (d:8832), and so does the owner ruling (d:527-537). Evidence against: the one place that used the proof kernel is the evidence seal check, `seal.intact()` plus goal recomputation (d:7060-7126, 136), which moved into `EvidenceSealValidator`. Verdict: confirmed for the whole group, with that single exception.

Text decides meaning for lifetimes, const values, toolchain and intrinsic declarations, wire, and fallbacks. Handles decide for types, loans and record patterns. Member identity `of_member(identity, name)` carries the name in every compare (rrc:166 and on; S:125 and on).

## Patterns not seen before

- **Silent refusals.** Most refusals carry no reason. rrc, S and recasts return `None` or `&'static str` reasons that only reach stderr under a trace flag (rrc:2411, 3062; 128 Surprises). S reports about 60 static strings as `Err` (130 Rules). Hard-coded unique-or-refuse counting on every lookup appears in at least 15 places (rrc:4703, 5390, 8428, 9622; S:3184, 3431, 3558; VC:5226).
- **The same fact recomputed and compared.** Retained views are re-judged from their original formation (recasts.rs:4416-4490). Plan-laid geometry is re-derived from the report (VC:7689-7845). Retained implementation demands are re-closed and compared (traits.rs:8160-8293). The recursive frontier from loans is checked against return equations (rrc:3862-3915). Descriptor-load conditions are checked twice with the same strings (rrc:5765-5792 vs 6023-6058). There are 5 such cross-checks.
- **Validators that mutate the program.** Open index normalization writes `normalizer_version: 4` (F:3266-3373). Dynamic call targets are rewritten in place (traits.rs:6067-6084). Typing replaced const arguments with name nodes (d:11758). There are 3.
- **Hard-coded constants deciding acceptance.** Schema ABI 4 and 32 fields (VC:7521-7536); `"Rat"` (F:2547); `compact_binary` (F:5633); presets only for `i32`/`u32` (VC:9317).
- **Budgets that fail open.** The static-inline extent budget accepts on exhaustion (VC:9615). Every other budget fails closed (recasts.rs:2772; rrc:7034; F:315).
- **Opposite answers for a missing definition in sibling arms.** VC:4062 vs 4078, F:707 vs 737, and Named vs Generic duplication generally (VC:3501-3602).
- **Dense-id rule breaches.** `BTreeMap` and `HashSet` keyed by handles (rrc:573-596, 908; VC:6392, 10894); `Vec::contains` visited sets (recasts.rs:5372; F:6071; VC:3141).
- **Environment reads deciding tracing.** Repeated on every call in rrc:4295-4308; T caches them because one read cost 0.75 s (T:1-12).
- **Staged-feature "rungs" in diagnostics.** "lands with the byte-view rung" (recasts.rs:1871), "this first conformance rung is concrete only" (traits.rs:1730), "not implemented yet (NAMED-DOMAIN-CASTS)" (d:10441, 10503).
- **The lowered-form checker already gated before deletion** (d:15039-15095, 137). The product path was already partly stubbed (d:16001-16005, 16248). After deletion, at least 26 product or review functions refuse "no product route yet" (d:1446-5701; 136 counts ~20).

## What a rebuilt compiler must still do

- Judge reference re-views (`as &T`, `as &[T]`): equal size, alignment, tiling, footprint within region, a proven offset bound, and fact implication (writable both ways, including atomicity). Rows 1-14.
- Check every layout-dependent rule in every target layout alternative. Rows 15, 99.
- For every returned reference, name its input or call origin, with matching path, access and extent, through calls, recursion and interface families. Rows 17-27.
- Enforce the access lattice: `&mut` supplies shared or write-only, write-only is never read, exclusive borrows need writable named places, and a bare range is shared. Rows 18, 31, 95.
- Track loans per leaf, with formation, activation, release at last use, state exit or reassignment, and moves into calls. Rows 28-30, 33-34, 94.
- Derive multiplicity and the linear claim frontier of every type, and require each linear claim to be consumed or returned exactly once across calls. Rows 32, 40-45, 85.
- Assume `data` and state `requires` at entry, restore them through mutable references, and match them to type qualifications. Rows 35-39.
- Check conformances: arity, bounds, signature, lifetimes, contract and borrow refinement, effect ceiling, `crashes none`, operators, refinement fit, parents and cycles. Rows 47-55, 64-65.
- Resolve implementations, `dyn` selectors, implementation slots and qualified calls to exactly one requirement. Rows 58-63.
- Admit const arguments only as closed canonical values of their carrier, including index types, array extents and indexed domains. Rows 69-75, 78.
- Check domain constraints and domain casts: existence, a single policy, parents, accounting for every carried domain, and proven membership before minting. Rows 76-77, 96-98, 103.
- Check type positions, aliases, lifetimes and boundary-trait placement. Rows 66-68, 79-80, 60.
- Check wire schemas, compatibility demands and migration routes. Rows 81-83.
- Check cleanup: `dropped by` selection, cleanup machine shape, residual cleanup after partial moves, and contents capabilities. Rows 86-88, 100-101.
- Check data declarations, establishment of non-zero types, and record-pattern exhaustiveness by field identity. Rows 89-91.
- Recognize sealed toolchain operations (activation claims, fences, atomics, intrinsics) by sealed identity, not by name. Rows 46, 84, 93.
- Keep `build.omg` away from runtime services, and fold Build constants under Build providers and target layout. Rows 105, 111.
- Refuse whenever any part of the program is refused or unverdicted. Row 106.
