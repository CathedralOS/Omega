# Group G01: provider planning and package review evidence

## What this code was

None of the six slices is the source checker. All of them are downstream consumers that were deleted with it because they read its tables (`CheckedTrees`, `CheckFacts`, typed trees) and call about a dozen of its functions (003 Surprises 1; 005 Surprises 1; 006 Surprises 1). Slices 001-002 and the first part of 003 are the `provider-planning` and `selected-dispatch` crates. They decide which implementation supplies each boundary requirement on the selected target: a checked adapter body, a compiler intrinsic, a syscall, an import, or a dispatch-table field. They pick the `ProgramEntry` machine, compute byte layouts for `data`, and seal Build-evaluated foreign locators into digests (001 "What this code is for"; 002 same). The rest of 003 and all of 004-006 are the `review-evidence` package. It turns an admitted package into a portable, name-free record of its public API, contracts, calling plans, provider plans and permissions, which a consumer's lock file accepts (004 `package_policy.rs:45-115`; 005 `package_review.rs:1-10`; 006 `encoding/mod.rs:1-8`). Almost every check in the group compares two copies of the same information: source against canonical, candidate against "custody", stored against re-derived. Few checks judge the user's program, and the README of provider-planning calls the crate "an unfinished bridge to the Terminal-only handoff" (001 `README.md:10-12`). Slice 006 also carries the README of the deleted `build-time-evaluation` crate, the only description in this group of compile-time evaluation rules (006 `build-time-evaluation/README.md`).

## Mechanisms

- **Layout engine** (001 `packing.rs`, `data_layouts.rs`, `builder.rs:425-496`). Sequential packing with checked arithmetic; tag-prefixed overlay without niche packing; generic instantiation by a linear binding list, const arguments followed to depth 16 (001 `builder.rs:479`); first instance memoised under the definition symbol and "poisoned" on a second instance. Serves `data` layout.
- **Callback slot closure** (001 `private_callback_closure.rs:166-414`, `semantic_ranges.rs`). Depth-first search through inline record fields to slot-bearing records, then a quadratic bit-range overlap test with no budget. Serves compiler-private callback storage.
- **External-completion review** (002 `completion.rs:115-767`). A path-exploring abstract interpreter over checked flow plans whose value domain is "exactly entry parameter N" or unknown. It refuses recursion and unmodelled operations, has no memoization and no budget, so cost grows with path count. Serves process-exit requirements. It is the only real program analysis in the group.
- **Whole-plan candidate derivation** (002 `plan_derivation.rs:25-208`). One pass groups `satisfies` rows into plans keyed by a plan-name string and packages, then drops plans with an absent target body. Run once per known target, not only the selected one (002 `prepared_providers.rs:428-518`).
- **Parallel calling-policy activation** (001 `plan_computation.rs:403-455`). Scoped OS threads, strided; first refusal in request order wins; all activations run.
- **Content digests** (001 `binding_digests.rs`, `plans.rs:335-380`). Domain-separated, versioned SHA-256; short report ids checked for collisions against full text.
- **Literal integer interval audit** (005 `assumed_bindings.rs:195-350`). Builds `i128` intervals from `==, <=, >=, <, >` against literals joined by `And`; reports disjointness only.
- **Graph walks with limits.** Trait inheritance (depth 64, 004 `inheritance.rs:31-35`), type instantiation (64), static arguments (64), proposition expansion (64, depth restarts per level, 004 Surprises), contract expressions (256), installation grounding (explicit stack, 005 `dependencies.rs:85-117`), nominal dependency walk (cycle check only, 005 `semantic_dependencies.rs:125-296`), evidence-requirement closure (no limit, 004 `propositions/evidence.rs:88-245`), domain alias expansion (cycle stack, 003 `api/domains/aliases.rs:28-90`), lifetime topology (cycle stack, 006 `lifetimes.rs:74-206`).
- **Re-derive and compare.** Calls the old checker's producer again and requires equality: 003 lists about a dozen (`api/data/evidence.rs:67-89`, `api/operators.rs:62-69`, `behavior/policy/mutation.rs:56-64`, ...), 004 six, 005 nine (`semantic_dependencies.rs:31-37`, `providers/intrinsics.rs:32-58`, ...), 006 three (`invocations.rs:42-52`, `service_reach.rs:43-102`).
- **Measure-then-emit encoding** under byte, sequence and depth limits (006 `encoding/encode/policy_rows.rs:72-92`).
- **(README) Three-interval sign analysis with a rational stride lattice** to prove `match`-valued divisors nonzero without enumerating arms (006 `build-time-evaluation/README.md:174-194`).

## The three properties, tested

**1. Acceptance was the code's own yes or no.** For: every slice reports its grep for `proof_admission`, `ProofNode`, `verify_obligation` and `certificate` found nothing in the slice (001 Rules preamble; 002 Surprises 1; 003 Surprises 1; 005 Coverage; 006 Accepts section). Every refusal is an equality, a count or another module's answer. Where the code wants assurance it re-runs the same producer and compares (003 Surprises 2; 005 Surprises 2), which catches later tampering but not a wrong producer. Against: one call into the proof crate, `proof::mathematical_declarations::check_mathematical_declarations` followed by a presence test (004 `contracts/mathematical_calls.rs:24-45`). The intrinsic program-storage shape reads `ProofFact::Membership` rows as syntax, not as proofs (001 `intrinsic_declarations.rs:792-845`). Verdict: holds for all six slices, about 1 kernel-adjacent call against roughly a thousand own refusals. But this code was never meant to judge proofs; it trusted checker output.

**2. Identity by text; names decide meaning.** For, names that decide meaning: hosted intrinsic machine, trait and method names (001 `intrinsic_declarations.rs:194-211,559-889`; 002 `provenance_replay.rs:234-260`, checked by me: a plain `match machine_name` on four literals with no package test); `"Console"` for the completion role (002 `semantic_roles.rs:51`); method name `"realize"` (003 `operator_adapter.rs:62`); `"uefi_x86_64"` and all target comparisons by string (001, 002, 004, 005); Extent fields `base`/`length` (002 `program_entry.rs:918-919`); dangerous authority by file name (003 `authority.rs:25-78`); `"Carry::Portable"` (003 `api/domains/aliases.rs:62`; 004 `contracts/facts.rs:171-179`); proof-view atoms and byte-sequence predicates by callee spelling (004 `calls.rs:236-286`); `self`, `result`, `len`, `capacity` (004 `members.rs:38-43,278`, `names.rs:115-128`); `OmegaLayout` (006 `validation.rs:84-86`); integer type names (004 `const_values.rs:78-83`); field alias by equal source span (004 `members/aliases.rs:53-61`); lifetimes matched by name throughout (004, 005, 006). Rendered identity text is the join key for requirements, provider types, plan names and generic instances in every slice (002 "Identity by text" lists 15 sites). Against: most first-level joins use `SymbolHandle`s, dense ids or digests; several joins pair a string with a package identity on purpose (002 `service_schema/mod.rs:1-5`); program identity is by pointer (`Arc::ptr_eq`, 002 `provider_instances.rs:34`, 003 `provider_binding.rs:51-148`, 005 `runtime_permissions.rs:116-130`); the completion review tracks values by position (002 `completion.rs:70-77`); the output records turn parameters into ordinals and lifetimes into binder positions (004; 006 `lifetimes.rs:208-241`). Much of the text in 004-006 is serialization that must outlive a compilation (006 "Identity by text"). Verdict: strongly present, and names decide meaning in at least 12 distinct places. Handles were used for lookup, but cross-stage joins were by rendered text.

**3. One rule per placement or construct.** For placement: none. ## Patterns not seen before

- **Deferred refusals stored as data.** Errors found while source exists are kept as `Result` fields and raised only if a consumer demands them: 001 (5 sites, `source_preparation.rs:37-57`), 002 (about 15 fields, its mechanism 9), 003 (`provider_binding.rs:22-40`), 005 (`runtime_permissions.rs:32-80`). Errors on unselected candidates never surface; some surface on unrelated lookups (001 defect above).
- **Re-derive with the same producer and compare.** About 30 instances across 003-006. It defends against tampering of stored records, not against a wrong rule.
- **Candidate against custody that is the same object.** Three slices find this on the common path (003 numeric, 004 `input.rs:195-199`, 005 `runtime_permissions.rs:50-55`).
- **Facts stored twice and cross-checked.** Exact and "rendered" invocation targets; keyword flag and keyword spans (006 `invocations.rs:42-52`, `suspension.rs:143`); source and canonical calling rosters (001).
- **"Exactly one, else refuse" as the main idiom.** About 12 in 001, about 30 in 003, about 45 in 004, about 40 in 005, mostly hand-written despite an `exactly_one` helper (005 `semantics/facts.rs:6-20`). Linear scans with no index throughout (005 Surprises 16).
- **Silent skips relying on later coverage.** Candidate derivation `continue`s on 20+ conditions (002 `plan_derivation.rs`), shape mismatch returns "not an intrinsic" (001 10 sites), review drops applications in six cases (003 `application_realization.rs`).
- **Review narrower than the checker.** Package review has its own vocabulary and refuses admitted programs (004 "not yet" list of 10 gaps; 005 lifetime bounds; 006 index expressions). Publication is a second gate.
- **Work done for every target.** Candidates derived for every known target (002 `prepared_providers.rs:456-518`); every authored locator checked (001 `plans.rs:157-170`); unselected entry rows shape-checked (002 `program_entry.rs:584-639`).
- **Uneven recursion budgets.** Depth 64 or 256 in most walks; none on the completion interpreter, evidence closure, overlap check or nominal walk.
- **Consent stability as a design goal.** Choices explained by what should not force re-acceptance (005 Surprises 18; 006 `identity.rs:6-8`).
- **Very few behaviour tests.** 001 about 17; 002 four source-text scans; 003 four; 004, 005, 006 one each. Two tests keep the old linear search as oracle for a new index (003 Surprises 21).

## What a rebuilt compiler must still do

- Lay out `data` by declaration-order packing with overflow checks, tag-prefixed case overlays, erased proof fields, quotients as carriers and refinements as their base, and refuse inline self-containment (layout rows 1-11).
- Lay out a generic data instance per closed argument list, so nested generics and multiple instantiations get their own offsets (generic arity row; defects 1-2).
- Choose exactly one whole provider plan per boundary requirement per target, with explicit build selection over target default, covering every schema method (provider-plan rows).
- Validate foreign bindings per target: `via` shape, locator normalization, syscall targets and width, table-dispatch borrow and `addr` field, vtable index (via, locator, table rows).
- Recognize compiler intrinsics by toolchain ownership and exact signature shape, not by spelling (intrinsic rows; defect on name match).
- Run float `match` equality as IEEE equality of the selected format (float row).
- Enforce boundary-operator realization limits: two operands, fixed tokens, no alias, no lifetime parameters, no result-case `ensures` (operator rows).
- Select the program entry from the target's `ProgramEntry` slot and check its two calling surfaces and contract package (entry rows).
- Require accepted bindings for dependency-owned entry contracts and services, with matching schema digests and terminal-authority permissions naming one method (accepted-binding and permission rows).
- Prove that an external-completion provider never returns, never crashes and passes its status unchanged to a real exit leaf (completion row).
- Check assumed-binding signature compatibility and publish every assumed binding as a risk (assumed-binding rows).
- Refuse emission for independent composition until a carrier exists, and refuse reached calls into other targets' family bodies (composition, inert-call rows).
- Require installation-bound service reach to be grounded (installation row).
- Require public declarations not to expose non-public traits, conformances, domains, data, relations, operators, propositions or progress profiles, with one consistent scope (visibility row).
- Require published effect ceilings (reach, suspension, blocking, invocations) on non-build callables and derive family-head interfaces from members (ceiling and family rows).
- Check static-argument categories, const encodings and lifetime binding in public signatures (static-argument, const, lifetime rows).
- Define and check the public contract and array-length vocabulary, including evidence lanes and mathematical-call applications (contract vocabulary, evidence, index rows).
- Evaluate compile-time values only on pure, terminating, closed code with lexical constant selection and proved nonzero divisors (README rows).
