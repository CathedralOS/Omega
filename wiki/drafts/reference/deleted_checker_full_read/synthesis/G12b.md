# Group G12b: validation of machine calls, machine parameters, operators, places, the program coordinator, proof contracts and quotients

File names are shortened in citations: `mcc` = machine_calls_core.rs (slices 118, 119), `mpb` = machine_parameters_and_bindings.rs (120), `ops` = operators.rs (121), `places` = places.rs (122), `pv` = program_validation.rs (123), `pcc` = proof_contracts_core.rs (124, 125), `quo` = quotients.rs (126). All sit in `omega-rust/psi/compilation/validation/src/`.

## What this code was

These seven files are about 54,750 lines of the old validation crate, and they hold most of what the old checker knew about calls. `mcc` recognises compiler-owned operations, decides which calls may appear inside a specification, checks effect ceilings, picks result-typed overloads and hashes generic contracts into "commitments". `mpb` decides whether a machine passed as a static argument refines the callback signature it is passed for, and whether each static argument fits its binder. `ops` resolves what `a + b`, `a[i]` and named operator calls mean. `places` turns an expression into a storage place and says whether two places overlap. `pv` is the coordinator: it runs about 45 declaration validators, then walks every statement with an interval environment, then schedules `ensures` checking. `pcc` holds support queries for contracts plus the rules for erased bindings, proof-only data, `[copy]`/carry properties, domain weakening, proposition entailment and boundary qualification. `quo` checks `quotient data` declarations and plans `Quotient::lift`/`define`, which it then almost always refuses. The nine reports found nine tests in total; five slices have none (118, 119, 121, 125, 126).

## Mechanisms

- **Call-graph closure walks.** `mcc` walks `operational.calls` three ways for purity, observation and primitive closures (mcc:4317-4386, 4994-5017, 5263-5273); `quo` walks call dependencies for "checked bodies only" (quo:462-484); `pv` walks cleanup closures (pv:4907-4972); `mcc` tests caller independence (mcc:2819-2861). None has a budget; each ends through a visited list, usually a `Vec` searched linearly.
- **Requirement fan-out with a path guard** (mcc:5027-5157): a bodiless requirement is judged through every satisfier, and a requirement already on the path is refused.
- **Result-directed overload resolution** (mcc:7488-8890): an expected type is pushed down to calls; templates choose first and specialization copies inherit the choice by occurrence ordinal.
- **Tree rewriting** in three passes that take `&mut TypedTrees` (mcc:7704-8009, 8934-9011, 9505-9677).
- **Canonical bytes and hash commitments** with version tags for templates, specializations, captures, reach dependencies and call bindings (mcc:2887-4168, 9184-9493), and a normalized declared-contract identity (pcc:1453-1665).
- **Structural type unifier with binder capture** (mpb:3567-3823) for callback refinement and type-argument inference; no budget.
- **Contract refinement by canonical text** (mpb:2188-2585): facts are rendered, type names substituted after `<` or `,`, parameter names replaced by `$index`, then compared as strings.
- **Operator candidate selection** (ops:1728-1770) and a two-phase resolution with `DomainPending` (ops:1523-1561).
- **Place relation lattice, window folding and constant-index evaluation** (places:587-710, 5616-5664, 5704-5941; depth cap 64).
- **Statement walk with an interval environment** keyed by path strings, invalidated per statement write set, narrowed on guards (pv:4277-4490, 3260-3283).
- **Parallel prologue** that reruns sequentially if any validator reported (pv:589-648); per-machine workers with 256 MiB stacks (pv:4983).
- **Verdict reuse by hash** (pv:650-1461): FNV-1a over statement and contract source text plus a dependency context.
- **Forbidden-content walk** (pcc:157-423), **domain atom closure** (pcc:2351-2448), **owner environments** in raw and indexed forms (pcc:3092-3549), **linear bound terms** (pcc:5247-5299, depth 128).
- **Proof/runtime occurrence census** (pcc:6214-6345), **carry derivation** (pcc:7963-8168), **relevance contexts** (pcc:9740-10872), **proposition entailment by label sets** (pcc:8513-8716).
- **Quotient plan**: schema derivation (quo:5774-5894), fact identity as rendered string plus trace string (quo:3350-3636), greedy one-to-one matching, dependent/fixed partition of preconditions (quo:2755-2995), result-flow graph check (quo:3965-4062). `quo` has no budget anywhere.

Budgets found: depth 128 (mcc:4397; places:94, 220; pcc:495-680, 5247-5299), depth 64 (places:5704), eight borrows (pcc:9889).

## The three properties, tested

## What a rebuilt compiler must still do

- Refuse duplicate callable identities and overlapping operator spellings (R2, R3).
- Resolve result-typed overloads from the expected type and refuse ambiguity (R23).
- Choose operator meaning in the scope order and by active domain, with builtin index and range meaning as the fallback (R48-R52).
- Admit a call inside a specification only if its whole closure is pure, observation-free, crash-free and terminating (R12-R15).
- Erase a runtime statement that cites a theorem only when the theorem is effect-free, terminating and read-only, and refuse proof-machine calls in runtime expressions (R16, R17).
- Check published `suspends`, `blocks`, service reach and `invokes` ceilings against bodies and conformances (R18-R20).
- Check that a machine passed as a static argument refines its requirement in shape, borrows, effects, contracts and crash routes, with a real implication check (R30-R35).
- Require exactly one authored satisfaction for a nominal machine parameter (R36).
- Check every static argument against its binder kind, declared bounds, `requires` facts and conformance evidence (R37-R44).
- Keep compiler-owned operations exact: assembly services and authority, descriptor, selector, task-register and interrupt primitives, Build operations and wire codecs (R4-R11).
- Decide which storage an expression names and whether two places overlap, including folded windows and constant indexes (R53-R68).
- Check that every completion supplies the declared result and that stored, bound, passed and returned values fit their targets in type and range (R69-R74).
- Prove each machine's `ensures` at every exit and each callee's `requires` at each call, for propositions as well as Boolean facts (R76, R94).
- Refuse implicit loss or gain of a domain qualification (R80, R81).
- Keep erased bindings, proof-only data, `embed` and mathematical terms out of runtime code (R84, R85, R91, R97-R99).
- Check `[copy]` and carry properties field by field, including opaque data receipts (R92, R93).
- Let only a domain's listed boundary requirements assert its membership (R96).
- Check contract fact form, proposition declarations and witness evidence interfaces (R86-R89).
- Derive bounds from callee `ensures` through `&mut` parameters and accept slice-tail recursion as decreasing (R101, R102).
- Check `quotient data` formation against the sealed `Equivalence` laws, and decide `Quotient::lift`/`define` from a congruence theorem and precondition transport (R104-R112).
- Keep cleanup machines non-suspending, non-recursive without a ranking, and returning normally (R18, R28).

## Notes the authors left

- On requirements in specifications: "This consumes the declared promise; it never inspects a selected private implementation or supplies an unresolved caller with stronger guarantees." (mcc:4815-4818)
