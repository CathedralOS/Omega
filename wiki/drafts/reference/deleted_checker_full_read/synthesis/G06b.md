# Group G06b: old checking stage: execution planners, second half

Slices read in full: 051, 052 (`execution_terminal_unit_control_statement_sequence.rs`, cited `seq.rs`), 053, 054 (`execution_terminal_unit_state_graph.rs`, cited `sg.rs`), 055 (`execution_terminal_unit_structural_scalar_store.rs`, cited `S:`), 056 (`execution_terminal_unit_types.rs`, cited `L`). Claims I checked in the old source are marked "(checked)".

## What this code was

These four files are the execution planners of the old checker's stage `05_typed-trees-to-checked-trees`. They do not report errors to the user. They turn a typed state machine plus the `CheckFacts` that earlier passes recorded (flow, borrow, ownership, cleanup, value and proof facts) into `Checked...Plan` records that the Terminal emitter lowers (051 seq.rs:2, 052 seq.rs:9032-9493, 053 sg.rs:1-13, 055 S:1-30). The statement-sequence planner orders one state body's operations and decides when each stored reference is released (051, 052). The state-graph planner joins several states, and sometimes several machines, into one control graph. It plans case dispatch, state-to-state edges with their argument transfers, terminators, result ownership and termination ranks (053, 054). The store planner turns each `place = value` into one typed store (055). The types file builds the type and domain catalogs that the plans reference, and it holds a speculative parallel planner (056 L1883-2529). Every function returns `Option` or `bool`. A `None` refuses the plan, and the only record of why is a `trace.phase` string (051 seq.rs:1292-1295, 052 seq.rs:8995-8998, 054 state_graph.rs:8887-8932, 055 S:21). Even so, the planners enforce several hundred language rules of their own: case exhaustiveness, exactly-one ownership of results, argument fit, write authority and domain preservation. No slice contains a test of a language rule. The only tests are two cache-equivalence tests (053 sg.rs:1386-1729).

## Mechanisms

- **First-match producer chains.** `local_data::plan_inner` (051 seq.rs:1312-1925), `assignments::plan` (051 seq.rs:107-371), `plan_assignment` (055 S:3280-3476) and the edge-argument cascade (054 state_graph.rs:6388-6907) try fixed lists of producers. The first that accepts decides what the construct means. None has a budget.
- **Reference retirement graph.** `carrier_retired` and `holder_retired_following` recurse over `RetirementNode` with an `active` stack and answer `false` on a cycle (051 seq.rs:3231-3499; 052 seq.rs:5503-5527). `transport::collect`/`supplies` builds receiver-supplier pairs and runs a transitive search over them (051 seq.rs:4575-4746). `capturing_operations` builds a `BTreeMap` index, rebuilt on every call (052 seq.rs:5057, 5137-5202). The cost per state grows at least with the cube of the operation count (052 Surprise 5). No budget.
- **Exit release scheduler.** A topological loop takes ready releases and refuses when it can make no progress (052 seq.rs:7420-7563).
- **Differential closure test.** For each pending release and each anonymous owner, two full retirement queries ask "closed with this release and not without it" (051 seq.rs:3787-3873).
- **Loan dependency search** (`Dependencies`, 053 sg.rs:2831-3454). A mutual recursion over borrow rows answers either "may stay alive" or "free to relocate" (sg.rs:2825-2829). Cycle stacks use `Vec::contains`. No budget. It also collects parent pairs.
- **Disposition counting** (053 sg.rs:4298-5182). Twelve consumer kinds are summed and the total must be one.
- **Exact array tiling** (053 sg.rs:5240-5277). It handles fixed literal arrays only.
- **Graph fusion.** It runs SCC (`checks::termination::strongly_connected_components`) plus two worklists (053 sg.rs:958-1074).
- **Storage walk and selector admission** (055 S:1306-1458, 2401-2495). This is the one placement-independent walk: fields, cases, literal and runtime elements, and `Referent` crossings all go through it.
- **Byte value planning** (055 S:378-579). A recursive descent with a depth budget of 128 pushes domain obligations down to the leaves.
- **Exactness by re-lowering** (055 S:2226-2292).
- **Compile-time wire framing** (052 seq.rs:8726-8861).
- **Type and shape collection with recursion markers and a request memo** (056 L3359-4112). A loop is bounded by `type_reference_count()+1` (L3346). Pruning runs to a reachability fixed point (`retain_transitive`, L4245-4325).
- **Domain predicate closure.** It has a lowering budget of 4096 (056 L289; also 054 state_graph.rs:9725-9732).
- **Speculative parallel planning.** `ConsultedMap` records reads behind a `Mutex`, `ChangeLog::admits` validates them, and `apply` replays the writes (056 L1883-2529). It serves compile speed.
- **Bounded syntactic walk.** It takes at most 8 steps through the left operand only (054 state_graph.rs:9297-9321; checked).

The budgets are 4096 (predicate lowering), 128 (byte nesting), 8 (erased-subject walk) and the type-reference count. Every graph recursion in 051-053 is unbounded and relies on cycle stacks.

## The three properties, tested

**1. Acceptance was the code's own yes or no.** For: none of the six slices calls `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type. Readers 051, 052, 053, 054 and 056 searched for these names, and reader 055 stated it. Every place that touched proof evidence did so by presence or by a stored flag:
- 054: an erased proof argument is accepted when a term is stored at the argument's role (state_graph.rs:7088-7105), and a state `requires` is accepted when a `state_requires_fact` exists (9699-9717).
- 055: `integer_assignment_at(...).is_valid()` gates one lane (S:1994-2010). `scalar_index_is_proven` and `byte_write_is_proven` are copied into the plan as booleans and do not gate it (S:644-647, 1843-1846).
- 056: `evidence_term.is_some()` (L4413).
- 053: `call_requires_decided` (sg.rs:1216) and `local_terminates` (sg.rs:3910). `exact_outcome_case_test` is imported from `published::proof` but used as a syntactic guard test (sg.rs:81).

Against: none. Several comments defer a judgment to a later stage instead ("Terminal re-proves `index < extent`", 055 S:2370; "lowering refuses each one", 051 seq.rs:2044-2048; "machine lowering refuses pending obligations", 053 sg.rs:1196-1197). Verdict: holds completely. No place in this group used the proof kernel.

**2. Identity by text.** For, in four places:
- the wire codec matches `call.target.as_str() != "encode"`, the schema name and the field names (052 seq.rs:8647, 8732-8746; checked);
- a computed dispatch subject's payload is matched by variant and field name, and the symbol is compared only when valid (053 sg.rs:766-777);
- `PrimitiveType::from_name` decides whether a type is primitive or data (056 L1437, L3650);
- `$T{n}` binder strings are part of the memo key, and the domain name takes part in the row-equality test (056 L1569, L2581, L2889).

Against: all six readers found identity by handles almost everywhere. These parts work entirely by handles:
- the retirement half of 051 (seq.rs:2288-4867) and all of 052 outside `wire_codec`;
- the loan dependency search and result accounting (053);
- the whole edge and terminator planner (054);
- destination resolution and the storage walk (055 S:1033-3662);
- the type catalog (056, by `TypeIdentityId` and `SemanticDomainId`).

Comments reject spelling outright (051 seq.rs:2294-2295, 2355-2357; 056 L1202-1203, L4328). The habit that replaces text is identity by source coordinate. A value is found again at (state, statement ordinal, role) in two fact tables (R9, 13 copies), and a loan is matched by (owner symbol, formation statement, owner path) (052 seq.rs:5600-5603). Conditional successors are told apart by `ordinal` and `ordinal + 1` (054 state_graph.rs:8659-8662). Verdict: text identity is rare (4 sites). Placement-by-coordinate identity is pervasive and does the same kind of harm.

**3. One rule written per placement or construct.** For, by the readers' estimates: 051 about 11% (20% of its planning half), 052 about 15%, 053 20-25%, 054 about 40% plus 10-15% passthrough, 055 25-33%, 056 about 20%. Large instances:
- scalar value selection, 13 copies (R9);
- edge-argument fit, 9 source kinds (R65);
- "plain byte domain", 8 copies that differ (R15);
- membership-carrier walks, 7 copies, about 600 lines (R74);
- the ownership rule restated for 8 terminator shapes and 12 consumer kinds (053 sg.rs:4853-5116);
- the "never completes normally" exit, 9 copies (R31);
- the nine-field `ReleaseReference` literal, 4 copies (052 seq.rs:5029-7381).

Copies drift apart (R8, R11, R15, R19, R22). Against: the storage walk (055), the loan dependency search (053) and the retirement graph queries are general. Headers state the opposite intent (051 seq.rs:8-10; 052 seq.rs:5470-5473, 6569-6572; 055 S:4-17). Verdict: strongly holds. The repetition here is mostly by producer kind, terminator shape and root kind (parameter vs local) rather than by expression placement. 055 shows the property also as missing cases: some lanes accept a parameter root only (S:273, 2806, 3536).

## Patterns not seen before

1. **Language rules decided inside a lowering planner, with silent refusal.** All six slices enforce rules (87 merged rows above) yet produce no user diagnostic. 052 counts 56 `return None` and 133 `?` (052 Surprise 2). 054 names ten "unsupported tail" shapes, which describe plan shapes rather than program faults (state_graph.rs:8887-8932). The authors call a `None` an "omission" (052 seq.rs:8995-8998), so a refusal may not even mean rejection.
2. **The plan and the facts are two descriptions to be reconciled.** Each planner re-finds facts by coordinate and requires exactly one row to match. This "unique match or refuse" idiom appears at 6 sites in 051 (seq.rs:765-4660), at least 8 in 052, 10 in 054 (state_graph.rs:5863-9126) and throughout 053.
3. **Proof results travel as booleans and handles** that are sometimes gated and sometimes only forwarded (055 S:644-647 vs 2002; 054 state_graph.rs:7088-7105; 056 L4413).
4. **Judgments deferred to a named later stage** that the slice cannot see: 051 seq.rs:1232-1233, 2044-2048; 053 sg.rs:1196, 3176; 054 state_graph.rs:8050-8053; 055 S:661, 2370, 2772-2776; 056 L3176-3178. That makes 9 sites.
5. **One plan flag written by several passes.** `discard_result_on_return` is cleared or set by `operation_custody::admit`, `subject_call`, `result_custody::account` (053 sg.rs:897, 3626-3638, 5179-5188) and by three places in 052 (seq.rs:7169-7175, 7615-7627, 7955-7957).
6. **Debug printing in the product path.** `eprintln!("CHECKSITE")` appears at 6 sites in 051, 16 in 052, 2 in 053 and 3 in 054, under three different trace flags.
7. **Unbounded recursions guarded only by cycle stacks with linear `Vec::contains`** (051, 052, 053, 056), with super-quadratic cost (051 Surprise 10, 052 Surprise 5).
8. **Runtime decisions made by the planner**: runtime case conditions for cleanup (051 seq.rs:2944-2981), executable termination-rank components (053 sg.rs:4064-4125), and relocation of owned storage across an arrival (053 sg.rs:2615-2818).
9. **Three notions of "same type"**: raw handle, normalized identity and shape identity (051 seq.rs:785, 1127, 1439).
10. **In-band zero-handle sentinels**: the uncommitted owner (051 seq.rs:3256; 052 seq.rs:5545-7412) and "not a jump" (054 state_graph.rs:8955).
11. **Comments that record past bugs**: "equal backing is not identity" (051 seq.rs:2355), "Statement coincidence alone used to charge..." (053 sg.rs:5449), "rejected a valid store merely because a later foreign call was opaque" (055 S:32-35), "incorrectly rejected preserved input qualifications" (056 L4628). That makes 4 or more, and 051 counts several more.
12. **Headers that claim placement independence the code does not have** (051 seq.rs:8-10; 052 seq.rs:6569-6572; 055 S:16-17).
13. **Machinery for compile speed inside the checker**: speculative parallel planning with replay (056) and memo caches that keep their old filters (053 sg.rs:1840-1843).

## What a rebuilt compiler must still do

- Write a place only with the authority its root grants, and never through a shared reference or a `const` parameter (R2-R6, R16).
- Reject a literal index outside a literal extent, and prove every runtime index in bounds (R7, R8).
- Treat a scalar value at any position (store, local, return, guard, argument, rank) as one checked value with one origin (R9, R10).
- Preserve bounded-integer ranges, refined predicates and domain memberships across stores, arrays and transfers (R11, R12, R15, R17-R19, R22, R83).
- Refuse float operations that have no selected provider, and handle short-circuit booleans in initializers consistently (R13, R14).
- Keep bounded byte strings within capacity and preserve their domains through literals, concatenation and copies (R16-R19).
- Distinguish rebinding a reference from writing through it (R21).
- Give erased locals, erased parameters and proof-only arguments no runtime slot, and require their evidence (R24, R78).
- Track borrows from `let` places, views and subslices with exact access and type (R26-R28).
- Enforce atomic-cell types and single-attempt atomic sequencing (R30).
- Stop at operations that cannot return normally (R31).
- Forward or return a formal with its exact access, qualifications and linear claims (R33).
- Carry the origins of a returned reference (R34).
- Account for every call occurrence (R35-R37).
- Accept only complete returning terminators and exact guard complements (R38, R39, R41).
- Make every state and terminal call agree on the machine's result (R40).
- Close borrowed windows at exit except on crashing paths (R42).
- End each loan after its children and borrowers, at a point the program can prove (R43-R48, R50, R51, R53, R54).
- Give every owned or affine result exactly one disposition, consume a linear value exactly once, and drop unmoved affine values (R49, R52, R56-R59).
- Check case dispatch over a closed sum for exhaustiveness and duplicates, and read payloads only from the selected variant (R60-R63).
- Fit every transition argument to its target parameter by type, access and multiplicity, under the loan-permission table (R64-R67, R81).
- Keep storage that a carried reference depends on alive across a state arrival (R68, R69).
- Require a checked `requires` decision for every arrival at a qualified state, and Boolean guards (R70, R71).
- Lower and check state and machine contracts of the admitted shapes (R72, R73).
- Attach domain memberships to the right carrier for entry, exit, results and arrivals (R74-R77).
- Check termination ranks for completeness and agreement across a recursive component (R79, R87).
- Admit declared results and owned contents only of supported kinds (R80, R81).
- Keep one consistent shape per type identity, and refuse recursive by-value types and lossy array elements (R82, R85, R86).
- Restrict lending of bounded, refined and atomic scalar fields (R84).
