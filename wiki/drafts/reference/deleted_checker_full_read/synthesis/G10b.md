# Group G10b: validation: calls and write frames, completed storage and content conservation

## What this code was
Slices 091-096 are one file, `calls.rs` (about 45,400 lines), in the old validation crate. Slice 097 is `completed_storage_and_conservation.rs` (7,049 lines). The front of `calls.rs` (091:1-6554) and its back (096:40903-45408) check calls. That part resolves the callee, matches arguments to parameters, checks static arguments and conformance dispatch, bans non-tail and unmeasured recursion, and rules on how a call's result may be used. Between them, about 34,000 lines (091:6555 to 096:40902) are the `write_frames` module. For every call, statement and expression it answers two questions. Which caller storage paths may the code write? Which place does a returned or stored reference point into? The answers are `Vec<String>` paths or `None` for "unknown" (092 "What this code is for"; 093 calls.rs:16270). In 097, `completed_storage` (F:5-4730) answers "which store supplies the value at this place at this point" over flow-fact snapshots, and from that derives reference backing, view extents, loan homes and whether a domain membership survives. `content_conservation` and `content_projections` (F:4732-7049) validate `ensures` contracts written with `old`, `separate` and `Content<Owner,A>::project`, and the user's `project` machines. None of the seven slices calls the proof kernel. Apart from one test each in 092, 093, 096 and 097, the group is untested.

## Mechanisms
- **Write-footprint fallback chain** (092 calls.rs:8537; 093 17191; 096 40377-40627). The chain first summarizes a checked callee. It pushes the callee on `inference.active_states` and returns `None` on recursion (096 40582), runs `summarize_complete_state_written_paths`, then instantiates relative paths against the argument origins (093 20401-20473). Failing that, it uses the boundary or requirement signature, and last a syntactic guess built from names. There is no budget. It serves R40.
- **Origin algebra** (093 `FrameSourcePlace` 20882-21177; 095 `SlotEffect` accumulate/join/apply 33073-33210, 30283-30420). Places are rebased from callee parameters onto caller actuals. A join with any unknown alternative is unknown.
- **Type walks** for R43: recursive, with `visiting` stacks, generic bindings truncated by mark (092 9192-9221), and verdict caches keyed by handle and bindings (093 18075). 095 F `walk_declared_origins` (37621) expands each fixed array to one path per index, so N elements times M leaves (095 Surprises).
- **Cyclic transition fixpoint** (092 12137-12253). It does semi-naive delta iteration over per-state equations, and terminates only because `substitutions_are_finite` (12821, SCC over growing edges) ran first. There is no counter. Its one unit test is at 12926.
- **State-equation and slot-exit solvers** (094 25602-25830, 29208-29450): queue fixpoints with no cap. A result-reachability least fixpoint folds `when` guards with three-valued `BoolTruth` (094 25395-25440; 093 17853-17942).
- **Statement prefix walk** (094 27678-28529): one 850-line walk with four query modes and five behaviour booleans. Its cache also keeps failures (27633).
- **Snapshot resolution** (097 F:113-428): iterative DFS with Active/Complete marks and a budget of 3·snapshots + 2·edges + 1. Refusals on budget: projection expansion is capped at 4096 (F:1747), membership traversal at 65,536 steps and depth 128 (F:3652-3770).
- **Other bounds:** cleanup type depth is 32 (092 11413), the saved-reference chain is capped at 64 (092 13806), and `mentioned_type_parameters` has a counted budget (094 29125).
- **Call-site traversal** (096 44609-44744): one pre-order walk numbers the calls in a statement and records whether each is conditional. Calls are later found again by `(statement_index, call_ordinal)` (096 45364).
- **Proof-machine descent** (091 5670-5867): a growing-set fixpoint over sub-state parameters, plus a strict-subterm walk through member projections and immutable aliases.

## Patterns not seen before
- **The same fact is computed several times, and the copies disagree.** Six type walks answer "can this type reach caller storage", with different defaults for `DynamicTrait`, `Constrained`, `Unit` and a missing definition (092 9179/9346; 093 18486/22326). Five path-overlap matchers treat the wildcard index differently (095 36449 vs 36464 vs 37157; 093 16942; 096 38506). Three access tests (097) and two `same_slot` definitions with different fields (095 33073, 33313) do the same.
- **Most refusals are silent.** In 092-095, refusal is `None` or `Err(&'static str)`, and the reason reaches stderr only behind trace flags (`STRUCT`, `CALLWRITE`, `CHECKSITE`; 092 8241, 14346; 094 22973; 095 34379). Reasons are discarded with `.ok()?` (092 10376). The user sees whatever the downstream consumer reports.
- **Calls and statements are identified by memory address or ordinal position.** Raw pointer addresses key the memo tables (092 11076; 093 15567 and 9 more sites). Calls are found again by pre-order ordinal (096 45364), and any change to the walk renumbers them.
- **There are many mutex-hashmap caches.** About 18 `Mutex<HashMap>` caches sit in `CallFrameCaches` (092 14965-15003). A failed lock is silently skipped (093 16157) and failures are cached (094 27633).
- **Language rules are written into toolchain special cases:**
  - nine compiler-realization exceptions (091 3738)
  - access-view lifecycle, `BorrowBytes` and interrupt context (094 24956-25140)
  - wire codec, scalar accessor and asm intrinsics exempted from reference effects (095 34369-34562)
  - the core-vector surface never walked (094 27688)
  - algebra and field names `start`/`end`/`magnitude`/`Nat`/`Succ` (097 F:6659-6786)
  - a hand-listed set of primitive atoms (092 14914)
- **Unreachable code is skipped**, relying on an earlier stage's `static_type_context_is_unreachable` marking (091 2437; 095 32800; 096 44762), including the right operand of a statically decided `&&`/`||`.
- **Single functions switch behaviour on modes:** `walk_state_write_prefix_body` with four modes and five booleans (094), the `Evaluation` walker with seven entry points (095 32591), three binder modes chosen by which wrapper is called (092 Surprises), and backing resolution with three entry modes (097 F:848-907).
- **A global switch:** "the program selects no cleanup" sets all cleanup writes to empty (092 11485; 093 16759).
- **Validation and plan-building are separate passes.** The diagnosing pass runs first, then silent re-runs build plans (097 F:6463, 6515), so a plan can be missing without any link to the error.

## What a rebuilt compiler must still do
- Check arity, argument type, reference access and scalar fit for every call argument (R1-R5).
- Refuse a call whose `requires` the caller's facts refute, and keep schema-field `requires` across accessor writes (R6, R7).
- Resolve each call to exactly one callee: entry, requirement, implementation row or dynamic slot, never an internal state (R8, R14-R18, R22-R24).
- Check static type, const and machine arguments, type-parameter bounds and full specialization of generic calls (R19-R21).
- Check that a call through a trait requirement keeps exactly the selected conformance's formals, header bindings and result domain (R17).
- Ban unmeasured, non-tail and self-entry recursion. Require proof-machine recursion to declare a measure, and prove the measure decreases at each self-call (R10-R13).
- Enforce result use: no unit result in a value position, no silent discard of a non-unit result, completion only through an exact root, no nested call argument until it is supported (R25-R29).
- Keep proof-only operations out of executable code, and refuse bodyless boundary calls that have no realization (R30, R33).
- Prove float-to-integer conversions finite and in range, or require an explicit trapping or saturating result (R34).
- Check `asm` intrinsic forms and register-operand constraints, `code_layout`, `address_of` and native callback binders (R9, R35, R36).
- Know which caller storage each call, assignment and cleanup may write, at field precision, and drop exactly the facts about overlapping places. Refuse or widen to the whole place when unsure (R40, R41, R44-R46, R59).
- Know which parameter storage an exclusive-reference result or stored reference points into, through views and recasts (R42, R53, R54, R61).
- Know whether a type can carry a caller reference or write, with one answer (R43).
- Handle recursive and cyclic state transitions with a bounded or provably finite summary (R39, R47, R60).
- Keep reference bindings stable: rebind only `mut` parameters, allow no reborrow of an unresolved binding, expose no frozen binding to a replacing write, and use divergent aliases only through known projections (R49-R52).
- Refuse a reference that carries a local's storage across a state jump, and reset case knowledge after a call that may write an enum (R56, R57).
- Take reference effects from a checked callee body or a declared borrow contract, and check that dynamic realizations match their slot (R16, R55).
- Check assignment destinations and struct and array literal shapes in arguments (R48, R58).
- Track stored values, reference backing, view extents and returned-descriptor loan homes over control flow (R62-R65, R67).
- Carry domain membership across returns and value-preserving owned casts only when proved for every path (R66).
- Check content-conservation `ensures` contracts and `Content::project` machines as the language specifies (R68-R78).

## Notes the authors left
- "machine call cycles are banned; stack size must be predictable" (091 calls.rs:953-955). "Runtime recursion is TAIL-ONLY (measured recursion amendment)" (091 6010-6013).
- "the structural measure must be a bare parameter name (rung 1); compound measures over proof data are not proven yet" (091 5555-5558). "a cycle without a measure is an unproven termination claim" (091 5535).
- Known gaps: value-call arguments "cannot itself be a machine call yet" (091 1708); "storage address_of for write-only references is not implemented" (091 2013).
- Membership for runtime family subjects is "discharge[d] at the call's own proof" (091 1253). No such check is visible.
- On cleanup: "No statement spells that run, so a write summary built from statements alone reports 'writes nothing'". "Whenever a hook's summary cannot be trusted ... the whole dying place is reported instead". "A value that is in fact moved elsewhere is charged early, never missed" (092 11360-11391). "Owned data cannot contain itself by value, so reaching this depth means the walk lost track" (092 11410).
- "A position this walk does not recognize is charged, so an unforeseen expression form loses precision, not soundness" (092 11633-11639).
- "A machine binder selects code the callee may run, never the storage type of a parameter" (092 7993), a relied-on invariant.
- "No caller location can be written when the complete signature footprint is empty" (093 16465).
- An earlier `&&` evaluation "made a long `&&` chain cubic" (093 17846-17852).
- "A lifetime-only dependency is a hold on caller storage even when no field spells a reference" (093 18353).
- "Only a `mut` parameter can be rebound. Without this check a write to a non-`mut` reference parameter moved to a generated mutable local and the assignment's own mutability rule never saw the parameter" (094 23259-23261).
- "A whole view `collection[..]` denotes exactly the collection's storage" (094 23819-23825).
- "Call ordinals and their owning target lanes come from one traversal" (096 44600). A generic specialization reports "the authored machine it was cloned from, not its generated `$specialized$` name" (096 41551-41557).
