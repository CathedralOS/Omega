## What this code was

The group holds three things. First, the `proof` crate's range checker: `obligations.rs` lists every place a value flows into a type with a range or named constraint (obligations.rs:42-194), and `checker.rs` decides each one (checker.rs:6564-6649). Second, the mathematical declarations elaborator (`md.rs`, 12,717 lines), which turns authored mathematical declarations, `core::Identity`, propositions and indexed `data` families into kernel terms and has the kernel check them (md.rs:1-8, 12388-12517). Third, the "checked trees" output format: about 34,000 lines of record types, lookups and consistency checks that the old checker (stage 05) filled and that lowering read "without re-running borrow, proof, or termination analysis" (LIB:8-12). A small fourth part admits opaque representation selections (`rs.rs`), and four documents describe what the `validation` crate enforced and where it stopped. The two halves of the proof crate never call each other: stage 05 calls the range checker and stage 04 calls the elaborator (I checked the call sites, `05_typed-trees-to-checked-trees/src/checking.rs:422` and `04_typed-trees-to-typed-trees/src/preparation.rs:2051`). Six of the nine slices contain no kernel call.

## Mechanisms

- **Three-way certificate verdict** (checker.rs:884-965). A closure builds a proof tree or returns nothing. "Nothing" hands the decision to interval code; the kernel certifies or rejects a built certificate. Every certificate proves `lower <= term AND term <= upper` for a literal term or a fresh atom numbered by the obligation's position (checker.rs:6583), from the strongest lower and upper assumption the checker collected (checker.rs:1275-1308). Only fixed-width integers get certificates (checker.rs:1992-2011), using 5 of the kernel's 28 rule variants (checker.rs:5793-5869).
- **Integer interval analysis, twice.** `obligations.rs` folds declared types and literals over one expression with no flow facts (obligations.rs:1363-1487, 1596-1603). `checker.rs` runs a second analysis with guards, refuted guards, `requires`, ensures witnesses and operand folding (checker.rs:4959-5561). Unknown is the `i64` range (checker.rs:5502-5507). One pass per obligation, no fixpoint, no budget.
- **Float range with a NaN flag** (checker.rs:3606-3867) and a backward reaching-store search (checker.rs:3348-3450); places are symbol vectors.
- **Elaboration to kernel terms.** Source scalars map to five assumed carriers plus kernel `Two` for booleans (md.rs:1201-1245). All integer widths share one carrier and stay distinct through alias definitions that conversion is told not to unfold (md.rs:4263-4303, 4412-4417). Anything untranslatable becomes an opaque assumed constant (md.rs:3077-3294). The kernel later checks every recorded application (md.rs:4305-4397). Budget: `DEFAULT_CONVERSION_STEPS` per kernel call, no total per program.
- **Indexed W-type description of a `data` family** (md.rs:8482-8583, 10871-11242): index type, label carrier, child positions, `out`, `next`; universe lift by padding (md.rs:8058-8082).
- **Induction theorem generator** (md.rs:7223-7606, 8919-9078), with a memo valid only while the stored declaration list is a prefix of the current one (md.rs:7172-7187) and a pass that lifts definitions over outer parameters (md.rs:5866-5960).
- **Deferred target-dependent obligations** (caof.rs:49-309, 555-631, 765-828): predicate trees with per-leaf owners and postfix interval programs, discharged all-or-nothing per target.
- **Definite call-transfer counting** (roots.rs:670-1623): sum along sequences, minimum over alternatives; no budget.
- **Content-claim frontier** (facts.rs:971-1069): replays claim transformations in arena order.
- **Paged, generation-stamped arenas with lazily rebuilt indexes** (c&p.rs:765-980; facts/lib.rs:1199-1257; roots.rs:511-662; LIB:242-366), for parallel per-state checking.
- **Contract identity hashing** (caof.rs:1029-1252): a 64-bit FNV-1a fingerprint and a 32-byte digest over sorted clause text.
- **Carrier closure** for opaque representations (rs.rs:54-222): recursive type-graph walk, no budget.
- **Bounds found**: 128 alias rounds (md.rs:5418), 128 constructor depth (md.rs:6512), 8 generic-instance hops (c&p.rs:1498-1520), 4,096 terms in the trap scan (predicates.rs:198-226), 64 terms per polynomial product (validation/README.md:454-456).

## The three properties, tested

**1. Acceptance was the code's own yes or no.**

For: all five range placements accept on the checker's own interval when no certificate was built (checker.rs:373-398, 547-577, 623-642, 689-715, 779-808); floats and named constraints never reach the kernel (checker.rs:824-845, 5993-6251). ## Patterns not seen before

1. **One crate, two opposite proof systems that share nothing.** `checker.rs` never mentions the elaborator's integer theory and `md.rs` never mentions `ProofPlan` (I grepped both). A range the checker "proves" is never a kernel fact the elaborator can cite, and an induction theorem never bounds a value in the range checker.

2. **Assumptions are audited on one side only.** The elaborator compares each theorem's assumption closure with a roster (md.rs:5314-5396). Nothing audits the assumptions inside a range certificate (checker.rs:1040-1055, 1072-1090).

3. **The same fact computed by several engines.** The integer range of an expression is derived five times: in `obligations.rs` (1363-1487), in `checker.rs` (4959-5561), by `validation`'s arrival and occurrence intervals (checker.rs:382-390, 787-799), as a deferred interval program (caof.rs:555-631), and as stored bounds (OP:915-922, 2296-2307). "Are these two expressions the same value" has four implementations (obligations.rs:1255-1323; checker.rs:4842-4929, 3983-4053, 6379-6391). `checker.rs` alone extracts place paths four ways (218-239, 4909-4929, 3452-3467, 4012). Trap freedom is stored four ways (predicates.rs:376; OP:942; caof.rs:1479-1482; v&v.rs:554). Paths below a root have four segment types (predicates.rs:818-824; a_b.rs:1342, 1641-1647; facts/lib.rs:467-476) and at least seven root enums (terminal.rs:879-884, 1273-1350, 1873-1910, 1960-1964; flow.rs:1878-1882); 080 and 082 count these differently because they count different things.

4. **Verdicts stored as a bare flag or site list**, twenty in all: four "proven" and "decided" lists (facts.rs:39-44); two handle lists (OP:941-942); `trap_free`, `formation_decided` (predicates.rs:375-376); two indexed-write booleans (flow.rs:1856-1860); `decided_byte_view_store` (terminal.rs:876); `normal_return_writes_complete` (flow.rs:277); `obligation_live` (roots.rs:1805); four ranking booleans (TC:594-713); `fact_is_truth` (OP:1482); `may_trap` (caof.rs:1479); `complete_predicate_theory` (terminal.rs:2275). A consumer cannot re-check any of them.

5. **Self-validating records.** "Receipt", "commitment" and "replay" name a hash recomputed from the record's own fields: resource axis, envelope, roster, callback receipt (caof.rs:3005-3438; facts.rs:2260-2291), selection commitment (selections/lib.rs:140-147). Such a check catches corruption and nothing else.

6. **Identity by source position.** Facts are keyed by (state, statement index, call ordinal), by role, and by the producing expression handle: eight records and lookups in 082 (flow.rs:675-679, 2126-2144; roots.rs:390-415; terminal.rs:1246-1250), the expression-keyed lists in 083 (OP:455, 917, 941-942), every root in 084 (v&v.rs:166-191, 2311-2410). A fact belongs to a spot in the source tree, not to a value.

7. **"Exactly one row, else nothing" as the enforcement device**, about thirty copies: twelve in 083, seven in 084, more in 080, 081 and 082. Each has a "first match" sibling that disagrees (flow.rs:1339-1382; a_b.rs:2039-2089; OP:2659 against 2664-2685; v&v.rs:2221-2300), and the refusal is a silent `None`.

8. **Missing evidence gives the permissive answer**, seven times across five slices: zero rows is "accepted" (a_b.rs:707-718); no rank evidence is "not applicable" (a_b.rs:873-875); a missing call record "completes normally" (v&v.rs:1262-1271); a missing schedule is zero transfers (roots.rs:1064); status `Missing` is a built-in fallback (OP:477-486); a missing call row falls back to wider entry constraints (flow.rs:2146-2167); no obligation means nothing to refuse (obligations.rs:344-366).

9. **Silent skips.** `continue` with no diagnostic on seven conditions in the theorem loop (md.rs:4953-5195), in the demand walk (md.rs:10386, 10497), and in about nine obligation skips (obligations.rs:113, 344-366, 565-577, 817-819, 871-877, 918-920).

10. **A kernel error used as a signal**, four times (md.rs:4588-4599, 7308-7315, 7656-7662, 11348).

11. **Infrastructure described as working but dead or vacuous.** Cache, store and key (about 1,360 lines); acceptance views that cannot reject (a_b.rs:7-1048); resource envelopes (about 430 lines); `lowered-psi` with no producer (lowered-psi/lib.rs:19); `LemmaFacts` stored nowhere. The crate test that bans string identity fields (LIB:97-151) sits beside dozens of them (caof.rs:952-1003; terminal.rs:777-778, 2033-2035; OP:1480-1555).

12. **Compiler-coverage refusals mixed into checked results.** Gap rows saying "this compiler does not lower ... yet" (FTU:1621-1705), `Unsupported` eligibility (terminal.rs:2531-2536), seven completion refusal reasons (v&v.rs:879-914), about ten "no kernel denotation yet" messages (md.rs:744, 2389, 2521, 6605, 10817, 12284).

13. **The checked form is not self-contained.** Flow facts carry authored expression handles (flow.rs:254-265), plans carry `SourceExpression` variants (FTU:232-237), and `CheckedTrees` derefs to the typed trees (LIB:779-785).

14. **No test in the group runs a program through a rule.** No test calls `check_proof_plan` or `build_proof_plan` (076, 079); seven of nine tests in 082 pin index bookkeeping; 083 and 084 test no language rule. The strong tests are kernel checks of generated terms (md.rs:9087-10329) and tamper tests on certificates (checker.rs:2071-2316).

15. **The authors measured the problem themselves**: the route census (checker.rs:5595-5623) and the documents (validation/README.md:8, 79-80, 130-131).

## What a rebuilt compiler must still do

- Refuse a value that may fall outside the integer or float range of the type it flows into, wherever the value appears (R1, R2, R4, R5, R6).
- Decide `finite`, `exact`, `non_negative`, `positive` and `wrapping` as properties of the value (R3).
- Let a guard, a refuted earlier guard, a state or machine `requires`, a callee `ensures` and a case test establish facts about a value, and drop each fact when the value may have been overwritten (R7, R8, R11, R12, R13, R14, R15).
- Derive the range of arithmetic from its operands, including shifted bounds, differences under an ordering fact, casts and unary operators, respecting wrapping and the float format (R9, R10, R16, R17, R20).
- Track NaN separately from float ordering, per format (R18, R19, R22).
- Decide domain membership and domain implication for a value (R23, R24, R57).
- Check authored mathematical declarations: binders, types, ordering, universe levels, core vocabulary, resolution, application domains and `core::Identity` (R25 to R37).
- Support indexed `data` families: eligibility, constructor evidence including case `requires`, recursive children at their declared index, and induction for `ensures` over an erased family value (R38 to R47, R50).
- Keep generated theorems free of unaudited assumptions (R48, R49).
- Model storage precisely: places with field, case and index segments, window composition, complete or opaque write frames (R51, R52, R53, R54).
- Enforce the reborrow access table and trace each loan to its origin (R55, R56).
- Know which arithmetic can trap and require a proof where it can (R58, R62).
- Defer target-dependent constant predicates, recipes and overflow checks until a target is selected, then decide them (R60, R61, R62).
- Publish crash routes per cause with their guards, and check a call site against its target's contract (R63, R64).
- Count definite transfers of an owned value on every normal path and dispose of what remains at each exit, per case (R70, R71).
- Determine which paths return, never return or crash (R73, R74, R84).
- Resolve operators, apply the selected operator's contracts, and use the built-in meaning only when resolution chose it (R68, R78, R79).
- Recognise each authored `requires` and `ensures` and its evidence binding (R80).
- Prove termination by a rank that never increases and strictly decreases on recursive edges (R81, R91).
- Conserve content claims across transformations (R67).
- Select providers and check their reach, native bindings and instances (R69, R82, R83).
- Admit an opaque representation only with an inert carrier and at most one selection per build (R87, R88, R89).
- Enforce the documented numeric and recast rules (R92, R93).
- Resolve a match payload binding to the matched subject's value (R85).
