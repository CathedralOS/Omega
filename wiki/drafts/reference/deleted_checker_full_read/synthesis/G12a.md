# Group G12a: validation crate, first half: declarations, domains and predicates, effect inference, expression types, float and mathematical contracts, frozen program, literals

File abbreviations (all under `psi/compilation/validation/src/`): DC = declarations_core.rs (slice 110), DP = domains_and_predicates.rs (111: lines 1-8315; 112: 8316-16187), EI = effect_inference.rs and EA = erased_actuals.rs (113), ET = expression_types_and_fields.rs (114), FM = float_and_mathematical_contracts.rs (115), FP = frozen_program_and_queries.rs and LIB = lib.rs (116), LS = literals_and_struct_literals.rs (117). Rule rows are numbered R1 to R109 so later sections can cite them.

## What this code was

These eight slices are 49,937 lines of the old checker's `validation` crate, the stage between typed trees and checked trees (LIB:30-38). The crate header says what it produced: "Successful validation is a source judgment, not a portable proof certificate" (LIB:6-7). DC checked declarations: visibility, package selection authority, duplicate names, state signatures and terminal calls. DP held a symbolic executor and prover for user predicate machines (DP:2813-6468), an interval engine for the same predicates (DP:1667-2812), the statement-by-statement tracking of whether a `data` value's `requires` facts still hold after writes (DP:7281-13992), and domain declaration and membership rules (DP:13995-16187). EI inferred suspend, block, invocation and service-reach effects by fixpoint and reported nothing itself; EA decided where each erased record field of a call argument comes from. ET typed expressions and checked casts, operators, matches, slots and references; LS landed unsuffixed literals and checked every struct and case literal at construction. FM recognised the core library's float laws by shape and classified "mathematical" (never executed) declarations. FP and LIB were the crate's plumbing: the read-only input, about 70 memo tables, program projection, and the product entry and native-locator shape checks.

## Mechanisms

- **Symbolic execution with a refutation prover** (DP:4193-6360). Paths carry integer comparisons, clauses, array reads and storage homes; arrays follow select/store and split the path when two indexes cannot be ordered (DP:5466-5560). To prove a clause the prover adds its negation and asks another module whether the comparisons are unsatisfiable (DP:4967). Budgets: 8,192 work units, depth 64, 256 case splits, 64 clauses (DP:4501, 6220-6221). Serves R41-R45.
- **Induction over recursive predicates** (DP:5562-5891). The engine pushes a lemma before walking a body; a recursive call uses it when the premises are implied again and one integer argument moved strictly up or down.
- **Interval-set interpretation of predicates** (DP:1667-2812). Arguments are sets of integer ranges; a frame worklist joins outcomes. Budgets: 16,384 work units, 4,096 elements, 64 ranges (DP:1687-1689). Serves R45-R47 and R59.
- **Invariant windows** (DP:7357-8285, 12794-13992). Per state, a vector of tracked places keyed by spelling string records established, pending and open; `walk_state` interprets statements; two state-graph fixpoints (DP:12851-12906, 12956-13080) carry establishment (intersection), open windows (union) and literal values across states. No iteration budget. Serves R51-R58.
- **Three-valued constant folder** (`fold`, DP:11654-11847), `i128`, with `born_zero`; and a second interval folder `bounds_eval` (LS:3215-3400), `i64`.
- **Scalar domain predicate compiler** (DP:14793-15269): translates a domain's facts into a checked Boolean tree, inlining one-parameter helper machines; depth 128.
- **Three effect fixpoints** (EI:374-438, 2170-2364, 2812-2922): invocation targets, suspend/block per (machine, selector vector) context with symbolic callback dependencies so `A(F) = F OR A(F)` stays symbolic (EI:2181-2184), and service reach. None has an iteration cap.
- **Erased-leaf walk** (EA:78-291): follows shared borrows and immutable locals to a closed construction, formal or observable place; bounded by expression count.
- **Result-type walk with cycle cut** (ET:4991-5607): an expression met again on the stack answers `None` and the answer is not memoized. FP generalises this as the **re-entrancy cut** (FP:321-553, 1638-1654): a query already active returns `None`, and answers computed under a cut stay out of shared memos.
- **Field-domain rows** (ET:7764-7897, 8484-8600): one row per field path that carries a domain, one copy per element of a literal-length array.
- **Float law recognisers and closed float evaluation** (FM:236-276, 537-594, 949-1116): shape matching in both orientations; evaluation through the numerics catalog; budget 1024.
- **Logical-machine greatest fixpoint** (FM:2329-2370) and **kernel term readers** (FM:2746-2851, 3192-3305), depth 128.
- **Literal landing** (LS:350-566, 632-805): collects (expression, destination type) pairs from every placement, evaluates exact rationals, rewrites the tree.
- **Declaration projection fixpoint** (FP:2135-2283): grows the reached set from roots until stable, then prunes side tables.

## The three properties, tested

**1. Acceptance was the code's own yes or no.** For: all eight reports find no call to `verify_obligation`, `ProofNode` or a certificate. The strongest steps are Rust results from other modules: `scoped_arithmetic_*` (DP:4967, 11075-11084, 14113-14233) and `construction_predicate_judgments` (LS:3699, 5228). "Proved" is also defined as "the callee walk produced no diagnostics" (DP:13462), "a prepared row exists" (FM:2372-2389), and "a whole value was assigned" (DP:7477). EI and most of DP and FM return `bool` or `Option` with no diagnostic at all. Against: FM is the only slice that touches the proof kernel, and only to read: identity values (FM:1773-1825, 3077-3111), float and scalar predicates (FM:2746-2851, 3192-3385), prepared theorem and carrier rows (FM:2391-2413, 3760-3770). ## Patterns not seen before

- **One predicate language, eight evaluators.** A `requires` fact is evaluated by the interval engine (DP:1667-2812), the symbolic prover (DP:2813-6468), `fold` (DP:11654-11847), `bounds_eval` (LS:3215-3400), arithmetic implication after a store (DP:10811-11097), `construction_predicate_judgments` (LS:3699), the scalar domain compiler (DP:14793-15269) and the kernel-term reader (FM:3192-3305). They use `i64` (DP:2522, 12108), `i128` (DP:11654), big integers (DP:5180, 14010) and big rationals (LS:2589), and support different shapes. Which engine runs depends on the placement (construction, field store, element store, call, zero value), so the same fact can be proved at one and unknown at another. No single report shows this.
- **"Proved" inferred from something that is not a proof.** Five forms: no diagnostics (DP:13462), all recorded attempts proved (DP:13100), a row exists (FM:2372-2389), a flag set by assignment (DP:7477), message text (LS:5650).
- **Copies that disagree.** At least seven: three statement walkers accept different programs (DP:4659-4706 vs 5913-6015); the assignment arm omits parameter replay; two read gates pick differently; three literal placement lists differ (LS, report 117); two kernel readers differ on disjunction; two generic-binding helpers differ; the two engines read literals as `i64` and as big integers.
- **Silent refusal.** EI has no diagnostics; DP 1-8315 has two diagnostic families for about fifty rules; FM has text for roughly a quarter of its rules. Eleven refusal reasons exist only under a trace flag (DP:10417-10516). The user-visible error comes later and far from the reason.
- **Budgets that become "not proved".** At least twenty distinct limits: depth 128 (DP, ET, FM), 64 (DP, FP), work 8,192 and 16,384 (DP), 1,024 (FM), 256 splits, 8 steps (FM:2603; DP:12622), 16 (DP:11165). Acceptance therefore depends on program size.
- **Fixpoints with no bound.** Seven: DP twice, EI three times, FP:2135, FM:2329. Five rely on unstated monotonicity.
- **The first state stands for the machine.** DC:1868; DP:12907, 13410; FM:2252, 3744; LIB:237-248.
- **Answers depend on unrelated program content.** `u64` named somewhere (DP:5433-5442), a type row written elsewhere (FM:3667-3706), which machine is "quiet" (LS:5660-5671), path sort order (DC:1720), vector order (DP:9180).
- **Verdict split across passes.** Six pending lists: LS range obligations and pending predicates, ET formation obligations, DP `formation_decided: false`, LIB pending condition owners (LIB:512-551), FP pending layout geometry (FP:3800-3855).
- **Hand-listed kinds ending in a default arm.** DP:8416, 9011, 13911; FM:2694 (`_ => true`); FP:4847 (`_ => true`); LS:5547.
- **The zero-value model is everywhere.** Storage starts zeroed and establishment means showing the zero or constructed value meets `requires` (DP:11679, 8271-8276, 9309; LS:3239-3245, 6070-6113; ET:8950-8982).
- **No rule tests.** Six of eight slices have no tests; the sixteen tests in 113, 114 and 116 pin identity, caching and traversal, never a program.

## What a rebuilt compiler must still do

- Refuse a public surface that exposes a private declaration, and a cross-package selection without a direct dependency (R1, R2).
- Refuse duplicate declarations, members, states, parameters and literal fields (R8).
- Check state signatures: one result type per machine, arrival-only contracts on states, Boolean crash routes, witness-bearing named evidence (R10-R15).
- Check terminal calls: declared target, valid arguments, result equal to the caller's result (R16-R18).
- Check product and entry binding: Build context, visible unique entry, exact `ProgramEntry` signature, arrival requirement, native-locator shape (R21-R27).
- Admit a machine to compile-time evaluation only when it terminates, reaches known services and holds no linear value (R28, R29).
- Reason about an operator only when it carries its built-in meaning, never a user overload (R35, R36).
- Prove a goal from `requires` premises, including recursive predicates over collections, with in-bounds indexing (R39-R48).
- Establish a `data` invariant at construction and require it again after every field, element, partial or view write, before any read, call or return (R50-R58, R64).
- Decide whether a zeroed value satisfies a type's `requires`, and refuse zero-filling otherwise (R59).
- Apply only the active case's requirements, and treat a case as impossible only when proved so (R60, R61).
- Keep per-field intervals and range constraints from `requires` (R62, R63, R65, R66).
- Decide integer domain membership, carrier agreement, tags, aliases, progress profiles, domain identity and cycle freedom (R67-R75).
- Infer suspend, block, invocation and service reach through callbacks and dynamic slots, conservatively when unresolved (R76-R79).
- Give every erased record leaf an exact source at a call (R81).
- Type-check casts, float formats, matches and coverage, operators, slot shapes and reference correspondence (R82-R89).
- Recognise the sealed float vocabulary and its laws, and evaluate closed float meanings (R90-R92).
- Form `core::Identity` and mathematical applications, classify binders, and erase what never runs (R93-R95, R98).
- Admit an `ensures` of a logical machine only with a kernel-checked theorem (R96, R97).
- Land literals by destination, refuse suffix conflicts and implicit fractional landing, and check struct, case, array and byte literals (R99-R109).
