## What this code is for

This slice is the middle of the "structural judge": the part of the old checker that decided whether a contract proposition (`requires`, `ensures`, a guard, an equality) follows from what is known at a program point. It defines the term language the judge reasons in (`StructuralTerm`, CE:80503-80601), the judge's whole state (`StructuralJudge`, CE:82188-82231), and the fact store it rewrites with (`RewriteTable`, CE:80603-81096). It contains the resolver that rewrites a term using known equations and by unfolding pure machine calls (CE:83124-83543, 83747-84007), the translator from a source expression to a term (`callee_term_leaf`, CE:84273-84831), and the top-level verdict functions `judge_proposition` (CE:84991-85190) and `judge_equation` (CE:85192-85285). The first 1,450 lines track what value each storage place holds across reads, bindings and assignments, so a fact about a field survives a store to a different field (CE:77438-78657), and decode integers stored in narrower layout fields (CE:78660-78888). A separate module reasons about IEEE float comparisons, NaN and float bounds (CE:79008-79973). Another captures "owned snapshots" of a value at state entry or at a call for termination ranking (CE:80045-80494). Every verdict is one of `Proven`, `Refuted`, `Unknown` (CE:79980-79985), computed by this code; nothing here builds or checks a proof object.

## Mechanisms

- **Term rewriting resolver** (`resolve_uncached_with_budget`, CE:83178-83543). It rewrites a `StructuralTerm` to a normal form using the rewrite table, name substitutions, uniform array elements, scalar folding, float comparison truth, contract normal forms and call unfolding. Limits: 32 rewrite steps per call (CE:83175, 83193) and recursion depth 32 (CE:83190). When a limit is hit it returns the term as far as it got, with no error (CE:83191, 83542). Results for applications and projections of applications are memoised (CE:83143-83166). It serves every contract comparison.
- **Call unfolding** (`unfold_application`, CE:83747-84007) is a small symbolic interpreter over a callee's single state: it binds parameters and locals by name, decides guards with the judge, follows the first transition whose guard is proven, and turns a tail call into a new application. Depth limit 32. With `require_closed_computation` it becomes a check-time evaluator that demands closed arguments and closed locals (CE:83770-83791, 83849-83857). `closed_application_value` (CE:83684-83745) is the entry point for check-time evaluation. It serves calls used inside contracts and static values.
- **Three-valued logic** (`StructuralJudgment::connective`/`negated`, CE:79045-79065) and **disjunction by case assumption** (CE:79193-79221).
- **Float bound worlds** (CE:79024-79043, 79600-79706): premises are expanded into disjunctive normal form; each "world" is a list of (subject, float predicate) pairs. A bound is proven when every world contains a predicate that implies it. Budgets: at most 32 worlds, 64 predicates per world, 64 visited premise nodes (`remaining`, CE:79618), depth 32. Runs only for runtime body judges not in case-facts-only mode (CE:79615).
- **IEEE comparison reasoning** (CE:79786-79872): matches premises on the same operand pair, uses complements for `==`/`!=`, derives "not NaN" from any true ordered comparison that mentions the subject, and applies `unordered_truth` / `same_meaning_truth` from the float catalogue.
- **Float interval intersection** (`observed_float_bounds`, CE:79708-79770).
- **Rewrite table** (CE:80603-81096): entries carry one of three meanings (scalar equation, value identity, logical predicate) and are indexed by a hash of the term's kind and up to 4 nested levels (`NESTED_KEY_DEPTH`, CE:80897). It also keeps bookkeeping for a cache of "integer premises": a revision counter, the largest capture occurrence seen, and a list of deferred length facts (CE:80630-80716).
- **Two-mode term identity** (`StructuralIdentity`, CE:81283-81591): `SemanticValue` (the type's `PartialEq`, CE:81593-81597) strips `ObservedValue` wrappers and ignores metadata; `ResolutionInput` keeps them.
- **Storage value tracking** (CE:77673-78420): a list of `CapturedStorageValue` records keyed by coordinate (root plus segments), each with entry value, current value, selected case, anchors and storage version. Stores preserve only provably disjoint, stably backed values.
- **Narrowed integer decode** (CE:78660-78888): finds the stored integer type of a layout field, computes its range, decodes literals, and otherwise yields an unknown with that range.
- **Branch join by intersection** (`rejoin_pure_outcomes`, CE:82425-82616).
- **Owned snapshots through a prefix visitor** (CE:80254-80493): walks every path through the statements before a site and requires one common snapshot.
- **Record eta** (CE:85287-85415): expands a record-typed term to a constructor of its field projections, and recognises a constructor of projections as the variable itself.
- **Worklists and guards**: child-coordinate worklist (CE:77524-77613); expression worklist with a seen-set (CE:78489-78513); an explicit stack for `and`/`or` chains so long chains do not recurse (CE:84206-84270); recursion guards on data symbols (CE:77871), type references with a cap of 32 (CE:85293-85295), and depth 64 for identity (CE:81239).

- Float projection operators are found by their two path segment names: `from_source_identity(namespace, name)` CE:79470-79476, 79889-79893, then confirmed by an exact toolchain contract.
- Written storage is a list of path strings: `written: &[String]` CE:78117; compared at CE:78189; cleanup paths merged by string equality CE:78212-78232.
- Hash keys hash names and paths (CE:80920, 80953, 80956); this affects lookup buckets only.

Symbol handles are used alongside: coordinates use `PlaceRoot::Symbol` and field symbols (CE:78396-78402), applications carry `target: SymbolHandle` (CE:80574), and `BoundValue(SymbolHandle)` (CE:80529).

## Surprises

1. **Property 1 holds without exception here.** The slice has no reference to `proof_admission`, `ProofNode`, `verify_obligation` or a certificate (a search of the file finds `proof_admission` only at CE:4591 and CE:88530, outside the slice). Every verdict is the `StructuralJudgment` enum returned by this code.

2. **Unknown values decoded from a narrowed integer field all get the same term.** `decode_stored_integer_term` returns `CapturedValue` with invalid expression, statement and callable handles and `occurrence: 0` (CE:78875-78887). Term equality for `CapturedValue` compares exactly those fields plus type and range (CE:81381-81395). So two unrelated unknown values stored through narrowed fields of the same view type are equal terms, and `judge_equation` proves identical terms equal (CE:85208-85210). This looks like a bug that could prove `a.f == b.g` for unrelated stores. I cannot see from this slice whether a later step prevents it.

3. **The Debug format is load-bearing.** Identity keys are Debug strings (CE:81257-81260), and the hand-written Debug impl leaves out `ObservedValue`'s type and descriptor (CE:81605), a constructor's `data` and `case` (CE:81680-81686), an indexed value's element type (CE:81701-81711) and a scalar binary's type references (CE:81725-81737). Changing a Debug impl of a term or of any handle printed inside it would change checker verdicts.

4. **One type, two equalities.** `==` on `StructuralTerm` deliberately ignores "authority" metadata (CE:81593-81597); the tests assert this erasure (CE:81822, 81916-81919). Code must remember to call `same_resolution_payload` where the metadata matters; the resolver mixes both (`!=` at CE:83461, `same_resolution_payload` at CE:83204, 83211, 83309, 83387).

5. **Float equality inside `judge_equation` uses `f64` values** (CE:85229-85239): `+0.0` and `-0.0` are judged equal and landing (F32 or F64) is ignored. The identical-terms shortcut (CE:85208) runs before the NaN test, so a term containing a NaN literal compared with itself is `Proven` if `FloatLiteral` equality is reflexive on NaN. Builtin float `==` is intercepted earlier by `judge_ieee_equality` (CE:85110-85112), so this would matter for float fields inside compared aggregates. Cannot tell if that is reachable.

6. **`exact_storage_coordinates_disjoint` returns `false` when the roots differ** (CE:78387-78389). So values under any other root are never put on the "preserved" list that `observe_captured_store` re-installs after the store (CE:78233-78282). Whether they survive then depends on `observe_storage_effects` (CE:78279), which is defined before this slice. The answer is conservative, but it is the opposite of what the function name suggests.

7. **`completed_descriptor_place` works only when the binding *is* invalidated** (CE:78444-78446), the reverse of every other storage reader nearby.

8. **Ex falso is applied only to negations** in `judge_proposition` (CE:85005-85006). Other proposition shapes do not consult `hypotheses_contradictory` in this function.

9. **In the data-identity branch only `Proven` is used** (CE:85096-85105). A `Refuted` from `judge_data_identity` is discarded and the code falls through to the identity-equality path (CE:85120).

10. **Performance bookkeeping lives inside the fact store.** `RewriteTable::push` decides whether to bump `integer_premise_revision` using an "is fresh capture" heuristic on occurrence numbers (CE:80691-80713) and defers some length facts until their collection gets a rewrite (CE:80640-80683). A wrong "fresh" answer would leave a prepared-premise cache stale. Whether that can cause a wrong acceptance or only a missed proof cannot be told from here.

11. **Cloned judges share caches.** `QueryState` holds `Arc<Mutex<...>>` memo tables (CE:82233-82242) and `Clone` copies the `Arc` (CE:82299). `judge_disjunction` clones the judge, adds the hypothesis `left = false`, and judges with the shared memo (CE:79211-79216). `with_fresh_query_state` exists (CE:82694-82699) but is not used there. `StructuralTraversalInputs::same_inputs` (CE:78906-78914) suggests cache keys compare inputs; the key logic is outside this slice.

12. **The join keeps a captured value that differs between branches only in its occurrence number** and uses the first branch's term (CE:82490-82518, 82563-82589). Branch-local facts are dropped because rewrites come from the pre-branch judge (CE:82430), so this reads as "some unknown value", but it does merge two captures that elsewhere count as distinct.

13. **Dead or odd arms.** `nested_rewrite_key` matches on `term.semantic_value()`, which never returns `ObservedValue` (CE:81980-81985), so the arm at CE:80957 cannot run. All float literals share one index bucket (`(6, 0)`, CE:80933). Kind numbers 9 and 18 are unused (CE:80907-80968). `float_bound_from_prefix_alternatives` returns `Some(false)` (CE:79637) but its only caller tests for `Some(true)` (CE:79592).

14. **Capabilities one might not expect in a checker**: a symbolic interpreter for callee bodies with locals, guards and tail calls (CE:83747-84007); check-time evaluation of closed calls (CE:83684-83745); NaN-aware reasoning that proves `x == x` from any true ordered comparison on `x` (CE:79820-79835, 79859-79868); decoding of bit-narrowed layout fields with range tracking (CE:78660-78888); record eta in both directions (CE:85287-85415).

15. **Arbitrary fixed limits**: reference peeling stops after 4 levels (CE:78679); depth 32 in twelve places (CE:79338, 79430, 79615, 79646, 79793, 82915, 83190, 83555, 83766, 84203, 84282, 85198); depth 64 (CE:81058, 81239); world budgets 32/64 (CE:79028, 79034, 79618, 79686). A program just past a limit gets `Unknown`, with no message saying a limit was hit.

16. **Whole-program scans on hot paths**: `projected_meaning` and `nan_predicate` iterate every operator in the program on each call (CE:79888, 79907); `integer_at_field` iterates every laid-out plan (CE:78746).

17. **Trace output is woven through the logic**: about 25 `eprintln!("STRUCT ...")` blocks guarded by `struct_trace()` or `trace_contract()` (for example CE:77644, 78245, 79236, 79606, 82963, 83763, 84104, 85121). They are the only place refusal reasons are reported; a user never sees why a term could not be formed.

18. **Property 3 is weak in this slice.** Placement-specific copies are few (about 3%). The code here is mostly organised by term variant and expression kind. The storage tracker (CE:77673-78420) already keys facts by a coordinate (root symbol plus field/case/index segments) with versions and anchors, and treats a write to `a.x` as leaving `a.y` alone (CE:78396-78402), which is close to the per-field tracking the new design asks for, though it sits beside name-keyed environments and string paths.
