## What this code is for

This is the second half of the old borrow checker: the part that walks each state's statements and decides whether a borrow, read, move or write conflicts with a loan that is still live. The first module, `statements` (5604-6882), is the per-statement driver: for each statement it checks newly formed loans against active loans, replays the statement's evaluation steps to check reads and moves, checks an assignment's destination against live loans, and then checks calls that write through an owner. The remaining modules are services for that driver. `successor_cleanup` (6883-6996) decides whether cleanup on a state-to-state jump ends a stored loan. `access_sources` (7002-8169) turns a source place or a recorded operand into the set of storage places it may denote, following stored references ("descriptors") one load at a time. `aliases` (8170-9034) computes a loan's ancestry ("lineage") and decides when two loan rows are the same descriptor occurrence. `completed_backings` (9036-10234) answers "what storage does this already-evaluated reference value point into" by walking the recorded graph of value producers. `formation_captures` (10235-10548) finds which recorded operand a `&x` expression actually read. `shared_observations` (10589-10952) is a service for the contract prover: it lets a fact observed through a saved shared reference be reused at a later call, if no write in between could have changed the referee. `place_access` (11057-11634) and `simultaneous` (11639-11745) hold the interference test and the wording for two holds formed together. The slice ends with the top-level entry `check_flow_call_borrows` (11757-11884), which runs the call, return-view, persistent-store, per-statement and aggregate checks and then publishes requirements onto callers.

## Mechanisms

- **Statement replay cursor** (checks_borrows.rs:5947-6153). `statement_steps` yields the statement's evaluation steps (`Observe`, `Complete`, `Move`, others). `SelectedEvaluation::enter` keeps a current loan list per evaluation route; on rejoining sibling routes it takes the union of their loans (:5987-5994). `Complete` steps drop loans a call replaced and add loans the call or expression completed (:6034-6110). Serves borrow checking inside one statement with branches. No budget.
- **Descriptor-load resolver** (checks_borrows.rs:7163-7391). A worklist of `PendingLoad` items: find the first reference type along the remaining typed path (`first_descriptor`, :7397-7413), look up the loans or incoming identities that sit at that slot, and push one item per alternative with the path suffix. Terminates by refusing when a `(loan, incoming, type, remaining)` tuple repeats among ancestors (:7367). Two purposes: the referent, or the descriptor's own storage for slice metadata.
- **Storage-address resolver** (checks_borrows.rs:7574-7759). Recursion over an operand's `backing` chain with an ancestor list; carries an `exact` flag per alternative that says the place is the operand's own typed home; merging duplicates ANDs the flag (:7761-7770).
- **Lineage computation** (checks_borrows.rs:8309-8463). Iterative post-order walk over loan parents and suppliers with an `active` stack (cycle returns `None`, :8394) and a `completed` list. At a join the ancestors are intersected using `same_descriptor` (:8346-8360); a reborrow additionally adds the intersection over its suppliers (:8361-8386). Two modes: `Access` rejects `LifetimeDependency` rows, `Formation` follows them.
- **Deepest-owner match** (checks_borrows.rs:8802-8962). Among live loans and incoming identities whose owner path is a prefix of the queried place, keep only those of maximum prefix length and append the remaining suffix to each loan's captured segments.
- **Completed-value producer walk** (`Resolver`, checks_borrows.rs:9233-10208). Recursive walk from a recorded operand to whatever produced its reference value (stored slot, selection arms, copy, call result, borrow expression, constructed child), accumulating a `BackingFrontier` of `(place, lineage)` alternatives plus an `immutable_image` flag. Cycle check by ancestor list (:9254). Side output: the list of argument operands whose own referent a call forwards (`forwarded_inputs`, :10199-10205).
- **Immutable-image profile recursion** (checks_borrows.rs:9867-9898): all alternatives of a retention profile must be image storage; invalid or cyclic profile is `false`.
- **Operand-tree walks** (checks_borrows.rs:10263-10287, 10475-10547, 11331-11388): depth-first over `backing`, `evaluated_inputs`, constructed children and selection alternatives, stopping at nested calls, to find the unique operand for a source expression.
- **Write-interval check** (checks_borrows.rs:10784-10818): enumerate writes between two operand cuts, compute each write's permission envelope, require non-interference with every saved backing.
- **Supplier-chain search** (checks_borrows.rs:6753-6783): worklist with visited list.
- **Parallel per-state checking** (checks_borrows.rs:11805-11874): rayon `par_iter` over states, each with its own diagnostics, bound lookup and `StateGuarantees`; results are concatenated in state order.
- **Deferred caller requirements** (checks_borrows.rs:6279-6291, 11875-11882): `incoming_backing.require` may accept an assignment by appending a `PendingRequirement`; after all diagnostics pass, `incoming_backing::publish` writes them into `facts.borrow`.

No mechanism here has a numeric budget or fuel. All visited and ancestor sets are `Vec` with linear `contains`.

## Identity by text

No value, place or declaration in this slice is identified by a name string, rendered label or string prefix. (Grep for `.name`, `== "` and `starts_with("` finds such uses only before line 5604, in other slices: for example checks_borrows.rs:301, :609, :1343, :1656, :4486.) What this slice uses instead:

- **Handles and source coordinates.** Loans, operands, calls and expressions are arena handles. An occurrence is found by matching source-tree coordinates: `(statement_index, call_ordinal, target_symbol, authored_expression)` for a call (:5741-5744, :8159-8162, :10655-10657, :11313-11314) and `value.expression == access.expression` for an operand (:10277, :10638, :10667, :11207, :11348). Uniqueness is demanded each time.
- **Position as identity.** The entry state is `machine_states(machine).first()` (:10864-10868). State exit is encoded as a statement index equal to the statement count (:6869, :6876).
- **Raw versus canonical path equality.** Segment lists are compared with plain `==`/`starts_with` at :6733, :7676, :8050, :8116, :10765, with `canonical_place_segments_equal` at :8863 and :10217, and with `owner_segment_matches_place_segment` at :8839.
- **Strings as refusal reasons.** About 130 `&'static str` reasons are the only explanation of a refusal; `descriptor_loads::resolve_for` throws the reason away unless a trace flag is set (:7150-7159).
- **Strings in diagnostics only.** `symbol_name` and `mutated_place.label(program)` render names for messages (:5934-5935, :6193, :6319-6320, :6502-6503). Messages locate code by statement ordinal ("statement {}"), not by a source span.

## Surprises

1. **Nothing here goes to the proof kernel (evidence for property 1).** The slice never calls `proof_admission`, `ProofNode` or `verify_obligation`. Every verdict is a `bool`, an `Option` or a `Result<_, &'static str>` computed here or by `overlap` (a separate file, `checks_borrows_overlap.rs`, :11055). The prover appears only as a supplier of premises: `StateGuarantees` is passed to `overlap::append_statement_premises` (:5667-5674, :6407-6414, :11838-11844). The word "certificate" at :6692 names an in-memory struct. A comment at line 10 of the file (outside this slice) says results are "transient judgments, not certificates to serialize and replay".
2. **An empty backing list means "no interference".** `access_interferes` is `!backings.iter().all(...)` (:11496), so an empty list never interferes. `resolve_loads` returns `Ok(Vec::new())` for fixed-array metadata (:7186-7188), which reaches `argument_backings` as an `ArgumentBackings` with no places (:11217-11231). For a fixed array the length is static, so this looks intended, but the safety of the whole judgment rests on no other path yielding an empty list. `stored_address` does guard against it (:7754-7756).
3. **Assignment writes and call writes are judged by different code.** The assignment path resolves the destination through aliases and also checks the holder place and caller backing (:6179-6291). The call path compares `call_write_accesses` places directly with `canonical_place_non_interfering` (:6489-6496) and has no holder check and no `incoming_backing.require`. The module comment at :11059 says "One live-loan judgment for every access to storage".
4. **The checker changes the facts it checks.** `check_flow_call_borrows` takes `&mut CheckFacts` and, after diagnostics pass, publishes caller requirements into `facts.borrow` (:11875-11882). A write that conflicts locally can be accepted on a promise that callers must meet (:6279-6291).
5. **The borrow checker serves the prover.** `shared_reference_observation` is `pub(crate)` (:10610, re-exported :10953) and returns a `flow::CapturedValue` that lets a predicate be queried at an earlier observation. It builds a fresh `LoanOccurrences::for_state` on every call (:10742) despite the "prepared once" comment (:10551), and it passes no ordering premises (`&[]`, :10809).
6. **Source is re-read during checking.** `retain_captured_lineage` finds the `let` statement at the loan's statement index and resolves its initial-value expression again (:8087-8111). `resolve_places_with_loans` scans all statements of the state on every query to learn whether the root is a reference-typed local (:8752-8759). `resolve_all` and `producer` dispatch on `ExpressionNode` kind (:7826-7861, :9520-9531, :9660-9687).
7. **Comment and code disagree in `supplier_preserves_loan`.** The comment says "Either way the active loan must be exclusive and permit the child's access" (:6685-6687), but the `LifetimeDependency` branch returns before that test and requires equal kinds instead (:6701-6709).
8. **Asymmetry in `resolve_all`.** Only a `Mutable` borrow expression is looked through to its target (:7827-7836); shared and write-only borrows fall to `place_at`.
9. **Refusal reasons are mostly invisible.** About 130 reason strings exist; eight messages reach the user. `resolve_for` prints the reason only under `trace_flags::check_sites()` (:7152-7157). Debug `eprintln!` output under `STRUCT` and `CHECKSITE` flags lives in the checker (:5924-5930, :6297-6315, :11285-11287, :11451-11478).
10. **Diagnostics name statements by ordinal** ("statement 3 mutates …") and carry no source span (:5931, :6190, :6316, :6499).
11. **`exclusive_carrier_cases` looks only at the first differing segment** (:8676-8687). If one carrier path is a prefix of the other it returns `None` (not exclusive).
12. **Helpers with no caller in this file**: `resolve_place` (:8702), `descriptor_capture` (:10244), `address_receiver` and `AddressReceiver` (:10289-10346), `actual_invocation` (:10353), `binding_reference_access` (:10967), `ArgumentBackings::forwards` (:11141). They are visible to sibling modules that may live in other files, so I cannot say they are dead.
13. **Quadratic bookkeeping.** Visited, ancestor and completed sets are `Vec`s searched linearly (:6758-6768, :8317-8350, :10250, :10269, :10486-10498, :11332-11335), and several per-loan loops rescan all activations or all loans of the state (:5706-5712, :6054-6107).
14. **A capability worth knowing**: the checker distinguishes a pointer variable's own storage from the data it points to, tracks multiple alternative backings per reference through match arms and copies, treats loans in different sum cases as mutually exclusive, and models immutable image storage as shared-only authority with no caller address (:9210-9217).
