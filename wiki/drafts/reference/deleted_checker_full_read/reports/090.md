## What this code is for
This file decides whether recursion between machines is allowed. It builds a call graph with one node per machine, finds the groups of machines that call each other (strongly connected components), and applies a different rule to each kind of group. Contracts (`requires`/`ensures`) may never call each other in a cycle (call_cycles.rs:3719-3792). A cycle made only of proof-only machines must have a "ranking": either every recursive call passes a field of the ranked parameter (structural descent, call_cycles.rs:393-567) or another module judges the argument strictly smaller under an order relation (interval descent, call_cycles.rs:249-392). A cycle that contains runtime machines must use only tail calls, and, when a termination measure is declared, each call must be shown not to increase the measure and every cycle must contain a strict decrease (call_cycles.rs:2545-3142). The file also resolves the declared `terminates by` measure of a machine into one of seven "rank orders" (call_cycles.rs:1475-1748), works out which states of a machine need a rank at all (call_cycles.rs:999-1134), and copies the accepted result into and out of a `CheckedRankArrivalPlan` table that later stages read (call_cycles.rs:702-953, 2101-2383). The file has no tests and makes no call to a proof kernel.

## Mechanisms

- **Strongly connected components of the machine call graph.** `build_machine_call_graph` (3697-3717) joins proof-machine dependencies, exact proof call sites and runtime call edges into one adjacency list; `strongly_connected_components` (imported, line 6) is applied to it at 63, 684 and 3819. The same routine is reused on six smaller graphs: helper-only edges (302), preserving edges (520), state-level relevance (1091), weak edges (3145), internal arrivals (3228) and contract edges (3772). No budget.
- **Rank-parameter inference by pruning** (474-501). Each member starts with every immutable entry parameter of the rank type as a candidate. For each call edge the loop keeps a caller candidate only if some callee candidate is reachable by a field path, and the reverse, until nothing changes. It fails if any set empties or does not end with exactly one candidate. This serves `terminates by` on proof-only machines and lets helpers have no authored rank. No iteration limit other than the shrinking sets.
- **Interval closure through helpers** (319-386). From each ranked origin it walks call edges depth-first through unranked helpers; each edge that lands on a ranked member is sent to `proof_interval_strict_decrease_judged`. Helper-only cycles are refused first (302-312), which bounds the walk.
- **State relevance** (1018-1134). Builds a graph over states (growing the state list as callees are found), marks a state relevant if it makes a call the code cannot see into ("opaque", 1044, 1063, 1067, 1071) or sits on a cycle that includes a ranked machine (1091-1105), then propagates relevance backwards along edges (1106-1126). States that cannot reach recursion are exempt from rank checks. An unknown state defaults to "needs a rank" (1014).
- **Weak-edge acyclicity** (2659-2675, 3121-3131, 3144-3150). Every non-strict edge between component states is collected; the component is accepted only if these edges contain no cycle, so every cycle contains a strict decrease. Serves runtime `terminates by`.
- **Guard accumulation** (2687-2699, 2786, 2802-2805). Within a state, each transition's guard is passed as true to its own call proof and as false to later transitions; a non-entry state's `requires` expression facts are added as true.
- **Protected write-frame check** (1320-1449). Builds the list of places the rank reads (parameters, mapped coordinates, range premises), then asks whether each statement's normalized write frame leaves them alone.
- **Inertness walk** (3281-3331). A subtree search that reports an expression as not inert when it finds an atomic once-operation, a binary operator without built-in meaning, an index or range without built-in meaning, or a call the caller did not admit.
- **Memoised component validation** (199-246). Proof components are built once per frozen program and each validates lazily through a `OnceLock`.
- **Unranked-component reachability** (606-636). Depth-first search from one machine that stops at the first recursive component it meets and returns it if it is unranked and does not contain the origin.

## Identity by text

- The rank parameter of a proof-only machine is found by comparing the parameter's name string with the witness subject string (4250). The witness subject is text, not a symbol.
- A ranking view is accepted only if the witness's `view_path` string equals the view id's canonical path string (1521, 1549, 1581-1582).
- A declared scalar view is looked up by the `view_path` string (1627).
- The lexicographic measure is found by splitting `view_path` on `"::"` and comparing each piece with the measure's path member names (1681-1687).
- The measure's owner is checked by comparing the text before the last `"::"` with the rendered display path of the data type (1695-1697).
- Each lexicographic component is matched to a data field by field name string (1717). The symbol is compared only when the component already has a valid symbol (1727); otherwise the name alone decides.
- Field lookup for structural descent passes the member name and case-variant name as strings beside the member symbol (4269-4275, 4286-4294).
- Whether a runtime component was accepted is recorded as an empty or non-empty diagnostic string (826), and later code reads acceptance from `row.diagnostic.is_empty()` (836, 855).
- All failure reasons are `&'static str` values; the proof-cycle diagnostic selects its reason by matching the member list (3857-3861), not by text.
- Machine names are joined into diagnostics only for display (708-712, 3777-3781, 3839-3843).

Against property 2: call graph nodes are machine positions, call targets are `SymbolHandle`s, rank places are `RankSubjectCoordinate { parameter, path }` with typed segments, and type equality uses identity ids (445, 563). Text identity is confined to resolving the authored `terminates by` clause.

## Accepts or skips without proof

- **No kernel anywhere.** The file contains no call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate. Strict decrease is decided by `proof_interval_strict_decrease_judged` (357), `prove_captured_rank_call` (3020) and `prove_ranking_range_call` (3089), all in `contract_entailment`; their yes/no is taken as final. Structural descent is decided by this file's own syntactic test (4259-4284).
- **One-machine proof-only self-recursion is never diagnosed here.** `validate_machine_call_cycles` handles a one-member component only for selector self-recursion and then continues (3820-3838). A proof-only machine that calls itself directly and fails both rankings has its failure pushed to `ranking_failures` (3945) but no diagnostic is produced in this file. I cannot tell whether another stage refuses it.
- **A member without a body witness is not examined.** In `project_component`, a member whose witness is missing is skipped (2682-2684), which also skips the "every edge was observed" test at 2959-2965. The function can then return `Ok(None)`, which `retain_runtime_rank_component` stores with an empty diagnostic (713-714), and `retained_runtime_recursive_components` lists it as accepted (836). I cannot tell whether callers always supply witnesses.
- **Assembly statements never invalidate a ranking.** After the write-frame check fails, `Assembly` and `AssemblyFact` statements are skipped (2728). `require_tail_component` also skips `AssemblyFact` (2434). Cannot tell whether assembly writes to ranked values are caught elsewhere.
- **Entry state with a captured rank skips all non-transition statements** (2713-2715) and skips the operand write-frame check (2787). `prove_captured_rank_call` receives the statement ordinal (3027) and may cover this; cannot tell from this file.
- **States judged not relevant are skipped entirely** (2709-2711, 2016-2018, 980-982, 2662), including the continuation and guard rules.
- **A failed implementation-selection lookup becomes an empty roster.** `collect_dynamic_implementation_selections(program).unwrap_or_default()` (2510) makes every slot have no implementations. Selector calls then add no graph edges (2480-2483) and pass `project_component` with nothing checked (2857-2885). Cannot tell whether the lookup failure is reported elsewhere.
- **Selector calls have no termination-contract requirement.** The "unconditional public termination contract" rule (2887-2906) applies only to non-slot targets; implementations outside the component are skipped (2858-2862).
- **Callees outside the component are skipped** (2919-2923). Their own termination is not this function's concern; `unranked_component_reached_from` (606-636) exists for that but its use is outside this file.
- **Boundary targets declared with an empty `invokes` list are assumed not to call back** (1059-1061, 1136-1183). This trusts the declaration.
- **A binary operator with no spelling is treated as inert** (1210-1213).
- **`natural_component` failure becomes an empty component** (2630-2634) rather than an error. By design it returns `None` for every order except natural and lexicographic (1948).
- **A consistency failure when reloading drops the row silently** (`filter_map`, 857; 874, 898). When storing, a formation whose owner or body does not match is replaced by a default handle (2188-2227).
- **Structural descent trusts field access.** Any chain of `Member` nodes on the rank parameter whose final type equals the rank type counts as strictly smaller (508-518, 4266-4278). The code does not check here that a named case variant is the live one or that the type cannot contain itself through a reference. Cannot tell whether other stages guarantee this.
- **Unknown symbols add no contract-cycle edges.** `declaration_call_dependencies` returns `None` for a symbol of no known kind (3519-3522) and the caller ignores that (3765). Opaque propositions add no dependencies (3523). Built-in functions and fixed core declarations have none by definition (3442-3453).
- **Only expression facts of a state's `requires` become guards** (2693-2697); membership and proposition facts are dropped. This loses information but does not accept anything.
- **`entry_rank_formed` is a flag supplied by the caller** (2542, 2579); this file does not check how it was established.

## Surprises
- **A directly self-recursive proof-only machine with no valid ranking produces no diagnostic in this file** (3820-3838; see above). The multi-machine case does (3844-3868). The recorded reason for the one-machine case is computed and then unused.
- **The two walkers that must agree walk different things.** Dependency collection visits an assignment's target and value (3622-3625) and uses `executable_children` (3686). Exact call-site collection visits only the assignment's value (4120), uses `children` (4228) and visits a call's receiver explicitly (4223). When they disagree the component is dropped at 136 and the user sees "the exact call inventory is incomplete", which names no real fault in the program. A proof call inside an assignment target would always trigger it.
- **The interval check passes the origin machine with a state that belongs to the caller** (350-360): `state_in_machine(&machines[caller], ...)` finds the state, then `proof_interval_strict_decrease_judged` receives `&machines[*origin]` and that state. When the caller is a helper these are different machines. This may be intended ("on every incoming path") but the pairing is not explained.
- **Missing implementation selections silently disable selector recursion checks** (2510; see above).
- **Acceptance is stored as an empty string** (826, 836). A component with `Ok(None)` and a component fully ranked are indistinguishable to `retained_runtime_recursive_components`.
- **The checker infers rank parameters.** A private proof-only helper needs no `terminates by`; the pruning loop picks its rank parameter (474-501). A second, independent ranking method (interval, 256-391) is tried only when the structural one fails (3933-3949). This is more capability than property 3 suggests.
- **Seven rank orders are supported** (1475-1495): natural descending, increasing to a bound, bounded distance, slice length, declared identity view, declared computed view and lexicographic over data fields. A lexicographic rank can be compared only from the entry state (3012-3019, 3118-3120), so a lexicographically ranked machine cannot make its recursive call from a later state.
- **An unnamed default.** With no view named, a member or indexed subject of unsigned type is treated as a natural descending rank; the variable is called `pending_natural_default` (1565-1576), which suggests a transitional rule.
- **`unranked_component_reached_from` does not look past any recursive component** (627-632), including the origin's own: calls made by other members of the origin's component are never followed. It finds an unranked component only when the path to it contains no other recursive component.
- **Unused or constant data.** `InternalArrival.recurrent` and `.arguments` are computed (3212-3235) and not read in this file. The sixth element of `proof_call_site_sort_key` is always 0 (3966-4006). `names` is built for every multi-member component at 3839-3843 but used only for proof-only failures.
- **Repeated work.** `dispatched_implementations` is recomputed for each selector transition (2848) although `require_tail_component` and `extend_runtime_adjacency` each compute it once (2426, 2456). `rank_relevance` is recomputed for each machine in `internal_rank_nonincrease` (975).
- **Runtime cycle failures are not pushed to the diagnostics list here.** `validate_machine_call_cycles` reports only contract cycles, selector self-recursion and proof-only cycles (3798-3869); a failed runtime cycle is written as text into the plan row (713-722, 826) for another stage to surface.
- **Error wording.** "a preserving cycle has no strict measure DECREASE" has an upper-case word (2970); the same "lacks a classified tail edge" string covers six different conditions (1272-1304, 2964).
- **Formatting.** Lines 159-160 and 871-930 are not in rustfmt layout, which suggests the formatter could not process those expressions.
