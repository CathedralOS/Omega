## What this code is for

This slice is not the source checker itself. It is most of the `provider-planning` crate, which sat after checking and turned checked source trees into target-specific plans: which implementation supplies each boundary (foreign/host) requirement, how each boundary call passes its arguments, and how each `data` type is laid out in bytes.

It has five parts. `calling_policy_plans/` evaluates the calling convention chosen for each boundary signature and re-joins the result to the original source declarations so that reports can name them. `data_layout_queries/` computes size, alignment and field offsets for `data` declarations (records, enums, quotients, generic instances, "plan-laid" fixed representations) and places compiler-private callback slots inside records. `evaluated_via_bindings/` and `native_bindings/plans.rs` take a foreign-symbol locator that a build-time program already computed (`via` leaf or Build-supplied binding), validate it for the target, and seal it into a receipt made of SHA-256 digests. `intrinsic_declarations.rs` decides whether a provider row is one of the compiler's built-in operations (console write/read byte, process exit, UEFI program storage/image, sealed accessors) by checking the exact shape of its trait, requirement and realization. `dispatch_tables.rs` and `native_provider_sources.rs` are small helpers for vtable-style bindings and target-family heads.

The README says this crate "still consumes checked trees and package-input custody" and calls that "an unfinished bridge to the Terminal-only handoff" (README.md:10-12), and "transitional source/checked-tree realization, not target-neutral Psi checking" (README.md:99-102). Almost every check here is a consistency check between two copies of the same information (source-side and canonical/Terminal-side), not a language-safety proof.

## Rules enforced

"Own judgment" means the code compares values itself and decides. No row uses the proof kernel; a search of the crate for `proof_admission`, `ProofNode`, `verify_obligation` and `certificate` found nothing.

## Mechanisms

- **Parallel policy activation** (plan_computation.rs:403-455). Runs one closure per pending calling policy on scoped threads. Worker count is `min(available_parallelism, items)`; worker *w* takes items *w*, *w*+workers, ...; the calling thread takes stride 0. If a thread cannot be spawned, the calling thread runs that stride itself (443-447). Results are stored by index and consumed in request order, so the first refusal in request order is the one reported (header 6-10). All activations run even if an early one fails. A worker panic is re-raised. Serves calling-policy evaluation.
- **Deferred refusals carried as data.** Source-side preparation stores `Result` values (`Result<String, String>`, `Result<_, Vec<Diagnostic>>`) for policy name, instances, ABI, review and per-target helpers (source_preparation.rs:37-57; plan_computation.rs:240-249; signature_review.rs:25-26; selected_providers.rs:25-43; intrinsic_declarations.rs:48-62). The error is raised only when a consumer unwraps that field. Serves calling plans, opaque representations and intrinsic shapes.
- **Inline-recursion detection** (builder.rs:153-201, 282-299). A stack of data symbols being laid out, 16 inline slots plus an overflow vector. A symbol found on the stack is a cycle. Serves `data` layout.
- **Sequential packing with checked arithmetic** (packing.rs:32-79, 124-130). Declaration order, align-up then add, every step `checked_*`. No reordering and no niche packing (data_layouts.rs:12-16). `align_to` with alignment 0 returns the value unchanged.
- **Tag-prefixed overlay for case-bearing data** (data_layouts.rs:275-353). Tag of `ENUM_TAG_BYTES` at offset 0, common fields next, all case payloads from one base aligned to the strictest payload alignment.
- **Generic instantiation by binding substitution** (builder.rs:425-496; type_reference_layouts.rs:150-238). A list of (parameter symbol, parameter name, argument type) is extended at each generic use and searched linearly. Const arguments are followed through named bindings to a depth of 16 (builder.rs:479). The first instantiation of a generic definition is memoised under the definition's symbol; a second, different instantiation "poisons" the entry (sets its symbol invalid and its signature to the empty string) and from then on every use is computed afresh.
- **Bit-range overlap check** (semantic_ranges.rs:10-151; private_callback_closure.rs:339-386). Builds half-open bit ranges for each field (per bit-field fragment, per stored integer, per repeated element, or the whole field) and tests every callback slot range against every semantic range and every earlier slot range. Quadratic, no budget.
- **Inline path closure** (private_callback_closure.rs:166-311). Depth-first search from each record through inline record-typed fields to records that hold callback slots, with a `seen` stack for cycles. Only `Record` shapes and directly named field types are followed (layout_plan.rs:63-69): references, arrays and enum payloads end the path.
- **Content digests** (binding_digests.rs; plans.rs:335-380; private_callback_closure.rs:78-107; plan_computation.rs:385-401). Domain-separated SHA-256 over length-prefixed fields, with versioned domain strings ("omega.evaluated-binding-evaluation.sha256.v2\0", "omega.native-build-binding-evaluation.v1\0", "omega.callback-natural-data-layout.v1", "omega.boundary-plan-application-report.v3"). Short "report" ids are derived from them and explicitly checked for collisions against the full text (callback_bindings.rs:206-221; private_callback_closure.rs:389-414).
- **Re-derivation as validation.** Several validators rebuild a value from retained parts and compare (`replayed_validated_plan` callback_bindings.rs:78-119; `native_demand` callback_layout.rs:111-133 and 153; composed placements callback_layout.rs:234-240).
- **Row grouping and merging** for Build-supplied bindings (plans.rs:180-266): linear search for an existing plan by (schema symbol, target name, supplier package, application text), then for an existing row by requirement identity text.
- Lookups by symbol are linear scans over arenas and vectors throughout (builder.rs:323-338; private_callback_closure.rs:180-183, 233-236).

- **Shape mismatch returns "not an intrinsic" with no diagnostic.** Every non-count failure in `boundary_row_shape` returns `Ok(false)` (intrinsic_declarations.rs:563, 603, 619, 624, 631, 639, 659, 662, 665, 668). Whether a later stage reports an unbound row cannot be told from this slice.

The realization's contracts are checked (745-753). Cannot tell whether another check constrains the requirement's contracts.

## Surprises

Evidence on the three properties first.

1. *Own yes or no, not the proof kernel*: holds completely here, but for a plain reason. Nothing in this slice calls the proof kernel, and nothing here judges a proof. The nearest thing is `canonical_storage_parameters` (intrinsic_declarations.rs:792-845), which reads `ProofFact::Membership` rows from the typed tree and matches their shape structurally to decide whether a signature "looks like" the program-storage entry. It reads a contract as syntax; it does not check that the fact holds.
2. *Identity by text*: strongly present. Names decide meaning for intrinsics (trait, method and realization machine names, `"ByteRead"`, `"i32"`, `"uefi_x86_64"`), targets are name strings everywhere, and most cross-stage joins compare rendered identity strings. Against the property: symbols (`SymbolHandle`), dense ids and digests are used alongside, and the authors check short hashed ids for collisions against the full text.
3. *One rule per source placement*: not present. This code has no notion of locals, fields or call results as fact carriers. Its repetition is duplicated validation between "source copy" and "canonical copy" of the same record.

Other findings.

- **Likely wrong layout for nested generics.** The memo key for a generic instance is the rendered text of its arguments, taken without substituting the enclosing bindings (type_reference_layouts.rs:170-177 calls `display_type_reference_with_constraints(*argument)` with no bindings). For `data Outer<T> { inner: Inner<T>; }` used as `Outer<u8>` and `Outer<u64>`, both inner uses render as "T". The second `Outer` is poisoned and recomputed, but `Inner<T>` matches the memoised signature "T" (207-211) and returns the layout computed for `u8`. I could not confirm from this slice whether typed lowering always replaces such uses with closed instances first (`definition.generic_instance` at private_callback_closure.rs:55 suggests closed instances exist). No test covers it.
- **Poisoning leaves orphans and loses field offsets.** After poisoning, each use inserts a fresh set of `FieldLayout` rows into the shared arena that no `DataLayout` refers to (type_reference_layouts.rs:234-237), and the first instance's entry keeps its fields but has an invalid symbol (218). A program with two instantiations of one generic data type therefore has no findable field offsets for either; the header says downstream "cleanly rejects ambiguous generic field access" (12-13). That is a real limit on generic data, stated only in a comment.
- **A refused opaque selection poisons unrelated lookups.** `opaque_review` unwraps every row it scans, so a refusal on an earlier, unrelated selection aborts the lookup for a different application (signature_review.rs:184-185). The test pins this (249-259). The header says refusals surface only "if a canonical signature actually uses an opaque representation" (21-22); in fact they surface when any opaque use is looked up past them.
- **Comment and code disagree on allowed helper provenance.** The header lists `BuildOverride` or `TargetDefault` (selected_providers.rs:4-5); the code also accepts `TargetRealization` (99), and the diagnostic text names all three (102).
- **Two materializer schema versions.** The `via` path passes `MATERIALIZER_SCHEMA_VERSION` = 1 (evaluated_via_bindings.rs:28; binding_retention.rs:188); the Build path passes the literal `2` (plans.rs:390). The Build path also passes the work-schedule marker in the argument position where the `via` path passes the evaluation-semantics marker (plans.rs:387 against binding_retention.rs:185).
- **`require_inferred_supply` is derived from the shape**, `hosted.shape == BoundaryIntrinsicShape::I32ToUnit` (intrinsic_declarations.rs:252). So exit and write-byte must use inferred boundary supply while read-byte may use the legacy or evaluated-import styles, and nothing says why the shape is the deciding property.
- **Hosted row order is load-bearing.** `exit_process_row` indexes `HOSTED_INTRINSIC_ROWS[0]` and `[1]` by position (intrinsic_declarations.rs:336-341).
- **Unreachable arms.** `IntrinsicDeclarationKind::Access(_) => Ok(None)` (intrinsic_declarations.rs:288) cannot be reached because `Access` returns at 274-282. The final `_ =>` in plans.rs:412 cannot be reached given how `locator` is built at 313-334.
- **`TypeLayoutDescriptor::BoundedByteBuffer` is never constructed** in the deleted tree (defined layout_plan.rs:43-46, read at 88; `type_descriptor` in builder.rs:350-422 never yields it). The header describes it as a live representation of `[u8; N] in <text-domain>` (layout_plan.rs:6-9).
- **Type-reference layout uses only target-invariant plan geometry** (type_reference_layouts.rs:46-50), while data-definition layout uses `geometry_for_target` (data_layouts.rs:91-95). A fixed representation whose geometry varies by target would lay out as a definition but fail as a type reference.
- **Self-recursive data is not an error at catalog time.** The recursion diagnostic only fires when the type is reached by value from another concrete type; on its own it is classified proof-only and skipped (builder.rs:86-88; builder/tests.rs:384-403).
- **Parallelism inside a planner.** Calling-policy evaluation spawns OS threads directly with `std::thread::scope` and falls back to the calling thread when a spawn fails (plan_computation.rs:403-455). All activations run even after one fails.
- **Panics instead of diagnostics** in a few places: `expect` in dispatch_tables.rs:36, data_layouts.rs:128, private_callback_closure.rs:107, 148, 150, 156, plan_computation.rs:453 and binding_digests.rs:135, 157.
- **Visit stack is not unwound on error** (builder.rs:299-306; type_reference_layouts.rs:225-229, 234-236). Harmless today because every caller drops the builder on error.
- **`source_free()` returns `Result` but cannot fail** (callback_layout_catalog.rs:98-100).
- **Sorting with a dummy parameter id.** Callback layouts are sorted and de-duplicated by building a `NativeCallbackDemand` with the made-up `NativeParameterId::new(1)` (private_callback_closure.rs:142-162).
- **Requirement refusals apply to every authored target, schema refusals only to the selected one.** In `form`, a prepared requirement error is raised before the target filter (plans.rs:153-156), but a missing service surface only after it (168-176). The header describes only the second behaviour (6-8).
