## What this code is for
This slice is the plumbing and the front door of the old source checker crate (`validation`), not the proof rules themselves. `F` defines the read-only input the checker runs over (`CheckingInput`, `CheckingContext`, `CheckingProjection`, `CheckingQuery`, `LayoutCheckingContext`), a large bag of memo tables (`CheckingMemos`, F1251-1505), and a re-entrancy "cut" mechanism that stops a query from asking itself (F24-553). It also holds shared read-only queries: projecting the typed program down to a Build, a set of source files, or a selection of declarations (F1732-2720); expression/type-tree walkers (F2722-3581); layout-target discovery (F3583-3856); product-declaration lookup by path text (F3857-4097); type-application scopes (F4112-4421); and a lifetime-region matcher over type references (F4422-4967). `L` is a coordinator: a header comment saying what the crate is, a module map, and about 700 lines of `pub use` re-exports naming the public surface (hundreds of functions on calls, contracts, arithmetic domains, custody, cleanup, recasts, ranking). It also contains four real inline modules: `compiler_evaluation` (L193-552, summarises a checked machine for compile-time evaluation), `product_entries` (L554-921, checks that an entry machine fits a root slot and collects root bindings), `native_locators::vocabulary` (L923-1414, pins the exact shape of the compiler-owned `ForeignBinding`/`DllImport` data types), and `value_custody::pattern_components::report_delivery` (L147-190). The crate header says "Successful validation is a source judgment, not a portable proof certificate" (L6-7).

## Mechanisms
- Re-entrancy cut (F321-553, F1638-1654, tests F36-318). `CheckingQuery` wraps an input and records one active query kind (`Numeric{machine,state}`, `OperandFits{machine}`, `CompletedCases{machine}`, `RecastFormation{expression}`). `has_active_*` returns true if the same query is active here or in any enclosing input; constructors return `None` when active, so a caller that would loop asks nothing. Each hit increments `cut_reads`; a query records `met_enclosing_cut` if the hit came from an ancestor. `CutGuard::memos` (F1647-1653) returns the shared memos only if no cut was read (`cut_reads()==0`), else the query-local memos, so answers computed under a cut are not published to the shared tables (test `only_cut_free_answers_under_a_query_reach_the_context`, F244-318). Serves recursion in numeric, operand-fit, case-population and recast reasoning. Limits: recast formation has a depth budget of 64 (F599, F1150).
- Memo layering (F1251-1625, F842-1008). `CheckingMemos` holds about 70 caches (OnceLock for per-program tables, Mutex/RwLock maps for per-key answers). Changing any context input (selections, effect plans, mathematics, layout deferral, borrow custodies, roots, opaque selections) either resets memos or keeps only a hand-listed "typed-tree" subset (`retain_typed_tree_memos` F1521-1550, `clone_typed_tree_memos` F1559-1624, `query_scratch` F1552-1557).
- Static-boolean memo (F695-727): a per-arena-slot byte (0 unknown, 1 none, 2 false, 3 true) in a growable `Vec<u8>`.
- Declaration projection fixpoint (F2135-2283). Starting from `selected_root` symbols, repeatedly projects the root tables, collects references from the selected program, adds each referenced symbol and its ancestors (while `retain_reference`), adds hand-listed child edges and const declarations whose evaluation entry is kept, until the set stops growing. Then prunes sidecar tables by owner (F2351-2446) and filters expression roots. Serves Build projection, source projection, subject projection and selection projection.
- Build descriptor closure (F2073-2112): worklist closure of descriptor symbols plus every conformance, walking up parents.
- Iterative traversals (F3029-3213): dense `Vec<bool>` "entered" set by arena slot; explicit stacks for post-order, pre-order, and collection so depth costs memory not thread stack (comments F3023-3027, F3042-3047, F3190-3192).
- Layout target discovery (F3722-3798): DFS over type references with a `visited` Vec of (reference, root_referent) pairs (linear `contains`), intersecting target-name sets from each target-specific layout.
- Type application scopes (F4112-4421): a stack of scopes, each with a binding list and `starts` markers per nested generic application; `head` chases named formals to actuals through the parent chain; `is_strict_argument` BFS looks for a type identity inside a generic's arguments.
- Region matcher (F4577-4935): structural co-walk of two type references with a set of alternative states (`applications: Vec<State>`); `lifetime_matches` is a caller callback that may prune states; domain constraints produce alternatives by trying every candidate with equal subject, symbol and erased identity. Dedups by `PartialEq`. No budget except cycle detection in `resolve` and `type_structure` via `visited` lists.
- Recursive-component dependency collection (L416-510): for each runtime rank component, checks each call between members has a retained edge by (source state, target state, statement ordinal).
