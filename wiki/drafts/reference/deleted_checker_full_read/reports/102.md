## What this code is for

The slice is the second half of the `ranking_range` module (which starts at ce.rs:24567, before the slice) and five whole modules after it: `refuted_requires`, `result_bounds`, `scoped_arithmetic`, `self_induction` and `shared_proof_walks`.

`ranking_range` (ce.rs:30996-34654) decides whether a machine declared `terminates by <measure>` really descends. It checks that the rank is a member of its range on entry, and that every edge (a recursive call or a transition to another state) arrives with a rank that is still in range and is smaller or not larger. It handles six kinds of measure (`Single`, `Computed`, `SliceLength`, `Field`, `Distance`, `IncreasingTo`, ce.rs:33137-33158), in two styles: from authored expressions (`prove_edge`, ce.rs:33672-34289) and from values "captured" by another walker (`captured_calls`, `captured_entry`, ce.rs:31000-31776).

`refuted_requires` (ce.rs:34655-35869) substitutes a call's arguments into the callee's `requires` facts and gives a three-valued answer (Proven, Refuted, Unknown). It reports an error only when a fact is structurally false.

`result_bounds` (ce.rs:35870-36613) infers an integer interval for a machine's returned value by reading its return statements and guards, and proves `ensures` goals that mention only `result` and literals.

`scoped_arithmetic` (ce.rs:36614-38389) is the public arithmetic interface used by other checkers: it takes expressions with explicit bindings, turns each call inside them into an opaque atom, imports the callee's `ensures` as hypotheses about that atom, and asks the arithmetic `Engine` for a verdict.

`self_induction` (ce.rs:38390-38479) lets a recursive machine assume its own `ensures` for each self-call whose `requires` holds. `shared_proof_walks` (ce.rs:38480-38789) is a memo that proves several call requirements of a proof machine in one batched walk.

## Mechanisms

- **Inductive ranking proof** (`prove_edge`, ce.rs:33672-34289). Builds one strict arithmetic `Engine` per edge. It binds each integer parameter to a named atom, installs carrier bounds, `requires` facts, guards and (at an edge) the rank invariant as hypotheses, normalises the rank to a polynomial, builds a substitution map from entry atoms to argument polynomials, applies it to rank and range, then asks `prove_at_least` for membership, pinning and the difference. Serves `terminates by`. No explicit budget here beyond the engine's own.
- **Captured-prefix visitor** (`CallProgress`, ce.rs:31024-31355). A `StructuralPrefixVisitor` that `recognize_structural_state_prefix` calls once per executed path reaching the call; it ANDs strictness across paths and stops at the first failure. Serves termination of calls whose arguments are not simple authored expressions.
- **Measure read-shape discovery** (`reads::scope`, ce.rs:31820-31958). A worklist over the measure body with a visited list; on a call it recurses into the callee's `requires`/`ensures` expressions, with an `active` stack of owners to refuse recursion. Produces the list of scalar coordinates a measure reads from a record input.
- **Selector evaluation** (`selector_value_at`, ce.rs:31991-32066). Recursive with depth limit 64 and a cycle list.
- **Guard decomposition** (`collect_guard`, ce.rs:34572-34653). Recursive, depth 128; returns whether the whole guard was visible.
- **Three-valued structural judgment with memo** (`remembered_instantiated_fact_judgment`, ce.rs:35004-35035). Memo keyed by fact expression handle per query.
- **Replayability analysis** (`target_result_is_unreplayable`, ce.rs:35578-35646). Recursive over callee bodies with a `seen` stack; a callee is replayable only if its entry state has one unguarded value transition and no call statements or `match`.
- **Interval analysis of returns** (`result_bounds::infer`, ce.rs:35885-36024). Hull join over all value exits; guard refinement against literals; all recursion capped at depth 128 (ce.rs:36143, 36195, 36276, 36388, 36436, 36482).
- **Scoped call transport** (`ScopedCalls`, ce.rs:37084-37719). Step budget 4096 (ce.rs:37109), depth 64 (ce.rs:36655, 37180, 37678). Post-order walk of each expression; memo lists `scopes` and `lengths` compared by structural equality.
- **Syntactic hypothesis matching** (`predicates::matches_asserted`, ce.rs:37822-37882). Normalises goal and each hypothesis to a tree of `Comparison(operator, left − right)` and compares for equality; depth 64.
- **Shared proof walk memo** (ce.rs:38558-38609). One walk per machine, stored in checking memos; a `(machine, thread id)` marker stops re-entry while building.

## Accepts or skips without proof

1. **Unsatisfiable requires makes everything true.** `engine.requires_unsatisfiable` returns membership true (ce.rs:31719-31724, 34075), returns an edge as strictly decreasing and non-increasing (ce.rs:34228-34236), skips equality of duplicate substitutions (ce.rs:34153, 34182), skips entry-invariant preservation (ce.rs:34222) and deferred endpoint landing (ce.rs:34307), and makes implication and relation Proven (ce.rs:38155-38157, 38307). The flag is set inside the engine; this slice does not show how. Cannot tell whether another check confirms the contradiction.
2. **Contradictory hypotheses in the structural judge**: a negated fact is `Proven` outright (ce.rs:35068-35070). But `instantiated_value_call_requires_proven` returns `false` in the same situation (ce.rs:34840-34842) and `reject_refuted_value_call_requires` returns without reporting (ce.rs:34720-34722). The two families treat contradiction in opposite ways.
3. **`Distance` with no range is a member on entry without proof**: `unranged_distance` overrides the proof result (ce.rs:33490-33504); in the captured entry both `Distance` and `IncreasingTo` are members without any inequality (ce.rs:31732-31736). At an edge, `Distance` must still prove rank ≥ 0 at source and arrival (ce.rs:34059-34063, 34268), so an edge check would catch a negative distance; for a machine with no edges I cannot tell.
4. **`IncreasingTo` is "clamped"**: membership is true without proof at source and arrival (ce.rs:34059, 34268, 34276). Strict descent then needs rank ≥ 1 and difference ≥ 1 (ce.rs:34281). The comment at ce.rs:33161-33169 says a later stage emits the rank as `MAX - lower`; cannot tell from this slice that the clamp matches it.
5. **`measure_constraints_cover_subject` always answers true** in practice: `integer_carrier` always returns an empty constraint list (ce.rs:32534), and an empty list returns `true` (ce.rs:32440-32442). The identity view is accepted on the type check alone (ce.rs:32255-32256).
6. **`RankValue::formation` installs `value == formed.value` as a hypothesis** instead of proving it (ce.rs:32660-32668). Both sides come from the same measure and input, so they are probably the same polynomial; cannot tell.
7. **Refuted-requires exemptions** (no error is reported): arguments cannot be mapped (ce.rs:34709-34717); requirement is the literal `false` and the caller state has any case-membership guard anywhere (ce.rs:34743-34747); the call is a terminal transfer, the requirement reads a field, the state name lacks "const", and no argument contains a call (ce.rs:34748-34757); the requirement compares two closed literals and so does the authored clause (ce.rs:34758-34767). This function only reports refutations; `instantiated_value_call_requires_proven` (ce.rs:34794) is the positive check, and I cannot tell from this slice that every call goes through it.
8. **`authored_clause_is_closed_literal_equation` defaults to `true`** on three failed lookups (ce.rs:35688-35700, and `is_none_or` at 35703), which keeps exemption 7d alive.
9. **A Proven verdict over an uncertified call projection stands; only Refuted is withheld** (ce.rs:35147-35153, 35278-35284, 35321-35325). "Uncertified" means a projection out of an application whose target has no abstract value-call signature (ce.rs:35328-35345). The test at ce.rs:35837-35867 pins this asymmetry. Cannot tell what else certifies the Proven case.
10. **Refuted is downgraded to Unknown** for float equalities and unreplayable applications under literal replay (ce.rs:35144-35151, 35216-35234). This withholds an error, it does not accept a proof.
11. **`collect_instantiated_predicates` drops** case observations and any conjunct that has no structural predicate (ce.rs:35514-35540). Dropping hypotheses weakens; no acceptance.
12. **`collect_guard` returns `Some(false)` for unrecognised parts** (ce.rs:34583-34585, 34598, 34639, 34649); `prove_edge` and `contract_comparisons` ignore that boolean (ce.rs:33944, 34033, 34373). Hypotheses are lost, not invented.
13. **`captured_integer_engine` continues** when an expression has no canonical place or no observed value (ce.rs:33003-33008). The later `constant_value()?` would fail for an unbound value (ce.rs:32971, 32985).
14. **`prove_edge` skips a demanded entry coordinate with no integer binding** (`continue`, ce.rs:34163-34168) and any target reading not demanded or with a non-empty entry path (ce.rs:34134-34137). No substitution is recorded for it. `required_symbols` (ce.rs:33855-33868) checks the required ones are bound; whether `apply_argument_map` fails or leaves an unsubstituted atom unchanged is outside this slice. Cannot tell.

## Surprises

1. **A substring of a state name changes the verdict.** `caller_state.name.as_str().contains("const")` (ce.rs:34748) decides whether a refuted field-reading requirement on a terminal transfer is reported. A user state named, say, `reconstruct` would be treated as "const evaluation".
2. **No proof kernel anywhere in the range.** The identifiers `proof_admission`, `ProofNode`, `verify_obligation`, "certificate" and "kernel" do not occur in lines 30996-38789. Every verdict is a `bool`, an `Option`, or a three-valued enum computed by `Engine` or `StructuralJudge` methods. The nearest thing to evidence is `IntegerApplicationFormation`, which `RankingRangeEdgeProof`, `RankingRangeEntryProof` and the formation functions return to the caller (ce.rs:33287-33299, 37739-37742); whether anything re-checks it is outside the slice.
3. **Dead constraint check.** `integer_carrier` builds `let constraints = Vec::new();` and never fills it (ce.rs:32534), so `MeasureBodyShape::ParameterForward.constraints` is always empty and `measure_constraints_cover_subject` (ce.rs:32434-32470), 35 lines of interval logic, never runs past its first line when reached from `declared_scalar_view`.
4. **Read shapes through calls are computed and then refused.** `reads::scope` goes to some length to follow calls and record `calls` and selector context on each read (ce.rs:31861-31949); `RecordRank::resolve` then refuses any read with a non-empty `calls` (ce.rs:32729-32731). Only the captured path (ce.rs:31311-31321, 31464-31479) uses such reads, and it does not look at `calls`.
5. **Read discovery follows contracts, not bodies.** On a call inside a measure body, `scope` walks the callee's `requires` and `ensures` expressions (ce.rs:31922-31949), not its body. The set of scalars a record rank "reads" is whatever the callee's public contract mentions.
6. **Opposite treatment of contradiction** between the structural and arithmetic paths (see "Accepts or skips", items 1 and 2).
7. **Atom names without the `\0` guard.** Most atoms start with `\0`, which no source identifier can contain. Two do not: `"ordinary-return"` (ce.rs:36041) and `"state:...:call-result:...:field:..."` (ce.rs:36962-36965). Whether user-derived atom names share that namespace is outside the slice.
8. **`unsigned_integer_atom` is used for every integer parameter**, with the primitive passed alongside (ce.rs:32934, 33848, 34516). `result_bounds::proves` binds the result atom with `unsigned: false` regardless of carrier (ce.rs:36044-36047). Cannot tell from here whether the name misleads or signed parameters are treated as unsigned.
9. **Leftovers.** `let _ = literal_replay;` inside a closure that otherwise ignores it (ce.rs:35372). `engine.install_scoped_expression(&goal)` is called twice in one function (ce.rs:38149 and 38158). A debug print to stderr sits in a formation function behind `struct_trace()` (ce.rs:37800-37805). `required_expressions` pushes a conjunction and then each of its conjuncts, so a requirement `a and b` yields three entries: the conjunction, `a` and `b` (ce.rs:38774-38784).
10. **Memory addresses as identity** in the shared-walk memo (ce.rs:38613-38615, 38628, 38634) and pointer equality on the program and machine (ce.rs:34687, 38572). A memo hit depends on the machine and state rows not having moved.
11. **Thread-aware checking.** The shared-walk code assumes a parallel checker and keys an in-progress marker by `std::thread::ThreadId`; it recovers from poisoned mutexes with `into_inner` (ce.rs:38525-38556, 38579-38606).
12. **The refuted-requires check is diagnostic-only and heavily exempted.** It was built to say "this call is certainly wrong" with the authored spelling and the instantiated spelling (ce.rs:34768-34790), and five separate conditions suppress it. It reads as error-message machinery layered on a judge, not as the rule itself.
13. **`self_induction` has no visible tie to termination** (item 20 above). The module is 90 lines and hands the judge the machine's whole `ensures` for each recursive application.
14. **`result_bounds` is a small, separate abstract interpreter** over statements with its own notions of "stable", "fence" and "capture" (ce.rs:36100-36580). It duplicates guard decomposition and carrier-bound code from `ranking_range` and decides place types by its own walk (ce.rs:36476-36579) instead of asking the type queries used elsewhere in the slice.
15. **One user-facing diagnostic in 7,794 lines** (ce.rs:34787-34790). The 40 distinct `&'static str` reasons in `captured_calls` describe internal bookkeeping ("lost its exact", "telescope", "authenticated projection") and are returned to a caller outside the slice.
