## What this code is for

This is the first half of the old checker's "exit checks": what must be proved when a machine returns normally. The slice holds four helper modules that the (out-of-slice) `check_exit_ensures` and `contracts::check_flow_call_contracts` call. `bindings` proves an `ensures` clause against the declaration that authored it, including clauses inherited from a trait requirement (exits.rs:42-189). `cases` decides, from the shape of the returned expression or from live flow facts, which variant a returned value is (exits.rs:190-555). `cyclic_headers` is an invariant-inference engine for machines whose states form loops: it proposes each exit's `ensures` as a loop invariant over the state's immutable fixed-width integer parameters, proves it by induction over the strongly connected components of the state graph, and also follows chains of tail calls to prove a guarantee from every value the chain can finally return (exits.rs:556-3030). `result_domains` enforces that a returned value is a member of the domains its return type declares: for scalar results, for fields of a returned record, for tail transfers between states, and for the fields behind every `&mut` or write-only reference the machine received (exits.rs:3031-5188). Every decision is a boolean produced by this code or by a helper in `validation`, `crate::flow`, `crate::values` or `prover`; nothing in the slice builds or checks a proof object. The slice contains no tests.

## Mechanisms

**Header-invariant induction over the state graph** (exits.rs:1749-2003, 2294-3001). For one machine it builds a `Header` per state, lists every named transition into each state (`arrivals`, 2488-2561), builds a caller-to-destination adjacency, and calls `crate::checks::termination::strongly_connected_components` (1811). Each exit's admitted `ensures`, with `result` replaced by the returned term, becomes a candidate predicate for that state (2434-2478, 2783-2802). `discover` (1854-1928) pushes each predicate backwards along incoming edges by substituting the edge's arguments for the destination's parameters; a path never revisits a state, so cycles are not unrolled. Components are then processed in reverse of the order the SCC routine returned (1827); `proves_component` (1930-2002) proves every demand of every member state at every arrival and, for the entry state, at invocation from `requires`. Only when the whole component proves are its candidates' exits admitted (1828-1833). Budget: `TRANSPORT_WORK = 16_384` units per discovery pass and per component (2020, 1859, 1937); substitution depth 64 (2021). When discovery runs out of budget it returns silently with the demands found so far (1863-1865, 1876-1878, 1884-1886, 1903-1905, 1916-1918); when `proves_component` runs out it returns false (1956-1958). Serves `ensures` on machines with looping states.

**Scoped substitution** (exits.rs:2004-2153). `demands::substitute` replaces a state's "current" atoms inside a nested `ScopedArithmeticExpression`/`ScopedArithmeticValue` tree with replacement values, charging one unit per node and never substituting inside a replacement (2094-2100 passes `&[]`).

**Completion closure over tail calls** (exits.rs:1266-1617). A worklist of `(machine, state, referent subject places, scalar associations)` starts with every state of the owner machine (1296-1310). For each outgoing edge it either follows a named state transition, follows a tail call into the callee's entry state, accepts an exit already admitted by the header-invariant pass (1563-1584), or proves the exit as a leaf. A `HashSet` of visited tuples stops revisits (1311, 1328-1335), so a recursive tail call is treated coinductively; `observed_return` (1312, 1616) makes a closure with no value producer fail. Shares the 16,384 budget (1289). Results are cached per machine and per contract in `MachineHeaderInvariants.completions` (2166-2170, 2221-2236).

**Two subject kinds carried through the closure.** `ScalarGoal` (exits.rs:989-1252) tracks which current parameter equals each invocation formal named in the guarantee, re-established at each call by an arithmetic equality proof. `ReferentGoal` (exits.rs:675-968) tracks which storage place each exclusive-reference field of the guarantee currently denotes, using the call's reference correspondence and prefix stripping (887-907).

**Frame freshening** (exits.rs:1083-1154). Because a recursive invocation reuses the same parameter symbols, the code renames the callee frame's invocation atoms to `completion:{machine}:{state}` atoms before substituting the original subjects back in.

**Hypothesis extraction** (exits.rs:2596-2639). Splits a true builtin `and` into conjuncts, folds `cmp == true/false` into polarity, and keeps only conjuncts inside the arithmetic fragment; other conjuncts are dropped as premises.

**Three-valued scalar domain judgment** (exits.rs:3092-3463). `Proven`/`Refuted`/`Unknown` joined across a domain's facts, with `Refuted` dominant and an early stop. Per predicate the order is: float predicate route, concrete evaluation with the known returned value, arithmetic implication from live `requires`/guard/boolean facts and live memberships of other places, then `completed_value_proves_domain_predicate`. A visited list of `(domain symbol, semantic id)` stops cyclic parent chains (3142-3152).

**Structural case observation** (exits.rs:351-501). One recursion over `match`, record literal, array literal and place, with a projection path and an expression-depth guard (`expression_at_depth`, 360-367).

**Cast stripping with bounded loops**: up to 128 exact casts (3552), up to 8 for literals (4294); binding collection depth 128 (3673); predicate meaning depth 128 (5082).

## Surprises

1. **The old checker inferred loop invariants.** `cyclic_headers` (about 2,470 lines, exits.rs:556-3030) is a bounded invariant-inference and induction engine: candidates from `ensures`, backward demand propagation, SCC-ordered induction, plus a cross-machine closure over tail calls. It runs for every machine, not only cyclic ones: a single-state machine is a singleton component whose demand is proved "at invocation" from `requires` (1984-1999). So this is also a general arithmetic exit prover for scalar `ensures`.

2. **Inconsistent handling of ambiguous origin rows.** `caller_atoms` equates a parameter with an invocation value from the first matching row (2732-2755); `ScalarGoal::new` requires all rows to agree (1057-1065); `ReferentGoal::new` refuses on a second row (810-815). The comment at 2698-2703 promises the stricter behaviour.

3. **An unreadable arrival can be skipped instead of refusing.** `arrivals` uses `continue` when `find_call_site` returns `None` (2494-2502), while the comment says an arrival that cannot be read must block admission (2480-2484).

4. **A comment and the code disagree about labels.** The comment at 3470-3476 says a predicate instance is "not decoded from an identity label", but each index value is obtained by decoding or parsing the type-reference name string (3508-3523). The instance identity is rechecked by name lookup (3491-3496), so both identity and value pass through text.

5. **Two differently built Debug strings must coincide for a proof to succeed.** The `return-place:{subject:?}` atom is built from a semantic place at 3280 and from `place_at` at 3718. If the two canonical places render differently for the same storage, the hypothesis silently fails to apply. This loses proofs rather than accepting wrong ones.

6. **Const-leaf domain checks ride on this exit check through synthetic machines.** The only way to explain the `@const-qualification-` prefix test (4093-4094) is that another stage builds machines with that name so that a const value's domain is checked as a scalar return. The name prefix then selects the user-facing message.

7. **Field obligations read only the entry state's return type; scalar obligations read the entry's and the current state's.** `check_result_field_domains` uses `entry.return_type` everywhere (4418-4423, 4451, 4541, 4592, 4651), while `scalar_exit_domains` unions the exit state's and the entry's (4125-4131) with the comment "Both the machine's external result and the current state's result are obligations" (4115-4118). A state whose own nominal return type promises more than the entry's is not checked for fields here.

8. **Production code carries stderr debug tracing.** Thirteen lines of `eprintln!("STRUCT terminal-referent …")` guarded by `validation::trace_flags::struct_trace()` sit inside the proof path (691-703, 716-721, 777-782, 789-795, 831-836, 842-847, 872-877, 946-951, 960-965).

9. **The completion closure starts from every state of the owner, not from the entry** (1296-1310). An unreachable state with no outgoing edge (1612-1614) or an unprovable exit makes the whole guarantee fail.

10. **With neither goal kind available the closure can only succeed through admitted exits.** If `ScalarGoal::new` and `ReferentGoal::new` both return `None`, a leaf exit yields `proven = false` (1585-1608). `ScalarGoal::new` returns `None` when the guarantee names any parameter that is not an immutable fixed-integer formal (1025).
