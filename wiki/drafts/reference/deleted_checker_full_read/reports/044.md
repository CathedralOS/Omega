## What this code is for

`progress.rs` decides whether a machine's published `terminates` promise survives the calls its body makes. Local state cycles are ranked elsewhere; this file handles the other half: every call to another machine, operator, requirement or cleanup target must itself terminate. A callee may terminate only on a condition, called a progress premise: "argument field X is a member of progress-profile domain P" (`ProgressPremise { profile, subject }`, where a subject is a parameter symbol plus a list of field symbols). The file derives, per machine, a `CheckedProgressSummary` (no guarantee, or terminates under a set of premises), by a fixed point over the call graph, and then refuses a machine whose derived premises are not all listed in its published contract (`progress.rs:4516-4597`).

Most of the file (about 2,300 lines, `progress.rs:2020-4356`) answers one question: "which entry parameter field did the value passed at this call argument come from?" It traces a call argument backward through locals, constructor literals, results of other checked calls, stored captures, shared and exclusive reference bindings, and state-to-state transitions, and gives up (no guarantee) whenever any step is not exact.

`execution.rs` is not a checker in the same sense. After checking has finished, it builds the plans that the Terminal Psi producer consumes: it erases fact-only theorem citations, attaches content-consumption parents to structural values, builds cleanup plans for state exits, collects the storage shapes that scalar computations construct, classifies each machine's signature, and turns each state's tail of transitions into a terminator or an ordered list of guarded exits. It does make judgments that affect acceptance: whether a list of `when` guards without a fallback is exhaustive (`execution.rs:2427-2596`), whether two guards are exact complements (`execution.rs:426-438`), and whether a state's cleanup can be done with no code (`execution.rs:625-1037`). Two of its submodules (`scalar_computations`, `terminal_unit`) live in other files and are only declared here (`execution.rs:496-497`, `2876-2877`).

## Mechanisms

- **Per-call-component fixed point of termination summaries** (`progress.rs:248-500`). `derive_summaries` builds a "reads" graph (each machine reads the summaries of its call targets, family members, requirement satisfiers and cleanup targets), hands it to `shared::machine_waves::MachineCallComponents`, and runs components callees first. Inside a component, machines outside any ranked recursion start at "no guarantee" and are re-derived until nothing changes; a member is frozen (`constant`) once it reaches "terminates with no premises". The loops at 461-499 have no iteration budget. Serves `terminates` contracts across calls.
- **Joint derivation of a ranked recursive component** (`progress.rs:506-575`). Each member starts from its local ranking promise (the optimistic value), all members are re-derived from the previous round until stable. The only bound is structural: a premise whose field path exceeds `finite_projection_limit` makes the member permanently "unavailable". The header comment calls this "A structural bound on finite premise transport, not an iteration budget" (36). Ranked components are forced into one call component by adding a ring of artificial reads (355-358).
- **Parameter lineage across state transitions** (`progress.rs:686-1111`). A demand-driven worklist finds which parameter subjects feed the demanded one through local transitions (`transfers::collect`), then closes a three-value lattice (Unseen, Exact set, Ambiguous) to a fixed point. `grows_on_cycle` (879-912) detects a transfer whose source is a strictly deeper projection of a parameter that the destination flows back into, and forces Ambiguous so that paths cannot grow forever. No budget; termination relies on the lattice being finite.
- **Backward value-origin tracing** (`progress.rs:2020-4356`). `at_place` first asks the captured-operand graph (`captured_values::at_call`), else falls back to `direct_at_place`, which calls `flow::value_origin_at_call_resolving` with two callbacks: one resolves a call result to a caller place by replaying the callee's returned expression (`call_result_place`, depth 16), one rebases a place across reference boundaries (`reference_boundary_before_statement`, 16 hops). Serves progress premises; the same transport is reused for profile preconditions at calls (4446-4500).
- **Capture-graph walk with ancestry** (`progress.rs:3038-3205`). A worklist of (capture, projection, ancestry) follows reference captures, retention-profile suppliers and completed-value predecessors; a repeated capture on one ancestry path fails; all leaves are joined.
- **Selector expansion** (`progress.rs:1738-1779`, again at 3062-3081). Each runtime-index segment is replaced by every fixed index of the fixed array it selects in. There is no size budget; a test pins 65,536 alternatives.
- **Finite guard coverage by enumeration** (`execution.rs:1983-2424`). Each guard becomes a row of columns (subject, admitted values); subjects are case-typed paths, computed case subjects, or Boolean operands. `tuple_rows_cover` enumerates the Cartesian product of the subjects' domains (limit 4,096) and requires some row without residual to admit each tuple. `computation_row` rebuilds the same rows from retained scalar computations, reading `Select(c, t, false)` as "and" and `Select(c, true, f)` as "or", with a cycle guard.
- **Exact complement of two guards** (`execution.rs:426-494`). Delegated to `checked_trees::values::guard_complement::exact_complement`; this file only locates the two guard rows and supplies the declared cases.
- **Shape collection worklist** (`execution.rs:1443-1857`). Walks structural value dependencies and scalar computation nodes of a state, collecting type plans and rejecting two different plans for one identity.

## Surprises

- **Termination is conditional on domain membership.** A machine's `terminates` contract can carry premises of the form "this parameter field is in progress-profile domain P", and about half this slice exists to carry such premises from a callee's parameter back to the caller's entry parameter. This is a larger feature than "terminates by a measure" suggests, and it is where almost all the origin-tracing code is spent.
- **Property 2 (identity by text) mostly does not hold here.** Subjects are symbol handles plus field-symbol lists; places are typed segments. The file repeatedly refuses "a matching spelling" as evidence (2201-2202, 4229-4235). The cost shows up as property 3 instead: exact structural identity is re-derived by a separate walker for each place a value can come from.
- **The tracer is a second value-flow analysis layered on the first.** It calls into `flow::` for the single-origin backward trace, then adds its own handling for the cases that trace cannot express (multi-route call results, shared-reference leaves, exclusive-reference roots, entry-frozen references, captured copies). Each addition has its own scan over statements. The comment at 2058-2060 states the underlying limit: the shared trace returns one place.
- **The fixed-point loops have no round limit** (`progress.rs:461-499`, `540-574`, `993-1009`). The joint derivation at 540-574 starts high and can only be stopped by stability or by the projection-length bound. I could not confirm from this file alone that premise sets cannot alternate between rounds; the only forcing mechanism toward a stop is `unavailable`.
- **The depth 16 is a literal in six call sites** (2088, 2129, 2156, 3230, 3247, 4321) plus the constant `REFERENCE_BOUNDARY_HOPS = 16` (3808) whose comment says it "matches the call-result recursion depth". Nothing ties them together in code.
- **Selector expansion has no budget and a test pins 65,536 alternatives.** In `derive_machine_summary` each alternative then runs the full origin trace and lineage derivation (1194-1211), and `lineage::resolve` rebuilds the whole `StateParameterLineage` for every premise (1034-1051) with no caching.
- **`callee_demanded_origin` builds a `FlowStateFact` with only two fields set** (`progress.rs:2699-2703`) and passes `None` for the flow view (2725), so the trace inside a callee runs without the callee's real flow facts.
- **An orphaned doc comment**: the long comment at `progress.rs:3861-3877` describes `exclusive_reference_root_place` but sits above `statement_writes_miss_slot`; the function it describes starts at 3908 with no comment.
- **Non-exhaustive guards are not diagnosed here.** `tail` decides exhaustiveness of a state's `when` arms and returns `None` when it cannot show it. This is an acceptance-relevant judgment made in a plan builder under `execution`, not in a check, and it re-reads the source guard expression (`exact_outcome_case_test(program, guard)`, `execution.rs:2516-2517`) to get the case while taking the subject from the checked expression row.
- **The early `Some(())` in `projected_read_retains_parent`** (`execution.rs:827-831`) accepts any path containing a field segment with an invalid symbol before the multiplicity, contents, nominal-drop and case tests. It reads like a workaround for a synthetic segment; no comment explains it.
- **Cleanup eligibility is computed twice and compared** (`execution.rs:980-1035`): once from parameter types and events, once from the ownership ledger's exit roots; inequality drops the plan. The code distrusts its own inputs enough to cross-check them, but reports nothing when they disagree.
- **A determinism bug is recorded in a comment** (`execution.rs:381-387`): type identity numbers depend on thread races, so plan order differed between runs; the fix sorts by identity text.
- **`family_summary` checks each member's derived summary only for "promises termination"** (`progress.rs:1269-1272`) and then uses the member's published premises (1278-1285), not its derived ones. For checked-body members the publication is checked separately at 4580-4589; for other members it is not.
- **`derive_call_component` skips re-deriving a ranked component when nothing outside it changed and there is only one** (`progress.rs:483-485`); with two or more ranked components in one call component every one is re-derived every round.
- **`terminal_cleanup` describes itself as serving "the older structural-control consumers"** (`execution.rs:575-576`) and warns against rebuilding a table that "has no executable consumer": part of this module was already a retained legacy path when it was deleted.
