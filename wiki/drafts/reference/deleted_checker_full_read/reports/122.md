## What this code is for
This file (`value_custody::places`, header 1-4) is the old checker's answer to "which storage place does this expression name, what type does it have, and do two places overlap?". It turns an expression into a `CanonicalPlace` (a root plus a list of `PlaceSegment`s: field, case, fixed index, fixed range, dynamic index; 5457-5535, 5969-6057). It resolves the type at each step of a place path, with generic substitutions (8288-8716). It decides whether two paths are disjoint, equal, prefix, extends or may-overlap (587-618). It folds fixed collection windows into absolute element indexes (5616-5664). It also decides whether an index, range or `len` read has its built-in meaning, meaning no user operator overrides it (1763-2492). A smaller part scans a state's statements to see whether a binding is written or exclusively borrowed (5-395). A further part checks assignment targets and emits four diagnostics (1101-1176). Another part builds "structural scalar fields", the coordinates that facts and contracts about scalar fields attach to (2557-3975). The file mixes place geometry, type projection, name-based resolution and several memoised syntax queries. Almost every function returns `Option` and answers `None` when it cannot decide.

## Mechanisms
- Place-relation lattice (587-710): compares two segment lists pairwise. Static pairs use symbol/index equality. Range-vs-range uses interval overlap (682-686). Range-vs-index uses containment (712-714). Index-vs-index is conservative (728-752). Result is one of five `PlaceRelation` values. Serves fact, loan and obligation keep-or-kill decisions (comment 560-568 cites `wiki/drafts/designs/fact_transport.md`). One unit test (769-793).
- Window folding (5616-5664): a small state machine over `[Window | Segment]` with checked arithmetic. Exact or absent. Serves subslice element places.
- Constant-index evaluation (5704-5941): recursive (depth cap 64) attempt to turn an index expression into a number by seven methods in sequence. Serves array and slice element identity. It consults other analyses (standing bounds, return bounds).
- Type projection cursor (8414-8484, 8543-8684): carries a list of (type-parameter, argument) substitutions while walking field/index segments through generic data. Serves typing of place paths. Bounded by `substitutions.len()+1` iterations (8660).
- Observation cursor (7883-8048): same walk over checked structural segments with identity comparison by `member_identity()`, returning `&'static str` failure reasons. Serves storage observations and qualification paths.
- Type comparison under substitutions (4867-4987): structural recursion over Reference/Slice/FixedArray/Generic, falling back to type identity ids. Cycle check at 5009.
- Binding-write scan (125-196): linear scan of every statement and every expression node of a state, repeated for each queried binding. Visit cap 128 for chain walks (94, 220).
- Memoised syntax queries (6270-6463): `states_naming`, `literal_arm_bindings` memoised per expression handle in `OnceLock` rows (binary-searched by arena index and generation), plus `state_matches` per state. Bypassed when `checking_memos()` is none.
- Array extent resolution (1455-1645): resolves extents through enclosing generic application scopes (`with_enclosing_data_identity_scopes`), const declarations or parameters; returns Closed(BigInt) or Bound.
- Saved-dispatch matching (3601-3688): parallel traversal of two structurally equal expression trees with a visited set, to find which saved subject a call occurrence belongs to.

## Surprises
- Name-resolution helpers disagree on shadowing: `nearest_scoped_local` lets a later local override an earlier one and a local override a parameter (5327-5344, last match wins), while `state_scoped_name_symbol` returns the parameter first, then the FIRST local (5417-5435, `find_map`). `local_or_parameter_type` (4153-4178) takes the first local, then parameter. All three map a name to a symbol or type for the same state.
- `bound_symbol_declared_type` (1404-1434) and `whole_program_member_type_position` (6970-7027) scan every machine, state and statement of the whole program per query. `symbol_type_position` reaches the global scan for any Parameter/Local/Field whose container lookup said "Unmapped" (6949-6967).
- `container_member_type_position` has three outcomes (Position, MappedMiss, Unmapped): a MappedMiss returns `None` at once; Unmapped falls through to the global scan (6949-6953). The distinction is not documented.
- `closed_generic_member_symbol` returns `Some(invalid)` on a miss (6747), and `effective_member_symbol_from_position` returns that directly (7281-7289) instead of reaching the later by-name fallbacks (7328-7336). Closed-generic receivers never fall back to by-name matching.
- `carriers_match` compares by NAME when a symbol is invalid (6150-6155), so two unrelated unresolved types with the same name match. `cast_shares_storage` relies on it (6109).
- Place identity depends on numeric analysis: `exact_fixed_element` calls `normal_return_integer_bounds` and `standing_integer_bounds` (5727, 5736-5744, 5779-5780). The same call is treated differently depending on how it is written: a bare call inside an index makes the segment dynamic `Index` (5682-5697), but a local bound to that call whose return bounds are a single value folds to `FixedIndex` (5730-5744).
- A `Const` name yields an `Expression(handle)` root (5997-6003, 6204-6215), so two reads of the same const are different roots and compare Disjoint (592-594).
- `PlaceRelation::Disjoint` for different roots is unconditional (592-594): roots that alias through references are not related here. Handling aliasing is left to callers; cannot tell from this file.
- `canonical_place_segments_equal` treats two Index segments as equal when `expressions_structurally_equal` (537-538), even though dynamic index values may differ between evaluations. `qualification_storage_path` is stricter and requires a "statically captured index" (7799). Whether callers guard the looser rule cannot be told here.
- `declared_place_type_raw` is a long cascade (1268-1387) whose order matters: a one-member name resolves through unique local/parameter matching (1305-1335), but a name matching two locals (shadowing) yields no type there and falls through to later branches, which may match by name via the string path (1376-1378).
