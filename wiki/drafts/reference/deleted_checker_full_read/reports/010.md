## What this code is for

This slice is the build-time layout half of the `build-time-evaluation` crate plus the crate root. It is not a fact or ownership checker. `layouts.rs` takes an authored *policy machine* (a machine named `Policy::plan`), feeds it a reflected description of a record (`Schema`), runs it at compile time, and then validates the value it returns as a byte/bit layout plan (`FixedLayout`), an access plan (`Access<Policy, Schema>` views with per-field read/write/atomic permissions), or a lifecycle plan (initialize / move-out / view / relocate of resident storage) (layouts.rs:1-9). For access views it also rewrites the syntax tree: every `Access<P, S>` type is replaced by a generated record whose fields are generated accessor types, and accessor machines are cloned from a toolchain template (layouts.rs:2341-2529, 3474-3696). After typing it recomputes each plan on the typed program, requires the same plan identity, and installs the plan and geometry into `TypedTrees` (layouts.rs:3737-3828, 5397-5669). `schema_reflection` computes sizes, alignments, bit widths and hashed field keys for a record under optional target facts (layouts.rs:6213-6937). `lib.rs` orders the pre-resolution passes (constants, generic arguments, trait defaults, access views, generic data), holds the `EvaluationDomain` that says which declarations a pre-check continuation covers, defers or runs the typed pre-check, and re-exports the crate's public surface (lib.rs:204-261, 618-661, 916-980). By the time of deletion the engine that ran policy machines had been removed: the crate header says layout and access policy plans "run a machine before the program is checked; no engine serves them, so they are refused" (lib.rs:9-12), so most of the validation after the evaluation call could not be reached in the shipped compiler (see Surprises).

## Mechanisms

- **Tracing a type operand to the calls that supply it** (layouts.rs:336-400). `policy_sources` reads the operand's origin. A lexical operand contributes the current call's source. A machine-parameter operand makes it scan every call to that machine, read the unique binding of that parameter, and recurse on the bound type. A `visiting` stack stops cycles (a cycle returns `Ok` and contributes nothing, 352-354). No budget. Serves access lifecycle admission: each supplying source is admitted separately (865-873).
- **Worklist over nested records** (layouts.rs:981-1022; helper lib.rs:901-914). Visits a schema and every record reachable through named types and fixed arrays, with a linear `visited` vector. Serves the View rules.
- **Layout plan validation as interval arithmetic** (layouts.rs:4461-4749). Two passes over at most 64 entries. It counts `At` entries per field, converts every placement to a destination bit interval, sorts intervals by start and checks neighbours for overlap (4723-4732), sorts each field's source fragments and requires them to tile `0..source_bits` (4699-4717), and checks constant stride for repeated arrays (4682-4697). All arithmetic is `checked_*`.
- **Target propagation and ordering of layout applications** (layouts.rs:5309-5375). A worklist copies each request's targets and owners to the applications its fields depend on until nothing changes; then a loop that picks any request none of whose dependencies is still pending produces a dependency order and reports a cycle when none is ready. Dependencies come from another worklist with a dense `seen` vector indexed by type identity (5705-5753).
- **Reflected natural layout** (layouts.rs:6727-6928). Recursive size/alignment computation: primitives from a table, references as `pointer_size × descriptor words`, arrays as element × count, records by aligning each field up and padding the end, sums through `conventional_sum_geometry` with the target's tag size, nested layout applications through their installed geometry. A `visiting` stack of type identities refuses recursion.
- **Minimal bit width from ranges** (layouts.rs:6667-6705). Intersects the primitive's range, the type's scalar representation range, and an interval read from the record's `requires` clauses (`validation::data_requires_field_intervals`, 6576) and returns the number of bits needed for the maximum; a negative minimum gives the full width. `Bits` placements must tile exactly this many bits (4712).
- **Hashed field keys** (layouts.rs:6525-6531). A policy refers to a field by FNV-1a of `"<schema name>::<field name>"`; collisions inside one schema are refused.
- **Probe, then recompute and compare** (layouts.rs:3592-3668, 3737-3828). To learn which accessors to generate before the program is typed, `desugar_access_views` clones the syntax, adds placeholder view records, runs generic normalization, name resolution and typing on the clone, evaluates array lengths, domain facts and layouts there, and computes each access plan. After the real program is typed it computes each plan again and requires equal `identity()`.
- **Which generic types depend on a type parameter** (layouts.rs:2777-3387). A hand-written walk over every item, statement and expression kind collects `Generic` type references any of whose arguments names a binder in scope; those are skipped by discovery (3951). Binders are a stack of names.
- **Dense call-target lookup** (layouts.rs:1892-1939). A vector indexed by symbol arena index maps machine and state symbols to a machine position, with a linear search when the slot holds a different symbol.
- **Declaration selections** (lib.rs:73-188, 516-598). `EvaluationDomain` carries a `work` and an `execution` selection; `project`, `activate_sources` and `exclude_completed_work` intersect or subtract them against another program's declarations.
- **Run or defer** (lib.rs:618-661). The pre-check runs array lengths first; if range endpoints, memberships, const applications or target observations still need an operator selection, it records deferred work and returns itself; otherwise it evaluates everything.
- **Fixed capacities**: 32 access fields (layouts.rs:1149), 32 boundary services (1150), 64 plan entries (4368), 32 schema fields/cases/payload fields/retired identities (6523); schema ABI version 4 (5554).

## Repetition by placement or construct

Property 3 (one rule per source placement) has little support here. This slice does not track facts on locals, fields, parameters or returns. What repeats is per construct or per stage:

- **Per call-site kind.** `invocations` computes target and trait scope three times, for a statement call (layouts.rs:244-272), an expression call (273-313) and a named transition (314-327).
- **Per syntax construct.** The dependence walk has one arm per item kind (2783-2936), parameter kind (2955-2985), type node (3077-3143), statement node (3170-3241) and expression node (3243-3347): about 610 lines (2777-3387).
- **Policy vs schema.** Discovery repeats candidate selection (4040-4064 / 4097-4123), visibility (4125-4138 / 4139-4152), authority (4153-4162 / 4163-4172) and publicity (4173-4181 / 4182-4190). Installation repeats "find by name and span" three times (2054-2067, 2068-2081, 2082-2095).
- **Probe vs authoritative.** The loop "select declarations, admit, compute plan" is written at 3634-3668 and again at 3779-3818; the three evaluation calls before it at 3616-3631 and again at 3762-3777. `compute_plan_laid_layouts_in` and `compute_prepared_plan_laid_layouts_in` differ by one line (5225-5248).
- **Per placement kind.** Overflow and span computation for `At` (4524-4533), `IntegerAt` (4578-4587) and `Bits` (4627-4656). `install_geometry` re-derives each kind from the report and re-checks array count and stride that `validate_plan` already checked (5824-5865 vs 4483-4498, 4682-4697), then converts each number to host width one message at a time (5783-5931).
- **Per access variant.** `access_is_exported` lists four variants (2693-2710); the aggregate and scalar paths of `parse_field_access` both decode Stable/External (1315-1352, 1358-1376).
- **Small helpers written more than once.** "Is this declaration from the core Layout source": 1111-1120, 1816-1823, 2289-2299, 2612-2619, 3966-3971. "Last `::` segment": 1601-1603, 4428-4429, 4839, plus eleven inline `rsplit("::")` uses. ## Accepts or skips without proof

- **No source map means "trusted".** `toolchain_layout_declaration` returns true when there is no source map (layouts.rs:2293), so does `sealed_accessor_template` (2612) and `same_package` (4263). With no source map a generic spelled `Access` is treated as the canonical template (3978), an operand with no selection is accepted (4034), and candidates are matched by name (4046, 4103). Cannot tell from this slice whether a production compile can run without a source map.
- **No authority means admitted.** `admit_policy_invocations` returns `Ok` when there is no selection authority (3866-3868); `require_declaration_selection_authority` returns `Ok` when there is none and neither file is a toolchain contract (4298-4300).
- **Template check skipped.** When the recorded template span has no source file, `selected_access_view` returns a default symbol and skips the origin check (2000-2002, 2012).
- **Calls skipped while collecting lifecycle demands.** A callee that is not an access execution declaration returns `None` (182-185); a callee whose machine still has open parameters returns `None` (186-191); `selected_scope` returns `None` unless exactly one conformance application matches (226-228). Whether a later stage sees the open-parameter callee again after instantiation: cannot tell.
- **Calls skipped while retaining applied results.** Argument-count mismatch on a non-factory callee continues (1708); a type argument that is not a named type continues (1722); a call whose target is not a known machine continues (1691-1693); an `Access<…>` result whose operands are not data symbols is left alone with no diagnostic (1833-1836). Discovery later reports "closed placement operand has no retained nominal selection" (4028) for unselected operands when a source map exists.
- **Layout requests skipped.** A storage application whose semantic type has no data definition is not requested (5281, 6065-6067); an open policy that is a conformance parameter is skipped (5285-5291); an open policy with no targets is skipped (5293-5295); with no layout targets and no layout applications the function returns no requests (5380-5382); an evaluation error `StaticInputUnavailable` with an open policy skips the whole application (5582-5586). The final loop at 6096-6108 refuses only *closed* applications without a layout.
- **Fallbacks.** Realized policy machine falls back to the template machine when no captured application matches (5469-5477). The private-slot owner falls back to `operand_lifetime_owner` (5614-5617). `field_symbols` falls back to the record's live fields when there were no targets (5638-5643). `transfer_width_bits` falls back to `size × 8` for any combination of placements it does not name (1432-1434).
- **Reflection failures swallowed.** A payload field whose layout cannot be reflected is given size 0, alignment 1, kind `Nested` (6398-6406). Zero-size fields are dropped from the schema silently (6599-6601). Erased fields are dropped (6582).
- **Unknown shapes pass.** `validate_nonresident_schema` continues on a symbol with no data definition (988-990) and ignores every type node other than Named, FixedArray and Constrained (1017), so a reference or slice field of a View schema is not examined by this function. `representation_dependencies` ignores type nodes other than arrays and named/generic (5749) and identities with no storage index (5719-5721). The dependence walk ignores unlisted item kinds (2935).
- **Extra plan entries ignored.** Entries beyond `field_count`, `service_count` or `entry_count` are never read (1235, 1510, 4462).
- **Unchecked integer casts.** Policy integers are cast `as u64` without a sign check (1556, 4391, 4439, 4842). A negative offset becomes a very large number; the overflow and size checks then refuse it in the fixed-size case. For a dynamic-size plan (4733) cannot tell. The private-callback path does check the sign (5053-5054).
- **Trusting declared ranges.** `declared_source_bits` narrows a field's bit width using the interval read from the record's `requires` clauses (6576, 6690-6697) and the scalar representation range. The stored width then relies on those declared facts holding for every value written; `stored_integer_write_is_total` (5980-6005) records whether an `IntegerAt` write is total, but nothing in this slice does the same for `Bits`.
- **Positional trust.** The "Ready" case is whichever variant comes first and the owner is its first payload field (673-687); profile parameters are at hard-coded positions (607-611).
- **Rejoin with absent recorded authority.** When the stored authority is `Absent`, `rejoin_source_authority` sets the selection authority to `None` and discards the authority the caller passed (lib.rs:401-402).
- **Retained placement reused across targets.** For a lifecycle demand the placement is first looked up in `access_view_plans` by policy, schema and machine with no target comparison (915-923); only the second lookup compares the target (940). View plans are computed with target `None` (3658, 3802).

## Surprises

1. **Most of this file could not run when it was deleted.** Every policy evaluation goes through `accounting.evaluate` (layouts.rs:1632-1639, 5576-5580). Looked up outside the slice: `EvaluationAccounting::evaluate` (evaluation_accounting.rs:695-702) ignores its arguments and returns `Err(no_typed_tree_engine(job))`, a `Rejected` error reading "no product route yet: … runs a machine at build time before the program is checked, and the tree interpreter that ran it is removed; the program is refused …" (evaluation_requests.rs:37-43). The crate header says the same (lib.rs:9-12). So any program that uses `Access<P, S>`, a `FixedLayout` storage application with targets, or a lifecycle call with no retained placement was refused, and `validate_plan`, `validate_access_value`, `parse_field_access`, `normalize_private_callback_demands`, `install_geometry`, `synthesize_exact_records`, `install_access_view_plan` and the identity comparison at 3811 were unreachable in the shipped compiler. The `StaticInputUnavailable` arm at 5582-5586 could not match either. The rule inventory above describes what the code would enforce, not what the last compiler enforced.
2. **`policy_request` computes a careful answer and then always refuses.** When a policy takes its data context it checks binding position, type and zero-initializability (6157-6196) and then unconditionally returns the "removed tree interpreter" error (6200-6205). The earlier checks only choose which message the user sees.
3. **Probable compiler panic on a zero-size field.** `schema_fields_for_target` drops fields of size 0 (6599-6601), so a plan needs no entry for them and `validate_plan` passes. `install_requested_layouts` builds its field list from `live_data_fields` instead (5506-5509). In `install_geometry` a field with no entries matches the arm `entries if entries.iter().all(Bits)` because `all` on an empty slice is true (5884-5887), pushes a bit field with no fragments and leaves its offset `None`; the `.expect("validated plan supplies every field")` at 5951-5955 would then panic. This holds if `live_data_fields` yields zero-size fields such as a nested empty record; that function is outside the slice. The test at 6948 shows empty records were expected.
4. **A message contradicts the code.** `require_scalar_access_field` says "the current access vocabulary admits only Inaccessible for aggregate fields" (1397), but 1315-1352 admits Stable and External on aggregate fields as `FieldAccess::Region`. Only Atomic on an aggregate reaches that message, because the scalar-path External call at 1368 is only reached for scalar fields.
5. **An always-true flag and a redundant check.** `generated_is_public = policy.is_public && schema.is_public` (4246) is always true because 4173-4190 already refused non-public declarations. For the same reason the "private … from another package" messages (4125-4152) only ever fire for cross-package use; same-package private use falls to "must be public".
6. **The frontend is run again on a copy to decide what to generate.** `retain_applied_results` clones the whole syntax tree and runs name resolution on it (1683-1684); `desugar_access_views` clones it again, types the clone and evaluates lengths, domain facts and layouts on it (3592-3632); `synthesize_exact_records` clones it a third time to use as the template source (2423).
7. **Capability not expected in a checker crate: code generation by text substitution.** Accessor machines are made by copying a toolchain template and replacing every type spelled `T` and every generic spelled `Accessor` (2641-2691). A template body that mentioned another type named `T` would be rewritten too.
8. **Atomic fields are typed by spelling.** Only schema fields written literally `bool`, `u32` or `u64` can be atomic (2573-2576); an alias or a constrained `u32` gets the "requires a plain schema type" message.
9. **Collision naming depends on discovery order.** Two different `(policy, schema)` pairs with the same bare names get `Access<P,S>` and `Access<P,S>#N` where N is the number of applications found so far (4213-4221). That generated name is later the only key used to find the view (1982, lib.rs:145).
10. **Missing closing backtick** in two messages: "unknown Exposure case `{other}" (1473) and "unknown ExternalRead case `{other}" (1489). The schema-shape diagnostic at 4196 is the only discovery diagnostic with no source span.
11. **Lifecycle operations come from two unrelated recognizers.** `core_lifecycle_operation` knows only `initialize` and `move_out` by name (1105-1106); View and Relocate can only arrive through `AccessExecutionDeclaration::authenticate` (182-199).
12. **Requires-derived intervals choose the stored bit width** (6576, 6690-6704). This is the one place in the slice where a declared proof fact changes representation; the slice does not show a check that the fact is established before a value is stored in the narrowed field.
13. **A library function prints to stderr.** `report_evaluation_diagnostics` writes warnings with `eprintln!` (lib.rs:876).
14. **Generic normalization gets one extra round, not a fixpoint.** After `normalize_generic_data` adds roots, const generic expressions and calls are evaluated once more (lib.rs:242-248); roots added by that second round are not revisited here.
15. **`EvaluationDomain` equality ignores its accounting** (lib.rs:83-91), and `same_pending_work` compares authorities by pointer (lib.rs:509-513).
16. **Property 1 evidence.** Nothing in the slice calls `proof_admission`, `ProofNode`, `verify_obligation` or a certificate type (confirmed by grep after reading). Every acceptance is the code's own arithmetic or comparison, or a yes/no from `validation::*` and `BuildTimeAdmissionPlan`. The one name with "prove" in it, `const_qualifications::prove_ready` (lib.rs:215), is outside the slice. For layout geometry the own-judgment checks are concrete and total (checked arithmetic, exact tiling, overlap by sorted intervals), which is different in kind from the fact-checking the brief describes.
