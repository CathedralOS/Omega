## What this code is for

This is the second half of the old checker's borrow-fact builder. It does not itself report "two borrows conflict". It walks each state of each machine once, statement by statement, and writes rows that say which storage every reference-carrying value borrows from ("loans"), who supplied each loan, and which loans a return value carries. Later stages (flow, last-use, escape checks, outside this slice) read those rows.

The slice starts inside `mod loans`, at `mod stored_calls` (4793), and runs to the end of the file. It contains: loans that a call installs in caller storage (`stored_calls`, 4793-5315); reference type tests (`types`, 5318-5358); loans for reading a stored pointer (`descriptor_loads`, 5362-5501); loans for a call's returned references (`invocation_results`, 5504-5761); loans for `let` bindings of references (`reference_borrows`, 5763-6006) and of data that contains references (`aggregate_loans`, 6013-6657); the declared "which input does the returned view borrow" relation and the routine that follows a pointer back through local carriers (`call_views`, 6658-7397); the per-statement entry points for locals, assignments and returns (7507-8062); per-machine arenas and handle shifting so machines can be built in parallel (`machine_rows`, 8063-8412); translation of loan owner paths to structural paths (`owner_geometry`, 8413-8552); writable roots (`roots`, 8553-8640); the per-state driver (`state`, 8641-9372); the check that a captured pointer came from a call's supplied output (`supplied_outputs`, 9373-9481); the tracker structs (9482-9543); and the top-level `build_borrow_facts` (9574-9643).

The slice contains no tests and no call to the proof kernel.

## Mechanisms

- **Following a pointer back through local carriers** (`rebase_borrow_places_following`, 7191-7355). Given a place, it finds every current loan whose owner is that place's root and whose owner path matches the place's segments, replaces the place with the loan's target plus the remaining segments, and repeats on the result. It returns one entry per alternative. It stops at a borrowed parameter's own root, at a place with no loans, at a place that already has an incoming identity, at an optional "storage boundary" predicate, or when the place is already on the `active` stack (7215-7220). The `active` stack is the only termination guard; there is no depth or fan-out budget. A loan that is only a lifetime dependency is recorded but not followed (7324-7326). Serves every reference binding, store and return.
- **One pass per state with a running roster** (`append_state_borrow_facts`, 8687-8907). For each admitted statement in order: snapshot the roster, add loans for borrowed computed values and stored-pointer reads, compute the carrier a store replaces, collect calls, add loans for call results, record returned-value loans, compute the statement's own loans, retire replaced loans, append the new loans. `current_loans` is the live roster; `state_loan_trackers` is the full history. There is no fixpoint and no join: a state is treated as a straight line and each state starts from its parameters only (8695-8703).
- **Last-use update** is called once at the end (8883-8894); its body is outside this slice.
- **Permission-source propagation** (8984-9062). Each tracker carries the nearest real borrowing loans (`permission_sources`). A derived loan copies the union of its suppliers' sources if all suppliers qualify, otherwise none.
- **Grouping and de-duplication of pending loans** (`grouped_carrier_loans`, 9096-9171). Sorts by owner symbol, storage owner and owner path, then merges a loan into an earlier one with equal fields, unioning supplier lists. The comparison walks back through loans with the same owner and path, so it is quadratic within a group.
- **Supplied-output identity reuse** (`capture_incoming_origin`, 8914-8944). For an output origin it scans every incoming-reference row of the machine for an equal identity before appending a new one. Other origins always append.
- **Exact carrier re-join for stored references** (`from_effects` 5155-5204 with `transferred_place` 5259-5314). A candidate supplies a stored reference only if its place equals the backing, or the backing is a projection of the exact carrier that was loaded; "all candidates must match some alternative" is required before any is used.
- **Applied declaration for a call's return relation** (`CallViewReturnContract`, 6726-6922). Resolves the callee signature by four routes (named conformance requirement, retained static machine contract, dynamic slot / target state / machine parameter / any trait, 6866-6898 and 6941-6978) and carries type substitutions. `carrier_reference` (6831-6857) chases `Constrained` and substituted `Named` types with a visited list; a cycle returns an invalid handle.
- **Owner-path translation** (`carrier_path`, 8466-8551). Walks a loan's nominal path (field, case, fixed index) through the type's declarations and emits a structural path.
- **Parallel build with handle shifting** (`build_borrow_facts` 9574-9643, `machine_rows` 8063-8412). Each machine is built on its own eleven arenas by a rayon `par_iter`, then appended in roster order; every handle and span is moved by the row count already in the program arena. The `Shift` methods destructure every field of each row type so that a new field fails to compile (comment 8064-8075).

## Surprises

1. **This half of the borrow checker never reports a borrow conflict.** Every refusal in the slice is about the compiler lacking information ("has no complete…", "has no prepared…", "lost its…"). The user-facing wording is internal, and the only location given is a statement index. Whether a program is rejected for aliasing is decided by whoever reads these rows.

2. **No proof kernel involvement.** There is no `proof_admission`, `ProofNode`, `verify_obligation` or certificate in these 4,864 lines. The verb "proves" appears in a comment (9414-9419) for a chain of row equality tests. This supports property 1.

3. **Dead and divergent `match` handling.** `reference_local_borrow_loans` has its own `match`-arm loop (5849-5869). Its only callers are itself (5858) and `binding_borrow_loans` (7900), and `binding_borrow_loans` returns early for a `match` initializer (7807-7830). So the inner loop cannot run. The two copies also differ: the outer one skips unreachable arms and refines the type per arm (7812-7817); the inner one does neither.

4. **Unused parameter.** `retained_reference_lineage` takes `_rebased` (7361) and ignores it; all four call sites pass the full rebased list (5976-5981, 6164-6169, 6321-6323, 6579-6581).

5. **Template-dependent relations get three different treatments.** For a call argument it is an error (7491-7493). For a `let`, assignment or return it silently yields no loans (7856, 7893-7895). For a stored call it silently yields no loans (4950-4952), or an empty roster under the owned-storage shortcut (4824-4834).

6. **Placement is unified by pretending everything is a `let`.** Assignments, returns, call results and borrowed temporaries are passed to the local rule as fabricated `TableLocalData` records (5634-5646, 7563-7575, 7641-7653, 7980-7992). Three of them use the state's own symbol and name as the "variable". This is a different pattern from property 3: one rule, reached through an adapter per placement, with the placement differences patched afterwards (storage owner overwritten at 5673-5676 and 7585-7588; owner, name and path rewritten at 8037-8040).

7. **Lineage depends on expression syntax.** Whether a loan is "direct root", "reborrow" or "unretained derived" is decided by whether the initializer node is a `Cast` or `Call` (7374-7382), not by a property of the value.

8. **Pointer following stops by comparing types.** `rebase_reference_formation_geometry` stops at the first place whose stored type identity equals the reference's declared referee type (7071-7104). Two different storage places with the same type are not distinguished by this test; when the place's type cannot be found the test answers "keep following" (7088-7090).

9. **Possible span relocation at state entry.** `append_incoming_reference_trackers` appends lifetime identities with plain `append` (9255) and other identities with `append_to_span` on the same arena (9289, 9335). With the present-day arena (`source-rust/foundation/arena/src/arena.rs:1019-1047`) a span that is no longer at the arena's tail is copied to the tail before the next append. If the arena behaved the same when this code was live, then for a state with two or more parameters where a later one has a retained lifetime path, the state's `incoming_references` span would point at copies while trackers created earlier keep handles to the original rows (9335-9366). I did not verify the arena version this code was built against, nor whether any consumer compares those handles with the span.

10. **Statement-added identities are outside the state's span.** `capture_incoming_origin` appends descriptor-load, invocation and output identities with plain `append` (8937) after the state's `incoming_references` span was fixed at 8696-8702, so `StateBorrowFact.incoming_references` (8899) lists only entry identities.

11. **Three different statement enumerations in one module.** Writable roots iterate `statement_table.statements(...)` (8574); the capacity estimate iterates `crate::flow::state_statements(...)` (8625); the main loop iterates `admitted_execution_statements(...)` (8717-8719). If these differ, a local can be a writable root without ever being walked for loans, or the reverse.

12. **Merging loans with different suppliers.** `grouped_carrier_loans` treats two loans as duplicates when all other fields match and both have suppliers, even if the supplier lists differ, provided the owner path has no dynamic index (9149-9151). The suppliers are then unioned (9159-9165).

13. **`stored_reference_loans` discards partial results.** `let first = selected.next()?` (6247) inside the loop returns `None` for the whole function if any one rebased source has no exact tracker, and the caller then falls back to the geometry path as if no stored descriptor had been found.

14. **Fallback loan with no supplier.** `from_effects` writes a loan aimed at the callee-reported backing even when it could not match any caller loan (5200-5225). It has lineage "unretained derived" and no suppliers, so `append_carrier_loans` gives it no permission source (8985-8986).

15. **Only one diagnostic survives.** All machines are checked in parallel and all results collected (9589-9608), but the append loop returns the first error and drops the rest (9624-9627). Within a machine the first failing state stops that machine (9596-9603).

16. **The unavailable-relation reason is discarded at call inputs.** `at_argument` replaces `Unavailable(reason)` with a fixed string (7494-7496), while `stored_calls::loans` passes the reason through (4961).

17. **Machine parallelism rests on a stated invariant.** "A state's borrow facts read only rows that state wrote" (8068-8069). `capture_incoming_origin` does scan every identity row in the machine's arena (8919-8931), but it filters on machine and state symbols, so it stays within the invariant.
