## What this code is for

This is the second half of the old checker's ownership ("multiplicity") file. It decides who owns each linear or affine resource at each point of a state body, and what must be cleaned up where. It does not read source text directly: it reads "flow facts" an earlier part of the same stage published (permission events, completed-operand trees, call facts, storage snapshots) and it writes more facts (permission events, cleanup dispositions, join bindings) for later stages.

The slice holds eight nested modules:

- `permission_schedule` (5369-5744): one walk over a state's statements that says in which order permissions are evaluated, where custody forks at a transition, and where the state exits.
- `returned_claims` (5745-6817): for a value being returned, passed or stored, works out which linear claim sits at each path of its type and checks that every declared claim path is filled exactly once.
- `selected_cleanup` (6824-7839): remembers what a conditional (`if`/`match` arm) move left behind so the remainder is cleaned up at state exit or at replacement.
- `selected_evaluation` (7840-8498): joins custody when two expression arms reconverge, minting a new claim identity for a place whose two arms carry different claims.
- `projected_affine` (8502-8743): a move of a field out of an affine owner.
- `projected_replacements` (8744-9206): an assignment that overwrites an owned subtree or a stored loan descriptor.
- `temporary_results` (9207-10863): anonymous temporaries (call results, constructions) that a call borrows, takes whole, or takes a piece of.
- `type_multiplicity` (10864-11025): small type queries.

There are no tests in the slice and no call into a proof kernel.

## Mechanisms

- **One permission schedule** (`permission_schedule::walk`, 5397-5509). Generic over a custody type `S: Clone`. It visits each admitted statement once, emits `Evaluate`, `MissedGuard` and `Exit` steps, and clones custody for each transition target or continuation so only the missed-guard state flows on. The comment says "No expression traversal is duplicated" (5370-5374). `append_constructed_owners` reuses it with `()` as custody (10250). No budget.
- **Case exclusion at a cut** (`SelectedCases`, 5576-5725). Picks the one flow row for a step, turns its constraint list into `CaseEvidence`, and marks places under inactive cases. `inactive_owned_cases_after` (5700-5724) shares an `Arc` list across consecutive steps when the exclusions did not change.
- **Claim collection over the completion tree** (`captured_claims`, 6030-6404, recursive). For one completed operand it gathers `(path, claim identity or Inactive, condition)` triples from, in order: transfer events on the operand's place; constructed children; the call that produced a fresh result (`completed_call_claims`, 6618-6703); a literal whose path is inactive; an inactive-case query; and a backward trace through earlier stores (`stored_claims`, 6413-6540). Selected operands recurse per arm and AND each claim with the arm's choice condition (6084). `check_frontier` (6542-6611) then checks coverage, disjointness and single use with `SelectionConditions` (`all`, `any`, `never`, `always`, `possible`, `covers`). Serves returning, passing and storing linear resources. No budget; recursion depth follows the operand tree and the store chain.
- **Backward store trace** (`stored_claims`, 6475-6539). Walks admitted execution order backwards from the consumer, stops at the first store whose destination is a prefix of the wanted path, and gives up (returns `None`) at any statement whose writes make the binding origin unstable (`binding_origin_is_stable`).
- **May-presence over routes** (`present_on_some_route`, 7146-7175). Every region starts present; each owned event updates presence on its route; arms join with OR. A region counts as gone only if no route kept it. Used by `retained_on_some_route` (7102-7139) and `retire_transferred` (7471-7508).
- **Must-availability join with identity minting** (`join_places`, 8448-8497; `enter_produced`, 8161-8236). At reconvergence `live`, `ever_established` and `case_excluded` are ANDed. A linear place whose two arms carry different claims gets a freshly minted identity with `PermissionProvenance::Joined`, and a `FlowSelectionPlaceBinding` records both arrivals and the destination. The comment says "nested selections never enumerate combinations of execution paths" (7843-7846).
- **Production and replay** (8161-8333). Production mints join identities and records bindings; replay (`join_recorded_places`) looks each binding up and checks it against the arrivals; `claim_origin` (8315-8333) confirms a later claim names exactly one such binding.
- **Candidate deaths** (`SelectedCleanup`, 6847-7701). Each conditional move adds an `Owner` holding a snapshot of places and remaining custody. `SourceBinding` (6868-6913) tracks later writes to the source so a candidate is not credited with storage that was overwritten. `finish` (7510-7700) emits cleanup events for ordinary deaths and for each surviving candidate, sorted in reverse declaration and establishment order.
- **Retained operand graph** (`retained_operand_productions`, 10337-10475). A worklist over operand handles following `backing`, constructed children, selected alternatives, copies and retention profiles. Visited sets are `Vec`s searched with `contains` (10416, 10458).
- **Borrow lifetime extension** (10058-10211). For each borrowed temporary, scans later calls and value observations in the same statement on a compatible route and moves the owner's `consumer` to the last one whose captured roots include the temporary.
- **Per-arm case tables** (`OwnedCaseSelections`, 7890-8086). A `BTreeMap` keyed by `(expression index, generation, arm index, generation)`; rows that disagree for one key collapse to `None` (8040-8053).

## Identity by text

Most of this slice identifies things by handle: `SymbolHandle`, `ExpressionHandle`, `PlaceRoot`, `Vec<PlaceSegment>` paths, `PermissionClaimIdentity`, arena handles. Places are compared by root equality and path prefix (for example 5733-5736, 6169, 7226-7235). That is evidence against property 2 here. The exceptions:

- `expression_establishes_obligation` turns a field symbol into its name with `data_field_name` and finds the struct-literal field by `field.name.as_str() == field_name` (10935-10945). The answer to "does this literal establish the obligation" depends on that name match.
- `literal_variant` finds a data definition by `definition.name == literal.type_name` over all data definitions and takes the first hit, then finds the variant by `variant.name == *case_name` (11006-11014). Its result decides the comparison at 10928-10931.
- `data_field_name` (11017-11024) returns a field's name from `any_field_owner`.
- `trace_missing_frontier` compares the environment variable `OMEGA_TRACE_CLAIM_FRONTIER` with `"*"` or the machine's name (6713-6721). Debug output only.
- Names used only to build messages: `place.name` (8131, 8264, 8274, 8485), `place_spelling` (7394-7395, 8596-8601), `program.symbols.name` (8615-8616, 9285, 10136, 10858), `machine.name`/`state.name` (7407-7408, 8604-8605, 10136, 10185, 10203, 10853), `normalized_type_identity_text` (9295), literal `"<unknown machine>"` (10854).

## Accepts or skips without proof

- **Default `true`** at 10974: any expression that is not a tracked place, array literal, struct literal or variant name is said to establish the obligation at any relative path, including a conditional case path. Whether a later check narrows this, I cannot tell from this slice.
- **`frontier.is_empty()` returns no claims** (6043-6046). The declared type alone decides that nothing needs tracking.
- **Child claims dropped** (6312-6318): when the parent already has transfer events, a child's live claim is skipped unless its path is among the unresolved transfers. `check_frontier` (6576-6579) refuses afterwards if a declared path ends up uncovered.
- **Fresh-result claims filtered** (6335-6341): if other claims exist, only `Inactive` ones from the call are added.
- **Paths accepted as inactive** on the word of `literal_value_path_is_inactive` (6348-6364) and `InactiveClaimQueries::preserved` (6365-6383).
- **`stored_claims` returns `Ok(None)`** on seven conditions (6426, 6430, 6453, 6462, 6505, 6536, 6539). `check_frontier` catches the missing path.
- **`completed_call_claims`** returns no claims when no call matches (6634-6636) and skips live events with unknown identity (6669-6672). `check_frontier` catches the missing path.
- **`receiving_destination`** returns `Ok(None)` when the statement row is missing or stores another value (6012-6017); the code then falls back to the expression's own place.

## Surprises

- **Property 1 holds without exception.** Nothing in the slice names `proof_admission`, `ProofNode`, `verify_obligation` or a certificate. Every verdict is a comparison of handles, paths, flags, counts, or a call into `validation::*` / `crate::flow::*`. The nearest thing to independent checking is production-then-replay of join bindings (8161-8333), where the same module re-reads records it wrote itself.
- **Property 2 mostly does not hold here.** Claims have their own identities (`PermissionClaimIdentity`), separate from the place that holds them, and a join mints a new identity distinct from both arrivals (8193-8208, 8307-8308). That is already "a claim belongs to a value, a place only says which value it holds", built on top of the source-tree checker's flow facts. Text decides meaning only in `expression_establishes_obligation` and `literal_variant` (10935-10945, 11006-11014).
- **A debug trace marked for removal shipped.** `trace_missing_frontier` (6705-6816) says "Root removes this with its call before landing". It reads an environment variable, prints with `eprintln!`, counts emissions in a process-wide `static AtomicUsize` capped at 48, and calls `ownership.walk_guard.note(...)` (6731), which touches shared facts from inside a diagnostic helper. It is still called at 6577.
- **A third verdict.** `unsupported` (7827-7838) returns `Diagnostic::incomplete(message, coverage.exceeded(..))`. Six refusals in `selected_cleanup` use it (7239, 7322, 7345, 7392, 7419, 7756): the compiler says it could not judge, not that the program is wrong. One user-facing error text begins with the word "unimplemented" (9311).
- **About 36 refusals in `returned_claims` are bare `&'static str`** (5862 to 6654). They describe disagreements between flow-fact tables ("child capture belongs to another evaluation occurrence"), not source-level faults. They carry no source span; whatever wraps them is outside this slice.
- **`retire_transferred` and `retained_on_some_route` disagree on `Consume`.** In `retained_on_some_route` a `Transfer` or a `Consume` makes a path absent (7117-7127). In `retire_transferred` only `Transfer` does; `Consume` is ignored (7494-7499).
- **`nominal` is computed inside the per-place loop but does not depend on the place** (9474-9478). If any linear written target of the constructed expression sits exactly at its own destination path, the "exactly one receiver" check (9496-9503) is waived for every child place of that construction.
- **`SourceBinding::follows_capture`** (6891) treats any event in a different statement as following the capture, with no ordering test. It relies on events arriving in forward order.
- **A sentinel statement index.** The final exit of a state uses index `statements.len()` when the last statement is not an expression (5495-5502). `stored_claims` special-cases that value (6477-6481).
- **A borrow is published as an `Establish` event** with `Multiplicity::Unrestricted` and the borrow's access (9334-9356), next to `Consume`/`AffineDrop` events for the owner's places.
- **Dead or redundant code.** `_facts` is unused in `append_transfer` (8523); `_machine` is unused in `is_borrowed_place_transfer` (8703). `append_transfer` tests `program.state_by_symbol(state).is_none()` at 8537 and again through `is_none_or` at 8582, where it can no longer be `None`. The `_ => continue` arm at 9291 looks unreachable. `type_carries_linear_obligation` and `type_multiplicity` (10876-10881, 10977-10982) are one-line forwards.
- **Linear scans.** A `Name` expression is tested against every member of every data definition (10958-10970). `literal_variant` scans all data definitions by name (11007-11010). Visited sets in `retained_operand_productions` are `Vec::contains` (10416, 10458). `ExpressionRoutes::expression` is a linear `find` per event (8411-8414). `join_recorded_places` and `claim_origin` scan all selection bindings per place (8247-8260, 8320-8328).
