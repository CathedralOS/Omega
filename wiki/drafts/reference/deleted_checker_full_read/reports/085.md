## What this code is for

The file holds two unrelated checkers in one module file (:1-4). The first, `access_views`, checks "access views": compiler-synthesized record types whose fields are accessors onto placed storage (stable, region, external or atomic), generated from a schema record plus a placement policy. It has three parts. `plan_replay::validate_plans` (:914-1163) re-derives every stored `AccessViewPlan` from the program tables and reports any part that no longer matches. `access_custody::validate_agreements` (:26-188) checks each conformance to the core trait `AccessCustody<Custody, Policy, Schema>`: the custody record must carry exactly the schema fields that have no runtime representation, with the same type and multiplicity, and none of the represented ones. `validate_statement` (:1172-1191) walks each statement and enforces the use rules for accessor fields: atomic accessors may only be used through an atomic operation the policy admits, binding-private accessors only inside the policy's package.

The second, `write_only_borrows` (:1580-3928), enforces the `&write` (write-only reference) discipline for the "current checked slice": a `&write` referent may be replaced or forwarded as `&write`, never read. It collects the write-only parameters and locals of each state as "roots" (:2125-2163), then walks every statement and expression of the state and refuses any expression that reads a root or a place whose declared type is write-only (:3720-3785). It also limits which referee types may sit behind `&write`, which projection paths may be written or re-lent, and refuses `&write` on any machine that has no checked Omega body.

Neither half calls the proof kernel. Every decision is a comparison this file makes itself or a yes/no query to another validation module.

## Mechanisms

- **Bounded search for erased descendants** (:504-612). Answers "does this type contain a non-runtime field anywhere below it". Recursive walk over named records, arrays, slices, constrained types and references, with a visiting stack for cycles, a memo list searched linearly (:548-552), a depth budget of 64 (:521, :535) and a record budget of 256 (:522, :553-556). When a budget runs out, the handle is invalid, a cycle is found, or the type is generic, a const expression or a dynamic trait, it answers `true`, which leads to a refusal. Serves custody conformance checking.
- **Nested custody spine** (:190, :465-502, :223-341). Recursion over nested schema records with an ancestor list for cycle refusal, a depth limit of 24, and a requirement that nested levels have a nonzero fixed layout width. Serves custody conformance checking.
- **Fixed layout calculation** (:784-839). Computes size and alignment of primitives, plain records (skipping erased fields) and literal-length arrays with checked arithmetic and align-up. It is used to print widths in diagnostics and to test for zero width (:478-479).
- **Slot derivation by sorting** (:886-912). To find a field's access-plan entry it collects the layout's field identities, sorts and de-duplicates them, takes the field's position as its slot number, and finds the access entry with that slot. This reproduces a numbering convention owned by the access-plan builder.
- **Projection resolution** (:1789-1898). Obtains the chain of member/index steps from `projection_climb` (called with budget `usize::MAX`, :1796-1800), finds the root name among the supplied roots, then walks outward tracking the current referee type and current access (write-only, mutable). Two endpoints: `Storage` (the place itself) and `Referent` (strip reference layers at the end). A caller-supplied closure admits each index selector. Serves `&write` stores, re-lends and recasts.
- **Root tainting** (:3787-3804, :3849-3927). `write_only_place_root` follows member/index receivers down to a name and matches its head symbol against the roots. `expression_mentions_root` is a full recursive walk of an expression that also follows saved match subjects (:3879-3881).
- **Reference-shell chain walk** (:3752-3763). Peels reference layers of a declared type looking for a write-only layer, with a visited list to stop on cycles.
- **Static range bounds** (:2953-2983). A lazily created `ImmutableBoundLookup`, shared across the whole program pass (:2122), turns range endpoints into `usize` when they are literals or immutable local copies.
- **Type-shape classification for `&write`** (:2216-2505). A set of mutually recursive predicates that classify a type as scalar, qualified leaf, byte slice, record, sum, array element, field leaf or assignment leaf.

## Identity by text

- The core trait is recognised by the literal name `"AccessCustody"` plus its source file being core `Layout` (:637-651).
- The policy plan machine is checked by `attached_data` string equal to the policy name and machine name equal to `format!("{}::plan", policy.name)` (:953-958).
- An accessor machine is checked by `attached_data` string equal to `field.accessor_name` and by the last `::` segment of its name equal to the operation name (:1141-1150).
- Fields without a numbered identity are matched by name string (:673, :685, :882, :1024-1025, :1092). `RetainedFieldIdentity::Positional(String)` then takes part in a sort whose order decides the access slot (:873-877, :898-902).
- Atomic fetch operations pass through strings: `fetch_operation` maps a binary operator to `"fetch_add"` etc. (:1541-1545) and `validate_assignment` maps the string back to a permission bit (:1236-1241). The generated operation set is compared as strings (:1123-1129).
- `is_unrestricted_scalar` excludes atomic types by `!name.as_str().starts_with("Atomic")` (:2225).
- A call statement's access view is found through the receiver's member names (`call_receiver_member_names`, :1450-1460, :1470-1480), and `call.target.as_str()` is passed to `accessor_target` (:1479).
- `attached_field` takes a field name string together with a symbol (:1988, :1999, :2004-2019); this path is unreachable (see Surprises).
- Canonical paths such as `Schema.field.sub` are built with `format!` (:278, :404, :691-693) but are used only in diagnostic text.
- Against the property: write-only roots are matched by `SymbolHandle` (:1975, :2034, :3859), view fields by field symbol (:1018) and state symbol (:1437), and types by normalized identity values (:376-378) or `stored_structural_type_identity` (:2666-2667).

## Accepts or skips without proof

- `validate_agreements` silently skips a conformance when the trait definition is missing, the argument count is not three, an argument is not a plain named type, no plan matches the (policy, schema) pair, or the schema or custody definition is missing (:31-69). I cannot see another check for a custody conformance that names a policy/schema pair with no plan.
- A non-erased schema field with no exact layout entry is skipped (:99-101). Cannot tell whether another check covers it.
- Index selectors inside a projection path are admitted by a closure that returns `true` and ignores the array length it is handed (:1738-1748, :1761-1771). The diagnostics say "proven-in-bounds" (:3086, :3511), but no bounds check is made in this file. Cannot tell where it is made.
- A statically known write-only range whose start exceeds its end or whose end exceeds the array length is accepted with no diagnostic: the `if` at :2992-2994 returns `true`, the same as the fall-through at :2995. Cannot tell whether another check catches it.
- A non-literal index into a write-only fixed array is returned as admissible (:3028); only the index expression is then scanned for reads (:2777-2787). An index into a directly rooted write-only byte slice is accepted for any non-range expression, with no bounds check (:3013-3018). Cannot tell where bounds are proved.
- `&write root` passed where the receiving type is not a declared `&write` (unknown callee, non-reference parameter) is accepted as a re-lend with no check (:2621).
- A referee mismatch pushes a diagnostic and returns `true`, so the caller treats the value as handled and scans nothing below it (:2670-2688, :1621-1634).
- A name whose declared type is a matching write-only reference is forwarded without any further check (:3328). This file does not check that the forwarded reference is not used again. Cannot tell.
- `&write name` where `name` is not a parameter or local of the state (for example an attached field), or is a shared-reference binding, gets no diagnostic from the `Borrow` arm: `binding_without_write_authority` returns `None` (:3828-3847) and `is_direct_name` is true (:3509). Cannot tell whether another check refuses it.
- `StatementNode::Assembly(_)` is skipped (:2740); a write-only root used inside an assembly statement is not examined here.
- `validate_opaque_call_inputs` returns silently when the callee's type arguments cannot be bound (:3367-3377, :3405-3407) and when the target is neither a machine state nor a boundary requirement (:3384-3386, :3415-3417). Cannot tell whether a non-boundary requirement with write-only inputs is checked elsewhere.
- `has_checked_write_only_implementation` treats a machine as checked when `AccessExecutionDeclaration::authenticate` returns a contract (:2072-2076), when all target-family members have checked bodies (:2077-2085), or when all requirement satisfiers do (:2086-2116). This trusts those other modules.
- `write_only_place_root` returns `None` for any path that is not name/member/index (:3801); a read reached through a call, cast or match result is then caught only if its declared type is write-only (:3740-3767).
- `validate_observation_access` returns "not an observation" when the declared type lookup or the reference-shell lookup fails (:3749-3757).
- Any stored reference type is a replaceable leaf under `&write` (:2472-2480).
- `access_views::validate_expression` does not descend into `SavedSubject` (:1389-1391).
- In the refusing direction: undetermined write-only input (`InputWriteOnlyAccess::Incomplete`) is treated like present and refused (:2173-2174, :3426-3427); unresolved transition or call targets yield an empty parameter list, so arguments are scanned with no receiving type and any mention of a root is reported as a read (:3115, :3175); an unknown fetch operation is refused (:1241-1243).

## Surprises

- **The `&write self` receiver path is dead code.** `WriteOnlyRoot.receiver_machine` is a private field (:2047) and every constructor sets it to `SymbolHandle::invalid()` (:2136, :2157, :2523, :2526, :2571; confirmed by grep). So `receiver::machine` always returns `None` (:1964-1972), and with it `receiver::record` (:1926), `receiver::field` (:1938), `projection_record` (:1951), `attached_field` (:2004) and `bare_field` (:1992). Consequences: `attached_root` is always false (:1803, :1686, :2634); the `bare_field` fallback in `resolve_projection` never succeeds (:1805); `mentions_name` reduces to head-symbol equality (:1978-1990); the `receiver::record(...).is_none()` test at :2188 is always true; `whole_root_replacement_is_admitted` reduces to its first alternative (:2436-2438). The diagnostics still describe the capability ("an exact checked `&write self` target on the whole receiver", :2036; "a consuming `self` receiver", :3507). Two constructors wrap the invalid handle in a stray block, `{ SymbolHandle::invalid() }` (:2136, :2526), which looks like the residue of a removed computation.
- **A bounds test with no effect.** `if start > end || end > collection_len { return true; } true` (:2992-2995). Both branches return the same value and neither reports anything.
- **Index bounds are claimed but not checked here.** The selector closures discard the array length (:1738, :1761), and the element-assignment helper accepts any non-literal index (:3028).
- **Mutability of a local changes which type equality applies.** An immutable `let w: &write T = &write x.f` goes through `local_formation`, which uses `type_references_match` and demands the "declared constraint atoms exactly" (:1616-1622). A `mut` local makes `capture` return `None` (:1645-1649), and the same initializer then goes through `write_only_call_subloan`, which compares `stored_structural_type_identity` and asks only for "compatible stored carriers" (:2659-2668, :2680).
- **`walk!` macro** (:3189-3193) expands to a plain `validate_expression` call but takes its six arguments separated by `=>`. It is used four times (:3275, :3341, :3492, :3559) next to direct calls of the same function. No reason is given.
- **Plan replay checks the compiler's own output.** The "no longer names its exact ..." and "changed its ..." diagnostics (:927-1160) compare a plan synthesized by an earlier stage with the program tables. They are internal consistency checks, not rules a user program can break by its own text, and they depend on naming conventions (`<policy>::plan`, accessor machine suffix) and a slot-numbering convention (:886-912) that another module owns.
- **Diagnostics say "parameter" for locals.** Roots include `&write` locals (:2143-2163), but the messages at :2191, :3518, :3770-3776 and :3689 all say "write-only parameter".
- **Locals count as roots regardless of statement order.** Root collection scans all local declarations of the state up front (:2143-2163); `projection_sources` with `None` likewise includes every local (:2540-2578). Only `local_formation::capture` stops before the local being formed (:1672-1676).
- **Possible conflict for atomic read-modify-write on accessor fields.** `fetch_operation` reads the operator from `atomic.value` as a binary node (:1539), and `validate_expression` then walks `atomic.value` with `atomic_place_allowed = false` (:1334), descending into both operands (:1345-1348). If the left operand is the accessor field place itself, the "is an accessor, not an ordinary value" diagnostic at :1297-1303 would fire on an admitted fetch. I cannot tell from this slice how the typed tree shapes that operand.
- **Small leftovers.** `#[allow(clippy::too_many_arguments)]` sits on the two-argument `plain_record_for_type` (:614-618). The `continue` at :184 is the last statement of its loop. `validate_custody_leaf` prints type names with `unwrap_or_default()`, so a failed text lookup prints an empty name (:379-382). `has_checked_write_only_implementation` is computed twice for the same machine at :2164 and :2178. `write_only_call_subloan` is named for calls but also serves assignments, locals, returns and transitions through `validate_received_value` (:3292-3303).
- **Against property 3 in one respect.** The write-only read check itself (`validate_observation_access`, :3720-3785) is one function keyed on root symbol and declared type, used for every expression position; the per-placement code is only the receiving-type lookup around it.
