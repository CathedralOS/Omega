## What this code is for

This file builds the type and domain catalogs that the old checker published beside each checked machine body (the "Unit plan"). Its header says "Structural type, shape, claim, and return-custody helpers" (L1-3). The central object is `ShapeCollector` (L2585-2623): given a source type reference it produces one `CheckedUnitStructuralTypePlan` row per type identity (record, sum, mixed, fixed array, reference, borrowed slice view, byte sequence, primitive scalar, atomic cell, opaque with selected representation) and one `CheckedUnitStructuralDomainPlan` row per (domain, carrier) pair. Around the collector sit helpers that decide what a callable's declared result looks like (L115-249), which domain memberships each parameter, result or state arrival carries (L975-1183, L4351-5262), which `[erased]` parameters own no slot (L1602-1853), which owned affine parameters a Unit return must discard (L711-974), and which scalar field restrictions (bounds, predicates, atomic cells) a field type keeps (L443-707). It also contains a mechanism for planning several machine bodies in parallel against copies of the collector and replaying their writes only if nothing they read changed (L1883-2529). Nearly every function returns `Option` or `bool`; `None`/`false` means "this plan is refused" and the caller (outside this slice) decides what the user sees. The file emits no user diagnostics of its own apart from three internal `&'static str` reasons (L4909, L4976, L4990). It makes no call to a proof kernel; its comments repeatedly say that registering a domain "describes its theory" and "establishes no membership" (L2747, L2793-2794, L4794-4795, L5057).

## Mechanisms

1. **Speculative parallel planning with consult tracking** (L1883-2529). Each machine body plans against a fork of the collector (`fork`, L2378-2382). `ConsultedMap` (L1925-2130) keeps a shared base map, a per-fork overlay, the set of keys read (behind a `Mutex` so `&self` reads can record), and the rows written with their prior value. `edits_since` (L2417-2469) packages what a fork read and wrote; `ChangeLog::admits` (L2324-2337) accepts a fork if no key it read changed at or after its base position, and `apply` (L2472-2495) replays the writes. A stale fork "plans again from the merged collector" (L1898). Limits: cleanup-control arenas are replayed only when no other body appended since the base (L2327, L1900-1903); reading the whole catalog (`iter`, L2032-2036) makes the fork depend on every type change. Serves compile speed, not a language feature.
2. **Type-shape collection with recursion markers and a request memo** (L3359-3703, L3734-4112). `add_type` memoizes on (type reference, binders, substitutions) per arena slot (`CompletedRequests`, L2219-2308); `in_progress` marks identities being built, and a re-entry returns `None` for value recursion (L3467-3469, L3579-3581, L3776-3778) while a stored reference records only the referent identity without expanding it (L1877-1880, L3103-3106). Bound: `add_logical_type` loops at most `type_reference_count()+1` times (L3346).
3. **Domain predicate closure** (L260-440). Lowers each domain's proof facts to a boolean expression under a 4096 budget, then two memoized recursive passes with cycle detection compute completeness and conjoin parent predicates, with simplification of `true`, `false` and equal operands (L412-423).
4. **Scalar interval intersection** (L558-706). Walks `Constrained` shells, intersects exact domain intervals in arbitrary precision, clamps to the carrier, and produces `Scalar`, `BoundedInteger`, `RefinedScalar`, `Atomic` or `AtomicBoundedInteger`.
5. **Reachability fixpoint for catalog pruning** (`retain_transitive`, L4245-4325). Starts from root identities and follows referent, element, field, schema, descriptor-presentation and opaque-carrier edges until the set stops growing, then drops every other type and domain row and clears the memo.
6. **Typed-reference visitor for layout queries** (L1461-1599). Walks the typed program once, tracking the lexical owner, and records every call that carries a `layout_query`, with the binders of its enclosing signature.
7. **Generic substitution walk** (`substituted_formal_type`, L1389-1408): last binding wins; a binding to itself stops the loop.
8. **Canonical carrier index** (L2634-2659): for each generic-instance identity, picks the data declaration with the lowest symbol arena index, skipping per-occurrence application views.
9. **Moved-path type projection** (L920-973): walks Field / Case+Field / FixedIndex segments through catalog rows.

- `PrimitiveType::from_name(name.as_str())` decides whether a `Named` type reference is a primitive scalar (L1437) and whether a named type is a data declaration (L3650).

- Member identities are built as `CheckedMemberIdentity::of_member(identity, name.clone())` for fields and cases (L1197, L3942-3945, L4236); path matching then compares the whole identity (L935, L945, L954).
- A synthetic `StateParameter` for a domain subject carries `name: domain.subject_name.clone()` (L283-288).

## Surprises

1. **No proof-kernel call in 5,365 lines.** The only contact with proof evidence is `recorded.is_some_and(|row| row.evidence_term.is_some())` (L4413), a presence test. Every other decision is this code's own `Option`/`bool`. This fits property 1, with the qualification that the file is a planner that describes shapes, and its comments say so repeatedly.
2. **The record's `requires` interval is computed for every field but used only for atomic fields.** `retain_scalar_field` reads `stated` only inside `if atomic` (L638-649). Callers compute and pass it for all fields (L488, L3891-3898, L3925-3934, L4025-4027), so for ordinary scalar fields the argument has no effect on the retained restriction.
3. **Comment and code disagree on re-checking a second presentation.** L2573-2577 says another presentation of an already-registered identity "still checks its complete shape". For primitives, arrays and data the code returns as soon as `self.types.contains_key(&identity)` (L3494-3496, L3773-3775) without building or comparing a shape. Only the byte-sequence, slice-view and reference paths go through the comparing `register_type` (L3461, L3490, L3148).
4. **Arrival domains look like a union over contexts.** The comment says internal state signatures "retain the qualifications proved on every arrival" (L4887-4888), but the loop adds a qualification when any one entry semantic context contains the fact (L4920-4999). Nothing in this file intersects across contexts. Whether `entry_semantic_contexts` is already a join is outside the slice.
5. **Quotient data copies its carrier's plan and changes only `identity` and `copyable`** (L3779-3788). `owns_linear_claim`, cleanup flags, `source_declaration` and native identities stay the carrier's, so a quotient declared linear over a non-linear carrier would keep `owns_linear_claim: false`.
6. **Opaque data with a selected representation mixes two declarations.** After `data = carrier` (L3860), fields come from the carrier, while `copyable` and `owns_linear_claim` were taken from the opaque declaration (L3769, L3789). The record path then writes `source_declaration: data.symbol`, which is the carrier's symbol (L4077); the sum/mixed path leaves `source_declaration` at its default (L3955).
7. **The canonical-carrier swap discards substitutions** (L3760-3768): when a different declaration owns the identity, the caller's substitution list is replaced by an empty one.
8. **`retain_transitive` over-retains byte view elements.** Any retained byte-sequence row keeps every element type ever registered beside any byte view (L4269-4271), not just its own.
9. **Catalog pruning bypasses consult tracking.** `ConsultedMap::retain` and `into_values` settle the overlay and edit rows without recording a read or write (L2079-2086); `retain_transitive` uses `retain` (L4322). This is safe only if pruning never runs on a fork that will later be judged by `admits`; the file does not enforce that.
10. **Optimistic concurrency inside a checker.** Parallel planning with read-set validation and replay (L1883-2529) is a capability I would not have expected in this stage. The reads are recorded through a `Mutex` that ignores poisoning (`PoisonError::into_inner`, L1951, L1979, L2035, L2105).
11. **`apply` overwrites two whole fields from the fork**: `unselected_opaque` unconditionally (L2491) and the entire `cleanup_control` when the fork appended (L2492-2494). The second relies on `admits` having checked that no other body appended since the base.
12. **Bounds wider than 64 bits refuse.** Final bounds go through `to_i64()?` / `to_u64()?` (L685-697), and stated intervals are `Option<i64>` (L530); a 128-bit field with a bound outside the 64-bit range yields `None`. The missing stated endpoints default to `i128::MIN` and `u128::MAX` regardless of the carrier's sign (L641-642).
13. **The structural signature check accepts only `ensures true`** (L4485-4488) and only whole-parameter `requires` memberships already present on the plan (L4452-4484). Everything else returns false. The rule is narrow by construction.
14. **A helper that is only an alias.** `add_affine_array_construction_type` calls `add_type` and nothing else (L3705-3711).
15. **A no-op trait impl.** `impl Extend<SymbolHandle> for QuerySubjects` discards its input (L1517-1519), apparently to satisfy the visitor's bound.
16. **`add_accessor_attachment` scans the access-view plans twice** for the same field (L2949-2955, then L2958-2963) and hard-codes `byte_alignment: 1` (L2983).
17. **Refusing rather than losing a membership.** The fixed-array `missing_membership` test (L3583-3607) refuses an array whose scalar element type has a qualification that would not survive as bounds or a predicate. This is a case where the old code declines instead of accepting.
18. **A relaxed past rejection is recorded in a comment**: "Requiring an issuance route here incorrectly rejected preserved input qualifications" (L4628-4629).
19. **Property 2 mostly does not hold here.** Apart from `$T{n}` binder strings, `PrimitiveType::from_name`, and names carried inside member and domain identities, this file works with handles and identity ids.
20. **Property 3 holds in a specific form.** The repeated thing is not an expression rule per placement but the question "which carrier does this membership qualify", answered separately for call result, boundary parameter, boundary result, ordinary result, parameter entry and state arrival.
