## What this code is for

This slice is the second half of the module that turns Omega's mathematical layer into terms for the proof kernel (`proof_admission`). It takes authored mathematical declarations (`MathematicalDefinition`) and generic `data` declarations whose parameters are `Type` or `Value` ("indexed families", for example a vector indexed by its length) and builds kernel declarations for them. An indexed `data` family becomes an indexed W-type: the code generates five terms (index type, label carrier, child positions, `out`, `next`) from the data's fields, variants, `requires` facts and recursive fields (:8482-8583, :10871-11242). A struct literal of such a family becomes a `sup` term whose constraint proof comes from an integer-arithmetic prover (`SourceIntegerTheory`) (:6506-7026). A property that must hold for every value of a family becomes an induction theorem built from one lemma per constructor case (:7223-7606, :8919-9078). The top-level `check_mathematical_signature` (:11931-12025) and `Elaborator::check` (:12388-12517) elaborate every authored declaration, then hand the whole declaration list to the kernel's `check_signature_with_attribution`, then type each mathematical application expression and store it in `PreparedMathematicalApplications` for later stages. About 1,320 lines (21%) are unit tests that run the generated terms through the kernel. The public entry `check_mathematical_declarations` (:12688-12703) returns an empty result when the program has no mathematical definitions and no demand for family evidence.

## Mechanisms

- **Indexed W-type description of a `data` family** (`terms::description`, :8482-8583; `Builder`, :8145-8446). From the ordered common fields, the per-case payload fields, the per-case constraint function and the per-case child-index functions, it builds: the index type (a Sigma chain over index fields, or a boxed unit when there are none, :8176-8194), the label carrier (Sigma over common fields of a tagged sum of case payloads, :8303-8322), the child-position type per label (:8346-8357), `out` (projects the index fields from the label, :8428-8445) and `next` (selects the child's index by position, :8358-8366). A sum of n cases is a right-nested `Sigma(tag : Two) …` (:8303-8315); n child positions are a right-nested `Sigma(Two) …` of boxed units (:8083-8095). Serves indexed `data` families.
- **Named-binder term language `S` compiled to de Bruijn indices** (:7775-7933). Binders are keyed by `Key::Source(SymbolHandle)` or `Key::Internal(usize)`; `S::term` walks with a scope stack and fails if a variable is not in scope. This lets constraint functions be moved under eliminators without capture (comment :7737-7739).
- **Universe lift by contractible padding** (`level_unit`, :8058-8082; `lift_payload`, :7999-8014; `description` :8503-8540). For `A : Type u` it builds `Box((a : A) → Squash(Id A a a))`, inhabited for every `A`, and pairs its canonical inhabitant in front of a lower-level payload. A multi-case family whose payload level is above 0 gets one shared product of all case payload types as `A`, stored as a definition. Limit: applied only when `cases.len() > 1` and the level is not 0.
- **Interning descriptions under external parameters** (`intern_description`, :8588-8688; `apply_description`, :8690-8713; `SourceFamily::at_levels`, :10680-10722). Each of the five description terms becomes a definition abstracted over the Type parameters that never change in recursive children; uses apply them to actuals and instantiate universe levels.
- **Uniform-parameter analysis** (:10899-10949). A Type parameter is "external" when every recursive field passes exactly that parameter back (`Named { symbol } == parameter.symbol`, :10917). If any Type parameter changes, all Type parameters become indices (:10921-10927). Value parameters are always indices.
- **Constructor evidence builder** (`source_family_constructor_term`, :6506-7026). Recursive over struct literals and erased immutable locals, depth bound 128, with six kernel `check_type` calls per literal. Each kernel call gets a fresh `Budget::new(DEFAULT_CONVERSION_STEPS)`, so there is no total budget per program.
- **Induction theorem generator** (`source_family_induction`, :7223-7606; `terms::induction`, :8919-9078; `InductionBuilder`, :8715-8881). Per case it declares bodyless constants for the fields, asks the integer theory to derive the goal from the constraint and child hypotheses, abstracts the constants, and stores the lemma as a definition. It then builds the step function by case elimination on the label, transports along a reflexivity proof that the re-packed label equals the label (`reconstruction_equality`, :9035-9054, :8854-8874), and applies the kernel's W induction (`family.ind`, :9072).
- **Induction memo** (`CheckedSourceInduction::reusable`, :7172-7187). Keyed by structural equality of invariant and parameter actuals plus the rule that the stored declaration list is a prefix of the current one. Each entry stores a full copy of the declaration list (:7702).
- **Instantiating an open induction at closed indices** (:7608-7686). When the index actuals contain no variable, it finds a cached open induction with the same parameter actuals and applies its theorem to the index tuple, instead of proving a new numeral fact.
- **Demand discovery** (`needs_scheme`, :10349-10433; `erased_family_demands`, :10435-10531). Decides whether the W scheme and integer theory are loaded at all and which families are built without being mentioned by a mathematical declaration.
- **Family reachability search** (`declaration_contains_family`, :10533-10652). Depth-first search through type references and data declarations with two visited lists; finds whether a type reaches the family being defined. Used to refuse nested and mutual recursion.
- **Universe scope save/restore** (`mod source_levels`, :11537-11632). Entering a family swaps out the level binders of the enclosing declaration and gives each Type parameter its own level.
- **Term order key** (`mod term_order`, :11633-11812). Serializes a kernel term to bytes (tag per constructor, little-endian indices) to give terms a total order. Callers are outside this slice.
- **Final pipeline** (`Elaborator::check`, :12388-12517). Demand families, collect applications, kernel-check the signature with attribution, check domains, infer each application's type, normalize it while keeping a set of retained constants opaque (`retained_application_constants`, :12519-12538), store results.

## Accepts or skips without proof

- **Placeholder for a recursive application** (:10777-10781). While a family is being built, `indexed_application` returns the term `Type 0` for any application of that family. `source_family` refuses the same situation (:10815-10819). Direct recursive fields are taken out before elaboration (:10887-10894, :10995-11000) and nested uses are refused by `direct_child` (:11267-11274), but a recursive field whose Type argument is itself the family (for example `Tree[Tree[T]]`) is a "direct child", and its Type argument goes to `index_operand` → `elaborate_type_reference` (:11429-11431, :11076-11080). If that function calls `indexed_application`, the child's index becomes `Type 0`. `elaborate_type_reference` is outside this slice; I cannot tell. The kernel would check the resulting description, but a description with a wrong index can still be well-typed.
- **Alias domains replaced by primitive carriers** (`kernel_primitive_domain`, :11358-11377; used by `close_family_telescope`, :11378-11389 and `kernel_field_domain`, :11351-11357). A domain that is a source alias constant is swapped for its primitive carrier term with no check at that site; when no alias is found the domain is kept. The test helper `close_source_telescope` asserts by kernel conversion that the two forms agree (:9917-9950); production code relies on the later kernel checks of terms that use the closed function.
- **Kernel failure used as "this invariant is open"** (:7308-7315, :7656-7662). `infer_sort(goal).is_ok()` means closed, `is_err()` means open, whatever the error was. A budget failure or an ill-typed goal is treated as "open" and goes to the general path, which is kernel-checked later.
- **`closed_predicate` returning `None`** falls through to the general induction path without a message (:7344-7365).
- **`instantiated_open_induction` returns `Ok(None)`** on count mismatch, on any index actual that "mentions a variable", and when no cached induction matches (:7614-7618, :7624-7629, :7663-7665). `term_mentions_variable` answers `true` for every term kind it does not list (`_ => true`, :7218), so closed terms containing `Fst`, `Snd`, `Sigma`, `Id` and others are treated as open. This only skips a shortcut.
- **Evidence recording skipped** when inside a constructor owner context or when a row for the expression already exists (:6486-6492).
- **Constructor-context values returned without a check at the lookup** (:6524-6531). The surrounding kernel checks of child, label and final term cover the use.
- **Demand walks ignore other type shapes**: `needs_scheme::reference` returns `false` for `Named` and all other nodes (:10386); `erased_family_demands::demand` does nothing for them (:10497). The constructor code follows `Named → generic_instance` to find the family (:6748-6757), the demand code does not. An erased binding typed through a named instance of a family would not create demand here. I cannot see whether another path covers it.
- **No demand, no check** (:12691-12695). With no mathematical definitions and no evidence demand, `check_mathematical_declarations` returns the default result with no signature.
- **Open terms** (:12280, :12335, :12339, :12349, :12351). Calls to targets that are neither authored mathematical declarations nor in scope, non-integer arithmetic, operators with no proposition denotation, members not in scope, and every expression kind not listed (`_ =>`) become `self.open_term(handle)` instead of a refusal. `open_term` is outside this slice; I cannot tell what it assumes about the value.
- **Identity requirements dropped** for every expression that is not a `Name`, `Call` or `Binary` (:12208-12213).
- **Float literal with an unknown carrier** is skipped with `continue` when meanings are stored (:12554-12560).
- **`retain_checked_source_application` runs only when there are no captures** (:12473-12477). What it retains and what applications with captures lose is outside this slice.
- **Index alias fallback** (:11443-11447): a symbol not found in `aliases` is used as itself.
- **Data-level `requires` facts on a family with variants**: they are added to the constraints only in the no-variant branch (:11015-11025). For variant families the constraints come from `validation::case_predicate_expressions` plus the case's own facts (:11010-11014, :11026-11034). Whether `case_predicate_expressions` includes the data-level facts is outside this slice; if it does not, they are not part of the family description.
- **Bodyless assumptions stay in the signature.** Constructor parameters (:6464-6467), per-case field values for induction (:7474-7481) and authored `MathematicalBody::Assumption` declarations (:12085) are kernel declarations without bodies. `excludes_parameters` (:7554-7564) and `source_constructor_dependencies` (:6436-6451) check that stored lemmas and labels do not depend on the temporary ones. - **Panics instead of refusals**: `.expect(..)` at :7388, :7419, :7505, :7697, :8963, :11127, :11147; `unreachable!()` at :11189 and :11436. The parameter-kind ones are guarded by the Type/Value check at :10830-10839.

## Surprises

1. **This slice contradicts property 1 for its own area.** Almost every acceptance is a kernel judgment: `check_type` (:6358, :6788, :6864, :6921, :6995, :7013, :7718), `check_signature` after each family (:10861), `check_signature_with_attribution` over all declarations at the end (:12395), `infer_type`/`infer_sort` (:7673, :8521, :11348, :11459, :11600, :12423, :12449, :12463). The header comment says so explicitly (:7732-7735). The code's own yes/no is limited to structural pre-checks (counts, node kinds, symbol matches) that refuse before the kernel runs, plus the items listed under "Accepts or skips without proof".

2. **Evidence for a named value is re-derived from source, not carried by the value.** When a constructor operand is a name, the code searches the owner machine's states for the local's declaration and re-elaborates the local's initializer expression (:6532-6599). It then has to prove by hand that the name still means that expression: immutable, erased, same type identity, single declaration, same state, later statement (:6543-6598). Each use re-runs the whole constructor derivation for the initializer; the only memo is the linear scan in `source_family_constructor` (:6486-6492), which avoids a duplicate row, not the work.

3. **Data-level `requires` facts are conjoined twice for a family without variants.** The no-variant roster passes `data.requires_facts` as the case facts (:10971), and the loop body adds `data.requires_facts` again when the case symbol is invalid (:11015-11025) before adding the case facts (:11026-11034). Each data-level proposition therefore appears twice in the Sigma chain, and every constructor and induction case must prove it twice.

4. **Two answers for one situation.** A family requested while it is being built gives a refusal from `source_family` (:10815-10819) and the term `Type 0` from `indexed_application` (:10777-10781). See the first item under "Accepts or skips without proof" for the path that may reach the placeholder.

5. **Failure attribution blames the next authored declaration.** On a kernel failure, `check` picks the first authored declaration whose position is at or after the failing declaration (:12397-12400). A failing generated declaration (a literal, a family description, a lemma) that sits before an authored declaration is reported as "mathematical declaration `X` fails kernel checking" for an `X` that did not fail.

6. **Cost.** Every kernel call builds `Signature::from_declarations(self.declarations.clone())` (for example :6358, :6442, :6787, :6863, :6969, :7012, :7287, :7619, :7716, :11344, :11450). Each cached induction stores another full copy (:7702). `source_family` returns `family.clone()` on every lookup (:10813), which copies every cached induction and its declaration list. `source_family` re-checks the entire signature after each new family (:10861) and `check` checks it again (:12395). `OwnerEnvironmentIndex::new` is built for every name operand (:6580-6581) although the `Elaborator` has a `source_owners: OnceLock<OwnerEnvironmentIndex>` field (:11911).

7. **A literal index is a type reference whose name is a number.** The index value comes from parsing the name text of a `Named` node with an invalid symbol (:11482-11506). This is the one place in the slice where text decides a value.

8. **The kernel error is thrown away at :11348.** Any `infer_sort` failure on a payload field's type, including a budget failure, is reported as "has an open dependent carrier whose encoding is unsupported".

9. **A misplaced doc comment.** The comment at :9844-9846 ("Check actual dependency closure rather than the ambient signature roster…") describes `excludes_parameters`, but it is attached to `mod indexed_vector_budget_tests`.

10. **Dead or redundant pieces.** `source_constructor_operand` takes `_expression` and never uses it (:7030). `PreparedSourceConstructor` is filled with `expression` and `constructor: expression`, the same handle twice (:6421-6422). `Builder::lift_count` wraps one field read (:8210-8212). The `uniform` flags for Value parameters start `false` and are still and-ed in the loop (:10899-10918).

11. **`term_order_key` is not self-delimiting for constants.** A `Constant` writes its level list with no length or terminator (:11656-11665), and level tags 0-3 (:11791-11806) overlap term tags 0-3 (:11646-11660). Two different terms can produce the same bytes if the same declaration appears with different numbers of levels. For well-formed terms a declaration has one fixed level arity, so this needs the terms to have passed the kernel first; the callers are outside this slice.

12. **`HashMap`, `HashSet` and `BTreeMap` keyed by dense handles** hold the elaborator's state (:11815, :11873-11875, :11893-11897, :11913, :11917), and `retained_application_constants` builds a `HashSet<u32>` of declaration positions (:12519-12538).

13. **The integer theory is loaded only when `needs_scheme` is true** (:12002-12020). A constructor or induction that reaches the "no shared integer vocabulary" refusals (:6824-6828, :7530-7534) means demand detection and use disagreed; the demand walk's blind spot for `Named` references (:10386, :10497) is one way that could happen.
