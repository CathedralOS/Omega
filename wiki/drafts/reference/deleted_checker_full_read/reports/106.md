## What this code is for

The slice is the second half of the module `normal_returns` and the whole of `resolution_inputs` and `resolution_queries`, all inside the `StructuralJudge` (the old checker's symbolic reasoner for contracts). `normal_returns` is a symbolic evaluator: it walks a machine body's statements and expressions in execution order and, for each feasible path, produces a symbolic value (`StructuralTerm`) together with a cloned judge that holds what is known on that path (64397-64403, 65709-66530). It splits paths at `and`/`or`, at `match` arms and at `is Case` tests, drops a branch when the judge refutes its guard, and adds the guard as an assumption on the branches it keeps (62444-62604, 62851-63085, 63088-63165). When it reaches a call it takes in the callee's `ensures` equations, case guarantees and content guarantees, applies the call's write frame to its model of storage, and records "post-call storage" (62283-62406, 67048-67064). It also serves "observation" queries from other modules: stop just before an operation and report the argument values, or report the value of one sub-expression (64948-65181). `resolution_inputs` and `resolution_queries` are a memo cache for the judge's term resolution and predicate judgments, keyed by the pointer identity of the judge's 20 internal fact tables, with a recursion guard for unfolding applications (67254-68297). About 1,450 lines are unit tests, almost all of them for the cache (64020-64087, 68299-69676). Nothing in the slice emits a user-facing diagnostic: every refusal is `None` returned to a caller outside the slice.

## Mechanisms

- **Path-sensitive symbolic evaluation with one judge per path.** `evaluate_normal_paths` → `evaluate_normal_value_paths` → `evaluate_normal_operands` (65577-66530). Each expression returns `Vec<NormalReturnPath>`; operands are evaluated left to right (or in the call's declared order) and every operand multiplies the path list. The judge is cloned per path. Depth budget 64 (65821). Logical operators use an explicit stack of `LogicalFrame` instead of recursion (65719-65780, 62432-62604). Serves every body expression: contracts at calls, facts after guards, storage after writes.
- **Rejoining pure paths** to limit path growth: after a logical expression (62531-62557), for short-circuit outcomes (62559-62601), in `normal_completion_paths` (64937-64944), and after a call's operand paths (66462-66528). The last also merges several captured results of the same call into one fresh captured value with the joined integer range (66483-66527).
- **Demand and stop protocol.** `NormalValueDemand` has five modes (`Value`, `Completion`, `Location`, `Observe`, `ObserveOnly`, 64591-64597) and `ObservationStop` three stop points (64513-64518). One walker answers "value of this expression", "state just before this operation with its arguments", "state after this value", and "which roots completed" (64948-65181). `OperationRequests` precomputes which sub-trees contain a requested operation using parent links over `VALUES` edges (63965-64009).
- **Sequential match refinement** (62879-63079): keeps a `remaining` set of subject paths; each arm splits it into "selected" and "skipped".
- **Captured-value identity resolution** (`completed_value_identity_at`, 64809-64898): rewrites a later captured value to an earlier one using recorded result equations and completed reads, oriented by capture occurrence number so rewriting cannot loop; depth 64; does no arithmetic folding.
- **Nominal receipts** (`CompletedNominalValue`, 63501-63706): each owned read of a data value records (anchor expression, type, fresh capture, observed value); chains are followed at most as many times as there are receipts (63536, 63646).
- **Memo cache for judge queries** (`CompletedResolutions`, 67574-67793): up to 8,192 entries; eviction picks the least recently used entry by a linear scan of ages (67771-67790); buckets keyed by a term fingerprint and a hash of 20 allocation addresses. A key holds `Weak` pointers to the judge's tables, so a later `Arc::make_mut` on a table must reallocate and the key no longer matches (67262-67310; pinned by test at 68575-68602). Each entry stores the recursion-guard questions it asked and their answers (at most 256, 68066-68067); it is reused only if those answers would be the same now (67754-67760). Four query kinds share it: resolution, integer projection, predicate, application equations (67620-67625).
- **Recursion guard for application unfolding** (`resolving_application`, 68085-68111): a linked list of active applications; depth is carried forward as the maximum seen.
- **Returned-field dependency trace** (68113-68136): records which callees a resolution visited and the lowest index in the owner chain, for the current judge and every ancestor frame.

## Accepts or skips without proof

- **Data invariant taken on trust at a local binding** (62128-62159). The comment says every construction and write is checked elsewhere, so the bound value "brings that invariant with it". Nothing in the slice checks it. The pending-recast exception (62138-62143) is the one case withheld. Cannot tell from here whether every producer is in fact checked.
- **Call statement completes even when its guarantees could not be derived** (62341-62397): the whole intake is one `if let … &&` chain; on any failure the judge proceeds with storage effects only. This loses facts rather than adding them.
- **Fact-only citation is given an empty, complete write frame** (62335-62336) on the word of `is_fact_only_requirement_citation`. Cannot tell what checks that classification.
- **Match with an invalid capture handle or invalid anchor passes the subject through unchanged** (62751-62753, 62764-62766) instead of refusing.

- **Detaching a returned nominal value falls back to the plain resolved value** when any condition fails (63498). Cannot tell whether a callee-local term can leak to the caller this way.
- **Missing type falls back to the enclosing receiving type**: `unwrap_or(scope.2)` (61996), `receiving.unwrap_or(scope.2)` (66145), `actual.unwrap_or(receiving)` (65226), struct field type failure becomes an invalid handle (63783) which is then filtered out (66137) and replaced by `scope.2`. ## Surprises

- **Two notions of term equality are in use, and the slice mixes them.** Tests assert that terms differing in observed type are `==` (68506-68510, 69319) but not `same_resolution_payload` (69320). The cache and nominal receipts use `same_resolution_payload` (67753, 63350, 63575, 63667). Other decisions in the slice use plain `==`: the "all arms agree" rule (63228), the short-circuit merge (62565), captured-identity rewriting (64886), the scalar observation match (64698), projection root match (64729) and the descriptor match that selects a reference source (66817). Those decisions therefore ignore the observed type and other "authority" fields that the cache was fixed to respect.
- **The cache's soundness rests on an allocator property.** Judge inputs are compared by `Arc` address. This is a valid version stamp only because each cache key holds a `Weak` to the table, which forces `Arc::make_mut` to move the data on the next write (67262-67310; test 68575-68602). A table mutated by any route other than `make_mut`, or a field not in the 20-owner roster, would not invalidate entries. `ring_licenses` and `semiring_licenses` are not in the roster (67502-67503).
- **The cache was added to fix exponential re-derivation and has its own 1,380 lines of tests**, more than the tests for the rules it serves in this slice (none). Its earlier key was a hash of `Debug` text (68730-68735).
- **Eviction is a linear scan over 8,192 ages on every insert once full** (67777-67779).
- **Library shapes are hard-coded in the checker.** `completed_placement_geometry` knows case names `Ready` and `Rejected` and field paths `view.run`, `returned.source`, `base`, `length`, `count` (64301-64326) and turns them into equations the caller may rely on.
- **Integer `match` loses the negative fact.** After a skipped integer value arm nothing is recorded (63014-63049), although the judge has a `disequalities` table (67498). A wildcard arm after `3 =>` does not know the subject is not 3.
- **A dynamic-trait cast of a conformance name is special-cased by shape** (65929-65951): exact domain, no semantic domain, target is a `DynamicTrait` type, operand is a `Name` whose symbol kind is `Conformance`. It is captured as an unknown value.
- **Constant folding is blocked by observation requests.** An anonymous numeric expression is folded to one integer only when no requested operation lies inside it (65982-66005); the request index comment says it "blocks folding" (63948). The value of a term can therefore differ in form depending on what a caller asked to observe.
- **Length equality is used as "no new guarantees"** when merging call outcomes: `path.judge.normal_guarantees.len() == pre_call_judge.normal_guarantees.len()` (66492-66493).
- **Merging captured results mints a new symbolic value** (`capture_sequence += 1`, 66511-66521) with an invalid statement handle and the joined integer range, replacing the per-path captures.
- **`resolve` silently returns its input at unfolding depth 32** even when a substitution applies (test 69423-69435). A caller cannot tell "already resolved" from "budget exhausted".
- **An expression statement's operands are received at the state's return type** (63813-63815), the same as a transition value.
- **`proof_only_classification(program)` is recomputed inside per-call predicates** (62258, 67229, 67235, 67238); nothing in the slice caches it.
- **Debug tracing is compiled into the checker**: `eprintln!` behind `struct_trace()` at 63230-63235, 66078-66083, 66741-66748; one test prints unconditionally (69292).
- **`capture_position_at_site` is a one-line forwarder** to `captured_argument_position` (64231-64237).
- **`BTreeSet`/`BTreeMap` keyed by handle parts and a `HashMap` of buckets** (63951-63959, 67576) are used where the handles are dense arena indices.
- **The module boundary cuts a file that is one 69,000+ line source file with modules nested four deep**; paths such as `super::super::super::structural_terms::…` appear throughout (for example 63410, 63475, 64104), and several blocks are indented as if pasted from another nesting level (62302-62306, 63728-63759, 67234-67243).
