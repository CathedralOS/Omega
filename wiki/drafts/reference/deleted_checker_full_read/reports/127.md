## What this code is for
This file is the old checker's complete rule set for "recasts": `&x as &T` / `&mut x as &mut T` / `&x as &[T]`, which re-view the bytes of an existing storage place as another scalar, fixed record/array, or slice shape (header comment, 1-4). Its job is to refuse any recast whose layout, size, alignment, byte-region footprint, validity facts, atomicity or write-back would let a view manufacture facts the storage does not hold. It builds a flat "leaf inventory" (offset, size, validity facts) for each type per layout alternative (2799-3995), then compares source and target inventories: shared views need "source implies target", writable views need implication in both directions (4027-4035, 4121-4128). It bounds byte offsets with interval analysis and calls out to arithmetic and contract predicates (1331-1397). It tracks "pending" record views (mutable recasts to a record that has `requires`) whose predicate is not yet established and refuses to consume them as valid values (583-966). It also exports the leaf/projection geometry (`recast_scalar_layout`, `recast_scalar_path_geometry`, `recast_record_source_leaf`, `reference_view_storage`, 2943-3320, 5019-5070) that later stages use to carry facts across a view. `validate_recasts` (5292-5415) is the driver: it judges `let r: &T = &x as &T` initializers and inline recasts, and refuses every other recast position. A second admission path (`read_admission`, 4411-4491) re-judges a retained view's original formation.

## Mechanisms
- **Leaf inventory ("representation") flattening** (`normalized_representation` 3471-3520, `mutable_record_representation_inner_body` 3605-3845, `mutable_record_type_representation_body` 3866-3948). Computes, per type, a list of leaves (offset, size, scalar facts, primitive, stored integer width/sign, byte-projection or bit fragments, field/element path, array steps). Uses the laid-out plan (`plan_laid_layout_for_data`) when one exists, else natural C-like alignment (3812-3824). Applies stored-integer narrowing (3722-3739), bit-field fragments (3740-3778), repeated array fields (3779-3799). Limits: depth 256 and work 16384 (2772-2773, 2783-2795), a `visiting` set for recursion (3616), phantom-lifetime shell depth < 2 (2357, 3931). Serves recasts of records and arrays.
- **Representation implication** (`representation_values_imply` 3997-4025). For each target leaf, binary-search source leaves at the same offset and look for one with equal size/projection/fragments whose facts imply the target's; otherwise the target must accept all bits and be inside initialized source storage. `InitializedStorageBits` (2674-2767) builds sorted merged bit ranges from non-atomic leaves and answers coverage with `partition_point`. Writable equivalence is implication both ways (4027-4035).
- **Scalar fact sets**: u64 bit-pattern interval lists (intersect 4913-4928, normalize/merge 4930-4943, signed ranges split at zero 4745-4778) and a float min/max interval (4585-4637, 4806-4829); implication per kind (4982-5017). Serves value-range facts on scalar views.
- **Closed-record eligibility DFS** (2359-2471): explicit stack, three-state coloring, budgets 4096 nodes / 16384 edges.
- **Offset interval analysis** (`composite_offset_upper_bound` 428-496): recursive upper bound for Add/Subtract/Multiply/ShiftLeft over standing intervals, literals, and unsigned floors, with `checked_*` arithmetic. `offset_expression_is_multiple_of` (498-581) is a syntactic divisibility analysis over literal, `*`, `+`/`-`, `<<`, and constant-range places. `proved_offset_upper_bound` (1332-1397) takes the minimum over declared, composite and occurrence bounds and then tries relational proofs (`occurrence_integer_expression_fits_range`, `completed_value_fits_integer_interval`). Serves byte-offset recasts.
- **Layout alternatives**: rules are run once per layout target from `layout_checking_targets` (228-234, 641-667, 1497-1510, 3269-3283, 5044-5047). `common_scalar_source_leaf` (3262-3284) requires all alternatives to agree on the same projected leaf.
- **Pending-view tracking** (583-966): finds which recasts reach an expression by asking the call-frame resolver for completed reference interpretation sources, then checks each issuing cast's formation (`formation_obligation` 625-677 recomputes source/target equivalence in every layout alternative).
- **Projection geometry** (2868-3320): `RecastScalarLayout::scalar_path_geometry` maps a structural path (fields, fixed indexes, runtime indexes treated as index 0) to offset, footprint, stride and extent, and demands a unique matching leaf (2951-2965, 2972-2979).
- **Qualification-view implication** (997-1017) over domain constraints.

## Identity by text
- Builtin scalar types are recognized by name as well as symbol: `exact_primitive_type` requires `name.as_str() == atom.symbol_name()` (4537); `exact_scalar_representation_type` likewise (4567).
- `mutable_scalar_representation_facts` decides "this is a primitive" with `PrimitiveType::from_name(name.as_str())` (4669-4672) before consulting the symbol (the symbol is used only to look up atomicity, 4681-4684).
- Const generic arguments are `Named` type references with an invalid symbol whose text is the value: `CanonicalConstValue::from_atom(name.as_str())`, `name.parse::<i128>()`, and `name.as_str() == value.to_string()` (2608-2635).
- Diagnostics are built from text: `machine `{}` state `{}`` context (1534-1538, 1753-1757); type names via `display_type_reference` and `named_type_reference` (1772-1775, 2057); `display_name(start)` for the offset (1326); "non-placed storage" placeholder (1589, 1592). These are only used to word messages.
- Reasons are `&'static str` values that travel as error data (737, 4336, 4419) and are only concatenated into messages.
- Type equality uses ids, not text: `normalized_type_identity` (979, 1662, 2058), `stored_structural_type_identity` (5029). Domains compare by `symbol` and `semantic_id` (1005-1007), paths by symbol handles (`RepresentationSegment::Field(SymbolHandle)`, 2904-2907). Member identity includes the member name text: `CheckedMemberIdentity::of_member(identity, name.clone())` (3074, 3129).
- `exact_interior_byte_region_offset` and literal checks compare integer node values, not text.

## Accepts or skips without proof
- `judge_scalar_recast` returns with no diagnostic when `defers_pending_layout_geometry()` and `pending_layout_geometry(...)` (1483-1490). Another check: `established_reference_formation` refuses when deferral is on (4420-4422), but for the original cast I cannot tell whether a later pass judges it.
- After a `Contained` byte-region footprint the aggregate and scalar paths return without comparing source and target representations (1815-1817, 1886-1888). The earlier gate requires the source be a u8 byte region and the target be fact-free (1673-1731), which covers it; except the fact-free test is skipped when `pending_view(...)` is some (1710-1712).
- A pending view with `qualification_compatible.is_none()` returns early as accepted (1796-1800); the pending-consumption rules (809-883) are the other check.
- Scalar path: if either `scalar_byte_size()` is `None`, returns silently (1902-1907); footprint falls back to 0 for an unsized target (1880).
- The atomic mismatch refusal applies only to shared views and only when both atomicity answers are known (1951-1955). `mutable_scalar_representation_facts_equivalent` (4945-4961) compares values and domains but not `atomic`, whereas `scalar_representation_facts_imply` does check it (4968-4970). A writable scalar recast between a plain and an atomic scalar of the same size therefore appears to pass 1966-1983; the writable byte-region path (1693-1695) has the same shape. I cannot tell whether another check elsewhere refuses it.
- Offset bounds: `composite_offset_upper_bound` for `Add` (439-448) and for a lone operand (436, 416-426) checks no lower bound; only Subtract, Multiply and ShiftLeft check floors (450-472, 484-487). `proved_offset_upper_bound` filters the declared and occurrence bounds for `low >= 0` (1345, 1357) but not the composite bound (1347-1348). `proved_offset_upper_bound` can end with `.or(interval_high)`, returning a bound above the needed one (1396); the caller then checks `offset + footprint <= region_length` (1250-1252) and `offset > region_length` (2106). Whether a possibly negative offset is refused depends on `upper_bound_beyond_place_carrier` and later checks that are not in this slice.
- `byte_region_footprint` returns `NotByteRegion` for non-u8 or non-region sources (1274), which the callers treat as "continue to other checks", not acceptance.
- `exact_scalar_representation_type` treats `AtomicBool/AtomicU32/AtomicU64` as their plain primitive (4553, 4560-4561); atomicity is a separate flag consulted in some places only.
- `withholds_default_predicate` returns `true` when origins cannot be resolved (804), i.e. fails closed. `pending_origins` returns an empty list when the machine has no pending formation (738-740) and `continue`s past recasts issued by other machines (757-759); I cannot tell what checks the issuing machine's side.
- `narrow_to_integer_interval` silently does nothing when an endpoint is missing or does not convert (4786-4803); that drops a fact, so it errs toward refusing.
- `report_unspelled_reference_pun` only fires when both sides resolve to scalar primitives (2307-2321); a non-cast initializer of any other shape is not judged here.
- `report_consumption` returns `false` (no error) when the expression has no type reference, is not a reference, or is not a pending record (819-829). Type errors are presumably elsewhere.
- `validate_recasts` judges inline casts with `cast.target_type` as the "let referee" (5384), so the "restate target" check holds trivially there.
- `qualification_view_compatible` returns `None` (unknown) for non-domain constraints or invalid domains (1039-1043); callers treat `None` as "no qualification story" and continue (1605, 1611).
- `closed_raw_generic_type_argument_is_eligible` treats any non-generic `Named` data with no lifetime/type parameters as eligible without checking its fields (2643-2651); the full eligibility check is run on the instance afterwards in `direct_phantom_lifetime_record_symbol` (2535).
- `4353-4354`: `.unwrap()` on `indexed_node` and `range_node` after `subslice_expression` succeeded (relies on that function's contract).

Four unit tests in `representation_implication_tests` (4130-4263), using a default `TypedTrees` and hand-built leaf inventories:
- `established_words_allow_byte_observation_but_not_arbitrary_restoration` (4163): two established 8-byte words imply a 16-byte raw byte region (shared OK) but are not equivalent to it (writable refused); widening the second word to full range makes them equivalent but bytes no longer imply the narrower words.
- `regrouping_initialized_storage_preserves_alignment_and_validity` (4191): two 2-byte full-range leaves regroup as one 4-byte leaf; narrowing the target to (0,1) breaks implication.
- `equal_logical_facts_require_the_same_fragment_encoding` (4211): equal logical bit-fragment leaves imply each other; swapping `source_lsb` of the fragments breaks implication.
- `padding_atomic_protocol_and_fragmented_encodings_are_not_raw_observations` (4244): padded (gap) leaves, atomic leaves, and non-byte-projection leaves do not imply a plain byte region.
No test in this slice exercises the diagnostics, offsets, footprints, pending views or `validate_recasts`.

## Surprises
- No proof-kernel use in this slice: no `proof_admission`, `ProofNode`, `verify_obligation` or certificate. Every accept/refuse is the code's own boolean or `Option`, or a call to the old checker's predicates (`completed_data_predicate_holds` 861, `completed_value_fits_integer_interval` 1383, `occurrence_*` bound functions 1276, 1340-1380, 2202-2218). This supports property 1.
- Identity is mostly by ids and symbols, not text; the text uses are the builtin-name checks (4537, 4567, 4670), const generic values encoded as type names (2608-2635), and diagnostics. Property 2 is only partly supported here.
- Property 3 is present as three per-construct judgments (scalar, aggregate, slice) and four per-placement entry points, plus duplicated helper walks (see Repetition), but one inventory (`MutableRecordRepresentation`) is shared by all constructs.
- Possible asymmetry on atomics: writable recasts use an equivalence that ignores `atomic` while shared/implication paths check it (4945-4961 vs 4968-4970; use sites 1692-1698, 1966-1983). Not checked against code outside the slice.
- Possible gap on offset sign: `Add` and plain-operand upper bounds do not check a lower bound of zero (439-448, 416-436, 1347-1348).
- Multiple-layout semantics: every recast rule holds only if it holds in each layout alternative (1497-1510), and `common_scalar_source_leaf` fails unless every alternative gives the same leaf (3278-3280). `read_admission` and `validate_recasts` use different entry conditions around deferred layout geometry (1483 vs 4420).
- `recast_scalar_layout`, `scalar_path_geometry`, `recast_record_source_leaf` and `reference_view_storage` are public outputs for other stages: they decide where a scalar field of a view lives (offset, footprint, array stride/extent) and whether a source leaf "covers", "preserves scalar value" or "preserves primitive bits" (3328-3349). Runtime indexes are matched to leaf paths by treating them as `FixedIndex(0)` (2958).
- A path with several matching leaves, zero extents, or ambiguous array suffix lengths returns `None` (2962-2977), so the absence of geometry is how refusal is expressed there.
- `validate_recasts` keeps `blessed` and `judged_inline` as `Vec` with `contains` (5372-5373, 5401-5402): quadratic in the number of casts. The final loop scans every expression in the program (5398), including expressions outside machine states.
- `1492` ("no complete exact layout alternative roster") is the only recast diagnostic without a source span in the main judgment.
- On error paths in the leaf inventory builder, `visiting` is left holding the symbol in several `?` exits (3629, 3681-3682, 3713, 3723, 3742); this is harmless only because the whole build then returns `None`.
- `access_view` recasts are refused outright (1586-1599) while access borrow factory calls are modeled as reference formations with `Access` or `ResidentAccess` interpretation (5204-5262); resident access checks owner qualifications by symbol equality (5157-5173).
- A "pending view" mechanism lets a mutable recast target a record whose `requires` is not yet true, and the checker tracks it until the predicate is proven (583-966, 3412-3442); it leaks from `pending_record_definition` (requires all `requires` facts be plain expressions and the type `Unrestricted`, 3433-3441).
