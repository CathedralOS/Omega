## What this code is for

The slice is the second half of the old checker's main `checks.rs`. It holds five things. First, the rest of `mod carry` (5969-8129): the check that decides whether each value still live across a call that may suspend is allowed to be kept, including the whole graph of loans (borrows) that the value depends on. Second, `mod ownership_occurrences` (8134-8998): a per-statement list of "observe", "move" and "complete" steps in source evaluation order, with a generic branch-and-join driver, used by the ownership and loan checks elsewhere. Third, `mod cleanup_admission` (9001-9196): the conditions a machine must meet before the compiler may run it automatically to clean up an owned value. Fourth, `mod crashes` (9197-11832): the checks that every place a machine can crash is covered by a `crashes` route the machine publishes, using guards known to hold on the path to that place. Fifth, `mod indexed_writes` (11837-12137), a small `mod places` (12140-12178), and the stage's entry function `check_checked_facts_recording` (12216-12418), which calls every check in a fixed order and batches their diagnostics. Sibling modules `content`, `multiplicity`, `operators`, `ranges`, `termination` are only declared here by `#[path]` (8130-8133, 12138-12139, 12179-12182). The slice contains no tests and no call into a proof kernel.

## Mechanisms

- **Loan closure for one call** (`retain_call_frontier`, 6423-6642). Starts from the loans in the call's entry constraints and the loans captured by its operands, then a worklist adds reborrow parents, supplying loans, supplied-output loans, retained call inputs and output inputs (6462-6527). No budget; it terminates because `push_unique` never adds a loan twice. Each closure member becomes a `LoanFact` row with a backing chosen by the `backing` closure (6552-6577). Serves suspension.
- **Retention fixpoint** (`retain_backing_values`, 7036-7141). Three cursors over live symbols, loans and output inputs; each marks rows `retained_for_crossing` and may add more symbols or loans, until all three lists are exhausted. This is how a live reference keeps the value it points into live.
- **Per-value lifetime join** (`retained_lifetime_demand`, 6715-7027). Worklist with a visited list over one value's loans; each row passes three match blocks (backing, source, parent resource). Returns "suspension allowed, strict otherwise" (7019-7026).
- **Completion authentication** (`outputs::completions`, 6099-6128). Recursion through transferred dependencies with an `active` stack that refuses cycles.
- **Carry-policy lattice** (7254-7323, 7747-7824, 8084-8094). Policies start `STRICT` per claim origin, are relaxed by permissions of the same origin, and intersected across origins, values and loan demand.
- **Branch-and-join driver** (`SelectedEvaluation<Custody>`, 8149-8248). Generic over the state type. Keeps a stack of open decisions; on each new occurrence it pops decisions the route has left, calling `leave` then `join`, and synthesizes the untaken sibling from the saved entry state when that sibling had no events (8205-8212). "each join runs once, without Cartesian path expansion" (8143-8144).
- **Statement occurrence ordering** (`StatementOrder`, 8722-8997). Recursive walk producing `Observe` / `Move` / `Complete` steps with a branch route and a `held_until` index that extends an access to the completion of the call that staged it (8749-8754).
- **Boolean structure split** (`boolean_structure`, 11228-11274). One step of `!`, `x == true/false`, `&&`, `||` under a polarity. Used by six collectors.
- **Bounded consequence collector** (`Consequences`, 9652-9783). Budget 4096 steps (9672) and depth 64 (9709, 9759); conjunction unions consequences, disjunction intersects them (9722-9726). Running out returns `None`.
- **Integer order reasoning** (11362-11610). Collects `<`, `<=`, `==`, `!=` relations on integer-typed operands; strengthens `a <= b` with `a != b` to `a < b` (11523-11541); closes transitively to a fixpoint with no budget (11543-11567); derives `a == b` from `a <= b` and `b <= a` (11569-11592); emits each consequence in both operand orders (11640-11663).
- **Comparison normalization** (11666-11696). Negated order comparisons flip only when operands have a total order (integers); otherwise no consequence.
- **Integer-type table** (`IntegerTypeClassification`, 11756-11831). One pass over all declarations into a dense table indexed by symbol slot with a generation check.
- **Path-conditioned coverage** (`infer_path_conditioned_guard_coverage`, 10517-10726). Per machine: state-level guard classification (10765-10852), joined per site with entry requirements and statement fallthrough (10862-10917), then matched against published buckets.
- **Byte class of a stored value** (12016-12078). Takes the value's exact scalar or integer bounds and tests every byte in the range against every byte predicate.

## Surprises

Evidence on the three properties first.

1. **Verdict source.** Nothing in the slice calls `proof_admission`, `ProofNode`, `verify_obligation` or any certificate check. The word "certificate" appears once, in a comment saying one is still needed (10477). Every rule is the code's own comparison or a question to another checker module. The entry function's verdict is "no diagnostics collected" (12409-12417).
2. **Text identity.** The suspension-carry check finds a value's claims by rendered label and prefix (7292, 7362-7373) and uses rendered argument text as the key (7852). The crash-coverage code is built on name-encoded identities; here the authors saw the danger and added a provenance check so that a name is trusted only when `crash_entry_operand` confirms it (9483-9498, 10393-10407). So this slice shows both the property and a deliberate defence against it. The loan code (5969-7208) is the opposite case: it works on handles throughout.
3. **Per-placement repetition.** Weak in this slice. The repetition here is per construct and per loan kind (see above), and the carry policy rule goes through one function for parameters, locals and arguments.

Things a careful reader would want to know.

- **A comment contradicts the code beside it.** 7210-7214 says liveness and loan backing never reconstruct a local from its name, yet the struct it documents carries `name`, liveness is asked with that name (7923-7937), and claim lookup is by label string (7996-8005).
- **Argument text as key.** For a call argument that is not a plain place (a call, an arithmetic expression), `display_name` (7852) will match no place label, so no claims are found and the value silently gets the type-wide policy. I cannot tell whether that case can carry a claim.
- **Claims without a policy row add nothing.** `effective_policy` uses `filter_map` (7261-7269): if some of a value's claims have a `ClaimCarryPolicyFact` and others do not, only the former are intersected; the latter do not count as strict.
- **Lifetime errors can be thrown away.** `retained_lifetime_demand` runs for every live value (8043-8058), but its result, even an error such as "the value names another crossing's loan", is ignored when `requires_borrow_preservation` is false (8084-8092).
- **Call identity by value.** Captured resources are tied to the call by `flow.control.calls.get(resource.call) == call` (6445, 6608-6609), a structural comparison of two call facts, not a handle comparison.
- **The check says "allowed" while stating what it does not establish.** Comments at 5981-5982 and 6712-6713 say the result grants no stack lease, no permission to park, and leaves address stability as an obligation. No code in this slice discharges that obligation.
- **Seventh guard collector bypasses the shared split.** 11196-11199 says every reader uses `boolean_structure`; `entry_value_consequences_at::collect` (9577-9619) re-implements it on another representation with its own polarity formula (9612). I checked the eight cases of `==`/`!=` with `true`/`false` under both polarities and the two formulas agree.
- **Short-circuit with a constant left side.** When the left of `&&`/`||` folds to the short-circuiting value, the right side is not walked at all (8895). Any move event recorded inside it is then appended as a conditional, unordered move (8590-8596) rather than dropped.
- **Last match arm has no branch token.** It runs under the accumulated "not selected" prefix (8864-8881).
- **Unbounded fixpoint next to a bounded one.** The Boolean collector has a 4096-step budget (9672); the integer order closure has none (11543-11567), and its relation equality includes expression handles (11347-11354), so the same pair of identities can appear several times and multiply through the closure.
- **A small order-theory prover lives in crash coverage.** Transitivity, strictness from disequality, antisymmetry, and NaN-aware negation (11515-11696) are decided by the checker's own code over canonical identities. I did not expect arithmetic reasoning here.
- **Covering asymmetry.** A site is covered when any one alternative of a bucket matches (10645-10653); a call route needs all its surviving alternatives covered (11009-11020); operator routes get no path facts at all (`&[]`, 11059), so a guard on the path cannot cover an operator crash.
