## What this code is for
This file is one source file holding two modules: `expression_types` (lines 6-7747) and `field_domains` (7749-9015). `expression_types` is the type-checking half of the old checker for expressions inside machine states. It computes the result type of an expression (`result_type`, 5081), decides whether an argument fits a required type (`argument_matches_type_reference_using`, 6963), and reports errors for casts, float formats, operators, match patterns, match coverage, array/scalar/struct shape, and reference/borrow correspondence. `field_domains` finds which `domain` qualifications hang on which field paths of a type (rows keyed by place path), looks up fields by name or symbol, and answers questions about domain implication, byte-sequence predicates (valid UTF-8, ASCII, no NUL, non-empty) and string literals that grant a domain. Almost every function takes `&dyn CheckingInput` (the whole typed program) and walks the expression tree or type-reference table directly. Results are cached in `frozen_program_memos` maps. Diagnostics are pushed into a `Vec<Diagnostic>` as formatted strings.

## Mechanisms
- Memoized expression classification with explicit stack. `value_class` (2576) and `expression_is_float_typed` (1679) classify bottom-up using a `pending` Vec so long operator chains neither recurse per operand nor retype subtrees; answers stored in `frozen_program_memos().expression_value_classes` / `expression_float_operands` (RwLock maps keyed by `meaning_key`). Serves operator and cast validation. Class is a 3-way enum Boolean/Text/Numeric (2490).
- Result-type walk with cycle detection (4991-5607). `result_type` types an expression across four owner kinds (State, Domain, Declaration, Telescope). `ResultTypeWalk` keeps an `enclosing` stack; meeting an enclosing expression answers `None` and marks the result as cycle-dependent so it is not memoized (comment 5027-5035). Other results (including `None`) are memoized per `(state, expression)` or `(telescope, expression)`. Parameter telescopes are interned through a `Mutex` map keyed by `(owner_symbol, Vec<(symbol,type)>, trait_scope)` (4850-4862). Serves all expression typing.
- Type-reference substitution/identity matching. `substituted_reference` (4217, bounded loop len+1), `call_value_index_carriers_match` (3015, depth cap 128), `projection_receiver_type` (4477, cap 128), `place_machine_symbol` (4733, caps 128x128). Each cap makes the function return `false`/`None` on overflow. Serves generics and reference correspondence.
- `carrier_conflict` (3267): structural comparison of delivered vs required carrier by `Carrier` kind (Parameter, Data, Implementation, Primitive) and recursion over relevant generic arguments; rigid vs foreign type parameters via `parameter_is_in_scope` (3230). Serves generic calls.
- `same_result_type` (5656): structural equality over type nodes with an `active` pair stack for cycles; used by match-arm result join.
- Field-domain row collection (7764-7897): walks nominal fields (guarded by `visited` symbols), slices (one `WHOLE_ELEMENT_EXTENT` sentinel path segment) and literal-length arrays (a row copy per index, `0..length`, plus a whole-element copy marked `transfer`). Memoized per type reference in a table of `OnceLock`s sorted by `(arena_index, generation)` and found by binary search (7787-7840, 8434-8482). Serves per-field domain obligations.
- Owned-field obligations (8484-8600): same walk producing `domains`, `custody` (fields needing cleanup via `linear_claim_frontier` / `nominal_cleanup_machine_for_type`) and `unresolved` paths (recursive data, or non-primitive carriers with no known definition). Arrays are visited once with index 0 and re-indexed for every element (8548-8581). No numeric budget except array length.
- Float coercion bounds (402-451): integer bounds compared to +-2^precision of the target format; single-value cases checked by `FloatSemantics` round trip.

It pins `FieldDomainRow::describes_projection`: a row path `[field, WHOLE_ELEMENT_EXTENT, case, field]` matches itself, matches a runtime `Index` only when `is_point_index` is true, matches a `FixedIndex`, and does not match when the case segment is replaced, truncated, an `OpaqueRange`, or a `FixedRange{0,2}`; an exact `FixedIndex 0` row does not match a runtime index or `FixedIndex 1`. No tests for any of the diagnostics above in this file.

## Surprises
- Diagnostic builds a Debug dump of the subject expression, every state parameter and every local into a user-facing error (783-789).
- Array length is ignored in several comparisons (1472-1503, 3306-3326), so `&[T; 3]` vs `&[T; 4]` may compare as the same view where this code decides. Some places do compare length: `same_result_type` 5685, `fixed_array_binds_open_length` 3800.
- `call_value_index_carriers_match` (3015) is named for index/value carriers but returns `true` for `Value` parameters (3085) rather than comparing them.
- Four near-copies of "is this text": `type_reference_is_text_carrier` (1847), `is_byte_sequence_carrier` (8897), `value_class` Text, and `comparable_byte_carrier_type` (6092, defined elsewhere). "Text" is any u8 array/slice.
- `value_class` is only three classes; `u8` vs `i64` or `f32` vs `i32` are both "Numeric" so class checks never catch numeric type mismatches; those rely on separate type-identity checks (2799-2811 only reports class crossings).
- `ExpressionTypeOwner` (6846) has a single variant and `Display` only names "machine `m` state `s` terminal expression"; the same owner phrase is rebuilt by hand in dozens of format strings with `machine.name`/`state.name`.
- `validate_binary_operand_types` (1512) returns nothing but also pushes `formation_obligations` of type `IntegerRangeObligation` (1548) through `.retain(...)`: this is the one place here that records a proof obligation rather than deciding. Everything else decides yes/no locally and pushes a Diagnostic.
- `exact_declared_field` (7956), `owned_nominal_data_definition` (8340), `const_length_declared_type` (3870) and the member lookup at 4624 linearly scan all data definitions/type parameters per call (no index), while other places use a binary-searched `OnceLock` table (7833, 8475). `result_mentions_type_parameters` and `has_domain_result_shell` use `Vec::contains` for seen sets.
- Field-domain rows for a fixed array are materialised once per element (7885-7893, 8557-8581): an array `[T; 1000000]` with a domain on T produces a million rows.
- `float_coercion_preserves_denotation` allows an integer-to-float cast whose bounds are the single value `x` beyond +-2^precision if `FloatSemantics::from_integer` round-trips it (423-427); a nice special case.
- `structural_match_pattern_is_total` (685) treats `MatchPattern::Value(_)` as total and `Wildcard` as not total, while `structural_match_cases_are_covered` (993) treats an invalid-symbol case (returned for wildcard and for unconditional destructure) as covering everything; wildcard handling is therefore split between three places (616, 689, 993, 1162).
- `result_type` for `Call` is a 150-line closure with ten distinct resolution strategies tried in order (5176-5321), each asking a different module; the first that answers wins.
- `named_value_type_reference` (7446) falls back to `first_named_value_declared_type(path.symbol, path.head_symbol)`: "first" implies a search where multiple declarations could match; the `matches_symbol` closure (7472) accepts either `path.symbol` or `path.head_symbol`.
- 7592: `program.symbols.get(grandparent)` is read without checking `grandparent.is_valid()`; 2849 `program.symbols.get(path.symbol)` likewise without validity check.
- Lines 4693-4699: when `substitutions` are non-empty and the collection type is not builtin-indexed, the identity of the collection must be unchanged by substitution or the projection is refused: generic indexing is thereby limited to builtin shapes.
