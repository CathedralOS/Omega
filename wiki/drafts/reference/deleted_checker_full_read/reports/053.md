## What this code is for

This is the first 5,751 lines of the module that plans a state machine as one "composed Unit control graph" (`sg.rs:1-13`). It is a planner inside the old checker's `execution::terminal_unit` area: it takes the typed tree plus `CheckFacts` (flow, borrow, ownership, cleanup and value facts that earlier checking passes recorded) and produces `Checked...Plan` records for lowering. It refuses by returning `None` or `Err(&'static str)`; the caller turns that into a failed plan. The slice holds eight sub-modules. `closed_sum` plans a `when`-case dispatch over a closed sum as the state's terminator (`sg.rs:41-926`). `fused` decides which other machines' states are planned in the same graph (`sg.rs:927-1174`). `guards` reads retained guard values and checks that arrivals at qualified states have a recorded `requires` decision (`sg.rs:1175-1275`). `loan_backing` works out which storage must stay alive, or may be moved, when a reference is carried across a state arrival (`sg.rs:1276-3455`). `local_results` decides whether a structural result may be disposed at an exit (`sg.rs:3457-3596`). `operation_custody` admits each planned operation of a state (`sg.rs:3597-3856`). `ranking` copies the termination rank roster that an earlier pass admitted into the executable plan (`sg.rs:3857-4181`). `result_custody` counts, for every structural result a state produces, how many owners it has on the way out and requires exactly one (`sg.rs:4182-5751`).

## Mechanisms

- **Graph fusion** (`fused_states`, sg.rs:958-1074). Starts with the dispatch machine's states. A worklist adds every state of any other machine with a body that a completing transition targets (sg.rs:967-990). It then builds a predecessor list between owning machines, calls `crate::checks::termination::strongly_connected_components` (sg.rs:1020), keeps the dispatch machine's component, and runs a second worklist that also keeps the component of any target reached by a transfer that moves an activation claim (`moves_activation_claim`, sg.rs:1080-1087) or passes two overlapping references that are not both shared (`shares_borrowed_storage`, sg.rs:1123-1153). Everything else is dropped from the graph. No budget. It serves tail transfers between machines and recursion with a shared rank and constant stack (comment sg.rs:931-936).
- **Loan dependency search** (`Dependencies`, sg.rs:2831-3454). A mutually recursive walk `contents_at` -> `loan` -> `root` -> `contents_at` over borrow fact rows, with two `Vec` stacks (`active` roots, `active_loans`) for cycle detection; a cycle answers false. It answers one of two questions chosen by `StorageQuestion` (sg.rs:2825-2829): "may this storage stay alive across the arrival" or "is this storage free to be relocated". It also records `(dependent, parent)` root pairs in `captured` (sg.rs:2992-2996), which become the parent relations of the retained storage. No depth or size budget; all membership tests are linear `Vec::contains`.
- **Ingress coverage recursion** (`ingress_covers_capture_path*`, sg.rs:2364-2523). Decides whether a captured reference path is already owed to a caller-supplied parameter reference. It recurses through selected alternatives (all arms must be covered), constructed children, descriptor suppliers and stored captures, with an `active` stack of (operand, path) keys; a repeat answers false.
- **Path prefix matching with index widening** (`selected_path`, sg.rs:2949-2980). An owner path matches a selected place path segment by segment; a fixed index matches a fixed range that contains it, and a dynamic index matches any index or range.
- **Exact array tiling** (`disposed_partition`, sg.rs:5240-5277). Recursive descent over a sorted list of moved or released paths; it consumes one path per array element in index order and fails on a missing sibling or an ancestor/descendant overlap. Only `FixedArray` shapes with a literal length divide; records never do (comment sg.rs:5231-5239).
- **Disposition counting** (`account`, sg.rs:4298-5182). For each producing operation it computes successor moves, cleanup discards, reference releases, view releases, call transfers, construction transfers, stores and projected dispositions, then requires the sum to be one (sg.rs:5126-5132).
- **Construction use walk** (`construction_local_uses`, sg.rs:5598-5674). A stack-based walk of a structural value graph (records, cases, arrays, whole references, whole projections, content inputs) with a `visited` list, collecting every place argument a construction consumes.
- **Per-request memo tables**. `RetainedBorrowRecords` (sg.rs:1318-1373) groups two fact arenas by key through `KeyedRows::with_rows` on `&self`; `DeclaredStoragePlans` (sg.rs:1556-1608) precomputes declared reference owner paths per carrier type in a `SymbolKeyMap`. Both are caches; comments say they "grant no loan or retention verdict" (sg.rs:1306).
- **Rank roster selection** (sg.rs:3884-4087). Filter, sort by state handle, reject conflicting duplicates, dedup; then match runtime components and collect non-strict ("weak") edges.

## Identity by text

- A computed subject's payload read is matched by name: the member's `case_variant` name must equal `variant.name` (sg.rs:766-772), and the field is found by `field.name.as_str() == member.member.as_str()`, with the symbol compared only when `member_symbol` is valid (sg.rs:773-777). For a place subject the same test uses symbols (sg.rs:746-757).
- Case and field identities are built as `CheckedMemberIdentity::of_member(identity, name.clone())`, carrying the name with the identity (sg.rs:414-417, 533-536, 579-582); duplicate-case and coverage tests compare these (sg.rs:418-420, 537-540).
- Refusal reasons are `&'static str` values passed to `trace.phase` or returned as `Err`; they label failures and do not decide anything.
- Everything else in this slice identifies things by handles: `SymbolHandle`, arena handles, `PlaceRoot`, typed path segments, `TypeIdentityId`, binding ordinals. This is evidence against property 2 for this slice.
- A related but different habit: values are identified by source coordinates rather than by value. Examples: guard at `(state, statement ordinal, Guard role)` (sg.rs:1241-1253); return value at `(state, ordinal, Return)` (sg.rs:472-482); rank observation at `(state, statement 0, RankObservation{component})` (sg.rs:4114-4120); a call by statement index, call site kind and authored expression handle (sg.rs:1741-1753); a result's home by the local declared at its statement index (sg.rs:274-280, 836-842, 4310-4317).

## Surprises

- **No proof kernel anywhere in the slice.** A grep of lines 1-5751 finds no `proof_admission`, `ProofNode`, `verify_obligation` or certificate. `exact_outcome_case_test` is imported from `crate::published::proof` (sg.rs:81) but is used as a syntactic test of a guard. Every yes/no here is this code's own comparison of fact rows, or a flag an earlier pass set (`call_requires_decided` sg.rs:1216, `local_terminates` sg.rs:3910, cleanup dispositions sg.rs:3582-3594). This supports property 1.
- **This code is a planner that also refuses.** The header says it plans (sg.rs:4-12), and comments say planning "consumes" the checker's decision (sg.rs:1179-1182), yet it enforces about sixty rules of its own: exhaustiveness of case dispatch, exactly-one-owner for results, loan retention. A program can pass source checking and still be refused here with only a trace phase string, not a user diagnostic.
- **Possible bug, operand index.** `retained_storage` adds a leading offset of one when the authored call target is a dynamic slot (sg.rs:1816-1824). `retired_carrier_backing` selects the operand with `.nth(argument_position)` and no offset (sg.rs:2689), though `selected_call` accepts dynamic-slot calls for both (sg.rs:1773-1780). For a dynamic-slot call the second function would look at the wrong operand; the later checks would most likely then return `None` (no relocation) rather than accept wrongly.
- **Dead expression.** `false.then_some(machine.symbol).or(Some(authored.symbol))` (sg.rs:4537) always yields `Some(authored.symbol)`.
- **Unreachable refusal arms.** `EstablishLocal(StructuralValue)` and reference holds are admitted unconditionally (sg.rs:3655-3657, 3675), so the reason strings for them in the fallback arm (sg.rs:3746-3748, 3752-3754) can never be chosen.
- **Redundant condition.** `active_loans.contains(&handle)` at sg.rs:3222 was already tested at sg.rs:3197.
- **Comment and code differ.** The `closed_sum` header says "a shared or mutable loan is read in place" (sg.rs:45). For a local place loan the code accepts only `SharedBorrow` (sg.rs:182); for a parameter it accepts the shared and mutable pair (sg.rs:237).
- **Accounting passes edit the plan.** `operation_custody::admit` clears `discard_result_on_return` before checking (sg.rs:3626-3638), `subject_call` clears it (sg.rs:897-898), and `result_custody::account` sets it back to true for some views after counting (sg.rs:5179-5188). The flag that the admission rule tests (sg.rs:3790) is therefore written by three different passes.
- **The implicit-disposition bit hides double ownership** (sg.rs:5117-5126), as noted above: the "exactly one" count cannot see two implicit owners.
- **Termination ranks are executable.** `bind_observations` attaches each rank component to a scalar computation root (sg.rs:4114-4125), and non-strict edges are published as `CheckedRankEdgeCoordinate` (sg.rs:4064-4074) for "runtime components". The termination measure is not only proved and erased; some of it is carried into the executable plan. This code does not check that a rank decreases; it checks that the roster an earlier pass admitted is complete and consistent.
- **Relocation of owned storage across an arrival** (`retired_carrier_backing`, sg.rs:2615-2818) is a capability I did not expect in a checker: when a state passes a reference to its own local, the planner may move the local itself to the successor, after a graph search shows nothing else depends on its address.
- **Several machines can be planned as one graph** on the basis of recursion, moved activation claims or overlapping borrowed arguments (sg.rs:1053-1055). Which graph a state lands in changes which rules in this file apply to it.
- **`owners.dedup()` and `component_of[0]`** (sg.rs:991-995, 1029) rely on fused entries being grouped by owner with the dispatch machine first. The pushes at sg.rs:981-988 keep that grouping, but nothing asserts it.
- **Caches keep their old filters.** `call_resources` is keyed by (call, machine, state), and every caller filters on the same three fields again (sg.rs:1840-1843, 2145-2148, 2693-2696). The cache uses interior mutability behind `&self` (sg.rs:1344-1353).
- **Debug printing in checker code.** `eprintln!("CHECKSITE ...")` under `trace_flags::state_reference_diagnostics()` (sg.rs:1855-1895) and a full operations dump under `struct_trace()` (sg.rs:5133-5146).
- **Property 3 holds, with a twist.** The repetition here is less by source placement of a value and more by control shape: one ownership rule is restated for eight terminator kinds and twelve consumer kinds. The loan dependency search is the counter-example: one general mechanism serving all placements.
