## What this code is for

These three files are the ownership ("multiplicity") part of the old source checker for linear and affine values. `permission_events.rs` is the producer: for every state of every machine it walks the statements in a fixed schedule and records "permission events" (Establish, Transfer, Consume, Restore, AffineDrop) for each owned claim, plus cleanup rows that say what must be disposed at each scope exit (permission_events.rs:774-1283). `linear_validation.rs` holds both the per-statement event production (`evaluate_statement_permissions`, `complete_statement_permissions`, linear_validation.rs:2640-3627) and the validator that replays the recorded events against a roster of tracked places and reports use-after-move, overwrite of a live linear value, unconsumed linear values and mismatched treatment across exits (linear_validation.rs:4203-4446). `cleanup_dispositions.rs` is the storage model the producer carries beside the claim roster: which regions of each owned root are moved, never established, in an inactive sum case, or still under construction (cleanup_dispositions.rs:559-584). The model works on source statements and source expressions: roots are local/parameter symbols or expression handles, paths are field/case/index segments, and the order of events comes from a "source occurrence inventory" of each statement (linear_validation.rs:2009-2017). The producer also resolves how a state call's result claims map back to the callee's claims, iterating to a fixed point (permission_events.rs:2009-2033, and the outer loop signalled by `Ok(true)` at permission_events.rs:206-208). It derives a lower bound of claims definitely live at each explicit crash (permission_events.rs:1580-1697). About 450 lines exist only to run the per-state walk in parallel and to reuse walks between fixed-point rounds without changing the result (permission_events.rs:341-765).

## Mechanisms

- **Copy-on-write ordered set of case observations** (`CaseExclusions`, cleanup_dispositions.rs:27-161). An `Arc`-shared table of canonical places in first-observation order with a fingerprint index. The hash only filters; full structural equality decides (cleanup_dispositions.rs:60-69). `contains_prefix_of` pops segments to test every ancestor, then falls back to a linear scan for element-range observations (cleanup_dispositions.rs:97-119). Serves sum-case payload absence.
- **Remaining-custody state machine and its join** (`RemainingCustody`, cleanup_dispositions.rs:559-584, 752-833, 1275-1353). Tracks excluded regions with a cause (Consumed, Unestablished, Unknown, InactiveCase), definite exclusions, inactive cases, per-root construction frontiers and zero images. `join` is a meet: possible exclusions are unioned, definite ones intersected, an `Unestablished` cause not shared by both sides degrades to `Unknown`. Serves cleanup at scope exit and partial moves.
- **Route replay with joins** (`SelectedEvaluation::enter/enter_with`, used at linear_validation.rs:535-615, cleanup_dispositions.rs:1102-1132, linear_validation.rs:2849-2891). Events carry a branch route inside one statement; state is forked and joined at expression-level branches. The implementation is outside this slice.
- **Statement occurrence schedule** (linear_validation.rs:2910-3383). One loop over `StatementOccurrence` steps (Observe, Move, Complete) emits events in evaluation order; named receiving writes are deferred to `complete_statement_permissions` (linear_validation.rs:3432-3627).
- **Claim identity/provenance scan** (`expression_permission_claim_scan`, linear_validation.rs:1600-1707). Recursive descent that peels a `Case`, `FixedIndex` or `Field` segment against a struct or array literal, then resolves the rest to a canonical place and requires all live places at that exact path to agree. One generic function serves two walks (identity, provenance).
- **Loan-completion regions** (linear_validation.rs:1794-1915). For each call: intersect the call's written regions with its exclusive-authority ceiling, turn closed integer indices into fixed indices, truncate at the first dynamic segment, keep maximal regions. If written regions are unknown it uses the whole ceiling (linear_validation.rs:1862).
- **Early death of anonymous suppliers** (`copy_source_completions` linear_validation.rs:3697-3847; `observed_completions::append` 2227-2390; `completion_cut` 2397-2423). Scans the occurrence list for a unique producer, a unique read and no later use on a compatible route. Each scan is linear in the occurrences, nested inside loops over observations.
- **Exit join in the validator** (linear_validation.rs:4369-4425). Collects the roster at every non-crash exit and compares each linear place's `live` flag with the first exit.
- **Call-result origin fixed point** (permission_events.rs:2009-2033). Repeats derive-maps, rewrite origins, deactivate absent results until nothing changes; budget is the number of events plus one.
- **Outer claim-outcome fixed point** (permission_events.rs:202-208). `prepare_permission_events` returns `Ok(true)` when the outcome maps changed, and the caller (outside the slice) runs it again. The comment at permission_events.rs:367-369 says the product program walks every state twice.
- **Parallel per-state walk with a cross-read guard** (permission_events.rs:471-666, 674-765). States are walked on a rayon pool, each writing ownership rows on its own page whose generation is `first_page + position`. A `WalkGuard` records whether a walk read another state's rows; if any did, or an append is refused, or there are fewer than 64 states or fewer than 2 threads, the function returns `None` and the caller walks serially (permission_events.rs:345, 514-517, 583-586).
- **Walk memo across fixed-point rounds** (`PermissionWalkMemory`, permission_events.rs:362-458). A state's previous walk is reused only if the caller says inputs were restored, the roster, page range, cleanup, termination and content plans are equal, and every outcome map the state consulted is unchanged.
- **Case-exclusion preparation in runs** (permission_events.rs:1347, 1414-1453). Steps are chunked by 8; each chunk carries the previous step's exclusion list to share unchanged lists.
- **Crash frontier underapproximation** (permission_events.rs:1580-1697). Replays recorded events with diagnostics discarded and lists claims live at each crash exit.

## Identity by text

Most identity in this slice is structural, which is evidence against property 2 for these files: roots are `PlaceRoot::Symbol` or `PlaceRoot::Expression` handles, paths are `PlaceSegment` lists, claims are `PermissionClaimIdentity` values with `PermissionProvenance`, and the case-observation table compares full structures on hash collision (cleanup_dispositions.rs:60-69). The exceptions:

- **Case subject identified by rendered label.** `case_transition_run_is_exhaustive` decides that successive transition arms test the same subject by comparing `program.expression_table.display_name(subject)` strings (permission_events.rs:1943, 1960-1967, 1971-1978). The data type is then found by scanning every data definition for one whose non-impossible variant set equals the covered set (1984-2000), not from the subject's type.
- **Struct literal field found by name string.** `expression_permission_claim_scan` maps a `Field { symbol }` segment to the literal's field with `field.name.as_str() == field_name` (linear_validation.rs:1669-1673).
- **Place display names** built as strings: `claim_place_name` renders `root::Case.field[3][a..b][<index>][?..?]` with fallbacks `"<case>"` and `"<field>"` (linear_validation.rs:1283-1320). Anonymous owners are named by `normalized_type_identity_text` of their type (1245). In this slice the name is only printed in diagnostics (587-594, 625-643, 4412-4413); matching uses root and path.
- **Trace filters compare the machine name string** against the `OMEGA_TRACE_CLAIM_FRONTIER` environment variable (linear_validation.rs:4129-4134, 4538-4541).
- **Diagnostics** render paths from symbol names and `Debug` output (linear_validation.rs:4592-4608, 1845-1847, 3292-3295, 4399-4407) and the case-selection explainer builds label strings (linear_validation.rs:952, 1000, 1009, 1041). These do not decide acceptance.

## Notes the authors left

- cleanup_dispositions.rs:1-7: "This is a projection of the permission producer's occurrence order, not a second control-flow analysis."
- cleanup_dispositions.rs:571-574: "Tag observations are facts, not transfers. They intersect at joins and are invalidated by writes; unioning them can erase every live alternative."
- cleanup_dispositions.rs:577-582: zero image, citing `ownership.md`, "Establishment and erasure".
- cleanup_dispositions.rs:617-621: "Unknown writes detach historical source associations; they never grant replacement or transfer authority."
- cleanup_dispositions.rs:1511-1515: "Borrowed writes can change tags without restoring a linear claim; unknown effects forget facts but never manufacture authority."
- linear_validation.rs:291-295: "This keeps cleanup authority attached to the exact source owner and claim rather than treating any StateExit consume as proof."
- linear_validation.rs:451-458: the recording pass "is the only producer of these events; this file walks them to decide the linear ownership rules ... never to record them a second time."
- linear_validation.rs:880-885: "neither a matching label nor a missing claim proves absence."
- linear_validation.rs:1210-1215: the claim frontier is "enumerated by the shared validation walker so the checker's place roster and the lowering replay cannot diverge."

## Surprises

- **No proof kernel anywhere.** None of `proof_admission`, `ProofNode`, `verify_obligation` or certificates appears in the 8,416 lines; the only `proof` token in code is a field passed through (permission_events.rs:701). Every acceptance is a comparison on the code's own roster flags (`live`, `ever_established`, `case_excluded`, `zero_image`).
- **The validator checks the producer against itself.** `validate_linear_permission_events` replays events that the producer in the same file emitted, starting from the same `initial_linear_places` (linear_validation.rs:4220 and permission_events.rs:796), the same `SelectedCases::at_step` (linear_validation.rs:4276 and permission_events.rs:1438), the same `claim_receipts` (linear_validation.rs:239 and 350), the same `exit_evaluation`, and a copied place-update block (597-606 vs 3985-3994). A wrong rule in a shared helper would pass both sides.
- **Dead branch.** `let owned_receiver = false && !type_reference_is_reference(...)` (linear_validation.rs:1071-1072) makes the owned-receiver claim path (1073-1090, 1097-1099, 1103-1104) unreachable.
- **Debug tracing marked for removal was still in the tree.** `trace_transfer_cut` is commented "remove before landing" (linear_validation.rs:4121) and prints up to 128 lines to stderr when `OMEGA_TRACE_CLAIM_FRONTIER` is set; a second trace prints up to 24 `CLAIM_RECEIVER` lines (4538-4587).
- **A result is thrown away.** `let _ = content_transformations::commit(...)` (linear_validation.rs:3664).
- **Exhaustiveness by label.** `case_transition_run_is_exhaustive` uses display-name equality for "same subject" (permission_events.rs:1960-1978), while a comment in the sibling file says a matching label proves nothing (linear_validation.rs:884). Guards with several conjoined tests are label-checked and then skipped without adding coverage (permission_events.rs:1954-1969).
- **An obligation can be erased by a derived map.** `apply_statically_inactive_call_results` turns a live call-result claim into a non-obligation when the callee's outcome map lacks the path (permission_events.rs:2061-2080). The map is derived by the same pass in the same fixed point.
- **Exclusive-call restore revives claims.** Every ever-established linear place under a completion region becomes live after the call with a new identity (linear_validation.rs:1929-2002). When the call's writes are unknown the whole exclusive ceiling is used (1862).
- **Hard-coded evaluation, patched afterwards.** Several events are built with `FlowPermissionEvaluation::Statement` even inside a transition-target evaluation (linear_validation.rs:1988, 3080, 3924, 3964), then a loop overwrites the evaluation of every event of the statement (3408-3410, 3613-3615).
- **Very wide functions.** `evaluate_statement_permissions` takes 24 parameters (linear_validation.rs:2640-2671) and `complete_statement_permissions` 17 (3432-3450).
- **User diagnostics contain Rust `Debug` output**: linear_validation.rs:642-643 (`{:?}` of root, source, identity, provenance), 4400-4402 (`{:?}` of exit kind plus `live=`, `case_excluded=` flags), 4594, 4606.
- **After a diagnostic the walk continues.** In the producer's step closure an error is pushed and the closure returns, but later steps of the same state still run on the half-updated custody (for example permission_events.rs:1025-1026, 1097-1100, 1161-1164).
- **Entry events for bodyless machines.** `walk_state` records StateEntry Establish events and only then returns `None` for a bodyless signature (permission_events.rs:798-831).
- **Quadratic scans.** `observe` scans all disposition rows for each AffineDrop event (cleanup_dispositions.rs:1174-1194); `retire_storage` scans them again (1629-1631); completion stamping walks every disposition row to touch the new tail (linear_validation.rs:2161-2170, 2582-2588).
- **Memory and speed engineering is a large part of the producer file.** The comments record a 2.7 GB preparation on 2,135 states and a 15 GB host limit (permission_events.rs:288-291) and that the product program walks every state twice (367-369). The parallel path silently falls back to serial on any guard failure (514-517, 529-532, 583-586, 598-613).
- **Evidence on the three sampled properties.** Property 1 holds throughout this slice. Property 2 mostly does not hold here (identity is by handle and structural path), with the two exceptions listed under "Identity by text". Property 3 holds in the form of per-placement branches and repeated literals; the authors' own comments at linear_validation.rs:1511-1515, 2860-2864 and 4004-4006 show they were unifying placements one piece at a time.
