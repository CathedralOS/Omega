## What this code is for

This file checks "content-bearing" domains: domains for which the compiler holds a content projection plan (a counted quantity or an interval set computed from a value's fields, checks_content.rs:3982-3990) under a named algebra. The language rule behind it is conservation: a value qualified by such a domain stands for some backing (memory, a run of cells), and a callable may only hand back that qualification if it consumed an owned claim to the same backing, or if it is an authorised issuer. The file enforces this at four points. At declarations, it checks that a signature returning content-bearing custody has an owned source or an exact lifetime-bound loan (`retained_custody`, checks_content.rs:5032-6686). At call sites, it checks every domain-membership fact a call's `ensures` published against the ownership ledger of that exact call (`call_results`, checks_content.rs:1774-3253). Inside checked bodies, it records at each normal return which entry claims and which returned claims an authored conservation equation binds (`body_conservation`, checks_content.rs:23-1141), and records call "replacement edges" from consumed input claims to result claims (`call_transformations`, checks_content.rs:3254-3465). After all bodies are checked, it follows those edges back through callees to make sure a conserved result really descends from the claim the caller moved in (`call_ancestry`, checks_content.rs:1216-1773). Finally it composes "partition" theorems (equations containing `separate(...)`) through wrapper machines by a fixed-point loop (`partition_wrappers` and `compose_partition_wrappers`, checks_content.rs:4029-5031, 6886-7119). The file never calls a proof kernel; it joins rows of the flow, ownership and qualification fact tables and asks `validation::*` helpers and the contract entailment object for the numeric parts.

## Mechanisms

- **Terminal-demand transport (worklist with a budget).** `terminal_demands::at_state` (checks_content.rs:82-215) starts from a machine-owned conservation plan and follows tail transitions and tail calls outward from the plan's owner, rewriting the equation's parameter roots onto each callee's formals (`rebase`, 437-469), until it reaches the state being checked. Visited set keyed by (state symbol, report fingerprint) with a full-plan comparison inside each bucket (122-133). Budget `TRANSPORT_WORK = 65_536` units shared across discovery and value correspondence (80, 485-491). Serves: a callee in tail position must prove what its caller promised.
- **Unchanged-incoming-value search.** `incoming_parameter` (checks_content.rs:331-435) is a depth-first walk over operand predecessors with `active`/`completed` sets; a cycle returns `None` (369-371); all predecessors must reach the same parameter symbol (410-413). Same budget.
- **Completed-producer search.** `completed_producers` (checks_content.rs:1075-1105) follows `flow::completed_values::predecessors` from a returned operand and collects every operand reached with an empty projection. No budget; `visited` is a `Vec` searched linearly (1082-1090).
- **Site preparation for parallel proof search.** `ConservationSites` / `answer_group` (checks_content.rs:726-908) enumerate (plan, return, completed value) sites, group them by completed value, and answer each group with one shared `validation::completed_value_conservation_answers` call, falling back to per-question calls for anything the shared walk did not prove (802-810, 821-822). Results are cached in `ConservationCandidate` and reused by `observe_body_completion` (556-574, 632-647).
- **Claim-lineage traversal.** `qualified_roots` / `call_parents` / `call_result_roots` (checks_content.rs:1305-1762) compute the set of root claim identities a claim descends from, memoised per (claim, domain, semantic domain, projection machine) (1658-1670, 1758-1760). Limits: 65,536 visits (1297), recursion depth 128 (1674), circularity refused (1671-1673). Alternatives must agree on the same root set (`same_roots`, 1764-1766).
- **Path-condition algebra.** `SelectionConditions` (from `crate::flow`) is used as a boolean algebra over branch choices: `any`, `all`, `negate`, `never`, `always`, `covers`, `possible` (checks_content.rs:617-626, 1610-1633, 4854-4912, 7037-7049, 7074-7082). It decides whether a set of alternatives covers every way control reaches a point.
- **Partition-wrapper fixed point.** `compose_partition_wrappers` (checks_content.rs:6886-7119) loops: promote conditional sources whose dependencies are available (6940-6969); for every machine, state and returned invocation try to instantiate each available partition source (6973-7002); merge compositions and OR their conditions (7004-7018); promote a composition to a source when it covers every ordinary return (7022-7058); stop when nothing was added. Each source carries a `derivation_depth` (4102-4105, 6958-6965, 7055). No explicit iteration cap; termination relies on the finite set of distinct compositions.
- **Structural source expansion.** `append_sources` (checks_content.rs:5903-6075) walks a type through constraints, references, arrays (element type visited once, with a symbolic `Elements(length)` segment), record fields and variant payloads, carrying generic applications. Recursion guard: a definition already on the stack with size not smaller than the ancestor's stops the walk and marks it incomplete (6020-6026); `type_size` (6098-6130) is a structural node count. Reports `complete` and `has_open_owned_carrier` separately (5775-5785).
- **Outgoing-row index.** `OutgoingRows` (checks_content.rs:4112-4145) is a lazily built key-to-rows index over the outgoing arena, keyed by state symbol.

## Identity by text

## Surprises

- **No proof-kernel call anywhere in the file.** A search for `proof_admission`, `ProofNode`, `verify_obligation` and "certificate" finds nothing. Things named "proof" here are declaration rows (`program.proof_facts` are authored contract clauses, checks_content.rs:2375, 3808, 5813, 6169) or the contract checker's own table (`facts.proof.contract_facts`, 2335). The numeric side is delegated to `validation::completed_value_*` functions (782, 966, 987, 1201) and to `ProvenExitExpressions` (6892, 6901, 7113, 7116); whether those reach a kernel cannot be told from this slice.
- **The unexplained accept at checks_content.rs:2307-2317.** A boundary-trait requirement whose domain does *not* list it as an `established by` issuer is accepted when the domain has no content projection or the qualified path is nested. Every neighbouring route has a comment about not minting authority; this one has none, and it sits before the issuance checks that would otherwise apply.
- **Checked-body callees short-circuit the call-site check** (2283-2285, 2021-2023), and the body-side code in this file only *records* (494-683). In this file the only body-related refusal is `check_used_calls` (1233-1274), which runs over `body_derivations` built elsewhere.
- **The header and one inner comment say names never identify things; three places do it.** The projection-plan carrier is a text identity (3724-3731); lifecycle outcomes match cases and fields by name with a dotted-string split (5286, 5308-5317); contract places fall back to parameter-name equality (3834) and compare field/case names first (3897, 3907).
- **Published row order depends on Debug rendering** (4367-4372, 4395-4401, 4403-4408). `ContentPartitionCompositionFact` equality is then used to merge rounds (7006-7008), so the sort is what makes two rounds' evidence compare equal.
- **Sort keys drop the handle generation**: `arena_index()` only, at 6862-6868 and 7090-7096.
- **Pointer identity decides two joins**: `std::ptr::eq(producer, call)` (4260) and `std::ptr::eq(path, selected)` (4290).
- **A positional index into type bindings**: `bindings[1].1` is taken as the element type of a move-out (2616). It panics if the lifecycle declaration yields fewer than two bindings.
- **`result_lifetime_argument_ordinal: 0` is hard-coded** (6497); it is consistent only because `lifetime_bound_result` requires exactly one lifetime argument (6519-6521).
- **Inconsistent argument to the same query**: `check_callable` asks `call_target_has_checked_body_contract(program, callable)` with a *state* symbol (6162, called with `state.symbol` at 7273), while the caller asks the same function with the *machine* symbol two lines later (7281). Cannot tell from this slice whether the function treats both alike.
- **Lifetime diagnostics print a stray quote**: the format strings wrap the name as `'{}'` inside backticks (6423, 6461), so `'a` is shown as `'a'`.
- **Internal-consistency failures are user diagnostics**: "placement primitive result lost its authenticated entry", "empty-run release lost its exact result type" and similar (2573-2611) describe compiler bookkeeping, not a program fault.
- **The extraction result is recognised by shape**: exactly one variant with exactly two payload fields, the second being the value (2073-2078). The comment says the caller must authenticate the operation first.
- **`owned_return_sides` only understands equations with all entry parameters on one side and all current results on the other** (1107-1140). A mixed equation (for example one that leaves part of the content in a parameter) is skipped silently by `observe_body_completion`, `conservation_sites`, `terminal_demands::at_state` and `observe_call_completion` (90-94, 527-531, 860-864, 3362-3366).
- **Receivers never transport terminal demands**: `transfer` requires `!call.authored_receiver.is_valid()` (262); mutable and const parameters are never bound (300-302).
- **Cost.** `state_conservation_plans` runs `terminal_demands::at_state` for every machine-owned plan in the program for every state (935-950), each with its own 65,536-unit budget. `check_call_result_qualifications` scans all `contract_facts` per fact (2335). `completed_producers` and several "already seen" tests use linear `Vec::contains` (1086, 1254, 2450, 2703). `facts.qualifications.content.plans.clone()` is taken per plan per call (3367).
- **`check_call_result_qualifications` is one closure of about 335 lines** (2193-2527) holding nine accept routes in a fixed priority order; which reason a user sees depends on which route failed last (`failure_reason` is overwritten as the cascade proceeds).
- **`prepare_retained_content_custody` runs `check_callable` against an otherwise empty `CheckFacts`** (7166-7172), so its judgments use only declarations and content plans; `check_retained_content_custody` later re-runs `check_callable` on every trait (boundary or not) and every machine state (7233-7293). Boundary trait signatures are therefore checked twice.
- **A capability not expected in a source checker**: the fixed-point composition of partition theorems through wrapper machines, with per-path-condition coverage and derivation depth (6886-7119), is a small theorem-propagation engine of its own, separate from the contract entailment it feeds.
