## What this code is for

This slice is the middle of the "structural judge", the old checker's own theorem prover for `requires`/`ensures` contracts written over data values. The first part (CE:46181-47910) walks one machine state's statements along every execution path, carrying a `StructuralJudge` (a bag of equations, case facts, substitutions and guarantees), splitting at guards and matches, following transitions and calls into other states, and producing one "case arm" per path end. The rest is module `structural_judgment` (from CE:47911), split into sub-modules: `algebraic_identity` proves equalities by rearranging sums and products under ring "licenses"; `cases` records and judges "value `x` is case `C` of data `D`"; `conditional_guarantees` holds implications that fire when their guards become known; `constructor_identity` defines when two constructors are the same; `data_identity` decides the identity relation `Id` between two data values; `domain_premises` turns declared type invariants (domain rows, data `requires`, variant `requires`, generic value indices, integer carrier bounds) into assumed facts; `equations` stores an equation as a substitution, a rewrite or a contradiction; `identity_elimination` uses a known `Id` to substitute; `integer_predicates` translates terms into polynomials for an arithmetic `Engine` and compares termination ranks. Every answer is one of `Proven`, `Refuted`, `Unknown`, produced by this code comparing its own terms. Nothing in the range builds or checks a proof object.

## Mechanisms

- **Path enumeration of a state machine (symbolic walk).** `recognize_structural_state_leaves_from` (CE:46181-47317) walks statements in `finite_execution_order`. Each statement returns either `Complete(leaves)` or `Continue { outcomes, local_binding, next_statement }` (CE:47200-47300); for `Continue` it recurses once per outcome from `next_statement`. At transitions it keeps a list of "remaining" judges for fall-through and a list of "selected" judges per arm (CE:46712-47196). It recurses into target states with `bind_invocation` and finishes the caller with `complete_invocation` (CE:47047-47120). Limits: no numeric budget in this function; recursion stops through `path.contains` (CE:46203, 46974) and `has_runtime_induction` (CE:46976). Serves contract proof by cases, citations, induction, and "visitors" that want the judge state at one statement.
- **Arrival de-duplication.** For a state that lies on a call cycle, the walk snapshots its whole arrival (state, inputs, environment, hypotheses, equations, citations, guarantees, path) and returns no arms if the same arrival already completed (CE:46211-46232, 47311-47315).
- **Reachability with memo.** `prefix_site_is_reachable_with_entry` (CE:47400-47431), `state_lies_on_prefix_cycle` (CE:47433-47478) and `state_prefix_reachability_destinations` (CE:47480-47532) are worklist searches over the state call graph, cached in `frozen_program_memos` behind mutexes. Unknown callee means "reachable" / "on a cycle".
- **Licensed algebra.** Flatten nested applications of a licensed `add` machine into a multiset; compare; then breadth-first exchange of hypothesis addend sub-multisets, depth 2, frontier cap 64 (CE:47984-48046). With a paired `mul` license: distribute into monomials, cap 64 monomials (CE:48211), then exchange hypotheses scaled by one goal atom, depth 2, frontier cap 64 (CE:48079-48146). Comment: "over-refusal past the cap, never unsound" (CE:48010-48011). Serves user-declared rings/semirings and quotient-type lemmas.
- **Case reasoning.** Three-valued `judge_case` with positive facts, excluded cases and exhaustion (CE:48739-48808); case-equation unification, depth 32 (CE:48810-48860); `resolve_case_subject`, depth 32 (CE:48939-49026); a per-expression "may contain a case test" table built once with a three-colour DFS (CE:48263-48356).
- **Conditional guarantees.** Forward chaining to a fixpoint (CE:49225-49264).
- **Identity (`Id`) decision.** `judge_identity_with_budget` (CE:49799-49844) tries in order: syntactic identity through known forms, normalization, disjointness, congruence, then transitive search. Budgets: work limit 8192 (CE:49689), depth 32 or 64, 64 forms per side (CE:49835-49836, 50491-50492), 64 visited and 64 pending endpoints (CE:49976, 50033). `data_identity_forms` (CE:50508-50616) is a worklist that follows substitutions, normal guarantees, identity edges, completed nominal values and projections.
- **Equation store.** `intake_equation_fact_with_purpose` (CE:52729-52900) orients each equation into a substitution or a rewrite, with occurs checks and depth cap 32; `eliminate_identity` (CE:53087-53205) does the same for `Id`, depth 32.
- **Invariant instantiation.** `intake_admitted_data_predicates` (CE:51805-51927) and `intake_domain_predicates` (CE:52083-52195) build a synthetic parameter list plus a name-to-term binding list, then call `intake_judged_instantiated_predicate`. An `active` stack of symbols stops recursion through recursive data types and domains.
- **Integer projection.** `IntegerObservations` (CE:53823-53832) maps observed terms to polynomial atoms, records carrier bounds and operations, and `install_premises` (CE:54105-54161) loops until no new premise or operation is admitted. `PreparedIntegerPremisesCache` keeps the 8 most recent prepared premise sets (CE:53863-53895); `take_goal_work`/`put_goal_work`/`reset_goal_work` reuse one scratch copy (CE:53897-53936). `PreparedIntegerOperands` memoizes per-operand projections by fingerprint bucket (CE:53328-53449).
- **Rank comparison.** `form_captured_integer_rank` and `compare_captured_integer_rank_sequences` (CE:53490-53683) save a rank as an `IntegerDenotation` with named atoms, re-instantiate it at the arrival, and compare lexicographically through the polynomial engine. Serves `terminates by`.

- `unknown_condition_neither_establishes_itself_nor_escapes_a_branch` (CE:49293-49325): an implication with an unknown guard proves nothing; learning the guard in a cloned judge proves the conclusion there only; a clone that learns the guard is false stays unknown; the original stays unknown; the clone that fired counts as having new guarantees.

## Surprises

- **No proof object anywhere (property 1).** The strings `proof_admission`, `ProofNode`, `verify_obligation`, `certificate`, `kernel` do not occur in CE:46181-54205. Every verdict is `StructuralJudgment` computed by term comparison, or a `bool`/`Result<bool, &'static str>` from the arithmetic `Engine`. The algebra comment says the ring laws were "CONFORMED (machine-checked)" elsewhere (CE:48050); here the code only reads `self.ring_licenses` and `self.semiring_licenses` and trusts their presence.
- **A capable prover.** This slice holds: multiset and polynomial normalization with bounded hypothesis exchange aimed at quotient-type lemmas (CE:47999-48011, 48069-48078); record eta (CE:50362-50474); bit-exact float identity (CE:50184-50206); budgeted transitive identity search (CE:49919-50046); lexicographic rank comparison through saved polynomial denotations (CE:53587-53683); atomic-load value intervals (CE:51754-51803).
- **Algebra proves `Id`, against the stated rule.** The comment says `Id` "uses value representation congruence" and that numeric equality "supplies no rule" (CE:49781-49782). Yet `identity_correspondence` returns `Proven` from `identity_algebra_equal` for applications and for the catch-all case (CE:50280-50284, 50310-50314), so `Id(add(a, b), add(b, a))` is accepted under a ring license. Whether a license's law is itself stated as `Id` is not visible here.
- **Two different term equalities are in use.** `ConstructorIdentity`'s `PartialEq` compares only carrier and member (CE:49612-49631); `same_resolution_payload` also compares declaration, case and type reference (CE:49521-49545). Some sites use `==` on terms (`judge_case` CE:48773-48774; `observed_atom` CE:53982; `left != right` CE:52862, 52874; `current == root_sem` CE:51993) and others use `same_resolution_payload`. The Debug output used as a sort key also prints only carrier and member (CE:49646-49659), so two atoms that differ in payload can share one sort key; after a stable sort the two sides may then compare unequal position by position (CE:47996). That can only refuse.
- **Possible name collision when instantiating a data invariant.** `intake_admitted_data_predicates` puts type parameters (CE:51844-51846) and fields (CE:51906-51912) into one binding list keyed by their plain source names, and `intake_judged_instantiated_predicate` then maps each parameter symbol to the first binding with its name (CE:52320-52328). A field with the same name as a const/value type parameter would receive the type parameter's value. The sibling function avoids this with `"\0case_field_{..}"` names (CE:50991). I cannot tell whether the language forbids such a clash.
- **Implicit trailing expression plus a live visitor gives up.** The walk turns a final bare expression into an arm with `source_target: None` (CE:46561-46569). Later, with visitors present and no body transfer, it evaluates `transition.source_target?` (CE:47139-47141), which returns `None` from the whole step. So a walk looking for a site in another state fails at any state that ends in a bare value expression that is not a followed call. Cannot tell whether this is intended.
- **Comment versus code in equation intake.** The comment says "a variable side becomes a directed substitution" (CE:52654-52655). The match tests the application/capture/projection arms first (CE:52827-52860), so `variable == application` is stored as a rewrite from the application to the variable, not as a substitution of the variable (CE:52844-52859 runs before 52861).
- **Diagnostic text does not match the failure.** When a single arriving rank has no provable lower bound, the error is "captured ranks do not prove natural nonincrease" (CE:53657-53665), the same text used for the real non-increase failure (CE:53672-53674).
- **A synthetic value with no producer.** Merging a never-branched-on `Bool` local creates `CapturedValue { statement: invalid, callable: invalid, occurrence: fresh, integer_range: joined ranges }` (CE:46519-46532). It is a new opaque value not tied to any call, and it carries an integer range although the local is `Bool`.
- **Variant `requires` are not gated on admission** while data `requires` are (CE:51043 versus 51112); see "Accepts or skips".
- **`integer_premises_contradictory` ends in `independent_integer_premises(observations).is_some()`** (CE:54179-54180). A `Some` prepared-premises value is read as "contradictory". The callee's body starts at CE:54196 and runs past the end of the slice, so I cannot say what `Some` means there.
- **Dead or odd code.** An empty `if` branch (CE:46601-46602). `next_statement` is computed twice with the same expression (CE:46307-46310, 46382-46385). `finalize_structural_case_arm` clones the judge and reads `normal_guarantees` from the original (CE:47735).
- **Debug tracing in the checker.** Ten `eprintln!("STRUCT ...")` sites guarded by a trace flag, reached through three different paths: `super::struct_trace()` (CE:46293), `crate::trace_flags::struct_trace()` (CE:51037, 51068), `crate::proof_contracts::contract_entailment::struct_trace()` (CE:53520), plus `self.trace_contract()` (CE:49789).
- **Unformatted code.** Several blocks are outside rustfmt's shape, including one statement of about 250 characters on one line (CE:51447) and CE:48466-48468, 48635-48659, 52102-52106, 53518-53524.
- **Global mutable caches.** Memo maps behind mutexes on the frozen program (CE:47438-47477, 47485-47530), a `OnceLock` table per program (CE:48385-48391), an 8-entry LRU with linear scan (CE:53871-53895) and a mutex-held scratch object (CE:53898-53914). `HashMap<&str, _>` is built per call for field lookup (CE:50431-50434, 53227-53230, 53267).
- **Evidence on the three properties.** Property 1: fully supported in this slice. Property 2: mixed; variables, locals, fields, projection paths and binding keys are strings, while cases, constructors and observed-field projections use symbols and type identities, and several comments reject deciding by spelling. Property 3: supported; about a fifth of the slice is the same rule written per statement kind, per call form, per value source or per contract owner kind.
