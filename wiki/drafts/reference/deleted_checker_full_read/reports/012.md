## What this code is for

None of the four files is the proof checker itself. `product.rs` takes what a package's `build.omg` asked for while it ran (provider choices, native bindings, service audits, assumed-binding contracts, behavior exclusions, boundary acceptances, wire-compatibility demands, test groups) and decides whether each request is admitted, by matching the executed request against the request the source declared and against the declarations it names (product.rs:1-6). The same file also decides which machines and declarations the checker is asked to check per target (`source_checking_applications`, product.rs:1860-1948), and it saves and re-joins provider choices across packages (product.rs:2511-2910). `syntax_probes.rs` builds temporary copies of the program ("probes") so that compile-time constants and access views can be typed and evaluated early; it selects which declarations and machine bodies a probe needs and strips or defers what cannot be decided yet (syntax_probes.rs:1-8). The README describes stage 04, which rewrites the typed program (specialization, operator calls, policy operators, record-pattern rosters) before checking. `assembly_and_operators.rs` has two parts: `assembly_control` turns an inline-assembly block that uses scratch registers into an ordinary generated helper machine with one state per label, versions each register write, checks that no register or zero flag is read before it is written, and copies the block's `requires`/`ensures` facts onto the helper as contracts (assembly_and_operators.rs:6-1405); `operators` rewrites operator expressions (`a + b`, `a[i]`, `a[x..y]`, match-by-equality) whose selected meaning is a user machine into explicit calls (assembly_and_operators.rs:1407-2204). So this slice mostly prepares and selects input for the checker and admits build configuration; it contains two real program rules of its own (scratch-register definedness and assembly control shape).

## Mechanisms

1. **Checking-work selection per target** (product.rs:1860-2116). For each target scope it builds an inventory of provider candidates (named implementations and machines that satisfy a boundary requirement; product.rs:1634-1733), marks which candidates a build choice or target default supplies (product.rs:1998-2013), then runs a fixpoint (product.rs:2041-2114): compute reachable machines and calls (`ProofApplications::reachability`), turn reached boundary calls into demands (product.rs:1319-1429), add as dependencies the members of candidates whose schema includes the demand, add nested machines of reached machines and both sides of specialization receipts as roots, repeat until nothing changes. The result is a `DeclarationSelection` that explicitly excludes every machine not reached (product.rs:2102-2112). No iteration budget; it stops because the sets only grow. Machines without a target go to the scopes that have layout facts, or to all scopes if none has (product.rs:1884-1905). Declarations that only appear as layout-storage type occurrences are added by a second pass (product.rs:1906-1946). Serves: providers, boundary traits, targets.
2. **Schema keys** (product.rs:1735-1847). A slot key is `(package identity, path string, optional application identity string)`. `Schema::trait_scope` walks a trait and its parents and refuses (returns `None`) when the same trait appears with two different applications (product.rs:1754-1768).
3. **Capture and re-join of build choices across packages** (product.rs:243-481, 2511-2910). A choice is saved as a declaration anchor (file, span, kind), an identity text and optionally a copied operand graph with its source map; on the receiving side it is located again by file and span, filtered by kind and identity text, the application is re-prepared, and its identity text is compared.
4. **Operator family derivation and replay** (product.rs:2945-3116). All boundary operators, token machines and domain operators with the same package and path string form one family; a saved family is compared coordinate by coordinate against the current one.
5. **Probe preparation loops** (syntax_probes.rs:139-147, 230-238, 250-286). Three "demand, complete deferred machine bodies, repeat" loops; the last also re-runs overload resolution to a fixpoint (`while !...is_empty() {}`, syntax_probes.rs:251), binds authored selections and derives operator selections each round. No budgets.
6. **Declaration dependency closure for a probe** (syntax_probes.rs:327-438). Starts from execution roots; target machine families are taken whole (syntax_probes.rs:371-389); follows references with `ReferenceClosure`; for each operator use in newly reached expressions adds the selected operator and every candidate (syntax_probes.rs:392-405); for each referenced symbol adds its ancestors, but a machine only when it is the symbol's own machine (syntax_probes.rs:416-428). Returns `(work, selection)`; `work` additionally holds declarations referenced by the endpoint expressions.
7. **Must-defined analysis for scratch registers** (assembly_and_operators.rs:268-410). One bit per scratch slot in a `u64` (compile-time assert that the slot count fits, 299-303). Forward dataflow over labels: entry starts with nothing defined, other blocks start at all-ones, a block's input is the intersection of predecessors' outputs; reachability is recomputed in the same loop; iterates until stable. Then each reachable block is replayed statement by statement and a read of an undefined slot is refused.
8. **Assembly control-flow graph to helper machine** (assembly_and_operators.rs:822-1228). Reachable labels become states of a generated machine; locals and parameters read in those labels become reference parameters (mutable if the label assigns them, 864-893, 905-909); scratch registers become by-value parameters; each exit becomes a transition, a zero-flag exit a guarded transition plus a fallback (513-604). The first block stays in the owner and is followed by a call to the helper (1165-1227). `requires` facts of a label become that state's `Requires` contract (1127-1137); `requires` of the first block's successors become the helper machine's `Requires`, wrapped as `!taken || fact` when the entry is conditional (1009-1064); qualifying `ensures` facts of the last block become the helper's `Ensures` (33-133).
9. **Register versioning** (assembly_and_operators.rs:1230-1339). Every assignment to a scratch register becomes a new immutable local named `<register>$version$<ordinal>`; later reads are renamed to the current version. This is static single assignment form built by hand for one construct.
10. **Operator-call binding** (assembly_and_operators.rs:1433-1750). Collects operator uses plus every binary expression reachable from executable values (deduplicated by `(expression, origin)`, with a comment explaining a quadratic walk that was removed, 1476-1482), picks a target by a three-step lookup (1974-2113), and overwrites the expression node in place with a call. Named operator calls (`Namespace::op(...)`) are bound by comparing path text (1609-1674).
11. **Match-equality rewrite** (assembly_and_operators.rs:1789-1897). `match s { v1 => a, v2 => b, _ => c }` with a user `==` becomes nested `match eq(s, v1) { true => a, _ => match eq(s, v2) { true => b, _ => c } }`, built from the last arm backwards.

## Surprises

**Evidence on the three properties.**
1. Proof kernel: no line in the slice calls `proof_admission`, `ProofNode`, `verify_obligation` or a certificate. The only "proof"-named items are `ProofApplications`/`ProofApplicationPlan` (product.rs:1303, 1622, 1864, 1879), which are a reachability plan, not a kernel. Every refusal is the code's own comparison or another module's answer. But most rules here are build-configuration admission, where a kernel would not be expected. The parts that touch proof content do not judge it: the assembly code *produces* `Requires`/`Ensures` contracts and moves a termination witness for a later checker (assembly_and_operators.rs:33-133, 764-820, 1009-1064, 1127-1137), and product.rs decides which machines are checked at all (2102-2112).
2. Identity by text: strongly confirmed in product.rs (see section above); symbols are used alongside, but application identity, slot keys, family membership, saved-choice re-join and toolchain enum cases all go through strings. One name decides meaning outright (`"select_provider"`, product.rs:3358).
3. Per-placement repetition: weak here. The repetition is per build operation and per helper, not per source placement.

**Things a careful reader would want to know.**
- Possible double evaluation: `rewrite_match_equality` passes the same `dispatch.subject` expression handle as the first argument of one call per value arm (assembly_and_operators.rs:1852-1853), so the subject expression appears in every nested `eq(...)` call. The README says the call emitter preserves "single evaluation" (README.md:72-73). If the subject has effects or is not a plain place, it is evaluated once per arm tried. I cannot see a temporary being introduced. The original match's `capture` is also replaced by a default (1881), and arms written after the first wildcard are discarded (1803-1806).
- The same rewrite refuses a match whose arms are all values with no wildcard ("has no following arm for a false result", 1847-1851), even if the match was exhaustive.
- `carry_ranking_witness` transfers a machine's termination witness to a generated helper by matching rendered expression text to symbol names, accepting a match on the part after the last `#` (assembly_and_operators.rs:790-794). Termination evidence therefore moves between machines on a string match, and the owner loses its witness and custody (810-819).
- `normal_exit_contracts::append` adds a last-block `ensures` fact to the helper as both `Requires` and `Ensures` when the last block is also block 0 (assembly_and_operators.rs:120-127). No comment explains why the fact is also a precondition; the first block runs in the owner before the call, which is probably the reason.
- In `normalize_graph` a captured local whose declared type is already a reference has the reference stripped and a new reference type built (assembly_and_operators.rs:901-917), while the call argument is a borrow of the local itself (1204-1208). For a reference-typed local that looks like a borrow of a reference passed where a reference to the referee is expected. Cannot tell whether a later stage reconciles this.
- `check_register_flow` runs twice on every graph with a zero-flag exit (assembly_and_operators.rs:676 and 830). Its `outgoing` vector is written (335) and never read: dead variable (305).
- `normalize` clones the whole typed program once if any state has scratch assembly (assembly_and_operators.rs:652).
- Panics instead of diagnostics: `.expect("scratch is a declaration name")`, `.expect("scratch carrier retained")`, `.expect("scratch declaration is a name")` (assembly_and_operators.rs:698, 703, 851); `unreachable!` at 1301 and 1684. In the branching path the same missing-carrier case is a diagnostic (926-927).
- Two different refusals exist for cyclic assembly: `admit` refuses any state without a finite execution order as "not yet implemented" (assembly_and_operators.rs:1367-1372), yet `normalize_graph` builds a full state machine with back edges and guarded transitions and carries a ranking witness (822-1228). Either `admit` runs on a different form or the looping support in `normalize_graph` is unreachable; cannot tell from this slice which.
- The second "multiple meanings" diagnostic (assembly_and_operators.rs:2078-2082) reuses the text "multiple explicitly selected implementation meanings" for closed selected meanings, the same as for evidence-bound ones (2042-2046).
- The entry of an evidence-bound operator call is found positionally: the n-th child symbol of the binder, where n is the requirement's position in the trait's requirement closure (assembly_and_operators.rs:2012-2022). Correctness relies on two separately built orders agreeing.
- `std::mem::replace(..., ExpressionNode::Boolean(false))` leaves an orphan `false` node in the expression table after the match rewrite (assembly_and_operators.rs:1891-1895).
- `HashSet` is used for three worklists (assembly_and_operators.rs:1470, 1483, 1580).
