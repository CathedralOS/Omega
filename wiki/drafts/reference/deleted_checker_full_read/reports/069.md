## What this code is for

This is the tail of the file that turns the old checker's intermediate results into the published `CheckFacts` table that later stages read. It contains the top-level driver `build_check_facts` (10993-11186) and `finish_check_facts` (11189-11527): the first builds borrow, value, operator, proof and semantic facts and then loops flow construction, permission events, receiver-loan retention and entry-requirement inference until nothing changes; the second runs the remaining checks in a fixed order and assembles the result. Around the driver sit about twenty small modules, each producing one fact table. Some of them decide things: index compatibility of indexed domain instances (5838-6849), operator crash-route discharge (7893-8739), static-callable crash refinement (10711-10877), the `embed` and fact-position totality rules (11423-11467), and nominal machine use identity checks (7301-7422). Most of the others copy or reshape data already decided by `validation`, `flow`, `checks` or `flow_effects`: termination, blocking, suspension, service reach, requirement-call specializations, resolved types, state locals, executable bindings, provider publication, qualification evidence origins, and call-site source custody. No function in this slice calls the proof kernel; where the slice proves something it uses its own Boolean prover `boolean_predicates::proves` (10846), label matching (8166-8199), or normalized-identity equality (6313-6325).

## Mechanisms

- **The checking fixed point** (11089-11159). Each pass restores the declaration fact plan, seeds the entry requirements inferred so far, builds flow facts, binds call source spans, then asks three questions in order: did `prepare_permission_events` ask for a retry (11140-11143), did `retain_selected_receiver_loans` add a loan (11144-11151), did `infer_entry_requirements` add a requirement (11152-11158). Any yes repeats the loop. There is no iteration limit or budget in this loop; it stops only when all three say no. It serves ownership permissions, receiver loans and contextual cleanup entry requirements.
- **Flow-construction reuse** (11096-11126, 11571-11610). Before building flow facts the loop clones the six input tables it reads (entry requirements, borrow, proof, domains, scalar expressions, operators). On the next pass it compares the whole tables with `==`; if all six are equal it copies back the previous flow facts and semantic plan instead of rebuilding. The comment at 11565-11569 explains why the semantic plan is not part of the key.
- **Index compatibility by normalization, then by fact search** (6605-6777, 5859-6012). For each (actual instance, expected instance) pair of one family, compare index arguments under two substitution lists (the enclosing call's binders for the expected side, the value's own call binders for the actual side). If unequal, search the facts in the statement's semantic contexts (after the value's own call `ensures`, 6619) for an equality. The search is linear over contexts and facts, first match wins (5921-5942). No budget.
- **Substitution lists as association vectors** (6140-6240). `BoundIndexSubstitutions` is a `Vec<(SymbolHandle, BoundIndexArgument)>` built from the call's static machine application bindings, then parameter-to-argument pairs, then aliases for applied trait signature parameters (6225-6238).
- **Integer write obligation as an interval comparison** (6885-6964). Computes the possible range of the written value (the retained range clamped to the semantic type), returns `true` if it lies inside the stored type's range, otherwise builds comparisons against the stored bounds over the entry-value expression and wraps them as `!path_condition || fits`. Limits: stored types must be non-address, 8 to 64 bits in multiples of 8 (6889-6895).
- **Per-machine parallel derivation** (7025-7049). `rayon` maps `machine_integer_writes` over machines on the checking thread pool, then inserts the rows serially in roster order so the result does not depend on thread count.
- **Crash-route discharge with polarity** (8054-8201, 8570-8645). A guard is walked as a Boolean formula by `labels::boolean_expression_has_polarity`; each leaf is tested against every flow row for the statement (all rows must prove it, any context in a row may). This is a universal-over-paths, existential-over-contexts check.
- **Crash refinement as an implication proof** (10820-10863). For each actual route, the goal is `!actual_guard || (OR of required guards with the same cause)`, proved from the requirement's lowered `requires` by `boolean_predicates::proves`; if that fails, structural guard coverage is tried.
- **Provider candidate enumeration** (8826-8899, 9152-9217). Collects boundary trait requirements, top-level requirements and boundary operators, sorts and de-duplicates them by symbol, then for every checked-body machine and every requirement computes candidate declarations through conformance-map rows and the machine's own clause. Quadratic in machines times requirements; no budget.
- **Worklist walks.** `resolve_occurrences` (10169-10207) resolves every expression's place and result type once using a pending stack and a dense table indexed by arena index. `selected_evaluation` (10636-10663) marks expressions that run only on a selected path, inheriting the mark downward. `CastWalk::scan` (9802-9892) is a recursive walk with a visited set. `expression_evaluates_effects` (8249-8268) is a stack walk that stops at the first call or atomic.

## Surprises

Evidence on the three sampled properties:

1. **Acceptance is the code's own yes or no.** Confirmed for this slice. Nothing here calls `proof_admission`, `ProofNode`, `verify_obligation` or a certificate check (searched 5838-11610, no hits). The only proof-library values consumed are `proof::checker::CheckedIntegerAssignment` decisions, copied into `CheckedIntegerAssignmentDecision` rows (11020-11039), and the `ProofPlan` handed to `build_proof_facts` (11019). Index compatibility publishes a `discharge` tag (`ClosedEvaluation`, `LicensedNormalization { operation_count }`, `EstablishedLocalFacts { facts }`, 6677-6697) that records which route the code took; it is a record of the decision, not a checked proof term. Qualification evidence origins such as `Prover` are assigned from declaration shape (9602-9610, 9721-9725).
2. **Identity by text.** Mixed. The index-compatibility core is handle-based and its comments insist on it. The crash-route statement-entry discharge and the integer-write operand test are text-based (8166-8199, 7125-7127), and struct-literal children are found by type and field name (6800-6809).
3. **One rule per placement.** Weaker here than the brief's samples suggest. `CompatibilityScan::append` is one check applied to an enumerated list of positions, and the position list is the per-placement part (6475-6569). The stronger repetition is per construct: spelled versus named operator uses, blocking versus suspension.

Things a careful reader would want to know:

- **The fixed point has no bound** (11089-11159). Three independent "changed" signals each restart the loop. Termination depends on each callee being monotone; nothing in this function counts passes or stops with a diagnostic.
- **Flow reuse compares whole tables** (11601-11609). Every pass clones borrow, proof, domain, scalar-expression and operator facts (11581-11590) and the flow and semantic results (11121-11125), which the comment at 11160-11167 calls "whole copies of the largest tables in checking".
- **Source-custody diagnostics are built and then discarded** (10387-10396). `authored_call_span` and `validate_occurrence` construct nine distinct error messages, some with source spans attached (10514-10519), and the only caller converts any error into a boolean flag. The messages can never reach a user from this path.
- **The `embed` diagnostic names one cause for two** (11444-11448). The refusal fires when the call is not the exact source call (`!exact_source`) or when the machine is not total (`!total`), but the text always says "is not unconditionally terminating".
- **`exact_source` is an odd uniqueness test** (11424-11439): it counts machines with the target symbol that have exactly one state with the target state symbol and requires the count to be 1.
- **Statement-form named operator calls with crash routes are refused outright** (8481-8514) with "carries crash routes no checked site can cover". This is a known gap expressed as a refusal, in a third loop separate from the two that do the real work.
- **A no-op left in the code**: `.map(|state| ((), state)).flat_map(|(_, state)| ...)` (8085-8086) wraps and unwraps a unit for no effect.
- **An unused binding**: the first `RuntimeValue` arm binds `subject` and does not use it (6170-6176); `_target_state_symbol` is an unused parameter (9687).
- **`unreachable_match_arm` only recognises a literal wildcard arm** (8734). An earlier arm that is exhaustive by other means does not make later arms unreachable for this test, so those uses keep their crash sites (conservative).
- **Asymmetric polarity proof** (8172-8200): a leaf required true goes through `context_proves_boolean_label`; a leaf required false is accepted only on an exact text match with a `BooleanValue { value: false }` fact. The two polarities have different strength.
- **`established_index_equalities` can return `None` when nothing differs** (5888-5890). It is only called after `bound_index_arguments_equal` said the arguments differ (6661, 6686), using a different comparison (`index_arguments_equal`, 5879). If the two comparisons ever disagree, the program is refused with "distinct normalized instances". That fails closed, but it means two equality functions must agree for acceptance.
- **Polarity of the fact payload is safe**: `FactPayload::boolean_expression()` returns only `BooleanExpression` and `ContractBooleanExpression` payloads (`evidence.rs:1030-1036`, looked up outside the slice), so a `BooleanValue { value: false }` fact cannot prove an index equality at 5925.
- **Generic struct literals are exempt from nested index checks** (6801). The filter `definition.type_parameters.is_empty()` drops them with no comment explaining why.
- **Range intersection can go empty silently** (7010-7011), and `integer_write_obligation` treats an empty range as "no obligation" by returning `None` (6910-6912, 6920-6922). Whether `None` means refuse or accept is decided by the caller, outside this slice; if a caller treated `None` as "nothing to prove", two contradictory receiving constraints would cancel the check.
- **Hash maps in a codebase whose rules forbid them for dense ids**: `HashSet<u32>` keyed by expression arena index, rebuilt per statement (9798, 9912); two `std::collections::HashMap<usize, _>` keyed by statement index per state (10255-10264); `SymbolKeyMap` for termination summaries (7667-7670). `selected_evaluation` uses a `Vec` with linear `contains` as its visited set (10637-10644), quadratic in expression count per statement.
- **`remap_service_reach_span`** (10034-10040) rebuilds a `HandleSpan<To>` from the raw index and generation of a `HandleSpan<From>`. It relies on the destination arenas being filled in exactly the source order (`inferred.machines.map(...)`, 9997-10030); nothing checks that.
- **`refresh_realized_contract_envelopes` panics instead of reporting** (11545-11555): `expect` and `assert_eq!` on conditions described as identity drift during checked validation. `build_check_facts` also has an `unreachable!` on an obligation-kind mismatch (11021-11025).
- **Provider publication stores refusals as data** (8880-8896, 9276-9277, 9299-9319). A broken provider relation does not stop checking; the reason string travels in the fact table to whoever later uses that interface.
- **`build_nominal_machine_use_facts` is called once per installed interrupt registration as well as once for the program** (11359-11368), so its identity checks and messages apply to callbacks too, with `application_index` renumbered afterwards (11369-11376).
- **`machine_domain_establishment_route` never returns a `BoundaryRequirement` route** (9679), so a machine is never classified as establishing a domain through that route kind here; admitted-requirement evidence comes instead through `call_qualification_source` (9613-9615).
- **`has_obligations` in `proof_applications::retain`** (7192-7207) is a broad OR over seven unrelated conditions, including whether any terminal layout observation exists; it decides nothing here but gates later work on a flag whose meaning is wider than its name.
