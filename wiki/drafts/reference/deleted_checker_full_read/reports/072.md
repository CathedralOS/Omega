## What this code is for

`values.rs` is the check pass's library for answering "what is known about the value at this place right now?" It does not walk statements itself; other modules (flow, validation, the scalar planner in `values_scalar.rs`, the lowering planner under `execution::terminal_unit`) call into it. It has nine inline modules. `current_integer_bounds`, `captured_intervals`, `captured_call_intervals` and `place_intervals` compute integer ranges for a storage place or a call argument from retained facts (values.rs:24-683, 1334-1657). `evaluation` is a constant folder over the already-selected `CheckedScalarExpression` / `CheckedBooleanExpression` forms (values.rs:684-1139). `float_predicates` turns a true float comparison into a `FloatPredicate` on one place (values.rs:1143-1333). `projection_evaluations` lists the index expressions along a place expression (values.rs:1658-1713). `reference_sources` decides whether a borrow can be captured and builds the lowering plan for it (values.rs:1717-2270). `snapshots` reads assignment facts (`AssignedValue`, `AssignedScalarValue`, `AssignedIntegerBounds`) out of fact contexts (values.rs:2271-3462). The file ends with `build_value_facts`, which records a type and an optional integer range for every executable expression occurrence (values.rs:3523-3602). Almost every function returns `Option`; `None` means "not known" or "refused", and the file itself emits no diagnostics.

## Mechanisms

- **Interval lattice by hand.** Ranges are `IntegerRange {minimum, maximum}` of big integers. "Meet" (intersect, empty → `None`) and "join" (hull) are written inline at each use. No widening and no fixpoint in this file; the interval arithmetic itself lives in `validation::selected_scalar_interval` (comment values.rs:1338-1342). This file is only the "source" of leaf intervals through the `SelectedScalarIntervalSource` trait (values.rs:111-162, 1466-1605).
- **Element enumeration with a budget** (`CurrentIntegerBounds::selected_path` values.rs:427-515, `projected` values.rs:594-634). For a runtime-indexed read it enumerates each concrete index, recursing through nested indices, and hulls the results. Budget is 4096 visits per top-level query and the same counter is compared against the collection length (values.rs:492, 615). Over budget → `None`, which callers turn into the carrier range (values.rs:1591) or the exact-place answer (values.rs:590). Serves array/slice element reads in range reasoning.
- **Per-root predicate index** (`rows_position`, values.rs:537-568; lookup values.rs:647-668). Builds, on first query for a root, the list of retained boolean predicates and an index of `(predicate, binding)` sorted by `place.compare_identity`; lookup is a `partition_point` binary search followed by an exact `==` filter. Roots are found by linear scan over a `Vec`.
- **Lazy, replayable assignment reader** (`RootAssignmentObservations` / `RootAssignmentInputBatch`, values.rs:2299-2463). Per place root it pulls assignment facts out of the context list only as far as a query needs, caches the canonicalized prefix, and replays it for later queries on other fields. The "completed call snapshot" test is memoised per row in a `OnceCell` (values.rs:2389, 2445-2456). A refusal on one field does not consume the tail for another field (comment values.rs:2361-2365; test at 3220-3225).
- **Three-valued constant folder** (`evaluation`, values.rs:750-1090) over the checked scalar expression tree with a pluggable leaf resolver `ScalarValueSource` (values.rs:703-746). Values are `i128`/`u128` internally, but leaves are admitted only via `to_i64`/`to_u64` (values.rs:1126-1129).
- **Float fact normaliser** (`collect_true`, values.rs:1174-1250). Recursive descent through borrows, `and`, and `== true`; tries both orientations of a comparison (mirroring the operator); the fact stores landed IEEE bits rather than an expression (comment values.rs:1145-1148).
- **Reference-capture geometry** (`capture_source`, values.rs:1833-2155). Resolves the borrowed expression to a place, asks the lowering planner for the evaluated path, then walks reference "shells" from the backing type down to the requested referent, counting crossings and checking access at each. The loop is bounded by the number of type references in the program (values.rs:1938, 1951). It returns a lowering plan (`CheckedUnitStructuralArgumentPlan`) plus storage interpretation.
- **Selector walk with cycle guard** (values.rs:1682-1711): linear `visited.contains` on each step.

## Accepts or skips without proof

- **Index clamp** (values.rs:485-491): a runtime index range that extends outside the collection is clamped to the valid elements before the hull is taken, so out-of-range indices contribute nothing. The comment at values.rs:335-336 says these results "do not grant initialization, index formation or access". I cannot see the bounds check from this slice.
- **Standing parameter interval** (values.rs:1421-1443): the declared interval of an immutable formal is used as a fact about its current value ("an immutable formal's arrival contract", values.rs:1340-1341). Establishing it at call sites is some other module's job; cannot tell from here.
- **Representation view** (values.rs:1097-1120): folds by reinterpreting bits and ignores the source type (values.rs:920); "Its caller has already established the carrier relation."
- **Exact cast** (values.rs:932): trusts the `range` stored in the cast node as the admissible source range.
- **Fallback backing type** (values.rs:1873-1884): when the lowering planner cannot produce a path for an expression-rooted place with no segments, the code assumes declared type = storage type = the requested referent. For a non-view borrow the later identity check (values.rs:1945, 1963-1968) then compares the referent with itself and passes. I cannot see another check on the expression's actual type on this route; `formed_reference_type` (values.rs:1778-1804) may be the one, cannot tell.
- **Default storage interpretation** (values.rs:2136-2138): `CheckedReferenceStorage::Declared` when neither view nor access view.
- **Deferral instead of refusal** (values.rs:2210-2211, 2234-2239, 2249-2255): a missing qualification inventory or supplying type becomes `Unavailable(reason)` in the published plan; the comment says "Unavailable inventory remains a refusal for the consuming lowerer" (values.rs:2168). The check pass itself does not refuse here.
- **`build_value_facts` failed type lookup continues** (values.rs:3548-3550): a missing type becomes `TypeReferenceHandle::invalid()` and the fact is still recorded; the primitive type then falls back to the caller's `expected_primitive` (values.rs:3551-3553). Cannot tell whether a consumer rejects the invalid handle.
- **Completed call snapshot** (values.rs:2805-2836): the raw "assigned the call" fact is dropped in favour of a scalar/bounds fact matched only by place, point and origin; nothing here checks that the second fact came from that call's contract.
- **Structural identity → true** (values.rs:1028-1030): accepted on syntactic equality of the two operand descriptions; this is a sound direction as long as both describe the same evaluation moment, which this file does not check.
- **Widening fallbacks (safe direction, not acceptance):** carrier range when nothing is known or the budget is exceeded (values.rs:642, 1398, 1504, 1540, 1591, 1654); contradictory facts (empty intersection) yield "unknown" rather than "unreachable" (values.rs:316-318, 588, 680, 1409, 1512, 1600).
- **Silent skips that only lose facts:** every `continue`/`return` in `collect_true` (values.rs:1186-1235); `storage`/`indexed_read` returning `None` for call arguments (values.rs:129-161).
- **Evidence on property 1:** no call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type appears in this file. The one proof-module call is `proof::checker::proved_assignment_integer_range_with_context` in `build_value_facts` (values.rs:3527, 3579). Every other range, value and borrow decision here is this code's own computation over the fact tables.

The streamed result equals the eager one. A literal expression root answers without reading any context.
- `root_assignment_inputs_preserve_prefix_extension_scope_and_snapshots` (values.rs:3129-3460): the cached per-root reader gives the same answers as the direct reader; repeated queries do not redo work (exact counts of contexts, canonicalisations and snapshot checks are asserted); a refusal on field `[0]` does not stop a later query on field `[1]`; a scalar refusal on two differing ranges still yields their hull `[-4, 13]`; two context handles with the same arena slot but different generations stay separate; a completed call observation suppresses the raw call fact only with the same context, point and origin (the three near-miss cases return `None`).

Both tests assert work counters and print them with `eprintln!`; they pin performance behaviour as much as results. No test in this slice covers the interval modules, the evaluator, float predicates, or reference capture.

## Surprises

- **The check pass and the lowering planner are the same code here.** `reference_sources` lives in the check pass but imports `crate::execution::terminal_unit::calls` and `...::types` (values.rs:1728, 1735-1736) and returns a lowering plan. Whether a borrow is allowed is decided as a by-product of whether its lowering geometry can be built; refusal is a bare `None` with no reason attached.
- **No diagnostics at all in 3,600 lines.** The only user-facing texts are the two `Unavailable` strings (values.rs:2237, 2253), and they are stored in a plan for a later stage rather than reported.
- **Comment and code differ on "frozen".** The comment at values.rs:1447-1452 explains that declared constraints hold only on frozen storage, and `field()` returns a `frozen` flag, but all three callers discard it (`_frozen` at values.rs:1489, 1523, 1614). In this file the flag has no effect.
- **"A missing element contributes its carrier" vs `bounds?`.** In the enumerations any element that returns `None` aborts the whole hull (values.rs:503, 624). That agrees with the comment only because `exact` starts from the carrier; an element whose facts contradict each other makes the whole collection read "unknown".
- **Saturating shifts.** `SaturatingShiftRight` is evaluated with `exact_shift_right` (values.rs:978-980). `SaturatingShiftLeft` first requires `exact_shift_right(left, count, right)` to succeed and discards the result (values.rs:982), apparently as a shift-count validity test. If `exact_shift_right` also fails when bits are shifted out (I cannot see its definition), then a saturating left shift of an odd value would never fold. Looks like a possible bug or at least an accident-prone reuse.
- **Trapping operations fold exactly like exact ones** (values.rs:995-1003): a trapping add that would overflow gives "unknown", the same as an exact add; the evaluator has no notion of "this traps".
- **Values wider than 64 bits never fold.** `admitted_integer` goes through `to_i64`/`to_u64` (values.rs:1126-1129) and `representation_view_value` handles only 8/16/32/64 bits (values.rs:1109-1119), although values are held in `i128`/`u128`. The standing parameter interval is also carried as `i64` bounds (values.rs:1438, 1441), so an unsigned bound above `i64::MAX` cannot be expressed on that route.
- **Size cliff at 4096.** Facts about elements of a collection longer than the remaining budget are unusable through `selected_read`/`projected` (values.rs:492, 615); nested arrays multiply against the same budget. The same program with a larger array silently loses range precision.
- **Contexts mean different things per reader.** For scalar values every payload across contexts must agree (values.rs:2629-2634); for integer bounds payloads are joined (values.rs:2712-2718); for retained predicates in `exact` every predicate is intersected (values.rs:676-677). The first two treat the context list as alternatives, the third as conjuncts. Whether that is consistent depends on what `retained_at_root` returns, which is outside this slice.
- **`ieee_equal_spelling_at_place` aborts the whole query** if any float-equality fact in the context has a non-place subject or a place that cannot be canonicalised (values.rs:2747-2752), where the sibling integer readers skip such facts (values.rs:2792-2793). It also scans every fact in each context instead of using the per-root index.
- **`keep!` macro** (values.rs:1168-1172) only renames `collect_true` with `=>` separators between arguments. It adds nothing; a careful reader will wonder whether it existed to get past an argument-count lint.
- **A `HashMap` keyed by `PlaceRoot`** holds the per-root readers (values.rs:2303), while the predicate index right beside it uses a `Vec` with linear search (values.rs:538); the project's data-oriented rule prefers dense tables.
- **Integer literal as float bound** is rounded to the float format first (values.rs:1262-1271), so `x < 16777217` on an `f32` records the bound `16777216.0`. This matches how such a literal would land, but the fact no longer shows the authored number.
- **`CapturedCallIntervals` uses the last operand as the epoch for every argument** (values.rs:81, 105), i.e. all arguments are observed at the point the final operand completed.
- **Against property 2:** this file is almost entirely handle- and structure-based. **For property 1:** all decisions are own judgment, with one call into `proof::checker`. **For property 3:** moderate; the strongest signal is the `lower_*` export list (values.rs:3504-3521), whose bodies are in another slice.
