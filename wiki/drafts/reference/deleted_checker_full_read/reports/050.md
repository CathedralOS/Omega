## What this code is for

This file does not judge proofs. It builds "plans": the records the old checker published for each machine so that later stages could execute it. A machine either gets a plan or the builder returns `None` and the machine is "declined" with a recorded gap.

It has eight parts. `boundary_contracts` and `boundary_machine` (control.rs:11-1305) build the published plan for a bodyless boundary declaration in three forms: a boundary machine, a trait requirement, and a legacy boundary operator. `call_occurrences` (control.rs:1306-4544) answers one question in many ways: is every call written in a statement executed exactly once by exactly one owner in the plan. `call_results` (control.rs:4545-4852) attaches a result local to a planned call and classifies which result types a plan can carry. `checked_machine` (control.rs:4853-5230) builds the plan for a single-state machine body by running about nineteen named phases. `construction_trace` (control.rs:5231-5445) records which phase was running when a builder returned `None`, purely for the diagnostic. `reference_captures`, `scalar_arrays`, `selected_copies` (control.rs:5446-5849) are small planners for local reference bindings, scalar array literals and copied payloads on returns. `structural_operands` (control.rs:5852-6905) finds the structural (non-scalar) arguments of a call, orders nested calls before their enclosing call, and plans each one.

Almost every function returns `Option`; `None` means "this builder cannot present this body". The facts it relies on (`CheckFacts`: flow calls, scalar computation roots, structural value roots, contract plans, service reaches) were computed by other modules, and this file re-joins them by handle and by `(statement index, call ordinal)` coordinates.

## Mechanisms

**Call occurrence ledger** (control.rs:1324-1423). `CallOccurrenceLedger` holds the call facts already owned in one statement, the scalar computations already walked (with each one's smallest call ordinal), and a stack of pending minima. A second struct, `CallOccurrencePrefix`, is an immutable copy of the shared part, keyed by `(arena index, generation)` in `BTreeSet`/`BTreeMap`, which each branch of a selected invocation borrows. It serves the rule "each authored call runs once".

**Recursive scalar computation walk** (`collecting::collect`, control.rs:2405-2675). Depth-first over `CheckedScalarComputationKind`. It memoises by `(state, statement, computation)`, detects cycles through a `visits` list with a `completed` flag, and propagates the minimum call ordinal upward through `pending_minima`. No depth or node budget. Thirteen kinds are matched exhaustively, with no wildcard arm.

**Structural value worklist** (`structural_values::collect`, control.rs:3504-3774). Iterative walk with a `pending` stack and a `visited` vector (linear `contains`). Exhaustive match on `CheckedStructuralValueKind`. It calls back into the scalar walk for selectors, subslice endpoints and projection evaluations.

**Outer-call discovery** (`outer_calls_in_prefix_traced`, control.rs:3806-4268). One pass over statements in authored order collects every call owned by a computation or value root; a second pass over calls sorted by `(statement, ordinal)` claims structural operands transitively (`claim_structural_operand_calls`, control.rs:4281-4328, a growing-vector fixpoint) and decides which calls are "outer" (scheduled as their own operation). A final sweep refuses if any call is unowned. It honours an execution-order prefix (`admitted_execution_order`, control.rs:3830-3838).

**Dispatch producer owner counting** (`dispatch_producers`, control.rs:2677-3055). For calls that re-read a saved dispatch subject, it maps each candidate to its producer, counts how many predecessors own each producer, and records "unknown operands" when a predecessor's argument walk fails. `LocalProducers::rescheduled` answers "would this leaf's preparation run an already-scheduled producer again" using a per-statement index so the cost follows new work (comment control.rs:3023-3024). The only test in the file checks this index against a linear scan.

**Selected invocation accounting** (`SelectedInvocationAccounting`, control.rs:3136-3488). Walks a completion tree (dispatch nodes and invocation leaves) with an explicit stack and a three-state visited map; each leaf is then accounted separately and `finish` checks the union covers the statement.

**Generic requirement substitution** (`specialized_signature_substitutions`, control.rs:1164-1260). Scans every flow call in every state for calls to the requirement, requires a specialization row at each, and requires all rows to carry equal type bindings. Quadratic in nothing worse than states × calls; no budget.

**Open constant recipe search** (`pending_recipe_requires`, control.rs:193-233). Worklist over contract expressions with a `visited` vector, collecting constant recipes that are valid but not yet closed.

**Contract lowering budget** (control.rs:74). `remaining = 4096` is passed to the scalar contract lowering functions per clause; this file sets the number and does not consume it.

**Structural operand collection** (`structural_operands::collect`, control.rs:6516-6647). Recursive preorder over call arguments with an `active` stack guarding against an expression containing itself; nested calls are emitted before their enclosing call.

**Value-call planner** (`value_calls`, control.rs:6107-6421). Worklist with a `Sequence { children, next }` frame so that later children are skipped once an earlier child has no normal continuation (control.rs:6145-6163).

**Construction trace** (control.rs:5251-5444). `Cell`-based last-writer record of phase, state, statement, "declined step" and a result-custody failure record; `DeferredFailure` restores an earlier position on drop. It produces the gap message; comment says it "never changes which bodies are admitted" (control.rs:5240-5241).

## Identity by text

This slice identifies almost everything by handle (`SymbolHandle`, `ExpressionHandle`, arena index plus generation) or by position. Text decides meaning in few places:

- `AsmRegisterOperation::from_intrinsic_name(builtin.name())` (control.rs:2131-2133): the builtin's name string selects which inline-assembly register operation a call is.
- `PrimitiveType::from_name(name.name())` (control.rs:2147) and `PrimitiveType::from_name(carrier.name())` (control.rs:4588): a register carrier's name string is converted to a primitive type, and at 4588-4589 that conversion decides whether a result may bind.
- `parameter.name == callback.binder` (control.rs:665): a type parameter is matched to a native callback parameter by name.
- Binders are passed as `&[(SymbolHandle, String)]` (control.rs:1266, 4730, 4776); this file passes them through and does not read the string.
- Every refusal reason is a `&'static str` (list in the Rules table). `restore_with_declined_step` compares two phase strings (`phase != mark.position.phase`, control.rs:5368) to decide whether to record a declined step; this affects the diagnostic only.
- `format!` builds the gap text (control.rs:5419, 5427-5433).
- `machine.name`, `state.name` appear in a debug `eprintln!` (control.rs:6409-6416).

Identity that is not text but is also not a value identity:

- **Pointer equality.** Call facts are compared with `std::ptr::eq` (control.rs:1758, 1791, 1885, 1895, 2080, 2109, 2584, 4090, 4091, 4114, 4233, 4234, 4237, 4300), and at control.rs:3323 two slices are compared by address. Correctness depends on every caller passing the same slice of the same arena.

## Surprises

**Evidence on the three properties.**

1. *Acceptance as own yes/no.* For. The names `proof_admission`, `ProofNode`, `verify_obligation` and "certificate" do not occur in the file (grep after reading). Every decision is a Rust `Option` or `Result<_, &'static str>`. The contract "commitment" and "report fingerprint" this file publishes (control.rs:442-443, 860-861, 977-978, 4625-4630, 5215-5216) are copied from `facts.contract_plans`, not checked here. The file's own comments describe it as publication that "does not recheck" (control.rs:239-243). So this slice neither produces nor consumes kernel evidence; it decides only whether a plan can be built.

2. *Identity by text.* Mostly against. Identity here is by handle, by `(statement, ordinal)` position, and by pointer address. Text decides meaning in four spots (builtin name → asm register operation; carrier name → primitive type, twice; type parameter name vs callback binder).

3. *Rule rewritten per placement.* Partly for. The repetition is per construct for boundary plans (three copies) and per expression role for call accounting (nine copies). The comment at control.rs:3783-3784 states the intent to avoid "destination types or statement-family recognizers", and the code still branches on `as_local_data`, `as_assignment`, `StatementNode::Expression`, `StatementNode::Transition` (control.rs:3851-4057, 4125-4158).

**Things a careful reader would want to know.**

- **About half the file exists to prove "each authored call runs exactly once".** Lines 1306-4544 (3,200 lines) rebuild, from separate tables of scalar computations, structural values and flow call facts, who executes each call. The need arises because the same call is recorded in up to three tables that do not share ownership, and has to be re-joined by position and expression handle. On a lowered form where a call is one instruction, this whole concern would not exist. This is the largest thing in the slice and none of the three sampled properties names it.

- **Two walkers disagree about a call reached twice.** The scalar walk refuses a call already in the ledger (control.rs:2573-2577). The structural walk accepts and skips it (control.rs:3600-3602), and uses `record_once` for access views and quotient calls (control.rs:3559, 3587). The value-call planner refuses any structural node reached twice (control.rs:6165-6167) while the accounting walk tolerates it (control.rs:3523-3525). A body can therefore pass accounting and then be declined by planning for sharing a node.

- **Two functions choose a nested call's result type differently.** `value_calls` uses `checked_structural_result_type` on `call_target_return_type(call.target_symbol)` (control.rs:6214-6221). `plan_call_operands` uses `result()`, which uses `nested_structural_call_return_type` and, for a boundary callee, `boundary_result_plan` with the callee's binders (control.rs:6844, 6654-6703). The same nested call can be classified by either, depending on whether it sits in a retained value or directly as an argument.

- **Boundary operators are treated more loosely than trait requirements.** A failing operator produces no gap and no message (control.rs:877-879), publishes no `ensures` at all (control.rs:973), and gets an empty service reach by construction (control.rs:943-946). The trait requirement path records a named gap for each of the same failures.

- **A generic boundary requirement called at two different type arguments gets no plan,** because one plan serves all sites and the bindings "must agree" (control.rs:1247-1251). A generic requirement that is never called also gets none (`resolved` stays `None`, control.rs:1254). Both report "boundary requirement: unresolved invocation telescope".

- **The 4096 lowering budget surfaces as a misleading message.** If a `requires` clause exceeds the budget set at control.rs:74, `boundary_scalar_requires` returns `None`, the pending-recipe fallback finds no open recipe, and the user sees "boundary scalar requirements have no retained plan" (control.rs:375).

- **`FloatRange` requirement rows are silently dropped** from the published scalar requirement (control.rs:182), while every other unexpected row kind refuses (control.rs:183).

- **The refusal reason is whatever phase was entered last.** The checked-machine builder has no error type; `LocalConstructionTrace` holds `Cell`s that helpers overwrite (control.rs:5330-5335). The reported reason is correct only if every helper marks its phase before every `?`. `DeferredFailure` and `restore_with_declined_step` exist to repair cases where a fallback overwrote the primary reason (control.rs:5294-5372). The gap reason type is `Unsupported` in every case (control.rs:593, 5441): the old checker reported "declined to plan" as "unsupported", not as a rule violation.

- **Pointer identity on slices.** `contains_leaf` requires `std::ptr::eq(calls, facts.flow.control.calls.span_or_empty(self.calls))` (control.rs:3323). Passing an equal copy of the roster would make every selected leaf fail, silently.

- **A transition call with a named target skips its own checks.** At control.rs:4148-4156 the call is already in `outer` when `continue` skips the call-site lookup, the unconditional-call check, the target-symbol check and argument collection. Whether another planner repeats those checks for named targets is outside this slice.

- **Linear result types bypass the contents test** in `checked_structural_result_type` (control.rs:4821). The comment says custody is checked by the call producer. The classification itself accepts any Linear non-reference type.

- **Stale header.** The file comment names `boundary_machine.rs`, `checked_machine.rs`, `construction_trace.rs` and `call_results.rs` as separate files (control.rs:4-8); they are inline modules here. Only `statement_sequence` is a separate file, pulled in by `#[path]` (control.rs:5850-5851).

- **Leftovers.** `establish_value` takes an unused `_operations` parameter (control.rs:6436). A debug `eprintln!("CHECKSITE completion-value-summary ...")` sits in the planner behind `trace_flags::trace_completion()` (control.rs:6408-6417). `checked_structural_result_type` and `checked_copied_result_type` return plans with `statement_index: 0, binding_ordinal: 0` as placeholders that callers must overwrite (control.rs:4748-4749, 4780-4781; overwritten at 6222-6223).

- **Capabilities not expected in a "checker".** The file handles inline-assembly register operations (control.rs:2127-2151, 4580-4599), global descriptor tables (control.rs:5126), static interrupt declarations (control.rs:393-397, 417-420), atomic fences and atomic access (control.rs:5137-5138), access-lifecycle placement primitives (control.rs:275-286), quotient calls (control.rs:3563-3589), native callback parameters (control.rs:657-678) and native code layout values (control.rs:3562, 6171). These are execution-planning concerns carried inside the checking stage.
