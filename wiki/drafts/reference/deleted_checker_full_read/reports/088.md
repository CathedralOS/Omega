## What this code is for
This is the second half of the old checker's integer and float range module. It holds the "value environment": the set of facts the checker believes about scalar values at one point in a state body (intervals, known constants, float bounds, ordering relations between values), and the rules for when those facts are dropped after a write or a call (A:25897-26918). It holds a small ordering theory over "operands" (places, fields, literals, collection lengths, indexed reads, call applications, arithmetic terms): a difference graph, a congruence closure, and a refutation query that hands comparisons to the arithmetic engine in `contract_entailment` (A:18144-18712, A:18907-22227). It checks that arithmetic inside specifications (`requires`, `ensures`, domain predicates, data `requires`, propositions, mathematical definitions, operator and trait contracts) is total: no trapping arithmetic, no division by a possibly-zero divisor, casts provably representable (A:24428-25817). It checks that a value written into a laid-out integer field fits the stored width on every layout target (A:23548-24358), that returned values fit the return type (A:22455-22722), and that a stored value honours its data type's `requires` interval (A:22322-22454). It computes slice lengths from subslice expressions (A:23246-23537), monotonic `x + c` update bounds (A:18714-18814), and intervals over the already-checked scalar expression form (A:22723-23245). The tail of the range is the module's re-export list and two small entry functions (A:26920-27042).

## Mechanisms
- **Refutation through the arithmetic engine** (A:18541-18646). `contradicts` turns the environment's relations, congruence equalities, carrier bounds and text-keyed intervals into `ScopedArithmeticComparison`s over atoms named `observation:{n}` and asks `scoped_arithmetic_comparisons_unsatisfiable`. Every prover in `live_integer_constraints` works by adding the negation of the goal. No budget here; the engine is outside the slice. Serves guards, range checks, collection footprints.
- **Greedy minimal premise set** (A:18286-18360). `contradicting_premises` finds why a match arm's environment is impossible: it removes base relations and base interval bounds one at a time and keeps as "premises" those whose removal makes the arm possible again. Returns rendered strings. Only runs for authored machines (A:18292). Serves diagnostics.
- **Difference graph** (A:19261-19547). Nodes are operands, edges are `left >= right + k`. Union-find groups nodes; only nodes with both an incoming and an outgoing edge ("core") can be equal. A Bellman-Ford-style longest-gap relaxation runs at most `n - 1` rounds per source and is cached; `checked_add` overflow skips an edge (A:19455). Two operands are equal when each is `>= 0` above the other (A:19418-19436).
- **Transitive gaps** (A:19895-20032). `ValueComparison::ordered_gaps` relaxes relations from one value, merging operands the congruence check says are equal, with caches for the pairwise answers.
- **Congruence closure** (A:20241-20426). `Equalities::prepare` collects terms from the relations and two query roots, seeds classes from difference-graph equalities, then merges terms with the same constructor and class-equal children through a worklist. Limits: 256 terms (A:19877), 65,536 comparisons (A:19878), term depth 128 (A:20370), structural comparison depth 128 (A:20078). Running out of budget returns `None`, which callers read as "not the same value" (A:20054-20055, A:20231).
- **Relation transport across a call** (A:20821-20926). Substitution of operands by bindings with a fixpoint that extends bindings through equalities (A:20910-20925) and bridges dropped operands through transitive gaps.
- **Operand construction** (A:21350-21590). One recursive translation from a source expression to an `Operand`, depth limit 128. `integer_meaning` is memoised behind a mutex (A:21598-21648).
- **Interval evaluation over the checked form** (A:22769-23245). `selected_scalar_interval` and `selected_boolean_decision` evaluate `CheckedScalarExpression` / `CheckedBooleanExpression` with exact big-integer intervals through a caller-supplied `SelectedScalarIntervalSource`. Wrapping arithmetic is handled by reducing both endpoints modulo the carrier size and checking they fall in the same period (A:23077-23101).
- **Layout reach** (A:23690-23863). `stored_integer_source_reach` evaluates, for every layout target alternative, whether a storage coordinate or anything below it holds a laid-out integer whose write is not total; recursion over data fields with a cycle guard (A:23817).
- **Specification walk** (A:24555-24676). One tree walk parameterised by four closures (domain, interval, built-in test, numeric coercion) serves both the state-bound and the declaration-level specification checks.
- **Value environment** (A:26012-26030, A:26218-26254, A:26443-26489, A:26809-26916). A record of text-keyed maps and sets plus a relation list, with rebind by string prefix, invalidation by string overlap, and join by intersection.

## Surprises
- **Two identity schemes inside one value.** `Operand::Place` holds a symbol and a text path; the congruence code compares the symbol, while invalidation, interval lookup, and every derived `==` use the text (A:20109-20111 versus A:21143, A:18626-18631, A:20933). The comment at A:21108-21110 says snapshot identity is supplied by declaration, "never spelling", and the next line tests the spelled path first (A:21111). `invalidate_unknown_writes` keeps text-keyed facts by declaration name with a uniqueness guard and keeps the other stores by symbol, in the same function (A:26320-26390).
- **Derived equality is stricter than "same value".** Because `Operand` derives `PartialEq`, `Integer` operands with the same value and different landing are different under `==` (A:20945) and equal under `same_constructor` (A:20112-20115). The difference graph, the atom list and `rebound` index operands with `==` (A:19395, A:18691, A:21172), so a literal written with and without a suffix is two graph nodes unless a later congruence step joins them.
- **Dead branch.** `validate_return_value_range` tests `range_constraint_interval(..).is_some()` and then makes the identical call in both branches (A:22693-22720).
- **A test-only variant in the production enum.** `Operand::CompletedCall` exists only under `#[cfg(test)]` (A:20950-20954), with `cfg(test)` match arms in production functions (A:20380-20381, A:20652-20653, A:21075-21076, A:21152-21153, A:21219-21220, A:22179-22180). Its test asserts properties of a "completed call event" that production code never builds. `DifferenceGraph` likewise has test-only fields and a test-only query (A:19275-19280, A:19475-19533).
- **Premises can be lost through the global `seen` list.** `validate_facts` skips an expression already seen under any earlier owner before it reaches the code that adds it to `prior_facts` and narrows the environment (A:25443-25446 versus A:25513-25525). If two declarations share a fact expression handle, the second one's later facts are checked without that premise. This makes the check stricter, not looser.
- **`proves_range` gives up when there are no ordering relations** (A:18446), although `contradicts` would also use intervals and carrier bounds (A:18600-18644). The one caller in the slice has already compared intervals (A:22352-22360).
- **`subtract_floor_limited` uses only direct relations** (A:21996-22004). The transitive `ordered_gaps` exists and `unsigned_increase_fits` uses it (A:22209), but `x - z` gets no floor from `x >= y + 1` and `y >= z + 1` here.
- **A diagnostic's wording decides control flow.** Whether a failed formation obligation blocks depends on its message starting with "exact arithmetic in " and containing "may overflow" (A:24417-24419). The policy-erasure message at A:25258 has the same shape.
- **Twenty-two refusal reasons are computed and thrown away** (A:18953-19118, A:19123-19126), and the statement is found by pointer equality (A:19033).
- **Trace output in the checker.** `eprintln!` lines guarded by `trace_flags::reference_slot_trace()` print internal state (A:19172-19177, A:26404-26422).
- **Resolver construction on demand.** `captured_references::operand` and `invalidate_assignment_paths` build a whole `CallFrameResolver` when none is passed (A:19163-19170, A:26500-26504).
- **Machine `ensures` premises do not reach states.** State completion premises start from the machine's `requires` environment, not the machine's completion environment (A:24784-24785).
- **`rebind` carries only the text-keyed stores.** `integer_ranges`, `boolean_values`, `ordered_values` and `float_elements` are not rebound (A:26218-26254); relations cross calls through the separate `rebind_relations` (A:20821).
- **The solver's atoms are always signed** (`unsigned: false`, A:18705); unsignedness is supplied by adding carrier bounds as comparisons (A:18611-18625).
- **Possible shift overflow.** `interval_fits` computes `1_i128 << bits` from the value primitive's byte size (A:24326-24330); a 16-byte integer primitive that accepts literals would overflow the shift. I cannot tell from the slice whether one exists.
- **Unused parameters:** `_relations` in `ordered_gaps_with_comparison` (A:22221), `_machine` and `_state` in `operand_carrier_within_ceiling` (A:22186-22187).
- **A piece that already fits the new design.** `selected_scalar_intervals` evaluates the checked expression form by position and storage root, with exact big integers, a public trait for its inputs, and no strings (A:22736-22997). It is unlike the rest of the slice.
- **On the three properties.** Property 1 holds for the whole slice: no kernel call, and the strongest decisions go to the arithmetic engine's own yes/no. Property 2 holds for the value environment and for declaration-level specifications, and holds only partly for the ordering theory, which is symbol-based at its core. Property 3 holds weakly: the visible repetition is per operand variant, per fact store, and state-bound versus declaration-level, more than per source placement.
