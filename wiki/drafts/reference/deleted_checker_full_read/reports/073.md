## What this code is for

This half of `values::scalar` translates source expressions into the old checker's "checked" scalar forms: `CheckedScalarExpression`, `CheckedBooleanExpression` and `CheckedProofTerm`. It does not check anything in the sense of refusing a program: there is no diagnostic string in the slice, and every function returns `Option`. `None` means "this expression is not in the pure scalar family here", and a different builder (the header calls it the computation graph builder in `execution::scalar_computations`, 20-23) or a different stage is expected to handle or refuse it. The header says so directly: "Recording operands does not admit the call or establish its result frontier" (9).

The slice contains eleven modules. `expression_plans` (4592-5654) walks every statement of every state once and records one located row per scalar value, tagged with a role that names the source placement (guard, return, local initializer, assignment value, call argument, transition argument and so on). `boolean_lowering` (257-825) lowers body guards and Boolean expressions in the body's scalar namespace. `contract_entry` (2872-4386) lowers `requires` and crash conditions in the invocation-entry namespace, with its own second Boolean lowerer (`crash_entry::Reader`). `call_lowering` (1159-2579) lowers call arguments, including erased scalar lanes and erased proof-term actuals. `call_arguments`, `array_constructions`, `atomic_operands`, `case_membership`, `constant_array_projection` and `expression_facts` supply the pieces those share.

The rows this code produces are inputs to later stages. The rules in the table below are therefore admission conditions for a lowering, not accept/reject verdicts on a program.

## Mechanisms

- **Budgeted recursive reader** (`crash_entry::Reader`, 3284-3294, `charge` at 3450-3457). Each visited node costs one unit of a 4,096 budget and recursion stops at depth 64; exhausting either zeroes the budget so every later step also fails. Five constructors each write the literal `remaining: 4096` (3052, 3084, 3114, 3229, 3345). It serves `requires` clauses, crash conditions and entry guards. `entry_predicate_has_meaning` has its own depth cap of 64 (3144).
- **Fixed-step walks.** Peeling borrows, members, references, constraints and `generated_from` chains uses loops of 8 steps (1963, 2197, 2337, 2362) or 64 steps (2983). A chain longer than the cap yields `None`/`false` without a message.
- **Dense scalar namespace.** A value is addressed as `Parameter { position }` or `Local { position }`, where the position is the count of non-erased primitive formals before it, plus the count of earlier immutable non-reference locals (477-484, 4428-4456, 5376-5389). Positions are recounted at each use (`scalar_position`, 3889-3898; `scalar_position_count`, 4448-4456). `mut` locals, reference locals and `mut` formals are addressed by symbol as `StorageRead` instead (460-475, 1541-1546).
- **Closed Boolean evaluation** (293-317). The code lowers an expression with empty parameter and local rosters and evaluates the result with a resolver that answers `None` for every variable, so only variable-free expressions produce a value.
- **Unrolled byte equality** (638-740). For two fixed arrays or two bounded owned sequences the code builds a Boolean chain, from the highest index down: `len(left) <= i || (i < len(right) && left[i] == right[i] && rest)`, all under `len(left) == len(right)`. The chain has one level per element up to the smaller capacity, with no cap. Reads carry `ExpressionHandle::invalid()` as their observation (686, 691).
- **The plan walk** (`build_checked_scalar_expression_plans`, 5485-5567). One pass over every machine, state and statement. For each statement it runs `array_elements::plan`, then `range_operands::plan`, then the planner for the statement kind (5530-5545). Locals join the roster after their own statement is planned (5051). A final pass removes rows whose source needs semantic-cast custody; it calls `expressions.retain` once per such binding (5549-5560), which is quadratic in the worst case.
- **Entry rebinding** (`EntryOperands`, 4209-4385). After lowering in the entry state's statement-0 namespace, a second pass rewrites each `StorageRead { symbol }` into the formal's entry position or erased position and refuses anything rooted in a local.
- **Symbol-derivation correspondence** (2213-2221, 2245-2373). Two type or index symbols "correspond" when equal or when one is reachable from the other through `generated_from` within 8 steps, in either direction. It serves erased generic proof carriers passed between a constructor's fields and a callee's formals.
- **Whole-program scans as lookup.** `call_is_boundary` scans all machines, traits and operators (1225-1241); `case_membership::lower` scans all machines and states (2606-2615); `structural_case_name` scans all data definitions (2788-2797); `projection_instantiated_by_call` and `projection_result_matches` scan all machines and states (2060-2080, 2229-2242). Each runs per expression lowered.

## Accepts or skips without proof

- **No operator record counts as builtin.** `operator_is_builtin` returns true when `operators.expression_use(expression)` is `None` (4572-4576). `BooleanLowering` relies on it alone (488, 496, 544, 568, 5614, 5626). The `Reader` adds `has_builtin_binary_expression_meaning` when a machine is known (3533-3542). Whether operator facts are complete for every operator expression: cannot tell from this slice.
- **With no machine, the builtin-meaning check is skipped.** `self.machine.is_none_or(...)` (3534) makes signature and operator crash conditions rely on `operator_is_builtin` alone for `&&`, `||` and ordering; only `==`/`!=` between Booleans get the extra spelled-meaning check (3575-3593). Integer and float comparisons hand the question to `result_contract::lower_*_contract_comparison` (3733, 3754), outside this slice.
- **The first state stands in for a missing state.** When the `Reader` has a machine but no state it checks meaning in `machine_states(machine).first()` (3538-3539).
- **Arguments that fail to lower are dropped, not refused.** In `lower_call_arguments` a scalar argument that does not lower is omitted while its ordinal still advances (1419-1440); likewise asm operands (1284-1307), erased lanes (1332-1360) and proof terms (1368-1392). A non-primitive formal is skipped (1399-1402). For a boundary callee every erased argument is skipped (1328, 1397). The header says another builder owns admission (9); cannot tell from here whether a consumer notices a missing ordinal.
- **`atomic_operands::lower_carrier` always returns `Some`** (254), even with zero rows (it breaks out when the place has no primitive type, 231-235, and omits operands that do not lower, 236-252). `assignment::plan` then returns early (4735), so an atomic assignment never gets index or value rows.
- **Transition arguments** are zipped with the target's formals (5200-5201), so a count mismatch is silently truncated. Unresolved transfers and targets, unlowerable arguments and erased formals with zero or several lanes all `continue` (5181-5194, 5268-5273, 5304-5306). ## Surprises

1. **The slice refuses nothing and says nothing.** It has no diagnostic text and no error type. `None` carries two meanings that the code does not distinguish: "not a pure scalar, another builder will take it" and "malformed or unsupported". A reader cannot tell from this file which `None`s become errors.
2. **The proof kernel is never called here, but kernel terms pass through.** The slice contains no `proof_admission`, `ProofNode`, `verify_obligation` or certificate use. `lower_proof_term` copies `constructor.schema`/`ty` and `evidence.term`/`ty` from `program.prepared_mathematics()` into `CheckedProofTerm::Mathematical` and `MathematicalApplication` (1684-1688, 1723-1728, 1734-1738), with the one comment "already kernel checked" (1681). So for erased proof arguments this code transports evidence produced elsewhere. Where a proof term is built from syntax instead (array, struct, name, projection, identity call; 1755-1933) the decision is this code's own.
3. **Same rule, different strictness by placement.** `lower_call_arguments` drops an unlowerable argument and keeps the call (1419-1440); `lower_direct_call_binding_arguments` drops the whole call (2450, 2494, 2519); `transition::plan` drops the argument (5304-5306). The first also returns `None` for an erased formal that is neither lane nor proof carrier (1393-1395), where the transition copy just continues (5270-5273).
4. **A direct call that initialises an immutable primitive local is recorded twice.** `local_data::plan` first calls `retain_expression_call_arguments` (4956-4965), which produces `UnitCallArgument`/`BoundaryCallArgument` rows with call ordinal 0, and then `lower_direct_call_binding_arguments` (5002-5025), which produces `CallArgument` rows for the same arguments. When the second succeeds, no `LocalInitializer` row is written (the `else if` at 5026).
5. **Call arguments are retained differently for a `mut` primitive local.** The condition at 4956-4960 skips `retain_expression_call_arguments` for a `mut` primitive local, while `assignment::plan` retains them for every assignment (4764-4768). `array_constructions` has the mirror asymmetry: a local's initializer call is always a direct root (126-128), an assignment's only when the callee is a boundary (129-132).
6. **Dead branch.** `if continuation { continue; } continue;` (5270-5273): both paths do the same thing.
7. **Unused inputs.** `lower_machine_entry_crash_contract_expression` takes `_exact_integer_casts` and ignores it (3042). `lower_current_state_predicate` takes `statement_index` and uses it only for a bounds test (3073-3076); the `Reader` it builds has no statement position, although the comment speaks of the caller's "actual statement" (3062-3063). In `lower_entry_scalar` a `Reader` is built with `subjects: None` and used only for its parameter list, budget and `primitive` (3222-3232).
8. **Unbounded unrolling.** `byte_carrier_pair_equality` builds a nested Boolean one level per element for the smaller of two capacities (699-727) with no cap, while the contract reader next door caps depth at 64. Two large fixed byte arrays compared with `==` would produce a tree as deep as the array is long.
9. **Placeholder handles enter the rows.** Unrolled byte reads use `ExpressionHandle::invalid()` as observation and occurrence (686, 691). Dynamic-family arguments are pushed with `ExpressionHandle::default()` as their authored expression (1483); `retain_call_arguments` then stores that handle in a source binding (1207), and the final pass asks `semantic_casts::requires_custody` about it (5551). What that query answers for a default handle: cannot tell.
10. **Correspondence of erased generic carriers is decided by a search over the whole program.** `projection_instantiated_by_call` (2041-2081) accepts when any statement in any state that owns the formal passes the projected expression to a call whose formals line up through `generated_from` chains. `projection_result_matches` (2223-2243) accepts when the expression's result type matches in any such state. Either one is sufficient (2019-2028). This is a heuristic match, not a check at the call being lowered.
11. **An identity function is special-cased.** A call to a mathematical definition whose body is a bare reference to one of its parameters is treated as that argument (1896-1931), with a `generated_from` fallback to find the parameter (1909-1912). No other definition body is handled; the arm returns `None` for them.
12. **`source_constructor` is consulted twice** in a row with overlapping conditions (1652-1669, then 1670-1730). The first recurses when the recorded constructor is a different expression; the second handles the case where it is the same one.
13. **`const` formals block every contract comparison.** `comparison_telescope` returns `None` if any formal is `const`, even one the predicate does not read (3688-3698). The nearby comment says "Unused generic parameters do not prevent checking a concrete condition" (3319-3320). That statement holds for type parameters and not for `const` value formals.
14. **Body Booleans have no float comparisons.** `construct_integer_comparison` refuses non-integers (790-796) and `BooleanLowering` has no IEEE arm, so `x < 1.5` in a body guard is never a pure Boolean plan, while the same text in a `requires` clause is read by the `Reader` (3552-3567).
15. **`scalar_qualified_call_expression` only recognises callees that are states.** It looks the target up with `program.state_by_symbol(call.target_symbol)` (2568), so a cast-wrapped call to a requirement, operator or dynamic slot is not a "value call" here, though `lower_call_arguments` handles those targets.
16. **`case_membership::lower` re-derives its own context.** It is handed only a parameter slice and searches all machines for a state with an equal slice (2606-2615). Two states with identical formal lists and the same formal symbol at that position cannot both exist, so the match is probably unique, but the function takes the first match without checking.
17. **Two `expect` calls** (887, 5502) panic if `scalar_parameter_roster` returns `None`. From 4428-4441 it cannot: the roster is filtered by the same test that the mapping repeats.
18. **Property 3 is visible in the data model, not only in the code.** The role enum itself (`Return`, `ContinuationReturn`, `LocalInitializer`, `StorageInitializer`, `AssignmentValue`, `AssignmentIndex`, `CallArgument`, `UnitCallArgument`, `BoundaryCallArgument`, `ErasedCallArgument`, `ErasedUnitCallArgument`, `DynamicFamilyArgument`, `TransitionArgument`, `TransitionContinuationArgument`, `ArrayElement`, `AtomicOperand`, `Guard`) is a list of source placements. Every consumer of these rows must therefore also branch on placement.
