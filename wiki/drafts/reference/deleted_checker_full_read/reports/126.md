## What this code is for
This file checks quotient types. A `quotient data` declaration names a carrier data type and a two-place relation over it, and must select one conformance to the core `Equivalence<C, R>` trait as evidence that the relation is an equivalence (`equivalence_selection`, 5-514; `formation_collection`, 515-619). The file also handles the two built-in operations `Quotient::lift` and `Quotient::define`, which let a public machine over quotient values be implemented by a "representative" machine over carrier values, justified by a user-written "congruence" theorem machine and, for lift, an optional "forward precondition transport" theorem (`relation_plan`, 916-7901). For each such call the code derives a "direct terminal relation plan": which arguments are quotient-related and which must be equal, what the theorem's parameters, premises and conclusion must look like, how public preconditions (called Q) relate to representative preconditions (called P), and whether the representative and theorems are pure, terminating and crash-free. It then turns a complete plan into a `language_semantics::quotient_correspondence::QuotientCorrespondenceJudgment` made of positions and identity strings (`normalized_judgment`, 1695-2611; `request_admission`, 7902-8029). Two public entry points exist: `validate_quotients` (8109-8123), which at validation time rejects every quotient operation with a long diagnostic describing how far its plan got, and `admit_checked_quotient_requests` (8125-8154), which after other checking either returns one judgment per request or falls back to the same rejecting diagnostics. The file contains no tests and no call to the proof kernel.

## Mechanisms
- **Call-closure walk for "checked body only"** (462-484). Depth-first over `machine_call_dependency_symbols` with a `HashSet<u32>` of visited arena indices. Returns the name of the first machine whose supply mode is not a checked body. No budget. Serves quotient formation evidence and the representative/theorem closure rule.
- **Fact identity by rendering** (`proof_facts_match`, 3350-3409; `proof_expression_identity`, 3461-3492; `expression_symbol_trace`, 3494-3636). Two proof facts are equal when two strings agree: the rendered proof expression with parameter substitutions, and a "trace" string built by walking every expression node kind. Returns no identity (so no match) when the expression contains a saved subject (3473-3480) or has no normalized identity (3466). Serves Define precondition pairing, theorem legality premises, transport premises/conclusions, and lift's exact-match step.
- **Greedy one-to-one matching** (2875-2917; 5980-5999; 6032-6055). For each expected fact, find the first unmatched actual fact that matches and remove it. No backtracking; relies on match being an equality.
- **Expected theorem schema derivation** (5774-5894). From the per-position relations: two theorem parameters and one relation premise per quotient input, one shared parameter per equal input, two legality premises (left, right) per representative `requires` fact, left and right argument position lists.
- **Dependent/fixed partition of preconditions** (2755-2799, 2943-2995). A `requires` fact is "dependent" if any `Name` node in it refers (by symbol or head symbol) to a parameter in a quotient position; otherwise "fixed". Public parameters of quotient type that are not passed to the representative also count as varying (2716-2726).
- **Structural type match under static substitution** (`substituted_type_matches`, 5206-5342). Recursive match of a representative (template) type against a concrete type through named, reference, fixed array, slice and generic nodes, looking up type and const parameters in the static bindings; every other pairing falls back to normalized identity equality (5337-5340).
- **Independence test by double rendering** (3431-3451). A membership fact's domain argument is accepted only if its type identity is the same when all static parameters are rendered as `membership-static-a` and as `membership-static-b`, that is, it mentions no static parameter.
- **Arithmetic implication with symbol bindings** (1081-1087, 1123-1133, 1368-1519). Builds bindings for `strict_arithmetic_expression_implication`: a shared atom (identified by a string such as `$theorem_parameter_3`) for a public parameter and its representative parameter, an exact integer for an integer literal argument, and exact integers for const static bindings. Only exact integer primitive parameters get bindings (1455-1458). The implication itself is in another module.
- **Result-flow graph check** (3965-4062). Builds one forwarding edge per non-result state and follows edges from every state until the result state, refusing a revisit. Quadratic over the state list; no budget.
- **Immutable alias chain walk** (3879-3922). Walks statements backwards from the returned name, requiring each to be an immutable local of the return type initialised by the next name, ending at the request in statement 0.
- **Closed literal classification** (4491-4774). Chooses one of 14 literal shapes by the target type's array depth and leaf primitive.
- **Eligibility fences** (6920-6974, 7241-7274). Termination from an oracle keyed by machine symbol, purity from `has_pure_effect_closure`, crash-freedom from `has_no_crash_routes`; `infer_operational_may` and `infer_service_reaches` are recomputed inside every plan derivation (6926-6927).
- **Batch admission** (7908-7960). Every request must produce a judgment; rows are sorted by declaration string, overload string and statement position; equal neighbours are an error.

No numeric budgets, depth limits or fuel appear anywhere in this file.

## Surprises
1. **The plan machinery is wider than what admission accepts.** Plan derivation handles representative static applications with type, const and machine arguments (5439-5534), type matching under substitution (5206-5423), const bindings for arithmetic (1423-1445), mutable parameters (4339, 6229) and Define preconditions paired one-to-one (2801-2919). The bridge then refuses all of them: any static binding (1811-1833), any type or lifetime parameter (2522-2533), any mutable parameter (2535-2543), any Define precondition (1887-1892, 1931-1944), any generic quotient (2449-2453). A plan that uses those features can only reach the rejecting diagnostic at 872-877. A large part of the file therefore produces diagnostic text, not acceptance.
2. **The function called `reject_quotient_operation_requests` rejects even a complete plan** (863-877: "but the complete checked quotient request batch was not admitted"). It is both the validation-time gate (8117) and the error reporter after failed admission (8147).
3. **Admission errors are thrown away.** `admit_checked_quotient_requests` ignores the `Err(Vec<String>)` from `extract` (8141-8145) and re-derives every plan to build diagnostics (8146-8147). The "duplicate canonical quotient correspondence identity" message (7955-7957) and all `extract_one` messages (7982-8009) and bridge messages (1745-2609) can therefore never reach the user through this path, except the subset that `reject…` re-renders as "normalized source correspondence unavailable: {reason}" (684-686).
4. **Repeated whole-program work.** Each plan derivation recomputes `infer_operational_may` and `infer_service_reaches` (6926-6927). A failed admission derives each plan at least twice (7993 and 649), and `render_failed_builtin_implication` derives the relation, runtime correspondence and partitions a third time (7418-7443).
5. **Arithmetic fallback is all-or-nothing on fact kind.** `public_expression_hypotheses` returns `None` if any public fact in the group is not a plain expression (1162-1174), so one membership or proposition precondition on the public operation disables arithmetic implication for every representative precondition in that group (1118-1122). Dependent goals see only dependent hypotheses and fixed goals only fixed ones (1088-1093, 1195-1196).
6. **Transport schema is order-sensitive, congruence schema is not.** The transport check indexes `requires[premise_position]` and `ensures[conclusion_position]` (6421, 6461); the congruence check searches (5980, 6032).
7. **Name paths with more than one member are not substituted in the trace** (3533-3539). A fact written over `p.field` as a multi-member name keeps the raw symbols of `p` in its trace (3540-3545), so the public and representative versions cannot be equal by identity. Facts using a `Member` node go through the receiver (3597-3599) and do work. Which form the earlier stage produces I cannot tell.
8. **Literal spelling is used two ways.** A closed literal argument keeps `literal.to_string()` (4761, 4905, 4964), while an integer literal inside a fact is traced by `canonical_spelling()` when landed and by `Display` when not (3623-3626). Float literals are traced by presented bits when available, otherwise by source text (3627-3630). Two spellings of one value may give different identities; cannot confirm without the literal types.
9. **No-op and dead code.** `theorem_location` returns its argument unchanged (1584-1593). `retain_legality` is always `true` (2047), so the `else` at 2297-2299 is dead. The match at 1459-1469 has one arm covering both variants. `_substitutions` in `static_argument_matches_type` is unused (5382). The second `NotQuotient` at 7547-7549 cannot happen because `quotient_for_type` already requires `quotient.is_some()` (512). The carrier re-check at 214-219 recomputes what the caller computed at 544 from the same input and cannot fail.
10. **Hard-coded position 0** in three transport errors (6356, 6368, 6399), whatever the real position.
11. **Misleading diagnostic for unknown law rows.** A conformance row whose requirement name is not one of the three law names gets "strengthens or changes the sealed equivalence law premises" (232, 194-200).
12. **Relation binders are handled in one path only.** `exact_relation_application_matches` supports generic carrier binders (350-380), which serves the formation law check. For operations, any relation with binders is refused up front (7554-7556), and the theorem conclusion requires empty binder arguments (6117).
13. **`CheckedTerminationOracle` has two meanings of "unconditionally terminates".** The trait default reads the checked summary and requires no premises (8050-8056); the `TypedTrees` implementation overrides it with `denotational_calls::unconditionally_terminates` (8065-8067). At validation time the oracle is the typed program itself (8117).
14. **A dense table indexed by symbol arena index** is grown to the largest public parameter symbol index for each transport check (6359-6372).
