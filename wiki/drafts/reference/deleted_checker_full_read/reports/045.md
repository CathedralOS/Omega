## What this code is for

This is the first half of the builder that turns typed expressions into "checked scalar computation plans": a DAG of nodes (`Value`, `Apply`, `Call`, `Select`, `Dispatch`, `StorageObservation`, `StructuralField`, `CaseMembership`, `WithOperands`, ...) that fixes evaluation order, operand custody and cleanup for scalar expressions that contain calls, storage reads or matches (esc.rs:1-11). It does not issue diagnostics. Nearly every function returns `Option`, and `None` means "this builder has no plan for this expression"; what a missing plan means for the program is decided by callers outside the slice. The slice holds seventeen sub-modules, apparently separate files flattened into one: atomic loads, boundary (bodyless/extern-like) calls, byte-sequence comparisons and predicates, call-argument evaluation, a result-type cache, enum case membership and construction, unit "completion" trees, entry-coordinate reads, declaration (measure) inputs, match dispatch, dispatch payload copies, dynamic (selector) calls, enum equality, indexed reads, integer operand typing, known-Boolean-result folding, quotient calls, and runtime rank observations for `terminates by`. The checks it makes are shape and agreement checks: a primitive type equals the expected one, a count matches, exactly one record matches a key, a flow record names the same expression. It trusts earlier stages for proofs: bounds, contracts, match coverage of structural subjects, and rank descent are all stated in comments as already established elsewhere (esc.rs:2005, 3202-3203, 3658-3661, 4939-4940, 5104-5108, 5782-5785). There are no tests in the slice.

## Mechanisms

- **Computation DAG with operand templates.** A node is `Apply { expression, operands }` where `expression` is a pure scalar template over `Parameter { position }` holes, and operands are other nodes (esc.rs:4241-4264, 4547-4559). This separates effectful sub-evaluations (calls, reads) from pure arithmetic. No budget.
- **Integer operand typing** (`integer_operand`, `integer_operands`, esc.rs:4272-4706). Each operand carries its own carrier type and arithmetic domain. An anonymous literal lands at the peer's carrier (`integer_peer_operand_carrier`), and the caller's expected type is used only when neither side has a carrier (esc.rs:4695-4704). Results are memoized in a linear list keyed by `(expression, expected)` (esc.rs:4277-4287).
- **Scalar dispatch planning** (esc.rs:2515-2650). Builds arms in authored order, tracks coverage (wildcard, or both Boolean literals), and stops at the first covering arm.
- **Admitted-arm dispatch with a pattern prefix** (`declaration_dispatch`, `dispatch_prefix`, esc.rs:2658-2753). Patterns of skipped arms are still evaluated before the next admitted arm. "Evaluate all, yield last" is encoded as an `Apply` whose template is `Parameter { position: last }`. The last admitted arm becomes a wildcard.
- **Rejected-pattern carry for structural dispatch** (esc.rs:2939-2999). Patterns of arms whose value is statically unreachable are wrapped onto the next arm through `WithOperands`.
- **Completion tree builder with cycle detection** (esc.rs:1908-1999). Recursion over match/call expressions with a visited map; a node in progress revisited gives `Refusal::Cycle`; a finished node is shared.
- **Enum equality expansion** (esc.rs:3858-3928). For payload-free enums it takes one tag-membership observation per case per side and chains `prev && (l_i == r_i)`, one `Apply` per case. A known constructor on one side reduces to one membership test (esc.rs:3820-3857).
- **Known Boolean result of a DAG** (`boolean_result`, `boolean_expression_result`, esc.rs:4849-4934). Three-valued evaluation: literal Booleans, `Select` (both branches equal counts), `Not`, and short-circuit `And`/`Or`. Calls, storage reads and dispatches are unknown. The comment says this does not license removing the graph (esc.rs:4832-4840).
- **Call result-type table** (esc.rs:1504-1610). Precomputes, in parallel with rayon, whether each distinct flow-call result type admits a checked structural result; lookup is a binary search with a compute-on-miss fallback.
- **Captured dispatch value tracking** (esc.rs:3518-3644). A worklist over expression children finds whether an expression reads a payload copied at a transition; pure roots that do are withdrawn.
- **Declaration binding search** (`has_declaration_binding`, esc.rs:2357-2401). A typed-reference walk finds whether an expression mentions a rebound measure formal.
- **Rank observations** (esc.rs:5101-5824). For each state with one agreed rank record it builds the runtime natural-number rank: identity, `MAX - x` complement (esc.rs:5787-5823), `upper - lower` distance in u64 (esc.rs:5189-5220), sequence length, or a declared measure's body evaluated with formals bound to entry coordinates. Inputs are widened to u64 (esc.rs:5312-5350).
- **Unique-match lookups.** Many decisions are "exactly one record matches": boundary trait owner (esc.rs:257-266), entry bound (2122-2135), comparison use (2506-2513), rank row (5415-5425), capture/binding (2196-2232).

There is no fixpoint, unification, interval analysis or search budget in this slice.

## Identity by text

- A sealed accessor is matched by operation name: `target.operation == call.target.as_str()` (esc.rs:521).
- An inline-assembly register operation is found from the built-in function's name: `AsmRegisterOperation::from_intrinsic_name(builtin.name())` (esc.rs:963-972).
- The primitive type of each such operand is found from the carrier's name: `PrimitiveType::from_name(carrier.name())` (esc.rs:981).
- Case and field path segments carry the member name next to the identity: `CheckedMemberIdentity::of_member(case.identity, case.name.clone())` (esc.rs:3373-3378).
- `declaration_input` reports failures as `&'static str` sentences (esc.rs:2184-2346); these are messages, not identities.

Everything else in the slice identifies things by handle: `SymbolHandle` equality, `ExpressionHandle` equality, `(arena_index, generation)` map keys (esc.rs:1307, 1768, 1915, 2914), type identities from `normalized_type_identity` and `structural_type_identity`, and structural equality of `CanonicalPlace` (root plus segments, esc.rs:2199, 2226, 2284). This slice is mostly evidence against property 2. Places are still source-shaped: a `CanonicalPlace` is a root symbol plus authored path segments, and many checks compare such paths.

## Surprises

- **This code is a plan builder, not a checker with messages.** A refusal is a bare `None`. The only human-readable reasons in the slice are the seventeen `&'static str` sentences in `declaration_inputs` (esc.rs:2184-2346), and the one caller in the slice throws them away with `.ok()?` (esc.rs:4295). `completions` is the one place with a structured refusal enum that is stored with the root (esc.rs:1892-1905).
- **Possible dropped cast.** In the integer `Cast` branch, when `construct_integer_cast` returns something other than `IntegerWiden` or `IntegerExactCast`, the code builds `IntegerOperand { value, value_source: expression, domain, ..operand }` and so keeps the inner operand's `computation` (esc.rs:4630-4637). `materialize_integer` returns `operand.computation` whenever it is valid and ignores `value` (esc.rs:4229-4230). If the inner operand was a call or read, the cast template in `value` would be discarded while later code takes the type from `value` (esc.rs:4541-4546). I cannot confirm this without `construct_integer_cast`, which is outside the slice.
- **The three arm loops disagree.** `prepare_dispatch` skips a repeated Boolean literal pattern (esc.rs:3157-3159); `dispatch` plans it again (2615-2625). The integer `Match` branch counts Boolean literal patterns toward coverage without checking that the subject is Boolean (4472-4480). `dispatch` keeps float subjects out of `declaration_dispatch` when arms are unreachable (2573-2575), but a float subject with rank-admitted arms goes into `declaration_dispatch` anyway, where every `equality_use` is invalid (2542-2550, 2714).
- **Inconsistent use of the expected carrier.** Three sources refuse when the carrier differs from `expected` (esc.rs:4297, 4329, 4360); the reference observation, structural field, same-carrier cast, semantic cast, indexed read and call branches do not compare with `expected` at all (4340-4351, 4371-4418, 4440-4447, 4499-4516).
- **Operating-system features inside the scalar planner.** Descriptor-table operations (`ActivateTask`, `ReloadSegments`, `ReadTask`, `ReadSegment`) are recognized as callees with hard-coded argument shapes (esc.rs:382-414), and inline-assembly register intrinsics are recognized by name (963-997).
- **A whole-value read is encoded as a field read with no field.** `quotient_scalar_call` emits `StructuralField` with `field: SymbolHandle::invalid()` (esc.rs:4977-4988). `quotient_call_value` also calls `structural_value` for a primitive formal (5017-5023).
- **Possible panics.** `source.segments[prefix.segments.len()..]` slices without checking that the prefix is shorter or actually a prefix (esc.rs:3440-3445). `program.machines()[position.0 as usize]` and `machine_states(machine)[position.1 as usize]` index directly (4162-4163).
- **Mixed integer conversions.** `self.statement_index as u32` appears four times (esc.rs:3262, 3281, 3301, 3438) while the same value is converted with `u32::try_from(...).ok()?` elsewhere (125, 147, 1900, 3697, 4972).
- **Maps and linear scans where the project asks for dense tables.** `BTreeMap<(u32, u32), _>` keyed by handle parts for completion visits and dispatch receivers (esc.rs:1912, 2912-2914); `Vec::contains` as a visited set (2383, 3566); `withdrawn.contains` inside `retain` (3633-3638); a linear memo list for integer operands (4277-4281).
- **Failed attempts leave nodes behind.** Several functions insert nodes or cleanup rows and then return `None` (for example esc.rs:356-368 followed by 384-386 and 405-407; 4648-4649 followed by replacement at 4669-4684). A `statement_nodes_start` field (5534, 5564) suggests later code deals with this; not visible in the slice.
- **Rank observations use only the first witness subject** of a machine (esc.rs:5446-5448) and clear `is_mutable` on every input so that a formal means its arrival value (5408-5411).
- **Redundant comparison.** `Some(geometry.primitive_type) != Some(...)` (esc.rs:2216-2217).
- **Enum equality covers only payload-free enums.** Any case with payload fields makes the whole comparison unplannable here (esc.rs:3807-3816).
- **Property 1 is supported but in a specific form.** The slice never consults the proof kernel. It is not itself the judge of proofs either: it repeatedly says an earlier owner already proved the thing (index bounds, contracts, coverage, rank descent) and then emits nodes marked `formation_decided: true` on that word (esc.rs:5208, 5339, 5811).
- **Property 3 shows up as per-source and per-callee-kind copies**, not as per-placement copies. Writes, guards, arguments and returns reach this builder through a role value, so the slice has one evaluator for all of them (esc.rs:1068-1071).
- **Layout.** The file is a run of top-level `mod name { ... }` blocks with their own `use` lists, and several stretches are not rustfmt-shaped (esc.rs:1197-1211, 2506-2511, 4041-4049, 4977-4988). It looks like a module tree flattened into one file.
