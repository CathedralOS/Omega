## What this code is for

The slice holds twelve sibling modules of the old checker's "proof contracts" layer, each a whole-program pass or a helper that other passes call. They run on the source-shaped typed tree (`CheckingInput`: expression table, statement table, type reference table) and push `Diagnostic::error` strings.

- `parameter_domains` (5819-5897) lists the domain constraints written on a parameter's type.
- `parameter_expression_meaning` (5899-5995) decides whether a contract expression over parameters uses only built-in operator meanings.
- `proof_embeddings` (5997-6685) polices the compiler-owned proof term `embed(value)` and "mathematical terms": they may appear only in proof positions.
- `proof_facts` (6687-7642) checks the shape of contract facts (boolean expression, `x in Domain`, proposition application) for five kinds of owner, and checks proposition declarations and their witness evidence traits.
- `proof_only_faces` (7644-7795) forbids proof-only data from appearing where a runtime layout is needed.
- `properties` (7797-8498) checks the data properties `[copy]`, `[linear]` and `[carry(...)]` against the fields, and derives the effective carry policy of a type.
- `proposition_entailment` (8500-9024) decides whether a checked machine establishes the propositions it `ensures` and the propositions its callees `require`.
- `qualification_evidence` (9026-9705) decides who may assert a domain membership or carry permission without a checked body (only boundary trait requirements the domain names as an establishment route).
- `relevance` (9707-10889) enforces that `[erased]` fields, parameters and locals never feed runtime data or control.
- `scalar_boundary_guarantees` (10891-11202), `signature_ensures` (11204-11365) and `slice_ranking` (11367-11589) are three narrow recognisers: an IEEE float "result is not NaN" consequence, bounds a callee's `ensures` places on a caller's storage through a `&mut` parameter, and "recursing on a slice tail strictly decreases".

Nothing in the slice calls a proof kernel. There are no tests in the slice.

## Mechanisms

- **Iterative cycle-safe expression walk with marks** (5911-5969). A stack of `(expression, completed)` pairs and a byte vector indexed by arena slot (1 = on the active path, 2 = done). Meeting a slot marked 1 returns `false`. The vector grows to the arena index of the largest visited expression on every call. Serves "built-in meaning of a parameter bound".
- **Proof/runtime occurrence census** (6214-6345). Two hash sets of expression handles are filled: `proof_seen` from every proof fact, every signature contract row, mathematical application nodes, transparent proposition bodies, bodies of proof machines and indexed logical machines, content projection bodies, and assembly facts; `runtime_seen` from machine owned-data initializers and all other statements. Erased-initializer nodes are then moved from runtime to proof (6341-6345). A node is legal as a mathematical term or `embed` only if it is in the first set and not in the second. No budget. Serves the proof-only rule for `embed` and mathematical terms.
- **Structural primitive typing of an expression** (6504-6562). When no declared type is found, the code computes the primitive type bottom-up: comparisons and logical operators give `bool`; arithmetic and bitwise operators give the common primitive of both sides, or the typed side's primitive when the other is an integer literal with no landed type; shifts take the left operand's type if the count is an integer.
- **Carry policy derivation** (7963-8168). A recursive walk over a type that intersects carry policies: primitives, zero-length arrays, `Unit` and const expressions are PERMISSIVE; references and slices are STRICT and set `requires_borrow_preservation`; `dyn` traits are STRICT; a type parameter contributes its declared bound or STRICT; named data contributes its declared policy (default PERMISSIVE) intersected with every stored field; unknown data, boundary-opaque data and data already being visited are STRICT. It keeps three stacks: parameters in scope, type-argument substitutions, and a visiting list. It also tracks a second policy `borrow_independent` that ignores references. No depth budget. Serves `[carry(...)]`.
- **Structural property check for `copy`/`linear`** (8333-8410). A recursive type walk with a substitution list; when a substitution is followed, all substitutions for the same formal are removed first (8359-8376), which prevents a self-mapping loop.
- **Proposition entailment by label sets** (8513-8716). For each state, the goals and the known facts are `String` labels. The pass walks the state's statement list once, in order; each call adds the callee's `ensures` labels (rendered with parameters replaced by the display text of the arguments, 8940-8961) and checks the callee's proposition `requires` against the set. Leftover goals go to two outside functions. There is no join, no invalidation and no budget. Serves proposition `requires`/`ensures`.
- **Qualification source classification** (9062-9119, 9613-9675). A small decision table: target kind (checked body / admitted requirement / boundary requirement / propagated) crossed with whether an authorization exists. The authorization is computed by scanning the domain's declared `establishment_routes` for the boundary trait and requirement symbol (using the template symbol for a closed generic application, 9652-9655).
- **Relevance contexts** (9740-9745, 10854-10872). Each expression is walked under one of three contexts (Runtime, ErasedInitializer, Proof). A call argument at a position whose callee parameter is erased switches Runtime to ErasedInitializer. Only Runtime reports erased reads; only ErasedInitializer reports runtime calls and atomics.
- **Tail-bound comparison** (11443-11559). A bound is normalised to `Literal(usize)` or `Symbol + offset` through four lookups on immutable integer bounds (11449-11482). Ordering is decided for literal/literal, same-symbol offsets, and symbol-vs-literal using the symbol's type floor (unsigned and `addr` 0, signed minimum, raised by an enforced declared range). Literal-bound versus symbol-start is always `false`. Arithmetic uses checked adds. Serves termination by slice shrinking.
- **Write-origin projection** (11317-11363). A callee bound on `param.path` is mapped back through every recorded write origin of the argument to a scalar storage coordinate; the bound is kept only if every origin gives the same place, preserves the scalar value and has the same primitive type.

## Identity by text

- A machine is "the `embed` machine" if the last `::` segment of its name is `embed` (6208). A call "names embed" by the same suffix test (6375, 6418). `is_exact_embed_call` requires both the target string to equal the built-in's name and the symbol to be the built-in (6445-6449).
- A domain constraint with no resolved symbol is treated as a carry permission if its name parses as one (5859-5869); likewise `carry_permission` renders the domain path to a joined string and parses it (7389-7395, 7571-7578).
- `is_implicit_case_domain` accepts `Type::Case` when any data definition's name equals the first segment and it has a variant whose name equals the second (7397-7414). Names are compared unqualified; the first match wins.
- The evidence trait of a witness proposition is found by symbol **or** by name, even when the symbol is valid and different (6907-6910). `select_named_evidence_implementation` finds the trait by `candidate.name == conformance.trait_name` only (8836-8839) and matches the conformance by alias string (8833).
- `expression_type_reference` finds a data field by member name (6611).
- `proof_argument_declared_type` finds the machine by name (`machine_by_name_str`), its attached data by name, and the field by name (7315-7331).
- `self.x` is recognised by path shape and `is_self_receiver()` on the first segment (7369-7387, 10405).
- `ProofFactOwner` carries `kind: &'static str` and names of data/domain/state as strings (6798-6816); `proof_fact_machine_name` returns a name that is then used for lookup (7355-7367).
- Properties are passed as the strings `"copy"` and `"linear"` and matched on (8313, 8320, 8330, 8354, 8385, 8443-8449, 8492-8496). Type parameters and data definitions fall back to name equality when the symbol is invalid (8038-8053, 8110-8113, 8438-8440, 8486-8490, 10318-10324).

A proposition becomes `normalized_identity_label(application, binder labels, argument labels)` where argument labels are rendered expressions (8996-9023). ## Accepts or skips without proof

- **No kernel anywhere.** No call in the slice reaches `proof_admission`, `ProofNode`, `verify_obligation` or a certificate. Every acceptance is this code's own yes, or the yes of a sibling function (`transparent_proposition_application_entailed`, `transparent_call_requirement_entailed`, `validate_checked_call_candidate`, `has_builtin_spelled_expression_meaning`). The records named "authorization" and "receipt" (`BoundaryQualificationAuthorization`, 9671-9674; `OpaqueDataPropertyReceipt`, 7816-7837) are plain structs holding symbols.
- `has_builtin_parameter_bound_expression_meaning`: a static type predicate is accepted without looking at its operands (5935-5937); `and`, `or`, bitwise and shift operators get no built-in-meaning check (5985-5992); every node kind other than binary/unary/borrow/cast/atomic is accepted without descending, including calls, members, indexes and matches (5966). Cannot tell whether another check covers them.
- `parameter_domain_constraints`: a domain constraint whose symbol is valid but has no definition, or whose symbol is invalid and whose name is not a carry permission, is dropped silently (5850, 5870). Only the first substitution is followed (5884). Cannot tell.
- `validate_integer_embedding_calls`: if `validate_checked_call_candidate` returns `None` nothing is recorded here (6092-6151); the code relies on that function having reported through `reject`.
- `is_boolean_fact_expression` returns `true` for any call, index, member or name without checking its type, for any comparison without checking operands, and for any unary operator applied to such a thing, including bitwise-not (7522-7529). The machine-contract path (`is_boolean_owned_fact_expression`) uses only this syntactic test unless the fact is a `match` (7452-7457). So `requires n` with an integer `n` passes this check. The domain path and the assembly path do check the type of names, members and indexes (7422-7428, 7557-7563). Cannot tell whether a type check elsewhere catches the machine-contract case.
- `validate_proof_facts` zips arguments with parameters (7163-7167): a proposition applied to too few or too many arguments is not reported here. Cannot tell.

## Surprises

1. **Proposition entailment is textual and never forgets.** (8513-8716, 8940-9023.) A proposition is the string that rendering produces. Facts learned from a call are stored under the display text of the call's arguments and are never dropped when those variables are later written. Facts learned from proof-output calls are stored under the callee's own parameter names (8739-8745), so they can fail to match the caller's goal, or match a goal about a different value with the same spelling. Statements are scanned in list order with no notion of branches.
2. **A vacuous equality in evidence selection.** `select_named_evidence_implementation` builds the candidate interface with `requirements: expected_interface.requirements.clone()` and then tests `selected == expected` (8840-8850). The requirements part of the comparison can never fail.
3. **One matched witness discharges the whole clause.** After checking the first witness proposition of an `ensures` clause against the forwarded implementation, the code marks every proposition in that clause as produced (8774-8821).
4. **`CarryDerivation::derive` looks able to recurse without end.** When it meets a named type that has a substitution it calls `self.derive(argument)` (8037-8045) with the substitution still in place. If a data definition applies itself to its own parameter in a stored field (for example a field of type `Foo<T>` inside `data Foo<T>`, reached through `validate_carry_policy`, which does not put `Foo` in the visiting list first, 7930-7931), the inner pass maps `T` to a type reference that is again `T`, and a field of type `T` would loop. The sibling walker for `copy` guards exactly this case by excluding self-mappings and removing the formal (8359-8376). Whether an earlier stage refuses such data before this runs I cannot tell.
5. **The "boolean-shaped" test answers differently per owner.** For a domain or an assembly fact a bare name must have type `bool` (7422-7428, 7557-7563). For a machine or statement contract a bare name, member, index or call is accepted with no type check (7456, 7522-7526), and `match` is accepted only there (7458-7478). A `match` fact in a domain, a data default domain or a trait signature contract is always "not boolean-shaped".
6. **Const binder arguments are matched by scanning the whole type table.** To substitute a proposition's `const` binder, `argument_matches` searches every type reference row for a `ConstExpression` whose integer literal equals the supplied literal (6735-6745). If the program has no such type reference anywhere, the function returns `false` and the user gets "argument N does not match parameter type", which is about a different thing.
7. **The diagnostic for opaque carry mentions a receipt that cannot exist.** The message says a carry policy cannot be relaxed "without an admitted property receipt" (8213), but `OpaqueDataPropertyReceiptKind` has only `Copy` (7812-7814) and the check has no receipt lookup (8208-8211).
8. **`Unit` and slices are never `copy`.** `type_satisfies_structural_property` falls to `_ => false` for `Unit`, `Slice`, `DynamicTrait` and `ConstExpression` (8408), while the carry walker treats `Unit` as fully permissive (8087-8089). A zero-length array is permissive for carry (8068-8069) but for `copy` still depends on its element type (8394-8401).
9. **Dead accumulation.** `proof_nodes` and `runtime_nodes` (6214-6215) are filled throughout `validate_proof_embeddings` and never read; only the two `seen` sets are used. Two hash-set types are in play: the module alias with `BuildSymbolHasher` (5998, used at 6216-6217) and `std::collections::HashSet` in the `calls` submodule (6018, 6037), both passed to `collect_expression_nodes`.
10. **`embed` of an address has no upper bound.** `integer_embedding` gives `addr` the interval `[0, +infinity)` (6466-6467) while every other integer type gets its exact range.
11. **A capability not expected in a source checker: a hard-wired IEEE lemma.** `scalar_boundary_guarantees` recognises one equation shape and emits "operands finite (and divisor non-zero) implies `result == result`", that is, the result is not NaN (10933-11063). The finite range is written as raw bit patterns (11180-11186). The result is encoded as a pseudo-parameter at position `parameters.len()` among the primitive-typed parameters only (10999-11007, 11039-11042). The guarantee is the code's own assertion about IEEE arithmetic; the only supporting evidence it consults is that the equation fact was already checked (`SourceCheckedGuarantee`, 10914-10917) and `application.validate()` (10969).
12. **A capability: a string literal can earn a domain by evaluation.** `string_literal_grants_domain` evaluates the domain's byte predicate on the literal's bytes (7580-7590). This is a real decision procedure rather than a pattern match, though it is the predicate module's own answer.
13. **A possible mismatch between a comment and the code.** The `relevance` module doc says argument positions align with the callee's non-`self` parameters (9729-9730). `argument_position_context` indexes `callee_parameters` directly by argument position (10862-10866), and `call_parameter_substitutions` in proposition entailment pairs arguments with all state parameters in order (8945-8959). Whether `state_parameters` already excludes `self` is not visible in this slice.
14. **Magic limit.** `dispatch_subject_of_erased_binding` peels at most eight borrows (9889); a deeper chain makes the function answer "no".
15. **Generic data escapes the attached-machine rule for erased fields.** The condition at 9958-9960 requires the data to have no type parameters before it reports, and the admission test it calls also returns `false` for generic data (10141-10142), so generic data with attached machines and erased fields gets no diagnostic from this rule.
16. **The qualification rule is the one place in the slice that looks like an authority chain.** A membership fact from an unchecked source counts only if the domain's own declaration lists that boundary trait and requirement as an establishment route (9656-9666), and external machines are forbidden from asserting memberships directly (9531-9582). The weak points are the head-symbol-only type match (9691-9693) and the route-free pass for carry permissions (9635-9642).
17. **Only one missing requirement is reported per call, and only one substitution level is followed** in `parameter_domain_constraints` (5884); both are quiet limits rather than stated ones.
18. **Evidence on the three sampled properties.** (1) Supported throughout: no kernel call exists in the slice. (2) Supported strongly in `proposition_entailment`, `proof_embeddings`, `properties` and the erased-field lookups; contradicted locally in `contract_names_field`, `slice_ranking::names_parameter`, receipts and establishment routes, which compare symbols. (3) Supported in `proof_only_faces`, `relevance::shape_admission`, the boolean-shape family and `qualification_evidence`; not supported in `properties::carry_derivation`, `slice_ranking`, and the census in `proof_embeddings`, which are single general walks.
