## What this code is for

This is the first half of the module `crate::flow::expression`, which walks each statement's and each transition's expressions in evaluation order and records what happened: which operands were evaluated, what storage they named, which facts hold after them (1-16). The slice holds eleven inline submodules, each adding methods to one `Execution` struct: short-circuit Boolean operators (41-296), projecting a callee's storage path onto the caller's actual arguments (297-725), `match` expressions (726-1478), by-value copies of variant payloads at a transition (1479-2025), meeting domain memberships at a join (2026-2245), walking a path through references (2246-2461), facts a completed expression result carries (2462-2762), domain memberships a call result promises (2763-2899), tying a returned reference to the arguments it borrows from (2900-3634), resolving a dynamic-dispatch call to one implementation (3635-3919), references a call stores into its arguments (3920-5007), transition targets (5008-5175), and snapshots of owned values (5176-5966).

The code never refuses a program and emits no diagnostic. Every decision here is "publish this fact or operand record" or "withhold it". Rules are enforced only indirectly: a later module that needs the fact refuses when it is absent. The facts go into two stores: `self.semantic` (facts, places, contexts) and `self.context.control` (operand, call, storage-snapshot and retention tables). The code calls no proof kernel function; it stamps each fact it creates with an evidence label it chooses itself (`propagated_evidence` or `checked_validation_evidence`).

## Mechanisms

- **Boolean continuations (41-296).** Each Boolean operand keeps up to two continuations (`when_true`, `when_false`), each holding its write prefix, context list and constraint list (56-67). `logical_expression` picks the continuation that evaluates the right operand, restores that path's state (130-143), evaluates the right operand, then joins the skipped path with the right operand's same-valued path (269-279). Negation swaps the two (88-100). No budget. Serves `and`, `or`, `not`.
- **Sequential fork and meet over match arms (982-1329).** Arms are visited in order. The "selected" branch gets its own contexts; the shared `contexts` accumulate the "not matched" facts for the next arm. After each arm the write prefix is restored (1267) and the arm's contexts are met with the previous arms' (1268-1276). Four running intersections are kept: memberships, owned member observations, scalar, predicates (1039-1043). Stops at the first covering arm.
- **Hash-bucketed membership meet (2053-2102).** `PlaceBucketIndex` hashes each membership's root and path; buckets give candidates and full equality is checked after (comment 2048-2052). Used for dedup, intersection and "already present" tests. Serves domain membership at joins.
- **Typed path walk through references (339-413, 2321-2459).** Walks a place path one segment at a time over the actual's type; at a reference crossing it reads the stored descriptor at a storage snapshot and continues from the referents, unioning retention roots. Two modes: `Value` loads the final descriptor, `Destination` stops at its home (2257-2261). Serves returned references and references stored by calls.
- **Backing-chain walks with cycle guards.** `owned_case_subject` follows `backing` handles with a `BTreeSet` of visited handles (777-820). `retain_copy_use` follows `backing` with a visited `Vec` (1852-1884).
- **Dynamic selection search (3837-3918).** Depth-first worklist over (operand, projection) pairs with an `active` stack; revisiting an active pair returns `None` (3859). It expands match alternatives and stored predecessors until it reaches constructor receipts. No step budget other than cycle detection.
- **Dynamic selector path enumeration (3797-3835).** Recurses through data fields looking for `DynamicTrait`-typed fields; stops when the prefix exceeds 8 segments (3804).
- **Storage timeline (4957-5005).** Each call store appends a new `FlowStorageSnapshot`; alternatives are installed from the same predecessor and joined. The call's `completed_storage` is the snapshot after its stores.
- **Retention-root union.** Many sites collect the set of lifetime roots a reference must keep alive by unioning the roots of each source's retention profile (490-494, 2431-2441, 3101-3107, 4358-4368, 4529-4551). An unknown profile sets `lifetime_known = false`, which yields an invalid retention handle.
- **Integer hull at joins (5219-5241).** Different integer values join to `[min, max]`. Serves match results.
- **Scalar evaluation fallback (5593-5642).** Lowers the expression to a unit scalar expression and evaluates it with place values read from the value's saved contexts.

## Surprises

- **5,966 lines and not one diagnostic or refusal.** The code only publishes or withholds facts. A reader cannot learn from this file what the program is refused for; that depends on which consumer misses which fact.
- **Evidence labels are chosen here, not earned.** Three publications stamp `checked_validation_evidence` (2692, 2732, 5445) on the basis of type shape and how the value was completed. No kernel call or obligation backs the label in this slice. This supports property 1.
- **Non-covered match drops the fall-through facts.** After the arm loop, `*contexts` is overwritten with the meet of the arm-selected contexts (1290-1293). The "no arm matched" contexts built in `contexts` during the loop are discarded, while the storage join does include the fall-through prefix (1282-1284, 1288). If a match that this code considers uncovered can finish without selecting an arm, facts that hold in every arm would be kept on a path that ran no arm. Coverage here is only wildcard, total structural cases, or `true`+`false` literals (1058-1097), so a match that the language accepts as exhaustive by other means would also land here. Whether another module rules this out, I cannot tell.
- **Skipped operands and arms get no flow records.** A right operand that can never be selected (231-243) and arms after a covering arm (1277-1280) are not evaluated. The file header (7-9) indicates this is deliberate, to keep flow in step with what computation folding skips.
- **Four copies of the reference-compatibility rule that do not agree.** Three accept a mutable source for a shared destination (665-666, 3074-3075, 4306-4308); the fourth requires equal access (4817). Only the stored-supplier copy peels declared constraints before comparing storage types (4311-4318).
- **`inputs` is checked but not used in `returned_descriptor`.** Line 3050 does `inputs.get(position)?;` and discards the value; the actual operand is then fetched from the call fact's `argument_operands()` (3056-3063). `capture_returned_region_descriptor` reads the type from `inputs` (3403) and the operand from the call fact (3436-3443). Two sources for the same actuals.
- **One uncomputable source aborts the whole exact descriptor.** `self.returned_slot_path(...)? != path` (3021) is inside the loop over all sources, so a source for an unrelated result path that fails to map returns `None` for this path too.
- **Dead-looking code.** `let places = Vec::new(); let referents = self.append_referent_places(&places);` (548-549) always appends an empty list. `BooleanCompletions::negated_boolean_completion` returns an invalid handle unchanged (92-94).
- **Operand records are copied freely.** `retain_owned_case_selection` inserts a fresh copy of the subject operand for every arm (926); `try_capture_reference_projection` inserts a copy of the actual (2360); `dispatch` inserts the subject again at 1294. `capture_output_lifetime_sources` inserts path spans inside a closure that may then return `None` (4127-4141), leaving unused arena rows.
- **Hash and tree sets in a codebase that forbids them for dense ids.** `BTreeSet` of (arena index, generation) at 777, 800; `HashSet<Vec<PlaceSegment>>` at 5699-5702.
- **Trace printing is compiled into the checker.** Twelve `eprintln!` sites behind two different flags (`check_sites` and `struct_trace`), some building sizeable debug vectors (4491-4523, 4669-4693). The nine `ReferenceProjectionRefusal` reasons exist only to be printed (2264-2317); the caller sees `None`.
- **An `unwrap` in checker code** at 4305, safe only because 4240-4244 already filtered on the same `reference_shell` call.
- **Capabilities I did not expect.** Predicate-only domain memberships survive a non-recast cast between types with matching carriers (2494-2574). Differing integer results of match arms join to a range (5219-5229). A whole zero-formed array of variants is carried as one `ZeroCaseElements` observation and re-read per element (5198-5207, 5722-5765, 5822-5838). A dynamic-dispatch call is devirtualised for borrow analysis when the selector's completed value provably came from one constructor (3652-3747, 3837-3918). A callee-stored pointer can inherit the permission of the exact output it was produced into (4760-4833).
- **Property 3 is weaker here than the brief expects.** The repetition is mostly per mechanism (returned exact / returned region / stored) and boilerplate, and two modules were explicitly written to be shared across placements (298-302, 2247-2251). Property 2 by text is absent; identity is by source expression occurrence and structural expression equality instead.
