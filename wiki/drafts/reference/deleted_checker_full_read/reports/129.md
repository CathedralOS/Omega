## What this code is for
The file decides, for a machine state that returns a reference (or a record holding references), where each returned reference comes from: which input parameter (or which call result), by what path, with what access (shared, mutable, write-only) and extent. It publishes these "origin" plans so callers can know which of their arguments stay borrowed while a returned reference lives. The slice covers: the tail of the module that walks a state's return statements and loans (4294-5598); descriptor-load slot preparation (5600-6211); declared-signature return sources (6536-6742); path/place conversion helpers (6743-6955, 8713-8931); type-carrier inventory with a leaf budget (7022-8058); stored-loan and storage-loan group lookups (8274-8711); initializer/argument sources for reference records (7212-7573, 9014-9223); and multiplicity / release-boundary helpers (9225-9716). Everything is read from already-built `CheckFacts` and typed trees. The functions almost all return `Option` or `Result<_, &'static str>`: a `None` means "no plan", and callers must then refuse. Two unit-test modules sit in the slice (5583, 5913, 6213).

## Mechanisms
- Budgeted type expansion (`reference_origin_expansion_bound`, 7034-7152): counts visits (<= 8192), leaves (<= 4096) and depth (<= 128); multiplies leaves by fixed-array length via checked arithmetic. Serves reference-carrying records/arrays. The opaque flag lets unbound type parameters count as a leaf that expands no further (only the inventory asks for this, 7029-7033). The same constants guard outputs in `normal_returns` (4474, 4510), `whole_reference_sources` (7604, 7713).
- Declared carrier inventory (7868-8058): a recursive walk over a type with a per-application scope (`DeclarationScopes`, defined outside the slice) so a const argument fixes an array's length per application. Yields known leaves plus opaque paths. Test at 6441 pins that two applications with N=1 and N=2 give 1 and 2 leaves and different type identities.
- Return-site walker (4368-4555): for each normal return statement/transition target, for each reference leaf, finds loans from the borrow facts captured at that statement and expands each into origins; deduplicates with `Vec::contains`; records coverage into an `observed` sink (4537-4551) used by a relation/fixpoint outside the slice (`relations.approximation`, `relations.productive`, 4331-4334, 4570-4573).
- Memoized completion targets (4580-4589): `self.calls.known_target` / `record_target` cache per call target symbol.
- Frame-origin publication (5286-5463, 5230-5284): composes a path from an incoming-reference prefix, recast chain and presentation suffix, tracking `Projected` vs `WithinRegion` extent.
- Descriptor-load slot preparation (5608-5910): one pass over all states and activations builds dense per-incoming-identity `Activation::{Missing,Unique,Ambiguous}` slots indexed by arena index minus 1 (5876), then a single answer per identity. A second mode `for_state` builds a sorted per-state roster searched by binary search on (arena index, generation) (5654). The code states in tests that arena index and generation must both match (5917, 5993).
- `unchanged_input_slot` (6060): an explicit stack walk over `Alternatives`, requiring all branches to be the same slot.
- Address refinement (5522-5554): normalizes view segments then walks the captured coordinate list against the candidate segments.
- Release-boundary computation (9534-9578): max over execution-order positions.
- Loop bound in `declared_input_reference`: 8192 iterations (8076).

## Accepts or skips without proof
- `captured_address_refines` returns false for `OpaqueRange` coordinates (5546), so unknown windows never refine: refuses (good direction).
- `normal_returns` `StatementNode::Expression` is handled only if it is the last statement (4397-4399); a non-last expression statement falls to `_ => continue` at 4457 and is skipped. Another check, `normal_completion_possible`, is asked at 4352 but I cannot tell whether it catches a returning non-last expression.
- `_ => continue` at 4457: any other statement kind is skipped as a return site. Cannot tell whether a later check covers a statement kind that returns.
- `ordinary_return_call` returns `Some(None)` when the callee has no known parameters or return type (4645-4648), which then treats the return as a non-call expression and moves to the leaf loop (4481ff) instead of refusing. At that leaf loop an uncaptured leaf still refuses only if `expression_leaf_present` says present (4532); cannot tell what `expression_leaf_present` returns for an unknown expression shape.
- `return_origins` returns `Some(Vec::new())` when the loan's formation is the stored image of the returned value (4729-4739): accepts with no origin. Meaning is an empty source set for that leaf; whether another path adds the real origin I cannot see here.
- `returned` returns `Some(Vec::new())` for a cycle in `active` (4343-4345) and for a non-returning state (4352-4357): assumes empty sources. Fixpoint outside the slice presumably settles it; cannot tell.
- `classify_completion_target` returns `Some(None)` (no target) for a callee without a checked body contract (4595-4597) or with no reference leaves (4599-4600): treated as not influencing completion.
- `ordinary` / `target_sources` 4316-4329: if the callee has no checked body contract, sources come from the signature alone (`returned_sources`), trusting the declared lifetime relation.
- `reference_origin_path` `trailing_window` branch (6790-6806) accepts an `Index` whose expression is a range (not an element selection) as `WithinRegion` when the collection is an array/slice.
- `is_element_selection` (6762-6766) is true for an invalid (absent) index expression: unknown dynamic index counts as an element selection.
- `completed_return_value` etc. use `normalized_type_identity` equality only (4843-4846).
- `result_loans` returns an empty group for temporaries and discarded results without checking more (9466-9478, 9484-9493).
- `whole_local_release_boundary`, `release_boundary` use facts only; `release_boundary` falls back to `reassigned_release_statement` (9672).
- `path_has_nominal_receiver` treats an unprojectable prefix as a nominal receiver (`is_none_or` at 9324): refuses-direction.
- `declared_carrier_inventory`: any `Named` type with `activation_claim_byte_carrier` returns with no leaves (7985-7990), `has_contents(NumericOwned)` returns no leaves (7910-7912), zero-length array no leaves (7919). These are accepted as carrying no references by type; the `DataSupplyMode::CheckedShape` check (8002) refuses opaque data.
- `is_reference_record` `visit` treats an erased field as absent (7192-7194); `reference_origin_expansion_bound` skips erased fields (7126).
- `origin_formal` and `loan_place_segments` are well-formed refusals.
- `initial_reference_establishment` requires no earlier loan; otherwise `None`.
- `completed_slot` and `prepare` map failures to `Err(&str)` stored per identity rather than failing the whole pass (5736-5756): a bad load poisons only its own slot.

## Surprises
- Every "decision" here is an `Option`/`Result` of the code's own judgment from already-computed facts; I saw no call to a proof kernel (`verify_obligation`, `ProofNode`, certificates) anywhere in 4294-9716. The refusal direction is almost always `None`.
