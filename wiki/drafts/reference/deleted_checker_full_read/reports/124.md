## What this code is for
This part of the file is mostly support code for contract checking rather than the checks themselves. It answers questions other checker modules ask about contract expressions: which callable owns a `result` occurrence (`contract_results`, 467-1199), what a contract argument is rooted at (`argument_subjects`, 5-62), what types and call targets an expression has when it sits in a declaration rather than a body (`expression_owners`, 2556-4977), and whether a name is an immutable integer bound (`immutable_integer_bounds`, 4979-5709). It also builds the string-based "declared contract" identity that is hashed into a callable's public contract commitment (`contract_structure`, 1201-1893). Three modules enforce language rules directly: `carrier_contents` (64-424) decides which types may appear in a quotient or be observed by value or through a shared reference; `domain_weakening` (1895-2554) refuses implicit loss or gain of a domain qualification when a value is delivered to a typed target; `instruction_effects` (5711-5817) decides which public primitive propositions model an inline-assembly effect. Only three diagnostics are produced in the whole range (1573, 2118, 2129); everything else answers with `Option`/`bool` and the caller decides. No code in the range calls the proof kernel.

## Mechanisms
- **Forbidden-content walk over a type** (`first_forbidden_content`, 157-329; `first_forbidden_data_content`, 381-423). One recursive walk parameterised by `ContentUse` (`Quotient`, `ValueObservation`, `SharedObservation`, 150-155). It sees through layout storage wrappers (164-176), recurses into generic arguments for `Type` parameters only (265-281), data fields (411-421), fixed-array elements (298-300). Recursion over data is bounded by a visited set of data symbol indexes that is never unwound (388). Serves quotient types and value/shared observation.
- **Routed-qualification search through domain aliases** (331-379): depth-first over alias constituents, visited set with removal on exit (357-361).
- **Contract occurrence index** (`ContractOccurrenceIndex`, 1101-1198): for every callable contract in a fixed visiting order (machines with an entry state, operators, then trait/refinement/prepared/machine-parameter signatures, 921-968), collects every expression node reached from the contract's facts and maps node -> list of contract positions. Answers "which callable declares this expression" (1160-1173), "which parameters are in scope" (1112-1126), "who owns `result`" (1175-1197). Memoised on the frozen program (822-827); with no memo, each query rebuilds the whole index (828, 877) or rescans every contract (842-864).
- **Machine-parameter contract closure** (`machine_parameter_contract_signatures`, 970-1043): worklist over every type parameter of machines, data, domains, conformances, traits, operators and callable signatures; each `Machine { contract }` parameter contributes its signature, whose own type parameters are pushed back. De-duplicated by `(symbol, parameters, contracts)` (1032-1036). No depth budget.
- **Declared-contract projection** (`declared_callable`/`declared_contracts`/`project_declared_fact`, 1453-1665): turns each parameter, result type, clause and fact into a normalized identity (strings and type identities) with generic binders renamed `$G{n}` and value parameters `$V{n}` (1399, 1412, 1437, 1447); clauses are sorted (1560). Transparent propositions are expanded by substitution with a scope stack that doubles as the recursion guard (1278-1281, 1326-1331). Serves the public contract commitment and contract correspondence between a declaration and its implementation.
- **Domain atom closure and set comparison** (`append_type_atoms` 2351-2393, `append_declared_atom` 2395-2448, `validate_domain_delivery` 2025-2140): collects atoms from a type through references and constraints, expands domain aliases and each domain's own subject membership facts with a symbol stack as cycle guard, then compares source and target sets with `atoms_equivalent` (2472-2506). No budget.
- **Owner environments** (`exact_owner_environments` 3092-3153; `build_owner_environment_index` 3489-3549): for an expression, every lexical setting that contains it — contract fact owners, domain predicates, transparent propositions, measures, parameter type constraints (binding only the parameters before the constrained one, 3263-3269, 3325-3330), data invariants/field types/variant payloads, const initializers, ranking expressions, executable statements (state parameters plus every earlier typed `LocalData` in the state's flat statement list, 2927-2944). Two implementations: a whole-program scan per query and a prebuilt index keyed by expression handle.
- **Declaration-side type inference** (`infer_expression_type`, 4107-4274): recursive, per-node, with a visited list as cycle guard; resolves names by symbol, then `self`, then reserved `result`, then bindings; computations (`Call`, `Binary`, `Unary`, literals) are delegated to `value_custody::expression_types::declaration_expression_result_type_reference` (4225). Serves member and call resolution inside contracts and other declaration positions.
- **Expression reachability** (`reaches`, 4389-4404): `program.subtree_any` over `SubtreeEdges::VALUES` with a visited set.
- **Immutable bound normalisation** (`normalize_bound`/`normalize_local`, 5554-5628): follows chains of immutable locals whose initializer is an integer literal or a name, with an alias list as cycle guard. A local initialised from a mutable value normalises to the local itself (5618). **Linear bound terms** (`collect_bound_terms`, 5247-5299): at most two symbols plus offset, depth limit 128, checked `i64` arithmetic. Serves index-bound and range facts.
- **Effect-model chain** (5786-5816): follows single-application transparent propositions until one is a modelled primitive.

- `indexed_owners_match_raw_rosters_targets_and_refusals_for_exact_worlds` (4869-4975): for a two-machine fixture, the prebuilt index and the raw scan return the same environments, call targets and statement sites for a contained call, a shared marker literal, a detached call, a handle of another generation and an invalid handle (4879-4889); the call has three environments and the marker two (4891-4892); `x.go()` targets the state of the machine attached to `x`'s type, which flips with the parameter type (4898-4907); two fact owners that type `x` differently give no target (4909-4932); a `CallSignature` owner with no matching signature gives no target (4933-4953); an owner whose state lacks the parameter falls back to the executable site and still resolves (4955-4974).

## Surprises
- **No proof kernel anywhere in the range.** A search of lines 1-5818 finds no `proof_admission`, `ProofNode`, `verify_obligation` or certificate. Every decision is an `Option`, a `bool` or one of three diagnostics. This supports property 1 for this slice, with the qualifier that most of the slice is lookup support rather than acceptance.
- **Dead map**: `BoundMaps.machine_self_parameters` is declared (4998), created empty (5017) and read (5145, 5662), but `BoundMaps::build` (5012-5073) never inserts into it and the field is private to the module. `machine_self_parameter` always returns `None`, so the fallback branch in `bound_name_receiver` (5661-5664) can never succeed.
- **Program-wide name maps**: `locals_by_name` is one map for the whole program, and a name used by two locals anywhere (any machine, any state) becomes `None`/`Invalid` (5062-5068). The name fallback therefore only works for local names that are unique across the entire program, so adding an unrelated local with the same name in another machine changes whether a bound is recognised.
- **The strengthening check is unreachable for atom-free sources** (2055-2058, described above). The early return was presumably meant for the weakening half only, since `dropped` needs source atoms but `assumed` is computed from the target.
- **The two owner-environment implementations are not the same code path for traits.** The raw scan visits only `trait_machine_signatures` (3277-3286); the index visits `retained_callable_contracts`, which adds refinement clauses, prepared callable contracts and machine-parameter contract signatures, and records `trait_scope` (3795-3805, 3850). The equivalence test's fixture has no traits, so it does not exercise the difference.
- **`OwnerEnvironmentIndex::new` passes an empty call-signature arena** (4518), so `CallSignature` owners never get an environment unless `with_call_signatures` is used (4524-4533).
- **`OwnerIndex::add` de-duplicates only against the last environment** (4472), and every `add_all` interns a new environment (4486), so identical environments are stored many times; the test counts on that (three environments for one call, two of them from equal owners, 4875, 4891).
- **Cost**: without the frozen-program memo, `source_contract_declaration_owner` and `source_contract_parameters` rebuild the whole `ContractOccurrenceIndex` on each call (828, 877), and `expression_has_source_builtin_index_meaning` calls both per index node (730-735). `first_forbidden_content` in `Quotient` mode scans every data definition's type parameters for each unknown named type (207-211). `signature_generic_binders` scans the whole `data_type_parameters` arena once per enclosing scope (1428-1440). `type_has_forbidden_value_observation_content` recomputes `proof_only_classification(program)` on each call (100, 142).
- **`checked_machine_call_target_from_executable_owner` takes `_contract_facts` and ignores it** (2689).
- **`declaration_owner` returns `Ok` with a default (invalid) handle** when the expression is in no contract (1164-1172); callers must test validity (`source_declaration_owner` does, 4606).
- **Machine type parameters are callable by name**: when ordinary resolution fails and there is no receiver, a call resolves to the single machine type parameter of kind `Machine` whose name equals the call target (2778-2791).
- **A capability worth knowing**: transparent propositions are compared by expanding them and normalising the body under substitution (1304-1350), so two contracts that name different transparent propositions with the same body correspond; opaque and parameter propositions are compared by symbol or binder position (1357-1388).
- **`Bool == Bool` is treated as a logical connective** for proposition context (451-458); that is a typed decision, not a spelling one, and needs `operand_type_reference` to succeed for both operands, otherwise the comparison is an ordinary value term.
- **Bound sums are canonically ordered by handle index and generation** (5223-5225), which is an identity by arena position rather than by text.
- Against property 2 for part of the slice: places are built from symbol handles and `facts::PlaceSegment` values (592, 639, 668, 5501, 5516), and `contract_argument_root` returns positions and field symbols (26, 44-48). Text identity is concentrated in the contract-identity strings, the member/state/receiver name lookups and the name maps listed above.
