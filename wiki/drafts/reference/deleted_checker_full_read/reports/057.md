## What this code is for

This is the first half of the old checker's "flow facts" builder. For every state, statement, call and exit of every machine it records which sets of facts ("semantic contexts") and which constraints (borrow state, loans, incoming references, writable roots) are active at that point, and it records how each write, loan expiry and transition changes them (1-31). It produces rows; it does not issue a single diagnostic and makes no accept/refuse decision about a program. Other passes read the rows and decide.

The slice holds: the driver that runs all machines to a fixed point in parallel groups (`builder`, 235-911); the table of what a completed callee proves about storage lent to it (`normal_returns`, 922-1320); attaching service-reach, suspension and blocking summaries (`reach`, 1321-1428); a persistent chain of "storage snapshots" recording stores and writes per statement (`stored_values`, `stored_views`, 1431-1864); tracking which entry parameter each state parameter came from, and which caller storage a write through a reference can change (`entry_origins`, 1869-2931); deciding what a taken guard lets later code assume (`guard_predicates`, 2942-3542); a small Boolean-formula engine over case selections (`selection_conditions`, 3609-3942); effects of named operator calls: writes and `ensures` (`operator_calls`, 3950-4682); the per-state builder (`state`, 4691-4978); the per-statement builder (`statements`, 4979-6005); the write footprint of an assignment (`storage_footprints`, 6006-6062); boundary-trait edges for calls (`boundaries`, 6067-6163); publishing return-type domain memberships on a call result (`call_results`, 6166-6241); and loan expiry and loan retirement on reassignment (`borrow_lifetimes`, 6254-6538).

## Mechanisms

- **Group fixed point with a growing pass bound** (532-603). Computes the incoming values of every state in a group of machines. Each pass after the first discards all output and restarts from the baseline fact plan (565-568). A "partial" pass rebuilds only states whose inputs changed; a "complete" pass rebuilds all. Success is a complete pass that leaves no dirty input (589-592). The bound starts at `2 + sum(1 + 2 x params)` (541-550) and is extended during the loop by `new_state_field_input_height` (581) and by twice the number of newly seen returned-predicate cells (586, 1124). On failure the group is rebuilt once with unknown inputs (516-524). Serves contracts and facts across transitions and calls.
- **Union-find grouping** (709-893). Path-halving union-find (713-719) over machine positions: lexical parent/child (728-750), calls that deliver values (753-816). A second union-find (`part_owner`) plus a loop that merges a part into its sole caller until nothing changes (830-857) finds "independent parts": parts no other part calls.
- **Record and replay** (402-503, 612-693). Each independent part converges alone on a rayon worker and records every value delivery per state visit. The group run then replays those deliveries instead of rebuilding the part. Any mismatch returns `None` and the group is rebuilt serially (491-495). This is for build speed; it changes no rule.
- **Per-machine output pages** (276-277, 662-668, 383-399). Each machine writes its rows to page `2 + roster position`, so parallel workers' rows can be adopted in roster order.
- **Returned-predicate greatest fixed point** (1060-1128, 1195-1319). Starts from "everything holds" for exclusive entry parameters (`assume_all`), then each complete pass replaces the table with the intersection over exits of what the facts prove; callers of a changed machine are marked dirty (587). The finite lattice is `machines x exclusive params x ByteSequencePredicate::ALL`.
- **Persistent storage-snapshot chain** (1454-1611). Each statement has a snapshot handle whose node is `Writes` (binding rows, content rows, two "complete" flags), `Store` (destination, captured value, projection), `PreserveBinding`, or `Join` of predecessors. An empty complete `Writes` returns the previous handle (1476-1478); a join of identical predecessors returns that predecessor (1599-1603).
- **Address resolution worklist** (1801-1863). For each prefix of a place whose type is a live view, replaces the prefix by the places stored there at the snapshot before the statement, up to depth 64.
- **Parameter-origin dataflow** (2449-2567). Per machine, a fixed point over named-transition edges unions, for each tracked state parameter, the set of entry parameters it may carry (`sources`, invalid symbol = unknown) and, when a call-frame resolver is given and `storage_origin_substitutions_are_finite` holds (2474-2475), the set of storage origins (`None` = unknown). No explicit bound: the loop stops when nothing changes (2559-2561). Three entry points share the solver: `machine_parameter_origins`, `activation_parameter_origins`, `machine_storage_origins` (2417-2447).
- **Guard decomposition and saved-decision worklist** (3436-3509, 3102-3205). Recursion over the Boolean structure, then a worklist that follows Boolean locals back to their reaching definition (`reaching_capture`, 3207-3273, walking the admitted execution order backwards and collecting write paths).
- **Read/write survival test** (3275-3429). Walks an expression, separating nodes whose value is read from nodes used only as an address, and checks that no read path overlaps any written path. Paths are strings (see "Identity by text").
- **Selection conditions** (3638-3941). A hash-consed Boolean DAG with nodes `True`, `Arm(selection, alternative)`, `All`, `Any`; `never` is the invalid handle. `restrict` fixes one selection to one alternative (Shannon expansion) and is memoised; `covers` and `possible` recurse over the lowest-numbered selection and are memoised; `negate` applies De Morgan and replaces an arm by the disjunction of its siblings. Interning and all memo lookups are linear scans of vectors (3755, 3794, 3865, 3899). The header says it "never materializes a Cartesian product of constructor fields or a DNF" (3615-3616).
- **Loan liveness by execution position** (6309-6336). Compares positions in `StatementExecutionOrder`, not source indices.

## Identity by text

- **Written and read storage paths are strings in guard reasoning.** `expression_write_frame(..).into_complete_paths()` yields `Vec<String>` (3049-3059, 3115-3121); `later_writes: &[String]` (3109); `reaching_capture` returns `Vec<String>` (3214); `reads_survive` takes `writes: &[String]` (3281) and decides overlap by `frame_paths_overlap(written, &path)` on strings from `frame_coordinate_path` (3345-3350, 3414, 3423-3427).
- **Storage origin rows carry the root's name.** `root_storage` sets `path: program.symbols.name(root).to_owned()` (2581). `LocalWriteSource` values are compared whole at 2086 (`source != &sources[0]`) and 2531 (`row.storage.contains(&source)`), so the text is part of that equality.
- **Operator resolution by name and arity.** `resolve_operator_statement_call` passes the receiver's name-path members as `&str` segments, `call.target.as_str()` and the argument count to `typed_trees::operator::resolve_named_call` (4003-4027, 4046-4053).
- **Operand labels.** `OperatorStatementOperand.label: String` (4060) is a canonical place label (4102-4106, 4176-4180), an expression display name (4125, 4174), a `::`-joined receiver path (4096-4099) or the parameter's name (4124).
- **Operator `ensures` are instantiated by label substitution.** `instantiate_operator_contract_expression_label(program, parameters, &operand_labels, expression)` produces a string that becomes the fact's `instantiated` identity (4494-4500); proposition arguments likewise, ending in `formula.identity_label()` (4556-4578).
- **Operator contract places are rooted by the parameter's authored name.** `parameter.name.as_str() == head` is tried first, then symbol equality (4637-4645). The comment: "Contract name paths are intentionally not resolved as caller symbols, so the parameter's authored name is the fallback root." (4622-4624).
- **Boundary edges match by name.** `signature.name == target_state.name` (6133).
- **Trace output** prints `machine.name`, `state.name` (5458-5463); no decision depends on it.

Against the property: everywhere else in this slice identity is a handle. Returned predicates are keyed by `(SymbolHandle, TypeReferenceHandle)` with generations (945-956); parameter origins compare `SymbolHandle`s (2283, 2291, 2528, 2542); places are `PlaceRoot` plus typed segments; saved decisions resolve a name through `single_segment_name_symbol` and `SymbolKind` (3133-3143). The `guard_predicates` header says "Generated names and adjacency grant no authority." (2949).

## Accepts or skips without proof

## Surprises

1. **This half of the flow builder refuses nothing.** There is no diagnostic, no `Result`, and no verdict in 6,538 lines. It only creates, keeps and drops fact and constraint rows. Property 1 holds here in a stronger form than "own yes or no": the facts are asserted by construction, and the judgement happens in whichever pass later reads them.

2. **In assumption mode, `rebase_contexts` computes a substitution and then discards it.** For a machine-level fact rooted at an entry parameter, lines 2793-2800 rewrite the fact's root to the current state's parameter. Then `complete &= target.is_valid() && !assumptions` (2830) forces `complete` to false whenever `assumptions` is true and the fact names any entry parameter, and line 2846 then drops the whole context, including its other facts. The rewritten fact has already been appended to the plan (2843) with no context pointing at it. The only call in this slice passes `assumptions = true` and ignores the second return value (4762-4772). So entry `requires` over parameters do not reach later states through this function; the per-state values module must be what carries them.

3. **`extend_invocation_observations` breaks out of its loop at the first unmappable place** (2182). The fallback it adds for that place is every reference parameter's referent, narrowed to that place's own field path when the path is static (2158-2177). Places after it in the list are never mapped. If a later place would have mapped to a different field of a referent, that field is not marked as written. The comment promises "If projection is unknown, invalidate every possible incoming referent" (2120); the code does that only when the unmappable place's path is not a pure field path. Looks like a possible under-invalidation; cannot confirm without the callers' place lists.

4. **The two operator-call paths disagree on a missing place despite a comment that they cannot.** The comment at 4302-4304 says the write set is "resolved through the same operand custody `apply_named_operator_call_effects` uses so the two can never disagree about what a `&mut` operand names". But `apply_named_operator_call_effects` drops a mutable operand with no place via `filter_map` (4237-4245) and continues, while `named_operator_call_mutated_places` returns `None` for the whole call (4335-4339).

5. **Operator `ensures` Boolean facts are attached to every operand's place**, whether or not the expression mentions that operand (4501-4546). `dependencies.dedup()` (4505) runs on an unsorted vector, so it removes only adjacent duplicates.

6. **`Condition::False` is never created.** `never()` is the invalid handle (3663-3665), and nothing interns `Condition::False`, so the `False` arms at 3829, 3873 and 3906 look unreachable. `negate` (3828) and `first_selection` (3872) call `self.nodes.get(condition)` with no validity check, so negating `never()` reads an invalid handle. Whether that panics or returns the default (`False` is the `#[default]`, 3630) depends on the arena.

7. **The pass bound is not fixed.** It grows inside the loop (581, 586). Termination rests on those increments being finite, which this slice does not show for `new_state_field_input_height`.

8. **Two notions of "entry state".** Most code takes `machine_states(machine).first()` as the entry (1010, 1068, 1962, 2131, 2687, 4820-4823), but `machine_groups` asks `state_values::entry_state_index` (773).

9. **Source order where execution order is used elsewhere.** `unknown_alias_footprints` takes `.take(statement_index)` over source order (5960-5962) and `parameter_edges` collects visible locals in source order (2317-2325), while the statement loop, loan expiry and `reaching_capture` use `admitted_execution_order` (5050, 6318, 3222-3226). Cannot tell whether the two orders can differ for local declarations.

10. **`append_proof_output_ensures` hard-codes `call_ordinal: 0`** (5930), at each statement and once more at the state's end index.

11. **A build-speed concern shapes the checker's structure.** The record-and-replay machinery (402-503, 612-693) exists so parts converge on separate workers, and the comment names one program shape as the case it serves: "each hosted target's `plan` body is such a part" (706-707). Correctness of the parallel path depends on replay matching the serial run exactly; any mismatch falls back.

12. **Returned predicates are coinductive.** A recursive body is admitted by assuming its own postcondition and checking that it is reproduced (1044-1058). The comment states that termination is "ranked separately". This is a capability a reader might not expect in a flow pass.

13. **Unused and stray items.** `address_before_statement` takes `_semantic` and never uses it (1803). `HashSet` is used at 2188 in a file that otherwise uses vectors and dense tables. An `eprintln!` trace sits in the statement loop behind `trace_flags::struct_trace()` (5458-5463).

14. **Invariants are enforced by panics.** `expect` and `assert_eq!` at 664, 5992, 5996-5999, 6320 and 6329 abort the compiler if borrow rows are not contiguous per statement or a loan's last use is not in the execution order.

15. **`capture_at_snapshot` declines for a root reference parameter when `shell.access != Shared || !parameter.is_mutable`** (1773). Only a mutable shared-reference parameter is looked up in the snapshot chain; every other reference parameter is treated as its own incoming address.

16. **Against property 3.** Guard observations, parameter origins, snapshot chain and loan expiry are each written once and apply to any place shape. The repetition in this slice is by construct (statement kind; statement form versus expression form of an operator call), about 10% of the lines.
