## What this code is for

This file decides, for every call and every named transition in a state body, whether the caller has established each `requires` clause of the callee (`check_call_requires`, :3227-3567). The header says so: "we prove each call's authored `requires` clauses at the call site from captured boolean premises, guard observations, predicate domains, transition guards and state preservation, and explain the missing fact" (:1-6). A requirement is a `Fact` from the call's `requires_constraints` contexts; its payload is a Boolean expression, a domain membership, or a proposition application (:3276-3281, :3312-3340). The file does not prove anything itself in one place. It runs a long ordered list of "routes", each a yes/no function, and accepts the requirement when any one says yes (:110-186, :3310-3419). Routes that this file owns are: guard text matching, guard structural matching through stable copies, the refuted-arm (ex falso) route, the "captured operand" judgment that decides whether the callee's formal may be read as the caller's current storage, seven domain-grant routes for different argument shapes, and a restoration check for `&mut` loans of domain-qualified locals. When no route proves a Boolean requirement the code may hand it on as a constant or recipe obligation instead of reporting it (:3447-3514); otherwise it emits "cannot prove requires contract for call ..." (:3547-3559). The file also contains the helper modules for label text rewriting (:1906-2053) and one unit test for a hash-bucket index (:4387-4565).

## Mechanisms

- **Route disjunction with And-split.** `boolean_requirements::proves` (:99-207) evaluates eleven routes in a fixed order with short-circuit `||`, then, if the expression is `a && b`, recurses on both. No premise is installed between conjuncts (comment :12-13). There is no `||` split here; the captured variant does split `||` (:583).
- **Capture-versus-source judgment.** `captured_boolean::judgment` (:238-310) returns a three-valued answer. It finds the contract rows of this call that share the requirement's source fact (:267-293), proves each against captured values, and otherwise checks whether "source substitution preserves captures" (:303-309). `capture_preserves_source` (:1069-1164) walks constructed children recursively, collects every read occurrence in the capture and in index segments, and asks the flow layer whether the observation at capture and at invocation agree. Serves call arguments evaluated before a sibling argument writes.
- **Whole-contract cache.** `WholeContractCache` (:3200-3225) holds one answer list per distinct roster of fact contexts, found by linear search on context slices (:3288-3298) and on contract handle (:399-403). It also lazily prepares the caller's current scalar values once (`OnceCell`, :3219-3223). Comment: "never reuse one arm's positive result to qualify another arm" (:3196-3198).
- **Structural guard/requirement equivalence.** `Comparison::equivalent` (:1714-1821) compares two expression trees in two namespaces (caller, callee). A single-member callee parameter name is replaced by the caller argument at the same position, with a `Borrow` peeled when the parameter type is a reference (:1724-1751). Names compare by resolved symbol, members by `member_symbol` and `case_variant`, literals by value. Either side may be replaced by the source of a stable copy (:1813-1820). Depth limit 64 (:1721). Closed integers fold through `lower_unit_scalar_argument` and `evaluate_checked_scalar` with no live inputs (:1827-1887).
- **Stable-copy discovery.** `stable_copies` (:1546-1650) walks the state's statements backward from the call, takes the latest store to each destination place, and keeps it as an alias only if the stored value is primitive, has source identity, and neither the destination nor any read of the stored expression changed before the invocation.
- **Refuted-arm unsatisfiability.** `contradictory_edge::proves` (:1441-1504) lowers the previous statement's `When` guard, binds it negated, appends it to the retained premises at the statement, and asks `boolean_predicates::unsatisfiable`.
- **Predicate-only domain reduction.** `predicate_only_domain_predicates` (:2085-2130) recursively flattens a domain into its predicate expressions, following memberships whose value is the domain subject into the parent domain, with an `active` stack for cycle refusal (:2095). Any other fact kind makes the domain not predicate-only (:2123).
- **Label tokenizer and text substitution.** `for_each_label_token` (:1929-1960) scans a label into identifiers (flagged "qualified" when preceded by `.` or `:`) and gap characters. `replace_unqualified_identifiers` (:2032-2052) substitutes whole unqualified identifiers. Serves incoming-guard matching across a transition.
- **Case-requirement projection.** `projected_case_requirement_labels` (:2732-2833) follows the guard subject through borrows and local initialisers for at most 8 steps (:2751), reads the subject's generic type arguments, and renders the case's predicates with the subject name and const-argument names substituted, producing each predicate and their `" && "` join (:2830-2832).
- **Call-argument projection for indexed captures.** `call_case_projection` (:802-963) builds a `CallArgumentProjection` from current scalar values at the caller point, after retiring values not preserved by the invocation snapshot (:944-953). Each missing input aborts with an optional `CHECKSITE` trace line naming the stage (:813-829).
- **Restoration membership index.** `restoration_memberships::Memberships` (:4285-4372) hashes `(place, domain)` with `DefaultHasher` into a `PlaceBucketIndex`, then confirms candidates by exact equality. `Obligations` is a `HashSet` used to check each `(place, domain)` once (:4376-4385).
- **Budgets seen:** depth 64 (:1721); `remaining = 256` for `lower_callable_scalar_contract_predicate` (:724); 8 steps of initialiser following (:2751).

## Surprises

1. **Comment and code disagree on "no later fallback may replace it."** The capture judgment's `Some(false)` is described as final (:234-235). In `check_call_requires`, `termination::profile_requirement_covered` is OR-ed afterwards without testing `captured_judgment` (:3404-3412), unlike the two groups just above it, which are gated on `captured_judgment.is_none()` (:3344, :3354). `selected_evidence_proves_requirement` is also OR-ed before it (:3311) but applies only to proposition payloads, for which the judgment returns `None` (:250-252).
2. **Text substitution can lose grouping.** `replace_unqualified_identifiers` pastes an argument's display text in place of a parameter name with no parentheses (:2040-2046), and `render_projected_requirement` formats binaries as `"{} {} {}"` with no parentheses (:2843-2860). If `display_name` does not parenthesise, a requirement `n * 2 > 0` with `n` bound to `a + b` becomes the text `a + b * 2 > 0` and would equal a guard that means something else. The label producers (`display_name`, `instantiate_call_contract_expression_label`) are outside this slice, so I cannot tell whether this can accept a wrong program; the equality test itself (:2932) has no structural check behind it.
3. **Negated float comparisons.** `negated_guard_conjunct_matches` treats `!(v >= n)` as `v < n` for any operator with a `complement()` (:2985-2992). The only gate at the call site is `has_builtin_operators` (:4125). For floats with NaN the complement does not hold. Cannot tell whether `complement()` or the builtin gate excludes floats.
4. **`subslice_grants_domain` contains no subslice logic.** The 17-line comment above it (:3675-3692) describes string literals first and subslices second, but the function (:3693-3720) only canonicalises the place and calls `prove_domain_at_place` with the contexts. `string_literal_grants_domain` (:3808-3824) has no comment of its own.
5. **Comment says "any call statement defeats the route"; the code does not do that.** `incoming_guard_proves_requires` (:4091-4092 versus :4156-4184) checks assignments by field name, prior call invalidations rooted at `self` that name a collected field, and label names. A call that writes elsewhere does not defeat it.
6. **`caller_state_preserves_field` scans every statement in the state, including those after the call** (:2328), while the label-name check stops at the call (`take(call_flow.statement_index)`, :2241). The field check also matches a member of the same name on any object (:2385). Both over-refuse.
7. **`collect_expression_self_fields` is misnamed and incomplete**: it collects every member name whatever the receiver and skips Unary, Indexed and Call nodes (:2304-2320).
8. **Ex falso is wired only for Boolean requirements and is not restricted to assembly.** `contradictory_edge::proves` is called only from `boolean_requirements::proves` (:170-177), so membership and proposition requirements on a dead arm are not discharged, although the comment says "every requirement follows" (:1392). The shape test (:1409-1435) accepts any state whose previous statement is a `When` transition without continuation, not only normalised assembly.
9. **Unbounded domain intervals are clamped to `i64`.** `predicate_only_domain_interval` substitutes `i64::MIN` / `i64::MAX` for a missing bound (:2191-2192), and uses `program.domain_definition(domain_symbol)` (:2175) where the sibling function uses `domain_definition_for_instance` (:2148). For subjects wider than 64 bits this narrows what the guard must show.
10. **A reachable `unreachable!` in the diagnostic path.** If a membership requirement fails and its `fact.place` is not a `Place`, the compiler panics with "contract domain membership already handled above" (:3530-3532). Nothing above in this function establishes that; it may be guaranteed by `contract_membership_place_is_accessible` or the fact producer, which I cannot see.
11. **Lender restoration diagnostic names the wrong thing.** The rule concerns the caller's domain-qualified local, but the text says "default-domain field requirement" and prints the callee's parameter symbol joined with the caller-side row path (:4742-4752). The check also covers only locals declared by `LocalData` in the same state (:4678-4692).
12. **Receiver offset used inconsistently.** In `check_lender_domain_restoration`, `arguments.get(position)` ignores `receiver_offset` while `operand_position` adds it (:4649-4650).
13. **Debug tracing in the checker.** `call_case_projection` prints `CHECKSITE call-case-projection stage=...` to stderr under `validation::trace_flags::check_sites()` (:818-824).
14. **Hash containers.** `restoration_memberships` uses `DefaultHasher` and `std::collections::HashSet` (:4273, :4378); the unit test asserts a performance property (:4480).
15. **Redundant work.** `selected_guard_predicate` re-checks `guard_preserves_values` and `premise_reads_survive_arm_operand_writes` that `selected_transition_premise` already required or that apply to the same guard (:2458 versus :2508-2516). `judgment` destructures the same payload twice; the inner `else` cannot run (:250-259).
16. **Qualification recorded with an invalid structural value** (`structural_value: ...::invalid()`, :3443), and silently not recorded when the statement index does not fit `u32` (:3434).
17. **Capability not expected in a "requires" checker:** it reasons about numeric reinterpretation of storage read through a view (:1272-1299, :1201-1215) and about returned loans whose callee has an empty write frame (:1305-1355), all to decide whether a formal parameter may be read as the caller's storage. This is the closest the file comes to "a fact belongs to a value": the capture code tracks observation rows and epochs by handle, while the guard routes beside it still compare text.
