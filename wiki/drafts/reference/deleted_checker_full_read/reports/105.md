## What this code is for
This slice is the middle of the `structural_judgment` module, the old checker's "structural judge": the object (`StructuralJudge`) that holds what is known at a program point (rewrites, substitutions, captured call results, induction values) and answers "is this predicate proven, refuted or unknown".
The first part (54206-55962) is the tail of `integer_predicates`: it turns terms into polynomials over named atoms, installs the known premises into an integer engine, and judges comparisons, Boolean combinations, "does this value fit this integer type", and "is left > right or left >= right".
`identity_normalization` (55966-57181) decides `Id` (data identity) questions by rewriting both sides through established identity equations grouped into connected components.
`induction_values` (57182-57335) records which recursive calls may be used as an induction hypothesis; `invocation_entry` (57336-57470) binds arguments when the judge walks into a callee body and restores caller state when it leaves.
`licenses` (57471-59048) decides when a user trait's laws entitle the judge to rearrange terms as a commutative ring or semiring, finds literal identity elements from trait laws, and holds the constant folder for scalar operations.
`logical_resolution` and `mathematical_predicates` (59049-59231) resolve `and`/`or` terms and instantiate mathematical predicates.
`normal_returns` (59232-61949) models what the caller knows after an expression or call completes normally: it prepares a call, captures bindings, either walks the callee's body or imports its `ensures` contract, mints fresh "captured" values for results and for storage the callee may have written, and computes the "completed value" of each expression kind.
Nothing in the slice reports a user diagnostic itself; every function returns a judgment, `Option`, `bool` or a `&'static str` reason to a caller.

## Mechanisms
- **Polynomial integer reasoning over named atoms.** `integer_value` and `mathematical_value` (contract_entailment.rs:55618-55849) turn a term into a `Polynomial`. Values they cannot open become atoms; each arithmetic operation is recorded as an `ObservedOperation` with `admitted: false` (55759-55767) and a placeholder or "completed value" atom. Premises are installed into `Engine`; goals are answered by lower-bound queries or by showing premises plus the negated goal unsatisfiable. Depth limit 64 (55625, 55779). Only `+`, `-`, `*` are opened (55840-55845); multiplication uses `checked_mul`. Serves `requires`/`ensures` on integers, fits checks and ordering.
- **Case split over Boolean structure.** `proves_observed_integer_boolean` and `integer_boolean_alternatives` (contract_entailment.rs:54556-54759) build a disjunctive normal form of the negated goal and of each `and`/`or` premise. Budgets: 64 recursion nodes (54565, 54660), at most 32 worlds or alternatives (54622, 54706, 54722), at most 64 comparisons per world (54628, 54712). Exceeding a budget gives "no answer".
- **Interval recipes.** `completed_integer_range_recipe` (contract_entailment.rs:54243-54390) combines a recorded recipe with one derived after rewriting, by intersection; attached to `CapturedValue.integer_range` at call results, post-call storage, casts and scalar reads (60070-60075, 60403-60420, 61572-61580, 61889-61892).
- **Prepared premises with reusable goal work.** `prepare_integer_premises` (contract_entailment.rs:55292-55324) projects all premises once; `cached_prepared_integer_premises` (55252-55290) caches the result under a key of revision counter, lengths, two mode flags and "input owner" identities; `prepared_predicate_proofs` (54977-55250) then judges each goal on a reset copy (`take_goal_work`/`reset_goal_work`/`put_goal_work`).
- **Identity components.** `IdentitySubstitutions` (contract_entailment.rs:56453-56647) indexes identity edges by head (`RepresentationCandidates`, rosters keyed by application target symbol and arity, 56303-56356), closes the connected component of the row a value reaches (`prepare_component`, 56505-56589) using `ClosedSpans` to skip rows already included (56362-56397), and picks as representative the right-hand side with the lowest node count (56570-56588). `rewrite_identity_context` (55995-56020) searches breadth-first for the first rewritable sub-term and retries after each change. All of it spends one shared counter `remaining` and has depth limit 32. Serves `Id`.
- **Explicit-stack resolution of `and`/`or`.** `resolve_logical_term` (contract_entailment.rs:59082-59153) resolves left then right without recursion; depth limit 32, rewrite budget 32 per chain.
- **Algebra licenses.** `conformance_slot_carriers_uncached` (contract_entailment.rs:57639-57682) builds a table indexed by requirement symbol arena index of (carrier type, entry symbol, trait application identity, alias); `algebraic_law_slots` (58393-58432) pattern-matches every trait law; candidates are joined on application, carrier and selected operation. `EntryMachines` (58208-58253) is a sorted vector with binary search.
- **Constant folder.** `fold_scalar_binary` (contract_entailment.rs:58802-58937) with exact big integers and per-policy result handling.
- **Callee body walk.** `observed_body_paths` (contract_entailment.rs:59747-59870) clones the judge, binds arguments (`bind_invocation`), calls `recognize_structural_state_leaves` on the callee's states and turns each leaf into a return path; `body_invocations` is the recursion guard (57408, 59774).
- **Fresh value identity by counter.** `capture_sequence` is incremented and stored as `occurrence` in every new `CapturedValue` (contract_entailment.rs:60063-60068, 60834-60838, 61670-61675).
- **Induction value set.** A vector of exact application terms, compared with `same_resolution_payload`, intersected at joins (contract_entailment.rs:57194-57334). Serves `terminates by` recursion in proofs.

## Identity by text
- Integer atoms are named by formatted strings: `format!("\0captured-integer:{position}")` (contract_entailment.rs:55865-55867); the proof shortcuts look atoms up by that name (`polynomial_mentions(&diff, &name)`, 55037-55038, 55216-55217) and detect the address bound by `atom.starts_with("\0address-model-bound:")` (55024).
- `completed_integer_comparison` names every non-arithmetic sub-term by its Rust `Debug` rendering: `Polynomial::atom(format!("{term:?}"))` (contract_entailment.rs:58983, 58985). Two sub-terms are the same value exactly when their debug text is equal.

## Surprises
- **"By shape, not by name" is done with names.** The license comment says laws are "detected by SHAPE, not by name" (contract_entailment.rs:57767). The matchers decide "same operation" by comparing the spelled `machine` string and "same variable" by comparing variable-name strings (58517-58564, 58669-58681, 58715-58765). Soundness of that rests on `consistent_operation_selections` (58773-58800), which ties each spelling to one target symbol.
- **Inconsistent unwrapping in the shape matchers.** `commutativity_shape`, `associativity_shape` and `distributivity_shape` match `left`/`right` directly (contract_entailment.rs:58492-58497, 58652-58657, 58695-58700), while `identity_law_shape`, `nullary_requirement` and `consistent_operation_selections` first call `.semantic_value()` (58125, 58183, 58778). A law whose sides are wrapped in an observation would not be recognized by the first three. Distributivity is recognized in one orientation and only as left-distributivity; associativity tries both orientations.
- **The circularity comment promises more than the code does.** The comment says a machine binding a law slot "gets NO licenses from that trait" and that this kills multi-machine cycles (contract_entailment.rs:58270-58274). The filter removes only candidates whose own law slot the judged machine binds, and only when the carriers match (58313-58324).
- **`complement().unwrap_or(operator)`** (contract_entailment.rs:55481, 55549, 55607) keeps the un-negated operator for a false premise when no complement exists. Looks like a latent unsoundness if any accepted operator lacks a complement.
- **All unobserved arguments are one term.** `Opaque("unobserved invocation argument")` is used for every argument without an observation (contract_entailment.rs:57425-57427). If two `Opaque` terms with equal text compare equal, two different unobserved arguments are indistinguishable. Cannot tell from the slice how `Opaque` is compared.
- **Value identity by debug text** in `completed_integer_comparison` (contract_entailment.rs:58983-58985): correctness depends on `Debug` output distinguishing every distinct value.
- **Global, non-local conditions.** `completed_integer_call` returns nothing if any rewrite anywhere has an arithmetic, application, indexed, projection, measure or representation pattern (contract_entailment.rs:61155-61178). `prove_observed_predicates` and `prove_observed_integer_ordering_minimum` branch on whether any rewrite has a given operator (54780-54788, 54810-54818, 54919-54943). Adding an unrelated fact can change the answer for a goal.
- **The fast path can answer "not proven" finally.** `prepared_predicate_proofs` is about 270 lines of early exits (contract_entailment.rs:55018-55245); `Some(false)` stops the slower exact route at 54964-54972. Several exits depend on `has_no_rewrites()` or whether premises exist (55162-55165, 55231-55232, 55238-55245), so provability depends on unrelated context.
- **Dead and redundant code.** In `integer_value`, the `matches!(value, IntegerEmbedding)` test at contract_entailment.rs:55707-55709 cannot be reached, because the `if let` at 55689-55706 always returns. In `project_integer_premises`, `identity.boolean()` is tested twice in a row (55440-55445). `denial_holds` has two overlapping emptiness guards (54859-54865).
- **Misleading names.** In `prove_observed_integer_ordering_minimum`, `greater_eq_judgment` holds the judgment of the strict `>` predicate (contract_entailment.rs:54789-54806); `ge_eq_judgment` holds `>=`.
- **Misplaced doc comments, signs of code moved by hand.** The commutativity description sits on `distributivity_shape` (contract_entailment.rs:58479-58482); the "trait-level half of the algebra license" description sits on `for_each_ensures_identity` followed by a second, different description (57784-57791); the "Compute the program's REARRANGE licenses" description sits on `struct RingCandidate` (58262-58276).
- **Discarded diagnostics and a 19-argument call.** `observed_body_paths` calls `recognize_structural_state_leaves` with 19 positional arguments including `usize::MAX`, `&mut 0`, `&mut []` and three empty vectors (contract_entailment.rs:59809-59829) and throws away any diagnostics (59830-59832).
- **Invalid handles as identity parts.** `prepare_normal_call` passes `arena::Handle::invalid()` as the statement (contract_entailment.rs:60786), and results are built with `statement: arena::Handle::invalid()` (60398, 61672), so these captured values differ only by expression, callable and the occurrence counter.

- **Unexpected capabilities.** User traits can earn ring and semiring rearrangement (contract_entailment.rs:58434-58641); literal identity elements are derived from trait laws as text for "index algebra" (57906-58033); wrapping overflow is folded exactly (58912-58925, test at 59453-59459); subordinate callee bodies are walked in place of their contracts (59747-59870); completed calls with the same denotation are merged into one canonical captured integer (61097-61219).

Cannot tell whether type lookup resolves that node by name.
