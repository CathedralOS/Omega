## What this code is for

This is the second half of the expression evaluator of the old checker's "flow" pass. It does not refuse programs and contains no diagnostic text. It walks each statement's expression tree in evaluation order (`Execution`, 9487-9522; entry `append_statement_calls`, 9531-9701) and writes rows into arenas of "flow facts" that later passes judge: one `FlowOperandFact` per completed operand, the storage places a reference or slice may point at (`FlowOperandReferent`, called "referents"), the lifetime roots a value keeps alive (`FlowOperandRetention`, called "retention"), the references stored inside an owned value (`FlowCapturedReferenceLeaf`), call facts, case-access facts, value-observation facts, loan activations, operator-invocation facts and atomic-execution facts.

Three submodules sit in the slice. `view_footprints` (5967-6334) computes the conservative set of storage a view may cover ("possible storage") and whether a view's backing may be projected into. `view_referents` (6335-8011) computes the exact places a reference denotes for each construct: member access, indexing and slicing, call results, match results, reads of stored references. `view_retention` (8012-9366) computes the lifetime roots for the same constructs. The rest (9368-12116) is the evaluator itself: operand prologue and epilogue, the per-construct `match` on `ExpressionNode` (11205-11781), the record of writes made while operands are evaluated, the removal of facts those writes invalidate, and the intersection of facts after a short-circuit.

When the code cannot establish something it returns an invalid handle or an empty span and goes on. Whether that leads to a refusal is decided by code outside this slice.

## Mechanisms

- **Explicit frame stack for binary operator chains** (`evaluated_operand_as`, 10050-10166). It evaluates an operand without recursing through left operands of binary operators. Each `BinaryOperandFrame` (9384-9391) holds the prologue result, the operator, and the evaluated left operand once the right one is running. The comment says each frame "runs exactly the steps, in exactly the order, that the nested calls did" (10039-10049). No depth limit. Serves deeply chained operators.
- **Write timeline with snapshots** (`operand_writes`, `record_operand_writes` 10751-10779, `write_prefix` / `restore_write_prefix` 10731-10749, `join_storage_prefixes` 10781-10788). Each write is a pair of optional place lists (observations, bindings); `None` means "unknown write". Each write appends a new immutable storage snapshot. A branch restores the prefix that reached its guard; a join builds a snapshot from predecessor snapshots. Serves evaluation order, short-circuit and match arms.
- **Fact invalidation by overlap** (`changed_operand_sources` 11902-11973, `filter_captured_sources` 11975-12016). For each operand, every occurrence's canonical place is compared with each later write. A write under the same root that may overlap marks the place changed. If the operand's place is a strict prefix of the write and has no runtime index, only the written descendant is marked (field-level precision, 11947-11966). An unknown write marks the whole place.
- **Intersection after a skipped path** (`meet`, 12018-12071): ordered intersection of semantic contexts, of constraint refs, and of live memberships.
- **Retention join** (`join_retention_profiles` 8241-8291, `capture_retention_join` 8333-8384): union of roots with alternatives kept; per-leaf join across alternatives.
- **Iterative depth-first walk with cycle check and budget** (`retained_backing_allows_projection`, 6235-6283). Budget is the number of profile rows; uses two `std::collections::HashSet`s.
- **Worklists over nested alternatives** of `StoredOperand` (7551-7596, 8137-8168).
- **Enumeration of concrete index paths** for a place with a runtime index (7513-7539, via `finite_projection_paths`). Limits are in the callee, not here.
- **Constant coordinate lookup** (`captured_coordinate`, 7764-7822): reads an integer from the fact store for the operand's place under its contexts.
- **Recursive image test** (`projection_is_immutable_image`, 7980-8010): follows a projection through constructed children.
- **Receiver walk** (`pointee_segments_start`, 11804-11828): climbs member, index and borrow receivers until one has view type.

## Surprises

1. **The slice refuses nothing.** In 6,150 lines there is no diagnostic and no error return. Every failure becomes an invalid handle, an empty span or an early `return`. The yes/no for all of these rules lives in consumers of the flow facts.
2. **An empty referent span has at least three meanings**: "unknown" (7241-7243, 7499), "immutable image, no address" (7240, 7498, comment 7977-7978), and "not a view" (10196, 10296). `stored_view_referents_at_place` returns the same `Some(empty)` for an all-image store and for an unknown one (7494, 7498-7502). Only the separate `immutable_image` flag on the retention profile tells them apart.
3. **The two call placements treat a failed argument order differently.** The expression arm stops (11372-11374); the statement arm proceeds with default operands (9659-9668).
4. **A structurally mismatched call is handled by erasing the statement's facts** (9792-9795), not by reporting. The erased constraint span also holds `BorrowLoan` constraint refs (see 6442-6443, 6614-6618), so restrictions are dropped together with knowledge.
5. **A fact about a call's result is derived by reading the callee's body** (`returned_constructor_case`, 12078-12099), not from its `ensures` contract, and it keys on the unresolved `call.target_symbol`.
6. **Binary operators are evaluated by two separate copies of the logic** (10064-10163 and 11299-11330). The recursive copy is still reached through `expression_result` from `evaluated_place` and `expression`, so the stack-depth repair covers only the operand path.
7. **The comment on `operand_is_view` (10941-10949) describes a resolver that returns `None` and an "intersection transport"; the function returns a `bool` and resolves nothing** (10950-10961). The comment belongs to code that is no longer there.
8. **`std::collections::HashSet` keyed by dense handles** in `retained_backing_allows_projection` (6252-6253).
9. **Rows are appended only to obtain a handle.** `capture_owned_reference_leaves` appends a referent row per place per path (6698-6702) though the handle is used only in the `Incoming` case (6746-6755). Operand rows are inserted for lookups at 7176, 8100, 8120, 8886, 11194, 11215; only one site rewinds (6132-6136).
10. **Leftover renames**: `let alternatives = contents; for contents in alternatives` (6724-6725, 7229-7230); `let projection = source_path;` so one span serves as both `projection` and `source_path` (9251-9256, 9275).
11. **A debug trace sits in the normal call path** behind a trace flag (9960-9965).
12. **`is_incoming_descriptor_place` ignores segments for parameter roots** (7058-7064) while the loan branch below it compares the full owner path (7088-7098). The two branches of one predicate use different precision.
13. **Uniqueness is required in several lookups** (6485-6490, 6592-6597, 9164-9165, 10556). If the same expression is evaluated twice in one statement, the lookup finds two rows and the permission, call ordinal or observation result is silently left unset.
14. **`dispatch_copy_value` is consulted both before and after evaluating the same operand** (10184, 10230) with different acceptance: the prologue takes only copies with an empty path, the epilogue takes any copy.
15. **`capture_indexed_referents` turns a known `start > end` into `OpaqueRange`** (7678-7683) with no other mark.
16. **`Assembly`, `AssemblyFact` and `Transition` statements evaluate nothing here** (9567, 9694), although `InvocationSite::Transition` exists (9464) and is handled by `invoke` (9900, 9911); the transition caller is outside the slice.
17. **`capture_member_retention` can produce a valid retention with zero roots** when the receiver has referents and every stored profile has known but empty roots (8926-8940). That reads as "retains nothing".
