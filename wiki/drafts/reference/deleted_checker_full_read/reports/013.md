## What this code is for

This slice is not a checker of proofs, ownership or contracts. It is the part of the old typed-tree stage that makes a concrete copy of a generic machine (monomorphization) and then repairs the copy. `bcr.rs` `body_cloning` deep-copies one template machine for one set of static arguments: it makes fresh symbols for the machine, its owned data, states, parameters and locals, copies every type, expression, statement, contract, termination premise, ranking witness and "retained constant recipe", and records the result as a `MachineSpecialization` (bcr.rs:692-1660). `bcr.rs` `body_rewriting` then rewrites the copy: it puts copied calls back to their authored form, points machine-parameter and evidence-parameter calls at the selected machines and implementations, substitutes type and const parameters, folds closed const arguments, appends runtime "Value" operands to calls and transitions, and deletes transition statements whose target has a `requires` that is false for the chosen constants (bcr.rs:2312-5601). `conf.rs` `conformance_application_lifetimes` fills in lifetime arguments that the author left out on a selected trait implementation ("conformance"), by matching the callee's parameter types against the argument types at each call (conf.rs:228-592). `conf.rs` `explicit_requirement_calls` takes a call written against a trait requirement with a named implementation (either as a qualifier or as the last static argument) and rewrites it to call the implementation's state directly, after checking the implementation really implements the trait application the call names (conf.rs:1362-2127). The same module refreshes those selections after the program changes (conf.rs:2168-2284). Along the way the code refuses a number of programs, mostly with "lost its ..." internal-consistency messages and a handful of user-facing rules listed below.

## Mechanisms

- **Fresh-symbol cloning with a symbol map** (bcr.rs:799-990). The cloner inserts generated child symbols in one batch per parent and pairs them with the source symbols by position (`next_child.next().expect(...)`). The result is `symbol_map: Vec<(old, new)>` and `SymbolRebinding::new(&symbol_map, &authored_symbols)`, where `authored_symbols` is the map without machine and state entries. Lookups are linear scans. Serves generic machines and captured methods.
- **"Everything created since" watermarks** (bcr.rs:768-769). `type_start` and `expression_start` are table sizes taken before copying. Later passes rewrite every type or expression with an index at or above the watermark (`references_from`, `named_references_from`, `iter_expressions_from`), on the assumption that only this clone appended to the tables in between. No other scoping is used.
- **Two-step copy through a staging table** (bcr.rs:1676-1691, 2025-2045, 18-41). When source and destination are the same program, the code copies into an empty `TypedTreeTables`, copies back, and composes the two correspondence lists so the copy still maps to the original.
- **Retained constant recipe copying** (bcr.rs:43-141, 157-270). For a copied type or contract expression, the recipe (lexical contexts, invocation list, pending range-endpoint marks) is rebuilt for the copy. The copy does not carry a closed value or an `evaluation_entry` (test at bcr.rs:320, 332).
- **Provenance walk** `authored_target` (bcr.rs:2804-2861): follows closed requirement application -> template, instance machine -> template machine, instance state -> template state (captured-state table, else same ordinal), with a visited list; no budget.
- **Call restoration then rewriting** (bcr.rs:2362-2729, 2871-3239). Each copied call is first put back to its authored operation with static arguments rebuilt from recorded bindings, then rewritten for the new specialization from four rewrite lists (machine parameter -> machine, evidence placeholder -> realization state, evidence binder -> conformance, forwarded static argument).
- **Runtime Value realization** (bcr.rs:908-978, 1288-1305, 3284-3329, 4962-5600). A const parameter bound to a runtime value becomes an extra trailing parameter on every state of the clone. Calls and transitions to clone states get matching trailing arguments. `OperandPlan` (5256-5272) splits planning (read-only) from realization (inserting nodes).
- **Const folding of static arguments** (bcr.rs:3565-3813). `const_integer::classify` gives a closed `i128` or Open; closed integers become `const_literal`; closed structured values become a canonical "atom" string. Recurses into nested applications and qualified static members.
- **Refuted-arm pruning** (bcr.rs:3932-4070): a three-case boolean evaluator over `requires` expressions.
- **Trait closure walk** (bcr.rs:4246-4268): trait, then its `refines` base, then its required parents, depth first with a visited list. Its output ORDER is used as an index into the evidence binder's child symbols (bcr.rs:4211-4212; conf.rs:2015-2026).
- **Scope resolution through application frames** (conf.rs:53-161). `Scope::resolve` replaces a named type parameter by the argument supplied in the nearest enclosing frame, trimming frames as it goes, with a visited list of `(reference, owner, frame count)`. `Scope::argument` maps a lifetime name outward through frames to a region identity and returns its spelling only if the caller can name that same region.
- **Lifetime inference by structural matching** (conf.rs:823-967 and 969-1103). Walks a required type and an actual type together (reference, constrained, generic with same base, slice, fixed array) and binds each callee lifetime parameter name to the caller's lifetime name; first binding wins and a different later one sets a conflict flag (conf.rs:727-740). Not a fixpoint; one pass over the arguments.
- **Declaring-application match** (conf.rs:1191-1275): a worklist over (trait application, ancestor list) pairs, pushing each parent application with an accumulated scope stack, comparing normalized type identities when the declaring trait is reached. Cycle guard by ancestor list; no budget.
- **Fingerprint naming** (bcr.rs:771-803): instance name is `template$specialized$<16 hex fingerprint>$<ordinal>$<symbol count + 1>`.

No budgets, step limits or fixpoints appear in this slice. All cycle guards are `Vec::contains`.

## Identity by text

Most identity in this slice is by `SymbolHandle` and arena handles. The following are by text or by position.

- Specialization identity: the fingerprint is computed from the template NAME, `normalized_type_identity_text` strings of type and const arguments, `joined_path()` strings of machine arguments, and evidence path strings (bcr.rs:654-667, 771-793). The generated machine name embeds it (794-798). `MachineSpecialization` stores display strings and identity strings of the arguments (1634-1637).
- A const binding is a `Named` type reference whose name is a decimal number: `binding_name.as_str().parse()` (bcr.rs:3395-3403).
- `remember_integer_type` looks for a `Named` type with an invalid symbol whose name equals the integer's decimal spelling, and inserts one if missing (bcr.rs:3871-3886).
- A closed structured const value is written as a static argument whose `path` is the canonical value's `atom()` text, and a `Named { symbol: invalid, name: atom }` type is inserted (bcr.rs:3790-3800).
- Fixed-array length const parameter matched by name when both symbols are invalid (bcr.rs:3436-3439, 3457-3460).
- Integer equality in `requires` decided by comparing canonical spelling strings (bcr.rs:4041-4045, 4056-4066).
- Field looked up by name on the receiver's data type to fill in a missing member symbol (bcr.rs:2217-2227, 2298, 2269).
- Realization target name is the text after the last `"::"` of `row.realization_name` (bcr.rs:4222-4228; conf.rs:1965-1971).
- Alias text `"<unnamed-conformance>"` stands in for a conformance with no alias and is passed to `apply_provider(.., alias.as_str())` (bcr.rs:4119-4121, 4163). `"<unnamed>"` in a diagnostic (conf.rs:529).
- Machine-binding entry name is `binding.path.last()` (bcr.rs:2889-2892, 4288-4291).
- Subjects and receivers are rebuilt as name paths from `program.symbols.name(symbol)` (bcr.rs:2502-2509, 2697, 5323; conf.rs:1492, 1645, 1719).
- Lifetimes are carried as `(String, String)` parameter-name/argument-name pairs everywhere in conf.rs: `bind_lifetime` and `resolved_lifetime` compare names (conf.rs:727-747); callee lifetime parameters are recognised by `parameter.as_str() == required.as_str()` (893-896, 930-932, 995-997, 1045-1047); inferred values looked up by name (437-439); `ApplicationScope.lifetimes: Vec<(String, String)>` (1153). The file header calls this "Name-owned" (conf.rs:2). `Scope::argument` does convert a name to a region identity with `lifetime_parameter_identity(program, owner, name)` and checks the caller sees the same region (conf.rs:140, 157-159), but it returns a spelling. When `caller` is invalid the name is returned unchanged (133-135).
- Domain membership contract built from `domain_name: String` (bcr.rs:568-573, 621-628).
- By position rather than by text: evidence placeholders are the binder's child symbols zipped with the trait closure order (bcr.rs:4211-4212; conf.rs:2015-2026); a specialized state maps to the template state with the same ordinal (bcr.rs:2849-2858); owned data symbols at `symbol_map[1 + index]` (bcr.rs:1156-1159); evidence bounds consumed in order by `evidence_index` (conf.rs:353-367); trailing call arguments are the runtime operands (bcr.rs:2633, 5178).

## Surprises

1. **A flag that cannot change.** `let complete = true;` (bcr.rs:736) is returned unchanged at 756, so `cloned.structural_type_equations_pending = !predicates_closed` (993) always writes false. The loop around it only ever refuses on `Some(false)`. It reads like the remains of a "defer when undecided" path.
2. **Evidence on the three sampled properties.** (1) Holds: nothing in the slice calls a proof kernel; every refusal is an equality or count compare in this code or a call into `validation::`/`typed_trees::`. Fingerprints and "commitments" (`application_report_fingerprint`, `application_commitment`, `accepted_template_commitment`) are passed along and compared for equality (conf.rs:1754-1761, 2145) but nothing here verifies them. (2) Mixed: symbols and handles carry most identity, but const values, lifetimes, specialization identity and some field and target names are text (see the section above). (3) Mostly does not apply: the slice transforms trees rather than judging placements, and its duplication is statement-call versus expression-call and construct-by-construct.
3. **Const values live in the type table as names.** An integer const argument is a `Named` type with an invalid symbol and a decimal name. `remember_integer_type` (bcr.rs:3871-3886) and bcr.rs:3791-3796 insert such a type and discard the handle; the insertion exists only so that some later lookup by name finds it.
4. **The compiler deletes code it has decided is unreachable, using its own small evaluator.** `drop_refuted_closed_transition_arms` (bcr.rs:3932-3967) removes `Transition` statements from the flat statement list of a state when the target's `requires` is closed-false. Any one false `requires` among the target's machine and state contracts is enough (4025-4027). Nothing is reported, and nothing else about the state (guards, preceding statements) is adjusted in this function.
5. **Inherited termination.** A specialized machine takes the template's published termination guarantee and `checked_summary` verbatim apart from symbol remapping (bcr.rs:994-1007).
6. **Machine-level facts are tied to the first state's parameters.** For runtime Value parameters, machine contracts, ranking subjects, ranking view arguments and the rank range are remapped with `state_realized_parameters.first()` (bcr.rs:1111, 1123, 1135, 1179), that is, to the extra parameter symbols of the first state only.
7. **Possible gap in the runtime-Value type check** (bcr.rs:4838-4861 versus 1722-1799), described under "Accepts or skips".
8. **Two functions named `copy_expression` with different effects.** `constant_roots::copy_expression` (bcr.rs:143-155) also copies constant recipes and can fail; the outer `copy_expression` (1696-1713) does neither. Contracts use the first (2089, 2115, 2140). Owned-data initial values (1163), ranking expressions (1110, 1122, 1134), proof output calls (1338) and runtime binding expressions (1934) use the second, so constant recipes rooted in those are not carried by this path.
9. **Dead condition.** In `refresh_occurrence_selections`, `handle` is read from `dispatch.selection_application` (conf.rs:2224, 2234), so `dispatch.selection_application != handle` (2262, 2276) is always false and the assignment at 2265/2279 writes the value already there.
10. **No-op at loop end.** conf.rs:338-340 `if inferred.is_none() { continue; }` is the last statement of the loop body.
11. **Early return drops collected diagnostics.** conf.rs:278 uses `?` inside a loop that otherwise accumulates `diagnostics`.
12. **Statement calls cannot carry a qualifier type.** `qualified_selection_arguments` reads `requirement_application` only for expression calls and uses an invalid handle for statement calls (conf.rs:1619-1625), so a statement call always takes the bare-symbol path (1643-1647).
13. **Routing mutates the authored application.** `through_implementation` writes a `StaticConformanceSelection` holding the closed application into the call's source application (conf.rs:1956-1961) before the rewrite is committed, and before the diagnostics check at 1547.
14. **Names depend on table size.** The generated instance name ends in `program.symbols.symbols().len() + 1` (bcr.rs:797), so it changes with the order in which specializations are made.
15. **Order coupling.** The evidence binder's child symbols are matched to requirements by the depth-first order of `collect_evidence_requirement_closure` (bcr.rs:4211-4212; conf.rs:2015-2026). Whatever created those child symbols must have used the same order; nothing here checks names or symbols.
16. **Panics as invariants.** Many `expect`/`unreachable!` calls assume earlier validation (for example bcr.rs:4203, 2525, 3579, 4352), so a broken upstream invariant aborts the compiler rather than producing a refusal.
17. **Most refusals have no source location.** The `source_calls` errors are bare `&'static str` wrapped into a diagnostic without a span (bcr.rs:2880-2881); the same holds for `TypeCopyError` (550-566) and several conf.rs errors (278, 343-346, 385-387).
18. **Erased parameters get a second type copy.** For erased state parameters and erased locals the already-copied type is copied again with the realized-symbol map (bcr.rs:1264-1267, 1276-1285), which is how proof-only bindings come to mention the runtime parameter symbols.
19. **A specialized clone is never public** (bcr.rs:1008), and when not capturing it has no conformance bounds and no type parameters (1038-1040, 1073-1074).
