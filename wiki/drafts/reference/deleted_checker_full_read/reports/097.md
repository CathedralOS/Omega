## What this code is for
The file answers "what value is stored at this place at this program point" for the old checker's flow facts (`FlowControlFacts`), and uses the answers for borrowing, custody and qualification proofs. `completed_storage` (F:5-4730) walks a graph of storage snapshots (stores, joins, writes, preserved bindings) and returns the stored operand, its alternatives, or "unavailable". It then derives which storage a reference or view can point to (`backing`, `reference_captures`, `frozen_references`), how long a view is (`descriptor_extents`), where a value came from (`predecessors`), whether a returned or cast value still carries a domain qualification (`memberships`, `owned_memberships`), and where a returned-descriptor loan was formed (`loan_homes`, `call_stores`). `content_conservation` (F:4732-6285) reads `ensures` facts that use `old`, `separate` and `Content<Owner,A>::project`, normalizes each into a "conservation equation" over a content algebra, and reports errors for malformed ones. `content_projections` (F:6287-7049) validates the user-written `project` machines (one shared-borrow parameter, linear carrier, one algebra constructor over field reads and closed arithmetic) and builds `ContentProjectionPlan`s. Nothing here calls the proof kernel; it computes yes/no itself and builds plans and fingerprints for other stages.

## Mechanisms
- Storage snapshot resolution (F:113-428). Computes, for a place and an observation mode (Binding, InlineContents, Contents), the set of store events that supply its value, or Incoming/Unavailable. Fast path: linear walk back along `previous` (F:367-428) bounded by snapshot count. Slow path: iterative depth-first search with an explicit stack, `Annotation::Active/Complete` marks, memoised results, and a work budget of 3*snapshots + 2*predecessor edges + 1 (F:124-138). Revisiting an Active node (a cycle) gives Unavailable (F:229). Serves reads of stored values for all borrow/custody questions. `ReadCuts` variant answers "preserved from these cut snapshots" (F:93-111).
- Reference backing resolver (F:909-1284). Recursive resolution of the storage places a reference value may point to, with stacks `active` (query pairs) and `active_profiles` for cycle refusal; three entry points differ by two booleans (`projectable`, `write_footprint`) (F:848-907).
- Retention-profile walk (F:1364-1656). Three nested active stacks (profiles, copies, selections) detect recursion; results deduplicated.
- Finite projection expansion (F:1747-1785). Worklist replacing each `Index` segment with every `FixedIndex` up to the fixed array length; bound 4096 paths.
- Reference-capture selection (F:2035-2929). Memoised recursive resolver (`memo`, `profile_memo`) with `active` guards, joined by `join` (F:2897-2928), which returns Unavailable if any alternative is unavailable.
- Completed-membership traversal (F:3652-3770). Depth-first proof by predecessors, `remaining = 65_536` steps, `visiting.len() >= 128` depth limit, cycle check on (value, path); requires every predecessor to prove membership.
- Descriptor extent (F:3057-3134). Worklist over captured views to a consistent element count (handles `FixedRange` with `usize::MAX` meaning "to end").
- Returned-descriptor loan supplier walk (F:4488-4647). Iterative DFS with active/completed lists over loan suppliers.
- Consumer capture search (F:4049-4150). Worklist over all operand sources reachable from a statement's rows.
- Content equation normalization (F:4914-5035). Recursive descent over `separate`/projection calls producing `ContentConservationTerm` trees, plus a duplicate-owner check (F:6008-6027).
- Projection expression normalization (F:6648-6798). Recursive syntactic recognizer for the closed fragment of scalar expressions.

## Surprises
- No call to the proof kernel (`proof_admission`, `ProofNode`, `verify_obligation`, certificates) occurs in the slice. Qualification is answered by `facts.qualifications.content.establishes_completed_membership` (F:3683-3695) and the file's own traversal; the one delegation to proof machinery is `validate_proof_body_formation` (F:6423). Property 1 holds: acceptance is the code's own yes/no.
- Property 2 holds in `content_conservation` and `content_projections`: field/variant lookup by name, carrier equality by identity text, algebra picked by string leaf, domain attachment by name leaf, root matched by `name == root_name` (F:5524). For the `Content` trait and algebras a guard `compiler_owned_symbol` limits the name check to toolchain-origin symbols, but that function returns true when there is no source metadata (F:6936). `completed_storage` (the first 4,730 lines) is not text-based: it uses arena handles and typed place segments, with only environment-variable names and debug strings as text.
- Property 3 holds strongly for "completion kind" (Selected, Copied, leaves, constructed, value source, InvocationResult, IncomingContents) and for the three entry points; duplicates differ in small ways (F:2495 vs F:3031 access test), so a fix to one would not reach the others.
- Access-compatibility rule differs between copies: case-access and reference-leaf paths allow a Mutable declared reference to supply a weaker request (F:2495-2497, 2622-2624); the frozen-leaf path requires exact equality (F:3031).
- `non_contract_expression_nodes` (F:4749-4778), by name a query, also collects callable plans and diagnostics as a side effect through `ContractContexts`.
- `validate_content_projection_conformances` emits diagnostics, but `build_content_projection_plans` re-applies a subset silently; a projection machine with an error is simply absent from plans (F:6463-6513) with its error given elsewhere.
- `predecessors_in_flow` takes `_semantic: &facts::FactPlan` and ignores it (F:3191).
- `ProjectionSubject.qualified` is used for domain constraints F:6997; otherwise `ProjectionDomainCandidate` is built by name match before type check, so a domain with the same leaf name from another package is dropped only when source metadata exists (F:6983-6989).
- The membership walk caps at 65,536 steps and 128 depth and on exhaustion records the refusal "completed membership traversal exhausted" (F:3670-3673): the code refuses on a budget, never accepts.
- Debug tracing uses `eprintln!` with environment variables inside checking code (F:503-509, 526-603, 2109-2136, 3707-3717).
- `Content` projections are limited to linear carriers (F:6375) and shared-borrow subjects (F:6957), and to `ensures` contracts (F:5976); `requires`/`invariant` positions are always errors.
- A "conservation equation" cannot mention more than one equation per qualification owner and algebra per callable (F:6008-6027), so equations must be pre-merged by the author.
