Terms used in this report, as the code uses them:
- **probe**: a synthetic one-state machine the compiler builds around a single initializer expression so that the build-time evaluator can run it (`append_probe`, CI:1321-1332).
- **materialized initializer**: the literal expression the compiler writes in place of a computed initializer.
- **custody**: the recorded list of source positions of the constants, operators and calls that an initializer used. The code compares custody lists from different passes.
- **receipt**: a record of one evaluation (program, machine, arguments, result, work units).
- **replay**: evaluating the authored initializer again in the final typed program and comparing the result with the stored value.

## What this code is for

This slice is the part of the old compiler that computes the value of a `const` declaration at build time. `CI` takes each constant whose initializer is not already a literal, works out which other constants it depends on, evaluates them in dependency order, and replaces each computed sub-expression ("leaf") with a literal (CI:3817-4520). It evaluates a leaf by wrapping it in a probe machine and running that machine through the build-time evaluator; calls to other machines inside an initializer are admitted one at a time with their concrete argument values (CI:586-696). Constants whose value depends on the target's data layout (for example `size_of<T>()`) are deferred and settled later (CI:3292-3544). After the final typed program exists, a "replay" pass evaluates the authored initializer and the materialized literal again and refuses the program unless both equal the stored value (CI:2077-2485). `EA` holds the receipts for those evaluations and checks that the work each one charged stays within a fixed budget of 100,000 units (EA:274, EA:425-471). `ER` holds the data types that describe one build-time machine invocation, and the refusal message for three jobs that no engine could run any more because the tree interpreter had already been removed (ER:14-43). This slice does not check `requires`/`ensures`, ownership or termination itself; where it needs those it calls the old checker or the admission code in other modules.

## Mechanisms

- **Readiness scheduling of constants** (CI:3931-4518). The code marks as "demanded" every constant that has unevaluated leaves and is not waiting on target layout, then closes that set over dependencies with a worklist (CI:3931-3951, CI:4164-4182). Each round it collects the demanded constants whose dependencies all have values (CI:3960-3972), evaluates them, and loops. A round with nothing ready reports a cycle (CI:3973-3992). No iteration budget; termination relies on each round finishing at least one constant or returning an error. Serves `const` initializers.
- **Cycle detection** (CI:4522-4572). Iterative depth-first search with an explicit path stack and three marks. It follows only dependencies in the current batch (`Dependency::Current`) and skips constants that already have values. It runs twice per round (CI:3930, CI:4154).
- **Propagation of "depends on target layout"** (CI:3783-3815). A fixpoint: a constant is marked as pending target observation if any constant it depends on is. The flag is written back into the syntax tree.
- **Probe projection** (CI:1835-1920). Two fixpoints over the typed program. The first finds machines that exist only because of a probe (captured applications, specializations, generated machines, lexical regions whose owner chain reaches a probe). The second keeps those that a non-probe declaration also references. The remainder, plus the probes, are removed before the old checker runs on the rest (CI:1922-1947) and are put back afterwards without having been checked (`rejoin_unjudged`, CI:1949-2029).
- **Replay domain closure** (CI:2083-2105). Fixpoint adding every constant referenced from an already selected constant.
- **Evaluate twice and compare** (CI:2241-2483). For each replayed leaf the code appends two probes, `@const-replay-N` for the authored expression and `@const-replay-materialized-N` for the literal, prepares and checks the program once, runs both, and compares each with the decoded stored value.
- **Authored/materialized correspondence** (`pair`, CI:3027-3279). A recursion over two expression trees, a type and an expected value at once, splitting an aggregate initializer into scalar leaves. An `active` list of expression handles guards against revisiting (CI:3036, CI:3089). An aggregate that is not a literal on both sides becomes one "structured" leaf (CI:3084-3088, CI:3260-3271).
- **Per-call admission with concrete arguments** (CI:586-696). Arguments are evaluated in the order `CallSite::argument_evaluation_order` gives; each value is also turned into a literal "snapshot"; the snapshots go to `snapshot_arguments_discharge` so that the callee's preconditions are judged on concrete values; only then does the callee run.
- **Deferred target constants** (CI:3301-3544). `retain_entries` gives each unevaluated scalar constant a private evaluation machine named `@constant-<name>`. `settle` repeatedly picks the first constant with no unevaluated dependency, evaluates it under its type's arithmetic domain (CI:3491-3500), overwrites every use of the constant with the literal (CI:3509-3533) and stores the value. It clones the whole typed program for every candidate it examines in every round (CI:3365).
- **Named-result overload resolution to a fixpoint** (CI:2288, CI:3353): `while !validation::resolve_named_result_overloads(&mut probe)?.is_empty() {}`. No budget.
- **Work metering** (EA:574-689). Every recorded evaluation runs under a `psi_work::WorkMeter` with a budget of 100,000 units. A receipt is reserved before the run (a `None` slot), filled after it, and `finish` refuses if any slot is still empty (EA:525-545). Storage is measured but its ceilings are `u64::MAX` (EA:321-330).
- **Program retention by equality** (EA:547-572). To avoid storing the same program per receipt, `reserve_invocation` searches the retained programs with full structural `==` on the trees (EA:214-234).
- **Type walks with a worklist** (CI:2487-2516 for "contains a float"; CI:2704-2739 for collecting operators; CI:4631-4659 for constants named in array extents).

## Repetition by placement or construct

This slice has little repetition per source placement (local, field, parameter and so on), because it deals with one construct, the `const` initializer. The repetition is per value shape and per pass.

## Identity by text

- **Source spans stand in for identity throughout.** A probe machine is found by comparing its symbol's source span with the leaf expression's span (CI:177-179, CI:4077-4079, CI:4245-4250). A constant item is matched to its resolved declaration by the span of its name (CI:3847-3853). A dependency in the current batch is found by `definition.name.source_span() == source` (CI:3728-3731), otherwise by `const_declaration_at_source_span` (CI:3734-3736). Uses of a settled constant are found by "a selection whose span equals the expression's span and whose target is this constant", and those expressions are overwritten (CI:3509-3533). Operator custody is a list of spans compared as a set (CI:2713-2714, CI:2762-2772). Authored and materialized roots must share a span (CI:3037). A span is a position, not text, but it identifies by where something was written, not by what value it is.
- **Type identity inside canonical values is a name string.** `DecodedCanonicalConstValue::Integer { type_name }`, `Array { type_name }`, `Record { type_name }`, `Variant { type_name, case_name }` are built from `primitive.name()` (CI:1642), `definition.name.as_str()` (CI:1704, CI:3018), `type_label` (CI:1622) and `symbols.name(...)` (CI:3019). They are compared as strings at CI:1525, CI:1729, CI:3058-3059, CI:3105, CI:3159, CI:3187. The record name is the bare declaration name, not a path, so two data types with the same name in different packages produce the same `type_name` here; I cannot tell from this slice whether the encoding distinguishes them elsewhere.
- **`type_label`** renders a type to text such as `[u64; 4]` or `()` (CI:1761-1793) and that text is compared at CI:3105.
- **Fields and cases are matched by name**: evaluated struct fields by `name.as_str() == field.name.as_str()` (CI:1563-1566, CI:1710-1713); cases by `variant_member_by_name` (CI:1811-1819, used at CI:1543, CI:1747); field order by name (CI:3222); a fallback field lookup passes `field.name.as_str()` (CI:1002-1008). `BuildTimeValue::Struct { type_name, fields: Vec<(String, _)> }` and `Case { variant, payload }` carry only names.
- **A constructor is written back as path text and must re-resolve.** `nominal_literal_for_definition` renders the data type's path with `display_path(symbol, "::")`, checks that looking that text up from the constant's source position returns the same symbol (CI:1483-1496, CI:1503-1517), and then emits a syntax struct literal whose `constructor_name` is that text, or `format!("{owner_path}::{variant}")` for a case (CI:1547, CI:1580-1590). Field names are emitted as `Identifier::generated(field.name.as_str())` (CI:1575).
- **Encoding prefix decides "is a float"**: `encoding.starts_with("float:")` (CI:2152-2156).
- **Integer type from a name**: `LandedIntegerType::from_name(&type_name)` (CI:1140-1143).
- **Numbers pass through decimal text**: integer literals from `value.to_string()` (CI:1131-1137, CI:1310-1312, CI:1403-1414, CI:4382-4388); an integer literal becomes a float by `FloatLiteral::parse(&value.to_string())` (CI:2823-2828).
- **Probe names are strings with meaning by convention**: `"@const-invocation"` (CI:248), `"@const-requirement"` (CI:565), `"@const-argument"` (CI:833), `"@const-replay-{n}"` (CI:2247), `"@const-replay-materialized-{n}"` (CI:2258), `"@const-float-custody-{n}"` (CI:2281), `"@const-float-replay"` (CI:2634), `"@constant-{name}"` (CI:3322). In this slice they are only labels; nothing here compares against them.
- **Callee passed as a display string** to the precondition check: `machine.name.to_string()` or `display_path(operator.symbol, "::")` (CI:673-678).
- `CanonicalConstValue::from_decoded(&decoded, expression_table(typed).display_name(expression))` carries an expression's display name into the value (CI:1165-1168).
- `CanonicalScalarScope` stores `target: String` and provider identities as text (EA:51, EA:77-86). `BuildMachineEntry::Name(&str)` lets a request name its entry machine by string (ER:113-116). `UnavailableStaticInput::Binding` carries a `display: String` (ER:59-62). The one test finds a machine with `realized_machine_named("bytes")` (CI:3564-3567).

Against this: most lookups of declarations, data definitions, fields in `pair` (CI:3225-3238) and callees use `SymbolHandle` equality, not names.

## Accepts or skips without proof

1. **Probe machines skip the old checker.** `CheckedInitializers::prepare` removes the probes, runs `prepare_typed_trees` and `typed_trees_to_checked_trees::lower_typed_trees` on the remaining "helper bodies", and `rejoin_unjudged` pushes the probes back (CI:129-138, CI:1949-1958). The initializer expression is then covered only by this file's own carrier checks and by the admission plan. I cannot tell whether the admission plan checks probe bodies.
2. **The old checker does not run at all for scalar leaves without calls.** `evaluate` prepares `CheckedInitializers` only if some ready leaf is structured or has calls (CI:4232-4240); otherwise `evaluate_probe` runs on the unchecked typed program (CI:4339-4347). Other check: replay later, but replay also skips these (item 9).
3. **Primitive destination accepted without comparison.** `require_expression_carrier` returns `Ok` as soon as the destination is primitive (CI:940-942). The evaluator's kind match (CI:471-516) catches a wrong kind at run time; I see no check of the arithmetic domain on this path.
4. **Array literal carrier check skipped when the type query returns nothing** (CI:946-949: `if let Some(actual) = ... && !match`). Length and elements are still checked.
5. **`result_carriers_match` returns `true` for `(None, None)`**: two types with equal `normalized_type_identity` that are not closed data (CI:1255).
6. **`extent` application probe falls back to the probe's return type** when the expression has no result type (CI:1113-1118).
7. **Integer results are not range-checked against the destination here.** `scalar_result` (CI:487-499), `canonical_value` (CI:1638-1649) and `literal` (CI:1400-1416) accept any `BuildTimeValue::Int(i64)` for any integer destination and reinterpret it with `as u64` when unsigned. `validate_exact_const_value_encoding` is called only on the aggregate application path (CI:1172-1176). Cannot tell whether the interpreter guarantees the range.
8. **Constraints on a destination type are stepped over.** `literal`, `canonical_value` and `type_label` go from `Constrained` to its base type (CI:1362-1364, CI:1602-1604, CI:1789). `evaluate` clears `definition.qualification` (CI:4486) and records a `ConstDestinationObligation` when `initializer_requires_destination_proof` says so (CI:4487-4496); `const_qualifications::prove_ready` (CI:3825, CI:4512), outside this slice, is what would discharge it. Deferral, with the discharging check not visible here.
9. **Replay skips constants with no calls and no float component** (CI:2188-2191).
10. **`contains_floating_component` does not descend `Generic` type nodes** (CI:2494-2513, `_ => {}`), so a call-free constant of a generic data type holding floats is skipped by replay. `literal` and `canonical_value` do handle `Generic` (CI:1437, CI:1666). Cannot see another check.
11. **A float constant written as a plain literal is checked by bits only** (CI:2598-2626); no evaluation.
12. **Float literal with no recorded format is accepted** (CI:2793: `is_some_and(|landing| landing != *format)`; CI:2819: `is_none_or`).
13. **In float replay, `Call` selections and path segments naming a dependency are skipped** (CI:2746-2756). Calls are covered by the call-custody checks in another module.
14. **The operator walk in float replay descends only binary, match and call nodes** (CI:2708-2739). Operators under any other node are not collected; the later set comparison (CI:2766-2772) would then differ, which refuses.
15. **A dependency's authored initializer already seen is not re-evaluated** (CI:2932).
16. **`dependency_leaf_value` reads the dependency's stored encoding and does not evaluate** (CI:3000-3010). The dependency's own entry in `dependencies` is checked at CI:2913-2942 if it is listed.
17. **Structured leaves skip structural correspondence** (CI:3084-3088, CI:3260-3271). In `validate` they are still compared by value (CI:2466-2478).
18. **Invalid roots and non-call selections are passed over in `settle`** (CI:3424, CI:3435-3437, CI:3447-3449).
19. **`evaluate` returns the syntax unchanged when no constant "requires initializer evaluation"** (CI:3826-3831), and constants with no leaves take their value from `canonicalize_initializer_payload` (CI:3995-4007), another module.
20. **`materialize_value` leaves any node that is not an array or struct literal as authored** (CI:4624).
21. **Cycle detection ignores `Retained` dependencies and already-evaluated constants** (CI:4532, CI:4545-4550).
22. **`prepare_selected_execution(...).unwrap_or(typed)`** keeps the unprepared program when the function returns `None` (CI:139-141, CI:2329-2332, CI:3373-3380). Cannot tell what `None` means.
23. **Accounting is optional.** With no collector, `reserve_invocation` returns `Ok(None)` and no receipt is written (EA:551-553); `finish` then returns an empty list that validates (EA:526-527). The work meter still runs.
24. **A `Failed` receipt is not checked for operators, program or machine** (EA:448-469); `has_complete_usage` reports it as incomplete (EA:252-264).
25. **`EvaluationAccounting::read` returns a default, empty collector** (EA:748-750).
26. **Receipts trust recorded assumed bindings.** `CanonicalScalarScope::capture` copies `providers.assumed_bindings()` into the scope without judging them (EA:92-99).

## Surprises

1. **No proof kernel anywhere in this slice.** Acceptance of a constant is "the compiler evaluated it, then evaluated it again and got the same value". Preconditions of called machines are handed to `snapshot_arguments_discharge` in another module. The words "receipt", "custody", "verified" and "charge" name records that this same code writes and re-reads; `validate_charge` checks arithmetic on work units (EA:159-183, EA:425-471), not a proof. This supports property 1.

2. **The initializer itself is not put through the old checker.** `rejoin_unjudged` (CI:138, CI:1949) is named for what it does: probes return to the program unjudged. For scalar leaves with no calls the checker does not run even on helpers (CI:4232-4240). Whatever the old checker guaranteed for machine bodies, this file did not obtain it for the expression in a `const` initializer.

3. **Most of the checks guard the compiler against itself.** About 80 of roughly 130 messages say an internal fact was "lost", "drifted" or became "ambiguous" between two passes over cloned programs. The design evaluates each constant in a cloned syntax tree, re-resolves and re-types it, later rebuilds probes in the final typed program, and compares. The need for those checks comes from identifying things by source span across clones (see Identity by text), where a span can match zero or two machines.

4. **Build-time evaluation already ran on Terminal Psi and required checked input.** `evaluate_terminal` refuses anything but `Checked` or `CheckedClosure` (EA:584-589), and the one entry that took unchecked trees refuses unconditionally (EA:695-702). So at deletion time three features were already refused for every program: a `FixedLayout` policy's `plan`, an access policy's plan, and a machine used as a constant domain fact (ER:14-22). The message says the program is refused "with no claim that it is wrong" (ER:39-41). A reader inventorying rules should treat these as features the old pipeline had stopped serving, tracked as EARLY-TERMINAL-JOBS.

5. **`PureEvaluationProgram::Typed` and `BuildMachineProgram::Typed` still exist** (EA:191, ER:177) and `retain`/`matches` handle them (EA:202, EA:216-218), although both recording entries refuse typed input and `evaluate` ignores its program. Dead variants in this slice.

6. **A 64-bit interpreter behind 128-bit canonical values.** Canonical integers are `i128` (CI:488-492, CI:1643-1647), but arguments must fit `i64`/`u64` (CI:650-658) and results arrive as `BuildTimeValue::Int(i64)` and are reinterpreted with `as u64` for unsigned types (CI:491, CI:1406, CI:1646). A constant call cannot take or return a value wider than 64 bits. No range check against narrower destinations is visible (Accepts item 7).

7. **NaN is a value without bits at build time.** `UndeterminedNaN(format)` is carried as its own value kind and its own expression node (CI:476-483, CI:635-637, CI:3504-3506, CI:4374). The compiler refuses to put it anywhere that needs a bit pattern (CI:1285, CI:1393, CI:1633, CI:2842). I did not expect the language to model "NaN with unspecified payload" in constants.

8. **`require_expression_carrier` has a parameter `_statement_index` that is passed through every recursive call and never used** (CI:921, CI:935, CI:979, CI:1017), and it accepts any expression for a primitive destination (CI:940-942).

9. **`pair` sets `leaf.structured`, but `validate`'s leaf loop never reads it** (set at CI:3085, CI:3267; loop at CI:2449-2483 branches on `scalar_probe_destination`). Only `validate_dependency_values` reads it (CI:2958). The flag has two unrelated owners: `Leaf.structured` in replay and `PendingLeaf.structured` in `evaluate` (CI:3764, CI:4238, CI:4300).

10. **The eight type-shape walks disagree about `Generic` types** (Repetition item 2, Accepts item 10). `type_label` returns "aggregate leaf carrier has no canonical label" for an array whose element type is a generic data type (CI:1782-1791), so `canonical_value` on such an array fails at CI:1622 even though `canonical_value` itself handles `Generic` elements at CI:1666. This looks like a bug: an array constant of a generic record type would be refused with an internal-sounding message.

11. **The callee of a constant call is found by search, not by a resolved reference.** `selected` filters all machines for "non-generic and `call_has_no_runtime_receiver(call, machine, entry)`" (CI:353-358). The answer depends on a predicate over every machine in the program, with an explicit "conflicting exact entries" failure (CI:360-362). Generic machines can never be called from a constant initializer on this path.

12. **Whole-program clones per item.** `owned_argument_probe` clones the typed program for each non-scalar argument and runs for the same argument in both validation and evaluation (CI:779, CI:809, CI:829). The operator route clones it per call and builds a new admission plan (CI:561-574). `settle` clones it per candidate per round and runs `prepare_selected_execution` on each clone (CI:3365-3380). `validate_anonymous_float` clones it per float constant (CI:2630). `reserve_invocation` compares whole programs with `==` per evaluation (EA:557-561).

13. **Hash collections keyed by dense handles**: `HashMap<ExpressionHandle, ExpressionHandle>` (CI:4278, CI:4598), `HashSet` of symbols (CI:1933, CI:1940). Most other sets in the file are `Vec` with linear `contains`.

14. **Panics in non-test code**: `expect` at CI:4303, CI:4351, CI:4413 and `unwrap` at CI:4506. The first two depend on the `any(structured || has calls)` test at CI:4232-4240 staying in step with the branches at CI:4300 and CI:4339-4351.

15. **A failed charge check masks a successful evaluation.** In `evaluate_terminal` and `evaluate_terminal_invocation`, `receipt.validate_charge()?` returns its error before `evaluation` is returned (EA:615, EA:682), so a bookkeeping failure replaces the real result. With no collector the same evaluation would succeed.

16. **A comment and the code differ in emphasis.** EA:7 says receipts are bound to "verified Terminal execution outcomes"; the only verification in this file is `validate_charge`, which checks budget, attribution sums, operator validity and presence of the program and machine. It does not re-run or check the outcome value.

17. **The re-resolution rule (CI:1483-1496) is a language-visible consequence of identity by text.** A constant whose computed value is a data type that cannot be named from the constant's source position (not imported, or shadowed there) is refused, because the compiler writes the value back as source text and needs the name to resolve. This is a rule a user can hit that exists only because of how the old compiler stored the result.

18. **Unbounded loops**: the overload-resolution loops at CI:2288 and CI:3353 and the main readiness loop at CI:3952 have no budget. The only numeric budget in the slice is the 100,000 work units per evaluation (EA:274).
