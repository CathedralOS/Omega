## What this code is for

This file plans one call made from the body of a machine state. "Plan" means: it turns a call the earlier passes already recorded (a `FlowCallFact`: statement index, call ordinal, target symbol) into a `CheckedUnitCallPlan` that names the target, every argument's storage source and path, the access each argument is passed with, and which linear claims move into the callee (calls.rs:1-14, 1934-2543). It does not compute borrow conflicts, ownership events or scalar values itself. Those arrive in `CheckFacts` (borrow facts, permission events, scalar computations, proof terms), and this file looks them up again by coordinate and refuses when the lookup does not give exactly one matching row. Every function returns `Option` or `Result<_, &'static str>`; `None` means "this call is not planned", and the only explanation is the last trace phase string set before the return (calls.rs:1953-1956). The file has 16 submodules: one narrow recogniser for building an affine array (calls.rs:16-172), the place-to-path walk (173-1500), a table of which storage may be presented as which parameter type (1502-1618), boundary-call admission (1619-1805), the call builder and target resolver (1806-2648), four argument planners split by where the argument's storage lives (2650-3571, 3834-4312, 4667-5907, 6278-7712), a planner for selector (dynamic) calls (3572-3833), a rule for forwarding a `&mut` parameter (4313-4666), signatures and entry claims (5991-6277), structural-result calls (7714-7920), boundary-requirement calls (7921-8460) and range (subslice) admission (8461-9357). There are no tests in the file. There is no call to the proof kernel anywhere in it.

## Mechanisms

- **Place-to-path walk** (`projected_argument_path`, calls.rs:911-1092). Input: a canonical place (root plus field/index/case/range segments). Output: the declared type, the storage type and a checked path. For each segment it asks `canonical_place_type_reference` for the type of the prefix, counts how many stored-reference layers that type has, and inserts that many `Referent` steps (calls.rs:947-971). Five thin wrappers choose which runtime selectors are allowed (calls.rs:634-649, 704-722, 752-820, 877-886). It serves every field, index, case and range argument.
- **Bounded reference walks.** Loops that peel reference layers use the number of type references in the program as their budget (calls.rs:671, 733-741) or run until no reference remains (calls.rs:933-939, 958-963, 3443-3448).
- **First-admitting-row tables.** `ordinary_parameter_path` classifies a path once (`ArgumentPathShape::of`, calls.rs:3972-4003) and then tries guarded rows in order (calls.rs:4031-4114). The header comment states the design: "Each call lane keeps one admission table whose first admitting row decides" (calls.rs:3837-3841).
- **Exhaustive event accounting.** Three places count the events they matched and require the count to equal the number of events found: shared temporaries (`covered == events.len()`, calls.rs:4889-4934), entry claims (calls.rs:6275) and claim transfers (calls.rs:7406-7410, 7710). This is how an event nobody claimed causes a refusal.
- **Rejoin by coordinate.** Facts from other passes are found again by (machine, state, statement index, call ordinal, target symbol) or by a role enum, and the code insists on exactly one hit (for example calls.rs:253-284, 7257-7269, 5354-5361). One helper does this lazily once per call (calls.rs:2752-2769).
- **Alias translation.** An argument place is replaced by another place in three steps: `receiver_aliases::resolve`, then `reborrow_restored_call_alias_target`, then the shared-cohort variant (calls.rs:6525-6559).
- **Carrier preservation scan.** For a forwarded `&mut` parameter, the code walks every statement before the call and every other call in the state, collects the places each writes (closing call writes over aliases), and refuses if any write names the whole parameter (calls.rs:4476-4553). It builds a fresh `StateMutationSummaryCache` per query (calls.rs:4512).
- **Generic instantiation comparison.** Builds a substitution from the callee's generic index symbols to the call's static arguments and compares normalized index identities pairwise (calls.rs:450-480).
- **Trace phases as refusal reasons.** `LocalConstructionTrace::phase` records a string before each check; a `None` return leaves the last phase as the explanation (calls.rs:1953-1956, 6408-6411).

There is no fixpoint, unification, interval analysis or budgeted search in this file.

## Identity by text

Most identity here is by symbol handle, expression handle, type identity id and (statement index, call ordinal) coordinates. The text cases are:

- Compiler intrinsics are recognised from the builtin's name string: `AsmGlobalDescriptorTableOperation::from_intrinsic_name(builtin.name())` (calls.rs:1985-1992) and `AsmRegisterOperation::from_intrinsic_name(builtin.name())` (2057-2064).
- Register carriers become primitive types by name: `PrimitiveType::from_name(carrier.name())` (calls.rs:2071, 2087).
- The forwarded `&mut` parameter rule compares the argument's single path member to the parameter's name as text: `members[0].as_str() != source.name.as_str()` (calls.rs:4417), beside the symbol comparisons at 4410 and 4415.
- Native callback parameters are matched to machine type parameters by binder name: `parameter.name == callback.binder` (calls.rs:8148, 8161).
- Case and payload-field identities carry the member name with the identity: `CheckedMemberIdentity::of_member(case.identity, case.name.clone())` (calls.rs:1051-1058).
- Binders travel as `&[(SymbolHandle, String)]` (calls.rs:39, 6028, 6100).
- Refusal reasons are `&'static str` values (calls.rs:1696-1712, 7329-7408) and trace phases; they explain, they do not decide.
- `display_path` and `type_identity_text` appear only in a debug print (calls.rs:5744-5757).

## Surprises

1. **The affine-array recogniser looks off by one.** It requires the array's literal length to equal `assignments.len() + 1` (calls.rs:48-51, 75) but checks assignments to indexes `0..assignments.len()` only (111-121). So a 3-element array matches with two element assignments, and a program that assigns all three does not match. I cannot see the caller, so I cannot tell whether it passes a shortened statement list. The bound 3..=26 has no stated reason. The whole function matches one exact statement sequence and one exact exit event.
2. **A rule shaped to one program.** `reborrow_restored_shared_cohort_observation_alias_target` applies only when the callee has two or three parameters, all shared references, an empty body, a Unit result, the call is call ordinal 0, and the certified mutation is the very next statement (calls.rs:7044-7061, 7109-7113). The comment calls it "the exact two- or three-child shared-freeze cohort" (7027).
3. **A magic depth.** `ordinary_parameter_path` accepts a path of one to three fixed indexes with no fields without requiring a checked-body callee or any caller/target access relation (calls.rs:4085-4089), and any path with no fixed indexes likewise (4097-4099). Only the reference-crossing rule and base identity equality follow (4206-4209).
4. **Comment contradicts code.** The comment on `runtime_indexed_path` says the selector is retained "only when the caller's published integer range proves it inside the enclosing fixed array's extent" (calls.rs:4277-4280). The code calls `projected_evaluated_path`, and the selector resolvers check no range (1205-1211 say so).
5. **Mutable authority is reconstructed here, not read from the borrow facts.** The borrow pass records a bare `&mut` parameter passed by name as a Read. This file then scans earlier statements and calls and, if none wrote the whole parameter, reports `MutableBorrow` (calls.rs:7285-7300, 4347-4461). This is a second borrow judgment living in the call planner.
6. **Two exhaustive-accounting checks are strict.** The shared-temporary validator and the claim-transfer join refuse when any event is unexplained (calls.rs:4934, 7406). That is a refusal by default, unlike most of the file.
7. **Hardware operations are planned inside the call planner.** Global-descriptor-table, register-access, descriptor-table and activation-storage operations are recognised first and return their own operation plans (calls.rs:1985-2109, 2272-2346, 2407-2458).
8. **Dead or redundant code.** `phase("stored reference argument: lent endpoint")` is overwritten by the next line (calls.rs:5187-5188). `if boundary { f(.., true) } else { f(.., false) }` equals `f(.., boundary)` (2224-2240). `loan.statement_index == statement_index` is tested twice (8812, 8823). The phase label "call operation: boundary argument parameter" is used for two different steps (8264, 8295).
9. **A merged comment.** One block comment above `fixed_index_within_extent` holds three unrelated descriptions; its first sentence ("The shared owner under the ordinary rule...") describes no function nearby (calls.rs:1302-1313).
10. **Debug printing left in the checker.** `eprintln!` under `struct_trace()` and `check_sites()` flags (calls.rs:5744-5758, 6898-6925).
11. **A string literal can satisfy a domain.** `byte_sequence_literal_argument` lets a literal meet a domain-constrained owned byte parameter when `string_literal_expression_grants_domain` agrees (calls.rs:1474-1487). That is a compile-time domain check on a literal, done in the argument planner.
12. **The refusal reason is whatever phase was set last.** A `None` from deep inside a helper is reported under the caller's most recent phase string, so one string can stand for many different failed checks (for example `borrowed_storage_argument`, calls.rs:3043-3244, takes no trace and has about a dozen refusal points, all reported under the phase its caller set at 6758 or 8280).

On the three properties: (1) holds throughout; the file never calls the proof kernel, and proof-term arguments are matched on type identity only (calls.rs:330-338). (2) is mostly absent here; identity is by handles and coordinates, with the text cases listed above. (3) holds strongly; see the repetition section.
