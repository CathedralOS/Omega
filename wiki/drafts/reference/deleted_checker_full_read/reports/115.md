## What this code is for

The file holds three modules. `float_projection_bindings` (7-1399) recognises when an operator declared in the core library has an `ensures` clause that states an IEEE float law in one fixed shape, for example "the float meaning of my result equals `convert(format, meaning(parameter))`", and it validates that the core library's float projection operators (`f32`/`f64` to `FloatMeaning`) and float semantic operations have exactly the signature the toolchain expects. `float_projection_invocations` (1401-1638) walks every proof fact in the program, finds calls to those projection operators and equalities between two projections, and either records them as validated or reports an error. `mathematical_applications` (1640-3771) is the source-side view of "mathematical" declarations: `core::Identity`, the fixed core names `Level`/`Type`/`Strict`/`Squash`, and user mathematical definitions, which have dependent formation rules and never run. It classifies generic binders as level, type or term, decides which expressions are erased (never executed), decides which machines count as "indexed logical machines" (machines whose body is a proof), and declares the tables (`Prepared*` rows) that an earlier elaboration stage filled with proof-kernel terms. Two sub-modules read those kernel terms back: `float_predicates` extracts `subject <op> float literal` facts and `scalar_predicates` rebuilds a checked Boolean expression over integers and floats from a kernel proposition. The rest is type-reference plumbing for mathematical calls: result type, argument types, substitution of generic arguments. The file contains no tests and makes no call to `verify_obligation`, `ProofNode` or a certificate; its only contact with `proof_admission` is reading `Term`, `TermArena`, `Declaration`, `Level` and `Sort` (1675-1678, 1789, 1800, 2710, 2856, 3130-3134, 3167).

## Mechanisms

- **Law scanner with both orientations** (236-276). `scan_conversion_equalities` walks every `ensures` expression fact of an operator, reads it through `float_law_subjects`, tries `(left, right)` and `(right, left)`, resolves the "converted" side as a call through a caller-supplied `resolve` closure, and hands a candidate to a caller-supplied `judge` closure. The first accepted candidate wins. It serves the float conversion contracts. No budget.
- **Input-only term check with a work budget** (537-594). `semantic_term_uses_only_inputs` recurses over an expression and admits literals, format constants, the operator's own parameters, projection calls and catalog calls. Each visit costs one unit of a 1024-unit budget (483, 659); running out returns `false`.
- **Closed evaluation of float meanings** (949-1116). `closed_meaning` evaluates a tree of projection and catalog calls over literals to an exact `FloatMeaning`, calling the numerics catalog's reference evaluator `kernel_discharge` at each catalog node (1050). Budget 1024 shared by both sides of a comparison (960). It serves `==`/`!=` on `FloatMeaning` in proof facts. The word "kernel" here is the float catalog's evaluator, not `proof_admission`.
- **Overload selection by operand kinds** (691-717). Filters call candidates to those whose parameter kinds equal the operand kinds; exactly one must remain.
- **Fixed-core vocabulary** (1694-1749). Resolves five symbols once; classifies by symbol, falling back to name spelling for `Level`, `Type`, `Strict`, `Squash` when the symbol handle is invalid.
- **Generic argument plan** (1991-2027). Zips binders with arguments, allowing all level binders to be omitted together.
- **Mathematical-only expression set** (2045-2108) and **definition roots worklist** (2110-2148). The worklist walks mathematical types (`Ordinary`, `Arrow`, `Application`) with a `visited` vector and collects expression arguments of type applications. Memoised per frozen program (`mathematical_expression_nodes`).
- **Erasure propagation** (2150-2315). One traversal carries an `erased` flag down from locals, parameter positions and fields; an expression seen in any runtime position is removed from the erased set at the end. Memoised (`erased_initializers`).
- **Greatest fixpoint for logical machines** (2329-2370). Starts from all machines with an exact theorem, repeatedly drops any whose body is not logical given the current candidate set, and stops when a pass drops nothing. `logical_body` (2436-2449) uses a stack; a machine already on the stack is taken to be logical. Memoised (`indexed_logical_machines`). Chain-following for erased evidence is bounded at 8 steps (2603).
- **Kernel term readers** (2746-2851, 3192-3305, 3123-3141). `application_spine` unwinds `Apply` nodes down to a `Constant` and returns the declaration index and arguments. `float_predicates::collect` and `scalar_predicates::predicate` recurse over `Squash`, `Sigma`, `Id` and spines, with de Bruijn variables resolved against a capture list that grows by one placeholder per `Sigma` binder. Depth limit 128 in both (2754, 3198). They serve refinement facts stated through mathematical propositions.
- **Prepared tables** (2863-3121). Arena-backed rows keyed by `ExpressionHandle`, `TypeReferenceHandle`, `TermHandle`, declaration index and `TypeIdentityId`. Every lookup is a linear `find_map` over the arena (3031-3073, 3113-3120).
- **Type substitution lookup** (3597-3673). Builds a substitution list from the generic argument plan, projects the type, and if projection changed nothing, computes a type identity under simultaneous substitution and searches every type reference row for one with that identity (3667-3672).

## Surprises

- **The proof kernel's terms are read back into checker facts.** `scalar_predicates::predicate` (3192-3305) decodes a `proof_admission::Term` into a `CheckedBooleanExpression`: `Sigma` is "and", `Sigma` over `Two` with a `CaseTwo` on variable 0 is "or" (3229-3245), `Id` over `Two` literals is a constant (3204-3214), `Id` over the integer carrier is integer equality (3215-3224). `float_predicates::collect` (2746-2851) does the same for float comparisons. The direction is kernel term to checker predicate, the reverse of handing an obligation to the kernel. For property 1 this cuts both ways: the kernel's representation is present and is the authority on what a proposition says, but this file never asks the kernel to verify anything.
- **`indexed_contract_is_proved` is a table lookup** (2372-2389). An `ensures` of a logical machine is reported proved because a row exists. The rows have `assumption_closure` and the table has `safety_assumptions`; this function reads neither.
- **Logical status can rest on unchecked machines.** Specialisation instances inherit it from their template without any check (2355-2362). A machine on the recursion stack is assumed logical (2442-2444). A callee reached through `logical_body` (2507, 2581, 2670) need not be a candidate, so it needs no theorem row; only its body shape is examined.
- **Logical machines forbid trapping arithmetic** (2673-2687): a cast or operator whose type is in the `Trapping` arithmetic domain disqualifies the body. Float literals, strings, zero values, atomics and indexing also disqualify (2648-2652, 2688). This is a purity analysis written as a syntactic allow-list, although the module comment says a mathematical definition is never "a purity claim" (1645).
- **The two kernel readers disagree on disjunction.** `float_predicates::collect` guards its `Sigma` arm with "domain is not `Two`" (2759-2760), so a disjunction falls to the spine arm, `application_spine` fails on a `Sigma`, and the whole extraction returns `None`. `scalar_predicates` reads the same shape as `Or`. A proposition containing any disjunction yields no float predicates at all.
- **A `Sigma` binder is given a placeholder capture**: `ExpressionHandle::default()` in the float reader (2764) and `None` in the scalar reader (3228). A subject that refers to the bound variable then fails (2784-2786, 2837-2839, 3316). In the "and" case the left conjunct is read under the old captures and the right under the extended ones (3247-3250), which matches a dependent pair.
- **Result-type lookup depends on what else the program mentions.** `applied_result_reference` ends by scanning every type reference row for one whose normalised identity equals the substituted identity (3667-3672) and returns `None` if the program contains no such row. `value_index_reference` does the same for a const literal generic argument: it searches all rows for a `ConstExpression` whose integer equals the literal (3693-3706). Whether a mathematical call has a result type can therefore depend on whether the instantiated type or the literal is written somewhere else in the program.
- **Format constant recognised by structural comparison with a decoded constant** (1153-1198). A struct literal of type `toolchain::FloatFormat` counts as `BINARY32` or `BINARY64` if its fields equal the evaluated value of that constant. To decode, the code builds `CanonicalConstValue::new("", encoding, "")` with empty strings (1187) only to reuse the decoder.
- **Four-way identity checks.** `is_exact_toolchain_float_data_type` (791-815) and `is_exact_toolchain_float_meaning_type` (1277-1303) each test the spelled name, the normalised identity string, the sealed source file, and the existence of a data definition with that symbol and name. The authors did not rely on any single one.
- **Panics on broken invariants inside a diagnostic walk**: `.expect("exact projection operation resolved its operator")` (1562) and `unreachable!` (1564), plus `unreachable!` at 467 and 1382.
- **Linear and quadratic lookups.** `walk_expression` uses a `Vec` for `visited` and for finding recorded projections (1503, 1513-1518). The prepared-table lookups are linear scans (3031-3073, 3113-3120) and the readers call them per expression. `expression_nodes` clones its memoised vector on every call (2057-2058).
- **Hard-coded namespace `"Float"`** for static call resolution (1480), while the projection table is consulted by `from_source_identity(namespace, name)` elsewhere (1445, 1461). Cannot tell from this slice whether every projection namespace is `Float`.
- **Type name typo**: `InitializerAccesss` (2155, 2259, 2265).
- **`closed_meaning` passes an empty parameter list** (1010) when resolving a catalog call, so closed evaluation works only for operands whose types can be found with no parameter in scope. That fits "closed" but is not stated.
- **A machine's signature is taken to be its first state's parameters** in `source_operations_have_same_meaning` (3744) and `erased_parameter` (2252).
- **Property 3 is weak here.** The file repeats per construct (contract kind, statement kind, float format) and has none of the per-placement copies (local, field, parameter, return and so on) that the sampling described.
