## What this code is for
The slice is the middle of the diff: the end of a native-application test, then many small edits across the product, package-compilation, review-evidence, provider-planning and build-time-evaluation crates, then the large deletions in Psi stage 03 (symbol-resolved trees to typed trees). The small edits mostly remove the old `CheckedTrees` type and the caches built on it (`RetainedCompilationChecks`, `retained_check`, `settled_checks`) and replace them with `FrozenTypedTrees` plus pointer-identity ownership checks, and they swap many judgments for the refusal text `no product route yet`. The large deletions are the old typing-stage calls into the `validation` crate: domain-cast accounting (`value as =Keep -Remove +Add`, 9800-10652), target-machine-family signature comparison (11037-11463), closed const-argument admission (11585-11773), contract-membership domain selection (10729-10892), source activation projection (10955-11033), and receiving-type queries for literals (9675-9792). In the products and review crates the deleted code derived "which dangerous services a program needs" and "which services a callable reaches" from the old facts (6578-6711, 8266-8353), and checked that a Build entry did not reach runtime boundary services (8003-8078). Some deleted code is documentation: `pipeline.md` (8806-9168) loses its description of the old checker route and gains a description of the lowered-form route. One deleted item is a seal check on proof evidence (7051-7127), moved into a new `EvidenceSealValidator`.

## Mechanisms
- Domain-cast accounting (10003-10610). Computes, for one run of cast entries on one operand, the set of domains the result carries and the intermediate type after each entry. It reads the operand's declared type, flattens its constraint layers (`flatten`, 9986-10006), collects carried domains plus ancestors (`carried`, 10242-10318), resolves each entry name to atoms (aliases expand to their constituents, indexed domains get an interned instance name, 10366-10396), checks each entry against the carried set, then walks entries keeping a running set where an added child removes the ancestors it implies and an ancestor is added only if no listed domain implies it (10561-10596). `spell` rebuilds a `Constrained` type and normalizes it (10620-10651). Runs are found by following `cast.value` back to the first entry and are settled inner run first by arena index (10899-10924). Serves domain casts (`NAMED-DOMAIN-CASTS`). No budget; ancestor walks `is_ancestor` loop until no parent (10026-10034).
- Target-family signature comparison (11044-11337). Renames each side's generic binders to shared fresh names (`$N{scope}G{position}`, `$C{position}`) and compares contract bytes and callable identities for equality, recursing for machine-typed parameters (`compatible_contracts` calls `compatible` which calls `compatible_contracts`, 11060-11172). Serves target-specific machine bodies. No recursion limit visible.
- Seal validation (7051-7127): finds the seal for (machine, obligation), checks `intact`, recomputes the operation's proof goal from Terminal Psi semantics and compares it to the seal. The new version delegates to `EvidenceSealValidator` built once per module (7039, 7064).
- Service-reach union (8272-8347): for each relevant machine unions published ceiling rows, transitive rows, unresolved installation upper bounds and invocation targets, then sorts by arena index and dedups (8345-8346). Serves package review of authority.
- Generic-origin equality (12029-12146, partly retained): `Equality` structure with an `active` pair stack (12085) to cut cycles; the deleted part lazily clones the whole typed program for replay (`replay.get_or_insert_with(|| (*base).clone())`, 12048).
- Closed const admission (11585-11737): for each generic application, loops over parameters and arguments, admits closed const expressions or canonical record/variant atoms, and replaces the argument node with a `Named` node carrying the canonical spelling (11758-11764).

## Surprises
- Large parts of what typing used to decide are now refusals, not replacements: `no product route yet` appears in at least 20 places in this slice (for example 7503, 7555, 7572, 8350, 9221, 9450, 10612, 11030, 11456). The deleted checks for domain casts, const-argument admission, target families and membership selection have no stated successor in this slice.
- The old stage-03 typing code called a separate `validation` crate for about a dozen judgments (assignment types, call parameters, closed const checks, dynamic call resolution). So "typing" was partly the old checker's front end.
- `required_dangerous_services` is replaced by `Err(..)` (6705-6711): every test fixture that needs a dangerous-service consent is now refused in discovery. This is a capability loss in test infrastructure, not only in the compiler.
- `with_checked_provider_selections` now errors on any non-empty selection list (8108-8113), `SelectedProviderSource::project_instances` errors unless the plan list is empty (7497-7504), and `semantic binding review` always errors (8348-8352). Package-handoff and review paths therefore work only for programs with no providers.
- `build_admission` no longer examines the transitive reach of the Build machine; it checks only direct `boundary_invocations` of each machine body in the module against emitted request rows (8058-8066). Transitive reach through calls is not visible in the replacement; whether the module is already flattened: cannot tell.
- Dead or retired code was kept alive until now: `lower_expression_handle_from_table` (10900-10908), a `ReplayTyped` lazy clone of the whole typed program (12029-12050), the `PackageReviewCrashRoute`/`PackageReviewTermination` records (8565-8602). The termination review record (`NoGuarantee` / `Terminates{premises}`) is deleted without a stated replacement in this slice.
- The old domain-cast code explicitly accounted for "silent removal" of domains; its replacement refuses every cast entry past the frontier (10215-10215, 10541-10614), so no domain cast with entries compiles.
- Decision details leaked into text: the old closed-const replacement turned a constant into a type-name node (11758-11764), so a value and a type name could not be told apart except by decoding atoms.
- The deleted seal check looked up `module.machines.iter().find(|c| c.id == machine)` and `blocks.iter().flat_map(operations).find(..)` linearly per seal (7088-7099); every seal costs a scan of the module. Moved into `EvidenceSealValidator`, whose cost is not visible.
- `CallingProgram::eq` before compared source owner, artifact, records and preparation (7718-7721); after, only artifact pointer identity (7722), while the field comment still says the evaluator is "omitted from catalog equality" (7714).
- The test for target-constant custody asserts the checker refuses a supplied candidate that differs from sealed declaration custody; this is one of the few places in the slice where a supplied (untrusted) program is compared with immutable custody (6775-6858).
