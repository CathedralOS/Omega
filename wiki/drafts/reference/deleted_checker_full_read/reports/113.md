## What this code is for
EI computes, over the typed program, four whole-program effect summaries by fixpoint: (1) which services/parameters each machine invokes synchronously (`infer_synchronous_invocations`, EI:334), (2) whether each machine, state and call may suspend or may block (`infer_operational_may`, EI:1179), (3) which services each machine, state and call can reach (`infer_service_reaches`, EI:2727), and (4) helper queries about declared ceilings and installation-bound reach. Calls through callback parameters, family members, static machine bindings and dynamic slots are resolved or kept as symbolic "parameter" dependencies that are later substituted. The results are plans handed to other checks; EI itself reports no diagnostics. EA decides, for each erased scalar lane of a call's erased record argument, where its actual value comes from (caller's erased formal, a proof-side expression, a field of a runtime record parameter, a field of a local) and emits the source-checking refusal when no source exists (EA:316-421). It is the single owner of that decision for both source checking and lowering (EA:1-11).

## Mechanisms
- Invocation fixpoint (EI:374-438): per machine, `transitive` and `realized` target sets; each round unions in family members' effective targets and, per call, the callee's effective targets with callee `Parameter(i)` substituted by the caller's argument origin (`substitute_target`, 980-988). Stops when no set changes. No iteration cap. Serves callback/service invocation tracking for boundary machines. Target sets are Vecs with linear `contains` dedupe (1000-1018).
- Callback worklist `callback_requirements::visit` (250-286): from a parameter list and invoked services, finds Nominal machine-parameter contracts whose trait is invoked and recurses into their signature's own parameters; `visited` is a Vec searched linearly (270).
- Operational fixpoint with context sensitivity (EI:2170-2364): contexts are (machine, selector vector); a call's captured callback arguments (`CapturedSelectorCalls`) pick implementation sets, interning new contexts on demand (1666-1695, 1854-1863); each round recomputes body and summary per context; two phases: first to fixpoint without `checked_dependencies`, then record which roots have symbolic parameter dependencies (2284-2295) and iterate again. Dependencies are `ContractDependencyWork<bool>` (concrete bool plus set of parameter symbols) so `A(F) = F OR A(F)` stays symbolic (comment 2181-2184). Substitution of static machine bindings is recursive (2066-2168). No iteration cap. Serves callbacks (`machine` type parameters) and suspend/block checking.
- Service-reach fixpoint (EI:2812-2922): per machine and per selected-call context, sets of ServiceReachId (sorted Vec dedup, 3685-3689), concrete vs installation-bound split, symbolic dependency (concrete + parameters) substituted through static bindings (3403-3448), cleanup contribution; stops when seven tracked fields are unchanged. No iteration cap. Serves service-reach ceilings.
- Erased-leaf resolution walk (EA:78-291): loop bounded by `expression_count()+1`; follows shared borrows, immutable reference locals initialized by a shared borrow, and constant-initialized locals until it reaches a closed construction, a formal, or an observable place. One walk serves primitive lanes and record leaves (EA:57-76). Serves erased record arguments.
- Interning: HashMap for selector contexts and machine positions (EI:1615, 1621); binary search over sorted (arena_index, generation) rows (1521-1530).

## Surprises
- EI produces no diagnostics. Comparison of inferred effects with declared ceilings happens elsewhere (not in this slice). Only EA:316-421 emits errors.
- Name-based matching survives in invocation analysis: EI:939-942 uses `||` between symbol equality and name equality, so a same-named parameter with a different symbol counts as the entry parameter. EI:759-782 resolves receivers and fields by authored name strings.
- Hash maps keyed by symbols/selector vectors (EI:1102, 1615, 1621) coexist with sorted Vecs and linear scans inside fixpoint loops (EI:269-270, 1002, 2085-2089, 2353-2355, 3429-3431).
- All three fixpoints (invocation 374, operational 2185, service reach 2812) loop until no change with no iteration bound. `propagate_operational_may` overwrites `summary` each round (2239-2278) rather than unioning, so termination depends on the computation being monotone; there is no explicit guard.
- After the operational fixpoint, `export_selected_call_contexts` (1889-1965) re-resolves every call and can intern new contexts while looping over `contexts.len()` (1898-1926); the final pass at 2305-2362 resolves every call a second time with `call_envelope`.
- EI:2422-2431: for compiler-synthesized acknowledgements the compiler writes `acknowledges_suspend/block` itself from the inferred result, so those cannot disagree by construction; the acknowledgement check only has bite for authored acknowledgements.
- EI:3714-3721 only bodyless `ExternalRealization` machines get governing ceilings; EI:3759-3761 family members exist only for bodyless machines.
- `call_sites` treats transitions (`transition.target`, `transition.continuation`) as call sites (EI:108-129); named-transfer receivers come from `path.head_symbol` plus members minus last (EI:659-676).
- EI has a second, reduced copy of call-target resolution in `invocations::push_call` (811-867) and `operational::push_call` (1423-1476), with different keys (operational stores `target_machine_symbol` from `machine_holding_state` of the first state; invocations from `state_to_machine_index`).
- EA:214 treats a local as initialized when its declaration ordinal is before the call statement's index (statement-list order), not by control flow. Cannot tell whether nested blocks are flattened into that ordinal.
- EA:120 and 297 bound their loops by expression count as a cycle guard rather than proving acyclicity; exhausting the loop gives a generic refusal at EA:290 and `false` at EA:305.
- EA:141-155 resolves a constant through `authored_initializer` or `materialized_initializer`, reading the initializer expression rather than an evaluated value.
- EA's `ErasedLeaf::ParameterField`/`LocalField` carry `facts::PlaceSegment` paths (EA:28-35), so unlike EI it identifies places by symbol segments, not text; the only strings are diagnostic reasons.
