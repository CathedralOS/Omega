## What this code is for

`CEV` answers one question for the old checker's published crash predicates: does this caller expression, read before statement N of a state, still hold a value that can be named in terms of the machine's invocation-entry parameters? A crash predicate is an expression tree (`CrashPredicateExpression`) over `Parameter(ordinal)`, member names, literal indices and builtin operators; when a callee's crash guard is carried to a call site, each formal is replaced by the caller's "entry operand". The file walks backwards from the read: through immutable and mutable local initializers, through state parameters, and through every named transition edge that arrives in the state, and it scans the statements in between for writes, exclusive borrows and mutating calls. It never emits a diagnostic; its answer is `Some(expression)`/`true` or `None`/`false`, and `None` means "provenance unknown".

`shared.rs` is five helper modules. `authored_selections` (9-3449, 70% of the file) finishes the ledger of "authored declaration selections": for every place the source text selected a declaration (a call, a member, an operator token, a path segment, a struct literal, a domain membership), it records which declaration or compiler intrinsic the checked program actually used, and it refuses the program if any such selection is still unresolved. The same module validates the Build binding protocol (`build_selections`). `call_formals` (3450-3474) aligns a selector call's operands with formals. `collections` (3475-3602) holds first-occurrence-order rosters. `machine_waves` (3603-3839) computes strongly connected components of the machine call graph and runs a per-component step in parallel waves. `operators` (3840-4868) rebuilds and cross-checks boundary operator applications, lists the checked machine bodies that could satisfy each one, and publishes a provider-requirement inventory.

Neither file calls the proof kernel. Neither file decides a `requires`/`ensures` obligation directly; `CEV` supplies names for predicates that other files judge, and `shared.rs` decides declaration identity and protocol shape.

## Mechanisms

- **Backward provenance fold with a depth bound** (CEV:1742-2116, 2260-2402). It computes an expression over entry parameters for a read. It recurses: expression → name → local initializer at the declaration's statement index, or state parameter → every incoming named transition edge, resolved in the source state at the edge's statement index. All arrivals must produce structurally equal expressions. Limit: depth 64 (CEV:1324); there is no memo table and no visited set, so a cycle is cut only by the depth counter. Serves crash predicates published for calls and operators.
- **Syntactic write scan with a path-disjointness algebra** (CEV:716-1315). For a binding symbol and a read path of `Field`/`Case`/`FixedIndex`/`FixedRange`/`Opaque` segments, it scans a statement window and answers whether any statement may overwrite or exclusively lend the path. Indexes are folded with `constant_integer_value` (CEV:806-824). Explicitly "deliberately syntactic and conservative" (CEV:724-727). No budget; cost is window length times expression size.
- **Point-specific scalar evaluation of an index** (CEV:60-166). It lowers the index to a scalar plan and evaluates it against the flow-fact contexts recorded at the entry of the index's own statement, to obtain one `usize`.
- **Literal projection through constructors** (CEV:232-363). It follows `x[i]`/`x.f` back into the array or record literal that initialized `x`, hop by hop, each hop moving the statement index back to the declaration.
- **Substitution over crash predicate expressions** (CEV:2412-2546). One structural walk; a `Member` spine above a `Parameter` is passed to the resolver as a list of member-name strings so the resolver can ask about one field only.
- **Fallback cascades for "which declaration did this select"** (shared.rs:359-465 for calls, seven sources; 1653-1698 for members, six sources; 2217-2336 for operators, seven sources). Each source is tried in order; most refuse on disagreement between candidates; the result feeds the selection ledger.
- **Parallel per-expression finalization** (shared.rs:1022-1299). Rayon over all expression rows, chunks of at least 256, one closure per occurrence, stop at the first refusal within one expression; results are merged in row order so output order is deterministic.
- **Generic-operator origin index** (shared.rs:2113-2143). One walk per checked value fact whose origin machine has conformance bounds, recording which facts contain each expression; built lazily once (`OnceLock`, shared.rs:1023-1024). Authors note the earlier form was quadratic (shared.rs:2107-2111).
- **Authored operand carrier inference** (shared.rs:2503-2641). Derives an operand's type from declarations, casts, literals, or the carrier that all candidate operators return; used to select operators in contract expressions that have no operator-use fact.
- **Machine call components and waves** (shared.rs:3629-3798). Iterative Tarjan SCC over a caller-supplied read graph; components are levelled so callees come first (or callers first); each wave runs its components in parallel and writes results back by roster position. Serves whole-program summaries (termination, mutation, crash, reach per the comment at shared.rs:3607-3608).
- **Rejoin by re-derivation** (shared.rs:4293-4526). A boundary operator application validated earlier is rebuilt from the operand types of the checked use and compared for equality; any difference is a refusal.
- **Boundary body candidate listing** (shared.rs:4604-4799). For each distinct (requirement, arguments) demand, list every non-generic checked-body machine whose declaration or specialization realizes it, with its contract commitment bytes.
- **First-occurrence rosters** (shared.rs:3500-3557). `push_unique` linear scan; `UniqueRoster` buckets by hash and confirms by equality.

## Identity by text

CEV:
- Crash predicate members are strings: `CrashPredicateExpression::Member { member: String }` built from `field_entry_name`/`member_entry_name` (CEV:419-424, 1525, 1862, 1876).
- Integer indexes and literals are decimal strings (CEV:457, 1796); floats are their source text (CEV:1799). An index string is parsed back to a number at CEV:536.
- `entry_parameter_place_at_write_boundary` recovers which field a member string means by rendering every field of the owner type with `field_entry_name` and comparing strings (CEV:572-595). The place it started from already held field symbols (CEV:413-424).
- An unresolved member is treated as the builtin length read when its spelling parses as the length measure (CEV:1651-1654). The receiver's type is not examined there.
- `formal_member_projection` resolves `members: &[String]` by `field.name.as_str() == member.as_str()` (CEV:1701-1706).
- The substitution resolver receives the member spine as `&[String]` (CEV:2436, 2441-2451); `Name(_)` and a call's `target` are carried as text (CEV:2464, 2534).
- Against the pattern: parameters are ordinals (CEV:2299-2301); the write scan compares `SymbolHandle`s for fields, cases and roots (CEV:761-773, 841-887, 954-956).

## Surprises

1. **`receiver_call_writes` always answers yes** (CEV:1262-1273). It runs `parameters.iter().find(|_parameter| false)`, which never finds anything, then `.is_none_or(|parameter| parameter.is_mutable)`, which is therefore always true. The comment says the callee writes "when the callee's `self` parameter is mutable". The code never inspects a self parameter, so every receiver call on a tracked binding ends its provenance, including calls on read-only receivers. The `is_mutable` test is dead.
2. **Leftovers of a removed self-parameter rule.** A comment about binding `self` to the `is_self` parameter stands alone with no code (CEV:2118-2124); `argument_index = parameters[..parameter_ordinal].len()` is just `parameter_ordinal` (CEV:2297); `_before_statement` is unused (CEV:2266).
3. **The "twins" disagree on indexing.** `entry_operand_projected_at` refuses an index step without builtin index meaning (CEV:1533-1535). `operand_entry_provenance`, the boolean version of the same walk, has no such test on its fall-through path (CEV:1424-1437): an authored (non-builtin) index whose index expression has an entry value passes the boolean check and fails the expression check. The comment at CEV:2043-2045 says such rules are kept in one place so they "cannot drift apart".
4. **A place is turned into text and parsed back.** `entry_parameter_place_at_write_boundary` starts from a canonical place with field symbols, renders it as an expression with member-name strings and decimal index strings (CEV:404-460), then re-derives the fields by string comparison against every field of the type and by `parse()` (CEV:523-596), then checks the result against a third derivation (CEV:619-624). It guards against two fields rendering alike (CEV:589-591).
5. **Only same-state forwarding is recognized as a no-op.** A parameter passed unchanged around a two-state loop (A to B to A) is not skipped (CEV:2308-2332 tests `source_symbol == state_symbol`); the recursion runs until depth 64 and returns no provenance. There is no memo or visited set, so with several incoming edges per state the successful case re-resolves shared upstream arrivals once per path.
6. **Assembly statements are invisible to the write scan** (CEV:1014) while assembly fact statements are scanned (CEV:1036-1042).
7. **Segment identity by counting.** `late_binding_ordinal` picks which path segment or struct field an occurrence refers to by counting earlier occurrences on the same expression that are still late-bound with the same binding kind (shared.rs:1453-1469). If an earlier segment or field had been resolved before this stage, the count would shift and the occurrence would be finalized against a different segment (index 0 means the path root at shared.rs:513-515). Nothing in this slice shows whether mixed resolved/late-bound segments can occur.
8. **Two files in this slice contradict each other on same-named payload fields.** CEV:1627-1630 says identity must never come "from the first same-named field"; shared.rs:1824-1832 returns the first payload field with the given name from any variant. In `checked_member_target` that lookup is the fourth, fifth and sixth fallback (shared.rs:1689-1691).
9. **The selection ledger is a second verdict issued after checking.** The refusal text says "remained unresolved after successful checking" (shared.rs:1442). A program the checker accepted can still be refused here because none of the reconstruction cascades could say which declaration an operator token, member or call selected. The cascades exist because contract and static-type expressions "can lack executable operator-use facts" (shared.rs:13, 629).
10. **"Builtin" is the default answer for operators.** Of the seven steps in `checked_operator_target`, five can end in `BuiltinOperator` (shared.rs:2224-2241, 2258-2272, 2285-2289, 2296-2329, 2330-2335), the last on the sole ground that no declared operator with that spelling is visible.
11. **"Proof-backed" without a proof.** The `operators` module header says it "retains proof-backed applications" (shared.rs:3845). The code checks applications by rebuilding them and comparing for equality, and identifies a candidate body by a non-zero contract commitment (shared.rs:4765-4767). No proof kernel call exists in either file.
12. **Hash maps in a codebase that forbids them for dense IDs.** `GenericOperatorValueOrigins` keys a `HashMap` by expression handle with a comment defending it (shared.rs:2040-2041, 2114); `UniqueRoster` uses `HashMap<u64, Vec<usize>>` (shared.rs:3523).
13. **Dead code kept deliberately**: `run_caller_first` and the caller-first wave table are computed for every instance and used only by the test (shared.rs:3662-3677, 3699-3706, 3832).
14. **`expression_is_contextual_statement_primitive` takes `_facts` and ignores it** (shared.rs:1862).
15. **Evidence on the three sampled properties.** (1) Supported: every decision in the slice is own judgment or a call into `validation`/`typed_trees`; no kernel call; CEV:31 disclaims certificate status. (2) Mixed: the write scan and place paths use symbols, but crash predicate members, indexes, Build operations, prelude types, `Equatable`/`equals` and several member lookups are strings. (3) Supported: statement call versus expression call is written out separately at least six times in shared.rs and twice in CEV, and the place walk is written six times in CEV.
