## What this code is for

This slice is five files of the `checked-trees` crate: the data the old checker (stage "Psi 05") wrote down after judging a program, kept beside the frozen source trees in one `CheckedTrees` value (LIB:1-26, LIB:688-692). Later stages ("Psi 06", "Psi 08", a "checked-interpreter", native realization) read these records "without re-running borrow, proof, or termination analysis" (LIB:8-12). Most of the slice is record and enum declarations with accessors; the checking that fills them lives in other crates. `flow_terminal_units.rs` describes how a Unit-returning or multi-state machine body is to be lowered: its states, terminators, calls, local bindings, cleanup steps and "gaps" (constructs the compiler could not lower). `operators_and_proof.rs` holds the result of operator resolution (which operator a `+` or `==` selected, candidates, status) and the proof bookkeeping: contract facts, evidence terms, outcome-specific guarantees, float "meaning" projections, a fixed lemma list, mathematical declarations with kernel terms, obligations and proposition vocabulary. `providers_and_trust.rs` rebuilds, from typed trees plus check facts, the provider declarations and instances used when a boundary requirement ("Import") is satisfied by a selected provider. `termination_and_cleanup_facts.rs` holds contextual cleanup dispositions (which storage is disposed at which exit) and the ranking tables behind `terminates by`. `lib.rs` is the crate root: re-exports, a keyed row cache, arena concatenation helpers, callback registration classification, and a source-scanning test that forbids string identity fields. The rules this slice enforces itself are mostly shape checks on these records (constructors that return `None`, validators, "exactly one row" lookups), not language judgments.

## Mechanisms

- **Reachability over states** (FTU:641-660). Breadth-first walk from state 0 over each terminator's successors; returns a per-state live flag, or `None` when a successor cannot be positioned. Serves multi-state machine lowering.
- **Gap chain** (FTU:1627-1640). From a machine's gap row, follows `Callee`/`BoundaryTarget` reasons to the gap of the target until no further gap exists or a machine repeats (`chain.contains`). Produces the "A calls B, which calls C; C has no executable body" message. No budget other than the cycle guard.
- **Explicit-stack tree walks** over nested completion selections and value calls: `invocation_scopes` (FTU:784-799), `with_value_calls` (FTU:2432-2448), `discardable_structural_result_by_ordinal_mut` (recursive, FTU:2388-2430).
- **Keyed row cache** (`KeyedRows`, LIB:242-366). Groups arena rows by a key function. On each read it compares the arena's revision and append epoch; if the arena only grew, it groups just the new rows, otherwise rebuilds. Used for call, exit, outcome-arm, proof-output and cleanup-state lookups (OP:2498-2510, TC:42).
- **Expression use index** (OP:956-998). Sorts operator uses by expression handle, chunks equal handles, records the first use with `Expression` occurrence and the full list. Rebuilt when `uses.revision()` changes (OP:1176-1209).
- **Arena concatenation by handle shift** (LIB:425-465, TC:47-189). When both arenas are append-only with the same fresh generation, rows from one are appended to the other and every handle into those arenas is shifted by the receiving arena's prior length.
- **Origin chase** (LIB:744-766). Follows `NestedExpression { parent }` links to a terminal origin, with a visited list as cycle guard and a requirement that all values of a parent agree.
- **Lane position counting** (OP:2589-2606). Walks the authored contracts of one kind in order and counts facts in contracts that have a binding name; this count is the expected position of the evidence term.
- **Stored results of analyses run elsewhere**: `ExactIntegerCastFact { minimum, maximum }` (OP:915-922) and `CheckedIntegerAssignmentDecision { minimum, maximum }` (OP:2296-2307) hold big-integer bounds. `CheckedRankArrivalEdge { non_increasing, strictly_decreases }` (TC:594-602) and `CheckedRuntimeRankEdge { strict }` (TC:707-713) hold ranking verdicts. This slice only stores them.

## Accepts or skips without proof

- `has_normal_continuation` for a terminator ends in `_ => true` (FTU:413), covering `ReturnUnit`, `ReturnScalar`, `ReturnStructural`. Reasonable by meaning; no other check visible here.
- `CheckedUnitEffectOperationPlan::has_normal_continuation` is `_ => true` for every operation except `Call` and `EvaluateStructuralValue` (FTU:2164-2170). An `EstablishLocal(StructuralValue { calls })` whose inner call is `Stopped` or never returns still reports `true`; `CheckedStructuralValueCall::has_normal_continuation` exists (FTU:2059-2067) but is not consulted. Cannot tell from this slice whether the producer always uses `EvaluateStructuralValue` for that case.
- `CheckedValueInvocationOutcome::Absent => true` (FTU:2065); `Absent` is the `Default` (FTU:2001-2009).
- `statement_ordinal().unwrap_or(0)` for a fallback or case with no ordinal (FTU:1012, FTU:1045): a missing ordinal becomes statement 0. Cannot tell if a later check catches it.
- `declaration_requirements` indexes with no bounds check; the comment says "lowering consumes the plan without re-checking it, so the index always resolves" (FTU:63-78).
- `admits_signature` ignores which plan kind it was called on (FTU:2643-2649).
- `resolved_through_builtin_fallback` accepts status `Missing` as well as `BuiltinFallback` (OP:481-485). `Missing` is the default status (OP:444-445) and is also counted as an issue by `resolution_issues` (OP:1334). Cannot tell which consumer wins.
- `resolved_contract_uses` drops any resolved use that has more than one candidate (OP:1382-1384) even though `selected_candidate` could find the chosen one. Its contracts are then not offered to whoever iterates this list. Cannot tell if another path applies them.
- `boundary_application_operands` leaves an operand's primitive type `None` when neither the declared type nor a unique binder closing resolves (OP:116-134) and still returns the operands.
- `contract_call_at` returns the last row when several rows share a call site (OP:2659); the stricter `unique_contract_call_at` exists beside it (OP:2664-2685).
- `callback_declaration`: a missing trait definition yields `satisfaction_is_boundary = false` (LIB:48-51).
- `callback_registration_declaration` falls back to `CheckedSource` when the operation is a machine parameter signature or the requirement trait is non-boundary (LIB:80-85).
- `provider_external_applications` returns `Ok(Vec::new())` when the requirement has no trait machine signature (PT:274-276) and when a native binding is already closed (PT:372-374).
- `provider_declarations`: with `installation_reach` false, reach is `Ok(None)` with no check (PT:56-60).

## Surprises

- **Evidence on property 1 is mixed, and the split is clean.** Contract and obligation records carry no proof object: `ProofObligationFact` is a kind, two symbols and an owner (OP:2254-2260); `ContractProofFact` is a handle to the authored source fact plus an optional evidence term that is a name, a lane position and a proposition with string arguments (OP:1456-1465, 1548-1557). Termination verdicts are booleans: `local_terminates`, `entry_rank_formed` (TC:618-619), `non_increasing`, `strictly_decreases` (TC:600-601), `strict` (TC:712); `fact_is_truth: bool` (OP:1482); "trap free" is a list of expression handles (OP:942). Against the property: the `mathematical` module stores kernel data from `proof_admission` (`TermArena`, `Declaration`, `TermHandle`) for mathematical declarations, source evidence carriers, indexed theorems (`term`, `ty`, `assumption_closure`) and identity formations (OP:2106, 2161-2222), and `ProofFacts` tracks `mathematical_safety_assumptions: Vec<u32>` (OP:2495). Nothing in this slice calls the kernel; it only stores the terms.
- **Module calls with Unit result must have no contract commitment** while every other Module result kind must have one (FTU:1213-1220, 1261-1284). So a contract commitment cannot be attached to a call of a Unit-returning module machine in this representation.
- **`Missing` is treated as a successful built-in fallback** (OP:477-486). A default-constructed use (status `Missing`, zero candidates, spelling `Index`; OP:678-693) satisfies `resolved_through_builtin_fallback(Index)`.
- **`resolved_contract_uses` uses "exactly one candidate" instead of "the selected candidate"** (OP:1378-1390). A resolved operator chosen among several candidates has its contracts skipped by this iterator.
- **`contract_call_at` silently picks the last duplicate** (OP:2659).
- **The string-identity guard can be evaded by type shape or field name.** `captured_argument_identities: Option<Vec<Option<String>>>` (OP:1506) is a list of string identities and does not match `identities: Vec<String>`. `requirement_identity: &'identity str` (PT:34-35) is not a `String`. Fields named `name`, `arguments`, `evidence_type`, `diagnostic_label`, `source_carrier`, `term_spelling` hold identity-bearing text without the word "identity". `diagnostic_label` is assigned from a field named `identity` (OP:2417).
- **Dead condition**: `provider_external_applications` returns early when `native_closed.is_some()` (PT:372-374), so the later filter `native_closed.is_none_or(...)` (PT:380-381) is always true.
- **`Debug` for `CheckedOperatorFacts` omits `boundary_body_candidates` and `boundary_declarations`** (OP:1000-1028), so debug dumps hide two tables.
- **The lemma vocabulary is a fixed list of five named lemmas keyed by a collection symbol**: `IndexInBounds`, `NonEmptyHasFirst`, `WindowLength`, `WindowSubrange`, `TailLengthDecreases`; quantified ranges have bounds `Zero | Literal(i64) | Length` (OP:2058-2088). These types do not derive the storage `Record` that every other fact type here derives, and `ProofFacts` (OP:2461-2511) has no field for `LemmaFacts`. Cannot tell from this slice whether anything stores them.
- **"Transitional" and "fallback" in float projections**: every `Direct*` source carries a `fallback: CheckedFloatProjectionInput`, and a `TransitionalInput` variant exists (OP:1809-1869). The names read as a migration left half done.
- **Hardware rules live in the plan constructor**: x86 descriptor-table limits (2..=8192 and 1..=8192 entries, U8/U16 results, fixed argument counts) are checked in `CheckedUnitCallPlan::new` (FTU:1192-1210). The operation set also includes register access, global descriptor table, atomic access and fence, and activation storage establish/borrow/release/split/merge (FTU:1752-1773, 1221-1260).
- **"Gaps" are a first-class output of checking** (FTU:1530, 1541-1557, 1621-1705). A machine the compiler could not lower gets a gap row; the diagnostic is `Diagnostic::incomplete` with a coverage form (declaration, signature, state, statement, call, expression, transition), not an error, except for an unselected opaque representation. This is a compiler-coverage refusal, separate from a language rule.
- **Checked plans point back into source trees.** `CheckedStateContractRequirement` has `SourceExpression(ExpressionHandle)` and `SourceFact(Handle<ProofFact>)` variants beside `Closed` (FTU:232-237); `IncreasingTo { upper: ExpressionHandle }` (FTU:226-229); `CheckedTrees` derefs to `TypedTrees` (LIB:779-785). Consumers of the checked form can and must read source nodes.
- **Per-placement vocabulary is baked into the obligation kind names** (OP:2243-2252, 2263-2294): the record type itself says assignment, call argument, initializer, state return, value, transition argument.
- **`CheckedUnitPlan::admits_signature` takes `self` and ignores it** (FTU:2643-2649).
- **`EvaluateStructuralValue` never continues normally** (FTU:2166): it exists only to represent a value evaluation that stops, yet shares `calls`/`operand_source` with the normal `StructuralValue` binding.
- **`integer_assignment_at` returns an invalid handle instead of `Option`** (OP:2753-2776); callers must test validity.
- **Default cleanup entry requirement is unsatisfiable** (`consequence: Constant(false)`, `antecedent: Constant(true)`; TC:363-374), so a default row refuses.
- **Consumers named in the crate header include a `checked-interpreter`** (LIB:17): an interpreter ran directly on this checked form.
