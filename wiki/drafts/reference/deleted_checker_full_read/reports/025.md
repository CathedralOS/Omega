## What this code is for

This file is one module (`checks::borrows::resources`) of the old source checker. Earlier checker stages had already produced two ledgers: a borrow ledger (`BorrowFacts`: loans, call records, argument accesses, incoming references) and a flow ledger (`FlowFacts`: operands, calls, constraints, and an activation and a weakening event for each loan). This file joins those ledgers into "resource rows" that the file header says are "consumed by execution planning and Psi 06" (cbr.rs:1-8), meaning the later lowering stage reads them to know when a borrowed place is suspended and when it is restored.

The single entry point is `initialize_checked_direct_borrow_resources` (cbr.rs:7134-7172). It runs these steps in a fixed order: validate supplied-output completions, build call-operand loan resources, build supplied-output resources, build stored-call-input rows, validate view formations, plan descriptor-holder lifetimes, rebuild the direct-loan and reborrow rosters, resolve each reborrow's parent, replay the lifecycle to produce "disposition events", bind a "restored call" to some events, and install the arenas.

The vocabulary the code uses: a *loan* is one borrow. Its *lineage* is `DirectRoot`, `Reborrow { parent_loan }`, `SuppliedOutput` (a reference a called helper wrote into an output), `UnretainedDerived` (a copy that forwards another loan's permission) or `LifetimeDependency` (a debt that keeps a helper's inputs borrowed while its output lives). A *descriptor* is a stored reference value. A *weakening* is the event that ends a loan (last use, local reassigned, state exit). A *disposition* says what happens to the parent when a child reborrow ends.

Most of the bulk (cbr.rs:3244-5028 and 5240-5793) is a search: given one evaluated reference operand, find which loan or call-argument access gave it permission, following copies, stores, match joins, helper results and helper outputs backwards. The rest is bookkeeping that turns the result into arena rows.

The code enforces real language rules (a reborrow may not gain access its parent lacks; a view made from a saved reference must keep every parent borrow; a saved reference must have been captured before its supplier retired). Most of its diagnostics, though, are internal-consistency refusals that say a ledger "drifted" or "lost" something.

## Mechanisms

**Supplier search (`permission_sources::collect`, cbr.rs:3638-4083).** Given an evaluated operand and a projection path, it computes the list of permission suppliers (a stored loan, or a call-argument access with its parent loans) and each one's backing place. It is recursive, with an `active` stack of `(operand, projection)` pairs for cycle refusal (3704-3715). It tries fourteen arms in a fixed `if / else if` order: completed invocation result, completed output, a refusal when the frozen selection is unavailable, loan formed at this expression, match/if alternatives, entry (parameter) invocation access, bare range, completed formations (storage predecessors), descriptor captures, frozen endpoint, retained suppliers, retained reborrow sources, binding observation, plain invocation access. Most arms return `Option<bool>` where `None` means "not my case". There is no budget; the only bound is the cycle check. Failure details are kept in a fixed stack buffer of 4 steps with 8 path segments each (3272-3321). It serves saved references, views of saved references, helper results and helper outputs.

**Backing resolution (`retained_backing::retained_places`, cbr.rs:5262-5412).** A worklist from a captured place to the original storage. It stops at an incoming reference. If the root is a call expression, it expands through the callee's return origins (`returned_places`, 5465-5606, guarded by an `active_calls` stack at 5300). Otherwise it crosses every live loan whose stored descriptor sits on the path (`store_destination_places`, 5327-5360), refusing if a loan is crossed twice (5349). Otherwise it crosses parameter references (5362-5399). Otherwise it accepts a terminal place if `terminal_storage_is_resolved`. It accumulates the crossed loans as lineage. `projected_operand_places` (5614-5792) walks an origin path segment by segment and calls `retained_places` at each `Referent` crossing.

**Lifecycle replay (`plan_reborrow_disposition_events`, cbr.rs:423-582).** For each state it creates Activate, Weaken and CompleteOutput events for every direct, reborrow and supplied resource, sorts them by `(statement_index, phase, loan arena index)` (546), groups equal boundaries into batches, and runs a four-state machine per resource (`Available`, `BorrowedBy`, `RetiredWhileBorrowed`, `Retired`; 2491-2502). Each child reborrow that ends produces one disposition event by walking up the parent chain (590-736), with one of seven dispositions: `BranchRelease`, `SharedRelease`, `Reactivate`, `RestoreSharedCohort`, `CascadeThroughRetiredParent`, `StateExitDirectRootHandoff`, `SameBoundaryLineageClosure`. No budget. It serves suspension and restoration of a parent borrow around its reborrows.

**Holder closure (`forwarded_lifetimes::plan`, cbr.rs:1812-2006).** It builds a table indexed by loan arena index that lists which loans hold a copy of each loan's permission (from transport suppliers, stored call inputs and supplied-output inputs). For each root loan it then does a breadth-first closure over holders and takes the latest weakening as the resource's real end (`final_weakening`), keeping the loan's own `lexical_weakening` separately. `closure_end` (2092-2149) is the depth-first variant with cycle refusal. It serves the rule that "replacing a reference slot must not end access held by an earlier copy" (1780-1784).

**Debt transfer fixpoint (`debts::install_transfers`, cbr.rs:6269-6352).** It repeats over pending `LifetimeDependency` loans, installing a transfer debt once all of a loan's suppliers have debts, until a pass makes no progress. Loans still pending at the end are left without a row and no error is raised (6346-6351).

**Debt window resolution (`resolve_windows`, cbr.rs:6476-6616).** A two-queue worklist over input permissions and loans, with seen-lists, that collects every held input place and its access. `validate_debt_sources` (6618-6667) is a depth-first walk for cycles across debt generations.

**Returned-projection frontier (`returned_projections::validate`, cbr.rs:1170-1327).** A depth-first walk over retention-profile alternatives with `active` and `completed` lists, refusing cycles.

**Roster reconstruction (`reconstruct_borrow_resource_rosters`, cbr.rs:2905-3227).** One pass over state-owned loans; the lineage selects a direct resource or a reborrow draft.

All sets are `Vec` with linear `contains`. Tables keyed by loan use the arena index into a `Vec` (1839-1845, 1990-1993, 2277).

## Identity by text

No decision in this slice compares strings. A search for `== "`, `!= "`, `starts_with("` and `contains("` finds nothing. Values, places, loans, calls and types are identified by arena handles, symbol handles, expression handles and `PlaceSegment` lists.

Text appears only in output:

- Symbol and type names rendered into diagnostics: `program.symbols.name` (cbr.rs:1315-1321), `machine.name` and `source_state.name` (2984, 3054), `display_path(.., "::")` and `normalized_type_identity_text` truncated to 128 and 256 characters (3358-3384), `published::labels::call_target_label` and `symbol_name` (5988-5993).
- String labels used only for tracing: `frozen_kind` ("not-frozen", "endpoint", "through-reference", "unavailable"; 3736-3741), `selection_kind` (4342-4347), `kind` ("binding", "contents"; 4461-4464).
- The `rule` variable (3742-4034) is a `&'static str` naming which strategy failed. It is recorded in the failure buffer and never branched on.
- Refusal reasons travel as `&'static str` (signatures at 2317, 4091, 5855, 6389, 6725); callers treat any `Err` alike.

Identity by *position* is pervasive and is the nearest thing to text identity here:

- A call is found by `(statement_index, call_ordinal)` or by `(authored_expression, statement_index)` (cbr.rs:2349-2354, 2240-2249, 4980-4984, 5295-5298, 7086-7091).
- A loan is tied to an operand by `formation_expression == capture.expression && statement_index == capture.statement_index` (4849-4850), or by `owner_symbol == binding symbol` plus a statement window (4919-4922).
- `exact_shared_cohort_observation` identifies a program shape by literal statement numbers: cohort member k must be activated at statement k+1 and the mutation must be at statement `cohort.len() + 2` (747-756).
- Type sameness uses `normalized_type_identity` (2407-2408, 5508-5509), an identity value defined outside the slice.

## Accepts or skips without proof

- **Stored-call-input failures are discarded** (cbr.rs:5827-5835). `retained_inputs` can fail with six different reasons; the caller prints under a trace flag or does nothing (`Err(_) => {}`), and the loan gets no stored-call-input row. That row is what makes the saved reference a *holder* of its input loans in `forwarded_lifetimes::plan` (1849-1874) and in `holding_end` (2159-2164). A missing row means fewer holders and an earlier end for the input borrow. I cannot see another check in this slice that catches it.
- **`install_resource`'s result is dropped** (cbr.rs:72, `let _ =`). It returns `None` when the owner operand is invalid, the carrier path cannot be typed, or the backing root differs from the parent-lifetime root (86-102). The comment at 17-18 says "Missing provenance produces no resource: carry must still establish complete leaf coverage", so the catching check is said to be elsewhere ("carry"); it is not visible here.
- **`call_operands::collect` returns silently** on an invalid operand (129-131), a type with no computable borrow-carrying paths (133-137), unavailable or empty alternatives (142-148), an invalid source arm (151-153), an alternative that does not cover every leaf (167-173), an unresolved capture set (273-277), or no source place (279-286). Same reliance on the outside "carry" check.
- **`formation_sources::validate` skips a state with no flow state** (1586-1592, `continue`), whereas `forwarded_lifetimes::plan` (1913-1921) and roster reconstruction (2916-2922) refuse the same condition. Those later refusals do catch it, because all three run in sequence (7143-7146).
- **Reborrow loans with no supplying loan are not formation-checked** (1613-1616, `continue` when `suppliers.is_empty()`). Only reborrows formed from a copied descriptor get the "retain every parent" rule. Whether direct reborrows are checked elsewhere I cannot tell.
- **Direct-root attenuation is skipped when the binding lookup fails** (2956-2963): with `if let Some(parent_access) = binding_reference_access(..) && ..`, a `None` falls through to building the resource. I cannot tell whether `None` occurs only for roots that are not reference bindings.
- **Loans from call results or descriptor loads that were never activated are skipped** (2940-2953) and get no resource.
- **`LifetimeDependency`, `UnretainedDerived` and `SuppliedOutput` loans get no direct or reborrow resource** (3215-3217); other tables handle them.
- **The "captured before its supplier retired" check passes when the boundary cannot be computed** (1965-1968): `weakening_event_boundary(..).is_ok_and(..)` treats an `Err` (a supplier whose end is not a statement boundary) as "not violated". Nine lines later the same function's error is propagated with `?` (1977-1978) for a different comparison. I cannot see another check for this case.
- **Binding-observation fallback after a definite failure** (4054-4075). If the chosen strategy returned false and the operand is a plain (not frozen) observation, `collect` truncates its output and retries `collect_binding_observation`, which accepts any loan owned by the same local symbol, formed at or before this statement, not past its last use, with sufficient access (4918-4930). This is a looser match than the strategies that failed. See Surprises.
- **`last_use_statement_index != 0` is read as "has a last use"** (4921-4922): a loan whose recorded last use is statement 0 is never considered expired by this test.
- **`AddressReceiver::InlineValue => argument_grant = true`** (3487) and **bare range gives `argument_grant = true`** (3436-3450): the call's own argument access is taken as the permission without following an earlier formation.
- **The permission of an opaque result is not consulted for checked-body callees** (2318-2320, `return None`); the comment says "Checked bodies retain their checked source relation".
- **Parameter roots of reference type count as resolved terminal storage** (5443-5450).
- **`bind_restored_call_uses` leaves events unbound on every mismatch** (24 `continue` exits between 842 and 1101). The comment says "Unsupported shapes stay unbound rather than receiving inferred authority" (829-830). What lowering does with an unbound event is outside the slice.
- **`install_transfers` leaves unresolved debts without a row and returns `Ok`** (6346-6351). `windows` later returns `None` for them unless `completed_output_value` holds (6390-6398), so a transported debt whose suppliers never resolved reads as "no debt" to callers. I cannot tell whether a caller refuses that.
- **`output_windows` returns an empty window list when the output has no lifetime sources** (6452-6454).
- **`validate_normal_output_completions` skips** calls with no borrow record (7086-7093), invalid loan handles (7096-7098) and loans not live at exit (7100-7106), and returns `Ok` at once when no supplied-output loan exists (7076-7082).
- **Supplied-output loans with no normal call get no resource** (5980-5982, 1937-1942).
- **`bounded_access` downgrades instead of refusing**: a Mutable leaf under a Shared ceiling becomes Read, and under a WriteOnly ceiling becomes WriteOnly (7054-7059).
- **`immutable_image` descriptor profiles are skipped** in returned-projection validation (1248-1250); the function still requires some other source to select the loan (1328-1330).

## Surprises

1. **A function recognises one program by its statement numbers** (cbr.rs:738-821). `exact_shared_cohort_observation` returns true only if the shared reborrows were formed at statements 1, 2, (3) in order, the mutating call is at statement `cohort.len() + 2`, the statement before it holds exactly one call with ordinal 0, that call's target is a checked-body machine whose state has an **empty body** and exactly as many parameters as the cohort, all `Shared` references, and each argument is a whole-root Read of a cohort member's owner symbol. The cohort size must be 2 or 3. This is the shape of one test program (a `&mut` parent at statement 0, two or three shared reborrows, one call to an empty observing helper, then a mutating call), not a general rule. The caller admits cohort sizes `1..=3` (868) and calls this only for sizes above 1 (950-951).

2. **`bind_restored_call_uses` also matches a shape** (cbr.rs:833-1103): exactly one call at the boundary statement, a callee with exactly one parameter that is a mutable `&mut`, exactly one argument access that is a whole-root Mutable access to the parent's owner symbol, exactly one `BorrowCall`, one `BorrowAccess` and one parent `BorrowLoan` entry constraint, zero child constraints, exactly one mutated place equal to the whole root. Anything else stays unbound. The condition at 891 (`!exclusive_reactivation && !bounded_shared_freeze`) can never be true after the test at 883 and is dead.

3. **A comment and the code disagree on the fallback** (cbr.rs:4582-4586 against 4054-4075). The comment on invocation coverage says "A failed present roster cannot recover an older source-slot formation." Yet when a strategy fails on a plain observation, `collect` retries `collect_binding_observation`, which matches loans by local symbol and statement window (4918-4930), a slot-based association. The same function is also tried inside the chain (4022), so the fallback matters only when an earlier strategy claimed the case and then failed.

4. **An error is swallowed by `is_ok_and`** (cbr.rs:1965-1968), as described above: the one user-facing ordering rule in the holder closure is skipped when the supplier's end is not a statement boundary, while the neighbouring code treats the same condition as an error.

5. **All stored-call-input refusals are discarded** (cbr.rs:5827-5835). Six refusal messages exist that no user can see without a trace flag.

6. **Most diagnostics describe the checker, not the program.** Texts such as "drifted from semantic-phase replay", "drifted from independent topological replay", "lost its completed invocation capture" and "has no authenticated permission transfer" report that two internal ledgers disagree. Only one diagnostic in the file attaches a source span (5998-6019). One prints raw `{:?}` handles and internal structs into the message (1313-1325). The words "replay", "independent" and "certifies" (5149) show the authors thought of this module as a second derivation checked against the first, but both derivations are the checker's own code and nothing is handed to a kernel. This supports property 1.

7. **Property 2 does not hold in this slice.** Identity is by handle throughout. What stands in for text is positional coordinates (statement index, call ordinal, authored-expression handle), compared in long hand-written conjunctions (for example 2369-2420).

8. **Parents must precede children in arena order** (cbr.rs:2817-2821). A reborrow whose parent reborrow has a higher index is reported as "drifted from independent topological replay". The slice states this invariant nowhere.

9. **The steps depend on each other through shared mutable facts.** `forwarded_lifetimes::plan` writes `holder_weakening` and `final_weakening` into supplied-output resources (2082-2088); `plan_reborrow_disposition_events` reads `holder_weakening` (527-544) and roster reconstruction reads it at 3088-3106. `supplied_permissions::install` appends to `call_loan_resources` (6147-6152), which `stored_call_inputs::install` then searches (5898). `call_operands::install` resets those arenas (67-69), so it must run first. Only the call order at 7139-7170 enforces this.

10. **`LoanOccurrences::new(program, facts)` is rebuilt four times** in one initialization (cbr.rs:43, 1583, 5811, 5973), each dropped before the facts are mutated.

11. **About 170 lines are trace output**: 13 `eprintln!` sites behind `validation::trace_flags::{state_reference_diagnostics, struct_trace, check_sites}`, including a 109-line storage-snapshot dumper (4391-4499), with prefixes "STRUCT …" and "CHECKSITE …".

12. **Some code is unformatted.** `collect_reborrow_sources` has a closure written on very long single lines (4158-4191) and so does `append_borrowed` (6985-6996), unlike the rest of the file.

13. **Two things named `diagnostic` in one scope** (cbr.rs:5984 closure, 6246 module function). The closure adds callee, machine, state and span. `refuse` (6250-6252) uses the bare function, so "completed output lost its output identity" (6023) and "completed output has ambiguous lifetime-input receipts" (6052) carry no location while their neighbours do.

14. **`weakening_boundary_key`** (2747-2760) duplicates `weakening_event_boundary` with a different phase encoding and is used only for the parent-status comparison (3235-3236). The two orderings agree only if the `LifecyclePhase` enum's derived order puts LastUseExpired, LocalReassigned, StateExit in the same order as 0, 1, 2; that enum is defined outside the slice. `LifecycleBoundaryKey` derives `Ord` (2464) over all phases including `Activation` and `NormalCompletion`, so the batch order within one statement depends on that enum's variant order.

15. **The failure buffer has a fixed size** (4 steps, 8 segments; cbr.rs:3279, 3287). Longer paths are cut in the message while the true count is printed (3385-3390).

16. **A capability worth noting.** The module models multi-level reborrow trees in which a parent is lexically retired while children still hold it (`RetiredWhileBorrowed`), closing through a chain of retired ancestors to a direct root, a state-exit handoff, or a completed helper output (cbr.rs:684-715). It also tracks, per loan, the set of all copies that hold its permission and extends the loan's real end to the last holder (1943-2001). These are the general parts; items 1 and 2 are narrow parts layered on top.

17. **Small leftovers.** `validate_source` (1341-1374) only repackages its argument for `validate_captured_source`; `_parent_entry_constraint` (1064) is bound only to assert uniqueness; `frozen_kind` exists only for a trace line.
