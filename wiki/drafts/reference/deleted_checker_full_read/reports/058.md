## What this code is for

This is the last half of `flow.rs`, the module that builds "flow facts" for the old source checker. The slice holds the supporting queries around the main flow builder, not the builder itself. It contains nine inline modules: `domain` (which places a domain predicate reads, and which facts a write retires), `jump_loans` and `receiver_reads` (what storage a call or state jump may read through its receiver while argument loans are held), `value_origins` (tracing a value at a place backward through earlier stores to where it came from), `constraints` and `reference_spans` (arena-span helpers and the rule for joining constraint lists at a control-flow join), `carried_semantic_dependencies` (a table of which nominal types and cleanup machines each machine depends on), `cleanup_case_evidence` (which enum case a dying owner holds at a cleanup point), `cleanup_effect_dependencies` (which cleanup machines run for the remaining part of a dying value, and whether a type can be cleaned up at all), `dynamic_effect_dependencies` (tracing a `Selector` argument back to the implementations it can name), plus `local_jump` and `terminal_invocation` (classifying a call as a jump to a sibling state or as the call that completes a transition arm). Lines 12577-12719 are the re-export hub for the whole `flow` module, including four sibling files pulled in by `#[path]` (`flow_mutation.rs`, `flow_ownership.rs`, `flow_place.rs`, `flow_reference_places.rs`; lines 8137-8138, 9006-9011). Almost every function returns `bool`, `Option` or a list for another module to consume; the slice issues only two diagnostics (11634, 11668). Nothing in the slice calls the proof kernel.

## Mechanisms

- **Domain dependency closure** (7029-7103). Computes the list of subject-relative place paths a domain depends on by walking its predicate facts and recursing into imported domains, rebasing the imported paths under the importing place. A `BTreeSet<u32>` of arena indexes guards cycles; a cycle answers "whole subject". Results are deduplicated quadratically (6774-6791). Only the top-level call caches its result (7002-7019); the recursion reads the cache but never writes it. Serves `domain` refinements.
- **Per-fact context survival** (7817-7897). For one context it collects the facts a write retires, then iterates to a fixpoint so every `StorageDependency` whose dependent left also leaves. The result is `Unchanged`, `Dropped` or `Reduced`; a reduced context is re-published as a new context at the same program point (7684-7697). Serves all proved facts.
- **Range narrowing worklist** (7737-7801). Splits a `ZeroCaseElements` range around the written elements and re-tests each remainder against the other writes of the same step until nothing matches. No explicit budget; each step strictly shrinks a range. Serves zero-initialised arrays of enum-tagged elements.
- **Receiver-read fixed point** (8551-8728). Builds each state's direct read set, then repeatedly adds each receiver call's instantiated target footprint (whole-run and one per loan-carrying parameter) until no set grows. Bounded by widening any instantiated place deeper than `MAXIMUM_PLACE_DEPTH = 32` to the call's receiver place (8443, 8770-8774). Built lazily once in a `OnceLock` (8451, 8495-8497). Serves borrow checking of `&mut self` calls with disjoint argument loans.
- **Backward value-origin trace** (9332-9513). Walks statements in reverse admitted execution order from a frontier, rewriting the demanded place to the source of each decisive store and requiring every passed statement to preserve it. Three caller hooks: `resolve` (owned call results), `rebase` (reference leaves inside owned locals), `observe` (early match). Literal chasing is bounded by `CAPTURED_SOURCE_LITERAL_HOPS = 16` (9044, 9548). Serves contract and termination reasoning about copies.
- **Join of constraint lists** (9850-9972). Order-preserving intersection by sorted identity keys with binary search, then appending loan and incoming-reference debts once each in first-encounter order.
- **Copy-on-write span filter** (10179-10207). Keeps a filtered list as a sub-span of the source while the kept rows are contiguous and copies rows only on the first gap.
- **Completed-result tree** (10885-11007). A worklist that groups returned values by the match arm that selected them, sharing route prefixes through `Rc<SelectionRoute>`. Budget: `operands.len() + operand_alternatives.len() + 1` steps (10898-10904); exceeding it answers `None`.
- **Structural cleanup walk** (11737-12160). Recursive descent over a type with generic substitutions, a set of removed paths, an `active` recursion guard, and an "inactive case" callback. Arrays are partitioned at the cut points of removed indexes and ranges so untouched runs stay one `FixedRange` leaf (12110-12158). Produces `CleanupLeaf::Nominal` or `Symbolic` leaves. `concrete_cleanup_paths` (11430-11452) expands ranges into individual indexes with `checked_mul` and `try_reserve_exact`.
- **Selector origin search** (12384-12575). Depth-first backward search over operand predecessors, across calls (parameter arrivals) and returns (callee exits), with an `active` stack of `(operand, projection)`; a revisit contributes nothing. No depth or step budget beyond the cycle guard.

## Tests in this slice

- `a_write_removes_only_the_elements_whose_tag_it_can_replace` (7989-8055): for an eight-element zero-formed array with the tag at `table[i].kind`, pins the element range each kind of write removes: one fixed index, a whole-element write, a whole-array or whole-root write, a fixed range (clipped to the array), a runtime index and an opaque range (all eight); and that a payload write under the tag, a sibling field, an out-of-range index, another field and another root remove nothing.

## Surprises

1. **No kernel, and almost no verdicts.** The slice has no call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type. Words such as "proves", "evidence" and "authenticated" name structural checks on fact rows (`proves_case` 11042, `CleanupCaseEvidence` 11162). The unit test builds a fact with `QualificationEvidence::default()` (7972) and the invalidation code never reads the evidence field. This supports property 1.

2. **The comment at 7464-7467 says "the same ... invalidation law", but the code is a different law.** `context_survives_place_mutations` uses `visit_context_invalidations` (7495-7525): any one matched fact kills the whole context, occurrence facts are not checked at all (only `matching_mutation_for_fact_place` is passed, 7481-7490), and `ZeroCaseElements` ranges are not narrowed. `filter_contexts_after_place_mutations` uses `context_survival` (7817-7897): facts leave one at a time, settled occurrences are also matched (7561-7571), and ranges are narrowed. A cleanup selection and the flow trace can therefore disagree about whether the same context is still alive.

3. **`context_survival` can drop an unmatched fact by a counting slip.** At 7858-7863 it pushes the guarded fact handle `dependent` into `dropped` without checking that `dependent` is one of this context's facts. At 7885 it compares `dropped.len() == fact_refs.len()`. A context with two facts, one a matched `StorageDependency` whose dependent lives in another context, reaches a count of two and is `Dropped` although its second fact was never matched. The error direction loses a fact (refuses more), it does not keep one.

4. **A context with a placeless `StorageDependency` is dropped before any write is compared** (7833-7839). `filter_contexts_after_mutations` is callable with any matcher (7622), so such a context dies on every filtering step whatever was written.

5. **Cycle guards and sort keys use the arena index without the generation.** `compute_domain_dependency_segments` keys its `visiting` set on `domain_symbol.arena_index()` (7043-7044), and `derive_checked_semantic_dependencies` sorts by arena index only (10418-10425). The test at 10216-10260 exists because two handles can share a slot across pages. For the domain walk a collision reads as a false cycle and widens the dependency to the whole subject.

6. **The domain dependency cache is written only at the top level** (7015-7018); the recursive calls for imported domains only read it (7036-7042). A diamond of imports is recomputed along every path. The cache and the dedupe are linear scans over `Vec`s (7002-7005, 6781-6786).

7. **Comment and code disagree on the literal-hop bound.** The comment (9038-9043) says a chain deeper than 16 "keeps its literal spelling"; the code returns `None` after the loop (9601), which ends the whole trace.

8. **`preserve_statement_effects` ignores the observation kind for a captured value.** With `OriginFrontier::CapturedValue` it always reads `entry_origin_writes` (9705-9716), although `ValueObservation::operand_writes` (9064-9078) exists to choose between `entry_origin_writes` and `entry_binding_writes` and is not called in this slice. For a `Binding` observation the stability test `binding_origin_is_stable` is then run against the content-write list.

9. **`StateReceiverReadCache` is filled from whichever `BorrowFacts` the first caller passes** (8495-8497) and never rebuilt; the comment (8447-8450) relies on the facts being immutable for the cache's life. Nothing in the slice ties the cache to one `BorrowFacts`.

10. **A one-variant data type is reported as `Runtime`, not `Selected`** (11386-11388): when the case is not proved and the owner declares no other variant, `reachability` answers `Runtime`. The exhaustion rule just above it (11364-11382) would answer `Selected` vacuously; the code special-cases against that.

11. **`reachability` proves a case by exhaustion** (11362-11382): if every sibling variant is excluded or proved absent, the remaining case is taken as selected. This is the checker's own case analysis over the declared variants, with no recorded proof step.

12. **A checker limitation is written into a user diagnostic** (11656-11667): "a runtime-indexed case observation names no reusable case fact: bind a borrow of the selected element before testing its case". The fact store cannot attach a case fact to `array[i]` for a runtime `i`, and the message tells the user how to restructure the program. This is direct evidence that facts were attached to storage spellings, not to values.

13. **`visit` leaves its scratch stacks dirty on failure.** Early `None` returns at 11820 and 11826 skip `active.pop()` (11855), and `visit_field_child` skips `path.pop()` on failure (11732-11733). The one caller that continues after a failure compensates by hand with `active.truncate` and `path.truncate` (11985-12007). The open-extent array arm pops `path` but not `active` (11786-11797); it survives only because that failure always propagates.

14. **`segment_order` scans every data definition in the program to rank one path segment** (12288-12310) and returns a payload field's position inside its variant but a field's or variant's position among all members; two siblings from different levels can share a rank. For closed generic applications, which "retain their own field/case identities" (12249-12255), the scan over `program.data_definitions()` may not find the symbol and then the whole path has no order. Cannot tell from this slice.

15. **An interprocedural value-flow analysis lives here.** `dynamic_effect_dependencies` (12319-12576) traces `Selector` values backward through stores, through every call that targets a state (12451-12472) and through every exit of a private callee (12541-12573), substituting parameters for actuals. It has no budget other than the cycle stack, and a failed step anywhere (`?` at 12459, 12467, 12495, 12556, 12563) abandons the whole narrowing for that argument.

16. **`derive_cleanup_effect_dependencies` enforces whole-program specialisation as a side effect** (11619-11641): any checked-body machine that calls a machine with open parameters is an error, raised from cleanup-effect preparation and worded as a cleanup problem.

17. **Every nominal type mention yields three dependency kinds at once** (10440), including a `Layout` dependency for a type seen only behind a reference (10549-10552 descends into `Reference`). Call return types are always recorded as private (10346) even for public machines.

18. **Identity by pointer address.** `selected_results` and `CompletedResult::belongs_to` accept a result only if the facts are the same object in memory (10892, 11036-11039). A structurally equal copy of the facts is refused.

19. **Property 3 shows up here as "fact on an occurrence" versus "fact on storage".** The three matchers at 7126-7233 exist because a by-value read records its facts on the read expression (a `PlaceRoot::Expression`), so the same fact must be found again by resolving the expression to storage after the statement ends. The author comment (7163-7172) gives the reason: other provers "match places by label". The mechanism is one function with three matchers, not three full copies.

20. **File shape.** One 12,826-line `flow.rs` mixes inline `mod` blocks, `#[path]` sibling files (8137-8138, 9006-9011) and a 140-line re-export hub (12577-12719) that re-exports about 120 names; the modules in this slice import one another freely through `super::` and `crate::flow::`.
