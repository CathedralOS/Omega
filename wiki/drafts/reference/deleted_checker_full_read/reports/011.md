## What this code is for

This file decides whether a machine may be run by the compiler at build time (a constant initialiser, a constant domain fact, a build policy, a range endpoint) and then runs it. The file header names five jobs: "Compile-time machine admission, build activation verification, hermetic build-machine execution, selected operator validation, and target-family body preparation" (me.rs:1-10).

Admission (`mod admission`, me.rs:12-4650) walks the call graph reachable from the invoked machine and refuses it unless every machine terminates, carries no linear values, has its `requires` discharged, stays inside the caller's package authority, and uses only permitted services without suspending or blocking. It discharges `requires` at concrete arguments by cloning the whole typed program, adding a generated machine that calls the entry with literal arguments, and re-running the ordinary source checker on the clone (me.rs:520-652, 759-827). After execution it checks that the returned value is "ConstEvaluable": a closed, copyable, non-reference shape (me.rs:1799-2584).

`mod build_activation` (me.rs:4651-4851) protects the compiler-owned `Build` value from being stored, copied or constructed by source. `mod build_machines` (me.rs:4852-5851) produces a Terminal Psi artifact for the entry and runs it in the Terminal interpreter under a work budget. `mod selected_operators` (me.rs:5852-6804) validates rows that say "this operator expression runs this provider body or this primitive float operation" and rewrites a private copy of the program accordingly. `mod selected_target_bodies` (me.rs:6805-7006) validates a chosen per-target body for a target family and rewrites calls to the family head to call that body.

## Mechanisms

- **Call-closure walk with a cycle stack** (me.rs:201-382). A depth-first walk over `BuildTimeCallEdge` rows keeps `completed`, `active` and a `path` of machine names. Re-entering an active machine triggers the recursive-termination query (me.rs:278-307). No budget. Serves termination, linear-carrier and `requires` admission.
- **Worklist closure walk** `walk_call_closure` (me.rs:3668-3691), used for `requires` detection, selection authority, static-application closure and closure listing. It skips symbols with no machine (me.rs:3677-3679).
- **Probe-and-recheck** (me.rs:520-652, 759-827, 871-931). To establish a precondition at concrete values, the code clones the typed program, turns each value into literal expressions (me.rs:1634-1791), adds a generated machine whose single state transitions to a call of the entry, runs `prepare_typed_trees` and `lower_typed_trees`, then reads the checker's crash summary and pending-obligation rows. Reference parameters get a generated local plus a borrow (me.rs:580-606). A target-context argument becomes a generated parameter of the probe instead of a literal (me.rs:544-560). No budget; one whole-program clone and check per call.
- **Demanded-closure cache** (me.rs:3977-4030). The checked closure for a root is cached in a `RefCell<Vec<..>>` keyed by `(program pointer address, machine count, data-definition count)` plus the evaluation domain (me.rs:3984-3988, 4004-4010). Failures are cached too (me.rs:4024-4027).
- **Call-edge projection** (me.rs:3733-3768, 4606-4649). Edges come from the operational plan's calls plus one edge per resolved operator selection that has a realization machine and state.
- **Structural result check with an active-type stack** (me.rs:1975-2069, 2123-2160). Recursion over the declared return type and the value together; the stack of `TypeIdentityId` refuses recursive data.
- **Result relabelling** (me.rs:1846-1961). A value read back from Terminal Psi gets the source type name and unqualified case name before it is checked.
- **Package custody lattice** (me.rs:3350-3506). Five custody classes (`Toolchain`, `ToolchainContract(span)`, `Package(id)`, `UnownedUser`, `Missing`) and a decision table over requester and owner.
- **Spelling confinement** (me.rs:3161-3214). For an unresolved authored selection, every symbol in the program with the same name and a kind fitting the late-binding kind (me.rs:3216-3257) must be selectable.
- **Terminal Psi execution** (me.rs:5046-5339). Produces an invocation artifact with `psi_terminal_production`, admits target machine selections and layouts, completes target-dependent scalar conditions, binds arguments, binds selected float imports, invokes under the caller's meter, converts the result and charges its size. The budget is the meter's; exhaustion is a refusal (me.rs:5307-5312).
- **Private execution copy** (me.rs:5944-6066, 6925-7005). Clones the program and overwrites selected expressions with calls to provider entry states or builtin binary nodes, and retargets calls to a family head to the chosen member, finalising late-bound authored selections first.
- **Selection propagation to specialised copies** (me.rs:6620-6689). A selected operator in a template machine is copied to the same authored occurrence in each specialisation whose target context matches.

## Surprises

1. **This "old checker" file already executes on the lowered form.** Build-time machines run as Terminal Psi in the Terminal interpreter (me.rs:5072-5097, 5289-5291). Only the admission side works on source trees. The pull request deleted an execution path of the kind the new design keeps.

2. **Precondition discharge is "write a program and type-check it".** There is no evaluation of the `requires` predicate at the argument values. The code clones the full `TypedTrees`, synthesises source for a call with literals, and runs the whole checker on it (me.rs:534, 642-643, 772, 802-803). `require_established_arguments` clones the program again and adds one data type and one machine per argument (me.rs:1520-1603). A single constant invocation with `requires` can therefore check the program several times; only the argument-independent closure is cached (me.rs:4004-4018). The verdict is the checker's yes or no read back through the crash summary and pending rows, which supports property 1.

3. **Two different ideas of "the entry state".** `entry_state` picks the state named like the machine and falls back to the first (me.rs:737-752, 1963-1973). `require_established_arguments`, provider validation and target-body validation take the first state (me.rs:1512-1515, 5906, 6215, 6886-6893). For a machine whose same-named state is not first, argument values are established against one state's parameters and the call probe uses another's.

4. **Admission mutates the arguments.** `literal` removes undeclared fields from the supplied value in place (me.rs:1751-1753), and the caller's `&mut [BuildTimeValue]` is what gets passed (me.rs:1043, 1047, 1522, 1542). The values executed afterwards (me.rs:4369, 4489, 4549) are the pruned ones. An extra field is dropped silently instead of refused.

5. **Sum results skip the copyability rule.** Records must be `Unrestricted` (me.rs:2143-2150); the `Enum` arm goes straight to `check_sum` (me.rs:2152).

6. **Interior mutability is a name-prefix test.** Any type named `Atomic...` is refused, including a user's plain data type of that name, and the test runs before the primitive lookup (me.rs:1996-2003, 2334-2341). No other property of the type is consulted.

7. **A machine with layout target facts is treated as terminating** (me.rs:310-323) without asking for a termination summary.

8. **The cycle branch has no test here.** `checked_constant_refuses_a_cycle_without_descent` shows the ordinary checker refusing first (me.rs:5814-5819), so the text "recursive machine-call cycle has no ordinary termination proof" (me.rs:296-304) is not reached by any test in the slice.

9. **Two closure walks disagree about non-machine targets.** `walk_call_closure` and the termination walk treat an edge with no machine target as a callable contract or operator (me.rs:125-129, 364-374, 2695-2730). `admitted_program_machine_closure_symbols` reads `edge.target_machine_symbol` directly and refuses any edge where it is invalid (me.rs:4314-4325), after the floor has already passed (me.rs:4289-4300). A closure with one trait-signature or operator call would pass the floor and then fail here with "contains an unresolved machine target". It also ignores the `target_state_symbol` fallback that `target_machine` uses (me.rs:3657-3665).

10. **Operator accepted, body possibly not walked.** See the me.rs:3745-3757 entry above: acceptance of a binary operator (me.rs:2900-2904) and creation of its call edge (me.rs:3753-3757) use different conditions.

11. **Unreachable arms and arm order in `require_selection`.** The `ToolchainContract`/`Package` arms at me.rs:3482-3485 cannot be reached, because `closed_contract_selection_violation` already returned for them (me.rs:3473-3477, 3402-3405). The `Toolchain` arm (me.rs:3486) comes before the `UnownedUser` and `Missing` arms, so toolchain code selecting a declaration with no provenance is accepted.

12. **Cache key is a pointer address plus two counts** (me.rs:3984-3988). Two different programs at the same address with the same machine and data counts would share an entry. The cache is cleared when selections change (me.rs:3843, 3873) but not otherwise.

13. **Arguments are routed to scalar or structural parameters by the value's shape, not by the parameter.** An `Int` or `Bool` goes to the next scalar parameter while any remain; everything else goes to the next structural parameter (me.rs:5238-5265). The doc comment says the artifact "splits one source list into those two ordered lists" (me.rs:5050-5051); the code reconstructs that split by guessing from values. A float argument is never "scalar shaped" (me.rs:5239-5242).

14. **`prepare_in` ignores its domain for one step.** It builds `domain.execution_program(program)` but calls `defer_pending_const_applications(&mut typed, &EvaluationDomain::all())` (me.rs:5406-5408).

15. **Selected float operators are rewritten to builtin exact arithmetic for admission and run as host imports for execution.** The private copy turns the expression into `Binary` with `ArithmeticDomain::Exact` (me.rs:6056-6063); execution binds a host closure with IEEE semantics to the Terminal import (me.rs:4918-4926, 4931-4997). The program that is checked for termination and the program that runs differ at those expressions.

16. **Synthesised provider calls acknowledge neither suspension nor blocking** and are marked `CompilerSynthesized` (me.rs:6048-6053).

17. **The closed-contract rule runs even with no package authority** (me.rs:2637-2654, 2696-2705, 2752-2762), while every other package rule is skipped without one. The test name says this is intended (me.rs:3411).

18. **Reference peeling differs between the two argument paths.** The call probe strips constraints and then looks for a reference (me.rs:561-572). `require_established_arguments` looks for a reference only at the top (me.rs:1524-1527), so a constrained reference parameter reaches `literal`, which strips the constraint, finds a reference and refuses with "snapshot has no closed literal carrier" (me.rs:1643-1645, 1788).

19. **Unused parameter.** `machine_linear_carrier_violation` takes `_path` and ignores it (me.rs:413-419), so the linear-carrier message cannot name the call path the way the other messages do.

20. **Violations travel as strings.** The closure and selection violations are computed here but the refusal is issued by `semantic_vocabulary::compiler_evaluation::require_compiler_evaluation_floor`, which receives them as `Option<&str>` (me.rs:4263-4270). This file never returns them itself; whether a `Some` always refuses is decided outside the slice.

### The three properties, in one place

1. **Own yes/no, not kernel evidence: supported.** No proof-kernel call anywhere in 7,006 lines. Decisions are own comparisons, answers from `validation::*`, `typed_trees_to_checked_trees::*` and `semantic_vocabulary::compiler_evaluation::*`, or a full re-run of the source checker.
2. **Identity by text: partly supported.** Symbols and handles carry most identity, but entry states, primitives, interior mutability, record/case/field identity of values, provider types, targets, services, conformances and the `Build` types are decided by strings (list above).
3. **One rule per placement: weakly supported here.** The clear cases are `Build` storage (seven placements) and provider requirements (three kinds). Most of the file is organised by machine and call edge, not by placement.
