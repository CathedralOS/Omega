## What this code is for

This slice is not the proof or ownership checker. It is the "provider planning" crate of the old compiler's realization half: the code that decides, after a program has been checked, which implementation supplies each boundary API (a `boundary` trait, a top-level requirement machine, a boundary operator, or a generated placed-scalar accessor) on the selected target, and which machine is the program entry.

It selects the `ProgramEntry` root slot for the target from the Build declaration's root bindings and validates the entry machine's source shape and its two calling plans (semantic and physical) (`program_entry.rs`). It derives candidate "provider plans" from the `satisfies` declarations in the checked program, one row per requirement, each row bound to a checked adapter body, a compiler intrinsic, a syscall, an import, or a dispatch-table field (`provider_planning/provenance_replay/*`). It hands the candidates to another crate, `provider_selection`, which chooses whole plans; this crate then re-joins the chosen plans to source declarations (`provider_identity.rs`, `adapter_conformance.rs`, `provider_declarations.rs`).

It also checks `AssumedBindingContract` declarations for signature compatibility (`provider_settlement/assumed_bindings.rs`), verifies attached component descriptions for independently deployed packages (`provider_settlement.rs`), and reviews that a provider of an external-completion requirement (process exit) reaches a real external leaf on every path with its status argument unchanged (`provider_settlement/completion.rs`). It extracts the native external binding rows (imports, syscalls, table fields with byte offsets) for the backend (`provider_planning/external_binding_rows.rs`).

Almost every record carries identities as strings (callable identity text, display paths, plan names), and many errors are stored inside records as `Result` fields and reported only if the candidate is later selected.

## Mechanisms

1. **External-completion review (`completion.rs:115-767`).** A path-exploring abstract interpreter over the checked flow plans (`checked.facts.flow.terminal_unit_effects`, `terminal_partial_affine_unit_cleanups`, composed plans). The abstract value of a scalar is `Option<usize>`: "this is exactly entry parameter N", or unknown (`completion.rs:16`). The interpreter starts the provider with `[Some(0)]` (`:129`), follows calls, local bindings, qualifications, selects, conditional and guarded terminators and state jumps, and merges branch outcomes (`Outcome::merge`, `:98-112`): a result origin survives a merge only if both branches agree. It computes three things: whether any path returns normally, the origin of the returned scalar, and the set of external leaves reached. Limits: recursion is refused, not solved by fixpoint (`:233-236`); there is no memoization and no budget, so a state shared by several paths is walked once per path; calls with structural arguments, dynamic routes, temporary cleanups or claim transfers are refused (`:301-308`, `:495-502`). It serves boundary requirements whose completion is `BoundaryCompletion::External` (process exit).

2. **Whole-plan candidate derivation (`plan_derivation.rs:25-208`).** One pass over all machines groups rows into plans keyed by (plan name string, provider package, origin package, schema declaration, provider symbol) (`:569-616`), then appends operator plans, top-level requirement plans, named-implementation plans and accessor plans, then filters out any plan with a row whose target body is absent (`:188-206`). Lookup of the group is a linear `position` scan per row.

3. **Named-plan join (`named_provider_plans.rs:186-241`).** For a bodiless row of a named implementation, searches every row of every earlier candidate (authored and native Build) for a row with the same requirement symbol, realization and identity text; all matches must agree on binding and origin. Serves named `satisfies` maps whose members are foreign or build-owned.

4. **Replay of calling plans (`program_entry.rs:751-770`).** For the two entry calling plans, re-derives the validated application (`replayed_validated_application`) and compares the plan, a report fingerprint and a commitment with the retained ones. This is a recompute-and-compare check on retained evidence.

5. **Recompute-and-compare for sealed accessors (`sealed_accessors.rs:112-177`).** Re-authenticates the accessor declaration, recomputes its schema and a 32-byte contract identity (`effects::compiler_accessor_scalar_contract_identity` over schema digest, placement commitment, access slot and operation, `:98-110`) and compares all with the plan.

6. **Source custody by digest (`source_contract.rs:158-169`, `:324-333`).** The bundled physical entry contract is identified by its path relative to the package root and a digest of its source bytes that must equal a digest built into the compiler (`program_entry_plan::exact_physical_contract_package_source_digest`). A separate FNV-1a fingerprint is carried and named "non_authoritative" (`:219, 354-364`).

7. **Table-field offset resolution (`external_binding_rows.rs:211-314`).** Finds the table record and field in the Terminal Psi module, then lays the record out with the foreign layout for each selected calling ABI and requires all ABIs to give the same byte offset.

8. **Per-target publication catalog (`prepared_providers.rs:428-518`).** Builds a provider proposal for the selected target and for every target in `TargetProfile::ALL` plus every target named by defaults, overrides, application roots and proof-application scopes, deriving candidates again for each target.

9. **Deferred errors.** Not an algorithm, but the crate's general method: an error found while source is available is stored as a `Result` field (`provider_rows.rs:15, 19-20, 25, 41, 149`; `source_contract.rs:31, 39`; `prepared_providers.rs:37, 40, 70, 196, 216`; `service_declarations.rs:33-34`; `assumed_bindings.rs:14, 20`) and reported later only if that candidate is selected or demanded.

## Surprises

1. **This slice is not a checker of proofs or ownership.** It never calls the proof kernel: a search of the slice for `proof_admission`, `ProofNode`, `verify_obligation` and "certificate" finds nothing. The only mention of proofs is `checked_trees::ProofApplications::...scopes(...)` used to list target names (`prepared_providers.rs:445-453`). Property 1 holds in the sense that every verdict is this code's own comparison or another module's answer. But the style differs from a bare yes or no: several checks are recompute-and-compare against digests, fingerprints and commitments (`program_entry.rs:751-770`, `sealed_accessors.rs:149-175`, `source_contract.rs:303-333`).

2. **Four machine names hard-coded in the compiler make a machine an intrinsic** (`provenance_replay.rs:234-260`). A user-declared machine named `ConsoleNativeProvider::write_byte` with the right trait, requirement and signature names and shapes qualifies; no package or toolchain ownership is tested in this function.

3. **On non-hosted targets the intrinsic inference has no shape check at all** (`provenance_replay.rs:357-391`): any bodiless boundary machine with attached data and one origin for the target becomes `ProviderBinding::CompilerIntrinsic`.

4. **The completion role knows only a trait named "Console"** (`semantic_roles.rs:51`), while the hosted catalog also knows `ProcessExit` (`provenance_replay.rs:253-258`) and a comment mentions "windows_x86_64's `via` ProcessExit" (`plan_derivation.rs:495`). A `ProcessExit` provider gets the external-completion review (`completion.rs`) but can never hold a completion role.

5. **A debug environment variable is read in production code**: `OMEGA_PROVIDER_DEBUG` (`named_provider_plans.rs:29`; `plan_derivation.rs:181, 194`) prints skip reasons to stderr. It is the only way to learn why a named provider plan was dropped.

6. **Results depend on the machine the compiler runs on when no target is selected.** `TargetProfile::host()` or `host_if_supported` supplies the target at `plan_derivation.rs:190-192`, `target_machines.rs:143, 167`, `provider_settlement.rs:222-226, 246, 395`, `prepared_providers.rs:402-405`.

7. **Independent components are fully verified and then always refused.** `settle_checked_providers` runs `verify_component` and selection for `Independent` edges, and `verify_selected_compositions_are_realized` (`provider_settlement.rs:443-465`) then rejects emission for every such edge. The feature is checked but cannot produce an artifact.

8. **The completion review is a real path-sensitive analysis with value tracking by position**, which the three sampled properties do not describe. It has no memoization and no budget (`completion.rs:619-653` re-walks the successor state on each path), so its cost can grow with the number of paths. Its leaf test accepts a leaf found in any candidate plan passed in, not only in the selected plan (`completion.rs:157-194`).

9. **Assumed-binding diagnostic and code disagree.** The text says "parameter order or passing modes" (`assumed_bindings.rs:133`) but the code compares only type identities. And `(None, None) => true` (`:51`) accepts when neither side has a calling plan.

10. **Unreachable code.** `selected_target.unwrap_or("cross_platform_cli")` (`external_binding_rows.rs:197`) cannot run with `None`, because `target_profile` at `:111` already fails when both the plan target and the selected target are absent. The second "does not belong to its retained package identity" check (`adapter_conformance.rs:224-231`) cannot fire after the filter at `:163-165`.

11. **Possible double count.** `exact_checked_adapter` collects machines by callable identity and then loops over all machines again adding target-scoped ones with the same identity (`adapter_conformance.rs:141-155`). If the first query already returns a target-scoped machine it is listed twice and the "resolves to 2 exact typed machines" error fires. Cannot tell from this slice whether `machines_by_callable_identity` excludes them.

12. **Three copies of family resolution disagree.** `bound_program_entry_shapes` and `prepare_compiler_program_entry` report "entry family .. has no body for target .." (`program_entry.rs:108-118, 662-672`); `check_unrequested_program_entry_rows` silently continues (`:618-620`).

14. **A comment says no inventory is "joined back by names or source spans"** (`target_machines.rs:5-7`), yet this crate joins rows by display-path strings and callable-identity text throughout (see "Identity by text"), and matches the bundled entry schema by leaf name (`source_contract.rs:173`).

17. **`extent_layout::capture` strips `Constrained` type wrappers** before looking at the data definition (`program_entry.rs:891-898`), so a refinement on the entry parameter type plays no part in the layout check.
