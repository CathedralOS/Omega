## What this code is for

This is the first half of the old checker's ownership ("multiplicity") module: the part that decides who holds each linear or affine value and whether a move, a store, a cleanup or a hardware instruction may end that holding. It works on a ledger of "permission events" (Establish, Transfer, Consume, AffineDrop) and a list of `LinearPlace` rows, one per claim, each keyed by a storage root and a path below it (`:2343-2384`). The header comment (`:1-11`) names the parts: `linear_obligations`, `consumed_owners`, `permission_events`, `claim_outcomes`, `linear_validation`, `type_multiplicity`, `owned_selection`, `returned_claims`. The slice holds these inline modules: `body_input_frontier`, `content_snapshots` and `content_transformations` (a "content conservation" scheme that lets a body replace qualified parent claims with child claims, `:13-1630`); `construction_frontier` (which parts of a partly built value are established, `:1641-1957`); `consumed_owners` (use after move, `:1958-2316`); `linear_obligations` (the `LinearPlace` types, claim-identity numbering, and the statement walk `prepare_storage_deaths`, `:2317-3000`); `owned_cleanup` (`:3003-3060`); `owned_selection` (ownership moved through a `match` that selects between sources, `:3061-4498`); `owned_transfer_paths` (publishes where each transferred claim sits inside the consuming operand, for lowering, `:4499-4613`); and `instruction_dispositions` (an assembly `ensures` fact that consumes a linear claim, `:4616-5366`). Five further sub-modules are only declared here by `#[path]` and live in other files: `borrowed_windows`, `claim_outcomes`, `cleanup_dispositions`, `linear_validation`, `permission_events` (`:1634-1640`, `:3001-3002`, `:5367-5368`). There are no tests in the slice. Most refusals in the content modules are returned as `&'static str` and turned into user diagnostics somewhere outside the slice.

## Mechanisms

- **Content snapshot traversal** (`place_matches`, `capture_matches`, `:428-554`). Decides whether a value observed now is still the value some producer made (or the entry value). It follows the stored-value ledger (`crate::flow::stored_values::at_snapshot`) and the completed-value predecessor graph (`crate::flow::completed_values::predecessors`), requiring every alternative and every predecessor to match. It keeps an active stack and a memo list of finished (capture, path) pairs; only `Ok` results are memoized (`:550-552`). Limits: 65,536 visits (`:491`), depth 128 (`:512`), cycle = refusal (`:505-511`). A fresh traversal is made per observed field (`:388`). Serves content-qualified ownership (`domain`s with a content projection).
- **Backing-address matching** (`:755-799`). Builds every (input address, result address) pair as a goal, sends all N x M goals in one call to `validation::completed_value_proves_backing_addresses`, then demands each row have exactly one proved column and no column be reused. No budget. Address rosters come from `owned_addresses` (`:811-882`), a recursive walk of the type that enumerates each fixed-array element separately (`:863-867`) and uses an ancestor stack to refuse recursive data. Serves boundary (trait `is_boundary`) implementations.
- **Two-phase transaction** (`prepare` `:1070-1330`, `commit` `:930-1068`). All equations at one completion are prepared and cross-checked before any place is changed; identical equations imposed by separate declarations are merged (`:1136-1151`, `same_completed_equation` `:1533-1584`). `commit` then inserts claim transformations, derivations and one body transformation, pushes a `Consume` event per parent and sets `place.live = false`. `consumed_places` (`:1494-1531`) later reports the parents so the statement walk can treat them as moved. `publish` (`:189-221`) writes the observed inputs into the fact tables.
- **Lineage roots** (`:1593-1629`). For an input that an earlier derived equation produced, takes that derivation's root roster; all derivations producing it must agree.
- **Construction frontier** (`:1693-1864`). A list of established path prefixes. `establish` replaces subtrees and folds upward while each ancestor is complete (`:1777-1802`); `completes_with` joins frontiers (`:1809-1825`); `seed_zero_values` pre-establishes what zero-fill provides (`:1725-1754`); `contains` and `retire` are prefix tests (`:1766-1775`). Arrays stay sparse until all literal-length elements are present (`:1844-1854`). Serves partial initialization.
- **Consumed-owner replay** (`:2053-2240` driven by `prepare_storage_deaths` `:2532-2878`). Walks `ownership_occurrences::statement_steps` in evaluation order (Observe, Complete, Move). Each consumed row carries the branch route on which the move happened; `routes_compatible` decides whether a use is on a path that saw the move; routes are cleared at statement end. Serves use-after-move. The same walk drives the borrowed-storage windows and collects "replacement deaths", which it appends as contextual cleanup dispositions (`:2847-2876`).
- **Claim identity numbering** (`ClaimIdentityAllocator`, `:2445-2508`). Each state gets a base ordinal `(position % 2^20) * 4096`, so a state's identities do not depend on states walked before it; a high-water mark keeps later mints above all of them (`absorb`, `finish_walk`). Overflow panics (`:2500`).
- **Owned selection capture** (`collect` `:3870-4009`, `record` `:3366-3726`). Recursively walks an operand's completion (Selected alternatives, Constructed children) to list every source place a `match` result may have come from, then ties each linear claim to one Transfer event and one evaluated place row (`evaluated_source_custody` `:3795-3846`), and writes a `FlowOwnedSelectionReceipt`. `retains_source_storage` (`:3733-3767`) replays events through `SelectedEvaluation` with an OR join to decide whether the source may still be present. `SelectionOccurrences` (`:4108-4304`) then carries the consumed regions forward through later statements.
- **First-match reachability** (`reachable_arms` `:4326-4370`) and **arm route** (`terminal_arm_route` `:4384-4410`, recursive into nested matches; the last reachable arm adds no branch decision).
- **Path overlap** (`place_paths_overlap` `:4436-4450`): pairwise comparison along the common prefix.
- **Receipt-tree validation** (`valid_effect_tree` `:5132-5303`). Worklist over a tree of instruction-effect receipts; termination is forced by requiring each child's arena index to be lower than its parent's (`:5295-5297`).
- **Transfer placement** (`:4525-4612`). For each live linear owned Transfer event, computes the claim path relative to the consuming operand's storage path, or records `Unresolved`, `OtherRoot` or `Outside`.

## Surprises

1. **No proof-kernel call anywhere in the slice.** There is no `proof_admission`, `ProofNode`, `verify_obligation` or certificate. Every acceptance is this code's own comparison or a yes/no from another checker function (`exact_scalar_membership` `:102`, `:1293`; `completed_value_proves_backing_addresses` `:767`; `completed_value_preserves_entry_projection` `:400`; `instruction_effect_evidence` `:4840`). The one place that keeps evidence and re-checks it is `instruction_dispositions`: a receipt tree is published (`:4871-4886`) and `valid_receipt`/`valid_effect_tree` re-validate it structurally (`:4996-5303`). That re-check is hand-written matching against flow tables, and its comments say it deliberately does not redo proof search (`:4992-4994`).
2. **`storage_place` does nothing, against its own comment.** The comment says it re-roots `self` spellings at the machine and joins attached-field roots to receiver storage (`:2266-2270`); the body copies the place unchanged and ignores `_program`, `_machine`, `_state` (`:2271-2281`). The module header says a move out of "an owned `self` receiver" is tracked (`:1962-1963`), but `owned_custody_chain` accepts only state locals and state parameters as roots and ignores `_machine` (`:2289-2302`). So either `self` is already a state parameter by this stage, or moves out of `self` are not tracked here; the slice does not say which.
3. **`place_paths_overlap` is asymmetric** (`:4440-4449`). A dynamic `Index` on the *used* side conflicts with any index on the consumed side, but a dynamic `Index` on the *consumed* side does not conflict with a `FixedIndex` or `FixedRange` on the used side, and a `FixedRange` never conflicts with a `FixedIndex` inside it. If a move out of `a[i]` can be recorded, a later use of `a[3]` is not reported by `consumed_through` (`:2237`) or `conflict` (`:4222`). `collect` refuses source paths with dynamic indices for selections (`:3992-4000`), but `record_owned_place` has no such filter.
4. **Only the first variant of a sum counts in the construction frontier.** `record_children` lists the plain fields plus the payload fields of the first variant only (`:1934-1954`), and `complete` uses that list (`:1855-1862`). A sum built through any other case never becomes complete by its children; it must be established whole.
5. **A hardware instruction can discharge a linear obligation.** An `ensures` assembly fact, or an `ensures` proposition at an exit, that matches an "instruction effect contract" consumes a live linear claim (`:4887-4906`), provided the claim's type has a boundary trait requirement authored in the same package (`:4959-4963`). Leaves of the evidence are a register intrinsic (identified by builtin name, `:5219-5228`) or an atomic release store (`:5157-5193`).
6. **`valid_effect_tree` mixes state and machine when counting exits.** It finds the callee by `state.state_symbol == call.target_symbol` (`:5258-5264`) but then collects every exit whose `machine_symbol` equals the callee's machine (`:5268-5276`) and demands one child per exit (`:5277-5291`). For a callee machine with several states this counts exits of all its states.
7. **The walk mutates facts before it knows the program passes.** `prepare_storage_deaths` writes `facts.contextual_cleanup` through `record_invocation` and `record_edge_invocation` during the walk (`:2681-2694`) and only afterwards returns `Err(diagnostics)` (`:2844-2846`).
8. **Size-dependent refusal.** A program whose value graph needs more than 65,536 snapshot visits or depth 128 for a single field is refused with a budget message (`:491-493`, `:512-514`). The backing-address check has no budget but is quadratic in the number of address leaves and enumerates fixed arrays element by element (`:755-766`, `:863-867`).
9. **Diagnostics deduplicated by text** (`:2243-2250`): two different uses that render the same sentence produce one error. The consumed-owner diagnostics are held in a separate list and appended last (`:2537`, `:2843`).
10. **The comment about ordering cannot be checked here.** `:2002-2005` says consumed-owner diagnostics are reported only after linear validation succeeds "(see `check_linear_obligations`)", but `check_linear_obligations` (`:2510-2519`) does not call `prepare_storage_deaths`; the ordering is set by a caller outside the slice.
11. **Two views of the program.** `publish_owned_transfer_paths` switches to `program.typed_program()` so that answers do not depend on "checking memos, deferred layout geometry or opaque selections" (`:4509-4512`, `:4529`). This says the checking input could answer the same place/type query differently from the typed program.
12. **Claim identities are designed for states checked independently** (`:2463-2467`): the per-state ordinal window (4096, wrapping at 2^20 states, `:2460`, `:2471`) exists so that walking states apart gives the same identities. A state that mints more than 4096 runs into the next state's range; the comment relies on the identity also carrying machine and state (`:2456-2458`).
13. **The file is a bundle.** The header names separate files (`linear_obligations.rs`, `consumed_owners.rs`, ... `:3-10`) that are inline modules here, while other sub-modules are still pulled in by `#[path = "checks_multiplicity_*.rs"]` (`:1634`, `:1636`, `:1639`, `:3001`, `:5367`). Paths in `use` lines still say `crate::checks::multiplicity::...` (`:2325-2331`). Several helpers used through `super::` (`type_carries_linear_obligation` `:1917`, `projected_affine` `:2331`, `type_reference_is_reference` `:4916`) are defined outside the slice.
14. **Selected sources are sorted in reverse** (`:3450-3456`): locals before parameters, later declarations first. Nothing in the slice says why; it matches a reverse-declaration cleanup order.
15. **An affine place gets its identity cleared right after it is set** in `apply_availability` (`:3147-3159`): affine claims carry provenance but no claim identity.
16. **The "content conservation" scheme is a large capability not named in the brief's background**: a body may trade qualified parent claims for child claims if a conservation equation was proved at the completed value, with exact-roster accounting of every nested obligation (`:556-1630`). About 1,600 lines of this slice serve it.
17. **Crash transitions are exempt from the open-window refusal** (`:2826-2836`): a state may leave by a crash exit with a borrowed-storage hole still open.
