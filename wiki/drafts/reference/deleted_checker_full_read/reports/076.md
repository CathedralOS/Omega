## What this code is for
This is the `proof` crate's checker for "bounded value" obligations: every place where a value flows into a type that carries an integer range, a float range, or a named constraint such as `finite` or `positive`. Another module (`obligations`, outside this slice) builds a `ProofPlan` listing those obligations; `check_proof_plan_with_decisions` (checker.rs:6564-6649) walks the list and either stays silent or pushes a "cannot prove ..." diagnostic. It handles five source placements, each with its own obligation type and its own check function: assignment, local/data initializer, state return, call argument and transition argument (checker.rs:332-822). For integer ranges it first tries to build a small proof tree (`ProofNode`) and has the `proof_admission` kernel check it (checker.rs:899-907); when it cannot build one it falls back to its own interval arithmetic or to interval functions in the `validation` crate. Float ranges and named constraints never go to the kernel; the checker decides them itself (checker.rs:824-845, 5993-6251). Supporting modules narrow ranges from transition guards, earlier refuted guards and `requires` contracts, and decide whether a fact about a place is still true at a statement by comparing written and read paths. The file also contains a counting module that classifies how each obligation was settled (checker.rs:5562-5968), a certificate cache (checker.rs:2857-2978, derivation_store.rs), and, in lib.rs, a reporting walk over syntax trees (`proof_surface`, lib.rs:39-649) and shared typed-expression helpers (lib.rs:650-918). Two obligation kinds in the plan, `BoundedValue` and `GuardedTransition`, are not decided here at all (checker.rs:6585-6588, 6619).

## Mechanisms

- **Three-way certificate verdict** (checker.rs:884-888, 934-965). `certificate_verdict_measured` first consults the cache, then calls a closure that either builds a `BoundedValueCertificate` or returns `None`. `None` is "Uncovered"; a built certificate the kernel accepts is "Certified"; one it refuses is "Rejected". Only "Rejected" refuses the program directly; "Uncovered" hands the decision to interval code.
- **Certificate shapes** (checker.rs:1268-1324, 1574-1687, 1770-1921). Every certificate proves a conjunction `lower <= term AND term <= upper`. The term is either a closed literal expression, or a fresh `MathValue` atom whose id is the obligation's index plus one (`ValueId::new(seed)`, seed from 6583). Each side is a two-step `IntegerLessOrEqualTransitivity` chain between a literal-vs-literal `ClosedIntegerRelation` leaf and an `Assumption`. The refold form inserts an `IntegerAffineBound` step with an `IntegerAffineWitness` for `place ± literal` (1617-1622). Limits: bounds must fit `u128` magnitude (`bigint_math_literal`, 1987-1990, converts through a decimal string); scalar bounds convert through `to_string().parse()` (1707-1718).
- **Strongest-anchor selection** (checker.rs:1275-1308, 1530-1558). Among the collected assumptions it picks the largest lower bound and the smallest upper bound and builds the proof only from those two; it needs both, and needs the target to contain them.
- **Bound collection from conditions.** A recursive walk over a condition that unwraps `x == true`, splits `&&`, and reads `subject cmp literal` or `literal cmp subject`. There are five integer copies and one float copy (see Repetition). No disjunction handling anywhere; a refuted `&&` contributes nothing (3697-3700).
- **Interval analysis for integers** (checker.rs:4959-5561). Ranges are closed `BigInt` intervals. Unknown is the "neutral range" `i64::MIN..=i64::MAX` (5502-5507). Sources: literal, declared constraints, guard, refuted guards, requires, ensures witness bounds, and operand folding with recursion into nested binary operands after replacing a local by its initializer (5309-5374). No fixpoint and no budget; one pass per obligation.
- **Invert-narrow-refold** (checker.rs:5104-5160). For `place ± literal`, shift the value's range back onto the place, narrow the place by a guard, shift forward, intersect.
- **Constant folding** (checker.rs:5532-5560). `integer_literal_handle` folds a tree of integer literals joined by binary operators using `integer_binary_range` on point ranges; result must fit `i64`.
- **Arrival/assignment stability** (checker.rs:12-284). Builds, for a statement index, the list of dot-joined paths that statements `0..=index` may write, plus the names of locals declared before it; a set of read paths is preserved if none overlaps. Serves requires-narrowing and guard-narrowing.
- **Float reaching-store search** (checker.rs:3348-3450). Walks statements backwards from the use to the nearest store to the same place (identity is a vector of symbols, 3452-3467), also tracking, for a local of reference type, whether the reference's origin changed (`local_reference_origin_before_statement`, 3371-3393, 3424-3429).
- **Float guard range with NaN flag** (checker.rs:3606-3867). State is an ordered range plus `may_be_nan`. Strict lower bounds use `f64::next_up` (3853); strict upper bounds use an exclusive-maximum flag (3861); an impossible bound sets the empty range `1.0..0.0` (4080-4086). The result is used only if not possibly NaN and inhabited (3603).
- **De-hoisting** (lib.rs:737-783; checker.rs:3879-3981). A name that refers to a state local with a call-free initializer is replaced by that initializer so guards written on a temporary can be matched with the original place. The float code loops this to a fixpoint with a strictly-decreasing declaration index (3892-3916, 3926-3947) and checks no write intervenes (3950-3981).
- **Derivation cache and store** (checker.rs:2857-2978; derivation_store.rs:43-173). A `BTreeMap` from `ProofObligationKey` to arena handles of certificates; lookup re-verifies each candidate; optional capacity with refusal; invalidation by key or predicate.
- **Route census** (checker.rs:5562-5869). Counts per obligation kind how it was settled: kernel judged, kernel core refused, interval fallback, no certificate, diagnosed, decided elsewhere. Printed to stderr when `OMEGA_PROOF_MEASUREMENTS` is set (5769-5774).
- **Proof surface report** (lib.rs:109-649). One pass over root syntax items that records domains, propositions, contracts and every constrained type site as strings. It enforces nothing.

## Accepts or skips without proof

- **Uncovered falls back to the checker's own interval judgment** in all five placements (checker.rs:373-398, 547-577, 623-642, 689-715, 779-808). The authors' own route table calls this `interval_fallback` (5599-5600, 5662-5663). No kernel check follows.
- **Float ranges and named constraints never reach the kernel** (824-845, 5993-6251). The route table calls an obligation settled only this way `no_certificate` (5603-5604).
- **A target type with no integer range and no float range is not checked** beyond named constraints: `if let Some(target_range)` (350-352, 525-527, 603-605, 667-669, 740-742) and `return false` (832-836).
- **`type_constraints` returns an empty slice when the span lookup fails** (5525-5530: `unwrap_or(&[])`). An obligation whose constraint span is invalid is then accepted with no check. I cannot see another check for this.
- **Overwritten assignment is skipped entirely** (342-344). The scan ignores `Assembly` statements between the two assignments (454) and finds the state by state symbol across all machines without using the obligation's machine (425-427). Whether assembly can read the place I cannot tell.
- **The kernel's assumptions are whatever the checker collected.** The certificate proves "a fresh value `v` (id = obligation index) with these bounds lies in the target". That `v` is the program's expression, and that the bounds hold for it at that program point, is not part of what the kernel checks. Sources of assumptions: the value's declared type range (1800-1807, 1248-1254, 1514-1517), guard conditions (1255-1257), refuted guards (1258-1260), surviving `requires` (1072-1090), and `validation`'s arrival interval (1040-1055).
- **Declared types are trusted as ranges**: `integer_range_for_value` returns the declared constraint range for any non-literal (4997-5000); `float_range` falls back to the declared float range (3321, 4109-4114); a declared float range also clears the NaN flag (3547). I cannot see in this slice where the declared range of the source value is itself established.
- **A cache hit returns Certified without building a certificate for the obligation in hand** (939-945). See Surprises.
- **An accepted fact whose mathematical core "Refused" would still count as Certified** (951-955 returns Certified for any `Ok`; 5788 counts the refusal). The route table names this `certificate_core_refused` (5600-5601).
- **`collect_read_place_paths` ignores every node kind it does not list** (276: `_ => {}`), including calls and their arguments. A state-guard condition containing a call therefore has no recorded reads for the call and passes the stability test (150-173). `requires` conditions are protected by `stable_expression`, which rejects calls (6298, 6375); guard conditions are not. `expressions_equivalent_for_proof` then treats two calls with the same target and equivalent arguments as the same value (4863-4890). I cannot see another check.
- **Invert-narrow-refold has no arithmetic-domain test** (5104-5160), while the certificate version of the same rule refuses non-exact and `wrapping` arithmetic (1489-1500). For a wrapping `x - 1` under guard `x <= 10` the interval version yields `0..=9`. Cannot tell whether a wrapping value reaches this path.
- **`requires` narrowing sees through casts**: when the value is `cast(x)`, a bound on `x` is applied to the cast's range (6422-6429) with no check of what the cast does to the value. Cannot tell whether casts are value-preserving here.
- **Unknown is `i64::MIN..=i64::MAX`** (5502-5507). `guarded_integer_range_for_transition_argument` starts from it when nothing is declared (5039-5040), so an undeclared value narrowed only from below is treated as at most `i64::MAX`. Cannot tell whether a `u64` value can arrive with no declared range.
- **`operand_is_unsigned` reads the field type from the first machine in the program** whose attached data has a field of that name, not from the obligation's machine (5460-5474; the obligation parameter is discarded at 5433). A wrong answer raises a minimum to 0 (5221-5225, 5335-5339).
- **De-hoisting without a write check in integer code.** `dehoisted_initializer` (lib.rs:765-783) replaces a local by its initializer if the initializer has no call; it does not check that the local is immutable or that the initializer's places were not written since. Integer callers use it directly (checker.rs:4765-4774, 4809-4819, 5356). The float code adds the missing check (`stable_initializer`, 3950-3981). Cannot tell whether hoisted locals are always compiler-made and immutable.
- **Contradictory facts are dropped silently**: `refine` returns the un-narrowed range when conditions make it empty (6352-6353); `contract_refined_certificate` discards the contract facts (1099-1101). Both then judge the wider range, which is the cautious direction.
- **`BoundedValue` and `GuardedTransition` obligations are passed over** (6619: `=> {}`), counted as `decided_elsewhere` (5710-5712). Where they are decided is outside this slice.
- **`exact` is satisfied by any declared integer range** and `finite` by any integer range or literal (6238-6240, 6107); `wrapping` by any integer literal (6114).
- **`float_range` accepts a float literal without checking its format against the destination** (3310-3313), while `float_range_at` requires `literal.landing() == Some(format)` (3416, 3440).
- Cautious defaults, for completeness: every unrecognised condition shape returns the range unchanged (4734, 4754, 4776, 4830, 5074-5081, 3695, 3740, 3812-3816, 6401, 6431); unknown statement kinds refuse or stop the scan (90, 3344, 3600, 507); missing call-frame information gives no conditions (190, 6280-6282); `expression_contains_call_node` answers false for node kinds it does not list (lib.rs:915); `expression_type_reference` answers `None` for them (lib.rs:713).

## Surprises

1. **The certificate cache is never used outside tests.** The only production entry, `check_proof_plan_with_decisions`, passes `None` for the cache (checker.rs:6568). A search of the old tree finds `ProofDerivationCache::new`/`with_capacity` only in the tests at 2400, 2429, 2445, 2508. So `derivation_cache` (2857-2978) and all of derivation_store.rs are test-only code, and the headers that say certificates are "cached" and "persisted" (checker.rs:9, lib.rs:9-10, 27) describe something the compiler did not do. The store header also says "Persistent" and "We serialize" (derivation_store.rs:2-4); the file holds an in-memory `BTreeMap` and arena and has no serialization.

2. **A cache hit would have verified the wrong thing.** `recheck` calls `candidate.verify()` (2951), which checks the stored certificate against the obligation, assumptions and context stored inside that same certificate (899-907). Nothing compares them with the obligation being checked now; the only link is the string key. The test at 2396-2422 shows it: certificates for "300 in 0..5" and "5 in 0..10" are filed under the key of an unrelated `count` obligation, and the second "still discharges the leg".

3. **What the kernel re-decides is narrow.** For every non-literal value the certificate is about a fresh atom numbered by the obligation's position in the plan (6583, 1103, 1244, 1525, 1817). The kernel confirms that the stated assumptions imply the target bounds. Whether those assumptions are true of the program's value at that point (guard still holds, no write in between, declared type honoured) is decided by the checker and by `validation`, not by the kernel. The clearest case is `interval_premise_certificate` (1032-1056): `validation::arrival_integer_expression_bounds` computes an interval, the checker confirms it fits (1044), wraps it as two assumptions, and the kernel confirms that `[a,b]` inside `[c,d]` implies the bound. The census then counts this as `certificate_kernel_judged`.

4. **Interval results leave this crate as "proved" ranges.** `proved_assignment_integer_range_with_context` (5396-5409) is public and returns the output of the interval analysis, with no kernel involvement; `pipeline/05_typed-trees-to-checked-trees/src/values.rs:3579` calls it. Separately, the range that `check_bounded_assignment` returns into `ProofDecisions.integer_assignments` is the target type's range, not the value's (353, 413-414, 6613-6616).

5. **Dead arm.** `closed_math_term` handles `ExpressionNode::Name` by calling `integer_literal_handle` (1930-1933), but `integer_literal_handle` only matches `Integer` and `Binary` and returns `None` for everything else (5536-5558). Named constants never become closed terms.

6. **Dead plumbing.** All five check functions take `_recipe_obligations` and ignore it (338, 519, 597, 661, 734); `ProofDecisions.constant_recipe_obligations` is therefore always empty (6578, 6644). `operand_is_unsigned` takes and discards its obligation (5433). `call_expression_return_type` ignores `_machine` and `_state` (lib.rs:847-854). The four `if discharge_declared_float_range(...) {}` statements have empty bodies (581-588, 646-653, 719-726, 814-821).

7. **`operand_declared_primitive` looks in the wrong machine** (5460-5474): for `self.field` it returns the field type from the first machine in the whole program whose attached data has a field with that name.

8. **The placements do not get the same rule.** 
   - `positive` / `non_negative` can be proved from a guard for transition arguments (6145-6148) and assignments (6183-6187), not for call arguments, returns or initializers.
   - `exact` can be proved from a single-point range for transitions and assignments only (6150-6155, 6189-6194).
   - `finite` for a return uses the guard-narrowed float range (6057); for a transition argument it uses the un-narrowed one (6139), although a guarded transition version exists (3469-3486) and is used for the float range check (819).
   - Only call and transition arguments try the literal-arithmetic route (`anonymous = true` at 677, 750; `false` at 361, 535, 1023).
   - Only assignments use state-guard narrowing, ensures witness bounds and the `a - b` rule; only assignments and returns use `requires`; only transitions use refuted exit guards for integers.
   - After a failed integer check, initializer and call-argument code returns early and skips the float check when no interval was known (573-575, 711-713); the others do not.

9. **The six condition walkers do not accept the same conditions.** `collect_guard_bounds` and `apply_handle_condition` handle a leading `!` (1342-1347, 4727-4732); `apply_source_condition`, `collect_contract_bounds` and `requires_conditions::apply_condition` do not. The two negated walkers accept only `subject cmp literal` with the subject on the left (1400-1405, 5076-5081), while the positive walkers accept either side. `apply_condition` alone sees through a cast (6422-6429). `apply_source_condition` alone de-hoists (4765-4774). Matching the subject uses `expressions_equivalent_for_proof` (text) in the guard walkers and `same_place` (valid symbols plus structural equality) in the contract walkers.

10. **Calls are treated as values.** `expressions_equivalent_for_proof` says two call expressions are the same if target, receiver and arguments match (4863-4890). A guard `f(x) < 10` can then bound a later, separate `f(x)`.

11. **An accepted fact can carry a refusal.** An `AcceptedFact` can carry `MathematicalCoreDecision::Refused` (5788 counts that case; the doc comment at 5600-5601 describes it as admission checking the rules while the core refuses the family; the test at 5908-5914 builds such a fact by hand). The checker treats any `Ok` from `verify` as Certified (951-955). Whether `verify_obligation` returns this for the certificate shapes built here is outside the slice.

12. **The census can undercount kernel-decided obligations.** `record_route` reports `interval_fallback` whenever any certificate attempt for the obligation was Uncovered (5662-5663). A transition argument whose first attempt is Uncovered and whose guarded attempt is Certified (762-771) is counted as interval fallback. The doc comment says this ordering is intended (5597-5598). Rows `bounded_value` and `guarded_transition` (5620, 5622) can only ever record `decided_elsewhere`.

13. **Float reasoning is more careful than the integer reasoning beside it.** It identifies places by symbols (3452-3467), tracks NaN separately and never clears it on a refuted ordering (3817-3828), uses `next_up` for strict bounds (3853), checks the literal's format (3416, 3440), follows a reference-typed local back to its origin and gives up if the origin changed (3371-3393, 3424-3429), and checks writes before de-hoisting (3950-3981). The integer side has none of these.

14. **A guarded transition certificate is refused for literal arithmetic.** `guarded_transition_certificate` returns `None` when `validation::land_anonymous_integer_expression` succeeds on the argument (1187-1204), after `bounded_integer_value` with `anonymous = true` has already had its turn on the same argument (743-753).

15. **Arrival bounds, when present, pre-empt the other return routes.** `state_return_certificate` returns the result of `interval_premise_certificate` directly (1000-1015); if the arrival interval does not fit, the declared-range and contract routes are not tried, and the fallback `return_arrival::integer_range` also returns the arrival interval first (6457-6468).

16. **Machine-level `requires` count only in the first state** (6283-6290: `is_entry` is "state is `states.first()`"). In any other state they are not used, even if nothing wrote the places.

17. **A return is recognised as a trailing expression statement**: both return routes require `statements[statement_index]` to be `StatementNode::Expression(value)` with the same handle (992-999, 6451-6456), and both require the context to point at the same program object by pointer equality.

18. **The checker carries its own instrumentation of the three properties.** The route table (5595-5623) is the authors' measurement of property 1, naming `interval_fallback` and `no_certificate` as non-evidence routes and citing `check_on_lowered_form.md`.

19. `proof_node_count` (5793-5869) lists 28 kernel proof rule variants. This checker emits five of them: `ConjunctionIntroduction`, `Assumption`, `Primitive` (with the judgments `ClosedIntegerRelation` and `Truth`), `IntegerLessOrEqualTransitivity`, `IntegerAffineBound` (1664-1686, 1859-1920).

20. lib.rs `proof_surface` skips `Const`, `Capability`, `Use`, `Measure`, `Conformance`, `Module` and `Package` items (lib.rs:114-115, 190-194), so constrained types in constants, and anything inside a module item if `root_items` does not flatten modules, are missing from the report. It folds `EnsuresForResultCase` into `Ensures` (lib.rs:414-416).

### The three sampled properties against this slice

- **Property 1 (own yes/no rather than kernel evidence): mixed, and measured by the code itself.** The kernel is called (899-907) and can refuse (the `Rejected` arm). But all five placements accept on their own interval judgment when no certificate was built; floats and named constraints never reach the kernel; overwritten assignments are skipped; and the kernel's premises are the checker's own findings (Surprise 3).
- **Property 2 (identity by text): strong evidence** in the integer and stability code (see Identity by text), with symbol-based counter-examples in the float code and in `requires_conditions::same_place`.
- **Property 3 (one rule per placement): strong evidence.** Five obligation types drive five copies of the check, the diagnostics, the range functions and the named-constraint functions, and the copies have drifted apart (Surprises 8 and 9).
