## What this code is for

The Rust file belongs to stage 04 (typed trees to typed trees), the preparation stage that runs before the checker. It has three modules. `selection` decides, for every call to a generic machine, which type, constant, machine, evidence and runtime-value arguments fill the callee's static parameter slots; it collects "proposals" from explicit `[...]` arguments, from the runtime argument types, and from the expected return type, then merges them per slot and flags conflicts (`selection_and_reflection.rs:7-1791`). `reflection` rewrites calls to the toolchain's reflection declarations (schema query, field visitation, active-case visitation, record inspection) into ordinary generated statements, helper machines and struct literals (`selection_and_reflection.rs:1793-3125`). `result_locals` settles the types and roles of compiler-inferred locals: match/dispatch subjects, operand captures for indexing, primitive locals initialised from a reference-returning call, and locals initialised by generic calls (`selection_and_reflection.rs:3127-4305`). None of this file accepts or rejects proofs; it produces selections, flags, rewritten trees and a small set of structural diagnostics.

The two Markdown files document stage 05, the deleted checker itself. `README.md` is a dense statement of what the checker enforced and, just as often, what it did not yet support: fact ownership, flow and range fixed points, the termination-ranking "tiers", borrow and loan judgments, lifetime correspondence, crash routes, entry-contract readers and what the checker handed to lowering. `authored_selections.md` describes how the compiler recorded which declaration each source use selected, for package-boundary review. The prose is the authors' own inventory of rules, so I list its rules in a second table.

## Mechanisms

- **Structural matching of a required type against an actual type** (`infer_static_bindings`, selection_and_reflection.rs:1095-1275). It walks both type-reference trees in step: a required name that is a template type or const parameter yields a proposal; references, constrained types, slices, fixed arrays and generic applications recurse into their parts; a named actual that is a generic instance is expanded to its application (1146-1165). It is one-directional, has no occurs check and no substitution environment: it only appends proposals, and agreement is decided later. Anything that does not match a listed shape yields nothing (1273). Serves generic machine calls.
- **Proposal merge with conflict flags** (`proposal_bindings`, 745-897). One vector per slot category; first proposal wins the slot, later ones are compared and set `conflicted` plus the first `conflict_reason`. Serves the same feature.
- **Slot classification of explicit arguments** (`collect_machine_proposals_for_callee`, 35-327). Explicit arguments are assigned by their own kind to the next free slot of that category, each category with its own counter (50-53), so position among arguments of other categories does not matter.
- **Specialization grouping** (`unique_complete_selections`, 981-1046). Groups complete selections under a `SpecializationKey` of normalized type identity text, const identity text, machine symbols and evidence fingerprints. Linear search over groups.
- **Worklist over a type tree** (`names_type_binder`, 1055-1093) with a visited list; follows generic instances.
- **Contract scope collection** (`contract_expression_scopes`, 357-419): gathers expression trees of every machine and state contract fact, sorts and de-duplicates by (expression, machine, state).
- **Three-pass call discovery** (`collect_call_selections`, 1580-1790): statement calls; expression calls reachable from each state's signature types, owned data types, local types, statements and proof-output calls; then every remaining call expression in the table that is not a contract expression or an authored "source recipe".
- **Reflection by expansion** (`elaborate_calls`, 2556-2859; `active_case::emit`, 1816-2176; `emit_fields`, 2988-3124). One reflection call is replaced per invocation of `elaborate_calls` (it returns `Ok(true)` after the first rewrite at 2578, 2618, 2856), so the caller must loop. Field visitation unrolls into one callback call per field, each preceded by a `FieldInfo` struct literal and a field loan. Active-case visitation builds a helper machine with an `entry` state that has one guarded transition per variant and one `case#i` state per variant.
- **Place aliasing for dispatch subjects** (`replace_place_aliases`, `normalized_place_aliases`, `replace_place_alias`, 3391-3507). Alias lists are sorted by symbol handle and searched by binary search; every `Name` expression in the whole expression table that resolves to an aliased local is replaced by a copy of the place expression, with member projections re-applied (3487-3503). Guards are excluded through a sorted guard list.
- **Use-agreement inference for operand captures** (`operand_captures::adapt`, 3588-3720). For each capture it collects the type each index/range use would read; if any two uses differ, or the capture is used anywhere other than as an index operand, it keeps the raw type.
- **Budgets and fixed points the prose names**: range-state fixed point with a 64-round budget (README.md:200-205); logical conversion with 4,096 work units and depth 64 (README.md:721-722); crash-summary call-graph fixed point (README.md:588-590); mutation-summary dirty-round propagation (README.md:265-267); generic provider specialization alternating with machine specialization to a fixed point (authored_selections.md:60-63).

## Identity by text

- A closed constant argument is bound by finding a named type reference with an invalid symbol whose **name equals the decimal text of the value** (selection_and_reflection.rs:86-92). Same for a literal spelling (164-167) and a fixed-array length literal (1299-1308).
- Template parameters are carried as `(SymbolHandle, String)` (523-524) and matched by `parameter_symbol == symbol || (both invalid && names equal) || parameter_name == name` (1111-1117, 1127-1133). The last disjunct makes the name alone sufficient, whatever the symbols are.
- Generic applications match when base symbols are equal **or the base names are equal** (1247-1250).
- `same_domain_family` falls back to name equality, or equality of the last `::` segment, when either symbol is invalid (1362-1371).
- `type_reference_is_any_generic_parameter` treats an unresolved named reference as generic if **any machine in the program** has an unresolved type parameter with the same name (932-947).
- Evidence-slot conflict compares `display_name()` strings (880-881).
- `SpecializationKey` type and const arguments are `normalized_type_identity_text` strings (1005-1020); two specializations are the same when those strings are equal.
- Reflection finds vocabulary fields by string: `"stable_number"` (1921), `"member_identity"`, `"owner_identity"`, `"owner_application"`, `"name"`, `"declaration_position"`, `"has_stable_number"` (1968-1994), `"storage"` (2442), `"qualified_type"`, `"case_identity"`, `"is_erased"` (3016-3049); `info_field` compares `field.name.as_str() == field_name` (2965).
- A case description is found by `case.name == variant.name.as_str()` (1963).
- Generated names: `__reflect_active#{state index}#{statement index}` (1860-1864), `case#{index}` (1883), `__reflect_query#{state index}#{expression index}` (2257-2261), `__reflect_{role}#{expression count}` (2930-2933), `__reference_result#{symbol index}` (3888). These label symbols created by handle; nothing in this slice looks them up by text.
- The conflict message renders bindings with display text, identity text and a `::`-joined supplier path (899-918). It is diagnostic text only.
- Against the property: reflection declarations are recognised through the core vocabulary catalog by symbol, and the comment says "a lookalike user declaration stays ordinary" (2539-2543). Captures are matched by symbol (3733-3735), aliases by symbol handle (3456-3461), and `replace_place_alias` notes "no index is encoded in a generated name" (3476-3478).
- The prose repeatedly denies name-based identity, which shows the authors were pushing against it: "Same-spelled locals or fields from another owner cannot supply a missing identity" (README.md:706); "a same-spelled or repeated call is not its result" (README.md:680); "A field spelled `len` keeps its declared type" (README.md:729-730); "User method names grant neither completeness nor an injected whole-receiver write" (README.md:269-270); "a `- 1` spelling alone grants no decrease proof" (README.md:323); "Selected user operators do not inherit builtin meaning from spelling" (README.md:725-726); "rather than trusting display strings or digests" (authored_selections.md:58); "never name matching" (authored_selections.md:103); "Same-spelled cleanup on another owner does not match" (authored_selections.md:86-87).
- The prose also records that text forms of storage exist: the `semantic` area's `places` "renders the storage" (README.md:114), and diagnostics come "from retained handles, not the normalized witness's fallback display labels" (README.md:344-345).

## Surprises

1. **Name alone identifies a template parameter.** In `infer_static_bindings` the lookup ends with `|| parameter_name == name.as_str()` (selection_and_reflection.rs:1116, 1132), which makes the two more careful conditions before it redundant: any required named type whose text equals a parameter's name is treated as that parameter, even when both symbols are valid and different. The sibling `infer_fixed_array_length_binding` has the careful form without the extra disjunct (1289-1292), so the two disagree.

2. **Binding a computed constant depends on a literal's text already existing.** A closed const value is bound only if some named type reference with that decimal text is already in the table (86-98, 1299-1308). If nothing wrote that number, no proposal is made and nothing is flagged at this point.

3. **Explicit type arguments are not checked against inferred ones here.** 1515-1522 drops the inferred proposal instead of comparing. `authored_selections.md:54-55` states the opposite policy for operator applications: "Explicit arguments must corroborate operand-derived bindings, not fill missing inference." These are different mechanisms, but the two policies differ. Const proposals are all kept (1523) and so are compared.

4. **Two selections at one site are settled by counting.** `upsert_selection` keeps whichever has at least as many bound slots (954-979); disagreement between them is never examined.

5. **Unreachable code in field visitation.** 2656-2663 returns an error unless author and subject share a source package, so the `ForeignScope` branch at 2676-2683 can never run, and the `!subject_data.is_public` test at 2647-2650 only changes which message a foreign author gets. Schema queries (2410-2417) do allow foreign scope.

6. **Unreachable filter in `refresh`.** The condition at 4196-4201 repeats the four conjuncts of 4168-4171, which already `continue`d, so 4196-4203 cannot fire. It reads as a leftover from a time when the first filter was weaker.

7. **Helper machines copy different properties of the owner.** The expression-call helper copies `suspends` and `blocks` (2278-2279); the active-case helper does not (1892-1902). The active-case helper calls user callbacks, so if a callback suspends, the helper's own flags say otherwise. Cannot tell whether a later stage recomputes them.

8. **The active-case entry state has no fallback transition.** It has one `When` transition per variant (2137-2141) and nothing else; exhaustiveness is left to whatever judges the generated machine.

9. **One error message is used for three vocabularies.** `info_field` always says "incomplete FieldInfo vocabulary" (2967-2969) though it is also called for `CaseInfo` (1976, 1986, 1990) and `TypeSchema` (2442).

10. **Reflection rewrites one call and returns.** `elaborate_calls` returns `Ok(true)` after the first rewrite (2578, 2618, 2856), so a state with N reflection calls needs N passes, each recomputing selections outside this slice.

11. **Alias replacement scans the whole expression table.** `replace_place_aliases` visits every expression in the program for each call (3399-3414), not only the state that owns the alias.

12. **A "logical" dispatch subject is deleted after substitution that can decline.** `replace_place_alias` returns without replacing when the occurrence has no pattern component (3473-3475), but the local is removed regardless (3339-3354). If such an occurrence exists it would name a deleted local.

13. **`reference_observations::materialize` returns `Result` but has no error path** (3834-3836, 3923).

14. **The builtin index read-through lists eight integer types by hand** (3808-3815). A reference to any other primitive keeps its reference type.

15. **Contract-expression handling leaves a gap I cannot close from this slice.** `collect_contract_expression_handles` adds the expression trees of every proof fact in the program (447-451). `collect_call_selections` skips all contract expressions (1677, 1742) if its caller passes that list, while `collect_contract_call_selections` only handles expressions tied to exactly one machine/state scope (1544-1549). Calls inside proof facts that belong to no such scope, or to two, get no selection from either function.

16. **The prose reads as a ledger of exceptions.** A large share of `README.md` states what a tier does not do or what "remains" or "still needs" support (for example 156-157, 246-250, 282-284, 369-371, 431-433, 579-580, 623-629, 671-673, 684-685, 691-692, 736-737, 768-770). The documented checker is a set of recognisers for specific program shapes, with refusal outside them.

17. **The prose describes source-only acceptance that later stages cannot replay.** Custom-view termination, crash routes and state-exit handoff are each said to pass source checking while having no Terminal or native evidence (README.md:246-250, 328, 375-376, 390, 772-776).

18. **Stale or inconsistent references in the prose.** `README.md` cites fixtures under `tests/omega/pass/...` and `tests/omega/fail/...` throughout and suggests `cargo run -p omega` (324, 372, 377). Its module table lists both `semantic/mod.rs` and `semantic.rs` as existing (113-114), and links `checks::borrows::*` modules to single flattened files such as `src/checks_borrows.rs` (548-550, 633-654), so the table of module paths does not match the file layout the links use.

19. **Budgets are fixed numbers.** 64 rounds for the range-state fixed point (README.md:204-205) and 4,096 work units at depth 64 for logical conversion (README.md:721-722); on exhaustion inference is withheld, which refuses rather than accepts.
