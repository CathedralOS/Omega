## What this code is for
This file is the old checker's validation of machine calls, in statement position and in expression position (header comment calls.rs:1-5). It decides whether a call resolves to something callable, whether its arguments match the callee's parameters, whether a result is used correctly, and whether recursion is allowed. It has sub-modules for: re-validating a "closed" trait-requirement dispatch record (24-448); argument range and narrowing checks (451-639); gates for asm intrinsics and receivers (640-961); calls through `dyn` selectors (962-1296); an expression walker (1297-3611) with its own call dispatch; generic bounds (3612-3837); trait requirement calls (3838-4244); asm operand constraints (4250-4397); static type-argument inference (4465-4795); receiver and receiver-less statement calls (4799-5265); recursion and termination of proof machines (5266-6029); discarded results (6030-6071); a memo of call signatures (6073-6180); unit-return admission (6181-6554); and the start of write-frame/alias analysis (6555-7570). Almost every function takes a `&dyn crate::CheckingInput` and pushes `Diagnostic::error` strings into a `Vec`. Nothing in this slice calls a proof kernel or builds a certificate. The result is the diagnostics list, plus a few returned records (`ValidatedBoundaryOperatorApplication`, `ValidatedSelfCallDescent`) that later stages consume.

## Mechanisms
- **Closed dispatch re-validation (calls.rs:31-447).** It re-derives, from tables, that a recorded dispatch (`StaticRequirementDispatch`) is exactly what the program's conformance, specialization and capture tables say. It walks a chain of executable templates with a `visited` list (89-114), re-closes the conformance application and compares by value (367-376), and compares operands position by position. Positions of evidence occurrences are found by index among `Conformance` bindings (289-366). No budget; the walk is bounded by table size. Serves generic trait requirements and closure-like captures.
- **Descent fixpoint for sub-state parameters (5670-5796).** It computes a set `descending` of sub-state parameters. A parameter joins the set when every transition into its state binds it either to a strict subterm of the measure or to a parameter already in the set, and there is at least one binding site. It loops until no parameter is added (5718-5787). No explicit budget; the set only grows. Serves `terminates by <param>` on proof machines with multiple states.
- **Strict subterm walk (5798-5867).** From an argument, it follows `Member` receivers and immutable aliases (`immutable_value_origin`), with a `seen` list for cycles, until it reaches the measure parameter. It requires at least one member step. If an alias was followed it also requires the measure be an immutable non-reference parameter and every receiver type be a non-reference.
- **Completion-leaf search (6285-6332).** An iterative traversal of `Match` arms that checks every leaf is a call satisfying a predicate; uses a `BTreeMap` keyed by (arena index, generation) to detect shared/cyclic nodes. Serves unit-return admission.
- **Unit-return closure (6491-6540).** A worklist over machines to decide whether any transitive completion returns a non-unit value (`has_inferred_value_return`).
- **Static type-argument inference (4576-4714).** Binds Type and Const type parameters from the explicit static tuple first, then infers remaining ones from value-argument types through `machine_parameters::infer_call_type_arguments` (4681-4702), then verifies const selections against the bindings. Returns `None` on any mismatch. Serves generic machine calls.
- **Alias origin computation (6819-7386).** `stable_alias_initializer_origins` computes a set of `FramePlaceOrigin`s (a string path, a precision, and a source place) for a reference initializer. It recurses over Borrow, Call (transparent results, boundary results, requirement results), Indexed, Member, Match, recast Cast; a macro threads 12 parameters. `Match` takes the union over arms (7138-7146). Serves write-frame analysis (which storage a call may write through references).
- **Assignment-destination currency (7414-7545).** For an assignment through references, at each depth along the path it peels reference shells and requires either that no earlier write overlaps the path, or the reference binding is preserved before and after. Overlap uses `frame_paths_overlap` on strings (7526).
- **Memo of call destinations (6079-6118).** A table of `OnceLock` rows sorted by symbol arena index and generation, binary searched; falls back to recomputation when not found (6113).

## Surprises
- Every error from the first module is a `&'static str`, but the public wrapper `closed_requirement_dispatch_is_valid` (31-38) returns only `bool`. The module name and wording ("capture", "supplying application", "telescope", "commitment") describe a trait-requirement dispatch re-check at 400+ lines that duplicates information the typed program already recorded; it re-derives and compares instead of consuming a certificate. `application_commitment` and `application_report_fingerprint` (46) are the only record-level integrity values; they are checked for being nonzero only, not recomputed in this slice.
- `user_asm_contract` (4271-4283) panics (`panic!`, `assert_eq!`) if a mnemonic accepted earlier is missing or not user-checked; `validate_asm_operand_constraint` (4321-4322) calls `.expect(..)` on a primitive name. These are reliance on invariants from another module, as panics inside the checker.
- The termination check for self-recursion in proof machines (5377-5457) recognises one exact syntactic shape: `transition when m > 0 -> f(m - 1)` (optionally `== true`), with literals `1` and `0` (5410-5411, 5455-5456). It is not an interval or ranking proof; the generic route is `proof_edge_strict_decrease_judged` (5603). Slice-length descent has another exact shape (5302-5363). The error text (5645-5651) lists these shapes as the accepted forms.
- `strict_subterm_of_measure` (5798-5867) accepts any member projection of the measure parameter as a "strict subterm"; at the code level it does not check which field is recursive. Whether the type system makes every field smaller is not visible here.
- `validate_proof_machine_recursion` computes `entry_name = machine.name.as_str()` (5501) from the machine name, not the entry state name, and uses it in the diagnostic (5646).
- `validate_self_recursive_call_positions` ends with `let _ = state;` (5921), an unused parameter. `recursive_entry_path` (5940-5973) walks the lexical parent chain of the machine to catch calls to enclosing machines.
- `statement_returns_reference_without_effects` (6757) decides "is the last statement" by pointer identity `std::ptr::eq(last, statement)`.
- Two modules, `signature_queries` (6073-6180) and `unit_returns` (6181-6554), use two different identity mechanisms for the same program: dense symbol handles with generation (binary search, 6108-6114; `BTreeMap` coordinates at 6295-6301), and in the same file strings (name lookups at 6057, 1953, 3458, 5184).
- `scan_target` (2393-2425) runs the scan with a private diagnostics list and then drops from it every message that equals a message `unknown_field_read_reports` would generate. In effect an unknown-field write target gets its error from a separate path, and suppressed diagnostics are deleted by string equality.
- `validate_family_tuple` (1150-1266) accepts runtime-value arguments and defers membership to "the call's own proof" (1253), but this code never verifies that such a proof exists.
- `validate_named_float_to_integer_call` (3556-3610) is invoked only for named operator calls (3306); the conversion path for non-operator float casts is elsewhere (`validate_cast_types`, `validate_range_cast_at_use`, 2754-2772).
- The diagnostic "machine ... cannot prove unqualified `op` operand ... finite and truncates" (3601) tells users to use `T in Trapping` or `T in Saturating`, a capability documented only in message text here.
- `report_bodyless_boundary_symbol_call` (3665-3757) lists nine compiler-realized exceptions as a conjunction of negated booleans; adding a tenth kind of compiler-provided realization requires editing this conjunction (3738-3751).
- `completion_calls_all` (6285-6332) treats an empty `Match` and any non-call, non-match leaf as failure and requires at least one call; so a unit-return completion by a literal `()` or a block is not admitted by this function.
- Alias analysis (6555-7570) mixes symbol-based facts (`source.root` is a `SymbolHandle`, `builtin_coordinates`, `recasts`, `result_home`) with string paths (`path: String`, `precision`); `binding_preserved` (7391-7412) compares records by symbol and segments while `frame_paths_overlap` (7526) compares strings.
