## What this code is for

This file is the root of the "terminal unit" planner inside the old checking stage. It runs after the source checks and turns each machine body, plus the facts the checks already produced (`CheckFacts`), into an executable plan (`CheckedUnitEffectPlans`) that the next stage lowers to Terminal Psi (ETU:1-7, 7078-8023). The header says its conditions "describe implementation coverage, not additional language rules" (ETU:4-7): a body it cannot plan gets a "plan gap" record, not a diagnostic, and the gap is reported only if lowering later demands that body (ETU:41-47, 2966-2974).

The entry point `build_checked_unit_effect_plans` (ETU:7078) builds plans for boundary machines, picks one of two routes for each checked body (single-state "sequence" or multi-state "graph", ETU:8167-8213), plans bodies in parallel with a merge that must equal the sequential result (ETU:7139-7256), selects cleanup actions, prunes every body whose callee has no plan (ETU:7455-7465), and then keeps only the type shapes the surviving plans mention (ETU:7476-7998).

The inline modules in this slice supply pieces of that: atomic memory events (ETU:151-623), moving values out of and back into borrowed storage ("borrowed windows", ETU:624-1951), byte-sequence operands (ETU:1952-2153), the callee-availability closure (ETU:2156-2688), gap records with source spans (ETU:2966-3112), erasing non-escaping `&mut` locals into their referent ("receiver aliases", ETU:3113-3448), scalar call target matching (ETU:3525-3935), and a query that follows where an owned value moves through a body so cleanup can be chosen (`storage_transfers`, ETU:3938-6466).

## Mechanisms

- **Callee-availability closure** (ETU:2177-2286, 2400-2672). Gives each candidate body a dense index, records `(target, caller, site)` edges while scanning each body's operations once, then runs a worklist from the already-dropped bodies along reverse edges, dropping each caller with reason `Callee(target)`. No budget; terminates because each body is dropped once. Serves "the lowerer must receive a complete plan" (ETU:7, 29-39).
- **Windowed speculative planning** (ETU:7139-7256). Bodies are planned in rayon tasks against a fork of the shape collector, at most `threads * 4` ahead (`FORKED_BODIES_PER_THREAD`, ETU:7076). The merge loop accepts an attempt only if a change log admits its edits, otherwise it re-forks from the current position or plans in place. The comment records why: an unwindowed fan-out cost "more than 3.5 GB on top of 9.6 GB" for one test package (ETU:7157-7173).
- **Transfer summary algebra** (ETU:5430-5507). `Transfers` holds `possible` moves (with destinations), `definite` moved paths, and `after_production` (moves after the value was produced). `append` is sequencing; `alternatives` intersects definite paths across branches by path-prefix (`common_paths`) and unions possible ones. Serves ownership cleanup at return and at state transitions.
- **Value-graph traversal for custody** (ETU:5791-6398). `Query::operation`, `call`, `argument_transfers`, `value`, `value_kind` walk operations and the retained structural-value DAG to find where one source (a parameter, local, result or expression) is moved. Cycle guard is the `active` stack (ETU:5987). `through_prefix` (ETU:5617-5643) stops when a later store reinstalls the same local path. `parameter_vacancies` (ETU:5703-5775) reduces the result to maximal definitely-moved paths and maybe-moved paths.
- **Completion path enumeration** (ETU:4199-4518). Turns a body's terminator into a list of `(source exit, guards, outcome)` paths, one per return or successor edge.
- **Open-window ledger** (ETU:1249-1850). A vector of places moved out and not yet restored, keyed by canonical storage place; `bind_extraction` adds, `replace` removes those a store closes, `is_closed` checks borrowed ones at the end.
- **Storage-place rebase through reference locals** (ETU:1202-1241). Follows `let r = &mut x` chains to the underlying parameter; fixed cap of 16 steps, then silently stops.
- **Receiver alias chaining** (ETU:3370-3447). Collects erasable exclusive reference locals in declaration order; `resolve` substitutes at most `aliases.len()` times and stops at materialized storage.
- **Current home of a local** (ETU:2872-2964). Scans the operation list backwards to decide whether a local name currently means its own home or its initializer's result.
- **Type shape retention** (ETU:7476-7998, 8321-8400). Gathers every type identity mentioned by surviving plans into a `BTreeSet`, then `retain_transitive`. `retain_value_types` is a worklist over value nodes using a `Vec` for the visited set (linear `contains`, ETU:8331).
- **Gap span selection** (ETU:2994-3111). Picks statement, state or machine span, joins target and value spans when in one source.

## Identity by text

- A member is resolved from the receiver's type by its name string (`member.member.as_str()`) and then compared with the recorded member symbol (ETU:3193-3200).
- Field and case identities carry the member's name next to its identity: `CheckedMemberIdentity::of_member(case.identity, case.name.clone())` (ETU:554-555, 6224-6233).
- Machine binders are `(SymbolHandle, String)` pairs passed to shape registration (ETU:940, 1303).
- The reason a body has no plan is free text: `GapReason::Unsupported(Cow<str>)` with "composed control vocabulary" (ETU:2617-2619), "sequence cleanup actions" (ETU:7421-7423, 7439-7441), or whatever `&'static str` a builder returned (ETU:7107, 7365, 7382). All `storage_transfers::completion` failures are `&'static str` (for example ETU:4004, 4246, 4828).
- The place where a builder stopped is recorded by phase strings: `trace.phase("atomic access: writing place")` and similar (ETU:232, 244, 300, 490, 512, 585, 1449, 1578, 1611, 1678, 1704, 1713, 1748, 8103).
- Declaration ABI refusals are formatted strings stored in the plan row, with a suffix appended by string formatting (ETU:6992-6996, 7016-7039).

Evidence against the property in this slice: values and storage are otherwise identified by handles and numbers, not text: `SymbolHandle`, `ExpressionHandle`, `TypeIdentityId`, binding ordinals, statement indexes, `PlaceRoot`/`PlaceSegment` (for example ETU:718, 460, 3475, 5883-5897). Two further non-text identities are used: `symbol_key` (arena index, generation) (ETU:8025-8027) and memory address via `std::ptr::eq` to find which scope owns an operation (ETU:3591, 6034, 6099).

## Accepts or skips without proof

- Calls routed as `Dynamic`, `ActivationStorage` or `DescriptorTable` add no dependency and are never checked for an available target (ETU:2359-2364). Cannot tell whether another module checks them.
- A sequence body dropped by `install_sequence_cleanup` returning false gets no gap record (ETU:7389-7410, 7412, 7430). See Surprises.
- `resident_range_decision` is copied from `facts.proof.integer_assignment_at` into the atomic plan without looking at it (ETU:313-319, 398-404). Cannot tell what the consumer does with an absent or negative decision.
- A failed alias lookup becomes "no aliases": `aliases(...).unwrap_or_default()` (ETU:500-502). The place then keeps its unrebased root. Later type and path lookups still have to succeed; cannot tell whether they catch a wrong root.
- `resolve_storage_place` stops after 16 hops or on any failed lookup and returns the partly rebased place (ETU:1212-1240). No refusal. Cannot tell whether a longer chain is caught elsewhere.
- A local that fails alias formation is skipped and the scan continues (ETU:3391-3402).
- `transfers` uses formation statement 0 when the binding is not in the result table (ETU:5531-5534).
- An argument that is not owned by the queried source and is not a structural expression, or whose expression has no value root, yields "no transfers" (ETU:5946-5960). Cannot tell whether another check covers a missed move.
- `_ => {}` arms that contribute no transfers: other local bindings (ETU:5122), other store values (ETU:5137), other operations (ETU:5155), other value kinds including quotient forms (ETU:6395). `_ => Destination::Unknown` (ETU:5825).
- A pure scalar expression is assumed to move nothing (ETU:4930, 5162).
- An extraction from a parameter path with no referent crossing always owns its source: `Parameter { .. } => Some(true)` (ETU:6429).
- A value root whose call preparation fails is left out of the prepared rows (ETU:6616, 6864). A later `value_call` that needs the schedule returns `None` (ETU:6056-6064), so this case is caught for values that are followed.
- A result whose owner cannot be found is left out of `results` but its operation is kept (ETU:6934-6939).
- "Freely discardable" trusts the type's `no_code_affine_cleanup` and `descriptor_cleanup` flags (ETU:1731-1738).
- `is_shared_borrow` and `initialized_local` classify custody from the declared type alone (ETU:2776-2854).
- Erased parameters are excluded from the position count by their declared relevance (ETU:3859-3863).
- Contract agreement between caller and callee is equality of a stored fingerprint and commitment (ETU:3700-3701, 3755-3756, 3888-3889), not a proof check.
- Type retention skips silently when a shape cannot be added (ETU:7802, 7857-7862, 7879-7884, 7913-7917) or a lookup fails (ETU:7788-7790, 7846); binders default to empty (ETU:7910, 8339).
- Boundary machine and body construction failures become gaps, never diagnostics (ETU:7101-7118, 7251-7253); gaps are reported only on demand (ETU:2972-2974).
- A refused declaration ABI is stored as an `Err` row, "not a failed source check" (ETU:6967, 7041-7051).
- A machine whose nominal cleanup plan fails to build is omitted (ETU:8247-8256); that builder is outside this slice and takes a diagnostics vector.

Every decision is the planner's own comparison or a call into `validation`, `checks`, `flow` or sibling planner modules. ## Notes the authors left

- "these catalogs describe implementation coverage, not additional language rules. The lowerer must receive a complete plan, never a partly recognized body." (ETU:5-7)
- "their current coverage differs, so a failed candidate is not permission to omit its unsupported statements." (ETU:26-27)
- "Every checked-body machine left without a plan carries one gap" (ETU:41-43); "The builders still return `Option`; the construction trace names the phase and statement where they stopped." (ETU:45-47)

- "the lowerer never recognizes an initializer/call/store pattern to manufacture replacement semantics." (ETU:55-56)
- "Treating these as one extraction-and-repair operation invents debt for ordinary locals." (ETU:57-59)
- "a separate whole-root admission mode would make the value's custody depend on its spelling." (ETU:638-640)
- "Mutable selector spelling alone cannot prove agreement with an earlier captured selection." (ETU:650-651)
- "Mutability is source admission, not storage identity." (ETU:854-855)
- "Mirrors the checker rule that windows key on the resolved storage place, not the access route." (ETU:1199-1200)
- "A linear replacement may repair a vacancy, but cannot overwrite a live obligation. Decide that from the exact place's checked custody, not from the replacement's multiplicity alone." (ETU:1429-1431)

## Surprises

1. **A sequence body can vanish with no gap, contradicting the header.** `install_sequence_cleanup` returns `false` when `temporary_actions::install` fails or the last operation is neither `Complete` nor a stopping operation (ETU:7389-7410). The `retain_mut` calls for partial-affine and sequence bodies use that result directly (ETU:7412, 7430) and record a gap only in the other arm (`_ =>`, when cleanup selection itself failed). So the body is removed and nothing is added to `cleanup_gaps`. The composed path does record a gap for the same install failure (ETU:7355-7368). The header promises "Every checked-body machine left without a plan carries one gap" (ETU:41-43). Callers of the vanished body are then dropped with `Callee(machine)` (ETU:2243).
2. **Sequence cleanup failures lose their reason.** `temporary_actions::operations(...).ok()?` discards the error text (ETU:7276-7286); the gap says only "sequence cleanup actions" (ETU:7421, 7439). The composed path keeps the text (ETU:7335, 7343, 7382).
3. **This "coverage only" planner re-decides ownership rules.** Linear overwrite refusal (ETU:1758-1760), double move-out refusal (ETU:1396-1402), unrepaired borrowed hole (ETU:1847-1849), `&mut` versus write-only access for a window (ETU:1122-1133, 1152-1162), strict claim carry (ETU:3913). Each is a silent `None` that surfaces as a coverage gap only if the body is demanded, so the same program property has a second judge here with a different failure mode from the source checker.
4. **Self-consistency by rebuilding.** `available_target` recomputes the callee's signature, scalar control, entry claims and the caller's claim transfers and requires them to equal what is already stored on the plans (ETU:3705-3715, 3744-3751, 3766-3769, 3807-3819, 3843-3857). The planner checks its own earlier output against a second run of itself; no outside evidence is involved.
5. **Dead or leftover code.** In `resolve_storage_place`, `root = source.root` is assigned, a `rebased_place` is built from it, and `root` and `segments` are immediately read back out of it (ETU:1229-1238). The trailing `if !closure.retained[caller_index] { continue; }` at the end of a loop body does nothing (ETU:2529-2531).
6. **Stale header sentence.** "Start at `build_checked_unit_effect_plans`, the checking stage's entry into this module (`build_checked_unit_effect_plans` is its test-only form without call frames)" names one function as both the entry and its test-only form (ETU:9-11); the real function takes `call_frames: Option<...>` (ETU:7084).
7. **`ScalarCalleeClosure` is a marker that is always present.** The comment describes passes "with" and "without" it (ETU:7062-7067), but it is a zero-sized `Copy` struct (ETU:7068-7069) and `prepare_root` constructs one on the spot (ETU:6945).
8. **The state-graph `finish` publishes no termination ranking.** It sets `natural_ranks`, `rank_components` and `preserving_rank_edges` to empty and `result` to `Unit` (ETU:2725-2729). Cannot tell from this slice whether the caller in `state_graph` fills them afterwards.
9. **Two segment arenas for one family of records.** `slot_occupied` reads a disposition's path from `facts.flow.ownership.segments` (ETU:1943-1947), while the neighbouring establishment check reads from `facts.contextual_cleanup.segments` (ETU:1692-1695); both records come from `facts.contextual_cleanup`. Could be intended; could be a wrong-arena read.
10. **Two predicates for "has a checked body".** The roster uses `machine.supplies_checked_body()` (ETU:7100, 7143); route choice and other checks use `supply_mode == MachineSupplyMode::CheckedBody` (ETU:3864, 8171, 8246). `body_route` returns `Sequence` for a machine that fails the second test (ETU:8171-8173). Cannot tell whether the two predicates always agree.
11. **Two multiplicity functions.** `program.type_multiplicity` (ETU:1279, 1310, 1377) and `checks::type_multiplicity` (ETU:1496, 8183) are both used for the same question.
12. **Atomic case lookup is program-wide.** The case a field sits under is found by scanning every data definition for a variant with that symbol, not by looking in the receiver's type (ETU:540-553).
13. **Identity by memory address.** Which scope owns a call operation, and which schedule a call belongs to, is decided with `std::ptr::eq` on plan rows (ETU:3591, 6034, 6099). This depends on the rows not being cloned between the two sides of the comparison; `consume_caller_results` does clone and write back operations (ETU:6744, 6811).
14. **Parallelism inside the checker.** Body planning runs on a rayon pool with speculative attempts that are thrown away when stale (ETU:7181-7239); the comment says most attempts in the earlier design "were stale anyway" (ETU:7166-7168).
15. **Costs worth knowing.** `has_computation_transfer` walks every scalar computation root in the program on each call (ETU:5676-5683). `CandidateClosure::close` finds each dropped target's machine by linear search (ETU:2266-2271). `retain_value_types` and `formation_place` use `Vec::contains` as their visited set (ETU:8331, 3152).
16. **Property 2 mostly does not hold here.** Apart from the member-name lookup (ETU:3196) and free-text reasons, this slice identifies storage by canonical place (root handle plus typed segments) and compares places structurally (ETU:712-729), which is closer to the new design than the sampling suggested for the old checker as a whole.
