## What this code is for

Both files belong to the "multiplicity" part of the old checker, which tracks ownership of non-copy ("affine") values.

`bw` implements "borrowed-storage invariant windows" (header `bw:1-30`). When a program moves a non-copy value out of
storage it only reaches through a `&mut` reference, the checker records the vacated place as an open "window". While the
window is open the checker refuses any read, borrow, move or partial store that overlaps the place, refuses calls that
may suspend, block, or enter a boundary/service, and refuses every exit from the state. A store of a value of the exact
same type into the place (or a store that replaces an enclosing owner) closes the window. A separate planner
(`ArmWindowPlan`) decides when a move made inside one arm of a `match` may open a window: only when every reachable arm
vacates the same set of storage places.

`co` computes "claim outcomes". A "claim" is the checker's record of one owned resource obligation, identified by a
`PermissionClaimIdentity` and a `PermissionProvenance`. For each state whose return type declares claims, the code
derives a map from each result path to its source: either a caller input (`Input{parameter, path}`) or something the
callee established itself (`Established{identity, provenance}`). With those maps it rewrites the identity of a call
result in the caller so that a value passed in and handed back is the same claim, and it builds "join receipts" that tie
a call result to every exit of the callee. The maps, the rewrites and the receipts are each found by iterating to a
fixed point. About 985 of the file's 5,018 lines are unit tests of two lookup indexes.

Neither file calls the proof kernel. Every decision is the code's own comparison of handles, place paths, enum values
and counts, or a question put to a neighbouring module.

## Mechanisms

- **Match-arm agreement (`bw:214-850`).** `collect_frames` (`bw:709-849`) walks a statement's expression tree once
  and records one frame per `match`, in pre-order, with its reachable arms, the arm that encloses it, and whether it
  sits in a conditional position. `seal` (`bw:309-413`) then visits frames innermost-first: it rejects a frame when an
  arm vacates the same storage twice, merges in the agreed debts of matches nested in each arm, rejects when a nested
  match disagreed, and finally requires all reachable arms to hold the same set. A second forward pass computes
  "agreed here and in every enclosing match" and "conditional here or above". `verdict` (`bw:423-478`) records the
  hole on the arm's own edge at once and parks the join-level window in `pending`; `commit_pending` (`bw:505-523`)
  releases it when the outermost match's own step is reached. No budget; cost is quadratic in debts per arm. Serves
  moves out of borrowed storage inside `match`.
- **Storage-route rebasing (`bw:1721-1762`).** Rewrites a place written through a `&mut` local to the place the
  local borrows, by repeatedly asking `flow::reference_route_source` and `flow::reference_source_place`. Hard limit
  of 16 steps, after which it stops and returns what it has. This is what lets `r.g` and `self.f.g` count as one
  hole.
- **Boundary reachability (`bw:996-1058`).** Depth-first worklist over recorded call targets with a visited list
  of machines. Any missing record makes it answer "may enter a boundary". No budget.
- **Window ledger (`bw:1182-1559`).** A plain vector of open windows scanned linearly on every use, move, store,
  call and exit.
- **Outcome-map fixed point (`co:3581-3659`).** Starts from no maps, derives one hypothesis per candidate state
  using the current maps for callees, keeps last round's map for a state that produced none this round, and stops
  when a round changes nothing or after `state_count + 1` rounds. Then a pruning loop drops every map whose state
  is not fully covered or cannot be re-derived, and repeats until nothing is dropped (`co:3642-3654`).
- **Source chain resolution (`co:4645-4717`).** Follows "this established claim is really the result of a call
  that forwards an input" through the candidate maps until it reaches an input or a claim with no forwarder. A
  visited list stops cycles; two different forwarders make it fail.
- **Origin rewriting (`co:4917-4970`).** Applies a list of `(old provenance, old identity) -> (new provenance, new
  identity)` rewrites to every owned permission event and to selection transfer rosters. Each value follows a chain
  of at most `rewrites.len()` steps and takes the first matching row.
- **Call-join fixed point (`co:1946-2044`).** Derives receipts, turns them into rewrites, applies them, and
  repeats until no event changes, at most `events.len() + 1` times; then derives the receipts once more and stores
  them. `derive_receipts` recomputes the whole outcome-map fixed point each time it is called (`co:1654`).
- **Return-frontier expansion (`co:903-1098`, `co:1302-1360`, `co:361-479`).** Recursive enumeration of a callee
  state's exits, following named transitions into their target states (an `active` stack refuses recursion), and
  forking the frontier in two at each statement-level selection that joined a claim. Results are memoised per
  `(callee state, path)` within one `derive_receipts` call (`co:1728-1757`). No size budget on the number of forked
  frontiers.
- **Hypothesis-and-dependency scheduling (`co:761-872`, `co:3395-3579`).** The surrounding walk reads last
  iteration's maps and join bindings as a hypothesis, records which ones it read, and is re-run when any of those
  changed; `fork_for_walk` / `take_consulted` / `absorb_walk` exist so several workers can do this in parallel and
  merge what they consulted.
- **Lookup indexes (`co:12-105`, `co:2221-2534`).** Two separate hash-keyed candidate indexes: `PlaceBucketIndex`
  buckets over outcome rows, and sorted `(hash, ordinal)` vectors over permission events (five keys). Both return
  candidates only; every caller repeats its full equality test (`co:2513-2515`).

## Accepts or skips without proof

`bw`:
- `exclusive_storage_chain` (`bw:1937-1944`) uses `.is_none_or(|access| access == Mutable)`. A prefix whose type
  cannot be found, or whose type is not a reference, counts as exclusive. Cannot tell whether another check covers a
  failed type lookup.
- `check_use`, `refuse_move_over_open`, `check_repair` and `check_edge_use` return silently when the place root is
  not a symbol (`bw:1433-1435`, `bw:1368-1370`, `bw:1480-1482`, `bw:571-573`); `check_repair` also returns when
  `place_at` finds no place for the store target (`bw:1476-1479`). Cannot tell what else checks those stores.
- `check_repair` removes a window without a type test when the store replaces an enclosing owner (`bw:1509-1513`).
  The ordinary type check of the assignment presumably covers the stored value; not visible here.
- `ArmWindowPlan::new` plans nothing for statement kinds other than local, expression, assignment and call
  (`_ => {}`, `bw:253`); transitions are not walked although the frame comment mentions "transition target"
  (`bw:104-105`). `verdict` then returns `None` for an event with no arm, and the caller uses the ordinary `open`.
- `effective_arm` falls back to an invalid arm with `.unwrap_or_default()` when the call site is not in the
  expression map (`bw:667-670`); the event is then treated as unconditional.
- `add_borrowed_move` drops an event with no arm or a non-symbol root (`bw:291-296`).
- `call_may_enter_boundary` treats any builtin without an asm service name as not a boundary (`bw:1026-1034`).
  All other unknowns in that function answer "may enter" (`bw:1018`, `bw:1041`, `bw:1044`, `bw:1047`).
- `collect_frames` does not walk the right operand of `&&`/`||` at all when the left side is a constant that
  short-circuits (`bw:801`); a `match` there gets no frame.
- `resolve_storage_place` stops after 16 hops and uses the partly rebased place (`bw:1729`).
- `open` stores a default (invalid) `required_type` when the type lookup fails (`bw:1326-1338`); the later repair
  then always fails the exact-type test (`bw:1516-1520`), so this one fails closed.

`co`:
- `ClaimOutcomePreparation::resolve` marks a received result path as not live, with `Unknown` identity, when the
  callee's map from the previous iteration has no entry for it (`co:3525-3531`). The map is a hypothesis; the walk
  is re-run when that map changes (`co:3454-3461`), and the map itself required the path to be provably absent on
  every return. Whether the final published events are re-checked against the final maps is not visible in this
  slice.
- `ClaimAbsence::arguments` answers "absent" when the callee's map has no entry for the path and the path contains
  a `Case` segment (`co:4019-4024`). During the fixed point the map is a candidate; the pruning loop
  (`co:3642-3654`) re-derives with the final set.
- `derive_checked_claim_outcome_maps` keeps the previous round's map for a state that produced no hypothesis in
  this round (`co:3628-3635`). The pruning loop removes it later if it cannot be re-derived.
- `derive_claim_outcome_hypothesis` drops every entry whose path matches more than one declared position
  (`co:3751`), after which that path is listed as inactive (`co:3759-3764`) without the static-absence test. Cannot
  tell whether a declared frontier can contain one path twice.
- `derive_receipts` skips the event with `continue` on ten different failures and produces no receipt and no error:
  `co:1669`, `co:1681`, `co:1684`, `co:1687`, `co:1690`, `co:1710`, `co:1766`, `co:1845`, `co:1854`, `co:1860`.
  Failure detail is collected only when the caller passes a `failures` vector (`co:1735`, `co:1760`, `co:1813`). A

  provenance with no receipt" (`co:2186-2190`). What refuses a result claim that could not be joined is decided
  elsewhere.
- `state_frontiers` skips exits flagged `cannot_return_normally` and transitions whose exit is not `Ordinary`

- `claim_outcomes_for_expression` returns an empty list for every expression kind it does not handle and for every

- Evidence on property 1: nothing in either file produces or consumes proof evidence. Every acceptance is one of

## Surprises

1. **No test in 7,021 lines pins a language rule.** The window rules, the arm-agreement rule, the outcome-map
   derivation, the receipts and the validators have no test here. The 985 test lines (`co:106-268`,
   `co:2536-3357`) check that indexes equal linear scans and assert visit counts and print timings with `eprintln!`
   (`co:263`, `co:2656`, `co:2921`, `co:3170`).
2. **Comment and code disagree on `self`-rooted storage.** The header and the function comment say the `self`
   receiver must be `&mut` for machine-rooted places (`bw:19-21`, `bw:1917-1918`). The code returns `false` for any
   place rooted at the machine symbol (`bw:1929-1931`), so such a move can never open a window. Either machine
   storage is rooted at a different symbol, or the feature was refused outright for machine fields.
3. **Comment and code disagree on spelling.** `place_spelling` is documented as spelling `self`-rooted storage
   "through the receiver" (`bw:1969-1971`); the code prints the root symbol's name for every symbol root
   (`bw:1979`).
4. **The validator is the generator run twice.** `validate_call_claim_joins` calls the same `derive_receipts` on
   the same facts and compares (`co:2081`, `co:2151`). This is the clearest evidence for property 1 in the slice:
   the check of the join table is a re-run of the code that built it, with its diagnostic calling this "exact
   source exit and call replay".
5. **Nested fixed points recompute each other.** `derive_receipts` runs the whole outcome-map fixed point on every
   call (`co:1654`). `publish_call_claim_joins` calls it up to `events.len() + 2` times (`co:1958-1969`),
   validation calls it again (`co:2081`), and all of this sits inside the outer preparation loop bounded by
   `revision_limit` (`co:3487-3501`). Three "did not converge" errors exist (`co:1967`, `co:3500`, `co:3658`); a
   program can be refused because an iteration count ran out.
6. **A liveness flag is cleared from a hypothesis.** `resolve` sets `obligation_live = false` and erases the claim
   identity of a received value because last iteration's callee map omits the path (`co:3525-3531`). An obligation
   to clean up a resource is dropped here on the strength of a candidate map; soundness depends on the re-walk
   scheduling (`reads_unchanged`) and on the absence test being right.
7. **Absence is defined only for variant payloads.** Every absence path requires a `Case` segment (`co:1476-1482`,
   `co:1604-1610`, `co:3857-3863`, `co:4021-4023`). A declared claim under a plain field with no source can never be
   "inactive", so the state gets no outcome map and, per the receipts code, no join.
8. **The two expression walks cover different constructs.** Source collection handles value-preserving casts and
   owned selections (`co:4184-4197`, `co:4369-4379`); the absence walk handles neither and answers `false` for a
   cast or a `match` (`co:3995`). A result written as a cast of a variant literal has sources but can never have an
   absent path.
9. **Two ways to signal "unresolved" in one function.** `claim_outcomes_for_owned_selection` returns an empty list
   when one arm's claim is unknown (`co:4443-4449`) but pushes a poison entry with `Unknown` identity when it found
   no entries at all (`co:4473-4481`). The poison entry is later rejected by `known_source`; the empty list falls
   through to the absence test.
10. **Entries on a path declared more than once are dropped and the path becomes inactive** (`co:3751`,
    `co:3759-3764`), skipping the static-absence test applied at `co:3738-3746`.
11. **Fields matched by spelling beside a comment that names cannot join namespaces** (`co:3960`, `co:4281`,
    `co:4317` against `co:4385-4387`).
12. **About 140 lines exist only to print `tokens[index]` instead of `tokens[0]`** in a diagnostic
    (`bw:1579-1651`, `bw:1773-1914`): `authored_projection` (32-step limit), `selector_path_matches`,
    `spelling_for_call_selector`, `reference_binding_source`, `reference_initializer`.
13. **Residue and oddities.** `resolve_storage_place` builds a `CanonicalPlace` and takes it apart again on the
    next two lines (`bw:1753-1759`). `JoinedOccurrence` is an enum with one variant (`co:494-502`).
    `ReturnFrontierFailure.source` is always `None` from `record` and set only at `co:1822`. A map type named
    `SymbolKeyMap` is used with keys that are not symbols (`co:596`, `co:2286`). Arm-edge invocations are recorded
    with `opened_statement: None` (`bw:631`), so their diagnostics omit "at statement N" while join-level ones
    include it (`bw:1417`, `bw:968-971`).
14. **Tie-break by row order is load-bearing.** `InactivePlaceWrites::preserved` picks the latest inactive
    establishment with `max_by_key`, which keeps the last of equal keys; a comment (`co:1487-1488`) and a test
    (`co:2852-2857`, `co:2918`) pin that the last row at the same statement wins.
15. **Against property 2.** This slice identifies storage structurally and goes out of its way to resolve two
    routes to one storage place (`bw:12-17`, `bw:1721-1762`). The text-based identity found here is limited to
    struct-literal field lookup and diagnostics.
16. **Capability not expected:** the window checker permits disjoint sibling work between extraction and repair,
    agreement across nested `match` arms with per-arm edge tracking, and a store to an enclosing owner as a repair,
    and it distinguishes "service reach" from "boundary invocation" by following wrappers through recorded call
    topology (`bw:988-1058`).
