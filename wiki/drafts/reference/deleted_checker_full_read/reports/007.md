## What this code is for
This file is the coordinator for build-time (compile-time) evaluation of constants in the old compiler. It does not evaluate expressions itself for the most part; it finds the places that need a constant, decides whether they can be evaluated now or must wait for operator selection, prepares a small executable program, calls an evaluator in another module, and writes the result back into the tree. The places it serves are: const-generic arguments in type references (`const_applications` on typed trees, `const_generic_calls` on syntax trees), `requires` membership facts of generic data instances (`const_domain_facts`), fixed-array lengths written as a call (`const_lengths`), declared constants whose initializer must be proved to fit a constrained destination type (`const_qualifications`), integer expressions inside contracts (`contract_expressions`, `range_endpoints`), and `size_of`/`align_of` queries (`data_layout_queries`). `constant_recipes` records the jobs that could not be finished so a later stage can redo them. The file also contains one self-contained evaluator: a small `i64`/`bool` interpreter for domain facts and data `requires` facts (`fact_expression`). Results are published by overwriting tree nodes: a call expression becomes an integer literal, a const-expression type argument becomes a `Named` type reference whose name is the value's text, a membership fact becomes the expression `true`. Nothing in the file calls a proof kernel; when a proof is needed (a callee's `requires`, a constant's destination constraint) the code builds a throwaway machine and runs the ordinary tree checker on it.

## Mechanisms
- **Round-based fixpoint with rollback.** `evaluate_selected_const_applications` (ce.rs:147-196) and `evaluate_selected_range_endpoints` (ce.rs:4876-4930) each loop: build the plan, evaluate every pending item, publish the ones that folded, and repeat while some failed but some progressed. If a round makes no progress or errors, a `restore` closure puts back every node published so far and re-marks the pending set (ce.rs:136-146, 4865-4875). There is no round limit; the loop ends on "no progress". Serves const-generic arguments and contract integer expressions.
- **Instance realization fixpoints.** `realize_folded_applications` (ce.rs:217-270) and `realize_symbolic_applications` (ce.rs:349-403) repeatedly scan every type reference in the domain and turn `Generic` references with closed arguments into concrete data definitions, restarting after each success. `realize_data_instance` clones the template, substitutes member types (`substitute_member_type`, ce.rs:509-611) and reuses an existing instance if `instance_origin_matches` (ce.rs:637-658). No budget.
- **Dependency layering.** `ready_layer` (ce.rs:1834-1898) builds a dependency list per application from pending type inputs, returns the applications with no dependencies, and runs a marking fixpoint only to detect cycles. The outer `evaluate_requested_calls` (ce.rs:2060-2067) reruns the whole group until no progress.
- **Demand-driven length evaluation.** `LengthJobs` (ce.rs:2597-2817) evaluates an array length by first recursively evaluating every other pending length in the program it needs, keeping an `active` stack for cycle detection. For each length it prepares the typed trees, runs the full tree checker (`prepare_typed_trees`, `lower_typed_trees`, ce.rs:2770-2775) and then runs the machine with `evaluate_checked_constant`, whose result type is `terminal_interpreter::TerminalExecutionResult` (ce.rs:2804-2806, 2834-2842). It passes `self.domain.accounting` to the evaluator (ce.rs:2713, 2805); the budget itself is not in this file.
- **Three-valued domain evaluation.** `evaluate_domain_facts` (ce.rs:1518-1587) returns true, false or undecided for an `i64` subject, recursing into nested domains with a `visiting` stack; a revisit yields undecided (ce.rs:1596-1598). Facts are evaluated by the `i64`/`bool` interpreter (ce.rs:1127-1330) or by running a one-parameter machine (ce.rs:1462-1516).
- **Probe machines.** For syntax-level work the code clones the syntax tree, appends a private machine whose body returns the expression (`append_probe`, `append_named_probe`, in another module), resolves and types the clone, and evaluates or checks the probe (ce.rs:2158-2233, 3003-3057). It records which constants and calls the authored expression selected before the probe was built and compares them afterwards (ce.rs:2166-2192, 1975-1989, 2342-2357).
- **Requires discharge by snapshot.** `snapshot_requires_discharge` (ce.rs:4317-4363) replaces each call argument by its evaluated literal and asks `snapshot_arguments_discharge` to check a synthetic caller labelled `"@const-endpoint"` with the tree checker, so the callee's `requires` are judged for concrete values.
- **Contract root discovery.** `contract_expressions::roots` (ce.rs:3322-3450) walks every proof fact of every owner in the domain, keeps closed integer-typed subexpressions that have a recipe, a layout query or a callable invocation, drops any candidate nested inside another root of the same owner, and sorts by handle.
- **Operator-selection gating.** Each job kind asks `closure_needs_execution_preparation` to decide whether evaluation must wait for operator selection (ce.rs:56-104, 1418-1460, 1666-1687, 2266-2272, 2717-2722, 3413-3421, 4756-4774).
- **Two-pass layout folding.** `SelectedConstantEvaluationRequest::evaluate` (ce.rs:5113-5141) folds `size_of`/`align_of` once in deferring mode, evaluates pending continuations, folds again in strict mode, then finishes the continuations.
- **Integer position peeling.** `IntegerPosition::prepare` (ce.rs:4575-4642) strips `Constrained` layers with a visited list, collecting domains and one arithmetic policy.

## Identity by text

The value is recovered later by `name.as_str().parse()` (ce.rs:545). A Boolean is stored as its atom text (ce.rs:845, 2360).
- `closed_argument` treats any `Named` reference with an invalid symbol as a closed argument (ce.rs:305-311). `closed_argument_eq` compares two such references by name text (ce.rs:691-695).
- Realized data instances are named `Template<arg, arg>` by string formatting (ce.rs:451-459); a symbolic const call is spelled `name()` (ce.rs:617). The symbol is inserted under that text (ce.rs:474-478).
- A domain fact's machine is found by symbol first, then by `machine.name.as_str() == call.target.as_str()` (ce.rs:1405-1408), and is then executed by name: `evaluate_const_evaluable_machine_for_invocation(typed, machine_name, ...)` (ce.rs:1500-1503).
- The entry state of a length machine is the state whose name equals the last `::` segment of the machine's name, else the first state (ce.rs:2904-2916).
- Probe machines are named `"@const-qualification-{constant name}-{ordinal}"` (ce.rs:3011-3014); the snapshot caller is labelled `"@const-endpoint"` and receives `machine.name.as_str()` (ce.rs:4354, 4358).

## Surprises
- **Evidence on property 1.** No proof-kernel call appears anywhere in the file (grep for `proof_admission`, `ProofNode`, `verify_obligation`, `certificate` finds nothing). Acceptance is this code's evaluation result or the tree checker's yes. The clearest case is ce.rs:1748-1751, where a membership fact judged true by the `i64` interpreter is replaced by the literal `true`, erasing what was claimed.
- **Dead block.** `endpoint_leaves` is created empty (ce.rs:2079) and never pushed to, so the conditions at ce.rs:2084 and 2133 reduce to the other operand and the whole block at ce.rs:2404-2453 (range-endpoint replacement on syntax trees, including the `expect` at 2447) can never run.
- **Unreachable error branches.** `integer_root_plan` always returns `Ok` (ce.rs:5033-5050), so the restore-and-return branch at ce.rs:4878-4882 and the `?` at ce.rs:3232, 4761, 4843 cannot fire. `impl EndpointCallee {}` is empty (ce.rs:4782).
- **Swallowed errors.** ce.rs:4897 drops all diagnostics from `evaluate_round` (which include failures of `prepared_admission`, ce.rs:4949-4955) whenever the plan has roots but no calls.
- **Message contradicts code.** The message at ce.rs:4626 says integer endpoint types "admit only range refinements and declared integer domains", but the match at ce.rs:4603-4630 has arms only for declared domains and for `Wrapping`/`Saturating`; every other constraint row, which would include a range row if ranges are stored as constraint rows, takes the error arm. An explicit `Exact` arithmetic constraint also takes the error arm. I cannot tell from this slice how ranges are stored.
- **Two definitions of "entry state".** Length evaluation finds the entry by matching the state name against the last `::` segment of the machine name (ce.rs:2904-2916); endpoint and domain-fact code use the first state (ce.rs:1412, 4206-4211, 4371, 5079).
- **Resolve by symbol, run by name.** `resolve_fact_machine` can find the fact machine by state symbol (ce.rs:1393-1400), but `evaluate_machine_fact` then runs it by name (ce.rs:1500-1503). The name fallback takes the first machine with that name and no attached data (ce.rs:1405-1408). If two machines share a name, the machine validated and the machine run may differ.
- **Type identity by spelling of the argument.** `closed_argument_eq` treats two const-call arguments as equal only if they call the same machine, and never equates a const call with a literal (ce.rs:669-680, 758). `realize_symbolic_applications` creates instances such as `Buf<len()>` before evaluation (ce.rs:345-404), while folded sites become `Buf<4>` (ce.rs:252-263). Two spellings of the same value therefore appear to produce two distinct data definitions. Two different machines with the same leaf name produce the same instance name text (ce.rs:617) under different symbols.
- **Domain facts are evaluated in `i64` regardless of the subject's type.** A `u64` value above `i64::MAX` cannot be tested for domain membership and is refused (ce.rs:1376-1380); arithmetic in facts refuses on `i64` overflow rather than following the carrier's width or policy (ce.rs:1275-1304).
- **`defer_unproved` rewrites the declared type.** For a constant not yet qualified, the constraint wrappers are stripped from its type reference in the syntax tree (ce.rs:3138-3143). The pending obligation keeps the original destination handle (ce.rs:2969-2973), so the constraint is not lost if `prove_ready` ran first, but until qualification every user of the constant sees the unconstrained type.
- **Zero-gate looks at one variant.** `find_map` takes the first `Variant` member only (ce.rs:1793-1799). This may be deliberate (all-zero storage selects the first variant), but nothing in the file says so.
- **Checker runs inside evaluation.** A full `prepare_typed_trees` + `lower_typed_trees` run happens per array length, inside a recursion over dependent lengths (ce.rs:2728-2732, 2770-2775), and again per group of constant qualifications (ce.rs:3050-3057). `validate_call` and `evaluate_call` each recompute the discharge decision, so the snapshot check (another checker run) can run twice for one call (ce.rs:4397-4398, 4463).
- **Array lengths already ran on the lowered form.** The length result type is `terminal_interpreter::TerminalExecutionResult` (ce.rs:2834-2842), while domain facts and endpoint calls use `BuildTimeValue` through the admission plan (ce.rs:1500-1514, 4465-4481). The header's "typed or Terminal evaluator" (ce.rs:7-8) matches this split.
- **Shared expression, one fold.** `evaluation_roots` deduplicates by expression handle (ce.rs:4706-4711) and the fold overwrites the shared expression node for every owner (ce.rs:4904-4906), although each owner has its own context with its own result type (ce.rs:3397-3400).
- **`prepare_and_invoke` mutates the caller's trees.** It calls `prepare_execution_applications(typed)` on the tree it was given (ce.rs:2737); in the `Independent` and `Pending` modes that is the real program (ce.rs:2533-2548), in `Selected` mode a clone (ce.rs:2562-2568).
- **Recast check tests every state.** `has_pending_recast_geometry` asks for the declared type of the cast operand in every state of the owning machine, not the state that contains the cast (ce.rs:3888-3893).
- **Proof-only refusal is not deferred.** In the deferring pass of layout folding, a proof-only operand is still an immediate error (ce.rs:3964-3972), while unresolved operands are only checked in the strict pass (ce.rs:3973-3977).
- **Diagnostics without location.** The generic-instance membership errors carry no source span (ce.rs:1732-1740), unlike most others in the file.
- **Property 3 in this slice.** The repetition is by job kind and by tree form (syntax tree versus typed tree), not by source placement. I found no rule here written separately for local, field, parameter or return.
