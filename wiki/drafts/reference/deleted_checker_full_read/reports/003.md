## What this code is for

None of this slice is the checker itself. It is two consumers that run after checking and depend on the old checker's data (`CheckedTrees`, `CheckFacts`, `facts::FactPlan`) and on functions of the old checker's `validation` crate.

The first consumer (10 files, about 2,340 lines) chooses which implementation supplies each "boundary" requirement on a target: a boundary trait, a top-level requirement machine, or a boundary operator. `provider_publication.rs` turns the provider selections a build authored into target proposals. The `selected-dispatch` crate then binds the chosen provider plans to the checked program: it decides which rows run as compiler intrinsics, which float `==` in a `match` runs as an IEEE intrinsic, and which checked machine body realizes a boundary operator at each use.

The second consumer (46 files, about 6,200 lines) is the "package review evidence" projector. It walks the checked program and writes an inert, sorted record of a package's public API (traits, conformances, domains, propositions, constants, operators, data types) and of each callable's behaviour (contracts, crash routes, termination, mutation write frame, service reach, capability flow, external bindings). A reviewer or policy tool reads that record.

The projector does not trust the retained checked facts blindly. In about a dozen places it re-runs a derivation from the old checker and refuses if the retained fact differs. It also refuses whenever a lookup that should find exactly one row finds zero or several. Almost every rule here is of one of those two kinds.

## Mechanisms

- **Re-derive and compare.** The projector calls a function of the old checker to rebuild a fact, then requires structural equality with the retained fact. Instances: definition fact plan (api/data/evidence.rs:67-89), quotient formations (api/data/projection.rs:91), operator crash contracts (api/operators.rs:62-69), dynamic-slot return sources (api/slot_metadata.rs:38-48), authored crash buckets (behavior/policy/crash.rs:45, 151-169), entry write frame (behavior/policy/mutation.rs:56-64), declared signature invocations (api/traits.rs:260), operational effects, service reaches and crash causes (callables/policy.rs:57-61). There is no budget and no partial result; a mismatch is a refusal. It serves package review of data invariants, crash contracts, mutation, service reach.
- **Content comparison of a fact plan.** `rechecked_data_definition_evidence` (api/data/evidence.rs:93-209) first checks every arena link (211-235), then replaces place handles by `CanonicalPlace { root, segments }` values so two fact plans compare by content. Expression, type-reference, symbol and `ProofFact` handles stay handles (12, 19, 36-38).
- **Exactly-one join.** Rows are found by a linear scan filtered on a symbol, and anything other than one hit is refused. About 30 sites, for example api/conformances.rs:41-52, operator_adapter.rs:134-146, behavior/policy/crash.rs:186-195. Some use the shared `exactly_one` helper (defined outside this slice).
- **Row alignment by position.** Selected plans and their provenance are parallel vectors; lengths are checked and then they are zipped (intrinsic_review.rs:104-114, callables/boundary_operators.rs:70-78, callables/boundary_requirements.rs:87-97, api/policy/traits.rs:42-49).
- **Domain alias expansion.** A recursive walk with an explicit stack for cycle detection, collecting atoms, then sort and dedup; empty result refused (api/domains/aliases.rs:28-90). Serves `domain` aliases and `Carry` permissions.
- **Reachable capability closure.** A worklist (`pending` vector with a cursor) over the checked service-reach call graph, starting at one machine; membership tested by linear `contains` (behavior/policy/flow.rs:42-115). Four `SymbolMap<Vec<..>>` indexes are built once per projection (152-192). Calls without a concrete machine body add no edge (88-103).
- **Bounded receiver walk.** Follows `Borrow` and `Member` nodes at most `expression_count()` steps (behavior/policy/receivers.rs:35-57).
- **Greedy bound matching.** Each provider bound takes the first unmatched requirement bound of the same shape (callables/boundary_requirements.rs:49-67).
- **Closed crash-predicate vocabulary.** A recursive total match turns checked boolean and scalar expressions into review expressions and returns `None` for forms with no public vocabulary: math-integer comparison, erased parameter, storage read, byte-sequence predicate, constant application, local-rooted field, implementation selection (behavior/crash/expressions.rs:36-40, 127-136). Values are named by parameter position, local position and structural path.
- **Deferred failure.** `PreparedBindingDeclarations` stores `Result` fields (owner, trust, external, issuers) and raises each error at the step that first needs it (provider_binding.rs:22-40, 147, 163, 177, 216); `provider_publication.rs:160-163, 176` stores a declaration-closing error inside the candidate.
- **Owner identity by address.** Program identity is `Arc::ptr_eq`, `Weak::ptr_eq` or `std::ptr::eq`, so an equal clone is a different owner (provider_binding.rs:51, 72, 148; provider_publication.rs:81).
- **Scratch copy of the program.** To name a closed implementation argument or instantiate static parameters, the code builds new type nodes in `validation::CheckingProjection`, a mutable copy of the program (api/traits.rs:304-318, callables/policy_parameters.rs:38-49). `callables/external_policy/signatures.rs:1-4` says this "clones the whole program", so an empty parameter list skips it (policy_parameters.rs:31-37).
- **Canonical order.** Nearly every projection ends with `sort` then `dedup`, or `sort` then refuse adjacent equals.
- **Inherited trait scope visit.** `AppliedTraitScope::abstract_scope(definition).visit(..)` enumerates a trait and its inherited scopes (provider_publication.rs:31-42, 123-133).

- `capability_rows_match_original_searches_with_duplicates_generations_and_replacement` (behavior/policy/flow/row_tests.rs:125-160): the `FlowRows` indexes agree with linear searches for machines, envelopes, service-reach rows and state owners, with duplicate machine symbols, a state listed twice in one machine, equal index with different generation, a missing symbol and the invalid symbol; again after the program is replaced and after envelopes and reach roots are cleared.
