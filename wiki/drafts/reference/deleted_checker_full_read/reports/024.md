## What this code is for

`calls.rs` is the borrow checker's judgment for call sites. For every call a state makes, it compares the call's arguments with each other and with the loans that are live at the call, and reports an error when two arguments, or an argument and a live loan, could reach the same storage with conflicting access (calls.rs:190-600). It also handles a moved (owned) operand that an earlier argument of the same call still borrows (calls.rs:53-188), the special case of a state jump that forwards the machine's mutable data parent together with child loans (calls.rs:717-1032), compiler-owned "exclusive place" operations (calls.rs:1044-1165), and a Build-specific receiver check (calls.rs:1616-1712).

`overlap.rs` is the spatial judgment those checks call: given two captured storage places and their access kinds, decide whether they are disjoint, whether one contains the other, and whether the two accesses are "non-interfering" (overlap.rs:2924-3015). Places are a root plus a list of path segments (field, variant case, fixed index, fixed range, index expression, opaque range). For index expressions the file normalizes each selector to a symbolic integer bound (overlap.rs:1077-1146) and asks an integer-ordering prover whether two points or half-open windows can be separated (overlap.rs:560-567).

The largest part of `overlap.rs` (overlap.rs:1148-2208) collects the "premises" that prover may use: the state's `requires` rows, incoming guards, domain membership predicates, transparent propositions, callee guarantees, results of checked predicate calls, and integer values the flow analysis recorded for immutable places.

Neither file contains tests. Neither file calls the proof kernel.

## Mechanisms

**Per-state parallel call check (calls.rs:1511-1608).** `check_compatibility` runs every state on a rayon pool. For each state it builds the state-entry premises once (`stated_ordering_premises`), creates one `StateGuarantees`, and for each call that `invocation_is_evaluated` extends the premises with statement-entry premises, then runs the Build receiver check and the argument conflict check. Diagnostics are collected per state and concatenated. Calls that the evaluated schedule does not contain are skipped (calls.rs:1561-1563).

**Active-loan set at a call (calls.rs:223-253).** Starts from the borrow-loan constraints at call entry and removes loans that `selected_retirement::before_call`, `reads::loans_ended_before_call` or `statements::local_loan_ends_before_successor` say have ended. Each remaining loan also gets the index range of the arguments that produced it (`returned_loan_input_range`, calls.rs:1226-1245), so a call-result loan is not compared with the inputs evaluated before it existed.

**Pairwise argument conflict with exemptions (calls.rs:308-460).** For each ordered pair of arguments the code skips the pair when: their evaluation routes are on incompatible branches (310-324); the later one's `evaluation_start` covers the earlier (325-330); one is the forwarded data parent and the other is an owned child inside it (331-353); one is a completed read before a terminal transfer of a mutable reference (354-370); either ended before the other was accessed (371-379); one forwards the other with a direct reborrow (380-392); both are reads (393-401). Otherwise every pair of backing places is compared.

**Invocation boundary (calls.rs:1251-1432).** `InvocationBoundary::at` rebuilds the statement's ordered occurrence list (`ownership_occurrences::statement_steps`) and finds the single occurrence that is this call. From it: `argument_routes` gives each argument's branch routes; `access_finished_before_call` says a nested call's input window is over when exactly one completion and exactly one supplier call exist and the nested result type is borrow-free.

**Carried data parent (calls.rs:874-1010).** A terminal invocation whose target takes the machine's data binding as a `&mut` parameter, and whose receiver place is a bare symbol with no segments, may forward the parent while children stay borrowed. Exactly one retained mutable access naming the parent place qualifies (calls.rs:916-929).

**Normalized integer bounds (overlap.rs:1077-1146, 939-951).** An index expression becomes one of: integer literal, immutable symbol plus offset, sum of two symbols plus offset, call result (by expression handle, with a field/fixed-index path), immutable entry indexed read, immutable projection, or — for selectors only — a mutable storage coordinate (`Storage`, `StorageProjected`). Storage coordinates are never structurally equal to anything (comment overlap.rs:931-938).

**Selector session cache (overlap.rs:538-588, 2225-2254).** One comparison evaluates each selector bound once, keyed by (side Forming/Active, segment index, position). Overlap and containment share the cache. Lookup is a linear search of a `Vec`.

**Ordering proof (overlap.rs:560-567, 768-832).** `<=`, `<` and `==` each try a structural rule first (same term, compare offsets) and then call `validation::prove_integer_ordering(premises, left, relation, right)`. The file's comment says the prover composes at most one ordered pair of premises through a shared middle bound, with `==` substitution (overlap.rs:1161-1164); that code is in `validation`, outside this slice.

**Premise collection (overlap.rs:1828-2024).** Three layers. State entry: the state's own `Requires` contract rows (not inherited) and incoming guards that apply at the state, transported through immutable parameter bindings. Statement entry: integer values of immutable owned places recorded in the semantic contexts (`stored_values::append`, overlap.rs:1463-1540) and callee guarantees available at that statement (`StateGuarantees::available`). Captured paths: guarantees available in an evaluated context, with mutable-storage premises removed.

**Premise decomposition (overlap.rs:2034-2207).** A recursive walk with a `negated` flag: `!` flips it; `x == true/false` and `x != true/false` recurse into `x`; `&&` (or `||` under negation) recurses into both sides; a comparison becomes one premise with the relation chosen from a (operator, negated) table; a predicate call (not negated) contributes the consequences `validation::predicate_ordering_consequences` returns. A non-negated `||` and a negated `&&` contribute nothing.

**Captured-value equalities (overlap.rs:39-122).** For storage-path comparison without current premises, the code derives equalities from recorded values: symbol equals the call result it was copied from; symbol equals an integer when the completed scalar is known and there is no read epoch; call-result selector equals an integer; two symbols are equal when their copies agree.

**Place compatibility (overlap.rs:2924-3015).** Computes `roots_valid`, `same_family`, `has_descriptor_load`, owner-path overlap, segment overlap and containment, `independent_input_permissions`, `disjoint`, `shares_dependent_fact`, and returns `non_interfering = both_shared || independent_input_permissions || (disjoint && !shares_dependent_fact)`.

No budgets, depth limits or fixpoints appear in this slice.

## Accepts or skips without proof

- **Independent input permissions (overlap.rs:2989-2992).** If either place is reached through an incoming reference, no descriptor load is involved, and the two are not the same root + same incoming reference, the pair is non-interfering with no further evidence. This assumes that two different incoming references, or an incoming reference and a local, never alias. The caller-side argument check in calls.rs:308-460 would catch a caller passing overlapping exclusive arguments; I cannot tell from this slice whether every way of producing two incoming references goes through that check.
- **Different roots are disjoint (overlap.rs:2993-2996).** Two valid roots that differ and have no incoming reference are disjoint. The only alias the code looks for is machine root vs attached field (overlap.rs:3114-3131).
- **`_ => false` in `place_segment_pair_may_overlap` (overlap.rs:2828).** Any segment-kind pair not listed, for which `static_place_segment_pair_equal` returns `None`, is judged "cannot overlap". That is the permissive answer. What `static_place_segment_pair_equal` covers (for example two different `Case` segments of one variant type, which share storage) is in `crate::flow`, outside this slice; I cannot tell.
- **Dependent-fact pin misses (overlap.rs:3311-3322, 3335-3357).** `Membership` and `Proposition` facts return `false`. `expression_mentions_field` walks only `Name`, `Binary`, `Member` and `Borrow`; a `requires` that relates two fields inside a unary `!`, a call, an index, a cast or any other node is not seen, so the sibling field is not pinned. I see no other check in this slice that would catch it.
- **Staged-move check skips on missing backing (calls.rs:162-164).** `argument_backings` returning `Err` makes `check_staged_operand_move` `continue` with no diagnostic. `check_call_access_conflicts` reports the same `Err` for the same call (calls.rs:298-304), provided that call is in the evaluated schedule.
- **Staged-move check returns silently when the move source is unknown (calls.rs:145).** `owned_storage_source` returning `Ok(None)` ends the whole check. Cannot tell whether another check covers it.
- **Empty backing set is vacuously compatible (calls.rs:165-178).** `backings.places.iter().all(...)` is true for an empty list, which skips the diagnostic. After a reported backing error the code pushes `ArgumentBackings::default()` (calls.rs:303), so later pair checks find no places and report nothing more (calls.rs:402-421); the program is already refused in that case.
- **Calls not in the evaluated schedule are not checked (calls.rs:1561-1563).** `invocation_is_evaluated` returns `true` when metadata is missing (calls.rs:1746-1761), so only a positive absence from `statement_steps` skips the check.
- **Later operand check is conditional (calls.rs:1103-1114).** In `check_exclusive_place_use`, the later operand is compared with the receiver only when the receiver expression is a `Borrow` or its place is absent or not symbol-rooted. For a plain symbol-rooted receiver the comparison is skipped. Cannot tell whether another check covers it.
- **`captured_places` drops invalid roots (calls.rs:1016-1027).** A callee footprint place with an invalid root is filtered out and not compared.
- **Loans removed from the active set (calls.rs:226-242).** Three other-module predicates remove loans before any comparison. This code trusts them.
- **Read/Read is always accepted** (calls.rs:393-401; overlap.rs:3003-3004, 3011).
- **Premises are accepted from other modules as given.** Callee guarantees (`call_guarantees::available`, overlap.rs:1955-1975, 1994-2015), predicate consequences (`validation::predicate_ordering_consequences`, overlap.rs:2049), recorded scalar values (`values::scalar_value_at_place`, overlap.rs:460-479; `AssignmentObservationBatch::scalar_value`, overlap.rs:1529), incoming guards (`IncomingGuardIndex`, overlap.rs:1881-1916). Each one widens what the prover can separate. No certificate is checked here.
- **Missing result binding defaults (overlap.rs:1959-1961).** `guarantee.result_binding(...).unwrap_or_default()` yields an invalid symbol and `result_mutable = false`; the bound then falls back to `CallResult` by the guarantee's call expression (overlap.rs:1662-1669).
- Cases that fail closed, for contrast: unknown bounds overlap (overlap.rs:638, 687-689); unresolved segment identity overlaps (overlap.rs:2696-2700); `debt_windows` error interferes (overlap.rs:3055); missing `CallFrameResolver` means not disjoint (overlap.rs:2901-2903); unidentifiable root gives a default compatibility (overlap.rs:3233-3238); missing guard evaluation state, missing state or statement row add no premises (overlap.rs:1886-1892, 1935-1949); invalid roots give `roots_valid = false` (overlap.rs:2942-2945).

## Notes the authors left

- calls.rs:1-11: "Source validation already judges reference formation against the exact receiving leaf... Rechecking only a captured place's root here loses that authority: an immutable owned aggregate can contain an exclusive descriptor."
- calls.rs:46-52: "Exact expression occurrences, not affine-looking actual types, distinguish a move from implicit shared lending."

## Surprises

1. **The dependent-data rule is decided by field-name text and a four-node walk (overlap.rs:3272-3357).** Whether writing field `b` is blocked while field `a` is borrowed depends on whether a `requires` expression of the data definition contains a name whose last path member, or a member access whose member, spells `a` and `b`. The walk covers `Name`, `Binary`, `Member`, `Borrow` only. A relation stated as `!(a > b)`, `fits(a, b)`, `items[a] < b`, a domain membership or a proposition is not seen. A name that merely ends in the same spelling (for example a nested `other.len`) matches. This is the one place in the slice where a soundness-relevant decision is made from spelling.

2. **Unchecked `i64` additions in proposition substitution (overlap.rs:1386, 1389, 1439).** `offset + actual_offset`, `offset + value` and `offset + first_offset + second_offset` use plain `+`. Everywhere else the file uses `checked_add` (overlap.rs:215, 906-925). In a release build an overflow would wrap and produce a premise about the wrong integer.

3. **`disjoint` and `non_interfering` can disagree in the returned record (overlap.rs:2993-2996, 3011-3013).** When `independent_input_permissions` is true, `disjoint` is forced to `false` while `non_interfering` is `true`. A consumer that reads `disjoint` gets the opposite answer from one that reads `non_interfering`.

4. **A Build-system rule lives in the borrow checker (calls.rs:1616-1712).** The checker inspects `build_selection` on call nodes and the literal target names `prepare` / `prepare_tests`. Five of its diagnostics say an operation "lost" something (calls.rs:1654, 1663, 1676, 1682, 1694); they describe internal inconsistency between compiler tables, not a user error.

5. **Asymmetric containment arm (overlap.rs:2443-2445).** A `FixedRange` container contains an `Index` point only when the point's bound is a literal integer; the prover is not asked. The mirror cases (overlap.rs:2380-2388, 2427-2429) do ask it. The effect is conservative (less containment proved).

6. **`local_jump` is recomputed inside the loop (calls.rs:483, 502).** The value is already in `internal_jump` (calls.rs:210). The inner `let Some(jump) = local_jump(...) else { return false; }` (calls.rs:502-504) cannot take the `else` branch because the enclosing condition already required `local_jump(...).is_some()`.

7. **`retained_debt_non_interfering` is not formatted like the rest (overlap.rs:3032-3053).** One-line `if ... { return None; }` bodies and long lines stand out from the rustfmt style used everywhere else, which suggests a late hand edit.

8. **`stated_ordering_premises` scans every contract fact in the program for every state (overlap.rs:1837-1844).** For each row it runs `state_requires_facts(program, machine, state).any(...)`. The cost is (all contract facts) x (this state's requires) per state.

9. **"Exactly one, otherwise nothing" appears seven times.** `retained_subject_access` (calls.rs:928-929), `InvocationBoundary::at` (calls.rs:1322-1325), `access_finished_before_call` completions and suppliers (calls.rs:1396-1402, 1409-1416), `returned_loan_input_range` (calls.rs:1243-1244), domain definitions (overlap.rs:1244-1247), parameter incoming-reference identity (overlap.rs:3047-3048). In each, two candidates mean the exemption or premise is not granted.

10. **Evidence on property 1.** No call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type appears in 5,150 lines. Every acceptance is this code's own boolean, or the boolean of `validation::prove_integer_ordering`, `simultaneous_hold_conflict`, `place_access::access_interferes` and similar. The header comment states the design choice: "No successful judgment is serialized for the checker to reconstruct later" (overlap.rs:5-6).

11. **Evidence on property 3.** The spatial judgment is not written per placement; one function serves loans, call arguments, cleanup receivers and "window debt" (overlap.rs:2848-2857, 2858-2921, 3359-3377). The comment says "The same spatial comparison serves source windows, arm joins and executable window repair" (overlap.rs:19). The per-construct repetition is in the call exemptions and segment-kind tables instead.

12. **Debug tracing is compiled in (calls.rs:432-455, 576-589).** `eprintln!` lines prefixed `CHECKSITE simultaneous-hold` and `call-live-loan-conflict` print under `validation::trace_flags::check_sites()` and `state_reference_diagnostics()`.

13. **A capability worth knowing about.** The borrow checker used value facts to separate array elements: `a[i]` and `a[j]` were disjoint when a `requires i != j`, an incoming guard, a domain predicate, a transparent proposition such as `Distinct(i, j)`, a callee guarantee about its result, or a recorded integer value of an immutable local proved the indices different or ordered (overlap.rs:1149-1181, 1296-1303, 1463-1540). Inclusive ranges, symbolic offsets and sums of two symbols were supported (overlap.rs:889-929).
