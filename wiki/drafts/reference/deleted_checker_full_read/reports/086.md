## What this code is for

This is the first third of the old checker's integer-arithmetic file. Its header calls the file the "Shared integer interval domain, premise-ordering oracle, guard narrowing, ordered values, and mixed-domain and exact-overflow validation" (1-5). The slice holds the expression walker (`expression_analysis`, 5581-8889) that visits every source expression, computes an interval `[low, high]` for it, and reports an error when an `Exact` integer operation cannot be shown to stay inside its type, when a divisor may be zero, when a shift count may reach the width, when two operands have different carriers or arithmetic domains, or when a `Trapping` operation is not covered by a published `crashes Trap` route. Around the walker sit helper modules: an arbitrary-precision interval type (899-1418), a difference-bound store (1419-1588), bitwise bounds (1590-1788), projection of a callee's `requires`/`ensures` onto its result interval (1790-2392), the rules for stores that narrow or implicitly convert (487-898), per-arm environments for `match` (2701-2882), carrying of known facts across a copy into a local, field or array element (3542-4679), checks on declaration (constant) initializers (4681-4956), division definedness (4957-5259), and reading intervals out of `domain` predicates (5260-5580). The walker returns, besides diagnostics, a bundle of "decisions" (8485-8494): obligations to check later, casts it judged exact, operations it judged formed, and operations whose check it postponed. Nothing in the slice calls a proof kernel; every verdict is an interval comparison or a boolean returned by another module of the same checker.

## Mechanisms

- **Arbitrary-precision intervals (`BigIntInterval`, 903-1289).** Optional low and high `BigInt`. Operations: intersect, add, subtract, union, divide (only when the divisor is strictly positive after sign normalisation, else unbounded, 987-1019), remainder, remainder by a constant with a tight case when both ends share a quotient (1041-1057), right shift over a count range, bitwise-and by sign quadrant (1076-1130), bounds from a comparison and from a refuted comparison (1132-1167), scaling, four-corner multiply, and `correlated_power` (same value multiplied by itself, so even powers are non-negative, 1253-1288). `to_interval` refuses an end outside `i64` (1182-1191). Serves domain predicates, range recipes and relational proofs.
- **Difference bounds (`DifferenceBounds`, 1422-1587).** Atoms are interned by name string and kept in lexical order; each atom has a sorted sparse row of `(target, bound)`. `record` keeps the larger bound (1484). `close` groups atoms into connected components with a union-find, adds the zero atom to each, and runs a Floyd–Warshall pass per component (1565-1586); a cycle with a positive sum marks the set unsatisfiable (1576-1580). There is no size budget; cost is cubic in the component size. `bound_indices` answers from a stored edge or from one hop through the zero atom (1497-1515). The users are outside this slice.
- **Bitwise bounds (`bitwise`, 1597-1787).** Converts the `i64` interval to `semantic_vocabulary::IntegerType` values, asks that type for and/or/xor/not/shift bounds, and falls back to the whole carrier. Takes a separately tracked exact `u64` value when one is known (1752-1765).
- **Projection of a callee contract onto the call result (`call_result_bounds`, 1807-2313).** Builds a fresh environment keyed by callee parameter names: each immutable, non-const parameter starts at its type range, is intersected with the caller's actual interval and with what each `requires` conjunct says about it; then each `ensures` conjunct that compares `result` with a literal, a widening cast, a parameter, a parameter `.length`, or arithmetic over those narrows the result. `&&` chains are flattened and each later conjunct is read under the earlier ones (1910-1958); `||` takes the union; a statically false or contradictory branch contributes nothing. Mathematical applications go through `scalar_predicate` and a small evaluator over `CheckedBooleanExpression` with a negation flag (2075-2132).
- **Deferred range recipes (`IntegerRangeRecipe`).** When a bound depends on a value only known later (a layout query, a const not yet evaluated, a call in an owner with a constant-evaluation entry, 2444-2465), the code builds a symbolic recipe (2399-2437, 5717-5734, 8456-8476) and, instead of deciding, pushes an `IntegerRangeObligation` (6493-6513).
- **Budgets.** `normal_return_length_collection` stops after 128 conjuncts (2510-2515) and peels at most 8 widening casts (2608); `bitwise_known_unsigned` stops at depth 64 (8386); type peeling loops are bounded by the type table size (413) or a visited list (5275-5285).
- **Match arm contexts (2726-2791).** One pass over the arms carrying a `remaining` context: each arm gets a clone narrowed by "pattern matched", and `remaining` is narrowed by "pattern did not match". Generic over the context type.
- **Evaluated write prefix (2891-2979).** An ordered set of written path strings with an `unknown` flag; `overlaps` finds candidate ancestors, `[*]` wildcards and descendants by string prefix and range lookups and leaves the final answer to `machine_calls::calls::frame_paths_overlap`. Not used inside this slice (used at lines 12072 and 26431 of the same file).
- **Fact transport on copy (`CopiedIntegerValue`, 3823-4565).** `capture` walks the delivered expression; for struct and array literals it recurses with a growing structural segment path and a growing text suffix; for a leaf it copies every interval, exact `u64`, float interval, "not NaN" mark, float alias and range recipe stored under the source's path, provided later sibling expressions do not write the source (`following_writes`, 3724-3741; `permits`, 3785-3811). Ordered relations are re-bound from the source operand to the destination and equalities `destination == source` are added as two `MinimumDifference(0)` relations (4232-4250). `record` then writes them under the destination path (4508-4564).
- **The expression walk (`ExpressionWalk`, 8710-8888).** A recursive abstract interpreter returning `Analysis {recipe, domain, interval, primitive}` (8448-8453). Five entry points configure the same walk with three flags (8539-8707). It records one `CheckedIntegerValue` per visit (8812-8816) and accumulates `ArithmeticDecisions` (8485-8494). The right operand of a short-circuit operator is analysed under an environment narrowed by the left (5896-5909).
- **Subtraction floor (6304-6342).** For a built-in subtraction, a lower bound on `left - right` comes from `ordered_values::subtract_floor` and from a captured numeric observation looked up by state symbol and expression handle; the larger is intersected into the interval.
- **Trap coverage by complement (8169-8257).** If the operation cannot be shown safe directly, the environment is narrowed by the negation of every published `crashes Trap` guard and the operation is checked again. This is done only in the entry state and only for guards built from integer and boolean literals, unary and binary operators and immutable primitive entry parameters (8134-8166, 8236-8239).
- **Trapping receipt demand (8265-8310).** A worklist closure: machines with a guarded ceiling, and machines with no ceiling and no closed private uses, need precise trap decisions; the need spreads to their private callees that publish no ceiling. Memoised per program.
- **Three-valued predicate evaluation (5325-5371).** Evaluates a domain predicate at one integer to true, false or unknown.

## Identity by text

- The value environment is keyed by path strings throughout: `record_assignment(path: Option<String>)` (502-516); callee parameter facts stored and read under `parameter.name` (1854, 2264); place reads by `place_path` string (7712-7713, 7864-7865); element facts by a formatted string (7850-7855).
- Element paths are formatted text: `"{collection}[{index}]"` (3064-3067) and `"{collection path}[{index path}]"` (3120-3124); the constant-index form uses a rendered place label (`place.label(program)`, 3082-3089, 3465).
- Float field facts are stored under a dotted string built from symbol names (395-399). Float aliasing is a pair of path strings (629-631); two match arms "read the same place" when their path strings are equal (551-556).
- A local is found by comparing its name text (`local.name.as_str() == name.as_str()`, 713); a bare name is tested against boolean literal spellings (690).
- `DifferenceBounds` atoms are name strings, ordered and searched lexically (1424-1461); the zero atom is passed in by name (1501, 1517).
- Written places are `&[String]` everywhere in `copied_values` (3559, 3727, 3769, 3887, 3955) and `EvaluatedWritePrefix` is a `BTreeSet<String>` searched by prefix, `"[*]"`, `"."` and `"["` (2919-2978). Overlap is decided on strings by `frame_paths_overlap` (2927, 6929) and `place_paths_overlap` (4347).
- `Operand::Place` carries `path: name string` next to the root symbol (3285-3288, 3373-3376, 3883-3886); `Operand::Field` carries `name` next to the field symbol (193-198, 311-316, 4181-4186).
- Copied facts carry a text suffix built with `format!("{suffix}.{}", field.name)` and `format!("{suffix}[{index}]")` (4299, 4318) and are re-keyed with `format!("{path}{suffix}")` (4532, 4548-4562). A stored range recipe is copied only if its place matches structurally and its stored path string starts with the source's rendered label (4359-4375). Descendant facts are selected by `strip_prefix` plus "next character is `.` or `[`" (4419-4422, 4440-4443, 4668-4669).
- A static machine argument's value is obtained by parsing its spelling: `CanonicalConstValue::from_atom(&spelling)` or `spelling.parse::<i128>()` (3378-3389).
- A proof atom's identity is the string `"\0declaration-value:{symbol:?}"` (4909).
- Diagnostics are recognised as duplicates by message prefix: `"cast target range in "` (2666-2671) and `"Exact integer cast in "` (7522-7529).
- The owner label is free text passed down as `&str`; the overflow message adds a sentence when `owner.ends_with("return value")` (6672), and the label is stored inside an `IntegerRangeObligation` (6508).
- Against the property: callee parameters and results are matched by symbol handle (2222-2227, 2546-2550, 6916-6919), checked values and numeric observations by expression handle and state symbol (4261, 4378-4381, 6318-6321), and stored integer range recipes by `CanonicalPlace` with `PlaceSegment`s (4359-4366, 4515-4535). Each copied observation carries both a structural segment path and a text suffix (3834-3838): the two schemes run side by side.

## Accepts or skips without proof

- **No proof kernel anywhere.** A grep of the whole file for `proof_admission`, `ProofNode`, `verify_obligation` and `certificate` finds nothing. The strongest external verdict used is `StrictArithmeticImplicationJudgment::Proven` from `contract_entailment` (4943-4953).
- **Deferral instead of refusal.** `require_representable_result` returns "not proven" with no diagnostic in two cases: it pushes an `IntegerRangeObligation` when a recipe exists (6493-6513), or a `PendingIntegerFormation` carrying the diagnostic text when pending formations are allowed and there is no storage graph (6515-6531). Whoever consumes those lists decides; cannot tell from this slice whether every one is consumed.
- **"Proven" means "the re-run produced no diagnostics"** in `forms_exactly` (5981-6024), `operand_interval` (2199-2215), `check_value_narrowing` (838-850), `returned_referent_range` (6941-6951), `exact_ordinary_actual_intervals` (7239-7249).
- **Callee `ensures` is used as a fact about the call result** (1856-1867, 7070-7094), about a result equal to a parameter's length (2476-2602), and about elements of array arguments (3171-3183). The last is limited to checked-body callees (3193-3202); for the first two the slice only requires an independent call application (7050-7069). Whether the callee body was shown to meet its `ensures` is decided elsewhere; cannot tell.
- **Callee `requires` is used to narrow the parameter intervals** when projecting the result (1836-1853), i.e. it is assumed to hold of the actuals. The call-site check of `requires` is elsewhere; cannot tell.
- **A `data` type's `requires` is recorded as true of any value of that type** (165-176, 393-403). The function name says "admitted", so the caller is expected to have established admission; cannot tell.
- **Declared range on a return or place type is trusted** (7049, 7867, 18-20). Environment facts found by path string are trusted (7864-7866).
- **User-defined operators skip all arithmetic rules**: when the operator is not the built-in one the result is the full range of its declared result type (5626-5628, 6061-6075). Other predicates that are not built-in comparisons are ignored as fact sources (238-246, 2005-2013, 3514, 5537), which is the conservative direction.
- **Stores**: no target primitive → no check (765-767); an interval missing either end is never reported as a narrowing failure (795); a suffixed literal or a read of an unresolved local initializer drops the source carrier, which disables the implicit-conversion rule (728-733); `is_direct_suffixed_integer_literal` says yes if *any* match arm is a suffixed literal (666-669). `check_value_narrowing` recurses per arm before reaching this (817-831); `check_validated_value_narrowing` is callable directly with a match (868-897), cannot tell whether it is.
- **`check_value_narrowing` discards the diagnostics of `validate_value_range`** and skips the narrowing check when there were any (838-850). Presumably the same validation runs elsewhere with real diagnostics; cannot tell.
- **Division**: non-fixed-integer primitive → not checked (5092-5098); a provably zero divisor suppresses the "not proven nonzero" message because the other rule reports it (5047-5049, 6148-6161); `signed_minimum` knows only `i8`..`i64` and any other primitive counts as "pair excluded" (4976-4984, 5032-5033) — cannot tell whether another signed carrier exists; proof integers set `signed_pair_excluded: true` (5252).
- **Abstract specifications**: shift and division checks return silently when the operator is not built-in, has no direct operand, has no width, or is not Exact (74-81, 92-94, 5194-5204).
- **Shift count**: returns "not proven" with no diagnostic when the policy has no within-width law, or no primitive or width is known (6701-6710).
- **Representability**: operators whose Exact policy has no `ResultRepresentable` condition fit unconditionally (6546-6555); when neither operand has a primitive and there is no target, `primitive` is `None` and division formation, representability and trap coverage are all skipped (5676, 5699, 5735-5736, 5782-5783). Anonymous arithmetic is folded first (8855, 7798-7836), which likely covers it.
- **Exact integer cast**: no diagnostic when `static_type_context_is_unreachable` (7495-7497) or when the walk has `checks_occurrence_fit == false` inside a machine (7520), i.e. in `analyze_arrival` and `analyze_meaning` (8673, 8702). The ordinary pass has the flag on.
- **Trap coverage**: a machine that publishes no crash ceiling is unrestricted (8104-8106); a `crashes Trap` contract with no guard or a literal `true` guard permits everything (8118-8125); arrival and meaning passes do not check (8672, 8701).
- **Declaration values**: node kinds not listed (calls among them) need no formation evidence in this loop (4744). `binary_result_fits` takes the prior facts as hypotheses with `holds: true` (4925-4931).
- **Fallbacks to "unknown"**: `NEUTRAL` for calls with nothing known (6874), unknown declared type (7856-7858), float and boolean literals (8884), failed atomic lookups (8821-8834); every node kind not named is analysed as a place (8885). These widen the interval, so they refuse more, not less.
- **`analyze_meaning` throws its diagnostics away** (8705); it is used to compute an interval only.
- **`scalar_path_survives` returns true when the write list is known and empty** (3561-3563); literals are always permitted as copy sources (3790-3799). Both are sound on their face.
- **Outputs downstream stages rely on**: `ExactIntegerCastFact` with bounds (7364-7370), `decided_formations` (5688, 5755, 5776), `trapping_decisions` (5796). These are this code's own verdicts published as facts.

## Surprises

1. **The interval type is `i64`, so the upper half of `u64` cannot be expressed.** A missing high end stands in for "up to `u64::MAX`". The consequences are spread over the slice: a side table of exact `u64` values (518-531, 8379-8439), a separate fit test for `u64` (6572-6592), `u64::MAX` patched in three places (2417, 6496-6498, 8472), and `bitwise::project` turning a lower bound above `i64::MAX` into `i64::MAX` (1782-1787). The last is sound but loses the bound.
2. **Some overflow checks end in neither yes nor no.** `require_representable_result` can push an obligation or a pending formation and return without a diagnostic (6493-6531). The pending record carries the error text to be issued later (6527). A reader of this function alone cannot tell that the operation is ever refused.
3. **Two answers to "which writes spoil a match arm's facts" coexist.** `dispatch_arm_environments` invalidates every arm's environment with the writes of the whole match expression, arm bodies included (2801-2825). The module right below it says "Later patterns and selected bodies cannot invalidate an earlier arm's premises" and builds `EvaluatedWritePrefix` for that (2884-2979), which nothing in this slice uses.
4. **`narrow_dispatch_selection` copies the subject's facts onto the capture path on both calls**, the "matched" one and the "did not match" one (2773-2788, 2873-2880), so the `remaining` context that flows to later arms also receives capture facts for an arm that was not taken.
5. **Declaration values refuse whole constructs rather than check them**: indexing, atomic access, borrow, zero value, recast and domain-qualified casts each get "has no declaration formation evidence" (4721-4752). The loop runs even when `local_formation` is supplied (4801), so if this function is called for a local's initializer those constructs would be refused there too; cannot tell from this slice who calls it with `local_formation`.
6. **The cast message says "machine" when there is none.** With no machine the owner label is substituted into "Exact integer cast in machine `{}`" (7532-7534).
7. **Wording depends on a label's suffix**: `owner.ends_with("return value")` adds a sentence (6672). Two diagnostics are deduplicated by message prefix (2666-2671, 7522-7529), so changing a message would change which errors are shown.
8. **A test-only enum variant is matched in production code**: `#[cfg(test)] Operand::CompletedCall` arms at 3630-3631, 4604-4605, 4639-4640.
9. **Tracing left in the read path**: an `eprintln!("SLOT integer-read …")` under `trace_flags::reference_slot_trace()` (7905-7917).
10. **`normal_return_recipe` is switched off globally when `program.constant_recipes` is empty** (2320-2322). Range recipes for call results exist only in programs that already have constant recipes.
11. **Trap coverage by complement works only in the entry state** (8236-8239) and only for guards over immutable primitive entry parameters (8134-8166). In any other state of a machine with a guarded ceiling, a `Trapping` operation must be proven unable to trap, which is the same demand as `Exact`.
12. **Machines that publish no crash ceiling and have no closed private uses are marked as needing precise trap decisions** (8275-8281), although trap coverage itself permits everything for them (8104-8106). The decisions are recorded (5788-5797) but no refusal follows from them here.
13. **Repeated work.** `forms_exactly_under` re-analyses both operand subtrees with fresh scratch state (6035-6042), `returned_referent_range` re-analyses the actual argument (6942-6948), and `exact_ordinary_actual_intervals` re-analyses arguments when the first pass produced any diagnostic (7227-7249). Each nesting level can re-walk its whole subtree once, so deep nests cost on the order of depth squared. I did not measure this.
14. **`checked_callee` scans all machines for every statement call** (3193-3202), and matches a callee by its machine symbol or by its entry state's symbol.
15. **In a data `requires`, a bare name is taken to be a field of the type** by reusing the name's symbol as the field symbol (276-284); the following lookup (292-299) rejects it if no such field exists.
16. **Atomic places are read in the `Wrapping` domain** whatever domain their type declares (7918-7922), and `enforced_declared_range` returns no range for an atomic type (638-641).
17. **Division by a same-carrier operand is taken as fitting the result type once definedness is shown** (5701-5702), without an interval check; this relies on `MIN / -1` being part of definedness.
18. **After reporting mixed domains the code still picks one** (the non-Exact operand's, 6201-6205) and continues checking under it, so one mistake can produce a second, policy-dependent diagnostic.
19. **Against property 3**: the walker itself is one piece of code for all expression positions, and the five passes are flag settings of it. The per-placement repetition in this slice sits in the fact sources and fact transport around the walker, not in the overflow rule.
20. **Against property 2, partly**: integer range recipes moved to structural places (`CanonicalPlace`) while intervals, exact `u64` values and float facts stayed on strings, and the copy code keeps both keys in step by hand (4359-4375, 4518-4535). The two can disagree: a recipe is dropped if the rendered label is not a prefix of the stored path string even when the places match.
