## What this code is for

This slice is not part of the source checker that judges whether a program's proofs hold. It is the middle of the `review-evidence` package: the code that turns an already-checked compilation into "package review evidence" and "package policy" rows, the records a person or a consuming package accepts when they take a dependency (`package_review.rs:1-10`, `semantics.rs:1-3`). It reads the checker's output tables (`compilation.facts`, typed trees, provider plans, service-reach rows, crash capsules) and writes portable records with no compiler-internal handles in them.

The slice covers four areas. `package_policy/` writes the package-wide rows: assumed-binding risk text, dangerous-authority exposure, external supply, native bindings, restricted build requests and semantic dependencies. `providers/` writes the selected provider plans, their rows, bindings, operator families, installation-bound service reach, compiler-intrinsic execution identities and boundary-operator application realizations. `representation/` writes opaque-representation declarations, availability, selections and ABI value placements. `semantics/` holds the shared translators: nominal identities and ownership, requirement identities, conformance applications and bounds, service methods, signatures, static ("type") parameters, crash routes and termination premises.

Almost every function has the same shape: look up one row by symbol, demand exactly one match, compare the projected value against a second copy ("custody", the retained original checked compilation, or a retained provenance record), and return `Err(vec![Diagnostic::error(..)])` on any disagreement. The module header calls this "fail-closed translation" (`semantics.rs:1`). The diagnostics are internal-consistency refusals ("lost its", "differs from", "has no exact"), not messages about the user's program, with a handful of exceptions that do state a language-level rule (public exposure of private traits or conformances, termination-premise roots, opaque-representation carriers).

## Rules enforced

"Own" means the code decides by its own comparison. "Asks" names the function in another module whose answer is used. No row uses the proof kernel: no file in this slice calls `proof_admission`, `ProofNode`, `verify_obligation` or anything certificate-shaped.

## Mechanisms

- **Literal integer interval audit** (`package_policy/assumed_bindings.rs:195-350`). For an assumed binding it computes, per positional parameter and for the result, a closed `i128` interval from the caller's and the supplier's contracts and reports when the two are disjoint. It only reads built-in binary expressions joined by `And` whose left side is the subject (`Result` or `Parameter(i)`) and whose right side is an integer literal, with `==`, `<=`, `>=`, `<`, `>` (lines 291-339). `!=`, `Or`, literal-on-the-left, arithmetic, and contracts with a `result_case` are skipped (lines 337, 343). Unparseable literals are skipped (line 317). `disjoint` requires both intervals to be non-empty (line 250), so a side whose own bounds contradict each other produces no finding. The result is text in the risk row; it never refuses. Serves assumed bindings.
- **Cycle-checked nominal walk** (`package_policy/semantic_dependencies.rs:125-296`). An explicit stack of `Symbol`/`Type`/`EndSymbol`/`EndType` entries walks a dependency's generic application down to the nominal declarations it mentions. `active_*` and `complete_*` are `Vec`s searched linearly. No budget other than cycle refusal. Serves semantic dependencies of materialized generic carriers.
- **Grounded-dependency check** (`providers/installation/dependencies.rs:85-117`). Depth-first search with an explicit `(node, next child)` stack and `visiting`/`complete` bit vectors; refuses on a back edge or an out-of-range child. No budget. Serves installation-bound service reach.
- **Trait-inheritance worklist** (`semantics/declarations/provider_schema.rs:40-81`). Walks parent traits from the selected schema, with a `visited` list, collecting each trait that declares the requirement; demands exactly one. Serves inherited boundary-trait requirements.
- **Static-argument reification** (`semantics/conformances/policy_arguments.rs:30-288`, `application.rs:25-124`). Recursively rebuilds a static argument as a type-reference tree in a scratch `CheckingProjection`, checking slot category at each level, limit 64 deep. Const values are turned into `Named` type nodes with an invalid symbol whose name is the canonical value text (lines 64-74, 255-265). `applied_kind` (lines 358-393) substitutes an earlier type argument for a const parameter's carrier when the carrier is a type parameter of the same declaration (the `Box<Element, const Count: Element>` case named in the header).
- **Caller-binder collection** (`policy_arguments.rs:290-356`). Reuses `typed_trees::references::visit_static_argument` to collect every type or machine parameter mentioned in the arguments and assigns each a framed identity string. Limit 64 deep.
- **Re-derive and compare.** Not one algorithm but the slice's main method: recompute a stored fact with the producer's own function and require equality. Instances: semantic dependencies (`semantic_dependencies.rs:31-37`), intrinsic execution identity (`providers/intrinsics.rs:32-58`), closed conformance application (`conformances/policy.rs:238-251`), crash buckets (`policy_crashes.rs:33-39`), opaque-representation selections (`representation/policy/selections.rs:40-51`), installation reach (`providers/installation.rs:163-185`), lifetime partition (`providers/policy/rows.rs:154-167`), operator plan name (`providers/policy.rs:234-244`), accepted schema digest (`runtime_permissions.rs:150-156`).
- **Framed identity strings** (`semantics/encoding.rs:4-20`). `framed_identity(label, children)` builds a length-framed string; `canonical_digest_label` builds `kind:hex`. Used to make callable and binder identities (`policy_callables.rs:109-132`, `policy_arguments.rs:332-335`).
- **Policy byte budget** (`package_review.rs:76-79`). One length comparison, made before service-binding candidates are computed.

## Repetition by placement or construct

This slice has no repetition by source placement (local, field, parameter, call result, and so on): it never looks at statements or storage places. Its repetition is by construct kind, mostly by the four provider schema kinds (boundary trait, top-level boundary requirement, sealed accessor, boundary operator) and by realization kind.

- **"Find the requirement under its schema kind", written five times.** Each copy matches on `ProviderSchemaDeclaration` and repeats "filter traits by symbol, demand one; filter its signatures by symbol, demand one" for the trait arm and "filter machines by symbol and supply mode, demand one" for the requirement/accessor arm: `providers/installation.rs:30-91`; `semantics/declarations/requirements.rs:63-120`; `semantics/services/authority.rs:25-91`; `semantics/services/signature.rs:126-182`; `semantics/declarations/provider_schema.rs:21-81`. A sixth partial copy is `semantics/declarations/requirements.rs:32-61` and a seventh `semantics/signatures/parameters.rs:420-442`.
- **Nongeneric vs specialized boundary application.** `providers/application_realizations.rs:47-108` and `:137-218` are the same loop (use-site destructure, package-ownership filter, location filter, row build, zero-digest refusal) with one extra field. The pair repeats again in `providers/boundary_policy/realizations.rs:102-117` and `:118-133`.
- **Three use tables, one filter.** `compiler_intrinsics.rs:379-395` (`named_uses`), `:397-417` (`named_requirement_uses`), `:419-447` (`uses`) each test "same site and same requirement" and build the same record.
- **Generic application rebuilt twice in one function.** `policy_arguments.rs:93-147` (argument arrives as a `Generic` type reference) and `:205-235` (argument arrives as symbol plus application); a third version is `application.rs:63-109`. Four wrapper type nodes (`Reference`, `FixedArray`, `Slice`, `Constrained`) each get an arm that recurses into one child (`policy_arguments.rs:163-189`).
- **Const value to named node, twice.** `policy_arguments.rs:56-74` (literal) and `:255-265` (named const).
- **Table bindings.** `providers/policy/bindings.rs:92-101` (`VtableField`) and `:102-111` (`TableFunction`) are identical apart from the variant name. Import and syscall rows are built at `:56-60`, `:73-82` and again at `:281-292` for native Build rows.
- **Value-parameter record** `{name, type identity, is_const, is_mutable}` is built at `semantics/signatures/parameters.rs:97-107`, `:368-379` and `semantics/services/signature.rs:105-110`; the proposition form at `parameters.rs:227-237`.
- **Lazy projection preamble.** `providers/policy.rs:37-52` and `providers/boundary_policy.rs:20-35` are the same 15 lines.
- **Mirror enums.** The compiler's enum is copied variant by variant into a `PackageReview…` twin: `providers/intrinsics.rs:63-140` (18 variants) and a second 18-arm match for labels at `:142-224`; `representation/physical_contract.rs:30-61`, `:88-113`, `:135-149`, `:167-177`, `:184-200`, `:207-252`, `:257-286` (19 registers); `package_policy/semantic_dependencies.rs:92-116`; `semantics/signatures/policy.rs:203-229`; `semantics/signatures/policy/values.rs:35-43` and its inverse at `policy_crashes.rs:55-60` (the same crash-guard enum converted in both directions).
- **"Exactly one, else refuse"** is written out by hand about 40 times (`let [x] = matches.as_slice() else { return Err(..) }`) although `semantics/facts.rs:6-20` provides `exactly_one` for it. Examples: `installation.rs:41, 53, 78, 104, 136, 151`; `requirements.rs:43, 54, 88, 107`; `authority.rs:32, 40, 60`; `availability.rs:41, 49, 62, 80`.

Estimate: about 1,300 of the 8,546 lines (roughly 15%) are per-construct copies of a rule or lookup, and about 450 more (5%) are mirror-enum copying. None of it is per-placement.

## Identity by text

Symbols (`SymbolHandle`) are the first join key in most lookups, and two headers say the code avoids name lookup on purpose (`policy_arguments.rs:2-3` "without parsing their display paths"; `services/authority.rs:2-3` "without display-name lookup"). But the identities this slice produces, and many of the comparisons it makes against provider plans, are strings.

- **A declaration's identity is its rendered path.** `nominal_identity` is `(owner, symbols.display_path(symbol, "::"))` (`semantics/declarations/identity.rs:32-39`). Every `PackageReviewNominalIdentity` in the slice is built this way and compared with `==`.
- **Requirement identities are strings**: `trait_requirement_callable_identity_text` (`requirements.rs:28`; `assumed_bindings.rs:41, 79`; `bindings.rs:237`), `machine_callable_identity_text` (`requirements.rs:140`; `policy_callables.rs:87`; `realizations.rs:26`), `boundary_operator_requirement_identity` (`requirements.rs:116`).
- **Joining plan rows to schema methods by identity text**: `providers/policy.rs:154-155`; `package_policy/native_bindings.rs:36-42`; `providers/installation.rs:100-101`; `providers/installation/dependencies.rs:41`; `providers/policy/families.rs:99-103`; `runtime_permissions.rs:189-192`; `semantics/services.rs:86`; `providers/boundary_policy/realizations.rs:69` (`requirement_identity` string equality).
- **Assumed-binding contracts are looked up by identity string** in a `Vec<(String, …)>` (`assumed_bindings.rs:42, 59-61, 79`), and the relationship is rendered as `"{required} -> {supplied}"` (`:136`).
- **Services are named by string in installation reach**: the upper bound and resolved rows are sorted `Vec<String>` of service names (`installation.rs:120-121, 159-160, 213-240`), mapped back with `id_for_name` (`:201-204`).
- **Callable identity is a composed string** (`policy_callables.rs:109-132`): machine path, overload text, symbol path, then the literal tags `"binder:{n}"`, `"machine"` or `"state:{name}"`, then per-parameter frames with `"{is_mutable}:{is_const}"`, then `"result-type"` / `"result-none"`, framed as `"conformance-callable"`. An operator spelling is framed in as `"token-bound"` (`:89-92`).
- **Binder placeholders are strings**: `"$parameter{ordinal}"` (`policy_callables.rs:98`), `"type-parameter:{n}"` (`signatures/parameters.rs:183`), framed `"conformance-caller-binder"` (`policy_arguments.rs:334`).
- **Caller binder located by display path**: `symbols.display_path(parameter.symbol, "::") == nominal.path` over every data type parameter (`policy_callables.rs:38-44`).
- **Const values carried as names**: a value becomes `TypeReferenceNode::Named { symbol: invalid, name: Identifier::generated(<canonical value text>) }` (`policy_arguments.rs:69-74, 260-265`; `application.rs:56-61`). An integer's type is passed as `primitive.name()` (`policy_arguments.rs:56`); a boundary application const carries `value.type_name` (`application_realizations.rs:316`).
- **Lifetimes are names.** Lifetime arguments are `Identifier`s or `String`s resolved by position of an equal name (`conformances/policy.rs:57-64, 171-176`; `application.rs:230-234, 283-288`; `policy_arguments.rs:340`); substitutions are name pairs where "the last matching source name is the lexical binder" (`signatures/parameters.rs:8-9, 49`).
- **Target compared by name**: `selected.target_name() == authored` (`application_realizations.rs:241`).
- **Plan names are generated strings and are checked as strings** (`providers/policy.rs:234-251`); provider type is an empty-or-not string (`:144`).
- **Dispatch table and field by name**: `dispatch.path(..) != table_name`, `field_storage(.., field_name)` (`bindings.rs:191-196`).
- **Owner path taken from a schema string**: for a top-level requirement, `owner.path = method.requirement_owner.clone()` (`semantics/services.rs:97`).
- **Toolchain path recognised by spelling**: one path component beginning `<` and ending `>` (`ownership.rs:108-119`).
- **Sentinel values as meaning**: an all-zero 32-byte digest means "lost" (`application_realizations.rs:102, 202-211`); an empty string means "no identity" (`compiler_intrinsics.rs:294`; `identity.rs:52`; `providers/policy.rs:144`).
- **Debug output inside policy text**: the assumed-binding row prints a non-adapter `ProviderBinding` with `{other:?}` and the dependency closure with `{:?}` (`assumed_bindings.rs:152, 184`); intrinsic labels use `{kind:?}`, `{register:?}`, `{operation:?}` (`intrinsics.rs:148-189`).
- **Parameter names are part of the evidence**: `name: parameter.name.as_str().to_owned()` (`signatures/parameters.rs:98, 369`).

## Accepts or skips without proof

- **A refuted assumed binding is still accepted.** When caller and supplier literal bounds are disjoint the finding is written into the row and nothing is refused (`assumed_bindings.rs:209-230`). The header says this is intended: the audit works "without vetoing accepted semantic links or granting propositions" (`:6-8`). I cannot see another check in this slice that refuses the binding.
- **Audit skips what it cannot read.** Non-literal bounds, `!=`, `Or`, literal-on-left and contracts with a result case contribute nothing (`assumed_bindings.rs:292-300, 311-319, 337, 343`); the fallback verdict is "unproved connection" (`:227`). Nothing else in the slice examines them.
- **Missing package identity or target renders as an empty string** in the risk row (`assumed_bindings.rs:185-186`). `runtime_permissions.rs:123-129` checks both before `render` is reached on that path; the `project` path (`assumed_bindings.rs:15-22`) has no such check that I can see.
- **Selection observation check is skipped when the handoff has none** (`package_review.rs:53-65`, `is_some_and`). Cannot tell whether the handoff constructor requires one.
- **Callables with no realized reach are skipped for slack** (`authority.rs:76-78`). They are still tested for exposure at `:65-69`.
- **Semantic-dependency walk**: an invalid symbol handle is skipped silently (`semantic_dependencies.rs:143-145`); builtin types and all parameter kinds are skipped (`:157-167`); `ConstExpression` and `Unit` nodes contribute nothing (`:278`). The whole table was compared with a fresh derivation first (`:31-37`).
- **Application selection defaults to true** for statement sites and for sites with no machine origin (`application_realizations.rs:229, 231-233`).
- **An application with an empty expression span and no authored selection is treated as "not this package's"** and dropped without a row (`application_realizations.rs:339-346`). Cannot tell whether another package's review picks it up.
- **Intrinsic applications skipped without a row**: any with arguments (`compiler_intrinsics.rs:55-57`), any whose requirement is a specialized copy (`:58-65`), statement sites (`:71`), Build-scope sources (`:74-81`), any whose requirement has no selected provider plan (`:218-224`), and any whose plan row is not a compiler intrinsic (`:256-263`). The header gives a reason for each (`:5-17`); the first two are said to be covered by the specialized path and by callable policy.
- **Implicit `Match` applications skip the package-ownership test** (`compiler_intrinsics.rs:149-160`); only the location-owner test at `:186` applies.
- **Authored use kind defaults to `Named`** when no token selection is found (`compiler_intrinsics.rs:344`), and `token_authored_use_kind(..).unwrap_or(realization.authored_use_kind)` trusts the derived kind (`application_realizations.rs:145-151`). The later "exactly one authored selection" check (`:412-429`) would catch a wrong kind.
- **Non-public machines produce no symbolic demand row** (`demands.rs:26-31`).
- **Boundary operators have no installation reach and no service authority**: `Ok(None)` (`installation.rs:90`) and an empty record (`services/authority.rs:84-90`). Header: "their operator contracts stay separate" (`authority.rs:5-6`).
- **Unsupported intrinsic with nothing retained is accepted as `None`** (`intrinsics.rs:264-265`).
- **Count-only reconciliation**: installation reaches and grants are checked by comparing totals, not by matching each stored item to a projected one (`providers/policy.rs:73-93`). A missing row and a surplus row elsewhere would cancel. Grants are separately filtered by `replays_selected_plan` (`:199`), which limits but does not remove this.
- **A plan with no provider-type declaration is accepted** when it is a native Build plan with all-native rows, or when it has no provider-type package and either an empty provider-type string or toolchain settlement (`providers/policy.rs:134-144`).
- **A toolchain-settled plan may leave schema methods without rows** (`providers/policy.rs:159-161`).
- **Only the first matching row's requirement is projected for a method** (`providers/policy.rs:162, 177`); the others are checked to name the same requirement (`:165-171`).
- **A syscall binding with no evaluated `via` row is accepted with `evaluated: None`** (`bindings.rs:63-82`, `evaluated_row` returns `Ok(None)` at `:150`). An import must have one (`:48-50`).
- **`CompilerIntrinsic { machine }` and `VtableSlot { index }` are copied without a check in this function** (`bindings.rs:84-91`). The intrinsic is checked separately by `project_compiler_intrinsic_execution` (`rows.rs:111-116`); I see no check of the vtable slot index in this slice.
- **Operator families from `UniqueCoveringCandidate`, `NativeBuild` and `TargetRealization` selection are not projected** (`families.rs:169-171`); coverage is always written as `CompleteDeclarationFamily` (`:135`), after the count check at `:76-84`.
- **Native rows skip owner and lifetime-partition validation** (`rows.rs:70-71`).
- **Opaque uses are skipped when the package has no selections, and a selection with no matching use is skipped** (`representation/policy.rs:65-67, 76-78`).
- **With no selected build machine, the machine checks are skipped** and selections are re-derived with `None` (`selections.rs:25-39`). The header says this is deliberate (`:5-6`).
- **Saved identity errors are held, not raised.** `PreparedRuntimePolicy::capture` stores `Result` values (`runtime_permissions.rs:32-36, 64, 76-80`); an error surfaces only if that service or requirement is later used (`:164, 206-207`).
- **Closure trait arguments compared by length only** (`application.rs:289`).
- **Unrecognised type nodes pass through unchanged** in a type slot (`policy_arguments.rs:190`), and a const-slot `ConstExpression` is returned as is (`:77-89`). The symbol path checks category (`:236-280`); the type-reference path does not for these nodes. Cannot tell whether an earlier stage guarantees it.
- **A const or value slot accepts a type parameter** (`policy_arguments.rs:272-273`).
- **A missing producer callable identity becomes an empty string** (`identity.rs:46-53`), by stated design (`:5-7`). `bindings.rs:175` stores it without checking for emptiness; the native path does compare it (`bindings.rs:252-253`).
- **Unresolved owner is returned, not refused, by `nominal_owner_from_symbols`** (`ownership.rs:69-82`); callers refuse later (`ownership.rs:31`, `selection.rs:18`, `selections.rs:71`, `policy_arguments.rs:328`), but `nominal_identity` itself returns an `Unresolved`-owned identity to any caller that does not look.
- **A symbol with no source file counts as Product scope** (`ownership.rs:153-159`, `is_none_or`).
- **`BoundaryRequirement` and `BoundaryOperator` schemas are returned by `provider_requirement_schema` without checking the requirement belongs to them** (`provider_schema.rs:37-39`). `requirements.rs:82-83, 105` and `services/signature.rs:131, 157-158` check `symbol == requirement` afterwards.
- **Service method facts are copied from the plan's schema**: completion, entry and result claims, service reach, synchronous invocations, `may_suspend`, `may_block`, `terminates_guarantee`, termination premises (`semantics/services.rs:169-186`). The same function projects `authority` from source (`:170`) but does not compare the two. Cannot tell whether the encoder or a later stage compares them.
- **No conformance for a provider type yields empty boundary arguments** (`services/calling.rs:104`).
- **Non-`Terminates` guarantees yield no premises** (`services/authority/progress.rs:18-20`).
- **`framed_identity` and `canonical_digest_label` ignore write errors** (`encoding.rs:11, 18`); writes to a `String` do not fail.

## Notes the authors left

- `restricted_build.rs:1-6`: copies request meaning only "so source edits do not demand fresh permission acceptance when requested authority is unchanged".
- `semantic_dependencies.rs:1-5`: `dropped by` edges "project the exact selected cleanup hook rather than a declaration family"; generic carriers follow "checked nominal application metadata … rather than publishing generated carrier names".

- `application_realizations.rs:1-7`: filter to the active target "so inactive generic demands never require active specialization plans"; reconcile token uses "whose `Operator` selection resolves to the specialized machine instance while the token spelling binds on the declared template".
- `compiler_intrinsics.rs:5-17`: "Build applications have their own checked instance and execution profile and are reviewed by callable policy rather than Product provider plans"; "A target that selects no provider for a requirement has no realization of the application to attest unless a selected plan binds the requirement without rejoining the use."
- `boundary_policy/realizations.rs:4-10`: "A requirement machine's token view shares its symbol, but the provider slot is the machine, so its coordinate uses the machine's named-callable overload identity rather than the operator signature."
- `installation.rs:1-5`: review substitutes dependencies itself "so a broad upper bound never replaces a selected child's concrete contribution".
- `installation/dependencies.rs:2-6`: "We ground selected installation rows in checked dependencies rather than mutual claims"; explicit stack "avoids consuming the host stack on long installed chains".
- `providers/policy.rs:4-7`: "toolchain-settled plans (such as `FilesystemHost`) omit authored provider types while covering only the leaves the toolchain binds".
- `bindings.rs:5-9`: a toolchain-settled row carries "no evaluated `via` receipt because no authored machine realized the row"; "For checked adapters, we prove which executable the row selected before replacing its private specialization name".

## Surprises

1. **This slice is not a checker of programs.** It was deleted with the old checker because it reads the old checker's tables (`checked_trees`, `typed_trees`, `validation`, `typed_trees_to_checked_trees`, `selected_dispatch`), but its own job is package review and consent records. Its "rules" are mostly agreement tests between two copies of the same data.

2. **Property 1 holds here in a specific form.** Nothing asks the proof kernel. Where the code wants assurance it runs the producing function a second time and compares (see "Re-derive and compare" under Mechanisms). That detects a stored value that was altered after it was produced; it cannot detect a producer that is wrong both times. The vocabulary shows the intended threat: "spoofed compiler execution identity" (`intrinsics.rs:236, 267`), "a supplied selection mask cannot hide a live checked declaration" (`ownership.rs:11-12`).

3. **The only place the slice reasons about contract content is advisory.** The assumed-binding interval audit can establish that a caller's `requires` and a supplier's `requires` cannot both hold, labels it "refuted entry connection", and still returns the row as accepted policy text (`assumed_bindings.rs:209-230`). The row itself says the mapping is "positional, runtime-only; no additional domain establishment authority" (`:184`).

4. **A bound on a trait with lifetime parameters can never be reviewed.** `trait_lifetime_arguments` is set to `Vec::new()` (`bounds.rs:40`) and then compared with the trait's lifetime-parameter count (`:58-65`). Any such trait is refused with an arity message ("with 0 target lifetime argument(s), expected N"). The refusal reads like a user error; it is an unimplemented case.

5. **Closure agreement on trait arguments is by count.** `application.rs:283-290` compares the trait symbol, the lifetime names, and `closed.trait_arguments.len() != trait_arguments.len()`. The diagnostic says the closure "disagrees with its exact instantiated trait application", but argument content is not compared there. The sibling `conformances/policy.rs:240-248` does compare the full lists.

6. **Candidate and original are the same object on the runtime-permission path.** `PreparedRuntimePolicy::capture` passes one `MathematicalCallQueries` as both `mathematical_calls` and `original_mathematical_calls` (`runtime_permissions.rs:50-55`), and builds the input with `SourceDeclarationInput::checked(&source.program, ..)`, which sets `original_program` and `original_checking_input` to the same program (`input.rs:51-66`, outside this slice, looked up after reading). Every candidate-against-custody comparison reached from this path (`ownership.rs:139-146`, `callable_scope.rs:31-38`) is then a value compared with itself. The comparisons only do work when the caller builds the input with `PackageReviewInput::supplied(program, custody)` from two different programs.

7. **Unchecked parallel-vector indexing next to checked.** `rows.rs:42-43, 113-114` and `providers/policy.rs:166, 177` index `row_requirements`, `row_realizations` and `row_compiler_intrinsic_executions` by plan-row index with no length test, so a mismatch panics. `compiler_intrinsics.rs:229-237` tests exactly those three lengths and returns a diagnostic. `native_bindings.rs:21-25` uses `zip`, which silently truncates.

8. **Two rules for the same thing.** A termination premise may be rooted at a parameter or a public declaration in `declarations/progress.rs:55-75`, but `services/authority/progress.rs:24-32` accepts only a parameter. The second is the service-method path; a public-declaration-rooted premise on a service requirement is refused there with "progress subject is not one exact requirement parameter".

9. **Inconsistent carrier substitution.** `applied_kind` is given the unprocessed sibling list, including later siblings, at `policy_arguments.rs:124`, and only the already-processed earlier siblings at `:221`. The two paths can pick different carriers for a const parameter whose carrier is a type parameter.

10. **Values travel as identifiers inside the type table.** Const values become `Named` type nodes with an invalid symbol and a generated name holding the canonical value text (`policy_arguments.rs:69-74`). The header of `signatures/policy.rs:4-6` shows the authors were moving away from "a dummy type string" elsewhere.

11. **Debug formatting feeds consent text.** The assumed-binding row embeds `format!("{other:?}")` of a `ProviderBinding` and `{:?}` of the dependency closure (`assumed_bindings.rs:152, 184, 189`). These rows go into `runtime_permission_rows` (`runtime_permissions.rs:217-229`). A change to a derived `Debug` impl would change what a user is asked to accept.

12. **A capability worth knowing about: authority slack.** `package_policy/authority.rs:75-90` reports each dangerous service that a callable declares in its service-reach ceiling but does not actually reach. `exposes` (`:99-125`) unions six different reach sources to decide exposure.

13. **Old target list.** `physical_contract.rs:88-104` enumerates `LinuxArm64`, `LinuxX64`, `MacosArm64`, `MacosX64`, `WindowsX64`, `UefiX64`, `CrossPlatformCli`, `LocalUnchecked`, `AlphaBootstrap`. `AlphaBootstrap` hits `unreachable!`, guarded by the `native_realization()` test at `:76-81`.

14. **`unreachable!` after self-construction.** `application_realizations.rs:95-101` destructures a row it built five lines earlier and has an `unreachable!` else-arm; similar at `families.rs:61-63`, `policy_arguments.rs:46, 391`, `establishment_routes.rs:38-40`, `services/signature.rs:181`.

15. **Dead parameter.** `services/signature.rs::project` and `project_declaration` take `calling: Option<&PackagePolicyCallingPlan>` and have a 22-line branch for `Some` (`:92-114`, `:48-52`); both functions are `pub(super)`, so their only callers are in `semantics/services.rs`, and both pass `None` (`:132`, `:134-141`). A grep of the package after reading found no other caller. The `Some` branches cannot run.

16. **Linear scans everywhere.** Lookups are `iter().filter(..).collect::<Vec<_>>()` over all traits, machines, conformances or data definitions per query; `callable_identity` scans every machine per call (`policy_callables.rs:57-75`) and `caller_binder_identity` scans every machine's type parameters and then every data type parameter (`:28-44`). Visited sets are `Vec::contains` (`semantic_dependencies.rs:165, 169, 242, 245`; `provider_schema.rs:44`). There are no dense tables or maps in the slice.

17. **Message reuse hides the site.** "uninstantiated generic service carries a closed calling application" is emitted from two functions (`semantics/services.rs:117`, `services/signature.rs:50`), and "assumed binding contract lost its exact requirement declaration" from two (`assumed_bindings.rs:64, 111`).

18. **Stated goal: keep consent stable across irrelevant edits.** Several notes explain a choice by what should not force a user to re-accept: private specialization names (`providers/policy/realizations.rs:1`), source edits with unchanged build authority (`restricted_build.rs:5-6`), operator tokens as a breaking change (`policy_callables.rs:6-9`). This is a design constraint that the three sampled properties do not describe.
