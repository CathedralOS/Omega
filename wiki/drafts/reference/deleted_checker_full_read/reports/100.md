## What this code is for

This slice is the part of the old source checker that decides whether one declaration's contract is covered by another's, plus several helpers that answer "is this fact known at this point in a state body". The first half (15225-19928) checks that a machine which realizes a trait requirement, fills an operator, or is passed as a callable value asks no more (`requires`) and promises no less (`ensures`) than the declaration it stands in for, and that it carries the trait's laws as its own `ensures`. A small inductive prover (16631-17140) checks the `ensures` of a single-state machine whose body is only transition arms, including tail self-calls. The second half (19929-23684) collects numeric observations at a statement (known scalar values, a proven lower bound on `a - b`, "this result equals that storage"), projects observed values through fields, indices and variant cases, checks that lending an exclusive reference to a field of a `data` with `requires` leaves the data's predicate true when the loan ends, and decides whether integer and float operands fit their target carrier (casts, conversions, binary results, divisors, shift counts). Small utilities decide whether a state's transition guards cover all exits and whether a fact mentions proof-only data or a zero value. Nothing in the slice calls a proof kernel; every answer is a `bool`, an enum verdict, or a diagnostic produced by this code or by sibling modules (`StructuralJudge`, `Engine`, `scoped_arithmetic_implication_for_declaration`). One entry point (15415-15431) already calls the new lowered prover, `lowered_discharge::prove_callable_refinement`, and falls back to the source path only when that prover says "unsupported" or "incomplete".

## Mechanisms

- **Positional atom unification for arithmetic implication** (15776-15901, 15988-16024, 16057-16083). Each fixed-integer generic, parameter and the result of both declarations is bound to an atom named by role (`\0contract-parameter:{position}`, `\0contract-result`, `\0contract-generic:{identity}`), so the two contracts share variables by position. The hypotheses and goal are handed to `scoped_arithmetic_implication_for_declaration`. Limit: only fixed-integer carriers get a binding (15995-16004); only facts whose operators all have builtin meaning take part. Serves trait-requirement and callable contract refinement.
- **Float predicate implication** (15235-15372). Reads `subject <op> literal` (either side), turns it into a `facts::FloatPredicate`, and compares subject identity plus `implies`. Serves float bounds in contracts.
- **Per-arm inductive entailment** (16648-17140). For a single-state, transition-only machine: build one `Engine` per arm; install the `requires`; install the negation of every earlier guard and the arm's own guard; bind `result` to the arm's value, or for a tail self-call install the `ensures` as an induction hypothesis after proving the measure decreases; judge each `ensures`. An arm after an unguarded arm, or with contradictory `requires`, is vacuous (16892-16899, 16958). No numeric budget in this slice; `collect_guard` takes a depth argument of 0 (16909-16915). Serves `ensures` on `transition`-style machines and `terminates by`.
- **Canonical source key with epoch scratch** (17502-17697). Iterative depth-first walk over an expression graph with cycle detection, a work budget `MAX_SOURCE_MATCH_WORK = 4096` (17514) on visits and on unfolded tree size (17638), reusing a visit array across calls by epoch number. Refuses if any spelled binary operator lacks builtin meaning (17677-17685). The key is the string from `normalized_expression_identity`.
- **Paired payload walk** (17792-18002). Walks two expressions in lockstep, budget 4096, depth limit 128 (17829), comparing the call/cast/member/struct-literal fields that the key omits.
- **One-way term matching** (19331-19442) with **generality check** (19004-19025). First-order matching of a law pattern against a proven term, binding requirement parameter names; then requires every binding to be a distinct satisfier parameter. `Opaque` never matches `Opaque` (19438).
- **Operation slot resolution** (19040-19129, 19161-19323). Lists the trait application and its parent traits, resolves a call target to a (requirement, application identity) slot, finds the conforming machine for the carrier by scanning all machines, rewrites law terms to call that machine.
- **Exit coverage by guard shape** (16283-16446). Pattern check on guards; no solver.
- **Numeric observation over all paths to a statement** (19996-20979). A `StructuralPrefixVisitor` receives a `StructuralJudge` per path and combines across paths: scalar values must agree or become unknown (20853-20860); subtraction minimums take the smallest (20797); result-to-storage associations are intersected (20578). Results are memoized per (machine, state, demand, transition-target flag) and statement index (20082-20147); a batch pass fills every statement of a state at once (20200-20372). A row computed inside an enclosing cut is stored only if complete (20057, 20071).
- **Observed-value projection** (21008-21165, 21595-21626). Walks `PlaceSegment`s over a `StructuralTerm`, crossing readable references, switching to the source constructor's carrier, and requiring a proven case for `Case` segments.
- **Loan hand-back check** (21639-21846). For each exclusive argument, finds the lent place, walks outward over each enclosing field, and re-judges the owning data's predicates at the call's return point.
- **Data predicate on current storage** (22072-22165, 22179-22276). Binds each field name to its current projected value, tries a direct projection term, then an instantiated-fact judgment with a synthetic subject binder.
- **Carrier-fit lattice** (22416-22433). `Refuted` beats everything, then `Unknown`; `Proven` yields to the other side; two `Pending` intervals are unioned. Results for all builtin binary operations of a machine are computed in one batch and memoized by (machine symbol, expression) (23133-23206, 23276-23324). A fit not established on the direct prefix walk is retried over "private arrivals" (23248-23272, 23364-23371).
- **Exact integer-to-float alternatives** (22620-22680). Generates up to 128 alternative predicates (one per scale) and accepts if any is proven.

## Accepts or skips without proof

- **Lowered refusal falls back to the source path** (15421-15430). If the lowered prover answers `Unsupported` or `Unproved(incomplete)`, `prepare_lowered` returns `None`, and the caller can use `prepare` and the source `entailed`. Cannot tell from this slice whether the caller always does.
- **Required `ensures` skipped when the machine has a conformance edge** (15643, 15627-15638). With `owes_through_edge`, every required `ensures` with builtin meaning is accepted here without entailment. The law check in this slice skips conjuncts that mention `result` (19713-19718) and silently drops conjuncts that are not equalities or Boolean calls (return value of `collect_equality_conjuncts` ignored at 19603-19609). So a requirement `ensures` such as a bound on `result` is checked by neither routine in this slice when the edge exists. Cannot tell whether a check outside this slice covers it.
- **`law_checked` skips the refinement check** (15652). It is `true` for every proposition fact (15882) and for any equality not mentioning `result` whose two sides have structural terms (16101-16125). The proposition and law checks at 18736 and 19582 would catch these if they run for the same machine; cannot tell whether they always do.
- **`boundary_qualification_authorization(...).is_some()` accepts** a required `ensures` (15644-15651). Defined elsewhere.
- **Parameter-count mismatch returns silently** (15565-15567). No diagnostic; cannot tell whether arity is checked elsewhere.
- **Contracts of other kinds skipped** in `ContractFacts::collect` (`_ => continue`, 15866) and in operator `collect_contracts` (`EnsuresForResultCase` and `Crashes` skipped, 18706-18707). Crash contracts get their own check (18576); result-case `ensures` of an operator are not compared anywhere in this slice.
- **Integer binding skipped silently** for non-readable or non-fixed-integer types (15995-16004). The fact then has no atom; the implication is less likely to prove, so this refuses rather than accepts.
- **`bind_selected_operations` returns silently** on empty or duplicate operations (15908-15910); `instantiate_family_packs` leaves a conjunct untouched when binder arguments cannot be synthesized (15970-15977). Both leave less to match, so they lean toward refusal.
- **Premises without builtin meaning or that are not expressions are dropped** from the hypotheses (16059-16068). Fewer hypotheses; refusal side.
- **No `Case` segment means "holds"** (16168-16174). Correct by construction: there is nothing to prove.
- **A state with no transitions counts as covered** (16297). Only the state's direct statements are read (16288-16296); cannot tell whether nested transitions exist.
- **Case guards with `==`** are accepted as case tests without the builtin-meaning check that `CaseMembership` gets (16353-16360). Cannot tell whether `==` on a case path can be user-defined.
- **Inductive check silently does nothing** for: more than one state (16658-16660), an empty body (16662), any non-transition statement other than an arm marker or a leading call-free immutable inferred local (16668-16679), a transition with a continuation (16680-16682), any other target kind (16700-16702), a guard that writes (16712-16722), an arm the engine cannot prepare (16728-16738). ## Surprises

- **The old checker already called the new one.** `CallableContractRefinement::prepare_lowered` (15415-15431) runs `lowered_discharge::prove_callable_refinement` and keeps its verdict (`terminal_check_tables::Checked<()>`); the source implementation is a fallback for "unsupported" and "incomplete". For the lowered variant one verdict answers both the `requires` and the `ensures` question (15511-15516).
- **No proof kernel anywhere.** A grep of the range for `proof_admission`, `ProofNode`, `verify_obligation` and `certificate` finds nothing. Every acceptance is this code's own comparison or a sibling module's enum verdict. This supports property 1.
- **A possible hole in requirement coverage.** For a machine with a conformance edge, required `ensures` conjuncts that mention `result`, or that are not equalities or Boolean calls, are skipped by `check_contract_refinement` (15643) and by `check_law_conformance` (19603-19609 ignores the "incomplete" result; 19713-19718 skips `result`). The comment at 18161-18163 says unsupported siblings must not get a receipt, and `matched_machine_law_guarantees` (18411-18419) and the operator check (18714-18722) both honour the "incomplete" result; `check_law_conformance` alone discards it. Whether a routine outside this slice checks those conjuncts I cannot tell.
- **Three different strengths for the same rule.** Trait requirements get arithmetic implication (16075-16083); operators get syntactic matching only, and a provider whose `requires` is weaker but differently written is refused (18539-18551, "may only repeat requirement premises", 18465-18466); laws get term matching with slot rewriting. The answer to "does this provider cover that contract" depends on which construct asks.
- **Law conformance matches declarations against declarations.** `proven_conjuncts` are read from `program.machine_contracts(machine)` (19672-19675), not from any record of what was proved. The `proven` vector that the inductive checker fills (16655, 16802) is not consulted here.
- **A proposition law can be satisfied by a string coincidence**: a rendered `ensures` expression equal to the expected Boolean label (18861-18864).
- **A name decides which parameter is the receiver**: `inherited_satisfier_parameters` drops the first parameter if its type's last path segment is spelled like the trait's (18309-18327).
- **Termination orders are recognized by path text** (17067-17077). With two decreasing subjects and no limit the measure is `upper - lower` for any accepted order, including `Nat::Descending` (17096-17099); the code does not tie the two-subject form to `BoundedDistance`.
- **`fact_mentions_proof_only_data` resolves names by text against the first state only** (16482, 16490-16496): a single-member name is looked up among the entry state's parameters; locals and other states' parameters are not consulted. A multi-member path is flagged if its first member is spelled like a proof-only data type (16498).
- **`complete_case_guards` searches every data definition in the program** for one whose variants are all present among the guards (16364-16382), instead of using the subject's type.
- **The proof check reads the layout plan.** `predicate_field_place` and `predicate_application` map a semantic field to its physical field through `plan_laid_layout_for_data` (22342-22362, 22385-22391), so the data-predicate judgment depends on how the data is laid out.
- **Memo use is gated by pointer equality**: `std::ptr::eq(stored, machine)` and the same for the state (20004-20009, 23283-23290).
- **Memo rows keep the first value written** (`get_or_insert`, 20144), and operand-fit memos store negative results (`Refuted`, `Pending`) as accepted entries and `None` for unaccepted ones (23191-23199, 23233-23237).
- **The judgment is overwritten, not combined, on some paths** in `OperandFit::observe`: `self.judgment = Some(CarrierFit::Unknown); continue` (23454-23456, 23589-23591, 23599-23600, 23608-23609). An earlier `Refuted` becomes `Unknown`. Both refuse, so acceptance is unaffected, but a "disproved" outcome can be lost.
- **`range_complete` is not cleared on two of those paths** (23599-23600, 23608-23609), while it is cleared on the others (23455, 23590). A recipe gathered from other paths can then still count as complete (23388-23392) although one path was not observed. I cannot tell whether a consumer relies on it.
- **Law diagnostics can repeat**: `carrier_slot_bindings` pushes the "AMBIGUOUS satisfiers" error once per law conjunct that needs the slot (19777-19784 inside the loop at 19711).
- **Law conformance is recomputed** by `matched_machine_law_guarantees` into a throwaway diagnostics list (18378-18400).
- **Environment and trace switches inside checking code**: `std::env::var("OMEGA_ENTAILMENT_TRACE")` is read on every call of the inductive check (16724); `struct_trace()` prints with `eprintln!` (16227-16231, 22245-22250).
- **Stale header comment**: 17142-17151 describes sibling `.rs` files that are inline modules of this one file; `float_implication` is declared before its parent's `use` lines (15226, 15375), consistent with files pasted together.
- **Possible panics**: `.expect("a provider crash contract contributes its own bucket")` (18601) and `unreachable!("semantic_value strips observations")` (19459). Both look safe from the surrounding code.
- **`ExpressionNode::Atomic` is handled at 16477 and again at 16557**; the second is dead for the proof-only walk and live only for the zero-value walk.
- **Property 3 is weaker here than in the sampling.** This slice has little per-placement copying of a rule across local/field/parameter/return. Its repetition is per construct (trait requirement, callable, operator, law, proposition law) and per conversion kind. The projection, numeric-observation and carrier-fit mechanisms are general: they work on `CanonicalPlace` segments and structural terms for any place. The only placement list is "local initializer or assignment" for delivered values (20275-20279).
