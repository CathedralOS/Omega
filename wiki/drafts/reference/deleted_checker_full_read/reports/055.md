## What this code is for

This file plans assignment statements. For each authored `place = value` in a state body it tries to produce one `CheckedUnitEffectOperationPlan::Store` record that the later Terminal emitter turns into a write (S:1-30, S:3280-3476). It resolves the destination from the target expression alone (module `destination`, S:829-1765) and the stored value from the right-hand side alone (module `value`, S:2559-2758), then picks a "store leaf" kind from the declared type of the place the path ends at: `ScalarField`, `Primitive`, `ViewElement`, `ByteElement`, `ByteContents`, `ByteDescriptor`, `SumField` or `RepresentationView` (S:11-25, S:2760-2776). Every function returns `Option`; `None` means "this planner does not write this assignment". The file contains no diagnostic text and builds no error value. The only record of why a plan stopped is a static phase string passed to `trace.phase(...)` (for example S:105, S:966, S:1024, S:3375). The file does not call the proof kernel. It reads earlier results out of `CheckFacts` (`facts.scalar_index_is_proven`, `facts.byte_write_is_proven`, `facts.proof.integer_assignment_at`) and copies them into the plan as booleans or decision handles (S:644-647, S:1836-1846, S:1995-2009, S:3453-3459). Comments say repeatedly that later stages re-prove what this planner records ("Terminal re-proves `index < extent`", S:2370-2371) and that earlier stages already judged mutability and loans (S:1203-1207, S:1581-1583, S:1713-1715). Whole-record assignment and array-literal assignment are explicitly left to another file, `control::statement_sequence` (S:18-19, S:27-30). The entry points are `build_structural_scalar_field_store_sequence_traced` (S:3020), `build_structural_call_result_field_store` (S:3100), `build_completed_byte_value_store` (S:3136) and `scalar_capture_destination` (S:2952).

## Mechanisms

- **Destination resolution** (`destination::resolve`, S:956-1092). It turns a target expression into a root (parameter plan row or local symbol), a canonical place, an optional trailing index, an optional recast view and a selector table. It applies receiver aliases from another module (S:1006-1009), rejoins loan locals to the place they borrow (S:1010-1014), then tries roots in a fixed order: structural parameter, `mut` scalar formal, exclusive-reference local, owned local (S:1031-1072). It serves every assignment target.
- **Storage walk** (`Destination::walk`, S:1306-1458). One loop over place segments builds the checked carrier path. It tracks the current declared type, the current record owner, a selected case, whether the walk ends at a field, and the position of the last element-view crossing. After each step it peels constraint shells and exclusive references, inserting explicit `Referent` steps, with a visited list to stop on a repeated reference type (S:1422-1444). No budget other than that list. `storage_projection` prefixes a `Referent` step when the root is an exclusive-reference local that is not a slice or byte descriptor (S:1283-1304). This is the one general, placement-independent mechanism in the file: fields, cases, literal and runtime elements and pointer crossings all go through it.
- **Selector admission** (`TargetSelectors::resolve`, S:2401-2495). It walks the target from the outside in, numbering indexed steps by depth, checks each against the selector list `validation::assignment_target_selectors` returns, and requires each runtime selector to be retained in `facts.values` at `AssignmentIndex { depth }`. It then adds a side table of index segments taken from the loans of the state's first borrow record (S:2464-2490) so that selectors introduced by a borrow alias, which the target never spelled, can still be named.
- **Byte value planning** (`byte_value_plan`, S:378-579). A recursive descent over the right-hand side builds a tree of `Literal`, `Concatenation`, `Whole` and `Field` nodes in an arena and returns a capacity for each. Depth budget 128 (S:391). Capacity adds with overflow check (S:437). Domain obligations are pushed down: literals must grant each domain, concatenation requires each domain be concat-preserving, places must have a source domain that implies each target domain. It serves bounded byte strings.
- **Scalar value selection** (`value::authored_value`, S:2656-2693; `primitive::primitive_store_value`, S:2076-2139). The stored value is found by coordinate `(state, statement index, role)` in two tables of `CheckFacts`: scalar computations and bound pure scalar expressions. A coordinate that has both is refused. A comment states the intent: a computation "that exists but belongs to a different machine, authored expression or carrier is a custody mismatch, not permission to fall back to another source" (S:2651-2654).
- **Exactness by re-lowering** (`scalar_custody_is_exact`, S:2226-2255; `scalar_store_value_is_exact`, S:2267-2292). The planner lowers the authored expression again with `values::lower_unit_scalar_argument` and compares the result structurally with the retained expression. It also compares the binding's symbol list against a freshly computed list (S:2203-2224).
- **Dispatch by leaf type** (`plan_assignment`, S:3280-3476). A fixed sequence of tests picks a lane: element view, whole-root byte index, whole byte contents, representation view, primitive leaf, byte field, shared view field, scalar field, sum field. The first lane that matches returns; several earlier lanes return `None` for the whole assignment rather than falling through (S:3336, S:3359, S:3370).
- **Runtime index to scalar expression** (`runtime_index_expression`, S:3184-3274). It maps each `CheckedRuntimeIndex` variant to a scalar expression. For `Local { position }` it recounts primitive-typed local declarations in statement order to find the dense position (S:3234-3254).

## Accepts or skips without proof

- **Local roots get no authority check here.** `exclusive_authority` returns `Some(())` for any `Root::Local` (S:1216-1218). The comment says "Source assignment validation already judged binding mutability and the stored-reference access route" (S:1203-1204). I cannot see that check from this file. Some lanes add their own local mutability test (S:123, S:188, S:2021-2026); the scalar field lane (S:3437-3463), sum field lanes and element-view lane do not.
- **Byte write and whole byte store run before `exclusive_authority`.** `plan_assignment` returns from `byte_stores::byte_write` (S:3338-3360) and `byte_stores::whole_store` (S:3361-3366) before the call at S:3367. Those lanes check access themselves, but they do not run the parameter roster count, and the `MutableBorrow` arm of `byte_write` (S:129) and the parameter arm of `whole_store` (S:176-184) do not test `parameter.is_const`. Cannot tell whether another stage catches a `const` borrowed parameter.
- **Index bounds are recorded, not required.** `index_in_bounds: facts.scalar_index_is_proven(...)` is copied as a boolean into `ByteElement` (S:645) and `ViewElement` (S:1844) leaves; a `false` does not stop the plan. Runtime path segments carry no bound at all. The module comment says "The planner proves no bound for a runtime element: Terminal re-proves `index < extent` for the segment's obligation" (S:2370-2371). The later check is outside this file.

## Surprises

1. **The file refuses silently.** There is not one diagnostic in 3,831 lines. A programmer whose assignment falls outside these lanes gets whatever the caller makes of `None`; the reason is known here only as a trace phase string. This fits property 1 (acceptance is this code's own yes or no) and adds to it: the refusal carries no stated rule.
2. **Proof results arrive as booleans and handles and are forwarded, not required.** `index_in_bounds` and `predicates_preserved` can be `false` in a plan that is still produced (S:644-647, S:1843-1846). Only one decision, the bounded-integer range on a `Primitive` leaf, gates the plan (S:2002-2004). The same decision for a `ScalarField` or `ViewElement` leaf does not (S:3453-3459, S:1836-1842).
3. **Dead parameter.** The closure `plain_domain(symbol, literal_grant)` is called twice, both times with `false` (S:276, S:284), so its `string_literal_expression_grants_domain` branch (S:262-267) never runs. The doc comment above still says "a whole-literal store must also satisfy it from the literal's own bytes" (S:234-235); that check actually happens inside `byte_value_plan` (S:396-402).
4. **Redundant test.** `view_stores::plan` re-tests width at S:2846-2848 after the field arm already returned on a width mismatch (S:2816-2818) and the other arms fixed `element` to `U8`. The condition can never be true.
5. **Unused binding.** `_value_state_parameter` (S:3538) is fetched and discarded; it works only as an existence check.
6. **Comment and code disagree on case literals.** The comment says the store establishes "a zero for each common field the literal leaves unnamed" (S:3601-3602). The code refuses when `constructor.omitted_fields` is not empty (S:3631-3633) and builds no zero fields. Either `omitted_fields` means something narrower than "unnamed common fields", or the zero-fill described was never written or was removed.
7. **Two integer tests for the same selector.** `selectors::retained` requires `is_fixed_integer()` (S:2538); `value::runtime_index` requires `is_integer()` (S:2745). Both judge the `AssignmentIndex { depth: 0 }` expression.
8. **Two domain implication functions.** A completed structural value is checked with `declared_domain_implies` (S:319); a place is checked with `domain_membership_implies` (S:473). The file gives no reason for the difference.
9. **The whole-store domain test is weaker than the byte-write test** for the same root (S:204-208 against S:142-152): it does not require empty establishment routes or default semantic roles.
10. **`plan_assignment` can fail early from inside a condition.** `validation::unwrapped_type_reference(program, destination.root_type)?` sits inside the `if` at S:3338-3358, so a `None` there ends the whole assignment plan rather than moving on to the next lane.
11. **The alias-selector side table uses only the first borrow record of the state** (`first_state_borrow`, S:2465-2468). Index segments from any other borrow record are not resolvable through it.
12. **`element_selector_target` takes a local's borrow target without an ordering or access-kind match with `rejoin_loan_local`.** It accepts only `ReferenceAccess::Mutable` (S:1885) where the rejoin accepts `Mutable` or `WriteOnly` (S:1630-1635), and it does not test that the local is declared before the statement or is immutable (S:1881-1888).
13. **Local-rooted stores are narrower than parameter-rooted ones in several lanes for no stated reason.** Indexed byte field store requires a parameter root (S:273); representation-view store requires a parameter root (S:2806-2808); the sum copy source must be rooted at a parameter (S:3536-3537). This is the placement property showing up as missing cases rather than duplicated code.
14. **A per-statement check re-counts the whole parameter roster.** `exclusive_authority` verifies for every single store that every parameter of the state has exactly one plan row (S:1231-1252). That is a property of the state, evaluated once per assignment.
15. **Two definitions of "plain" data disagree about lifetimes.** `plain_checked_shape` deliberately ignores lifetime binders, with a spec citation (S:1464-1474). `closed_sum` requires `data.lifetime_parameters.is_empty()` (S:3773). A sum with a lifetime binder can be walked through but cannot be stored as a sum field.
16. **Evidence against property 2 in this slice.** Identity here is by symbol handle, expression handle and `(state, statement, role)` coordinate. The coordinate scheme has its own cost: the same authored value must be looked up again in two tables with exclusivity rules between them (S:2097-2116, S:2667-2677), and the code re-lowers an expression to confirm that the stored record is the one it expects (S:2245-2254, S:2281-2291). The planner does not hold the value; it re-finds it.
17. **The design described in the header is close to the replacement design in wording.** The header and module comments say a store leaf is chosen "independent of whether that leaf is a field, array element, or whole element" (S:16-17) and that destination and value are resolved separately. The code still keeps eight leaf lanes, three source kinds and two root kinds, and each combination that works is one that someone wrote an arm for.
