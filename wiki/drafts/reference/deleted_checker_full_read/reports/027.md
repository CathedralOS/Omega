## What this code is for

This is the first half of the contract checker in stage 05 (typed trees to checked trees). The header comment (checks_contracts.rs:1-34) says each call's `requires`, each exit's `ensures`, each self-transition arrival requirement and each write into a domain-refined field "must be proved from the checked facts at that point". The slice holds the helper provers, not the main walk: the modules `calls`, `exits`, `writes` and `prover` are separate files pulled in by `#[path]` (checks_contracts.rs:579-580, 1464-1465, 1828-1829, 3959-3960).

What is in the slice: a prover for `asm` block `requires`/`ensures` facts (`assembly`, 208-578); the check that a generic cleanup hook's prerequisite holds at a call (`contextual_cleanup`, 581-722); the binding of named evidence arguments to a callee's `requires` lane (`evidence`, 723-1463); the check that a nominal parameter's declared field domains hold on every actual argument (`nominal_inputs`, 1467-1827); and six separate ways of deciding that a Boolean `requires` expression holds at a call: argument intervals (`argument_intervals`, 40-207), guard and match-pattern observations plus label matching (`direct`, 1832-3085), domain membership (`domains`, 3086-3206), a closed evaluator over literals and immutable initializers (`evaluator`, 3207-3958), integer bounds and arithmetic implication (`call_bounds`, 3968-5425), and predicates carried along with copied values across selections (`captured_predicates`, 5426-6445).

Every function in the slice returns `bool`, `Option<bool>`, a list of predicates, or pushes a `Diagnostic`. None calls a proof kernel.

## Mechanisms

- **Denotation comparison with a budget** (`Denotations::equal`/`compare`, checks_contracts.rs:1887-2054). Decides whether a caller-side observation and a callee-side expression denote the same value. It substitutes a formal by its actual (1905-1917), expands an immutable Bool local to its initializer (1918-1923, `captured` at 2199-2296), peels borrows (1924-1931), compares projected leaf places including through a single loan storage (1932-1963, 2120-2154), then matches node kinds structurally (1967-2053). Budget: 4096 steps and depth 64 (1889, 1900); exhausted budget returns false. Serves call `requires`.
- **Purity test for a local's initializer** (`selected_pure`, checks_contracts.rs:2298-2378): walks the checked scalar computation plan; only value leaves, byte-sequence predicates, structural fields, selected float comparisons and `Apply` nodes are pure; same 64-depth and shared step budget.
- **Propositional entailment from one premise** (`guard_values::proves_with`, checks_contracts.rs:2403-2477): recursive on `!`, `== literal`, `&&`, `||`. It is one-premise: a true `||` guard proves nothing and premises are never combined.
- **Closed evaluator with cycle guards** (`ContractExpressionEvaluator`, checks_contracts.rs:3891-3957): computes `Option<bool>` and `Option<i64>` by following names to arguments, immutable literal initializers, array-literal elements and struct-literal fields. Two stacks of in-progress expressions stop cycles created by self calls (3904-3918, 3936-3956). Integers are i64 only; arithmetic folding is `ranges::folded_integer_binary` (3632).
- **Interval comparison** in i64 with optional ends (checks_contracts.rs:5110-5208), with interval narrowing from a guard (5149-5157, 5296-5303) and monotonic update transfer through `+`/`-` (`guarded_update_bounds`, 5266-5308, delegating to `validation::builtin_monotonic_integer_update_bounds`).
- **Arithmetic implication** (checks_contracts.rs:4419-4561): this code only prepares hypotheses and bindings; the decision is `validation::strict_arithmetic_expression_implication`. Hypotheses are true conjuncts of surviving caller `requires` and true branch facts (`true_conjuncts`, 4569-4597, worklist; `positive_comparison_expression`, 4603-4648, capped at 64 wrapper peels).
- **Selection-condition coverage** (checks_contracts.rs:6039-6207): conditions are handles into a shared condition DAG (`SelectionConditions`, defined elsewhere). `implies` is "premise and not conclusion is impossible" (6039-6048). `qualify` accumulates the conditions under which the required predicate is provable and accepts when their union covers everything (6176-6205). Comment at 6027-6031: "A good candidate cannot hide an incompatible candidate under the same choice."
- **Predicate transport** (checks_contracts.rs:6224-6388): for each alias of each capture, takes the predicates retained at the alias's read point plus current call guarantees, folds known case truths, splits conjunctions, rebinds each operand to a required binding whose aliases agree under the capture's selection, or replaces the operand by its observed literal value (6339-6354); merges equal predicates by OR-ing conditions (6373-6383).
- **Deferred obligations** (`recipe_requirements`, checks_contracts.rs:108-206): turns `subject op recipe` plus the argument interval into `AtLeast`/`AtMost` obligations on the recipe, to be discharged "under the selected target before Terminal production" (102-107).
- **Backward scan of an asm block for writes** (checks_contracts.rs:364-420) and **enclosing transfer lookup** (327-356).
- **Per-parameter requirement table** (`DeclaredFieldRequirements`, checks_contracts.rs:1493-1556): a `SymbolKeyMap` from parameter symbol to unique (segments, domain symbol, semantic domain id) rows, built once from semantic facts whose origin is `StateParameterDomain` at the state's own point (1523-1539).

## Identity by text

- A proposition `asm` fact is proved by its rendered identity label: `contexts_prove_proposition_label(.., &formula.identity_label())` (checks_contracts.rs:528-539).
- Evidence terms are found by authored name: `checked.name == name` (1126), `terms.get(*term).name == name` (1370), `term.name == name` (1384). This is name resolution of user-written evidence names.
- Instantiated propositions carry their arguments as rendered labels: `argument_labels` from `instantiate_call_contract_expression_label` (1162-1174, 1421-1447), `proposition.arguments = argument_labels` (1453), `normalized_identity_label` (1451-1452). The "inhabits" checks at 995-996 and 1289-1290 therefore compare label strings.
- A context fact proves a Boolean requirement when its label string equals the requirement's `display_name` (2651, 2672-2681), with `label.strip_prefix("boolean:")` deciding which proposition labels count (2675, 2799).
- The call-instantiated version compares the instantiated label with a fact label (2753-2760, 2805) and with a place's label: `instantiate_call_contract_expression_label(..) == semantic.place_label(program, candidate_place)` (2806-2815).
- `.len` is recognised by spelling: `CollectionMeasure::from_authored_spelling(member.member.as_str()) == Some(Length)` (2940-2941, 3636-3637).
- Domain membership proves an expression by label: `domain_proves_expression_label(domain, base_label, candidate_label)` tried with the canonical place label and then the display label (3105, 3122-3129, 3191-3203).
- Struct literal fields are selected by name: `field.name == member.member` (3741).
- The evaluator matches a parameter by name when no symbol is resolved: `name == parameter.name.as_str()` (3763-3769); likewise locals: `local.name == *name` (3797-3803).
- Arithmetic atoms are identified by a formatted string: `format!("\0call-parameter:{actual:?}")` (4665).
- A guard's interval for an operand is looked up by the operand's rendered label: `guard_interval_for_label(program, guard, &display_name(argument))` (5149-5155) and `&display_name(expression)` (5296-5300).
- Diagnostic-only labels: 475-493, 705-718, 1746-1751.

Evidence against property 2 in this slice: `guard_values` says "Branch truth is structural evidence, not a display-label substitution" (2382-2385) and uses `expressions_structurally_equal` (2399); `match_patterns` says "display labels never establish equality between different symbols or mutable storage locations" (2511-2513); `Denotations` compares symbols, member symbols and canonical places (1949, 1957, 1981-1983); `guard_implication` compares `CanonicalPlace` values (4780-4783, 4904-4905); `nominal_inputs` keys on place segments plus domain symbol plus semantic domain id (1497-1501); `captured_predicates` identifies values by place and read epoch (5453-5456, 6079-6093). In `direct`, the structural routes run first and the label routes are the last fallback (2771-2816).

- `nominal_inputs::check` returns silently when the target has no parameter list (1569-1572) or the call site is not found (1579-1587). A requirement is skipped when a literal argument makes the path inactive (1605-1614), when a pointwise ancestor is an empty range or zero-length array (1700-1706), or when `selection.path_is_inactive` (1709-1710). These are stated as vacuous cases, not unknowns.
- Two calls are treated as denoting the same value when they have the same target, `checked_value_call_candidate(..).is_ok()` and pairwise-equal arguments (1993-2027). The decision that such a call is repeatable rests on `checked_value_call_candidate`, outside the slice.
- `guard_values::proves_with` returns `true` for any requirement when the premise is a Boolean literal recorded with the opposite value (2423-2427). This is sound only if such a fact can exist only on an unreachable path; the code does not check that.
- `evaluate_scalar` is called with `&|_, _| true` as its "comparison is admitted" callback (2907, 2910, 3424). At 3424 builtin meaning is checked first (3407-3410). In `instantiated_live_value_proves` (2820-2912) I see no operator-authority check before evaluation; cannot tell whether `evaluate` itself refuses authored operators.
- The evaluator compares integers for `<`, `<=`, `>`, `>=` and negates with `!` without asking whether the operator is builtin (3294-3341, 3384-3386); only Boolean `==`/`!=` asks (3401-3411). - A missing operator-use row is read as "builtin": the test is "no row with status other than `BuiltinFallback`" (4585-4589, 5002-5005).
- `context::prove` returns `Some(true)` on the termination module's word for ranked self-transitions (4402-4413).

- `transport::predicates` replaces an operand that cannot be rebound with the literal value currently recorded at its place (6339-6354); the predicate is kept with that constant.

Conservative defaults (refuse on unknown) are the common pattern: budget exhaustion (1900-1902), `LoanStorage::Many`/`Unknown` (1959-1960), missing frames (2121-2123, 4063-4065), `unwrap_or(false)` (3855, 4294, 4989), statement call sites (5066), more than one loan storage (5239-5241), unbuildable selections (6411-6417), no captures (6011-6013).

## Surprises

- **No proof kernel anywhere.** A search of the slice for `proof_admission`, `ProofNode`, `verify_obligation` and "certificate" finds nothing. The `evidence` module binds evidence terms and writes rows (`ContractEvidenceArgument`, `ProofOutputCallFact`, 1317-1331, 828-842), but the acceptance test is `==` on proposition records built from labels (995-996, 1289-1290). Property 1 holds for the whole slice.
- **A header claim the code does not keep.** `argument_intervals` says it is "a client of the one interval engine rather than another private one" (41-55), yet the slice holds two more private interval comparers: the evaluator (3286-3355) and `call_bounds::prove` (5198-5208), each with its own sources of bounds.
- **A comment and the code disagree on purity.** `Denotations` says expansion "never evaluates a user call or assumes its purity" (1856-1857), but two calls to the same target with equal arguments are declared equal whenever `checked_value_call_candidate` returns `Ok` (1993-2027).
- **Every call expression is "a reference loan".** `expression_is_reference_loan` returns `true` for any `ExpressionNode::Call` (2086-2089) without looking at the return type; the result then depends on `reference_expression_origins_before_statement` returning origins (2136-2140).
- **A type handle borrowed from an unrelated parameter.** To decide whether Boolean `==` is builtin, `boolean_operand_type` needs a Bool type handle for literal, unary or binary operands; it takes the type of the first Bool-typed parameter of the target or caller (3527-3546) and strips `Constrained` wrappers. If neither machine has a Bool parameter it returns `None` and the comparison is not evaluated. Whether `true == (a < b)` can be decided thus depends on unrelated parameters.
- **An ordinal recomputed by counting.** `captured` derives `binding_ordinal` by counting earlier immutable primitive locals with initializers (2225-2235) to find the scalar plan row with role `LocalInitializer`. This must mirror the numbering of whichever stage wrote the plans; nothing in the slice ties the two together beyond the later equality checks at 2243-2247 and 2262-2264.
- **Two functions named `prove` with different reach.** `call_bounds::context::prove` (4297) admits statement-form call sites (4338-4367); `call_bounds::prove` (4992) refuses them (5066). The same requirement at the same callee is therefore judged by fewer routes when the call is written as a statement.
- **Receiver offset only for expression calls.** `nominal_inputs::check` shifts operand positions by one for a receiver only when the call site is `CallSite::Expression` (1596-1598); statement-form calls with a receiver get offset 0. Cannot tell whether statement calls record their receiver as an operand.
- **The proposition compared is not the proposition recorded.** For an outcome-arm evidence term the "inhabits" test uses the instantiation with captured identities (`captured_outcome = true`, 1267-1291), then the row stored for the runtime call is a second instantiation with `captured_outcome = false` (1302-1323).
- **Partial bindings survive a diagnostic.** After "unknown incoming evidence term" or "does not inhabit" the loop continues and the call's `evidence_arguments` span is still written with the positions that did bind (1258, 1299, 1333-1337). Harmless if any diagnostic stops compilation.
- **Label matching is deliberately switched off for one fact kind.** For `BooleanValue` facts the closure returns the structural result and never falls through to the label comparison (2791-2793); `BooleanExpression` and uninstantiated `ContractBooleanExpression` facts do fall through. So the authors already distrusted labels for branch truths but kept them for the other two kinds.
- **Only uninstantiated contract facts are premises.** Both the direct prover and the arithmetic prover use `ContractBooleanExpression` facts only when `!instantiated.is_valid()` (2775-2779, 4421-4426, 4527-4532), i.e. the caller's own `requires`, not facts instantiated from calls it made.
- **Debug tracing in the checker.** Three long `eprintln!("CHECKSITE ...")` lines gated by `trace_flags::check_sites()` sit inside the nominal-input check (1630-1632, 1689-1691, 1726-1728).
- **Linear scans per query.** `facts.operators.uses.iter().any(..)` runs over every operator use for each expression tested (4585-4589, 5002-5005); `contract_facts.iter()` is rescanned per evidence parameter (1059-1076, 1115-1129, 1153-1158); `proposition_vocabulary.applications.contains` is a linear search (817-826); a `std::collections::HashSet` keyed by arena index is allocated per contract fact (884).
- **A general capability I did not expect:** `captured_predicates` (5426-6445) reasons about which of several possible source values a copy holds, keeps one obligation per alternative, and accepts only when the union of supporting selection conditions covers all possibilities. It is value-and-epoch based, not placement based, and is the part of this slice closest in spirit to "a fact belongs to a value".
- **The six requirement provers are not composed here.** Each returns a bare `bool`; the order in which they are tried, and therefore which one "wins", is decided in the external `calls` and `prover` files. A requirement that needs two routes at once (for example an interval for one conjunct and a guard truth for another) can only succeed if the caller splits the conjunction itself; the split is repeated inside most routes (see the ten copies listed above) but premises from different routes are never combined inside one route.
