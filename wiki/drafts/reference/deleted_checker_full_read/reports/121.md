## What this code is for
This one file is the operator layer of the old validation crate. It does five jobs. (1) It checks operator declarations: duplicate signatures, overlapping spellings, valid parameter/return types, and `crashes` routes being Boolean expressions (2725-2910). (2) It validates a named-operator application (explicit static arguments against what the operands imply, and bounds on type parameters) (67-415). (3) It resolves which operator, domain operator, trait-backed meaning, or builtin a given `a + b`, `a[i]`, `a[i..j]` or named call refers to, producing "operator use facts" with candidates and a resolution status (1227-1483, 1523-1770, 1978-2677). (4) It derives checked operator facts handed forward to later stages: crash contracts, realization contracts, named requirement uses, float policy adapters (516-643, 1100-1139, 2192-2210, 2600-2653). (5) It recomputes the type of an expression from the typed tree in a given state (737-1069), because the checker had no lowered values to ask. It never calls a proof kernel; every result is its own computation over typed-tree tables.

## Mechanisms
- Candidate selection (1728-1770): partitions (operator, domain) pairs into domain-scoped candidates that are active and root candidates; exactly one active domain wins, several is Ambiguous, otherwise the single root candidate, else builtin fallback, else Missing/Inadmissible. Serves domain-scoped operator overloading. No budget.
- Domain activity test (1365-1386, 1577-1705): an operand "selects" a domain if (a) its recomputed type selects the domain, (b) it is syntactically a cast naming the domain, or a name whose local initializer (earlier statement) is such a cast, or (c) a `requires` Membership fact on the same binding symbol names the domain. Local-initializer recursion at 1645-1680 follows initializers; no cycle guard is visible (a local initialised from itself is prevented elsewhere, cannot tell).
- Type recomputation (737-1069): a recursive function that infers an expression's type from the tree, parameters, earlier locals (by position `take(statement_index)`), data-binding fields, generic field substitution, and operator return types. It is a second, partial type inference separate from the typer. Serves operator resolution. No budget; returns None when unsure.
- Generic field type check (1030-1037): substitutes data type arguments into a field type and accepts only if the normalized identity is unchanged after substitution (i.e. field type does not depend on parameters).
- Two-phase operator resolution: `build_operator_uses` marks uses with `DomainPending`, then `select_pending_domain_operator_meanings` (1523-1561) finalizes them using `select_scoped_candidates`; `derive_pre_flow_operator_selections` (516-521) runs a pre-flow version.
- Walk with dedup: `collect_expression_operator_use` (2002-2105) traverses each executable value with a `(expression, origin)` seen set to avoid revisiting.
- Pre-specialization selection (1887-1967): for every binary expression in contracts and statements, decides explicit trait selection target, builtin intrinsic, or skips.
- Structural static-argument equality (458-508): recursive comparison of generic type applications.

## Surprises
- Type inference is duplicated inside the checker: `expression_type_reference_in_state` (755-906) re-derives types from the tree (Match, Member, Call, Binary, literals) separately from `crate::expression_result_type_reference`, which it also calls for Borrow/Indexed/Call (814-832). Two sources of a type for the same expression.
- The type recomputation for a `Match` returns the first arm's type and for Binary the left operand's type (779-786, 886); a result type chosen by position.
- Local lookup uses statement position (`take(statement_index)`, 961, 1667) so only straight-line earlier locals count; locals declared in nested blocks/other states are not seen.
- `local_initializer_selects_domain` matches by name OR symbol with no requirement that the symbol be invalid (1670-1671), so shadowing by a same-named local could select the wrong initializer.
- `select_scoped_candidates` returns `Resolved` when exactly one root (non-domain) candidate exists even if domain candidates exist but are inactive (1751-1752); domain operators are only picked when active.
- `named_operator_use_fact` has a dead integer-namespace arm (2158-2163) returning None identical to the `_` arm.
- `float_type_reference` has an unreachable `_ => return None` after mapping only F32/F64 (912-920).
- `validate_named_operator_application` is public and validates bounds with an empty assumption set (370), so it cannot check calls inside generic machines using their own bounds; `use_is_generic_template` flags such uses (2248-2258) for later handling.
- `HashSet<..., BuildSymbolHasher>` and `BTreeMap` are used (1971, 575) despite the later project preference for dense tables; (historical note, not a bug).
- `OperatorUseSink.seen` dedups by `(expression, origin)`, but `Match` returns early (2055) before the generic child traversal, so match children are walked manually; `Binary` with no resolved candidate still traverses children (2102).
- The module never touches proof kernel types (`ProofNode`, `verify_obligation`, certificates); `ProofFact` is read only as data (604-611, 1701-1704, 2776-2782). Domain membership "proofs" are signature `requires` facts read as trusted syntax.
- `crash` buckets use `BTreeMap` keyed by `CrashCause` (592), sorted rows by arena index/generation (561-568, 636-641): output is deterministic by handle order.
- Evidence on the three sampled properties in this slice: (1) strongly present: no proof-kernel call anywhere; (2) present, moderately: names used for namespace, domain-cast, float policy, local lookup fallback, signature keys; most core identities (operators, domains) use `SymbolHandle`; (3) present: see Repetition section (candidate-fact construction, builtin-indexed fallback, trait-meaning lookup, mint-selection duplicated; per-origin handling of type recomputation).
