## What this code is for

This file enforces that a value written into a place whose declared type carries a `domain` refinement (`f: &[u8] in Utf8`, `x: u8 in Digit`) is a member of that domain at the moment of the write (writes.rs:1-17). The header says read-side narrowing trusts the declared refinement at every read, so every write has to be proven; without this check "the field-read narrowing would rest on an unenforced refinement (the #40 trap)" (writes.rs:4-16). The entry point `check_domain_field_writes` runs once per machine state: it walks every statement's expressions in evaluation order and judges struct-literal fields, array-literal elements, whole constructed values, `as ... in D` casts, executable domain tests, local initializers and assignments (writes.rs:1580-1911). A second entry point, `check_routed_cast_coverage`, refuses routed casts that the walk never visited (writes.rs:2269-2291). The file distinguishes two kinds of domain: "predicate-only" domains, where proving the predicates is enough, and "routed" domains (`domain_requires_provenance`), where the value must also carry authorized provenance and predicate truth alone is refused (writes.rs:215, 571-608). Three nested modules supply the provers: `domain_implications` (membership from live facts, call results, casts, concatenation, recast views; writes.rs:337-892), `member_domains` (evaluating a domain's predicates on a value, including indexed domain families; writes.rs:1026-1548) and `domain_tests` (executable `x in D` tests; writes.rs:893-1025). `constructor_memberships` builds a sorted index of captured operands by (state, statement, expression) so a constructed child is judged with the facts live when that child finished evaluating (writes.rs:57-335). Each successful judgment is appended to an arena of `CheckedValueQualification` rows by `record_qualification` (writes.rs:2293-2313); later judgments and the cast coverage check read those rows back.

## Mechanisms

- **Evaluation-order walk with a threaded context set** (`ConstructionWalk::scan`, writes.rs:1962-2110). The walk carries a list of fact-context handles. It recurses into children in authored order. At a `match` it clones the set per arm and afterwards keeps only contexts present in every arm (writes.rs:1975-1990). At a call it replaces the set with the exit contexts of the call flows recorded for that exact expression, intersected when there are several, and empties the set when no call flow is recorded (writes.rs:2042-2071). For a transition it scans the guard, then each target's arguments with the contexts of that `TransitionArm` program point added (writes.rs:1667-1705). It has no budget and no fixpoint. It serves constructor fields, array elements, casts and domain tests.
- **Sorted occurrence index with binary search.** `ConstructorMemberships` sorts captured operands by (state symbol, statement index, expression handle) and finds a range with `partition_point` (writes.rs:96-112, 147-165, 168-180). Construction rows are sorted by (statement, expression) and searched the same way (writes.rs:1649, 2095-2102).
- **Unique completed-operand search** (`completed_operand`, writes.rs:440-479). It walks the stored operand's constructed-children tree looking for the operand whose expression equals the queried one. Two different operands with the same expression, or an invalid child handle, return `Err`, and the caller then uses an empty context set (writes.rs:420), so nothing can be proven.
- **Recursive predicate evaluation with a cycle stack.** `value_satisfies_bound_domain_predicates_in_contexts` pushes `(domain symbol, SemanticDomainId)` on `active`, refuses re-entry, and pops afterwards (writes.rs:1183-1186, 1201, 1234). The stack is shared with the outer qualification proof (writes.rs:540-556).
- **Interval inclusion** (`live_bounds_satisfy_domain`, writes.rs:296-334). It applies only when the domain's predicates describe one exact interval; "Necessary numeric consequences alone are insufficient".
- **Decision rows as a memo.** `record_qualification` appends a row; `value_proves_qualification` and the cast judgment scan the whole arena linearly for a matching row (writes.rs:376-386, 2192-2199). `check_routed_cast_coverage` scans the arena once per cast node (writes.rs:2274-2290). There is no index.
- **Prover ladder** (`value_proves_qualification_with_domain_stack`, writes.rs:545-643). Routed: exact live membership, then owned call result, then predicates only if the declaration has no routes and no alias. Predicate-only: computed result type, then `value_proves_domain_in_contexts` (literal, concatenation, recast source, place fact), then the domain's predicates.

## Accepts or skips without proof

- **No proof kernel anywhere.** The file never calls `proof_admission`, `verify_obligation` or builds a `ProofNode`. Every acceptance is a `bool` from this file or from `validation`, `prover`, `exits`, `flow`. The header says the retained record "supplies no independent Terminal certificate" (writes.rs:22-23).
- **Assignment with an exact-interval domain is recorded as qualified without being judged here.** When `exact_declared_domain_interval` is `Some`, the refusal condition is false and control reaches `record_qualification` (writes.rs:1826-1827, 1861-1869). The header mentions a separate "#63 assignment range-check" (writes.rs:14-15); it is not in this slice, so I cannot tell whether it always covers the case. The recorded row can later satisfy `value_proves_qualification` (writes.rs:376-386) and the cast judgment (writes.rs:2192-2199).
- **A domain with no proof facts is satisfied by any value** (`program.proof_facts(domain).is_empty()` returns true, writes.rs:1190-1192). On the routed path this is reachable for a routed domain whose own declaration has no establishment routes and no alias (writes.rs:589-607). Cannot tell whether such a domain can exist.
- **Vacuous domains are accepted and recorded** before any other test, including before the erasure test for locals (writes.rs:216-217, 229, 1729-1738, 2181, 2188-2191). Decided by `domain_is_vacuous` in `validation`.
- **Fields of generic data types get no construction obligations.** `construction_field_domain_identities` returns an empty list when `data_definition.type_parameters.count() > 0` (writes.rs:2129-2131). Cannot see another check for these.
- **Field domains that are neither routed nor predicate-bearing are filtered out** (writes.rs:2139-2144).
- **Failed lookups skip silently:** the whole state check returns when `machine_state_by_symbols` fails (writes.rs:1590-1594); the cast judgment returns when `domain_definition` fails (writes.rs:2172-2174); a domain test with no definition or no routes is skipped (writes.rs:918-923); an unknown data definition or field type yields no obligations (writes.rs:2126-2136); array element domains skip captures whose type does not unwrap to a `FixedArray` (writes.rs:123-131). For routed casts `check_routed_cast_coverage` is a backstop; for the others I cannot tell.
- **Operator candidate shortcut:** `initializer_satisfies_predicate_domain` returns true when the operator resolved at the value's expression selected a candidate whose `domain_symbol` equals the required domain, without evaluating predicates (writes.rs:1062-1070). It trusts the operator's declared result domain.
- **Trusting a declared result type:** `value_result_type_carries_domain` accepts a predicate-only domain from the expression's result type when the value is not a live storage read (writes.rs:782-812, 609-618). The comment says computed calls and casts "retain their independently checked result contracts" (writes.rs:340), i.e. it relies on the callee's or cast's own check.
- **Authorized-result exemption** (writes.rs:1618-1641): relies on `machine_has_checked_domain_establishment` and on the return check elsewhere. It also accepts an exit whose `returned_value` operand handle is invalid (writes.rs:1631).
- **`value_case_path_is_selected` returns true when the value has no place** (writes.rs:493-495). A value without a place has no `Case` segment, so this looks harmless.
- **Predicate fallbacks bypass the case-selection gate.** `value_proves_qualification` returns false for an unselected payload path (writes.rs:373-375, 558-570), but the callers then try `initializer_satisfies_predicate_domain` (writes.rs:1774-1783, 1839-1849) or `value_satisfies_domain_instance_predicates_in_contexts` (writes.rs:2210-2225), which do not repeat that gate. Cannot tell whether the predicate leaves reject stale payload facts.
- **Transition targets other than `Named` and `Value` are not scanned** (`_ => Vec::new()`, writes.rs:1699). A call statement's root expressions are its arguments only (writes.rs:1925-1928). Assembly statements have none (writes.rs:1923).
- **`record_qualification` drops the row silently if the statement index does not fit `u32`** (writes.rs:2301-2303). This fails toward refusal for routed casts.
- Refusing defaults, for balance: a missing call flow empties the context set (writes.rs:2068-2070); an ambiguous operand empties it (writes.rs:420); `Proposition` facts, aliases, cycles and unknown predicate shapes return false (writes.rs:1184-1189, 1232, 1414).

## Surprises

- **The assignment path records a qualification it did not judge** for exact-interval domains (writes.rs:1826-1827, 1861-1869). The row is indistinguishable from a proven one, and later code treats rows as proof.
- **`check_routed_cast_coverage` matches a decision by expression handle only** (writes.rs:2280-2282). Any row for that expression counts, whatever its domain, machine or state. A routed cast that failed in the walk records no row, so it is likely reported twice: once by `judge_value_qualification_cast` (writes.rs:2240-2244) and once by the coverage pass.
- **The four copies of the write rule accept different things** (see Repetition). An integer proven by live interval bounds is accepted as a constructor field but that prover is not offered for a local initializer; an erased membership is refused for a local but the erasure test is not applied to an assignment or constructor field.
- **The local-initializer diagnostic always says "an annotation cannot establish routed qualification"** (writes.rs:1805), including for predicate-only domains and for the erasure case.
- **Header and code disagree in two places.** The header says the struct-literal case is "handled in validation" (writes.rs:8-9), yet this file checks struct-literal fields itself (writes.rs:1991-2014). The header credits string-literal acceptance to `super::grants` (writes.rs:13); the code calls `validation::field_domains::string_literal_expression_grants_domain` (writes.rs:669).
- **Fallback contexts may come from an unrelated call.** When the statement has no stored operand for the value, `value_semantic_contexts` uses the exit contexts of the last call recorded in the statement, whether or not the value involves that call (writes.rs:424-436).
- **No short-circuit handling in the walk.** `Binary` scans left then right with one context set (writes.rs:2034-2037). After `a && f()` the set is `f`'s exit contexts even on the path where `f` did not run. Cannot tell whether the flow stage compensates.
- **Two ways of reading a context span.** The statement-entry contexts are collected from `semantic_context_refs` directly (writes.rs:1652-1666, 2057-2066), while other sites filter through `active_context_handles` (writes.rs:436, 2055). Cannot tell whether inactive contexts can appear in the first form.
- **An executable test on a routed domain is refused unless the value already has the membership** (writes.rs:907-957). A test therefore cannot be used to discover membership of a routed domain; tests on domains without routes are not examined here at all.
- **The "borrowed view cannot hold a concatenation" rule lives in a domain-write file and checks only the top-level value shape** of an assignment or local initializer (writes.rs:1874-1909). The same concatenation inside a struct field, argument or return is not examined here.
- **Redundant call:** the cast's last disjunct (writes.rs:2210-2225) repeats what `value_proves_qualification_in_contexts` already tried (writes.rs:630-642); it can only differ when the earlier call stopped at the case-selection gate.
- **A panic path:** `ConstructorMemberships::new` calls `.expect("operand arena iteration returns live recorded handles")` (writes.rs:106-107).
- **The machine's result type is read from its first state** (`program.machine_states(machine).first()` then `entry.return_type`, writes.rs:1597-1601).
- **Module paths show the file was flattened.** Visibility is `pub(in crate::checks::contracts)` and siblings are reached as `super::super::exits`, `super::super::prover`, `super::return_values`, `super::call_values` (writes.rs:91, 345-346, 1629, 1753), so the original was `checks/contracts/writes.rs`.
- **Both exhaustive matches have no `_` arm** over `ExpressionNode` and `StatementNode` (writes.rs:1972-2084, 1922-1932), so a new node kind would fail to compile rather than be skipped.
