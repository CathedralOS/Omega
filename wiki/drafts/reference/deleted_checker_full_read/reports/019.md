## What this code is for

This file is the driver of the old checking stage ("typed trees to checked trees"). Its public entrance `lower_typed_trees` (793-801) takes a frozen typed program plus the judgments that the preparation stage produced, runs every check in a fixed order inside `check_program` (1021-1421), and publishes a `CheckedTrees` value that carries the program and a large `facts` record. Most checks are not written here: the file calls about thirty functions in `validation::`, `checks::`, `proof::`, `crate::flow`, `crate::published::facts` and `crate::execution`, and stops at the first one that returns diagnostics. Three checks are written in the file itself: call acknowledgement of `suspend`/`block` effects (module `call_acknowledgements`, 27-375), the ban on naming a boundary trait as a value type (376-605), and the refusal of portable code that references a target-specific machine (module `target_families`, 606-741). The file also owns whole-program result reuse: `RetainedCheck` (808-900) keeps a checked result beside the exact input it was computed for, and `reuse_retained_check` (920-938) hands that result back without rechecking. Finally, the tail of `check_program` (1292-1404) copies mathematical proof records (identity formations, evidence carriers, indexed theorems, safety assumptions) from preparation into the published facts, with one consistency check on indexed theorems. The file contains no tests.

## Mechanisms

- **Positional call matching (53 lines of logic, 318-365).** `validate_call` identifies each call by the pair (statement index within the state, ordinal of the call within that statement). The ordinal is a counter reset to zero for each statement (59) and incremented in pre-order: a call is counted before its receiver and arguments (327-328, 292-295). The matching record is found by a linear scan of the state's `CallOperational` slice (329-331). The walk has no budget; overflow of the counter panics (`expect("call ordinal overflow")`, 328). Serves `suspend`/`block` acknowledgement.
- **Operational state lookup (47-54).** For every state the code scans every operational state of every machine for an equal symbol. Quadratic in the number of states; no index.
- **Deferred overflow accumulation (396, 431, 1011-1018, 1066, 1099, 1148-1150).** Overflow diagnostics from validation and from fact building are held in `deferred_overflow` instead of failing at once. `merge_overflow` puts them in front of whichever later error stops the check. If no later check fails, line 1148 fails the program with the overflow diagnostics alone. Serves integer overflow reporting.
- **"Entailment errors first" reordering (463-478).** When the proof pass or fact building fails and the program has a storage graph, the driver runs `validation::judge_contract_entailment` only to obtain its diagnostics and places them before the original failure. Without a storage graph it returns the original errors alone; the comment (457-462) says rechecking contracts without storage history "can blame valid code for losing facts after unrelated writes".
- **Whole-result retention and reuse (808-938, 947-994).** `RetainedCheck` stores the unprepared typed program (`Arc<TypedTrees>`), the preparation admission, the external roots, a flag `admits_pending_inputs`, the shared checked result, and two lists of per-dependency-body judgments. Reuse of the whole result requires full equality of the first three (858-878). Per-body reuse is offered only from strict checks: `strict_dependency_bodies` and `strict_frozen_dependency_bodies` return empty slices when the retained check admitted pending inputs (884-899). Body judgments are recorded only when `retain && !admits_pending_inputs && deferred_layout_applications.is_empty()` (976).
- **Reference visitor with per-owner visited sets (676-740).** `PortableReferences` implements the shared `TypedReferences` visitor. `declaration` sets the current owner and clears two `HashSet`s of visited expression and type handles; `expression` and `type_reference` return whether the handle is new. Call arguments are followed only when `static_argument_role` is `ValueDependency` (736-739). Refusals are de-duplicated by linear search in a `Vec` of (owner, member) pairs (693).
- **Parallel execution of independent checks (1151-1168, 1242-1272).** Three validators run under nested `rayon::join`; seven selection/classification passes run under a `rayon` scope, each writing into an `Option` local that is unwrapped with `expect("every selection and classification pass ran")` (1274-1281).

## Surprises

- **Evidence on property 1 (own yes or no).** Nothing in this file calls `proof_admission`, `ProofNode`, `verify_obligation` or a certificate check. The driver accepts a program when a chain of about thirty `Result`-returning functions all return `Ok`. The one proof-named call, `proof::checker::check_proof_plan_with_decisions` (422), returns `ProofDecisions { integer_assignments, constant_recipe_obligations }` (425-428): decisions and leftover obligations, not evidence objects. Theorem terms and types are carried through as data (1385-1396). This file supports property 1; whether the callee uses a kernel is outside the slice.
- **Evidence on property 3.** Two of the three locally written rules are a per-construct walk or a hand-listed set of placements (see Repetition). The third (portable references) uses a shared visitor.
- **`with_source_span` is applied twice (336-343 then 357, 363).** The closure `at_call` attaches the span only when it is non-empty, and then both call sites call `.with_source_span(source_span)` again unconditionally. The guard for an empty span has no effect.
- **`x = f()` is a nested position but `let x = f()` is not.** An assignment's value goes through `validate_child` (98-105), so a suspending call on the right of an assignment is refused, while the same call as a local's initializer is direct (137-147). The message text lists only "simple `let` right-hand side", so the code and message agree, but the asymmetry is a rule a reader would not guess. Likewise every match arm value is non-direct (263), even when the match is the whole statement.
- **A named transition target is treated as a call (163-181).** It consumes a call ordinal and is checked for acknowledgement like any call. Its arguments are non-direct.
- **Positional matching is fragile and fails open.** See "Accepts or skips": the acknowledgement check depends on two independent walks agreeing on call order, and a mismatch produces silence rather than an error (329-334, 47-54).
- **`validate_call_acknowledgements` is defined here but not called in this file.** `check_program` never names it; some other module must call it (cannot tell which from the slice).
- **Header says one entrance, file exports three.** The header states "`lower_typed_trees` is the one entrance" (6), but `lower_typed_trees_reusing` (947) and `reuse_retained_check` (920) are also `pub`.
- **Header claim with no visible code.** "Every production request enforces crash admission" (9): no call in this file is named for crash admission. It may happen inside `check_checked_facts_recording` or `finalize_execution`; the slice cannot confirm it.
- **Comment at 1020 misstates the caller.** It says `lower_typed_trees` "has found complete" the program. `lower_typed_trees` performs no completeness check (793-801); completeness comes from preparation.
- **`retain` and `retained_input` are independent (957, 976, 979).** A `RetainedCheck` is built whenever `retained_input` is `Some`, even if `retain` is false; `retain` only controls whether dependency-body judgments are recorded. A caller passing `retained_input` with `retain == false` gets a retained check with empty body lists.
- **A retained check is built before the request is admitted (979-988).** If `admit_request` fails, the retained check is dropped with the error, so a later request must recheck even though the program-level judgment succeeded.
- **Whole-program reuse compares entire typed programs with `==` (865-866).** It is exact, not a hash, and its cost is a full structural comparison.
- **The portable target-family contract is refused as "unimplemented" (666-668).** The comment block (607-617) describes a designed mechanism (a bodyless Requirement per family), but the check refuses every portable reference to an authored target member. A whole language feature was a stub in the old checker at the time of deletion.
- **`HashSet` and linear `Vec::contains` in `PortableReferences` (679-681, 693)** against the project rule of flat tables indexed by dense IDs.
- **Entry state is "the first state" (1366-1369)** and an ensures clause is "the n-th expression fact" (1358-1362), skipping non-expression facts when counting. Both are positional conventions shared with whatever produced `indexed_theorems`.
- **`lower_typed_trees` clones on a path that cannot occur (798-800).** It passes `retained_input: None`, so the `Arc` has one owner and `try_unwrap` always succeeds; the `unwrap_or_else(clone)` fallback is dead.
- **Contract entailment may run twice on a failing program**: once in `entailment_errors_first` to order diagnostics (471), which is reachable from both the proof-failure path (432) and the fact-building failure path (1091).
