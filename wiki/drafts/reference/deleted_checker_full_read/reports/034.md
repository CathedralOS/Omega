## What this code is for

This file answers one question for the rest of the old checker: "at statement N of this state, what integer does each tracked thing hold?" The struct `CurrentScalarValues` (:4609-4636) is built at a state's entry and then replays every earlier statement of the state in execution order (`replay_prefix`, :4886-5228). It keeps four separate tables: scalar bindings by symbol (`current`), scalar record/array fields by owner and path (`fields`), slice and array lengths (`lengths`), and saved Boolean conditions (`conditions`), plus a list of arithmetic hypotheses (`hypotheses`). Each statement kind captures the right-hand side into those tables, then asks the storage graph which earlier entries a write may have reached and blanks them (`retire_unpreserved`, :5394-5499). Other checks then ask the frame to bind a contract expression to those captured values (`scoped_operations`, :6743-6845) and to prove a goal (`proves`, :5994-6037), which it forwards to `validation::scoped_arithmetic_implication`. The same frame serves call preconditions (:433-462), callee `ensures` arriving at the caller (:713-785), exit postconditions (:3077-3135), rank/termination entry observations (:2292-2500, :3735-3911), subslice window bounds (:1691-1746) and a byte-length bound query (:6879-6895). The file contains no diagnostic text: it returns `Option`, `bool` or an empty `Vec`, and a refusal is an absent value that some caller turns into an error. The header calls the whole thing "private proof construction scratch, not an invocation-memory snapshot or a retained certificate" (:6-8).

## Mechanisms

- **Prefix replay.** `at_completing` (:4705-4884) builds the entry roster, then `replay_prefix` (:4886-5228) walks `admitted_execution_order` up to the queried statement and applies one transfer per statement kind. Every query rebuilds the frame from entry, so a state with n queries pays about n replays. The free function `byte_length_bound` (:6879-6895) builds a whole frame to return one number.
- **Completed-call memo.** `CompletedCallGuarantees` (:227-322) stores the hypotheses derived for each call, keyed by statement index, machine, state and call site; a row answers only when actuals, machine values and result are all equal, otherwise it is re-derived and replaced. The comment gives the reason: replay made a state with n calls pay n² derivations (:213-226). It serves callee `ensures`.
- **Anchors and storage-graph preservation.** Each tracked entry has an anchor snapshot (:4629-4633). `retire_unpreserved` (:5394-5499) asks `place_preserved_since(at, place, anchor)`; survivors are re-anchored at `at` so the next walk is shorter (:5475-5479). `anchor_changed_entries` (:5327-5348) compares the whole roster before and after each statement to find what changed. Serves ownership/effect soundness of every fact above.
- **Scoped binding with a budget.** `scoped_operations` (:6743-6845) walks an expression with an explicit stack, collects symbol binders and occurrence binders, and charges each bound value's size (`charge`, :6846-6873) against a 4096 budget and depth 64. `admitted` (:6655-6726) is the recursive yes/no twin. Serves every contract expression.
- **Join by interval union.** `joined_values` (:2961-3004): equal -> first; else union of closed intervals around a fresh atom. Serves `match`.
- **Case split.** `proves` (:6005-6035) with `capture_alternatives` (:5889-5912), limited to 8 arms.
- **Selector-as-value projections.** `ScalarProjection::Element` stores the captured selector value; equality ignores the source segment (:3419-3433) and falls back to a proved equality (:3440-3468). Serves indexed reads and entry rank observations.
- **Contiguous-run selection.** `selected_value` (:3328-3395) sorts known elements, scans equal-value runs, then tries the whole roster.
- **Dependent application reading.** `application_value_with_captured` (:71-185): stack walk, budget 4096, names resolved to captured values, actuals or current symbols.
- **Declared-read telescope.** `declared_projection` / `declared_read_selector_value` (:2344-2457): resolves a declaration's indexed read through selector arguments with five fallbacks, depth 64. Serves termination ranks.
- **Path closure.** `parameter_projection_paths` (:2527-2575): collects every place rooted at a state parameter in statements and contracts, plus every suffix of each path, with a `HashSet` of visited expressions.

## Surprises

**Evidence on the three properties.**
1. No proof kernel. The names `proof_admission`, `ProofNode` and `verify_obligation` do not occur; "certificate" occurs once, in the header, to say none is retained (:8). Every "proved" is `validation::scoped_arithmetic_implication(..)` or `scoped_arithmetic_values_relation(..) == StrictArithmeticImplicationJudgment::Proven` (:2453, :2980, :3308, :3466, :5991, :6000-6001, :6030, :6628, :6636): an enum from another module, with nothing kept. On the strength of those answers the file constructs `checked_trees::CheckedEntryIndexBound` rows (:3898-3908) that go into the checked tree.
2. Mixed. Places are handles, not text. Text decides equality of unknown values (the atom strings), one field lookup (:1995), static argument values (:609, :641), and whether a length fact is kept (path-name rendering).
3. Strong, as listed above.

**Looks like a bug: a match arm's window endpoint can be replaced by the pattern value when it is a different expression.** `substitute_matched_subject` replaces an endpoint when `value == subject || same_symbol_term(value, subject)` (:2058). `same_symbol_term` (:2085-2094) says two `Term`s are the same subject when their lists of `Symbol` binders are equal and non-empty. It does not compare the terms' expressions, and it ignores `Occurrence` binders. `capture` returns a `Term` for any admitted expression that is not Exact/Trapping `+ - *` (:5816-5832; `completed_scalar_value` returns `Term` or `AdmittedIntegerRemainder`, `checks_contracts_prover.rs:2255-2265`). So with subject `which & 3` and an arm `0 -> row[0..which ^ 5]`, both capture as `Term`s whose only symbol binder is `which`, and the endpoint `which ^ 5` would be replaced by `0`. The four window proofs (:1728-1743) then run on the replaced value. The comment's intent (:2082-2083) is two occurrences of one bare parameter name. I did not run this; it follows from reading the three functions.

**Possible fact-keeping across assembly.** :5203, described above.

**A selector guessed from an unrelated observation.** :2410-2431, described above. It sits in the termination-rank entry path.

**Declared-read atoms may collide.** The identity at :2316-2319 is `declared-read:parameter:{P}:calls:{calls}`. It has no state and no coordinate. Two reads of different fields of one parameter with equal `calls` would get the same atom, and so be treated as equal integers. Whether `read.calls` distinguishes them is not visible here.

**The scoped expression's `owner` depends on traversal order.** In `application_value_with_captured`, `owner` starts as the first argument's parent (:83-87) and is overwritten each time a formal name or member is popped from the stack (:95, :100, :123). The builtin-meaning check for a `Binary` node (:166-171) uses whatever `owner` is at that moment, and the returned expression carries the last value (:180-184).

**No diagnostics and almost no tests.** A 6,895-line file that decides bounds, casts, joins and effects has one unit test, about a cache.

**The frame is the fact engine, and it is rebuilt per query.** Every `at(..)` replays the state prefix. The memo (:227-322) and re-anchoring (:5384-5392) are both repairs for the cost of that design, and both comments say so.

**`i64` is the bound type at four seams.** Declared, entry, call-return and frozen-field bounds arrive as `i64` and are widened with `BigInt::from_i64` (:496-497, :2913-2914, :5718-5719, :6448-6449); integer literals are captured with `value_i64()` (:5650, :1361). A `u64` bound or literal above `i64::MAX` cannot pass through these as an exact value.

**Probe atoms with an empty identity.** `fixed_length(.., String::new)` is called only to test `is_some()` (:819, :1048, :1241, :1581, :5091); the atom it would build has the identity `""` and is discarded each time.

**`retire_unpreserved` can run twice for one assignment** (:5111 and :5159), and `conditions.next().unwrap_or(false)` (:5493) drops any condition beyond the computed list.

**A nested `match` inside an arm loses the outer arm's subject substitution** (:1642-1646 calls `matched_length` without `subject`/`replacement`). Loses precision only.

**Capability not expected:** unknown-index reads over known array contents (:3311-3396), translation of known elements through an exact window (:3266-3292), saved Boolean guards carried through record fields and copies (:2135-2271), and proof by cases over match arms (:6005-6035).
