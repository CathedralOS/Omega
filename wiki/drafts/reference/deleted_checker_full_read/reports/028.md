## What this code is for

This is the back half of the old checker's contract file. It holds the helper provers that the call-`requires` check and the exit-`ensures` check consult, and at the very end the function that runs all contract checks (`check_flow_call_contracts`, 11676-11935).

Each helper answers one narrow question with a `bool` or an `Option`: can a callee's entry predicate be proved from the values the caller's operands had when they were evaluated (`call_values`, 6447-8141); does a content-conservation `ensures` hold because the body writes nothing (`content_preservation`, 8222-8605); does a scalar `ensures`/`requires` hold on the current scalar values (`current_values`, 8606-8817); which postconditions did the earlier validation stage already prove for a machine (`entailment`, 8818-9394); does a float value satisfy an `f32`/`f64` predicate domain (`float_predicate_domains`, 9396-9910); does a guard fact still describe a named jump's operand after earlier operands ran (`guard_operands`, 9911-10253); does `embed(result) == 3` hold at an exit (`integer_embeddings`, 10254-10390); what integer interval does a guard state for a place (`intervals`, 10391-10524); does a domain membership reach a place through a reference (`reference_domains`, 10525-10742).

The `labels` module (10750-11350) renders expressions as text and substitutes a callee's formal names by the caller's argument text; other provers compare these strings. `places` (11351-11376) and `return_values` (11377-11651) hold small shared lookups, and `return_values` also contains the one diagnostic emitted in this slice (an activation claim returned from its activation).

Nothing in the slice builds or checks a proof object. Every prover returns its own yes/no or forwards to a `validation::` or `CurrentScalarValues` function that returns a yes/no.

## Mechanisms

- **Captured-operand binding of predicates** (`call_values`, 6447-7908). For each observation a callee predicate makes on a formal, the code finds the caller operand at that position (`actual_at`, 6734-6765, adding one for an expression-call receiver), fetches the values that operand could have had (`captured_values`, 6831-6864), and rewrites the predicate's operand either into a literal (when the value is known) or into a fresh positional parameter bound to a canonical place (`bind_observation`, 7410-7451). It intersects the fact contexts of all operands it touched (7646-7650) and records one "epoch" per binding so that the same place read in two epochs is checked for agreement. Serves `requires` on calls and cleanup predicates. No budget.
- **Three-tier proof attempt with one recursion** (`proves_bound_predicate_mode`, 7560-7818). Tier 1: observed values folded into literals; accept if `transport` reports `proves_required` (7772) or `proves_captured_predicates` succeeds (7805). Tier 2: prove `guard implies requirement` using the selected guard (7808-7814). Tier 3: call itself once with folding off and prove the guarded requirement with `boolean_predicates::proves` (7776-7782, 7815-7817). Bounded: the recursive call passes `false`, and the `false` branch returns before recursing.
- **Operand provenance walk** (`operand_erases_membership`, 7910-8101). Depth-first search through operand records: constructed children (path prefix match), selected alternatives, copies, backing operand with address projection, stored reference sources, retained suppliers, value source. An `active` stack stops cycles. No depth budget. Serves domain erasure (casts or expressions that drop a domain).
- **Call-graph worklist** (`body_preserves_case_tags`, 8864-8928). Visits every machine reachable through recorded calls, with a linear `visited` list. Fails closed on an unknown callee, a body that is not checked, a missing or incomplete write frame, or any assignment to a non-primitive destination. Serves tag-only proof of case requirements.
- **Per-machine memo of proved postconditions** (`ProvenExitExpressions`, 8936-9118). A vector keyed by machine symbol, filled lazily from validation's rows; a single (not iterated) pass adds law guarantees whose sources are all present.
- **Exit frontier cache** (`ExitValueCache`, 8617-8623). `Option<Option<...>>`: the scalar-value frontier at one exit is built once and reused for all clauses, including the "unavailable" answer.
- **Float bound implication** (`float_predicate_domains`, 9396-9910). Splits the domain predicate on `&&`, turns each conjunct into a `FloatPredicate` bound in the domain's format, then tests implication from a literal, from a premise on the same place, or from the nonnegative-difference rule. Premises are gathered by splitting context facts on `&&` with a worklist (9864-9889). Format-specific (F32 vs F64).
- **Guard interval lattice** (`intervals`, 10391-10524). Reads a guard as a `BigIntInterval` for one spelled place: `&&` intersects, `== true` is peeled, each comparison against a closed integer literal gives one interval. Containment is tested against a requirement whose unstated ends are `i64` extremes; `narrow_i64_bounds` narrows an optional `i64` pair.
- **Operand write-ordering test** (`guard_operands`, 9911-10253). For a named jump, collects every other call in the same statement and the same arm, computes the places each may write (index expressions blanked so any index matches, 10021-10027), locates the call's argument position by subtree containment, and checks whether any later-read argument reads an overlapping place.
- **Label rendering and substitution** (`labels`, 10750-11350). A recursive renderer turns an expression into text; name nodes are replaced by the argument's text (call contracts) or the base label (domains). Provers elsewhere compare the resulting strings.
- **Content plan rebinding** (`inherited::rebind`, 8409-8444). Rewrites a trait requirement's conservation equation so parameter roots (position, symbol, name) point at the satisfying body's parameters, then recomputes the report fingerprint (8372-8373).
- **Parallel per-state checking** (11744-11838). Call `requires` and field writes are checked per state on a rayon pool; results are merged in state order, then exits are checked sequentially.

## Accepts or skips without proof

- **Decided means "no diagnostic"** (11804-11812). A call is recorded as `DecidedCallRequires` when `check_call_requires` pushed nothing. If `statement_index` does not fit `u32`, the row is silently not recorded and no error is raised. Whether downstream needs every call to have a row: cannot tell from this slice.
- **Accepted postconditions come from a list** (9080-9091). `for_machine` takes validation's `normal_returns` as proved without rechecking; the comment says "nothing rejudges it" (9060-9062). The proof is validation's own yes/no.
- **`transported.proves_required`** (7772-7774) is accepted as a flag from `captured_predicates::transport` (outside slice).
- **`membership_evidence` fallbacks** (7102, 7123, 7126, 7131, 7134, 7137, 7177, 7189, 7201, 7204). Ten failure paths return `Some(MembershipEvidence::default())`, which is one case with empty contexts and `referents: None`, rather than `None`. An erased membership returns zero cases (7165-7169). `Ok(None)` from position lookup returns `None` (7122). The consumer is outside this slice; whether an empty case list or an empty-context case can be read as "nothing left to prove" cannot be told from here.
- **Missing lookups that return quietly in `check_activation_return`** (11401-11425): unknown machine, unknown state, no result type, or a non-named type all return without a diagnostic. A claim inside an aggregate is not caught here; the comment says aggregate custody is decided elsewhere (11389-11392). Cannot tell from this slice whether that other check existed.
- **`runtime_values` path sets `preserved = true`** (9270-9274). Unless both caller and callee are proof machines, entry-premise preservation is not checked here; the decision is handed to `validation::selected_value_call_requirement_entailed` / `structural_call_requirement_entailed`. An unknown callee machine also takes this path (9263-9264).
- **`unchanged_projection` does not check for direct assignments** (8479-8493). It requires complete, empty write frames only. `entry_premises_are_preserved` in the same file adds "no assignment statements" with the comment that direct owned-parameter assignments "are not outward effects" (9188-9192, 9213-9220). Whether content plans can name an owned mutable parameter: cannot tell.
- **`required_subject_bound` accepts any lowered call** (9547-9557). If the predicate is not confirmed by `has_ieee_meaning` but is a call node, it is still accepted as a comparison. Whether `comparison()` already restricts which calls qualify: outside slice.
- **`finite_call_argument`** (9836-9846) trusts any operator whose path is `Float::is_finite`, `F32::is_finite` or `F64::is_finite`; it does not check that the operator is the bundled one.
- **`requirement_reads_survive_earlier_operand_writes`**: returns `true` when the requirement mentions no target parameter (10058-10061) and when the call is not a named jump (10066-10068). An operand call whose authored expression is not found inside any argument is skipped with `continue` (10070-10074). Only operands at strictly earlier positions are considered (10077); a writing call inside the same argument as the read is not. Cannot tell whether another check covers those.
- **`fact_requirement_mentions`** returns no mentions for any payload other than a boolean contract or a membership (10170), which makes the survive check return `true` for them.
- **`establishes_closed_requirement`** (10460-10467) treats a guard with no upper end as satisfying any requirement whose high end is at least `i64::MAX`, and likewise for the low end. For a subject wider than `i64` this accepts a bound the guard does not state. Whether callers restrict the subject type: cannot tell.
- **`comparison_bound`** returns the unbounded interval when a subject/literal pair is not a closed comparison (10519-10522); the comment says the result is "only ever weaker than the guard". Combined with the previous item, an unbounded interval satisfies a requirement whose ends are the `i64` extremes.
- **`contexts_prove_domain`** accepts if any one context contains a matching fact (10708). Whether contexts are alternatives or jointly true at this point: cannot tell.
- **`selected_contexts.unwrap_or_else(|| contexts.to_vec())`** (7739): a predicate with no observations is judged in the caller-supplied contexts.
- **`instantiate_call_contract_expression_label`** falls back to the parameter's own name when the argument is missing (10915) and to the unsubstituted rendering when nothing matches (10939). These produce a label that will most likely fail to match; they do not accept by themselves.
- **Fail-closed places worth recording**: `arm_operand_frame` returns `None` when a write frame cannot be bounded and both callers return `false` (10062-10065, 10121-10124); `body_preserves_case_tags` returns `false` on any missing fact (8876-8895, 8920-8922); `isolated_proof_values` ends with `.unwrap_or(false)` (9390); `operand_erases_membership` on an invalid or already-active operand returns `false`, meaning "not erased" (7919-7921), which is the permissive direction for the cycle case.

## Surprises

1. **Two definitions of "what an exit returns" that disagree.** `return_values::exit_return_expression` (11577-11599) accepts a statement expression only if it is the last statement, and a transition target only if the target belongs to that transition and the transition's exit is `Ordinary`. `current_values::proves_exit_expression` (8643-8674) accepts a statement expression at any index and a transition value target without either check, and also handles the past-the-end exit. Two exit provers can therefore see different returned values for the same exit.

2. **`unchanged_projection` omits a condition its neighbour says is needed.** See 8479-8493 against 9188-9226. If a content plan can name a by-value mutable parameter, a body that assigns it has an empty outward write frame and still changes the content.

3. **The `i64` sentinel conflation in `establishes_closed_requirement`** (10455-10469). An unstated guard end is treated as the `i64` extreme, and the requirement's unstated end is published as the same extreme. An explicit requirement `self <= 9223372036854775807` cannot be told apart from "no upper bound", and for a `u64`/`i128`/`u128` subject a guard with no upper bound would establish it.

4. **The comment says "without matching text"; the subject is found by text.** `intervals` promises no text matching of the bound (10395-10397), which is true of the bound, but the place the guard talks about is identified by `display_name(...) == subject_label` (10511-10512).

5. **`nonnegative_difference` may be dead.** It calls `comparison(program, value)?` and then requires `binary.operator == Subtract` (9656-9659). If the helper `comparison` (outside the slice) returns only comparison operators, this function can never succeed and the subtraction rule described at 9409-9415 never fires. Cannot tell without the helper.

6. **Struct literals collide in domain labels.** The domain renderer labels any struct literal by its type name alone (11131), so `P { x: 1 }` and `P { x: 2 }` render the same, while the call renderer prints constructor values (10946). `domain_proves_expression_label` compares such labels for equality (11089-11090).

7. **A matched parameter name replaces the whole name path.** In `name_label`, when the first member of a path matches a parameter by name, the function returns the argument's label and drops any remaining path members (10883-10915). The match also fires on name equality alone, even when the symbol differs.

8. **Shared borrow and bare place render the same** (11254). `&x` and `x` have one label; `&mut x` is `mut x`. A label match therefore cannot tell a shared borrow from the value.

9. **`domain_proves_expression_label` recursion has no cycle guard** (11092-11105). It relies on domain memberships being acyclic; nothing in this slice checks that.

10. **`value_qualifications` is merged inside the exit loop** (11856-11858 then 11897-11905). `check_result_field_domains` for an exit in an early state sees only the qualifications of states merged so far; exits in later states see more. Records are copied into a new arena, so any handle into a per-state arena would no longer point at the same slot. Whether either matters depends on code outside the slice.

11. **`check_state_transfer_result_domains` diagnostics do not block the "decided" row** (11784-11790): `before` is sampled after that check, so a call that fails it is still recorded as decided. The pass as a whole still fails because diagnostics are non-empty.

12. **Only the last two exit checks are de-duplicated** (11896-11916). `exit_diagnostics` is sampled after `check_exit_ensures`, so duplicates among earlier checks are kept.

13. **Leftovers that show removed generality.** `actual_at` computes `ordinal` twice, both equal to `position` (6753-6757), and `Actual.argument` is an `Option` that is always `Some` (6755-6758) while callers still handle `None` (7143, 7179, 7242). `requirement_reads` has `let argument_index = index;` (10205). `RequirementRead` has one variant (9938-9940). `fact_requirement_mentions` ignores `_facts` (10160). Two iterators map each item to `((), state)` and immediately discard the unit (8909-8915, 11484-11491).

14. **Receiver offset is derived two ways.** `actual_at` adds one only for `CallSite::Expression` with a valid receiver (6750-6752); `captured_argument_expressions` takes the offset from `flow::captured_call_operands` (6821-6822). A statement call with a receiver gets no offset in the first.

15. **Debug trace in the hot path.** With `struct_trace` on, every call prints `CALLREQ caller=... proof=... target=... proof=...` to stderr (11769-11783); `caller_is_proof` exists only for that line (11760).

16. **`structural_call_requirement` recomputes `proof_only_classification` per requirement** (9243), while the orchestrator computes it once (11702).

17. **Law guarantees are added in one pass, not to a fixpoint** (9042-9055, 9093-9107). A guarantee whose sources include another guarantee's result is added only if order happens to allow it. In `for_machine` the additions are not de-duplicated (9107) and are skipped entirely when the base list is empty (9092).

18. **Pointer identity** is used to match a named transition path to a call site (`std::ptr::eq(path, selected)`, 11551). This is the opposite of text identity and depends on both lookups returning references into the same table.

19. **`premise_expression` drops facts that came from a call's `requires`/`ensures`** (9892-9894). A float bound promised by a callee's `ensures` on a place is not used as a premise for float domains.

20. **Evidence on the three properties.** (1) Supported throughout: no proof-kernel call appears; every decision is a `bool`/`Option` computed here or returned by `validation::` or `CurrentScalarValues`. (2) Mixed: `call_values`, `content_preservation`, `guard_operands` and `reference_domains` identify values by handles, symbols and canonical places, and their comments reject text ("a printed place prefix cannot create the relation", 6566); `labels`, `places`, `intervals`, `integer_embeddings` and `finite_call_argument` decide by strings. (3) Supported: one prover per placement and value kind, plus the literal copies listed above; the comments at 7540-7544 and 8703-8706 show the authors merging some of these ("share one captured Boolean algebra", "The same prefix transfer handles an ordinary call and a named state edge").
