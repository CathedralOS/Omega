## What this code is for

This slice is the second half of the module that turns a multi-state machine into one "composed Unit control graph" plan (`CheckedComposedUnitControlMachinePlan`). It is plan construction, not diagnosis: every function returns `Option`, and a refusal is `None` plus a trace phase string naming the step that declined. The slice holds five inner modules and the driver. `returns` (5754-6129) plans how a returning state produces its scalar or structural value. `successors` (6130-7590) builds one edge from a state to another state in the same graph: for every parameter of the target state it decides where the argument's value comes from and whether the transfer of ownership or of a loan is allowed. `terminal_calls` (7591-8038) plans a transition arm that finishes the machine by calling a machine outside the graph. `terminator` (8039-9322) classifies the statements at the end of a state (return, crash, jump, two-way conditional, ordered guarded chain, closed-sum dispatch, terminal call) and builds the matching terminator plan. `unit_completions` (9323-9596) binds a retained tree of "match → call" completions for a Unit-result state. `build_traced` (9608-10141) drives everything: it checks the machine shape, plans each state's signature, contracts, operations and terminator, then checks parameter custody shapes and attaches termination ranks and returned-reference origins. Most judgments here compare records that earlier stages stored in `facts` (flow calls, guarded exits, scalar expressions, structural values, proof terms) against the typed tree by state symbol and statement ordinal.

## Mechanisms

- **First-match cascade for an edge argument** (state_graph.rs:6388-6907). For each structural parameter of the target state the code tries nine source kinds in a fixed order (source parameter, subslice, string literal, whole local result, case payload, projected value, loan from a parameter or local, freshly computed value) and takes the first that admits. The order decides meaning: an argument that could be read two ways gets the earlier reading. It serves state transitions with arguments.
- **Stop after a non-returning operand** (state_graph.rs:6391-6392, 6903-6905, 6948-6967). A `scan` stops planning further structural transfers once one argument's evaluation cannot return normally; scalar arguments at later positions are then skipped.
- **Result numbering** (`next_result_ordinal`, state_graph.rs:5929-5938): the next free binding ordinal is one more than the largest ordinal among all producers, including nested value calls. Return values and edge operands number into the same roster.
- **Recursive binding of a completion tree with a cycle guard** (`bind_expression`, state_graph.rs:9457-9595). It walks retained completion nodes, keeps the set of active `(arena index, generation)` handles, refuses a revisit, and computes "can continue normally" bottom-up: an invocation continues only if all its operations do; a selection continues if any arm does. No depth budget.
- **Bounded syntactic walk** (`expression_names_erased_dispatch_subject`, state_graph.rs:9297-9321): at most 8 steps down through borrow, member, the left side of a binary, or a unary operand, to find a name that is a local whose binding is an erased dispatch subject.
- **Predicate lowering with a budget** (state_graph.rs:9725-9732): `lower_state_scalar_contract_predicate` is given a mutable budget of 4096.
- **Interning of declaration requirement sets** (state_graph.rs:9762-9782): a linear search for an equal set, else append; the state stores the index.
- **Failure-reason selection** (state_graph.rs:8288, 8306-8328, 8348-8349, 8928-8930, 8935): the trace is marked before the Unit-completion and closed-sum attempts; if those attempts advanced the trace and the tail is finally unsupported, the trace is restored to the earlier failure so the reported reason is the more specific one. This affects only which reason is shown.
- **Liveness and entry reachability** (state_graph.rs:10011-10020): `live_mask` (outside the slice) marks reachable states; the code then checks whether any live edge targets the entry state.
- **Termination ranks** (state_graph.rs:9663-9678, 10112-10114): natural ranks, rank components and rank-preserving edges are computed by the `ranking` module (outside this slice) and attached to the plan.

## Identity by text

Almost nothing here is identified by text. Values and places are identified by symbol handles, expression handles, arena handles, binding ordinals, parameter positions and `(state symbol, statement ordinal, role)` coordinates.

- `CheckedMemberIdentity::of_member(variant.identity, variant.name.clone())` and the same for the field (state_graph.rs:7578-7585): the case-payload plan carries the case and field names as strings next to their identities.
- `machine_binders` returns `(SymbolHandle, String)` pairs that are passed into type identity construction (state_graph.rs:5970, 6034, 6090, 6705, 6863, 7896).
- Trace phases are string literals, some built by `concat!` (state_graph.rs:6202-6246), and `loan_backing::retained_storage`, `retain_parameter_arrival_domains` and `finish_state_graph` return their refusal reason as a string that the trace records (6936-6940, 9788-9793, 10110). The strings do not decide acceptance.
- `machine.name` and `state.name` appear only in `eprintln!` trace output (6037-6047, 6065-6071, 8222-8225).

Identity by coordinate rather than text deserves a note: the true and false successors of one conditional are told apart only by statement ordinal `ordinal` and `ordinal + 1` (8659-8662), and a guarded chain arm is matched to its retained record by `ordinal + index` (8752-8755). A default (invalid) `SymbolHandle` is used as the in-band signal "this arm is not a jump" (8955, 8971, 8983, tested at 8773 and 8844).

## Accepts or skips without proof

- **Proof terms are copied, not checked** (state_graph.rs:7088-7105). An erased proof argument is accepted when a term is stored at the transition-argument role. No kernel call appears in this slice. Whether the term was verified when stored: cannot tell from here.
- **A source-fact requirement is accepted on presence** of `facts.proof.state_requires_fact(...)` (9699-9717). The record is not inspected.
- **A contract expression that fails to lower is kept, not refused** (9746-9752): the requirement becomes `SourceExpression(expression)`. Only domain and finite rows that fail to lower are refused (9753-9758). Whether a later stage proves the kept expression: cannot tell.
- **A scalar return arm is accepted on the presence of a retained record** at its statement (8597-8616, 9067-9085). The first alternative (`expression_at(...).is_some()`) does not compare the machine or the primitive type; the second compares only the machine. The arm is then given the machine's declared `primitive_type`. Another check: cannot tell.
- **Edge cleanup is optional at this point** (6307-6312): if no cleanup record exists for the edge the successor is returned without discard positions. The module comment says a later owner "refuses missing plans" (8050-8053).
- **A stored-loan check passes when the lookup fails** (6727-6733): `stored_leaf_access.is_none_or(loan_permitted)` is true both when the leaf stores no loan and when `canonical_place_type_reference` could not resolve the place. `projected_loan_transfer` then repeats the path resolution and can still refuse (7320-7331).
- **Carrier identity defaults instead of refusing** (7373-7385): for a bounded view without a dynamic selector, and when `add_reference_type` fails without a dynamic selector, `carrier_type_identity` is `Default::default()`.
- **A borrowed parameter forwarded to a borrowed parameter** compares only structural type identity and access (6399-6407); the normalized type identity (which the owned case compares) is not compared. The qualified-arrival check at 10034-10041 may cover refined types; cannot tell.
- **A proof-only tail returns Unit without running its arms** (8492-8498, 8715-8724, 9266-9280). The test is: Unit result, and every guard names an erased dispatch subject. The arms' targets are not examined. See Surprises.
- **`transition_on_erased_dispatch_subject` returns true for any non-`When` guard** (9291-9293).
- **Entry state exempt from qualified-arrival checking** when no live edge targets it (10015-10036): its parameters' qualifications are trusted to the invoking call.
- **States that are not live skip the parameter custody checks** (10021-10024).
- **Linear owned parameters skip the contents check** (10063).
- **Open borrowed windows are accepted when all paths crash** (9902-9906).
- **A non-returning call anywhere in the state's operations ends terminator planning** (8115-8132): the tail statements are not classified or checked.
- **`_ =>` arm tries a jump** (8465-8476): any unconditional transition not matched earlier is handed to `successor`, which refuses if the target is not in the graph. This arm does not accept by itself.
- **`complete_expression` with an already-bound structural result** returns it without the returned-reference-sources check (8181-8184); the freshly produced path does the check (8210-8228). The whole-plan check at 10115-10138 runs afterwards for `states[0]`.
- **`abandons_custody: false` is fixed** for every Unit completion (9451-9453); this is the cautious value.

## Surprises

- **Nothing in this slice reports an error to the user.** Every refusal is `None` with a trace phase. A program this module declines is presumably handled by a different route or refused elsewhere; from this slice a reader cannot tell which, and the same construct can therefore be "unsupported" here for reasons of plan shape rather than language rule (the ten "unsupported tail" phases at 8887-8932 describe shapes, not faults in the program).
- **Proof-only tails are decided by a shallow syntactic walk, and the arms are dropped** (state_graph.rs:8492-8498, 8715-8724, 9266-9321). `expression_names_erased_dispatch_subject` follows only the left operand of a binary expression (9314) and never looks at the right operand, gives up after 8 steps, and accepts when it reaches a local that is an erased dispatch subject. If every guard in the tail passes, the state's terminator becomes `ReturnUnit` and the comment says the arms are not executed. The code does not check what the arms' targets are: an arm that jumps to another state or calls another machine is treated the same as an arm that finishes. Whether an earlier stage guarantees such arms are always pure completions: cannot tell.
- **Four different cut-offs for "the earlier result that is this local"** (6498 `<`, 6621 `==`, 7169 `<=`, 7529 `<`). The `<=` in `projected_value_subject` admits a result established at the edge's own statement ordinal, which the other three do not.
- **After a non-returning argument, later scalar arguments are skipped but later erased scalar and erased proof arguments are still required** (6965-6967 against 7044-7105). The edge is refused if those later erased records are missing, although the code after the stop point never runs.
- **`terminal_calls::completion` is evaluated twice** for the same inputs, once in the match guard and once in the arm body (8440-8456).
- **`complete_expression` and the whole-plan check disagree on which state's returned references to collect.** The per-state path asks for sources of the returning `state` (8218-8220); the final step asks only for `states[0]` (10134-10137), although any state in the graph may return.
- **The `selected static destination` path** (8235-8287) plans a single jump or return when `selected_transition` picks one arm of a guarded tail statically. The unselected arms are not planned or checked in this function.
- **In-band sentinel**: `internal_destination` returns `Some(SymbolHandle::default())` to mean "valid arm, but not a jump" (8955, 8971, 8983). A real target that happened to be the default handle would be read as a return.
- **Direct indexing without bounds checks** in code that otherwise uses `get(...)?`: `signatures[source_index]`, `signatures[target_index]` (6358-6359), `program.state_parameters(source)[*position]` (7022), `program.state_parameters(source)[position]` (7520), `program.state_parameters(state)[parameter.position as usize]` (10044, 10048), `planned[0]` (10020), `states[0]` (9634, 10131, 10136).
- **Evidence on the three properties.** (1) Supported: there is no call to a proof kernel, `verify_obligation`, `ProofNode` or certificate type in the slice; the only contacts with proof are presence lookups of stored facts and terms (7093-7103, 9701-9709). (2) Not supported here: identity is by handles and coordinates; strings appear only in traces and in two name fields carried beside identities (7578-7585). (3) Strongly supported: see the repetition section; the edge-argument cascade alone is about 520 lines of one fit rule written per source placement.
- **Debug output in product code**: three `eprintln!("CHECKSITE …")` lines print under `validation::trace_flags::trace_completion()` (6036-6048, 6064-6072, 8221-8226).
- **Formatting drift inside the cascade**: the body of the per-parameter closure (6393-6902) is not indented to its nesting level and has stray alignment (for example 6781-6782, 6879), which suggests the block was edited by insertion many times.
