## What this code is for

These three files are the part of the old flow analysis that answers two questions for the rest of the checker: "which storage may this statement or call write?" and "is a value that was read earlier still the same value now?". None of them reports a user-facing error itself; they return `Option`/`bool` answers that other flow code turns into kept or dropped facts.

`flow_mutation.rs` computes write sets as lists of `CanonicalPlace` (a root plus field/case/index segments) or `StorageRegion` (a place, or "content reached through" a place). For an assignment it finds the target place and follows local reference bindings back to the storage they point at. For a call it uses, in order: special compiler operations, a whole-program per-state mutation summary computed by a fixpoint, a boundary signature's write frame, and finally the "signature ceiling" (everything the declared parameter types could let the callee write). A `None` answer means "unknown", and the file header says flow then drops every active context (flow_mutation.rs:1-6).

`flow_observations.rs` ties a case (tag) test or a scalar read back to the exact operand occurrence flow recorded for it, and decides whether an earlier observation of a reference "descriptor" may be reused for a later read of the same descriptor.

`flow_operand_contexts.rs` selects which fact contexts apply to one call operand (a detached copy keeps its capture-time facts; a view keeps only facts that are still live at the call), and supplies the chronology checks: whether any recorded write between two points overlaps a place.

## Mechanisms

- **Whole-program mutation summary fixpoint** (flow_mutation.rs:2713-3235). For each state with borrow facts it collects direct writes (assignments and atomic-once locals, 3296-3371) and cleanup writes, then iterates: each dirty, still-complete caller pulls its callees' new writes, places them at the call's actual arguments, and keeps those that are exported. A reverse `callers` list and a `dirty_mask` drive rounds (2913-2924, 3213-3233). Rounds run in parallel with rayon over callers and read the previous round's summaries. It is incremental: each call remembers how many callee writes it has consumed (`seen_writes`, `seen_held`) and caches instantiations in a per-call linear `Vec` (3105-3142). No iteration budget; termination relies on write lists only growing and `complete` only falling. An incomplete summary has its writes cleared (3223-3226) and is never recomputed (2930). The result is stored once in a `OnceLock` (2514-2533). Serves call-effect invalidation and borrow access checks.
- **Held-write runs** (flow_mutation.rs:2565-2568, 2603-2609, 3161-3191). Besides the whole run's writes, a summary keeps per-parameter "writes while that parameter's loans are held"; a jump or terminal machine call uses the held subset (`TargetRun`, from `flow::jump_loans`, outside this slice).
- **Origin rebasing worklist** (flow_mutation.rs:1833-1930). Follows a place rooted at a local reference binding back through recorded local write origins to the storage it denotes. Uses a stack of `(place, crossed origins)`; crossing the same origin twice returns unknown. Produces a union of may-write regions. Serves writes through `&mut` locals and views.
- **Alias closure** (flow_mutation.rs:1298-1392). Given physical written places and the list of local origins, adds every alias name under which facts may live, translating coordinates through windows with `alias_projection` (1087-1137: fixed range/index arithmetic, unknown element for dynamic selectors).
- **Region algebra** (flow_mutation.rs:2306-2469). Four kinds of write footprint: declared storage, resident content, nonresident content, unresolved content. `declared_places` refuses if any footprint is not declared storage (2363-2367), so a consumer that only understands places gets "unknown".
- **Signature ceiling** (flow_mutation.rs:148-552). A type-directed walk of each parameter that enumerates owned resident owners and carried exclusive loans. Cites `wiki/spec/language/dependent_values.md`, "Mutation frames" (23-36).
- **Boundary frame refinement** (flow_mutation.rs:4382-4446, 4478-4635). A frame path names storage without index selectors; the code restores an index selector by matching the path against the call's recorded exclusive borrow referents, and blocks the refinement when a non-borrow exclusive actual or the receiver shares the coarse path.
- **Retention agreement** (flow_observations.rs:941-1093). Mutually recursive `profiles_agree` / `alternatives_agree` compare two retention profiles (roots, stored value, leaves by path, alternatives both ways). A revisited pair returns false (1005), so cyclic profiles never agree. No depth budget other than the visited list.
- **Formation-chain peeling** (flow_observations.rs:848-901) and **backing-chain walk** (1100-1124): loops with visited lists that return `None` on a repeat.
- **Write-interval chronology** (flow_operand_contexts.rs:186-299, 971-1043, 1086-1136). Writes are recorded as growing prefixes per statement. The code joins "rest of producer statement", "whole intervening statements" in admitted execution order, and "consumer prefix", and tests each write against a place with a pluggable relation (`contents_overlap` or `binding_overwrite`, 635-639).
- **Context selection cache** (flow_operand_contexts.rs:30-184). `BTreeMap` keyed by operand handle, a stable-copy flag, the invocation constraint span, state and statement; lazily prepares case and membership evidence with `OnceCell`.

## Identity by text

- `place_from_origin_path` (flow_mutation.rs:1983-2030) turns a dotted string into a place: it splits on `.`, finds the root by comparing the first component to parameter names and then to local declaration names (`parameter.name.as_str() == root_name`, 1994-2008), resolves each later component as a member name (2010-2022), and reads a trailing `"[*]"` as "whole collection contents" (1989-1991, 2023-2028).
- `frame_write_place` (flow_mutation.rs:1969-1981) strips `"[*]"` and calls the same parser. Its callers feed it write-frame paths: cleanup paths (2801-2805), boundary signature frames (4392-4394), statement and discarded-result cleanup frames (4799-4800).
- `source_place` falls back to `source.path`, a string, when no structural origin exists (flow_mutation.rs:804-813).
- `AssignmentWriteTarget::Storage { paths }` are strings parsed the same way when the target has no direct place (flow_mutation.rs:1517-1534).
- The boundary refinement exists because the string path dropped index selectors: "the only extension a dotted frame path could have coarsened away" (flow_mutation.rs:4615-4620, 4469-4477).
- Names used only for trace printing: `state.name`, `expression_table.display_name` (flow_observations.rs:496-502).
- Refusal reasons are `&'static str` values but are only printed, never compared (flow_observations.rs:107-125, 260-467).

Evidence against the property in this slice: everything else identifies storage by `SymbolHandle`, `CanonicalPlace` segments, arena handles and expression handles, and several comments forbid text identity: "without treating lifetime inputs or the display path as an address" (flow_mutation.rs:942-945); "nor an equal-looking source path can replace that observation" (flow_observations.rs:643-647); "source spelling alone never redirects a guard" (flow_observations.rs:1336-1337); "equal rendered paths cannot erase an intermediate write" (flow_operand_contexts.rs:664-668). flow_observations.rs and flow_operand_contexts.rs contain no string-based identity.

## Accepts or skips without proof

- flow_mutation.rs:4770-4778: `close_storage_places_over_aliases(...).unwrap_or(targets)`. If alias closure fails (no resolver at 1264, or origins unavailable at 1265), an assignment's write set is just its direct targets, with no alias names added. The sibling paths return `None` on the same failure (4700-4707, 4811-4818). I cannot see another check that retires the alias facts.
- flow_mutation.rs:4135-4144: `call_receiver_write_accesses` returns an empty list when there is neither a summary nor a receiver place. Cannot tell whether a caller treats empty as "no write".

## Surprises

- **No kernel anywhere, and no user diagnostics.** The slice never calls `proof_admission`, `ProofNode`, `verify_obligation` or a certificate type. The word "certificate" appears twice, in comments only (flow_mutation.rs:107, 4083). Every answer is an `Option` or `bool`. This fits property 1, with the qualification that this code mostly decides what to forget, and its default on failure is "unknown, forget everything".
- **Fact loss is the failure mode, by design.** Dozens of `?` exits lead to `None`, which the header says drops every active context (flow_mutation.rs:1-6). A program that hits any unhandled shape here (a custom index operator at 1436-1445, an operand chain 128 deep at 2076, a cyclic rebase at 1917) loses all facts at that point with no message naming the cause. Only trace flags print reasons (`CALLWRITE` at 4375-4459, `CHECKSITE` at flow_observations.rs:496-598).
- **Comment and code disagree on alias closure failure.** The comment says "An unresolved origin requires full invalidation" (flow_mutation.rs:4711-4714), but the assignment path uses `.unwrap_or(targets)` (4770-4778) and continues with the unclosed set.
- **Comment and code disagree on rendered paths.** `state_storage_writes` is described as working "without ... interpreting the frame's rendered report paths" (flow_mutation.rs:2541-2545), but the summary's cleanup rows are built by parsing path strings through `frame_write_place` (2801-2805).
- **Root lookup by name picks the first match.** `place_from_origin_path` checks parameters first, then takes the earliest local with that name before the statement (flow_mutation.rs:1994-2008). If a state can declare two locals with one name, or a local with a parameter's name, the wrong symbol is chosen. I cannot tell from this slice whether the language allows that.
- **The same `"[*]"` suffix has two meanings.** `frame_write_place` strips it and keeps the whole collection place (1975-1980); `place_from_origin_path` turns it into `FixedRange { 0, usize::MAX }` (2023-2028). The comment at 1963-1968 says this is deliberate.
- **Machine-rooted summary writes can never be instantiated.** Export rules treat a write rooted at the machine symbol as exported (flow_mutation.rs:2956, 3274) and the receiver query treats it as "reached through receiver" (2678-2679), but `instantiate_call_relative_writes_pre_resolved` only matches roots that are target parameter symbols and otherwise returns `None` (3552-3565, 3664). Such a write forces the caller to "unknown" or to the whole-receiver fallback. This looks like a leftover from an earlier design where the machine symbol was the receiver root.
- **Unreachable match arm.** `AssignmentWriteTarget::LocalBindingReplacement` returns early at flow_mutation.rs:1465-1470 and is matched again at 1514-1516.
- **A pass-through wrapper.** `canonical_receiver_place_for_call_site` only forwards to `receiver_place_for_call_site` (flow_mutation.rs:2166-2181).
- **Summary cache depends on who asks first.** The `OnceLock` is filled with the `call_frames` of the first caller (flow_mutation.rs:2706-2708), and one caller always passes `None` (2661). `complete` requires a resolver (2741-2747). Whether `shared_call_frames_or` always builds one is outside the slice; if it can return `None`, every summary would be incomplete for the whole compilation.
- **Parallel fixpoint inside the checker.** rayon `par_iter` over states and calls (flow_mutation.rs:2718-2759, 2836-2927). Results are collected in index order and each round reads the previous round's state, so the outcome looks deterministic.
- **`seen_writes` doubles as a flag.** For a call with no body summary it is set to 1 to mean "ceiling already added" (flow_mutation.rs:3009-3037); for summarized calls it is a count.
- **`UnresolvedContent` contains nothing, not even itself.** `same_storage_space` has no arm for it (flow_mutation.rs:2369-2379), so `contains` is always false for it.
- **Write-only range normalization does not peel constraints.** `normalize_write_only_range_place` matches a direct `Reference { access: WriteOnly }` node (flow_mutation.rs:4840-4847), while `is_exclusive_reference` peels `Constrained` wrappers first (438-446). A constrained write-only reference is not normalized.
- **x86 descriptor-table instructions are known to flow analysis.** SGDT/LGDT are modeled as calls with a ten-byte write (flow_mutation.rs:4158-4188, 4890-4932).
- **`call_write_accesses` panics on `None`** with "access-route projection always retains the ownership fallback" (flow_mutation.rs:4105). Reading `call_write_places`, every access-route path does return `Some`, so the invariant holds in this file.
- **Map and set use.** A `HashSet<CanonicalPlace>` (flow_mutation.rs:1307) and a `BTreeMap` keyed by operand identity (flow_operand_contexts.rs:39) appear in code whose project rules prefer dense tables; the second has a comment defending it (35-38).
- **Key comment overstates the key.** The selection cache comment says the key retains "the operand/type pair" (flow_operand_contexts.rs:11-14), but the key holds only a `stable_copy` flag derived from the type (44-51, 171-181). The selection depends on the type only through that flag, so behaviour is consistent.
- **Inconsistent failure handling in copy lookup.** In `completed_copy_read_place`, a copy whose expression has no place aborts the whole query (flow_observations.rs:1421), while other mismatches skip that copy (1418-1431); `copied_payload_at` skips in both cases (1368).
- **Linear scan of every operand in the program** for each `call_return_before_statement_agrees` query on an expression call (flow_operand_contexts.rs:894-904).
- **The order of 35 gates is treated as part of the contract.** "Keep every correspondence gate in its original evaluation order" (flow_observations.rs:242-246). The gates are a hand-written chain of occurrence, loan and type checks that together stand in for "this read is of the value that reference formation produced".
