## What this code is for

This is the second half of the old checker's "machine calls" file. It holds eleven modules that all answer questions about calls between machines.

`denotational_calls` (4217-5506) decides whether a call may appear inside a specification (a `requires`/`ensures` fact, a measure, a proposition, a ranking expression): the called machine and everything it reaches must have no effects, no service reach, no hidden state, no crash route, and must terminate. `effects` (5508-5984) checks that a machine's published `suspends`, `blocks` and service-reach declarations cover what its body does, that inline-assembly intrinsics have the authority the build grants, and warns about discarded pure calls. `fact_call_projections` (5986-6490) admits `call(...).field` inside a fact only for one narrow shape. `fact_only_citations` (6492-6988) decides when a runtime statement that calls a proof machine can be erased as a theorem citation. `invocations` (7065-7352) checks `invokes` ceilings. `machine_data` (7354-7442) checks machine-owned data declarations. `result_overloads` (7460-9175) is not a check at all: it picks which overload a named call means, using the expected result type, and rewrites the typed tree in place; it also rewrites numeric casts into calls to float-conversion requirements. `static_machine_call_contracts` (9177-9494) builds byte fingerprints of generic machines' reach and call bindings. `terminal_transitions` (9496-9678) rewrites a transition that names a callable into a transition that returns a call expression. `graph_components` (6990-7063) is a strongly-connected-components helper.

Nothing in this slice calls the proof kernel. A search of the range for `proof_admission`, `ProofNode`, `verify_obligation` and `certificate` finds nothing. Every yes/no is computed from flags, declared contracts, and the two inferred plans `flow_effects::OperationalPlan` and `flow_effects::ServiceReachInferencePlan`. The only obligation handed to anything else is the `formation_obligations: &mut Vec<checked_trees::IntegerRangeObligation>` that `validate_owned_data` passes through to `validate_type_reference_handle` (7373, 7391).

## Mechanisms

- **Call-graph closure walks.** Three worklists over `operational.calls` with a `Vec` visited list: `primitive_value_closure` (4317-4386), `each_reachable_checked_machine` (4994-5017, taking a per-machine predicate), and the tail of `has_pure_effect_closure` (5263-5273). No budget; termination comes from the visited list. `visited.contains` is a linear scan, so each walk is quadratic in the closure size. They serve specification calls, fact projections and theorem citations.
- **Requirement fan-out with a path guard.** `has_observation_free_closure` (5027-5157) recurses from a bodiless requirement into every machine that satisfies it, carrying `requirements_in_flight`; meeting a machine already on the path returns false (5033-5035). So a cyclic requirement chain is refused rather than assumed.
- **Requirement-satisfier index.** `RequirementSatisfierIndex` (4463-4519) builds sorted `(requirement symbol, machine position)` rows once and answers with two `partition_point` binary searches. It is cached on the frozen program (4525-4531), with a linear scan when no cache exists (4536-4555).
- **Candidate memo.** `checked_value_call_candidate` stores results per `(machine, state)` behind a mutex on the frozen program (4886-4904). If the lock fails it recomputes.
- **Depth-capped expression recursion.** `closed_expression` refuses at depth 128 (4397).
- **Strongly connected components.** Kosaraju's two-pass algorithm, written recursively with no depth bound (6991-7049); `component_ids` maps node to component (7051-7062).
- **Set-inclusion ceilings.** Service reach (5582-5587) and synchronous invocations (7291-7311) both compute "inferred minus declared" and report each missing element. The conformance version renumbers parameter indices when the machine forwards the boundary as parameter 0 (7239-7266).
- **Result-directed overload resolution.** `MachineOverloadIndex` groups machines by interned `(CallablePathId, CallableParametersId)` (7488-7528). `collect_expected_expression_calls` (8684-8808) and `push_expected_call` (8824-8890) push an expected type down from a typed position through `match` arms, borrows, atomics and array literals to the call. `select_overload_symbol` (8528-8570) compares the interned result-dispatch identity of each overload with the one requested. Serves named calls whose overloads differ only in result type.
- **Template-then-copy selection.** `SpecializationSelections` (8083-8153) makes generic templates choose first and records the choice by authored-occurrence ordinal; a specialization copy reuses it (`inherit`, 8124-8136) and selects for itself only when the template recorded nothing. Both the expression pass (`for copies in [false, true]`, 7734) and the statement and transition passes (`templates_then_copies`, 8103-8113) follow this order.
- **One-level proposition substitution.** `substituted_projection_requests` (6086-6147) pairs a transparent boolean proposition's parameters with the application's arguments and reports each `parameter.field` in the body whose argument is a call. It does not follow nested proposition applications.
- **Tree rewriting.** Three passes mutate `TypedTrees`: `resolve_named_result_overloads` (7704-8009) overwrites `target_symbol` on calls and transition targets, fills `registration_operation`, and turns statement calls to operators into expression statements or generated locals; `bind_float_conversion_casts` (8934-9011) replaces a cast's operand with a new call node; `normalize_terminal_transition_calls` (9505-9677) replaces a named transition target with `TransitionTargetNode::Value(call)`.
- **Canonical byte fingerprints.** `static_machine_template_reach_contract_bytes` (9184-9314), `static_machine_parameter_contract_bytes` (9316-9394) and `static_machine_call_binding_bytes` (9408-9493) emit a versioned tag (`omega.static-machine-reach-dependency.v1\0`, `omega.static-machine-operational-contracts.v1\0`, `omega.static-machine-capture-reach.v1\0`, `omega.static-machine-call-bindings.v2\0`), then length-prefixed, sorted, de-duplicated records. A declaration is encoded as a package digest plus its `::`-joined display path (9396-9406).

## Repetition by placement or construct

## Identity by text

- An operator's meaning as a float projection is found from its two path members as strings: `FloatProjectionOperation::from_source_identity(namespace.as_str(), name.as_str())` (5488-5491).
- An asm intrinsic's instruction comes from the builtin function's name (`asm_intrinsic_mnemonic(function.name())`, 5825-5826); its authority contract is looked up by that mnemonic string (`asm_catalog_entry(instruction)`, 5827-5828); its service is a `&'static str` name resolved by `AssemblyServices::resolve(program, machine.symbol, service_name)` (5757-5769).
- The projected record field is found by comparing name strings: `field.name.as_str() == member.member.as_str()` (6304).
- A conformance is matched to a trait requirement by name; when the conformance names none, by the last `::` segment of the machine's name: `machine.name.as_str().rsplit("::").next()` (7211-7227).
- `machine_specialization_matches_template_identity` takes `machine_identity: &str` and forwards it (7445-7457).
- Named-call families are found by a path string: `named_statement_call_family_path` / `named_expression_call_family_path` return a string passed on as `path: Option<&str>` (8231, 8307, 8375) into `named_call_family_members(program, path, source_span)` (8383, 8581); `named_machine_overload_family_symbol` takes `target_name: &str` (8574).
- Which overloads a call can see is decided from a source span: `source_reference_can_see_symbol(source_span, symbol)` (8187, 8210, 8462, 8508) and `source_reference_may_select_symbol` (9137). For statement calls the span passed is the enclosing machine's symbol span, not the call's (7786-7789).
- A struct literal's data definition is found by name when the symbol table has no source metadata: `definition.name.as_str() == literal.type_name.as_str()` (8695-8696). Its field type is found by case-name and field-name strings (8706-8707).
- The float-conversion operator is chosen by text: `format!("from_{}", source.name())` (9112); `owner.as_str() == destination_owner && member.as_str() == requirement_member` (9124-9125); destination owner is a literal from `"I8"` to `"F64"` (9158-9172); integer sources are recognised by `IntegerCarrier::from_spelling(source.name())` (9097-9098).
- Whether a cast was written by the author is decided by its source span being non-empty (9107-9110).
- A boundary operator is matched to a transition target by comparing path-member lists: `program.operator_path_members(operator.name) == members` (9568-9572).
- Fingerprints identify a declaration by `program.symbols.display_path(symbol, "::")` plus a package digest (9396-9406), and a trait requirement by `trait_requirement_callable_identity_text` (9339-9342).
- A generated local is named `__discarded_named_requirement#{}#{index}` (7982-7985).
- Diagnostic-only labels: `format!("{}::{}", trait, signature)` (7120), `parameter#{index}` and `service#{}` (7322, 7328), `<unknown canonical service>` (5598, 5625), `<none>` (5616), `<empty>` (8556).
- Two hash maps key on `arena_index()` alone, dropping the handle generation: `entry_to_group: HashMap<u32, usize>` (7484, 7519-7521, 8432-8434, 8451-8454) and the expression-owner map (7621, 7693-7696). `SpecializationSelections::copies` is a vector indexed by arena index (8090-8094, 8115-8122).

Against property 2: most decisions here use `SymbolHandle` equality, symbol kinds (4831, 6673, 9536-9562) and interned ids (`CallableIdentityId`, `CallablePathId`, `CallableParametersId`). The satisfier index keys on arena index and generation together (4467-4469).

## Surprises

1. **A third of this "validation" file rewrites the program.** `resolve_named_result_overloads` takes `&mut TypedTrees` (7704-7706). Before selecting anything it prepares static type contexts, calls `elide_unreachable_case_arms` and `retain_proven_type_contexts` (7707-7723). It then overwrites call targets (7854-7864, 7888-7889), replaces statement calls with expression statements (7973-7976) or with a generated immutable local named `__discarded_named_requirement#..` (7978-8004), and returns the list of changed owners (8006-8008). `bind_float_conversion_casts` (8934) and `normalize_terminal_transition_calls` (9505) also mutate. Name resolution, desugaring and checking live in one crate.

2. **The statement rewrite drops fields.** When a statement call to an operator is rebuilt as an expression call, `static_requirement_dispatch`, `quotient_operation`, `authored_call_binding` and others are set to `None` or default (7943-7964) regardless of what the statement held. Statement calls do carry `static_requirement_dispatch` (read at 6830, 6878). Cannot tell whether a statement call to an operator can have it set.

3. **Ambiguous result overloads are kept silently.** `select_overload_symbol` reports an error for zero matches but returns `None` for two or more (8552-8569), which leaves whatever target the earlier stage guessed.

4. **Statement calls never get an expected result.** The statement pass passes `None` (7790), so a statement call always requests the empty result set; the expression pass looks one up (7753).

5. **The statement and expression selectors disagree.** For a provisional boundary operator, the statement version returns the provisional symbol when there is one overload and otherwise calls `select_overload_symbol` directly (8248-8271). The expression version calls `selected_named_callable_symbol` (8324-8337), which first consults the machine overload group (8451-8474). The same call written as a statement or inside an expression follows different code.

6. **Calls nested in most expressions get no expected type.** `push_expected_call` lists `Binary`, `Cast`, `Unary`, `Member`, `Indexed`, `Range`, `StructLiteral` and others as "do nothing" (8873-8888). A result-overloaded call inside `f() + 1` is resolved against the empty result set. When one call is reached from two positions, the later expectation overwrites the earlier (8851-8856).

7. **The projection gate and the projection validator traverse differently.** See 6035-6041 and 6466-6474 under "Accepts or skips". The gate exists to save work, but it prunes subtrees the validator would enter.

8. **The projection validator covers fewer roots than the specification-call validator.** It reads `program_proof_facts` and transparent propositions (6008-6029). The other reads `program_scoped_proof_facts`, mathematical-application nodes, ranking custody and measures as well (4584-4641). A `call(...).field` in a measure body or a ranking expression is not looked at by `validate_fact_call_projections`.

9. **Abstract-signature projections fall through.** 6249-6268 deliberately accepts an abstract signature in place of a concrete target and uses its return type for all the shape checks, then 6315 discards the result. Either the abstract path is unfinished or the row type cannot express it; the code does not say.

10. **The asm authority check sees two statement shapes only** (5807-5818). This is the check that keeps privileged instructions out of hosted programs.

11. **The reach containment for asm services is a debug assertion** (5790-5794), and the loop around it does nothing else (5784-5795).

12. **Fingerprints cannot tell apart two declarations with the same path.** `encode_declaration` writes only the package digest and the `::` display path (9396-9406). The same file's `result_overloads` module exists because several callables share one path and differ in parameters or result. `static_machine_call_binding_bytes` encodes the selected entry this way (9489), so two bindings that select different overloads of one name produce the same bytes. The parameter-contract fingerprint adds `trait_requirement_callable_identity_text` (9339-9342); the call-binding one does not.

13. **Two maps ignore handle generation** (7484, 7621), and `provisional_target_is_named_non_operator_callable` looks up `target.arena_index()` without first testing `target.is_valid()` (8432-8434). Whether an invalid handle's index can collide with a real entry depends on the handle encoding, which is outside this slice.

14. **Float-cast binding walks machine statements only** (9018-9035). Casts in contracts, constant initializers and owned-data initializers are not bound, while `expression_owners` in the same module does walk contracts and constants (7636-7654, 7664-7683).

15. **`has_no_crash_routes` requires family members to *publish* a crash ceiling** (5370-5376). Read literally, a family member with no published ceiling makes the closure "have a crash route". The members are separately visited for `machine_declares_crash` because `push_checked_machine_call_targets` queues them (5286-5291). The intent seems to be "an unpublished ceiling is unknown, so refuse", but no comment says so.

16. **Refusal is the default in the denotational code.** `closed_expression` ends in `_ => false` (4454); a missing or duplicate summary returns false (5231-5233, 5253-5255, 5297-5299); a requirement with no satisfier returns false (5047-5055); a missing frame resolver makes every borrow fail (5107-5110). This part does not show the "lookup fails, so accept" pattern. The skips listed above are mostly in the callers that decide which calls reach these tests.

17. **Whole-program inference can run per call.** `has_checked_effect_and_termination_closure` recomputes `infer_operational_may` and `infer_service_reaches` for the entire program on each call when no prepared plans exist (6538-6539). It is called per theorem, per cited callee and per static machine argument. `read_only_parameter` builds a new `CallFrameResolver` per parameter (6630), and `proof_only_classification(program)` is called again at 6593, 6641 and 6959.

18. **Acceptance of a theorem citation is syntactic.** `work_free_argument` and `place_spelling` (6946-6987) accept an argument because it is spelled as a name, a member chain, a literal or a shared borrow of those. The function name says "spelling".

19. **`InitialValueOwner` is an enum with one variant** (7410-7415) and a `Display` impl for it (7417-7425): the remains of a per-placement owner type.

20. **Unbounded recursion.** The SCC helper recurses once per node on a chain (6992-7020). `record_expression_owner` (7687-7702), `collect_expression_bindings` (9039-9073), `push_expected_call` (8824-8890) and `append_substituted_projection_requests` (6115-6147) recurse with no depth cap, while `closed_expression` in the same file caps at 128.
