## What this code is for

This file is `RangeFacts`, the fact store the old range check (index and slice bounds check) carried through the statements of one state (crf:1-18, struct at crf:4971-5054). It holds collection lengths, known integer values, Boolean guard locals, and nine kinds of proven relation: valid index, exclusive upper bound, below a const binder, non-negative, ordering, range bound, minimum length, exact length, and subslice window parent. Almost every relation is a `Vec` of tuples of `String` labels, where a label is the rendered text of an expression (crf:4987-5042).

The file does not decide whether an index access is in bounds and emits no diagnostics. Its callers (`ranges::check_indexed_accesses`, `state_arguments`, crf:8-9) insert facts with `prove_*` and query them with `*_is_proven`. What this file itself decides is (a) which facts survive an assignment or a call, (b) which facts may be copied to another name or another spelling of the same storage, and (c) which storage places an expression reads.

About 3,150 of the 5,101 lines (the `dependencies` module, crf:540-3700) are a second, typed layer built beside the label tables. It computes, for each recorded expression, the set of canonical storage places (`CanonicalPlace`: a root symbol plus field/index segments) that the expression reads. A write is then compared with those places to decide which string labels are "preserved" and which are "affected". The authors call the labels "the range checker's legacy expression labels" (crf:542).

Other parts: `call_writes` (crf:26-456) joins the range check to the already-checked call, borrow and flow facts of the state; `closed_arrivals` (crf:457-538) records comparisons between two integer literals so an unreachable branch can discharge bounds; `invalidation` (crf:3701-4110) retires facts after writes; `proofs` (crf:4111-4805) is the insert/query API of the relation tables; `values` (crf:4806-4968) is the insert/query API of the value rosters.

## Mechanisms

- **Read-set walk (`ReadWalk::collect_reads`, crf:2141-2337 with helpers crf:1199-2095).** Computes the set of canonical storage places an expression reads, and whether that set is complete. It recurses over the expression tree with a depth bound of 128 (crf:2631). It returns "incomplete" for anything it cannot account for. It serves fact preservation across writes. An incomplete walk keeps the walked prefix in `reads` (crf:2766).
- **Label preservation (`preserved_expression_labels`, crf:3531-3603).** Given the places a statement writes, returns the labels whose every row has a complete read set disjoint from every write. Element writes do not expire a descriptor read (crf:3567-3573). Preceded by a label-collision pass (crf:3456-3529) that groups all rows by label in a `BTreeMap` and discards labels whose rows disagree.
- **Two-level invalidation (`invalidate_relational_bounds`, crf:4024-4046).** Takes two predicates: `overlaps` for value-level rows and `covers` for descriptor rows. A write below a collection retires element facts but keeps the collection's extent (crf:4018-4023).
- **Ordering closure (`close_ordering_bounds`, crf:4457-4463).** Forward-chains ordering facts into index and range-bound pairs until a fixpoint, inside `validation::propagate_integer_upper_bounds`. Runs after every `prove_index`, `prove_range_bound` and ordering insert. The comment says eager minting is needed so the derived pair can ride "the parameter-position transport across a state edge" (crf:4450-4455). The query-time chains (crf:4494-4578) are one hop only.
- **Captured-selector interval hull (crf:174-291).** For one indexed operation, collects every capture row, obtains an integer interval per selector from `CapturedIntegerIntervals`, and takes the hull (crf:282-288).
- **State transport (crf:2369-2612).** Rewrites a predecessor state's read set into the receiving state: roots through a parameter map, index selectors by searching the whole expression table for the first structurally corresponding expression (crf:2391-2399).
- **Alias fan-out (crf:618-829, 975-1151).** When a value is bound to a local, the code iterates every expression in the program (`iter_expressions()`, crf:676, 1043), finds those whose canonical place equals the source place under the new binding, and copies the source's facts onto each such expression's label, adding a dependency row for each. This exists because facts are keyed by text: a fact cannot follow the value, so it is copied to every spelling in advance.
- **Frozen integer identity (crf:837-875).** Follows a chain of immutable local copies (up to 128 hops) to one value symbol. Used to equate selectors and to re-root a read at the original value (crf:2073-2090).
- **Window overlap (crf:4786-4803).** One hop from child to parent label, then constant interval disjointness.
- **Closed literal comparison (crf:470-536).** Stores selected literal-versus-literal comparisons and asks the scoped integer engine whether they are jointly unsatisfiable.

- **Selector alias versus place alias.** `alias_captured_selector` (crf:618-829) and `alias_place_facts` (crf:975-1151) are the same loop: scan all expressions, compare places, walk reads, test root currency, then `prove_window_parent` / `alias_collection` / `alias_index`, then push a dependency row. - **Retirement test written three times** inside `retire_captured_observations`: measured results (crf:3231-3242), binding value (crf:3244-3258), binding length (crf:3262-3275).

## Identity by text

- Every relation table is keyed by `String` labels: `proven_indexes: Vec<(String, String)>`, `proven_index_upper_bounds`, `below_const_binders` (index side), `proven_non_negatives`, `proven_orderings`, `proven_range_bounds`, `minimum_lengths`, `exact_lengths`, `window_parents` (crf:4987-5042). All queries compare strings (for example crf:4314-4320, 4426-4428, 4478-4482, 4643-4649, 4676-4682).
- Labels are produced by `expression_table.display_name(expression)`: crf:610, 675, 807, 1130, 1131, 3422, 3676, 3750, 3842.
- `ExpressionDependencies.label`, `ScalarBindingDependency.label`, `ReceiverLength.label` are strings (crf:2636, 2654, 2716). The typed read sets are attached to labels, and the answer handed back to invalidation is a `Vec<String>` of preserved labels (crf:3537, 3602).
- `expression_is_disjoint_from_writes` answers by checking whether the preserved list contains the expression's rendered text (crf:3675-3676).
- `write_affects_bound` decides by string: splits the label on `.`, tests characters for alphanumeric or `_`, compares path strings with `frame_paths_overlap`, strips the data-binding name as a prefix with `place_field`, and tests `name.contains('.')` (crf:4098-4109).
- `descriptor_covered` turns a dotted label back into a place with `flow::place_from_origin_path(program, state, statement_index, label)` when no symbol is supplied (crf:4064-4068).
- `roster_lookup` falls back from symbol to name (crf:4816-4834); `value_fact_matches` matches on symbol or name (crf:4960-4967). All four value rosters carry a name string beside the symbol (crf:4983-4986, 5043-5047).
- `atomic_local_name_symbol` falls back to finding the nearest earlier local whose `name` equals the member text, because the desugar's generated result names "never carry resolved symbols" (crf:1357-1362, 1380-1396).
- `temporary_member_symbol_at` resolves a member by `member.member.as_str()` on the type's symbol (crf:1537-1541).
- `record_scalar_binding_dependency` requires `local.name.as_str() == label` (crf:3049).
- `windows_may_overlap` decides "distinct bases never overlap" by label inequality (crf:4787-4795).
- `alias_collection` / `alias_index` return early when `original == alias` as strings (crf:4124, 4163).
- `assign_local(symbol, name, ..)` forgets collection facts by the name string (crf:4897-4899); `forget_collection_expression(label)` removes rows by label (crf:2793-2796).
- `invalidate_call_writes` receives the call's writes as `paths: Option<&[String]>` (crf:3859) and compares them with labels (crf:3923-3930).
- Counter-evidence: const binders are keyed by symbol on purpose ("The binder's symbol, not its spelling, is the identity: a same-named local is not an extent", crf:4255-4257, 4989-4993). Read sets, scalar binding places, call identity and operator identity are all typed handles. `find_call` uses pointer equality of tree nodes, not text (crf:350, 367).

## Accepts or skips without proof

- **Every `prove_*` is an unconditional insert** (crf:4232-4757). This file never checks that a fact holds; the caller's guard analysis is trusted. `seed_receiver_lengths` and `seed_storage_dependency` likewise install facts and read sets supplied by the incoming-edge caller (crf:2989-3030). Whether those callers check: outside the slice, cannot tell.
- `retain_closed_integer_arrival` trusts that "the caller established builtin comparison meaning and selected this exact arm" (crf:465-469). Cannot tell from here.
- `record_incoming_guard_dependencies` trusts that parameter bindings were "already proved label-stable by the incoming-edge analysis" (crf:3327-3331). Cannot tell.
- `roster_lookup` returns a value found by name when the symbol is not in the roster (crf:4830-4833). A fact recorded for a different same-named entity can be returned. No other check visible here.
- `record_dependencies` records nothing for names, integer literals and Boolean literals (crf:3368-3373). A fact keyed by a plain name therefore has no typed read set unless a scalar binding row exists (only integer locals bound at a declaration or assignment, crf:3042-3070). For such labels the decision is the string fallback. For an assignment, when there are no index upper-bound facts, `bound_frame` is not built (crf:3757) and the fallback compares the label only with the rendered assignment target (crf:3788). A write that reaches the same storage through a different spelling would not expire a name-keyed fact by this route. Whether the caller's own `assign_local` path or the borrow checker rules this out: cannot tell from this slice.
- `invalidate_assignment_bounds` returns early when there are no relational bounds, leaving `locals`, `integer_locals` and `integer_fields` untouched (crf:3727-3748). The caller presumably updates those through `assign_local` / `assign_field_integer`; not visible here.
- `invalidate_call_writes` returns at once when `paths` is an empty list, without consulting the structured call writes (crf:3862-3864). Trusts the caller's path list.
- `invalidate_call_writes` keeps a collection length that a write covers when the declared type is a fixed array (crf:3973-3985). This trusts the declared type; sound for fixed arrays.
- `mutable_byte_view_extent` saves a byte-slice parameter's lengths before invalidation and re-proves them after (crf:3816-3823). Trusts that an element write cannot change a slice's length.
- `preserved_scalar_binding_labels` preserves an owned integer local across a call without alias closure, on the reasoning "An owned integer slot has no referent" (crf:3605-3609).
- A dependency row with a complete but empty read set (literals only) is preserved across every known write (crf:3561-3576). Sound.
- `windows_may_overlap` returns false when base labels differ (crf:4793-4795). It follows only one parent hop, and bounds are offsets into the direct parent. A window of a window has its parent, not the root, as base, so it is reported as never overlapping a sibling of its parent. The only caller in this slice (`alias_collection`, crf:4128) is conservative on "false". Other callers are outside the slice: cannot tell.
- `prove_window_parent` on a known child replaces the parent but keeps the old constant bounds when the new bounds are unknown (`bounds.or(*known_bounds)`, crf:4752-4753). The old offsets were relative to the old parent. `forget_collection_facts` removes the row on reassignment (crf:4696-4697), which may cover the usual case: cannot tell.
- `range_bound_value_is_proven` returns true for bound 0 with no length fact (crf:4613-4615). Sound.
- `collect_reads` returns "complete" with no reads for literals, type expressions and zero values (crf:2208-2214), for a wildcard match pattern (crf:2321) and for an absent range endpoint (crf:2295-2297). Sound.
- In the call arm, the target state is looked up and bound to `_target_state` but not used (crf:2259-2265); only its existence is checked. The callee's own reads of machine storage are taken from the operand access rows alone (crf:2248-2253). Whether those rows include storage the callee reaches other than through operands: cannot tell.
- `static_application_carries_no_caller_storage` accepts an argument with an invalid symbol if it has a const literal (crf:1233-1235).
- The result-symbol closure in `collect_atomic_write_reads` always returns true (crf:1327-1334); the validity check happened earlier in `atomic_local_name_symbol`.
- `atomic_fetch_operand` and `atomic_compare_exchange_operands` assume the exact tree shape the parser's desugar builds and take operands by position, with no check of operators (crf:1407-1430). A differently shaped `value` with enough binary nodes would be read positionally.
- `transport_reads` substitutes the first corresponding expression found anywhere in the program (crf:2391-2399).
- `alias_captured_selector` and `alias_place_facts` scan every expression in the program, not only this state's, and register rows under this machine and state for any that match (crf:676, 1043). Machine-rooted places are shared by all states, so an expression in another state can receive a row. The row is only used through its label, so the effect is extra label entries.
- `record_dependencies` stops silently at depth 128 (crf:3363-3367): deeper subexpressions get no row. `collect_reads` at the same depth returns incomplete (crf:2201-2205), which is conservative.
- On the refusing side: unknown writes preserve nothing (crf:3538-3540); a write rooted at a field symbol preserves nothing (crf:3552-3557); incomplete read sets agree with nothing (crf:3685-3687); a label with rows of different meaning is not preserved (crf:3579-3581); labels that are not plain dotted identifiers are always expired by the string fallback (crf:4099-4104); calls clear all field integers (crf:3876, 3950) and all Boolean guards (crf:3824, 3877, 3988).

## Surprises

- **No proof kernel anywhere.** The slice has no call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type. The only "proof" import is `published::proof::contract_target_from_state_symbol` (crf:1191), a lookup. Bounds facts are tuples of strings in vectors; the two outside engines consulted are `validation::scoped_arithmetic_comparisons_unsatisfiable` (crf:535) and `validation::propagate_integer_upper_bounds` (crf:4458).
- **Three fact systems coexist in one store.** The label-keyed tables; the typed dependency rows built to police the labels; and the separate semantic `facts::FactPlan` plus flow operand captures, consulted for immutable integer values and captured selector intervals (crf:103-140, 174-291). The second exists only because of the first: about 60 percent of the file computes which strings a typed write leaves true.
- **A collision detector for the keys.** `label_collisions` (crf:3456-3529) exists because two different expressions can render to the same label. The code detects this per query and refuses to preserve such labels. It does not stop a fact proved for one meaning from being read under the same label by the other meaning while no write intervenes; that query path (`index_is_proven` and the rest) has no collision check.
- **Facts are pushed to every future spelling.** Binding a local triggers a scan of every expression in the program to pre-copy facts onto labels of expressions that will name the same storage later (crf:676, 1043). The cost is rows × all expressions per binding, and the scan is not limited to the current state.
- **`prove_exact_length` with a conflicting value deletes the fact and does not record the new one** (crf:4662-4671). The outcome depends on call order: asserting 3, then 4, then 4 leaves 4.
- **`prove_window_parent` keeps stale constant bounds after re-parenting** (crf:4752-4753), described above.
- **`windows_may_overlap` treats a window of a window as having a different base from its grandparent's other children** (crf:4791-4795), and answers "never overlap" for them. The comment says the function is conservative; for nested windows it is not.
- **Comment and code disagree in `validate_place_read`.** The comment says "Normalization runs before the current-root check so attached fields answer through the machine root" and speaks of "the pre-normalization root" (crf:2000-2005). The body performs no normalization and does not modify the `&mut` place (crf:2006-2031).
- **`captured_length_collection` does not filter by machine and state and does not require an empty segment list** (crf:3149-3153), while the sibling lookups do (crf:3165-3167, 1169-1172).
- **Mixed statement index across states.** For an incoming guard, `record_dependencies` walks reads in the evaluating (predecessor) state using the receiving walk's `self.statement_index` (crf:3386-3393), and `StateTransport` resolves places in both states with that one index (crf:2519). Root currency for the predecessor state is therefore judged against a statement prefix measured in the other state.
- **Atomic operands are recovered from the algebraic shape of a desugared model expression**, `prior + (prior == expected) * (replacement - prior)`, by tree position (crf:1416-1430).
- **Alias bookkeeping order differs** between the two near-identical alias routines (crf:808-810 versus 1132-1134).
- **`integer_locals.retain` in `invalidate_call_writes` calls `program.symbols.get(*symbol)` on roster symbols** (crf:3951-3958), while `assign_local` can push roster entries with whatever symbol the caller passed and an empty name (`name.unwrap_or_default()`, crf:4900). An empty-name entry would match any later lookup with `name == Some("")`.
- **`at_most_is_proven` ignores the strict flag** (crf:4478-4482); this is intended (strict is stronger), but the comments at crf:4486-4487 and 4565 still describe `at_most` as "seeded from `<`" guards, predating the flag.
- **The file ends with a comment that introduces something not present**: "Count derived snapshots without changing production fact storage..." (crf:5098-5101) is the last text in the file; the item it describes is not in this file.
- **Evidence on the three properties.** Property 1 (own yes/no, no kernel): confirmed for this slice. Property 2 (identity by text): strongly confirmed for the fact tables, with the qualification that the authors had already built a typed place layer and deliberately used symbols for const binders. Property 3 (rule rewritten per placement): weak here. The repetition is per relation table and per write kind; storage placements are handled uniformly by `CanonicalPlace`.
