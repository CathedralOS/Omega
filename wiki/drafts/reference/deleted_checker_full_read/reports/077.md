## What this code is for
This file turns the "mathematical" part of an Omega program into terms of the proof kernel (`proof_admission`): authored mathematical declarations, `core::Identity` applications, propositions written as source expressions, indexed data families encoded as W-types, and the evidence values that programs pass around (md.rs:1-8). The first module only builds printable records of each declaration, with types and bodies stored as strings (md.rs:25-74). The rest is methods on one `Elaborator` that walks source expressions and type references and emits kernel `Term`s into an arena plus a growing list of kernel `Declaration`s. Source scalars are mapped to a handful of kernel "carriers": one shared integer type, an address type, two float types and a unit type (all kernel assumptions), and booleans as the kernel `Two` (md.rs:1201-1245). Comparison, arithmetic and negation become uninterpreted kernel constants (md.rs:1247-1310), and any source expression the elaborator cannot translate becomes an opaque assumed constant applied to the variables it mentions (`open_term`, md.rs:3077-3294). Every application the elaborator builds is recorded and later checked by the kernel for domain agreement (`check_source_domains`, md.rs:4305-4397). For machines that take one erased evidence value of an indexed family, the code builds an induction theorem for each `ensures` clause, kernel-checks it, and refuses it if it depends on an assumption outside an audited list (md.rs:4942-5306, 5310-5398). The tail of the slice closes generated theorems over outer type parameters (md.rs:5586-6046) and starts building constructor schemas (md.rs:6171-6357).

## Mechanisms
- **Capture worklist for source applications** (md.rs:330-471). For each call to an authored mathematical declaration or `core::Identity` outside a mathematical body, a stack walks the argument tree. An operand with a source type becomes a captured kernel variable holding the whole evaluated value (comment md.rs:423-425); an operand without one is split into its children. An operand whose type is a known indexed family goes to `source_family_constructor` instead (md.rs:433-442). The visited set is a `Vec` searched linearly (md.rs:406-413). No budget.
- **Universe level inference** (md.rs:533-617). Level binders the caller omitted are filled from the kernel sort of the first argument whose binder names that level; each unconstrained `Type` binder adds one "generalized" level. Budget: `DEFAULT_CONVERSION_STEPS`, one budget shared by the inferences of one call (md.rs:585).
- **Interning of kernel assumptions** (macro md.rs:286-300; md.rs:1201-1383). Carriers, relations, operations and literals are each pushed once into the declaration list and reused by position. Without an integer theory each integer literal is a separate assumed constant of its carrier (md.rs:1363-1367); with one, the theory supplies the literal (md.rs:1345-1362). Float literals are interned per (carrier, bit pattern) (md.rs:2976-2978).
- **Source aliases** (md.rs:4263-4303). Each distinct scalar source type (for example `u8` or a policy-qualified integer) gets a transparent kernel definition whose body is the shared carrier. Conversion is run with those definitions held opaque (`retain` closures at md.rs:4412-4417 and 4460-4465), so two fixed-width types that share the integer carrier do not convert to each other. Alias reuse is decided by `source_references_correspond` (md.rs:4484-4516).
- **Deferred domain check** (md.rs:4012-4037 and 4239-4252 record; 4305-4397 check). Every application spine and every expected-result pair is recorded with its scope domains and level arity. Later the kernel infers the callee type, reduces it to a `Pi`, compares each argument's domain, then substitutes the argument into the codomain. Budget `DEFAULT_CONVERSION_STEPS` per invocation (md.rs:4317).
- **Opaque operation abstraction** (`open_term`, md.rs:3077-3294). For an untranslatable expression it collects the scope positions the expression and its result type mention (`free_positions`, md.rs:1451-1524), closes that set under the positions each domain mentions (md.rs:3168-3178), rebinds the domains over only the retained positions (`rebind_domain`, md.rs:1526-1551, which substitutes `Term::Dummy` for dropped variables), and pushes an assumption of that `Pi` type. An existing assumption is reused when owner, source type and bindings match and `source_operations_have_same_meaning` says yes (md.rs:3232-3248).
- **Identity requirement transport** (md.rs:1697-2183). Each `Identity` formed inside a declaration is stored as a lambda over the declaration's scope (md.rs:1705-1711). A call instantiates it with the call's levels and operands (md.rs:2066-2084). A function formal that is applied stores an "application" closure until an actual supplies its emissions (md.rs:1793-1812, 1966-1979). Pending source parameters are tracked per declaration so partial applications work (md.rs:2131-2151).
- **Full normalization** (md.rs:2715-2804). Calls the kernel's weak-head normalizer, then recurses into every child; shares the caller's budget.
- **Proposition encoding** (md.rs:3344-3712). `and` flattens to a spine, sorts operands by `term_order_key` (md.rs:3637), and becomes right-nested `Sigma` (md.rs:3659-3671); `or` becomes `Sigma` over `Two` with `CaseTwo` (md.rs:3673-3697); `==` becomes `Id` with operands ordered by `term_order_key` (md.rs:3477-3481); `<` and `<=` use assumed integer relations, with `>` and `>=` rewritten by swapping operands (md.rs:3520-3525); a boolean subject becomes `Id Bool subject true` (md.rs:3403-3411).
- **Induction theorem per `ensures`** (md.rs:4942-5306). For a machine whose entry state has exactly one erased parameter of an indexed family and a unit result, it builds an invariant as a lambda over the family's index (projecting indices with `Fst`/`Snd`, md.rs:5222-5234), calls `source_family_induction`, abstracts outer type parameters, kernel-checks, and stores the assumption closure.
- **Parameter closure** (md.rs:5866-5960). Walks the declarations the theorem reaches, copies each definition that depends on a parameter as a parameterized definition (once, cached in `ParameterAbstractions`, md.rs:5599-5613), rewrites references, then shows by a reachability walk (`excludes_parameters`, md.rs:5818-5861) that no parameter assumption remains. Visited sets are bitsets indexed by arena slot.
- **Evidence alias propagation** (md.rs:5402-5520). A fixpoint, capped at 128 rounds (md.rs:5418), that copies evidence or a constructor schema from an immutable erased local's initializer to each later `Name` expression that reads the local in the same state.

## Identity by text
- Declaration records store types and bodies as strings: `type_spelling`, `term_spelling`, `result`, and the universe as `normalized_type_identity_text` (md.rs:52-62, 160, 191-237). `mathematical_type_identity` builds the identity of a function type by formatting `"({binder}: {domain}) -> {codomain}"` and of an application by joining rendered arguments with `", "` (md.rs:215-234). The binder name is part of that string.
- `FixedCoreVocabulary::classify(symbol, name)` takes a name beside the symbol (md.rs:142, 154, 740, 2482, 2616, 2651). `static_term` joins a path with `"::"` to feed it, with the comment "The fixed vocabulary's unresolved fallback expects the full qualified spelling. A resolved symbol remains authoritative." (md.rs:728-737). With an invalid symbol, the name alone selects `core::Type`, `core::Level` and the rest (md.rs:2651-2655).
- A universe level literal is recognized by parsing the name text of an unresolved type reference as a number: `name.as_str().parse::<u64>()` (md.rs:2365).
- Level binders are found by name when the symbol is invalid (`level_names`, md.rs:2702-2705; used at md.rs:701-704).
- Scope entries are found by name when the symbol is invalid: md.rs:491, 775-778, 1059-1062, 2657-2658, 3152-3158, 3794-3797. Arrow binders are pushed with `symbol: None` and only a name (md.rs:2415-2419).
- Field lookup for a member access without a member symbol compares field names (md.rs:1033, 1040).
- `LandedIntegerType::from_name(primitive.name())` selects the expected landed type from the primitive's name (md.rs:812).
- Not by text: declarations, carriers, scope symbols, aliases and families are keyed by `SymbolHandle`, `TypeReferenceHandle`, `TypeIdentityId` or declaration position throughout (for example md.rs:1083, 2595, 3232-3248, 4280-4284, 5362-5367).

## Accepts or skips without proof
- `operand_carrier` is a syntactic guess: any non-arithmetic binary operator is `Boolean` (md.rs:954); arithmetic with one unknown side takes the other side's carrier unchecked (md.rs:941); `BitwiseNot` is always `Integer` (md.rs:958); any primitive other than bool/addr/f32/f64 is `Integer` (md.rs:1109). The later kernel domain check (md.rs:4305-4397) covers applications; whether it covers every proposition built from these carriers I cannot tell.
- `scalar_operand_term` builds an integer literal in whatever carrier the caller passed, without looking at the literal's landing (md.rs:2840-2849); the boolean and float arms do check (md.rs:2851, 2959). Through `interned_literal!` this pushes an assumed inhabitant of that carrier (md.rs:1363-1367). It trusts source typing. Use inside a theorem would be caught by the roster check (md.rs:5319-5327); elsewhere I cannot tell.
- Closed integer arithmetic is folded by `program.closed_integer_expression_value` and entered as a literal (md.rs:942-950, 3019-3024). The kernel does not see the arithmetic.
- Anything untranslatable becomes an assumed opaque constant (`open_term`, md.rs:3268): non-exact fixed-width arithmetic (md.rs:3025-3036), multiplication without an integer-multiply constant and all other operators (md.rs:3042-3045), operators without the builtin meaning (md.rs:3047-3055), non-builtin `==` and non-integer order comparisons as `opaque == true` (md.rs:3469-3474, 3504-3517). These assume a value of a type, not a proof of a proposition, so the fact stays unprovable rather than becoming proved.
- Two different source expressions share one opaque constant when `source_operations_have_same_meaning` says so (md.rs:3241-3247). That equality is another module's judgment; the kernel then treats them as identical.
- `source_domains_correspond` returns `validation::checked_argument_matches_type_reference` instead of kernel conversion for anonymous numeric results (md.rs:4436-4446).
- Assumed kernel vocabulary, whose meaning comes only from whatever `integer_theory` supplies outside this slice: negation as a constant `Type 0 -> Type 0` (md.rs:1275-1283, 3432-3439); `<`, `<=`, `+`, `-` (md.rs:1247-1310); the `addr` bound as an assumed integer (md.rs:3729-3741); each integer embedding as an assumed function (md.rs:3310-3319); float relations (md.rs:3586-3593).
- Assumed types: integer, address, f32, f64 and unit carriers (md.rs:1201-1245, 1330-1333); every data or builtin type not otherwise known becomes a fresh assumed `Type 0` (md.rs:3897); a lifetime-only generic data type likewise (md.rs:2598); a type parameter becomes an assumed `Type u` (md.rs:3861-3867). Boolean is the exception: a definition whose body is the kernel `Two` (md.rs:1208-1217).
- `elaborate_proposition_term` returns `Ok(None)` for other binary operators (md.rs:3391) and `subject_proposition` returns `Ok(None)` for non-boolean subjects (md.rs:3413). Connectives refuse a `None` operand (md.rs:3627) and constructor premises refuse (md.rs:6300-6305), but the `ensures` theorem loop silently skips the clause (md.rs:5213-5215). Whether a consumer refuses when the theorem is missing I cannot tell from this slice.
- `retain_indexed_contract_theorems` skips a machine with `continue`, and no diagnostic, when: it has no states, not exactly one erased family parameter, no unit result, the evidence type is not generic, a binder is not Type or Value, the telescope is longer than the index list, or the index mapping is not one-to-one (md.rs:4953-4993, 5126-5128, 5184-5195). I cannot tell whether another check then refuses.
- `retain_source_evidence_carriers` skips machines with other binder kinds (md.rs:4724-4731) and skips non-erased references that contain runtime types (md.rs:4785-4798, with a comment). A missing carrier later yields "source evidence has no independently formed closed source carrier" (md.rs:5370-5373) for evidence rows.
- `retain_checked_source_application` returns `Ok(())` when the expression has no type reference, the type is not a known family, or the scope is non-empty (md.rs:4868-4879).
- `prepare_identity_values` drops any emission that does not normalize to the Id declaration applied to three arguments (md.rs:2211-2215).
- `source_applications` continues with a default (invalid) owner when no owner is found (`unwrap_or_default`, md.rs:367-375). `named_term` has a message for that case (md.rs:3759-3761); otherwise I cannot tell.
- `source_carrier_domains` treats any `infer_sort` failure, including budget exhaustion, as "the type depends on the scope" and keeps the domains (md.rs:4588-4599).
- `retain_source_evidence_aliases` stops after 128 rounds without reporting unfinished entries (md.rs:5418, 5515-5519).
- `member_carrier`, `name_carrier` and `declaration_result_carrier` return `None` on any failed lookup (md.rs:1010-1045, 1060-1062, 1092-1096); callers then refuse or fall back to opaque terms.
- Evidence against "accepts without proof": theorem, schema and evidence acceptance at md.rs:5252-5268 and 5314-5396 goes through `check_type` and `judgment_assumption_closure`, and with no integer theory the accepted roster is empty (md.rs:5314-5318), so any theorem that depends on an assumption is refused.

## Surprises
- This slice mostly contradicts property 1. Application domains, Id values, induction theorems, constructor schemas and evidence are all decided by kernel calls (`infer_sort`, `infer_type`, `check_type`, `convertible_retaining`, `judgment_assumption_closure`), and theorems are refused unless their assumption closure lies in an audited roster (md.rs:5314-5327). The elaborator's own judgment decides what the kernel is asked: which carrier an operand has, when two opaque expressions are the same constant, and when an operator has its builtin meaning.
- The kernel vocabulary is nearly all assumptions. Integer, address, floats and unit are assumed types; `<`, `<=`, `+`, `-`, negation, literals, embeddings and float relations are assumed constants. Negation is not `P -> Empty` but an opaque `Type 0 -> Type 0` constant (md.rs:1275-1283), so within this slice `!P` and `P` have no kernel relationship.
- All integer widths, `Int` and `UInt` share one kernel carrier (md.rs:1109, 1126-1137, 3881-3892). Distinctness is restored only by the alias definitions that conversion is told not to unfold (md.rs:4263-4303, 4412-4417). A check that omits the `retain` closure would treat `u8` and `i64` as the same type.
- The boolean encodings differ by context: the boolean literal `true` is a definition with body `TwoOne` and `false` has body `TwoZero` (md.rs:1376-1378), while the proposition for literal `true` is `Id Two 0 0` and for `false` is `Id Two 0 1` (md.rs:3699-3712).
- `embedding_term` pushes a new assumed function on every call and never looks for an existing one (md.rs:3310-3317), unlike float relations (md.rs:3566-3582) and opaque operations (md.rs:3232-3248). Two elaborations of the same embedding give different constants, so they would not convert. This looks like a completeness bug, not an unsound acceptance.
- `scalar_operand_term` accepts an integer literal for any requested carrier (md.rs:2840-2849), and `zero_literal` gives the unit and address carriers a numeric literal `0` (md.rs:2994-2997).
- `abstract_parameter_closure` skips every position `<= first` (md.rs:5904) and errors on any dependent declaration without a body (md.rs:5938-5940). A later parameter whose type mentions an earlier parameter is such a declaration, so a dependent outer telescope would fail with "source theorem retains an unabstracted dependent assumption". The only caller in this slice passes independent `Type u` parameters (md.rs:5135-5147).
- A kernel error is used as a signal in `source_carrier_domains` (md.rs:4588-4599): failure of `infer_sort` in an empty context is read as "open type".
- `elaborate_mathematical_type` pushes a scope entry, elaborates the codomain, pops, and only then applies `?` (md.rs:2415-2425), so the scope stays balanced on error. Other loops clear the scope by hand on each exit path (md.rs:5191-5194, 5239, 5304), and an early `?` return inside those loops (for example md.rs:5153, 5166, 5241) leaves `source_constructor_context` and the saved levels unrestored.
- Linear `Vec` membership sets are used for visited expressions and dependencies (md.rs:406-413, 3127-3135, 3141-3143), and `retain_source_evidence_aliases` rescans every machine and state for every pending name on each of up to 128 rounds (md.rs:5418-5449).
- The whole declaration list is cloned into a new `Signature` each time a context is needed: `instantiation_context` (md.rs:873), `source_application_input` (md.rs:4069), `source_carrier_domains` (md.rs:4587), and twice per `ensures` clause in the theorem loop (md.rs:5258, 5269).
- The first module's string records (md.rs:25-74) and the kernel elaboration below it describe the same declarations in two forms; nothing in this slice compares them.
