## What this code is for
This file checks the "static" arguments of generic calls and applications on the typed tree: machine parameters (callbacks, written `machine X` with a signature or a nominal trait requirement), const/value parameters, type parameters, implementation (conformance) evidence, and lifetime arguments. It has three top-level modules: `machine_parameters` (F:6-5651), `static_arguments` (F:5653-7180) and `static_bindings` (F:7182-8449). `machine_parameters` decides whether a machine chosen as an argument "refines" the required signature: same shape (generic arity, parameter modes and types, return type), compatible borrows and lifetimes, same or weaker effects (service reach, `invokes`, `suspends`, `blocks`, termination), and `requires`/`ensures`/`crashes` facts that are a conservative refinement. It also admits "nominal" selections, where a machine must carry exactly one authored satisfaction row for a trait requirement. It also infers type arguments for calls, and prepares rows for installed-interrupt registration. `static_arguments` checks, per call, that each authored argument fits the binder kind it lands in (type, const, value, machine, implementation) and that requirement tuples satisfy declared `requires` facts. `static_bindings` checks every retained static machine application: lifetime tuples, type bounds, const bindings, forwarded and closed conformance evidence, accessor primitives. Everything runs over the typed tree (`CheckingInput`), with the proof side delegated to `crate::proof_contracts::contract_entailment`.

## Mechanisms
- **Structural type unifier with generic-binder capture** (F:3567-3796): `required_type_matches_inner::<EXACT>` walks the required and actual type trees; when it meets a required `Named` symbol that is a `generic_types` parameter it pushes a binding and returns true (F:3628-3637); already-bound names are compared recursively with the bound actual (F:3590-3627). Const-like parameters compare through `static_const_type_reference_identity` (F:3595-3617). The `EXACT` instance strips `Constrained` wrappers (F:3676-3703) and requires equal Named symbols; the non-exact instance falls back to `corresponding_types_match` (F:3798-3823), which compares `type_identity` values after substituting bindings and renaming paired binders. No budget; recursion bounded by type-tree depth. Serves callback refinement and call type-argument inference (`infer_call_type_arguments`, F:3874-3945, `closed_static_call_type_bindings`, F:1661-1840).
- **Binder pairing by position labels** (F:683-686, 3805-3810, 3832-3837): required and actual binders that correspond get the same string label `$formation{n}` so that type identity treats them as equal. Serves callable refinement under different binder names.
- **Contract-fact refinement by canonical text** (F:2188-2585): see Identity by text. Falls back to a real implication judgment (`CallableContractRefinement`, F:1944-1968, 2060-2066) only when the text comparison fails.
- **Borrow/lifetime refinement setup** (F:665-821): builds a `CallableBorrowContract` for required and selected sides, with substitution tables, enclosing lifetime frames and applied-demand rewrites; the judging is in `borrow_contracts`. Two-phase: prepare before type parameters are inferred (F:557-571), validate after (F:603-612).
- **Nominal satisfaction counting** (F:3156-3276): iterates `machine_trait_conformances`, counts rows whose arguments match under applied identity scopes; also an inline "map" row (F:3180-3214); accepts only when exactly one row. Identity comparison uses `typed_trees::type_identity` scopes (declaration, arguments, lifetimes) rather than strings, except the lifetime rows which are `(String, String)` (F:8313-8325).
- **Whole-program call sweeps**: `form_static_machine_selections` (F:4458-4572), `validate_authored_static_arguments` (F:6297-6428), `validate_source_const_recipes` (F:6243-6295) and `validate_static_machine_bindings` (F:7700-8076) each iterate every call expression and every call statement of every state. `validate_static_machine_bindings` collects applications into one Vec, sorts and dedups by (arena_index, generation) (F:7774-7776), then also dedups judgments by comparing earlier judged entries linearly (F:7933-7946).
- **Sorted-vector lookup by handle** (F:6067-6093, 6507-6545): `(arena_index, generation)` sorted vec with `partition_point`; `CallScopes::context` returns None if the same expression occurs twice (F:6085-6091).
- **Lane ordering of parameters** (F:6685-6710): evidence parameters and ordinary parameters are consumed as two queues in source order; if one queue is empty the argument takes the other queue's next parameter so the kind mismatch is still reported.
- **Open/closed tuple classification** (F:7442-7602): an authored tuple is "declared source" if its target, scope, operands and bindings line up; a flag `open` records whether it mentions parameters of the enclosing declaration; a closed tuple is additionally judged refuted or not by the arithmetic requirement judgment (F:7598).
- **Performance short-circuit** (F:6028-6046): `CallScopes::build` returns empty when no trait has tuple requirements and no call has requirement application or provider readiness.

## Surprises
- Contract refinement acceptance is a text comparison of re-rendered, normalized strings (F:2188-2585). `alpha_normalize` replaces every word that equals a parameter name, with exceptions based on neighbouring characters (`.`/`:` before, `:`/`(`/`{` after). `substitute_type_actuals` only replaces names appearing right after `<` or `,`. The proof-side implication is consulted only on failure (F:2059-2078), so a text match accepts without that judgment.
- The crash-route check treats `routes` as sorted strings; `unconditional` is "any contract of that kind has zero facts" (F:2169-2178).
- `accessor_primitives::validate` indexes `parameters[0]` and `parameters[1]` with no length check (F:7220-7221); would panic if the primitive's machine had fewer than two type parameters.
- `machine_parameter_contract_definition` (F:5184-5237) scans every machine, trait, conformance, data definition and alias to find one parameter by symbol; it is called from the nominal path (F:3068) and callable shape (F:226). `dynamic_selector_scope` (F:7604-7663) scans all states, statements and expressions of a machine for the call that owns an application. `validate_declaration_machine_selection` recomputes `infer_operational_may`, `infer_service_reaches`, `infer_synchronous_invocations` for each declaration selection (F:5135-5141) and `machine_state_index` each time (F:5108): whole-program work per call.
- `is_declared_source_tuple` returns `true` when `require_declared_application_operands` fails (F:7536-7541), the opposite polarity from the rest of the function (which returns `false` on failure).
- The unresolved-build-operation skip is keyed on a call-target NAME string (F:4777).
- The nominal `arguments_match` closure has side effects on `operand_mismatch` and `helper_mismatch`, and only the first mismatch is kept (F:2900, 3048); `helper_mismatch` selects a different message (F:3220-3227).
