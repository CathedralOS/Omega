## What this code is for

This slice is twelve sibling modules inside `contract_entailment.rs`. Each one asks the same engine, the `StructuralJudge`, a different question about one point in a machine's body. The engine walks the statements that lead to a site (a "prefix walk"), carrying hypotheses and symbolic values (`StructuralTerm`), and each module supplies a small visitor (`StructuralPrefixVisitor`) that the walk calls when it reaches the site. The questions are:

- does this call satisfy one `requires` clause of its callee (`call_requirements`, ce:7680-9516);
- which facts does a lemma call (a "citation") deliver, and are the lemma's own `requires` met (`citations`, ce:9517-10381);
- is an index or range inside a collection's bounds (`collection_bounds`, ce:10382-10943);
- does a finished value satisfy or refute a `domain` (`completed_domains`, ce:10944-11234);
- is a finished value below a const parameter or inside an integer interval (`completed_observations`, ce:11235-11595);
- what does each field of a finished value equal, and which `data` variant is the value (`completed_values`, ce:11596-12426);
- does a struct literal satisfy its `data` type's `requires` (`construction_predicates`, ce:12430-12898);
- does the all-zero value satisfy a `data` or `domain` invariant (`zero_predicates`, ce:12899-13051);
- does a returned value satisfy a contract at normal exit (`exit_predicates`, ce:13054-13225);
- is an ordinary Boolean statement or a `crashes` condition proved (`statement_predicates`, ce:13226-13532);
- what is the identity or index value of a call argument's field (`call_projection_identity`, ce:13535-14045);
- do "content conservation" equations hold, for counted quantities and interval sets carried by values (`content_conservation`, ce:14046-15224).

Every answer is a `bool`, a `StructuralJudgment` (`Proven`, `Refuted` or `Unknown`) or an `Option`, produced by this code and the judge. Nothing in the slice builds or checks a proof object.

## Mechanisms

**Visitor on a prefix walk.** This is the slice's main general mechanism. A question is a struct that names a site `(state symbol, statement index, in_transition_target)` and implements `StructuralPrefixVisitor`: `entered` records that the walk reached the site, `unresolved` records that it could not, and `observe` receives `(program, machine, state, judge, environment)` (ce:8679-8727, ce:10833-10850, ce:11535-11557, ce:12058-12071, ce:12366-12373, ce:12801-12826, ce:13123-13138, ce:13506-13519, ce:13746-13762). The walk itself (`observe_runtime_state_prefix`, `observe_acyclic_invocation_prefix`, `observe_private_arrivals` and their batched forms) is outside this slice. Nine questions share it. An answer is positive only when the site was seen and every observation was proved.

**Three walks tried in turn.** A caller tries up to three sources of hypotheses: the current state under its own contract; the whole invocation from the machine's entry when the state graph has no cycle; and the facts at the machine's private callers ("private arrivals"). `run_requirement_walk` tries a shared memo, then the state walk, then the case-arm or state-prefix recognizer, then private arrivals (ce:8494-8594), resetting `seen` and `proven` between attempts (ce:8524-8525, ce:8583-8584).

**Two-pass, batched bound proofs.** `CollectionBoundsDemands` records every bound the range checker asks about during a provisional pass and answers `false` (ce:10598-10625). `resolve_deferred` proves all recorded demands in one batched walk, retries the unproved ones through private arrivals in one batch, then one at a time, and reports whether anything became proved so that the caller runs again (ce:10627-10732). Demands sit in a `BTreeMap` keyed by `((state index, generation), statement index, expression handle position)` (ce:10529, ce:10554). No budget.

**Fold over completed values.** `fold_completed_values` runs a caller's fold over every completed path of one expression, first under the state's own contract, then from private arrivals, and reports whether coverage was complete (ce:11403-11450). `CompletedObservation` is the generic visitor behind it; a fold can stop early with `ControlFlow::Break` (ce:11465-11594). Domains, static bounds, integer intervals, conservation, entry-projection preservation and backing addresses all use it.

**Source attribution for a finished value.** `CompletedProjectionVisitor` lists, for each field path of a completed value, what the field equals: a sub-expression of the site, a projection of a state parameter, an integer, or a scalar operation over such sources (ce:11612-11625, ce:11634-11703, ce:12071-12206). Across paths it keeps only the sources common to all (ce:12178-12200). Recursion is capped at depth 64 (ce:11636).

**Variant memo.** `completed_value_case_at_occurrence` answers "which variant" from a per-machine table that one batched walk per state fills, guarded by mutexes and keyed by `(machine, state, statement index, expression, type)` (ce:12208-12274, ce:12288-12355).

**Citation as fact injection.** A lemma call's `ensures` is substituted at the argument terms and added to the judge's hypotheses in statement order, so later citations see earlier ones (`CitationFacts`, `CitationFrontier`, ce:9563-9634; `collect_citation_predicates`, ce:9846-9987). `extends_in_order` checks that an incremental intake leaves the judge as a full intake would (ce:9615-9619). `citation_needs_site_judge` skips building a per-site judge for a lemma with no `requires` and no variant observations (ce:9757-9785).

**Interval cancellation.** For interval-set conservation the code checks validity and pairwise separation, then matches endpoints as a multiset: starts on the left and ends on the right must cancel against ends on the left and starts on the right (ce:14076-14100). The work is quadratic in the number of intervals; each comparison is one judge query.

**Law graph for conservation.** `proof_dependencies` puts the goal's two sides and both sides of every available law of the same algebra into a union-find, merging terms the judge proves equal (ce:14389-14409). Each law becomes a two-way edge between classes, carrying the laws it depends on (ce:14428-14444). `derivation_depth` is a stack search from the class of the goal's left side to the class of its right side that follows only edges whose requirements the caller allows, and returns the largest source depth on the path it finds (ce:14535-14565). An endpoint that the judge cannot prove equal to itself belongs to no class (ce:14400-14403, ce:14413-14415). No budget; the pairwise comparison is quadratic in endpoints.

**Budgets found.** Depth 64 in `CompletedSources::sources` (ce:11636); 4,096 nodes and depth 64 in `has_formed_identity_predicate` (ce:13315, ce:13322). Every judge call in the slice passes a trailing `0`, apparently a starting depth (for example ce:10492, ce:13395, ce:13526).

## Surprises

1. **No proof kernel anywhere.** The range never mentions `proof_admission`, `ProofNode`, `verify_obligation` or certificates. Every verdict is `matches!(judgment, StructuralJudgment::Proven)` on a value the `StructuralJudge` returned (for example ce:9099, ce:10484-10496, ce:11228, ce:13217-13219, ce:13521-13529, ce:14148-14155). The citation doc comment (ce:9838-9842) rests soundness on other checks running "in this same validation batch", not on evidence.

2. **What can be proved depends on which construct asks.** A call's `requires` may use facts from the machine's private callers (ce:8585-8592), and so may a collection bound (ce:10702, ce:10814), a completed-value fold (ce:11439) and a construction predicate (ce:12538). An ordinary Boolean statement (ce:13481-13495), a normal-exit contract (ce:13107), a variant question (ce:12351) and a projection identity (ce:13728) may not. Conservation leaves private callers out on purpose and says why (ce:14676-14678). The others give no reason.

3. **"Zero paths reach the site" is handled differently by each visitor.** It leaves a call requirement proved (ce:8787-8794). For a bound, one branch refuses and the other accepts (ce:10909 against ce:10899-10907). It makes a completed value unavailable (ce:11573-11576), a variant incomplete (ce:12388-12390), a projection invalid (ce:13801-13803), and a construction unobserved (the loop at ce:12861 does not run, so `observed` stays false).

4. **Self-citation contradicts the doc comment.** ce:9838-9842 says lemma cycles are banned by the call-graph rule. Yet `can_establish_citation` and `instantiate_citation` have a path that lets a proof machine with a unit result cite itself (`allow_self_induction`, ce:9713-9728, ce:10203-10206), and `citation_guarantees` takes it by passing `true` (ce:9429, ce:9440). `collect_citation_predicates` passes `false` (ce:9970). The descent check `proof_call_has_structural_descent` at ce:9487 guards a different route (`intake_state_induction`), not this one.

5. **Citation errors are thrown away on the walk route** (ce:9408, ce:9443), as item 6 of the previous section describes.

6. **A shortcut returns `Proven` for every `data` invariant of a literal** when the prepared-mathematics view holds a matching constructor record (ce:12457-12474). The code here compares handles and one type identity; the judgments themselves come from somewhere else.

7. **One unreadable caller premise switches the route off.** `prepare_requirement` declines a runtime requirement unless every `requires` it collected for the caller is a "runtime predicate fact" (ce:8429-8437). A premise that has nothing to do with the goal still makes the call requirement unprovable by this route.

8. **`or` is classified like `and`.** `runtime_predicate_fact` and `runtime_fact_for_parameters` require both sides of an `or` to be readable (ce:9131-9134, ce:9176-9179). This is a classification, not a proof, so it errs toward refusal. `contains_case_premise` and `case_fact_only` look only through `and` (ce:9287-9289, ce:9299-9301).

9. **Projection lookups disagree inside one module.** `ContentValues::magnitude` and `interval_sets::members` find a content projection by machine alone (ce:15084-15087, ce:14113-14116). `observe_term` requires machine, domain and semantic domain (ce:14337-14341).

10. **Dead arm.** `ContentValues::subject_term` handles a `Parameter` root by building `StructuralTerm::Variable(name)` (ce:15119), but its only caller is the `Result` arm of `scalar` (ce:15152-15153); parameter roots go through the symbol-keyed `parameter_projection` (ce:15147-15151). A result place that passes through a variant or a fixed index yields `None` (ce:15127), so conservation over such places is never proved.

11. **Graph search edge case.** `derivation_depth` returns only when an edge arrives at the goal class (ce:14555-14557). If the goal's two sides fall in the same class and no law touches that class, it returns `None`. The numeric judgment at ce:14628-14631 would normally have proved such a goal first, but for interval sets `same_term` compares endpoints in order (ce:14489-14493), which is a different test from `interval_sets::judge`. The depth returned is that of the first path found, not the smallest.

12. **Crash conditions look at fewer contracts than their sibling.** `proves_crash_condition` accepts only machine-level `crashes` facts (ce:13377-13388). `has_formed_identity_predicate` and the shared judge also read the entry state's contracts (ce:13297-13309, ce:13259-13274).

13. **Omitted struct fields are zero inside the invariant check** (ce:12749-12754), so the zero-initialization rule is applied here as well as wherever construction is typed. Combined with ce:12494-12495, a supplied field that did not resolve would be judged as zero.

14. **Identity strings carry debug formatting.** The identity of a contract subject is built with `{:?}` of a symbol handle (ce:13894-13897, ce:14036-14042), so whether two identities are equal depends on the `Debug` output of `SymbolHandle`.

15. **Debug instrumentation runs through the checker.** The range has 30 `eprintln!` calls and 14 `trace_call_consumer_outcome` calls, gated by `struct_trace()`, `struct_trace_owner` and `trace_flags::struct_call_consumer_selection()`. `begin_call_consumer_trace` (ce:8619-8676) selects a call by comparing display-path strings, prints pointer addresses (`{call:p}`, ce:8652), and builds a `PlaceRoot` from an index and generation supplied by the trace flag (ce:8672-8675). In `CallRequirement::observe` roughly a third of the lines are trace calls.

16. **Evidence against property 3 in its strict form.** The site of a question is `(state, statement index, expression handle)`, so locals, fields, arguments and returns are not separate code paths here. The placement that does leak is `in_transition_target`: some questions compute it (ce:8279, ce:10754, ce:11498, ce:12517, ce:13093) and others hard-code `false` (ce:12228, ce:12343, ce:13460).

17. **Pointer equality decides identity in four places**: a statement call site (ce:7790-7792); whether a lemma is the machine being checked (ce:10010); whether a machine and state are the stored ones before the memo is used (ce:12297-12302); and a named transition path (ce:13708).
