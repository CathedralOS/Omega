## What this code is for
S turns the declared contracts of `data` types and machine states into facts the checker can use at calls. (1) `declaration_predicates` (S:25-2261) rewrites `requires` facts of `data` into checked boolean/scalar predicate rows per state parameter, guarded by the variant ("case") they apply to, so a state's entry can assume them and a mutable-borrow return must restore them (S:268-322). (2) The middle of the file (S:2355-3062) computes which domain qualifications ("whole" or at a structural path such as a field, case, array index, slice element, referent) a type carries, and checks that a state's `requires` rows are exactly the qualifications its parameter types imply (S:2405-2498). (3) S:3064-3977 reconstructs, for a call to a function that returns a linear (owned) structural value, which claims (permission/ownership obligations) cross into the callee, which come back in the result, and at which paths, by matching the checker's flow facts (permission events, claim outcome maps, call facts) against the typed trees (S:3446-3686). T is a set of once-per-process environment switches for debug tracing, with parsing for `OMEGA_STRUCT_TRACE` values.

## Mechanisms
- Predicate spelling (FactSpelling, S:906-1443): a recursive-descent translation of typed expression nodes to `CheckedBooleanExpression`/`CheckedScalarExpression`; failure at any sub-node returns `None` for the whole fact (all-or-nothing). Serves `requires` on `data`.
- Interval carrier check (field_carriers, S:47-251): three-valued evaluation (`Some(true)`, `Some(false)`, `None`) of a predicate using intervals of fields built from primitive carrier bounds, `enforced_integer_type_bounds` and `atomic_field_interval`. Serves deciding that a declaration is implied by the carrier. Limits: only `<`, `<=`, `==` on integer intervals, boolean connectives; everything else `None`.
- Recursive storage walk with visited stack (S:375-448, S:511-585, S:826-861): DFS over owned fields of data definitions, identity = (symbol, generic instance) (S:253-266). Cycles terminate by `visited` (treated as not carried in `complete_definition_storage`, S:382, but skipped silently in `RowEmitter::descend`, S:542, and false in `storage_carries_rows`, S:847). A memo `checked_own_facts` prevents re-evaluating a definition (S:386-394); `RowEmitter.emitting` memoizes `definition_emits_rows` by pointer (S:593-600).
- Array expansion: rows for a fixed array of known literal length are emitted per index (S:529-536) unless the element type carries no rows (S:526). The test at S:2165-2259 pins that a 32-element array of a case-implied carrier emits 0 rows, but 32 rows when the predicate is not carrier-implied.
- Qualification inventory (`structural_qualification_inventory`, S:2755-3062): one recursive `collect` over a type reference through Reference, Constrained, Slice, FixedArray, Named/Generic; keeps a `path` stack, `active` list for recursion cut-off (S:2963), `try_reserve` for array expansion (S:2931); sorts and dedups outputs. `zero_only` mode checks only the first variant and zero-byte admissibility (S:2836-2843, S:2976). Serves domain qualifications carried by storage.
- Claim frontier matching (S:3064-3177, S:3688-3762, S:3793-3906): set-equality and prefix-overlap checks on sorted path lists (`windows(2)`, `starts_with`, S:3130-3135), linear scans over permission events by (machine, state, source, kind, access, multiplicity, obligation_live).
- Trace-selector parser (T:71-81): `caller->callee@index:generation`.

## Surprises
- All errors from the custody code are `&'static str` strings, not typed diagnostics; there is no proof-kernel call anywhere in this slice (no `proof_admission`, `ProofNode`, `verify_obligation`, certificate). The rules are yes/no decisions of the code itself, with structural equality of flow facts as the "evidence".
- The roster is built by silently skipping what it cannot express (S:643-656, 679-689), and soundness relies on a separate predicate (`declaration_facts_carried`) being consulted by callers. The file's tests were written around that coupling ("must not disappear", "cannot hide").
- A test module keeps a copy of the superseded algorithm (S:1789-1857, S:2268-2283) as the reference for equivalence; the new memoized version changes cost (15 vs 5 evaluations) but must keep result equality.
- Declaration rows derive from `Option<bool>` three-valued interval evaluation implemented here (S:114-166), a small decision procedure outside the proof kernel; `Comparison::Equal` with both singleton intervals returns true only when equal (S:151-157).
