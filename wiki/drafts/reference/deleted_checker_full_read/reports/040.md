## What this code is for
This is the first half of the index and range check: the part that decides which facts a state may assume before its statements run, and the shared expression walker. The check itself ("every indexed access and subslice range must be proved within its collection's length", :1-4) and its diagnostics live in later lines of the file, outside this slice. The slice holds seven modules. `incoming_guards` (:40-1335) works out which transition guards hold at each state's entry. `loop_invariants` (:1336-3330) recognises counters that only go up or only go down inside a loop and derives bounds for them. `requirements` (:3331-3491) turns `requires` clauses into starting facts. `state_arguments` (:3492-4846) runs a fixed-point over a machine and its nested machines to learn what every edge into a state proves about that state's parameters. `assignment_lengths` (:4852-4970) decides how an assignment changes a byte collection's live length. `expression_transfer` (:4971-5367) is one expression walker that both the range check and the state-argument collection use. No function in the slice refuses a program or emits a diagnostic; every function either adds a fact to `RangeFacts` or declines to add one. No function calls the proof kernel.

## Mechanisms
- **Single-predecessor back-walk with a join meet** (:280-501). For each state the walker follows the unique incoming edge backwards, collecting each edge's guards that survive the writes accumulated so far, and stops at a join, the entry, or a revisited state (:437-441). A second pass handles joins by intersecting what each incoming edge carries (:445-498). Limits: guards match across edges only by identical expression handle; the written set is a list of strings; an opaque call sets `written_any` and kills everything further back. Serves index proofs in loop bodies (`transition self.i < n { true -> body }`, :259-262).
- **Two parallel transports along edges** (:601-845). One maps target parameters to canonical places of arguments (`CanonicalPlace`), composed hop by hop. The other maps target parameters to immutable integer symbols. The comment at :708-711 says the second exists because place identity cannot survive reassignment.
- **Natural-loop detection** (:1738-1786, :2881-2894). Back edges are edges into `head` from states unreachable from the entry once `head` is removed; the loop is everything that reaches a back source without passing `head`. Quadratic list scans, no budget.
- **Interval propagation with widening** (:1365-1524). Computes the counter's interval at each loop state. The head's interval is the entry range united with what back-edge guards allow and is never revised (:1348-1355, :1459). A worklist pushes intervals through assignments and transition guards. After a state's interval has changed more than `states.len()` times, any bound that moved is dropped (:1485-1494). Guard parsing recursion is capped at depth 128 (:1566). Serves the no-overflow side of the monotone-counter invariant.
- **Search over authored bound chains** (:2150-2216). Collects `lower <[=] upper` relations from the machine's `requires`, then does a worklist search over label strings from the loop bound to any `collection.len`, tracking strictness. A visited list stops cycles. Each step requires `machine_preserves_path`.
- **State-argument fixed point** (:4353-4462). Starts with only the root entry state dirty. Each pass reruns dirty states from fresh `RangeFacts` (parameters, `requires`, facts collected so far), replays every statement through the shared statement transfer, and records what each internal call or transition carries. Contributions are re-merged from scratch each pass; a state is dirty next pass if its merged entry changed. It returns when a pass changes nothing; after `MAX_PROPAGATION_PASSES = 64` it returns nothing (:4351, :4461). The iteration starts optimistic (first edge installs its facts) and weakens.
- **Meet operators** (:4217-4345): `MergedFact` (Unseen / Known / Conflicting), `MergedBound` (Unseen / Known / Unbounded with min or max), `MergedBinders` and `MergedIndexProofs` (intersection).
- **Machine families** (:4495-4605). Dense rows over machine roster positions: `root` follows the parent chain up to 32 levels; `children` lists machines declared in a machine or in one of its states. `nodes` lists every state of a family depth-first.
- **One expression walker with a sink** (:5002-5016, :5136-5365). `ExpressionTransfer::transfer` fixes one evaluation schedule; the sink differs only at an indexed read and at a call's entry. The comment at :4977-4979 says two separate walkers had lost match guards and short-circuit guards.
- **Guard index cache** (:95-131). One `OnceLock` per "resolver present / absent", shared by ranges, contracts, crash coverage and multiplicity (:88-93).

## Accepts or skips without proof
- **Index facts from `requires` mentions** (:3426-3490). Any `c[i]` inside a `requires` fact is recorded as in bounds, whatever surrounds it: either side of any binary operator including `||` (:3448-3451), under a unary operator (:3476-3478), inside call arguments (:3452-3457), in a match subject (:3437-3439). Whether callers must prove these accesses when they establish the `requires`: cannot tell from this slice.
- **Inclusive subslice in `requires`** gives minimum length 1 and a valid end index (:3407-3424), again regardless of position in the expression. Same question.
- **Guard survival compares strings spelled in different states** (:889-907 with :914-952). Guard paths use the evaluating state's data-binding name; write paths use the writing state's binding name or the call frame's rendering. If two states of one machine spell the root differently, a write does not overlap and the guard is kept. `loop_invariants` canonicalises for exactly this reason (:2524-2527). I see no canonicalisation on the `incoming_guards` path; whether states of one machine can in fact bind different root names, the comments at :3114-3116 and :975-980 say they can.
- **Earlier-arm negations are not checked against later guard evaluation** (:296-350, :504-508). An edge's own guards, including the negated earlier guards in its run, are taken as holding at the target "without a survives check". If a later guard in the run contains a call that writes what an earlier guard reads, the earlier negation is still carried. Seeding filters guards that themselves contain calls (:1332), but the earlier guard need not contain one. Whether guards may contain writing calls: cannot tell.
- **Unanalysable guard survives at the immediate edge** (:905). Later filtered for this consumer by `expression_tail_eligible` returning false on unknown nodes (:1332); the other consumers named at :91-92 are outside this slice.
- **Edges are named transitions only** (:1046-1051, :1722-1726). `TransitionTargetNode::Value` targets and any entry into a non-first state from outside are not edges. Single-predecessor reasoning (:584-599), loop-entry detection (:2366-2390) and the state-argument merge (:4106-4139) all assume the listed edges are every arrival. Cannot tell whether a computed target can enter a named state.
- **Unknown machine in the guard index returns no guards** (:158-163). This loses facts; it does not add any.
- **Lookups that fail and continue**: `find_state` failing inside `loop_modifications_direction` skips that loop state (:3278-3280) and inside candidate collection (:2898-2900), while the same failure in `loop_preserves_path` returns false (:2629-2631). `seed_incoming_guard_facts` skips an entry whose evaluation state is missing (:1077-1079). `seed_loop_invariant_facts` skips a label that cannot be rendered (:3082-3089, :3098-3105).
- **Argument and parameter lists are zipped** (:3618, :3707, :3718, :4704). With fewer arguments than parameters the unmatched parameters stay `Unseen` for that edge, and `merge_contribution` skips `Unseen` values (:4705-4721), so that edge does not weaken them. Arity is presumably checked earlier; cannot tell.
- **`updates_preserve_order` returns true by default** (:1523); it returns false only when `builtin_monotonic_integer_update_bounds` gives no bounds (:1442-1444) or a state position is missing (:1411-1413, :1464-1466). A branch whose interval is empty is skipped (:1477-1480, :1516-1519).
- **`value_preserves_indexed_extent` returns true** when the target is not indexed (:4886-4888), the collection is not a bounded byte type (:4889-4894), or the value writes nothing (:4902-4904). It returns false when the frame is unknown (:4895-4901).
- **Recast of an indexed value skips the index sink** (:5307-5312). For `cast.form.is_recast()` over `c[i]`, the walker visits `c` and `i` but never calls `sink.indexed_access` for `c[i]`. Whether another check covers that access: cannot tell.
- **A match with no recorded operator uses counts as a built-in comparison** (:5167-5177): `builtin` starts true and only a non-`Expression` occurrence clears it.
- **`ExpressionTransfer::transfer` returns at once** when the expression has no call, cast, atomic or (for the checking sink) indexed node (:5143-5147).

3. **Mentioning `a[i]` in a `requires` makes `i` a proven index of `a`** even under `||` or negation (:3426-3490). `requires flag || a[i] > 0` seeds `prove_index("a", "i")`.

7. **Three definitions of "family" that disagree for a machine declared inside a state.** `children` includes it under the enclosing machine (:4519-4525). `root` stops climbing when the parent is not a machine, so that machine is its own root (:4531-4534). `family_related` tests `parent == scope` and climbs only through machine parents (:4593-4599), so it does not relate a state-nested machine to its enclosing machine. 8. **The 32-level cap in `root` and `family_related` stops silently** (:4530, :4592); a deeper nesting yields a non-root "root" and `false` without any report.
