## What this code is for

The slice is the whole `arithmetic_judgment` module: the integer arithmetic prover that the old checker used to decide `requires`/`ensures` entailment, measure (ranking) values, operand-fits-carrier questions and call-contract arithmetic. Its central type is `Engine` (contract_entailment.rs:6249-6278), a bag of hypotheses: polynomial lower bounds, a difference-bound matrix, equality substitutions, per-atom intervals, known-nonzero differences and a registry of "opaque terms" (quotient, remainder, shift, bitwise, wrapped/saturated value, conditional value, call result, measure application). Source expressions are turned into `Polynomial`s whose variables are strings (:6026-6031) by two separate translators: `normalize` (:7053-7459), which computes a value without checking that operations are defined, and `formed_value` (:847-967), which also demands that every operation's operands and result provably fit their carrier types. `judge` (:6894-7014) answers a fact with `Proven`, `ConstantFalse`, `Refuted` or `Unknown` (:6019-6024) by asking the lower-bound prover (`LowerBoundQueries`, :3328-3890). The module also forms the integer value of a declared measure applied to an input (:719-845), of a call to a contracted declaration (:39-212) and of a `match` (:322-487), and it reads propositions stored as proof-kernel `Term`s and decides them with the same arithmetic (:4587-4988). The engine has two modes that the code never names in a comment: a "non-strict" mode where a variable is a parameter's source name (:6284-6297, :7171-7179), and a "strict" mode where symbols and expression occurrences are bound explicitly by handle (:5093-5124, :5870-5890). No diagnostic text is produced anywhere in the slice; every decision leaves as `Option`, `bool`, `Judgment` or `CarrierFit`. About 520 lines are unit tests that exercise the arithmetic on an empty program.

## Mechanisms

- **Polynomial normal form.** `Polynomial` is `BTreeMap<Monomial, BigInt>` with `Monomial = BTreeMap<String, u32>` (contract_entailment.rs:6026-6031). Add, subtract, negate, checked multiply (fails only on exponent overflow, :6118-6139). Helpers recognise `atom - atom + c` and `±atom + c` (:6141-6190). Serves every arithmetic fact.
- **Equality substitution.** `harvest_substitution` records `atom := polynomial` when the atom does not occur in the replacement and has no substitution yet (contract_entailment.rs:1834-1851). `substituted` applies the map for at most `SUBSTITUTION_ROUNDS = 8` rounds and returns the current polynomial unchanged if a multiplication overflows (:1853-1896, :6281).
- **Difference-bound matrix.** Bounds of shape `a - b >= c` and `±a >= c` seed a matrix with a `"\0zero"` node; closing it sets `requires_unsatisfiable` on a contradiction (contract_entailment.rs:1787-1832). The matrix type itself (`arithmetic_domains::DifferenceBounds`) is outside the slice.
- **Lower-bound prover** (`prove_at_least(p, c)`: is `p >= c`?). Order of routes: conditional case split first and final (contract_entailment.rs:3519-3527); constant, matrix difference, single atom (:3610-3638); exact stored bound (:3463-3480); proportional stored bound (:3736-3775); interval of the polynomial (:3713-3734); a greedy pairing of positive and negative atoms over matrix edges for 3 to 128 atoms (:3640-3711); Horner-form interval for nonlinear polynomials (:3818-3863); then one combination step with each stored bound, by subtraction or by scaling (:3529-3548, :3777-3816). There is no multi-step linear combination. A prepared index sorts and dedupes stored bounds to the strongest per polynomial (:3339-3397); `prove_with_deferred_preparation` builds it only if the cheap routes fail (:3503-3517).
- **Integer rounding in scaled proofs.** `prove_scaled_lower_bound` relaxes the goal by `scale - 1` only when strict symbol bindings exist, are valid, and the engine is not in proof-integer formation (contract_entailment.rs:3801-3808).
- **Contradiction search.** `integer_comparisons_unsatisfiable` installs comparisons, refreshes opaque intervals, applies a gcd test on equalities (`excludes_integer_zero`, :6058-6074), returns false at once if all bounds are difference-shaped with no opaque terms, else runs `bounds_are_inconsistent`, a pairwise check of each stored bound's complement against every other (contract_entailment.rs:6860-6892, :1723-1750). It always answers false without strict bindings (:6864-6866).
- **Hypothesis installation.** Comparisons become lower bounds; a constant bound that fails marks the context unsatisfiable; a disequality is sharpened to a strict inequality when one direction is already proven (contract_entailment.rs:6779-6858).
- **Opaque terms with intervals.** Quotient, remainder, shifts, bitwise, policy values get a minted atom and an interval (contract_entailment.rs:3024-3201, 2715-2761); `refresh_opaque_intervals` recomputes them (:6525-6568). Division, modulo and right shift add descent bounds such as `dividend - quotient >= 0 or 1` (:2377-2460) and a fixed-quotient remainder equation (:2348-2375).
- **Known-bits analysis** for `&`, `|`, `^` to depth 64 (contract_entailment.rs:3211-3291).
- **Wrapping residue.** Reduces coefficients modulo `2^n` and flattens nested wraps of the same primitive (contract_entailment.rs:2763-2804); `complete_integer_policy` wraps or clamps constants (:2856-2878).
- **Conditional values and case split.** A `match` value becomes an atom with arms `(conditions, value)` (contract_entailment.rs:3931-3955). To bound a polynomial that depends on one, the prover clones the engine per arm, substitutes the arm value, treats an arm with unsatisfiable conditions as vacuous, and charges `1 + bounds + opaque terms` per arm against a shared atomic allowance; exhaustion answers false (:3970-4031).
- **Path-splitting evaluation** of `match` and Boolean conditions with one engine clone per path, pruning infeasible paths (contract_entailment.rs:264-586).
- **Call congruence.** After new equalities, each opaque call or measure application is re-keyed on its normalized arguments; if that reaches an existing term, the two atoms are equated (contract_entailment.rs:4043-4095).
- **Integer denotation capture and replay.** The dependency closure of opaque terms under a value is saved and can be rebuilt in another engine under a leaf substitution (contract_entailment.rs:1366-1499). Serves ranking measures carried between arrivals.
- **Scoped bindings and call capture.** `install_scoped_bindings` validates and installs a binding set (contract_entailment.rs:5603-5729); `capture_expression_calls` walks an expression post-order with a 4096-step budget, binds fixed-integer call arguments, and installs the callee hypotheses (:4382-4515).
- **Remainder fixpoint.** `refresh_admitted_integer_remainders` re-installs modulo bounds until nothing changes (contract_entailment.rs:5294-5310).

## Identity by text

- **Every arithmetic variable is a `String`.** `Monomial = BTreeMap<String, u32>` (contract_entailment.rs:6026); substitutions, intervals, opaque terms, unsigned set, parameter set and matrix positions are all keyed by that string (:6255, :6267-6272, :1776-1781).
- **Parameter atoms are source names.** `Engine::new` uses `parameter.name.as_str()` for every state's parameters and skips a name already present, so same-named parameters of different states are one variable and the first one's signedness is kept (contract_entailment.rs:6286-6294). Entry range hypotheses use the same name (:6715). Non-strict `normalize` turns a single-segment name into `Polynomial::atom(name)` if the name is in `parameter_atoms` (:7171-7179).
- **`result` by spelling.** `with_result_atom` declares the atom `RESULT_BINDER` unless a root-state parameter is spelled the same (contract_entailment.rs:6615-6623). Strict `normalize` returns the result binding when the name's single member `as_str() == RESULT_BINDER` (:7166-7169).
- **Opaque arithmetic terms are named by the `Debug` rendering of their operands:** `"\0integer-policy:{primitive:?}:{domain:?}:{value:?}"` (contract_entailment.rs:2749), `"\0integer-remainder:{operand:?}%{modulus:?}"` (:3046), `"\0integer-quotient:{dividend:?}/{divisor:?}"` (:3076), `"\0integer-shift-{direction}:{value:?}{operator}{count:?}"` with `"left"`/`"<<"`, `"right"`/`">>"` passed as strings (:3094-3095, :3128, :3146-3147), `"\0integer-bitwise:{operator:?}:{bits}:{signed}:{left:?}:{right:?}"` (:3188). `register_opaque_term` treats equal names as the same term and drops the second (:6002-6010).
- **Counter-numbered names:** `"\0conditional:{identity}"` (contract_entailment.rs:3952), `"\0declared-application:{identity}"` (:4117), `"\0applied-call:{identity}"` (:4165).
- **Places and expressions rendered to a path string.** `integer_source_identity` builds `name:{symbol:?}`, `literal:…`, `binary:Op(l,r)`, `cast:…`, `member:{symbol:?}:{variant:?}:receiver`, `index:coll:idx`, `call:…`, else `occurrence:{expression:?}` (contract_entailment.rs:7619-7677). It names the atom for a member place (:7090, :7119), the key under which a matched member subject is replaced by a constant (:5141-5145), and embedded values `"\0embed:{primitive:?}:{identity}"` (:7572-7576).
- **Other rendered names:** `"\0proof-symbol:{symbol:?}"` (contract_entailment.rs:6591), `"\0call-result:{expression:?}"` (:7434), `"\0address-model-bound:{model:?}:{bound:?}"` (:7548-7550), `ZERO_ATOM = "\u{0}zero"` (:6280).
- **Lookups by name:** opaque term found by atom name (contract_entailment.rs:1394, :2775-2777, :3278, :3997, :4009); `unsigned.contains(identity)` decides signedness when a polynomial is exported (:4565-4568); `opaque_terms_since_mention(start, atom: &str)` (:6459-6464); `opaque_term_name_if_uncorrelated` returns names (:6399-6457).
- **Denotations carry leaf names** (`leaves: Vec<String>`) and are replayed through `BTreeMap<String, Polynomial>` (contract_entailment.rs:1319-1324, :1406-1417). External binding values carry `Atom { identity, unsigned }` strings (:5102-5105, :5218-5221).
- **The leading NUL** is the only thing separating minted names from source parameter names.
- **Evidence against the property in the same file:** strict mode binds by `SymbolHandle` and `ExpressionHandle` (contract_entailment.rs:6256-6262, :5164-5173, :5860-5868); declared reads use a parameter symbol plus `PlaceSegment` path (:1191-1239, :5755-5764); call and measure opaque terms compare symbols, expression handles and argument values, not names (:4107-4110, :4153-4158).

## Accepts or skips without proof

- **Operator with no spelling counts as builtin.** `selected_binary_meaning` returns `true` when `spelled_binary_operator` is `None` (contract_entailment.rs:5475-5481). Which operators that covers is decided outside the slice; cannot tell whether another check covers them.
- **Call result range assumed before it is checked.** `calls::form` pushes the declared return primitive's min and max as bounds on the call value (contract_entailment.rs:173-182) and only then runs `complete_formed_call` and the "result lands in return type" check (:183-195). For a fixed-width return type that check can no longer fail. The callee's own body check is outside the slice; cannot tell.
- **Declared types supply hypotheses.** Entry parameters get their primitive range and range-constraint interval (contract_entailment.rs:6714-6754); a member place gets its primitive range or standing interval (:7100-7126); a call result gets `call_result_interval` (:7424-7442); an embedding gets its interval (:4902-4915, :7578-7586); a `BoundedInteger` binding gets its interval (:5222-5231). Each trusts the declared type or the supplying module.
- **"Unsigned" means "not a signed integer".** `unsigned_parameter_carrier` is true for any primitive that is not a signed integer (contract_entailment.rs:7592-7600), so a parameter of a non-integer primitive type is seeded with `>= 0` (:1795-1797, :1761-1767). Cannot tell whether such atoms can reach an integer comparison.
- **Parameters of later states.** `Engine::new` declares atoms for all states' parameters (contract_entailment.rs:6286-6294) but range hypotheses come only from the first state (:6711-6714); the unsigned `>= 0` seed still applies to all.
- **Missing type information defaults.** In `formed_value`, an operand with no type borrows the other operand's primitive, and a missing policy becomes `Exact` (contract_entailment.rs:934-942). A literal cast source takes the target type (:889-894). Arithmetic-domain constraints on a type are skipped when checking a value against it (:981-984).
- **Unchecked value path.** `normalize` computes `~x` without the operand range check (contract_entailment.rs:7181-7186), bitwise operations without the builtin-meaning check (:7188-7197), Exact `+ - *` as the mathematical value with no overflow check (:7277-7293), and strict fixed-integer `/` and `%` without a nonzero-divisor proof beyond the constant-zero refusal (:7294-7308). ## Surprises

1. **No proof-kernel call anywhere in the slice.** The only kernel item used is the data type `proof_admission::{Term, TermHandle}` (contract_entailment.rs:4591), which the engine pattern-matches and then decides with its own arithmetic (:4732-4860). There is no `verify_obligation`, `ProofNode` or certificate. What formation leaves behind (`IntegerApplicationFormation`: casts, calls, chosen dispatch arms, :600-607) is a record of the engine's own decisions; `from_retained` re-checks only handle validity and cast ranges (:630-673). This supports property 1.
2. **The call-result check is vacuous for fixed-width return types.** In `calls::form` the return type's range is pushed as a hypothesis at contract_entailment.rs:176-181, then checked at :189-195. `form_declared_integer_application` does it in the other order: check at :820, assume at :822-832.
3. **Atom names omit fields that the term carries.** The remainder name leaves out `tight_interval` (contract_entailment.rs:3046) and the shift name leaves out `count_bits` (:3128). `register_opaque_term` keeps the first term registered under a name (:6003-6005), but the caller then overwrites the atom's interval unconditionally (:3055, :3130). So one atom can hold the first term's definition with a later call's interval.
4. **Same-named parameters in different states are one variable** in non-strict mode, with the first one's signedness (contract_entailment.rs:6286-6294). A member place's type and standing interval are read from the machine's first state whatever state the expression is in (:7099-7117).
5. **Member places are identified by rendered path text, with no version.** Two reads of the same member path give the same atom (contract_entailment.rs:7119-7127, :7619-7677). Nothing in this slice separates a read before a write from a read after it; cannot tell whether a caller does.
6. **Unary minus is not in the engine's language.** `normalize` returns `None` for every unary operator except `~` (contract_entailment.rs:7181-7187); `formed_value` likewise (:874-880, :954-963).
7. **Trapping is treated inconsistently.** The checked path calls Trapping value-preserving like Exact (contract_entailment.rs:2018-2019); `selected_binary_meaning` does not admit Trapping result types for fixed integers (:5455-5459); `selected_policy_result` returns `None` for Trapping (:7504).
8. **Budget exhaustion is a definite "no", and it takes priority.** The conditional split is tried first and its answer is final (contract_entailment.rs:3519-3527); a test pins that an exhausted allowance answers false even where the matrix alone proves the goal (:1682-1693). The allowance is one atomic counter shared by all clones (:6352, :1625-1626), so a provable fact can become unprovable depending on how much earlier work in the same engine family consumed.
9. **Integer rounding depends on engine mode.** The `scale - 1` slack applies only with valid strict bindings and not in proof-integer formation (contract_entailment.rs:3801-3808); in the other modes the same integer goal is held to the weaker rational argument.
10. **`address_model_bound` appends a duplicate bound on every call** (contract_entailment.rs:7533-7537). The per-arm work charge is `1 + bounds.len() + opaque_terms.len()` (:3971-3973), so repeated mentions of the address bound raise the cost of later case splits.
11. **`for_proof_integer_formation` scans every expression in the whole program** each time it is constructed, binding every qualifying name symbol program-wide (contract_entailment.rs:6576-6594).
12. **Debug tracing ships in the decision path.** `eprintln!("STRUCT …")` lines gated by `struct_trace()` sit inside call, dispatch and mathematical-term formation (contract_entailment.rs:47-54, 109-113, 164-166, 186-188, 336-342, 442-449, 459-464, 577-582, 740-742, 4599-4619).
13. **Unsatisfiable context is handled three ways:** `integer_value_fit` answers Unknown (contract_entailment.rs:5045-5047), `form_integer_expression` refuses (:702-707), `form_declared_integer_application` returns a value without a formation record (:834-843).
14. **An unexpected capability:** the engine does real symbolic work beyond linear arithmetic, including known-bits reasoning for bitwise operators (contract_entailment.rs:3211-3291), wrapping residue arithmetic (:2763-2804), congruence closure over calls and measure applications (:4043-4095), and replayable captured denotations (:1366-1499). The `MIN / -1` rule is stated precisely per policy and tested (:2236-2251, :2611-2651).
15. **`match` normalization ignores patterns:** `normalize_matched_integer` requires all arms to have the same value and never looks at conditions (contract_entailment.rs:7461-7482), while `dispatch::form` does full path splitting for the same construct (:322-487). Which one runs depends on the entry point.
