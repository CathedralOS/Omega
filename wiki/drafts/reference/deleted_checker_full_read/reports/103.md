## What this code is for
The slice holds four modules of the old contract-entailment checker. `specification_calls` (38790-43867) checks that an expression written inside a contract, a data predicate, a constant expression or a proof body is "formed": every call, operator, index, cast and payload projection in it must have a selected contract owner, well-typed arguments, and `requires` clauses that follow from the facts written before it in the same specification. Its submodule `applied_bindings` (38791-41129) works out what a call's static arguments (types, constants, runtime values, machines, trait implementations, lifetimes) bind to, so that a callee's contract can be instantiated at the call. `static_applications` (43868-44390) judges the `requires` clauses of a generic machine signature that mention only its constant parameters, with a small three-valued evaluator over a budgeted case split. `strict_arithmetic` (44394-44479) is a thin public entry to the arithmetic engine. `structural_case_arms` (44480-46180) walks the statements of a machine body path by path, carrying a `StructuralJudge` and a name-keyed environment, so that other checks ("visitors") can observe the facts that hold at a given statement, enter callee bodies at call sites, and collect the leaf values of case-split proof machines. Everything here decides by calling the checker's own judges (`StructuralJudge`, the scoped arithmetic engine) and pushing `Diagnostic::error` when they do not answer `Proven`. No test code is in the slice.

## Mechanisms
- **Premise-threading formation walk.** contract_entailment.rs:41956-42579. A recursive walk over one specification expression that carries three lists: facts asserted, facts denied, and match captures (41579-41583). It gives short-circuit meaning to `and`/`or` and to match arms, checks children before the node, and stops checking a node as soon as any child produced a diagnostic (42140-42156). Cycle detection is a stack with linear `contains` (41970, 42139). No depth or size budget. Serves `requires`/`ensures` clauses, data and domain predicates, constant expressions and proof bodies.
- **Building a judge from premises.** contract_entailment.rs:41607-41676. Flattens asserted conjunctions and denied disjunctions with a worklist, keeps only facts that pass `structurally_substitutable_fact`, builds `StructuralJudge::from_declaration_requires`, binds match captures, and feeds each fact with its polarity. Returns no judge at all if any spelling in the premises or arguments names two symbols (41619).
- **Requirement instantiation by two engines.** contract_entailment.rs:42446-42557. A requirement of the callee is tried first on the structural judge under a substitution list `(parameter name, term)` extended with constant bindings, then on scoped integer arithmetic (43744-43823), where parameters become binders mapped to the caller's argument expressions and static constants become integers. Either `Proven` suffices.
- **Acyclicity search.** contract_entailment.rs:43609-43637. Depth-first search over contract owners reached through calls in `requires` facts, with `active` and `complete` vectors of symbols. No budget.
- **Static-requirement evaluator.** contract_entailment.rs:44211-44389. `judge_alternatives` splits each positive hypothesis: `and` into two hypotheses, `or` into two worlds that must agree (`Proven, Proven` or `Refuted, Refuted`, else `Unknown`). Budget: 4096 steps per requirement (43979) and depth 128 (44219, 44279); exhausting either gives `Unknown`. `judge` is a three-valued evaluator for boolean literals, bound boolean constants, `not`, `and`, `or`, boolean equality, and otherwise the scoped arithmetic engine. Serves generic machine signatures with const or value parameters.
- **Dependent result types compared up to renaming of formals.** contract_entailment.rs:40572-40601, 40666-40689, 40768-40796. Each formal is given the identity string `"\0public-result-formal:{position}"` in both the requirement and its generated slot copy, and the two result types are compared by `try_normalized_index_identity` text. `value_index_names` (40713-40767) is a worklist over type references and const-expression nodes that collects the names a type's value indices read. Serves result types like `Counted<(source.bytes.len)>` (comment 42918-42925).
- **Finding a type reference by its identity text.** contract_entailment.rs:39459-39493 and 43036-43057. To express a substituted type the code computes the identity of the substituted type and then scans every entry of the type-reference table for one with that identity; `result_reference_for_identity` memoises the answer in a mutex-guarded map keyed by the identity string. If the program has no such reference written anywhere, the look-up fails and the caller returns `None` (43056) or falls back to the unsubstituted reference (39456).
- **Applied binding intake.** contract_entailment.rs:40166-40516. One pass over the callee's static parameters against the retained bindings of a static application, producing five lists (types, constants, runtime parameters, machines, implementations) plus lifetime-region pairs (39802-39832, via `borrow_contracts::resolve_callable_lifetime_bindings`). `transport_parameters` (40127-40164) renames the binders from the public signature to the implementing machine.
- **Completed-arrival memo.** contract_entailment.rs:44489-44594. A `HashMap` from a bucket (state, start index, flag, 64-bit hash of the environment) to earlier arrivals; a hit requires exact equality of inputs, path, parameter names, environment, hypotheses, equations, citations and guarantees (44527-44552) and a different parent (44581). Stops the body walk from repeating a state reached again with the same facts.
- **Entering callee bodies.** contract_entailment.rs:44658-44862. For each call in a statement whose selected contract is a concrete machine, the walk obtains pre-call frames from the judge (`completed_observations`, 44911-44918), binds the invocation (`bind_invocation`, 44822-44828) and recurses into the callee's entry state. Recursion is cut by the `path` list of states (44699, 44728). A prefix that could not be fully observed aborts the whole walk (44922-44924).
- **Path-set forward walk of one state.** contract_entailment.rs:45465-46123. Follows `finite_execution_order` (45478-45485), keeps a vector of active paths each with its own judge and environment, splits a path per outcome of a local binding, assignment, expression or call, merges outcomes that added no effects or guarantees (`rejoin_pure_outcomes`, 45795-45846, 45907-45926), prunes contradictory paths with a memo keyed by (integer premise revision, number of guarantees) (45597-45612), and after the straight-line prefix processes guarded transitions in order. Gives up, leaving a visitor unvisited, on any statement kind it does not list (45959).
- **Two liveness scans.** contract_entailment.rs:45339-45454. `local_symbol_is_dead_in_remaining_prefix` and `local_symbol_is_never_branched_on_in_remaining_prefix` scan the remaining statements for mentions of a local, the second also following copies into locals whose names start with `__` (45445-45451). They decide whether split outcomes of a local can be merged.

## Surprises
- **Property 1 holds without exception here.** No line in the slice mentions `proof_admission`, `ProofNode`, `verify_obligation` or a certificate (checked by search after reading). Every acceptance is a `Proven` returned by `StructuralJudge`, the scoped arithmetic functions or `arithmetic_judgment::Engine` (contract_entailment.rs:41814-41817, 42527-42544, 43814-43822, 44471-44477). The only record handed onward is the list of deferred `IntegerRangeObligation`s (41355, 42180).
- **Some `requires` shapes can never be proved inside a specification.** At contract_entailment.rs:42490-42560 a requirement is judged only if it is a plain expression and the call is "plainly selected". A callee requirement written as a named-domain membership, or as a proposition outside the named-evidence lane, has no expression, so `proven` is `false` and the call is always refused with "cannot prove requires contract". The same holds for a direct member call such as `Write::try_from(value)`: its owner is `Concrete` and it carries a static requirement dispatch (42637), so `arguments_select_plainly` is false (42485-42489) and any `requires` on the member is reported unproved without being examined.
- **A guard is compared with itself.** contract_entailment.rs:45076 calls `guard_expressions_equal(program, first_condition, first_condition)` in the unguarded-second-transition branch. Given the function body (45129-45154) this is true exactly when the condition is built only from boolean and integer literals, names and binaries, so it acts as a shape filter, but it reads like a slip for a comparison that was never needed.
- **"Structurally false" is decided from the unsubstituted clause.** contract_entailment.rs:42562-42572 says "the instantiated fact is structurally false" only when the callee's requirement expression node is the literal `false`; no instantiation is consulted.
- **Two definitions of "unsigned".** `unsigned_integer_atom` lists `U8`, `U16`, `U32`, `U64` only (contract_entailment.rs:44421-44427); the other three atom sites use `!primitive.is_signed_integer()` (43737, 44069, 44097). An `addr`-like primitive is unsigned under one and not under the other.
- **A left operand whose check was deferred is not used as a premise.** contract_entailment.rs:41999-42001 adds the left side of `and`/`or` to the premises only if it added neither a diagnostic nor a formation obligation. So `a and b` where `a` contains a pending `addr` fit forms `b` without `a`.
- **Value patterns never become premises.** In a specification match only destructuring arm conditions are assumed in the arm and denied afterwards; a value-pattern arm is neither (contract_entailment.rs:42072-42075, 42096-42103, 42120-42122).
- **Diagnostics from a child suppress all checks on the parent** (contract_entailment.rs:42140-42156), and the count of diagnostics is the signal used for "formed" (41999, 42056, 42098). Formation status is therefore inferred from the length of the diagnostics vector.
- **A user-facing diagnostic carries an internal dump.** contract_entailment.rs:42317-42344 appends "; untyped call `..` target `..`, source `..` / `..`, selection `..` / `..`, public result `..`" for each untyped call operand.
- **Trace printing is compiled into the checker.** `eprintln!("STRUCT ...")` under `struct_trace()` appears at contract_entailment.rs:39792-39796, 39853-39860, 39875-39880, 39894-39896, 39902-39909, 39950-39952, 39969-39977, 40200-40204, 40220-40231, 42522-42524, 44973-44979. Several refusal reasons (the `&'static str` errors of 38838-38955, 39035, 39398-39423) are visible only through this trace; the user sees the generic "cannot prove requires contract" text.
- **Signatures are compared by Rust pointer.** `std::ptr::eq` decides whether two `StateSignature`s are the same at contract_entailment.rs:39941 and 43166.
- **Owner selection order can hide bodies.** `selected_contract_by_symbol` prefers a dynamic slot, then a signature found by `signature_by_symbol`, then the entry machine's signature, then an operator, and only last the concrete machine (contract_entailment.rs:42753-42781). `observe_calls` enters only `Concrete` owners (44719-44723), so a call target for which a signature is found is not entered by the body walk even when a concrete machine exists.
- **Substituted types must already exist in the program.** contract_entailment.rs:43050-43056 and 39473-39486 can only name a substituted type if some type reference with that identity was already written; otherwise the call's parameter scope is `None`. Whether a program is accepted can depend on an unrelated type annotation existing elsewhere.
- **A `HashMap` keyed by a hash of `Debug` text** sits in the walk (contract_entailment.rs:44485, 44514-44524, 44570). Hits are confirmed by exact comparison, so a collision cannot cause a wrong skip, but the bucket is recomputed with `format!` for every arrival.
- **`contains_completed` requires a different parent** (contract_entailment.rs:44581) while `complete` deduplicates on the same parent (44588-44590). The same arrival from the same parent is therefore never reported as already completed.
- **A merged boolean local becomes an invented captured value.** When split outcomes of a `bool` local are merged, the code mints `StructuralTerm::CapturedValue` with an invalid statement handle, an invalid callable and a fresh occurrence number, carrying the join of the outcomes' integer ranges (contract_entailment.rs:45830-45844).
- **Hypothesis atoms are made for the parameters of every state** of the calling machine (contract_entailment.rs:44074-44101), while hypotheses are taken only from the machine's and the one caller state's `requires` (44102-44110).
- **Effect inference may be rerun per query.** `body_can_be_observed` calls `infer_operational_may` and `infer_service_reaches` over the whole program when no prepared plans exist (contract_entailment.rs:44983-44992), and it is called once per call occurrence (44736-44741).
- (second read) **The slice ends on a 19-parameter wrapper.** `recognize_structural_state_leaves` (contract_entailment.rs:46125-46169) clones the judge and forwards its 19 arguments plus a start index of 0 to `recognize_structural_state_leaves_from`, whose body is in the next slice. Three of the arguments are keyed by name text (`parameter_names: &[String]`, `environment` and `case_hypotheses` as `Vec<(String, StructuralTerm)>`, 46134-46136). `StateLeafStep` (46171-46178) is the step result: either finished case arms or a list of `(optional value, judge)` outcomes to continue from.
- (second read) **The contradiction memo is cleared by a skipped guard.** After a guard is assumed false the new path's `checked_contradiction_state` is `None` (contract_entailment.rs:46105), so the next transition site tests the judge again; when the guard's truth is unknown the old memo is kept (46107).
- **Capabilities worth knowing existed:** short-circuit and match-arm premise threading for specifications (41982-42123); comparison of dependent result types up to renaming of formals (40572-40796); path-sensitive forward execution with merge of pure outcomes (45465-46123); entry into callee bodies for observation (44658-44862); a named-evidence lane for `requires` propositions (42469-42484); ex falso in both the arithmetic entry (44467) and the path walk (45603-45610).
