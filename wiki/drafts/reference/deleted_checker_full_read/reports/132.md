## What this code is for
The file holds two modules of the old source checker. `type_references` (F:5-5600) checks every place a type is written in source: type aliases, generic data applications, `dyn` traits, references and lifetimes, fixed arrays, constrained types (`in finite`, `in Domain<..>`, `in OmegaLayout<..>`), and const/value/machine/implementation arguments to generic data. It also decides whether a const argument is a closed, canonical value of the right carrier type, evaluates closed boolean/integer predicates of data `requires` over canonical const values, and normalizes "open index expressions" (`N + 1` over const binders) by selecting algebra operations from trait conformances. `wire` (F:5602-6806) checks wire schemas (numbered fields, retired numbers, version eras) and evaluates "wire compatibility demands" between a local and a peer schema (readable, writable, unknown-preserving, canonical, migration-covered). The checker works on the typed tree (`CheckingInput`), pushes `Diagnostic`s into a Vec and returns nothing; where a value fact cannot be decided it pushes `IntegerRangeObligation`s outward (F:1446, F:1749-1753) for other code to discharge. No proof kernel call occurs in this slice.

## Mechanisms
- Closed scalar evaluator (F:305-504). Computes a bool/i128 value of a data `requires` predicate over a completed canonical record or variant. Recursive with depth cap 128 (F:315, F:570). Fragment: integer/bool literals, one-segment names bound to a field or evaluated const, `not`, `and`/`or` (left side short-circuit, F:440-452), six integer comparisons, bool `==`/`!=`, case membership (`x == Case`) against the active variant (F:523-558), member projection through nested records/variants (F:560-657), and calls to admitted integer predicates (via `closed_integer_predicate_value`, F:411-415). Anything else is `Err`. Serves default-domain `requires` on data used as const index values.
- Closed const normalizer (`closed_expressions::Context`, F:1132-1403). Builds a `DecodedCanonicalConstValue` from an expression and a carrier type. Cycle check via `active` stack, depth cap `MAXIMUM_DEPTH`, node cap `MAXIMUM_NODES` (F:1146-1157). Each result is revalidated against the carrier by `validate_decoded_structured_const` (F:1163). Serves const arguments to generic data, domains, array lengths.
- `AppliedValueCarrier` (F:1797-2034): a type reference plus the parameter/argument telescope it is applied under. `resolved` substitutes a type parameter by its argument (F:1872); `identity` computes a normalized type identity with simultaneous substitution (F:1943-1962) or with static machine arguments (F:1915-1942); `array_length` closes an array extent from a literal, a const param value, a named const, or a parsed name (F:1971-2033). Serves const-argument carrier matching.
- Canonical const validation (F:2611-2815): structural walk comparing a decoded value to a data declaration; `visiting` stack for recursion; runs `const_predicates::validate` (F:2707, F:2778, F:2786) per record/variant.
- Exact-cohort eligibility (F:2514-2585): recursive structural check with `visiting` set against recursive data.
- Open index normalization (F:3266-3373): collects all domain const-argument sites and indexed-qualification casts, finds the owning machine of each expression by walking its leaves (F:3418-3446), picks the unique matching conformance operation for each `+ - * /` node (F:3448-3516, F:3518-3570), reads the declared algebra laws (commutativity, associativity, distributivity, left/right identity literals F:3540-3566), and writes `OpenIndexNormalization { normalizer_version: 4 }` and operation selections into the expression table (F:3349-3368), only if no diagnostics. A second pass `bind_machine_index_operations` (F:3572-3634) does the same for expressions inside machine contracts/statements, selecting only when exactly one candidate exists, silently skipping otherwise.
- Type-reference walker `validate_type_reference_node` (F:5080-5469) with a `TypeReferenceOwner` carrying the placement (14 variants) and a `generic_depth`; owner decides `is_runtime_value_position` (F:4603) and value-formation facts (F:967-1014).
- Era selection (F:5820-5849): exact path match, else `::`-suffix match among candidate paths; 0/1/many gives Missing/Resolved/Ambiguous.
- Migration route search (F:6049-6078): depth-first (stack `pop`) search with a `visited` Vec over a list of (old, new, machine) edges; first route found is returned (not shortest). Edges that are uniquely bound are preferred (F:6012-6019); if only an ambiguous route exists the error lists the doubly bound edges.
- Retired identity reuse scan (F:6154-6215): walks eras in route order, accumulating retired numbers per scope (Fields, Cases, Payload(case)) and numbers dropped between eras, and reports the first live number that was retired earlier.
- Quadratic scans: pairwise duplicate detection by `[..index].iter().any` (F:6485, F:6550, F:6593, F:6620); `Vec::contains` for visited sets (F:6071, F:5536-5546). No explicit budgets besides depth 128 and canonical limits.

## Surprises
- The slice contains no use of the proof kernel (`proof_admission`, `ProofNode`, `verify_obligation`, certificates). The verdict is the code's own boolean/diagnostic. The only proof-flavoured hand-offs are `IntegerRangeObligation` lists (F:1446, F:1749-1753, F:2322-2333) that the code passes outward, and the calls to `proof_contracts::*` helpers. One such handoff is dropped on one path: `check_closed_const_expression_in_carrier` returns `Ok(None)` when obligations exist (F:1446-1448) and the caller `alias_arguments::validate` then continues to the generic checking with a fresh `obligations` argument (F:153-160, F:171-186). Whether the original obligations are re-created in the continued path cannot be seen here.
- The wire compatibility check decides "compatible" by comparing field numbers and rendered type strings (F:5904-5920), and treats shape equality as both readable and writable (F:5637-5642); the "strict decoder" accepts only equal shapes (cases: every writer case must exist in reader with equal payload; extra reader cases fine; fields: sets must be equal), so adding an optional field is never compatible without a migration route. `readability` and `writability` are the same relation with arguments swapped, so for cases they differ, for plain fields they are equal in both directions.
- `schema_accepts` for a plain-fields shape is symmetric equality; for cases it is directional (F:5889-5902), but when only one side has cases `writer.cases.iter().all(...)` over an empty writer list is vacuously true if the writer has none (F:5891).
- Migration route search is DFS using `pop`, so the route returned is not necessarily the shortest, and only the first route found is reported (F:6056-6076). The "certified edges" step filters out any (old,new) pair bound by more than one machine before searching (F:6012-6019), so ambiguity only surfaces as an error if no unambiguous route exists.
- `retired_identity_reuse` treats a number as retired when an era drops it without listing it (F:6193-6205), so dropping an identity implicitly retires it for later eras, even though the schema validator (F:6785-6799) requires an explicit `retired n;` tombstone for the `wire`-schema form. The two mechanisms apply to different forms (`WireSchema` vs ordinary data with identity numbers) and are written separately.
- `ordinary_data_shape` returns `None` for data with no identity metadata (F:6360-6362); such data cannot be named in a wire demand. A row for a generated `WireSchema` is merged with an ordinary data of the same qualified path and the data's cases override the schema's (F:6304-6312).
- `exact_const_primitive` only returns a primitive when `name == primitive.name()` (F:2863), so a type alias or renamed builtin symbol is refused as a const carrier. `f32`/`f64` const carriers are excluded everywhere (F:2880, and `exact_structured_const_carrier_is_eligible` accepts only Bool and integer primitives F:2522).
- `data type "Rat"` is excluded from const-value eligibility by name (F:2547), a hard-coded special case in an otherwise symbol-driven check.
- `value_formation_facts` reads `requires` facts from the machine contracts only when the signature is the machine's first state (F:986-995), i.e. entry-state identity decides which contracts count as prior facts.
- `match` guard in `constraint_validation` has a match on a single-variant enum `ValueDomain::Finite` with a duplicate empty arm (F:735-748), `validate_scope_field_types` has a dead trailing `if ... { continue; }` (F:6650-6652), (see next item for `type_references_match`).
- `type_references_match` treats two invalid handles as equal (F:5567-5569) and otherwise compares normalized type identity (F:5574).
- `validate_indexed_domain_argument_pack` unwraps by `unreachable!()` in `const_binder_type_reference` if the binder is not Const/Value (F:3783), relying on the earlier `is_const_or_value` filter.
- Normalizer version is a literal `4` (F:3342) written into the expression table by this validator: the validation pass mutates the program (`normalize_open_index_expressions(program: &mut TypedTrees)`, F:3266-3373), unlike the rest of the file.
- `AppliedValueCarrier::matches` uses `identity()` and compares `NormalizedTypeIdentity`, so most carrier comparisons are by normalized type identity (a structural value), not by text, but `canonical_carrier_label` text is used for the canonical atom's `type_name` and compared as text against the value (F:2210, F:2350, F:2416, F:2660).
