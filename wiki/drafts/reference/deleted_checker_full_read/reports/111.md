## What this code is for
The slice holds two and a half top-level modules of the old checker's proof-contract code.

`bound_expression_meaning` (dp.rs:6-1664) answers one question many times: does this operator, comparison or case test in a bound, guard or fact carry the language's built-in meaning, or could it be a user-defined operator? Other checker code only reasons about an expression arithmetically when this module says yes.

`collection_predicates` (dp.rs:1666-7278) reasons about user-written predicate machines, which are pure machines that return `Bool`, such as "this array is sorted". It contains two separate engines. `exploration` (dp.rs:1667-2812) runs a predicate over sets of integers and reports which argument values make it true or false. `implication` (dp.rs:2813-6468) is a symbolic executor with its own small theorem prover: it proves that a machine's `requires` premises imply a goal expression (`premises_prove_expression`, dp.rs:7271-7277), and it derives ordering facts that follow from a predicate call. The top of the module (dp.rs:6470-7278) turns those results into consequences other code consumes: intervals, element bounds, orderings, and whether a `data` type's `requires` fact holds for a zero value.

`default_domains::assignment_windows` (dp.rs:7281-8315) tracks, statement by statement, whether a write to a field of a `data` value has broken that data type's `requires` facts, and refuses to leave a state while they are unproved. The slice ends at line 8315, where `assignment_windows` closes; the rest of `default_domains` is outside it.

## Mechanisms
- **Memoized built-in-meaning query** (dp.rs:489-545). Caches the answer per binary expression. The cache key identifies the machine and state by their pointer offset inside the program's slices (513-545). Serves every feature that reads operators in facts and guards.
- **Bounded tree height** (dp.rs:599-701) and several other depth-128 walks (324-342, 1202-1256, 1267-1334, 1482-1505). They compute a height or a type and stop at depth 128.
- **Interval-set abstract interpretation of predicate machines** (`exploration`, dp.rs:1667-2812). Each argument is a set of integer ranges ("atom"). The engine runs the predicate's states with a frame worklist, joins outcomes, requeues on change (2137-2212), and splits an atom when an index is not a single value (2608-2616). Budgets: 16,384 work units, 4,096 array elements, 64 ranges per set (1687-1689), nesting 64. Result: the sets under which the predicate returns true and false (`Unfolding::decided`, 6911-6918). Serves `data` `requires` facts, predicate intervals and constant predicate calls.
- **Symbolic execution with path conditions** (`implication`, dp.rs:4193-6072). A `Path` carries integer comparisons, clauses (disjunctions), array read observations and storage homes (4235-4241). Values are symbolic integers, booleans, records and collections (4193-4224). Arrays follow a select/store discipline: `read` walks stored updates and earlier observations and splits the path when it cannot decide whether two indexes are equal (5466-5560). Records keep per-field observations and updates (3415-3585). Mutable storage is modelled by homes and places, and a reference argument aliases the caller's place (3729-4191). Budget: 8,192 work units (4501), depth 64 (4587, 5171, 5573), depth 32 for subject enumeration (3597).
- **Refutation prover** (dp.rs:4966-5118, 6236-6360). To prove a clause it adds the negation of each literal and asks whether the comparisons are unsatisfiable. It first splits the comparisons into connected components by shared atoms (6315-6360), then case-splits on clauses with a budget of 256 consultations (5006-5027, 6220). Booleans become clauses with a cap of 64 (6236-6285, 6221). The arithmetic answer comes from `scoped_arithmetic_comparisons_unsatisfiable` in another module (4967). When a budget runs out the prover answers "not proved".
- **Induction over recursive predicates** (`activation` / `generalized_activation`, dp.rs:5562-5891). Before walking a predicate body the engine pushes a lemma: "for these arguments under these premises, the goal holds" (5870-5879). A recursive call to the same machine, state, judgment and goal may use the lemma if its premises are implied after substitution and one integer argument moved strictly in one direction (5596-5626). Integer arguments are first replaced by fresh atoms bounded by their carrier so the lemma is general (5679-5733). A recursive call that matches no lemma fails (5628-5630). Two judgments exist: `Consequence` (the call being true implies the goal) and `RequiredResult` (the call returns true) (4262-4266).
- **Candidate enumeration with a necessary/sufficient test** (dp.rs:2843-3081 and 4353-4499). The code lists candidate conditions (boolean subjects, comparisons found in the entry state, then every pair of integer subjects times six operators) and keeps those the prover shows necessary; `exact_conjunction` stops when the kept set is sufficient.
- **Enclosed-field traversal for partial writes** (dp.rs:7697-7785). A worklist descends from the written place through arrays, slices and data fields and lists every field underneath. Budgets: 16,384 visits, depth 256.
- **Invariant windows** (dp.rs:7357-8285). Each tracked place records whether its facts are established, which requirements are pending, and whether a window is open. Places are keyed by a rendered spelling string.
