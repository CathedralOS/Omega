## What this code is for
This slice is not checker code. It is the last two stages of the old target-neutral pipeline: stage 07 optimizes the lowered program (`LoweredPsi`, which wraps a `TerminalModule`), and stage 08 publishes the optimized module as a Terminal Psi product.

Stage 07 runs up to five rewrites chosen by the caller: folding a branch on a constant condition and deleting the blocks and machines that become unreachable (`cfr.rs:14-222`), constant folding (`passes.rs:14-77`), removing block parameters that always receive the same value (`passes.rs:134-283`), removing duplicate pure operations (`passes.rs:390-486`), and removing unused pure operations (`passes.rs:600-658`). Most of the code is not the rewrite itself. It is the work of finding every block, edge, operation and value that some proof or source-correspondence table names by id, so that the rewrite leaves those alone (`cfr.rs:249-617`, `cfr.rs:719-965`). `run_psi_optimization` computes a semantic identity of the module before and after and seals both into a `PsiOptimizationStageResult` that only it can construct (`opt.rs:18-64`, `opt.rs:81`).

Stage 08 has two parts. `finalize_terminal_program` validates activation storage and wraps the module as either a portable artifact or an invocation-local code carrier (`08/lib.rs:33-62`). `verify_boundary_result_policies` is an audit that compares each float-returning boundary call in the Terminal module against the old checker's fact tables (`CheckedTrees`), and checks that the call is followed by exactly the float result adapter the source selected (`rpv.rs:277-498`). The 08 README says production does not run this audit (`08/README.md:23-25`).

## Mechanisms
- **Branch folding with a removability gate** (`cfr.rs:14-81`). The pass maps each `BooleanConstant` result to its value, then for each `Conditional` on such a value builds the replacement `Jump`, computes which blocks become unreachable from the entry (`stranded_blocks`, a worklist, `cfr.rs:83-117`), and commits only if every one is removable. No budget. Serves dead-branch removal while keeping proof and ranking ids.
- **Machine pruning fixpoint** (`cfr.rs:171-222`). Start from the root set, close it under calls, evidence calls, cleanup machines and closed-reach callees (`machine_transitions`, `cfr.rs:534-575`), collect evidence ids from the kept machines, add any unkept machine that contains one of those ids, and repeat until the kept set stops changing. No budget; it ends because the set only grows.
- **Evidence inventory** (`cfr.rs:286-366`). One function walks about a dozen module tables and four per-machine tables and puts every named block, edge, operation and value into four sets. Every pass's safety depends on this list being complete.
- **Constant folding to a fixpoint** (`passes.rs:38-76`). The pass sweeps all operations repeatedly, replacing an operation by a constant when `constant_goal_free_scalar_leaf` returns a literal, until a sweep changes nothing. It is named "sparse conditional constant propagation" but has no reachability lattice and does not look through block parameters.
- **Block-parameter collapse** (`passes.rs:201-322`). `raw` maps each parameter to the argument at its position on every incoming Jump/Conditional edge. `resolve_in` follows these chains with a memo table and a `visiting` set that stops on cycles. A parameter collapses when all resolved arguments are one value of the same type and qualifications. Removed positions are then dropped from every edge (`07/lib.rs:41-78`).
- **Dominator-based value numbering** (`passes.rs:425-575`). Blocks are visited in reverse postorder (`terminal_semantics::control_graph::finished_order`). Dominators are full sets per block, computed by iterative intersection. Leaders are a `Vec` searched linearly, so the cost is quadratic in operations; there is no budget.
- **Ranked coverage** (`cfr.rs:826-849`). Asks `scalar_demand::ranked_coordinates` for the blocks and values that termination evidence covers, then records every scalar used inside those blocks. It clones each operation kind and terminator to call `map_scalar_uses` as a visitor.
- **Shape recognizer for saturation eligibility** (`rpv.rs:22-274`). Starting from the `eligible` value, it walks definitions backwards and accepts one shape: `conjunction == 1u8`, where the conjunction is a tree of `u8` bitwise ANDs whose leaves are byte views of `not (bits & mask == constant)`. Mask `0x7f80_0000` / `0x7ff0_0000_0000_0000` compared with itself means "finite"; mask `0x7fff_ffff` / `0x7fff_ffff_ffff_ffff` compared with 0 means "nonzero" (`rpv.rs:187-226`). The list it reads off must equal the expected list in order (`rpv.rs:73`). If `eligible` is a boolean constant, it instead evaluates the predicates on float constants (`rpv.rs:229-274`). Budget: 4,096 definition lookups; running out returns false (`rpv.rs:48`, `rpv.rs:81`). Each lookup is a linear scan of all the machine's operations and requires a unique definer (`rpv.rs:82-89`).
- **Roster counting** (`rpv.rs:282-304`, `rpv.rs:494-496`). Three independent counts must agree, which catches an adapter with no verified call and a source policy with no adapter.
- **Sealed result type** (`opt.rs:73-100`). Privacy, not checking, guarantees stage 08 receives a module that went through `run_psi_optimization`.

## Identity by text
- The audit decides that a boundary call still targets the original source declaration by comparing two strings: `module.identities.text(declaration.identity)` against `requirement_identity(checked, target)` (`rpv.rs:395-399`).
- `requirement_identity` builds that string three ways: a rendered operator requirement identity (`rpv.rs:504-513`), a rendered machine callable identity text (`rpv.rs:518-526`), or, for any other machine, the bare `machine.name` (`rpv.rs:527`). In the last case two machines with the same short name in different packages would compare equal here; I cannot tell from this slice whether the identity table stores a qualified name for them.
- All diagnostics from the audit are `&'static str` (`rpv.rs:281`); a caller can tell failures apart only by comparing text.

Everything else in the slice identifies things by typed ids (`ValueId`, `BlockId`, `EdgeId`, `OperationId`, `MachineId`, `SymbolHandle`). This is evidence against property 2 for these two stages. Two things are identified by position instead of by id:
- The adapter is "the next operation in the block" (`rpv.rs:424-427`).
- A qualification row names its jump argument by position, which is why copy propagation must keep every parameter of the receiving block (`passes.rs:337-340`). `prune_debug_map` pairs old and new machines and blocks by index with `zip` (`cfr.rs:928-939`), so it is correct only for passes that do not remove or reorder machines or blocks.
- A source call is located by source coordinates (state symbol, statement index, call ordinal, authored expression) rather than by an id carried through lowering (`rpv.rs:378-388`).

## Surprises
1. **This slice contains no checker rule about source programs.** It is an optimizer, a publisher and one audit. The audit (`rpv.rs`) is the only file that depends on the old checker: it reads `CheckedTrees`, `checked.facts.operators.for_each_resolved_expression_selection` and `checked.facts.flow.control.calls` (`rpv.rs:6`, `rpv.rs:290-293`, `rpv.rs:368-388`). That dependency is the visible reason it went with the checker.

2. **Facts already belong to values here.** Qualifications sit on the value declaration (`ValueDeclaration.qualifications`), and both copy propagation and value numbering refuse to merge two values whose qualifications differ (`passes.rs:246-249`, `passes.rs:455-456`). This is the model the new design describes, already present in the old lowered form.

3. **The optimizer's main cost is side tables that name values by id.** Proof and source-correspondence data live in about 25 module tables outside the control-flow graph. A rewrite cannot rename an id inside those tables, so each pass must find every id they name and leave it alone. The four passes build that list four different ways:
   - Control-flow cleanup: named rows, callbacks, interrupt registrations, coercions, returns, entry ranges, block invariants, crash contracts, proof-output calls, reborrow restorations, content ancestry, closed-reach calls, partition compositions, contracts, source calls, selected comparisons (`cfr.rs:286-366`, `cfr.rs:626-648`).
   - Copy propagation: named rows, block invariants, qualification blocks, return rows, ranked values, contract, crash routes, call erased arguments, jump and conditional erased arguments, crash site guards, source-call frontier (`passes.rs:330-361`, `passes.rs:144-200`).
   - Value numbering: named rows, boundary-application results, ranked values, contract, crash routes, call erased arguments, crash site guards, source-call frontier (`passes.rs:584-585`, `passes.rs:400-424`). It does **not** add block-invariant values, return rows, coercion rows or the erased arguments on Jump and Conditional edges, all of which copy propagation adds explicitly. If `record_named_rows` does not cover them, value numbering can delete an operation whose result an invariant, a return row or an erased edge argument still names. `record_named_rows` is outside this slice, so I cannot confirm; the comment at `passes.rs:356-358` shows this kind of dangling id did happen in copy propagation.
   - Dead scalar elimination: named rows, boundary results, invariants, all source-call frontiers, qualification blocks (`passes.rs:625-636`); the rest is inside `complete_scalar_demand`.
   No pass retains a Jump's `erased_proof_arguments`, `structural_arguments` or `cleanup_actions` (fields at `cfr.rs:65-67`); whether `map_scalar_uses` rewrites them cannot be told here.

4. **Two different policies protect termination evidence.** Branch folding and constant folding skip any machine with `ranked_scc` entirely (`cfr.rs:20-22`, `passes.rs:18-20`). Copy propagation and value numbering work inside such machines and protect only the covered blocks, values and uses (`passes.rs:228-240`, `passes.rs:447-449`), and skip the machine when `ranked_coverage` returns `None` (`passes.rs:139-143`, `passes.rs:395-399`). `ranked_coordinates` is outside the slice, so I cannot tell whether an unranked machine yields `None` (in which case these two passes run only on ranked machines) or an empty coverage.

5. **Four selectable optimizations are empty.** `ProofCheckElision`, `StateSpecialization`, `RepresentationSpecialization` and `LoopInvariantScalarMotion` do nothing (`opt.rs:48-51`) and still appear in the sealed execution record. A reader of an artifact's provenance would see "proof check elision" selected when no code ran for it in this stage.

6. **"Sparse conditional constant propagation" is plain constant folding.** There is no executable-edge tracking and no propagation through block parameters (`passes.rs:14-77`). Branch folding lives in a different pass and reads only literal `BooleanConstant` operations (`cfr.rs:23-32`), so folding a branch on a computed constant needs constant folding to have run first in the selection order.

7. **Branch folding can skip blocks.** The loop indexes `machine.blocks` by `position` and removes stranded blocks inside the loop (`cfr.rs:77`), then increments `position` (`cfr.rs:79`). If a removed block sat before `position`, the next block is skipped and its conditional is not folded. This loses an optimization, not correctness. Also, `stranded_blocks` returns every block unreachable from the entry, including ones that were already unreachable before the fold (`cfr.rs:111-116`); one such block that is not removable blocks every fold in the machine.

8. **README claims that the code in this slice does not show.**
   - `07/README.md:4-5` says the stage "records input/output semantic and proof identities"; the code records two semantic identities only (`opt.rs:60-62`).
   - `07/README.md:3-4` says it "validates the complete input … validates the output"; the code computes an identity (`opt.rs:22`, `opt.rs:55-59`).
   - `07/lib.rs:14-16` says every published artifact records the identities; `finalize_terminal_program` drops the execution record and the debug map for `Invocation` publication (`08/lib.rs:40-41`, `08/lib.rs:56-60`).
   - `08/README.md:3` links "publish_artifact.rs" to `src/lib.rs`; there is no such file, only an inline module (`08/lib.rs:30`). "Entry receipts" and "Receiver eligibility" (`08/README.md:13-15`) also link to `src/lib.rs`, which only re-exports `terminal_codec::entry_receipt` (`08/lib.rs:28`, `08/lib.rs:65-67`) and contains no receiver-eligibility code.
   - `08/lib.rs:41` discards the third part of `LoweredPsi` with `_`, while `08/README.md:6` says "only source-join records remain alongside it".

9. **The eligibility recognizer accepts one emitter shape and nothing else.** It does not decide whether `eligible` means "inputs finite and divisor nonzero"; it decides whether the operations look exactly like what the emitter writes, in argument order (`rpv.rs:62-73`). Any equivalent formulation (a different mask, a boolean AND instead of a `u8` AND, predicates in another order, a value routed through a block parameter) is refused. An integer divisor is refused outright (`rpv.rs:41-42`). So it is a check that the emitter was not changed, usable only against that emitter. Stage 07's own passes could break the shape: value numbering can merge the two byte-one constants or duplicate views, which the recognizer tolerates because it follows definitions by id, but a pass that folded the conjunction partially would be refused.

10. **Copy propagation shares one mutable retained set across machines** (`passes.rs:137`, `passes.rs:362-367`), so each machine's contract and ranked values stay retained for all later machines. Value numbering clones the set per machine instead (`passes.rs:400`). The first is more conservative and order-dependent; the difference looks accidental.

11. **`ranked_coverage` and the audit clone to visit.** `map_scalar_uses` is a rewriting function used as a read-only visitor by cloning each operation kind and terminator first (`cfr.rs:836-846`, `rpv.rs:478-486`). There is no read-only visitor for scalar uses in this slice.

12. **Property summary for this slice.** Property 1: holds in the sense that every decision here is the code's own set-membership, equality or shape test, and the one independent audit is not run in production; nothing consults a proof kernel. Property 2: mostly does not hold; ids are typed, with one text comparison of boundary identity that can fall back to a bare machine name (`rpv.rs:527`). Property 3: holds in a changed form; the repeated unit is "per value-declaration site", "per call variant", "per side table" and "per pass" rather than per source placement.
