## What this code is for

This slice is the second half of the "published" layer of the old checker: the code that turns a typed program into the tables (`ProofFacts`, `FactPlan`) that later checking rules and later compiler stages read. It does three jobs. First, it binds "proof-output calls": a call whose callee publishes named `ensures` evidence, which the caller destructures into a runtime `value` and named evidence terms (`bind_proof_output_call_facts`, 5363-5942). This part does refuse programs, with about 45 distinct diagnostic reasons. Second, it assembles the whole `ProofFacts` table: obligations, contract facts for machines, states, trait signatures, operators, evidence terms, call rows, exit rows and the proposition vocabulary (`build_proof_facts`, 6680-6883). Third, it builds the "semantic facts" plan (`build_semantic_facts`, 10257-10273): for every contract, call, state parameter and zero-initialized local it writes a `Fact` row saying "this property holds of this storage place at this program point", plus `StorageDependency` rows that make a later write retire the fact. A large part of the slice translates a callee contract's places (`result`, parameters, `self`, field paths) into the caller's places at one call (`mod places`, 10352-11053). Most of this code decides nothing itself about whether a program is correct; it states premises and obligations that other code consumes. When it cannot build a row it usually returns or continues without a diagnostic.

## Mechanisms

- **Transitive trait-requirement search** (6198-6220). Depth-first walk over `program.trait_requirements` with a visited list of symbols; returns true if the required trait is reachable. No budget; the visited list ends it. Serves static requirement dispatch declared on a parent trait.
- **Evaluate-once dispatch subject** (6928-7070). For each transition statement with a `When` guard, `computed_case_subject` finds the call a case test compares, `evaluated_case_subject` scans all earlier statements of the state for a copy (quadratic in arms), and `statement_dispatch_calls` walks every expression root of the statement with a worklist, marking calls inside a copy as `SavedSubjectRead`. Visited set is a `Vec` searched linearly. Serves closed-case dispatch over a call result.
- **Conjunction decomposition for case atoms** (7443-7485). Worklist over binary expressions; splits only `And` nodes that `validation::has_builtin_decomposed_guard_meaning` approves; collects `validation::applied_case_membership_variant` hits. Serves case observations from contracts.
- **Observation context** (10238-10255, used at 7336, 7424; inline variants at 8268-8295 and 8969-8992). One fact plus one `StorageDependency` row per place it reads, in one context, so a write to any of those places retires the fact. This is the lifetime model for every fact in the slice.
- **Zero-formation walk** (9279-9398 and 9494-9603). Recursive descent over a type: peel domain constraints, expand fixed arrays, descend into record fields and into the first variant's payload. For a top-level fixed array, `zero_cases` emits one `ZeroCaseElements { first: 0, end: length }` row per case position instead of one row per element (9306-9313); nested arrays enumerate every index (9314-9327). `collect_zero_initialized_field_domains` enumerates every index of every fixed array (9536-9545) and adds a whole-extent row (9546-9548). No budget on the enumeration.
- **Deduplicated per-type domain rows** (9630-9656). A `Vec<(TypeReferenceHandle, Vec<FieldDomainRow>)>` memo, searched linearly, so each lent type's declared rows are computed once across all parameters.
- **Parallel bind, ordered seed** (10286-10335). `state_declaration_predicates` and `bind_parameters` run per state on the rayon checking pool; seeding into the `FactPlan` is done afterwards in roster order so handles are deterministic.
- **Call-relative place instantiation** (10422-10523, 10562-10656, 10924-10992, 10999-11047). Recursive translation of a contract expression into a caller place: try an exact argument projection first (`call_contract_argument_projection`, 10529-10560, which requires a single literal projection), else recurse on Borrow/Name/Member/Indexed; fall back to prefix substitution of the parameter root (10861-10916).
- **Exact inherited-application selection** (8136-8186). Iterates the conformance machine's trait conformances, collects the declaring scope of each, refuses (returns `None`) if two candidates are not the same application, then checks every trait argument by type identity.
- **Proposition identity by normalization** (6320-6363, 8735-8900). Render each argument to a label in the caller's terms, hand labels to `program.normalize_nominal_proposition_application` / `normalize_proposition_application`, and use the resulting value (`CheckedPropositionApplication`) or its `identity_label()` string as the identity.

## Accepts or skips without proof

Most of this slice publishes facts, so "skip" here means either "a premise is not stated" (safe direction) or "an obligation row is not stated" (unsafe if nothing else states it). I mark which.

- **Call requirement rows dropped silently.** In `append_call_semantic_contract_refs`: a contract the call "does not own" is skipped (8914-8919); a boolean contract whose label could not be instantiated is skipped (8931-8934); a contract for which `call_contract_evidence` returns `None` is skipped (8945-8947). The same loop builds both `CallRequires` and `CallEnsures` contexts, so on the requires side these drop an obligation row. `instantiate_call_contract_payload` leaves the label invalid when `find_call_site`, `call_target_parameters` or `inherited_satisfier_parameters` fail (8754-8798). Cannot tell from this slice whether the contract checker in `checks::contracts` independently refuses those calls.
- **Proposition rows kept with an empty instantiation.** For `ContractPropositionApplication`, a failed instantiation leaves `instantiated` invalid and the row is still appended (8857-8899; only the boolean case is filtered at 8931). The consumer then sees the callee's uninstantiated schema. Cannot tell how consumers treat it.
- **Domain instance left at the template identity.** `instantiate_call_domain_membership_instance` returns early on nine different failures and on a failed interning lookup (8657-8732), leaving the callee's template `semantic_domain` on the caller's row. The comment says missing evidence "still fails ordinary entailment" (8640-8641); that entailment is outside this slice.
- **Place falls back to the callee's own place.** `instantiate_call_contract_place` returns the declaration place, rooted at a callee parameter symbol, when no substitution is found (10965-10977). A caller-side fact is then stated about a callee symbol. Cannot tell whether any caller place can ever match it.
- **Place falls back to an expression-rooted place.** `contract_fact_place` uses `facts.append_place_from_expression` when the structured place fails (7676-7693); so do member and index receivers (7886-7888, 7929-7931), parameter-domain arguments (9085) and argument substitution (10891-10893).
- **Field segment with an invalid symbol.** When neither the typed tree nor the by-name lookup resolves a member, the code appends `PlaceSegment::Field { symbol: SymbolHandle::invalid() }` and continues (7901 with 7915-7919; 7984 with 7994-8000; 10490 with 10504-10508; 10640 with 10648-10652). Two different unresolved members would then produce equal places. No check visible here.
- **`FactPlace::Unknown` rows.** Dependency places that cannot be instantiated become `Unknown` (7333, 7421, 8979-8980); outcome-specific rows with no dependency places are stated at `Unknown` with default evidence (8486-8494); membership binding errors become `Unknown` (11018, 11040); every proof obligation is a fact at `Unknown` (10340-10348). The comment at 8098-8102 calls `None` "fails closed"; whether `Unknown` is treated as "always invalidated" or "never invalidated" is decided by the consumer, outside this slice.
- **Outcome-specific rows with default evidence.** 8491, 8501 use `QualificationEvidence::default()` for facts with origin `CallEnsures`; ordinary call ensures rows go through `call_contract_evidence` (8935-8947).
- **Unknown qualification names skipped.** In `call_parameter_domains`, a selected constraint that has no domain symbol and is not a carry-permission name is skipped with `continue` (7151-7153). Any failed lookup of caller, callee, state, entry or type bindings returns an empty requirement list (7096-7125). These drop obligations; cannot tell if another check owes them.
- **Entry facts taken from declared types.** `append_state_parameter_domain_facts` states `param in Domain` at state entry for every immutable parameter from the declared type alone (9718-9741), with evidence `propagated_evidence(state.symbol)`. The comment says callers establish it through the parameter's implicit `requires` (9606-9610); that check is elsewhere.
- **Zero-case and zero-domain facts taken from the type.** 9370-9379 states the first variant holds for any uninitialized local whose type does not "require establishment"; 10021-10047 states domain membership when `domain_admits_zero_byte_carrier` says so, with `checked_validation_evidence`. Both trust `validation` predicates.
- **Owner `Unknown` accepted.** `contract_fact_point` and `contract_fact_origin` map an unknown owner to `ProgramPoint::Global` / `FactOrigin::Unknown` and keep the fact (10128, 10174-10176, 10218).
- **Proof-output pass.** `(Some(_), Some(_))` and `(None, None)` fall through `_ => {}` (5681), which is the intended accept. `unwrap_or_default()` at 5465 and 5571 cannot fire with a wrong value because the preceding checks `continue`. `machine_target` absent with an open requirement sets `immediate = true` without checking state count (5541-5547); `check_open_proof_output_requirement` has already limited the shape.
- **Vocabulary omissions.** Transparent propositions are left out of the vocabulary (6573); applications that fail to normalize are left out (6610-6612); `Membership` facts produce no label (6511); outcome-specific and crash contract kinds map to `None` (6645-6646).
- **Proof-output facts skipped.** In 8393-8427, an output with no matching contract fact, no semantic handle or no evidence is skipped (premise side).
- **Case observations skipped.** 7277-7323 returns or continues on eight conditions (premise side).
- **`intake_call_ensures_propositions`** adds every callee `ensures` label to the caller's known set (6431-6465) with no check here that the call's `requires` held; the first state of the callee machine is taken as the entry (6436-6444). The requires check is elsewhere.

## Surprises

- **Nothing in the slice consults the proof kernel.** The feature called "proof outputs", "evidence terms" and "witness lanes" is checked entirely by table lookups: an evidence argument is accepted when a term of that name exists in scope and its stored proposition value equals the instantiated callee proposition (5822-5859). The output evidence term is then created by appending a table row (5898-5909). No derivation is built or verified here.
- **Evidence names are scoped by string within a state, and ordering is by `source_statement_index`.** `proof_output_source_term_by_name` lets a call use any earlier package's output in the same state by name (6303-6317). It does not look at control flow: an output bound under one guarded arm at an earlier statement index is findable from a later statement. Cannot tell whether a later rule restricts this.
- **Statement-index arithmetic as identity.** The package must sit at exactly `runtime statement index + 1` (5733), and call rows are selected with `call_ordinal == 0` hard-coded (5455, 5744, 5764, 7767, 8390). A proof-output call can only be the first call of its statement.
- **Comment and code disagree on float bounds.** The module comment says "Immutable scalar parameters also carry their enforced float ranges" (9167), but the float-bound loop (9668-9687) runs before the `if parameter.is_mutable` test (9688), so mutable parameters get the entry predicates too. Whether `validation::declared_float_field_bounds` filters them is not visible here.
- **Two sibling walkers guard recursion differently.** `zero_cases::collect` uses `(data.symbol, generic_instance)` (9347); `collect_zero_initialized_field_domains` uses the data type's name string (9554). Two different data types with the same name in different packages would be treated as a cycle by the second and their field domains dropped (premise side, so it loses facts rather than inventing them).
- **`zero_cases::collect` pops its visited entry (9397) but shares `visited` with array elements while passing a fresh path** (9298-9305); the domain walker instead clones the visited list per level (9557). Same intent, two implementations.
- **Residual `self` handling after the receiver was retired.** The comment at 10809-10812 says the implicit `self` receiver is gone and Psi 01 rejects the spelling, yet `is_self_receiver` is still tested at 7955, 8020, 10596 and 10904, and 10904-10913 still substitutes a receiver place for a parameter named `self`. Those branches look dead.
- **A state symbol is compared with a field called `machine_symbol`.** In `contract_expression_place`, for `StateSignature` and `CallSignature` owners the test is `state_symbol == result.machine_symbol` (7840-7843). Either `ReservedResultPlace.machine_symbol` holds a signature symbol for trait requirements, or this arm never matches; cannot tell from this slice.
- **`ensures` declaration facts are duplicated per dependency place rather than linked.** For `Requires` the code writes one fact plus `StorageDependency` rows in one context (8269-8295). For `Ensures` it writes a full copy of the same payload at every place the contract reads, with no context (8296-8309). The two kinds therefore have different invalidation shapes for the same contract text.
- **Call-site parameter-domain facts are built with an empty `domain` span** (`domain: Default::default()`, 7140) and seeded rows use an invalid `value` expression (9816); consumers must rely on `domain_symbol` and `semantic_domain` only.
- **A synthetic contract is fabricated to reuse a helper.** For outcome-specific arms the code constructs a `ContractProofFact` owned by the caller state (8455-8466), although the guarantee belongs to the callee, in order to call `semantic_contract_payload`.
- **Dense handle indexing with a grow-on-demand `Vec<Option<_>>`** (8311-8316, 9040-9044) and an `expect("contract fact handle index overflow")`; linear `find` over all contract facts per proof output (8395-8397) and over all evidence terms per binding (5780, 6288) make these passes quadratic.
- **The vocabulary's application list is deduplicated by linear `contains`** on a `Vec` (6369-6378), while the initial list built at 6607-6614 is not deduplicated at all.
- **`intake_call_ensures_propositions` picks a machine's first state when the call target symbol is a machine** and otherwise resolves a state (6436-6444); the same "first state is the entry" convention appears at 6756, 7723, 8052, 10141. The entry state is identified by position in the state list.
- **Capability not expected in a "published facts" file:** this file contains a complete admission check for static trait-requirement dispatch with a fingerprint and a commitment (`application_report_fingerprint`, `application_commitment`, 6034-6052), restricted to non-generic one-state Unit/`i32`/`bool` callables. The fingerprint and commitment are only tested for nonzero here and passed to `selected_conformance_applications`.
- **Evidence for property 3 is weaker here than the sampling suggested.** The slice has clear per-owner and per-construct repetition (about 15-20%), but several authors' comments describe deliberate unification: one walker for record fields and collection elements (9163-9165), one `append_observation_context` (10233-10255), one `state_point` (10083-10087), one positional parameter binding shared by "place substitution and operand-epoch selection" (7503-7507).
