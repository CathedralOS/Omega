## What this code is for

Thirty-two of the 33 files belong to the `review-evidence` package. That package does not check programs. It runs after the old checker has accepted a package and turns the checked result into "package review" records: a canonical description of the package's public API, calling plans, external bindings and terminal-authority permissions that a consumer's lock file can retain and compare (`record/baseline/component_assumptions.rs:1-8`, `encoding/mod.rs:1-8`).

The `capture/` files read the typed trees and the checker's fact tables and write those records. While doing so they re-check that three copies of the same information agree: what the source authored (keyword spans, `invokes`/`reaches` rows), what the checker recorded as facts, and an immutable "custody" copy of the original compilation (`capture/source/invocations.rs:1-9`, `capture/source/family_interfaces.rs:1-8`). A disagreement refuses the review with a "reviewed callable ..." or "package review rejects ..." diagnostic.

The `capture/semantics/types/` files compute a text identity for every type in a public signature and refuse types whose leaves have no exact symbol (`capture/semantics/types/identity.rs:1-16`, `capture/semantics/types/validation.rs:1-12`).

The `record/` files are almost all plain data definitions: the vocabulary of contract expressions, static arguments, external bindings, trait shapes and provider realizations. One of them validates the canonical order and ownership of a public API record (`record/public_policy/validation.rs:26-66`).

The `encoding/` files are entry points for writing those records as bounded binary and text rows.

The last file is the README of the deleted `build-time-evaluation` crate. It describes compile-time evaluation of constants, array lengths and const-generic arguments, the rules that gate it, and a long list of forms it did not yet handle.

## Mechanisms

- **Recursive walk over a type with a substitution stack.** `review_lifetime_topology_with_substitutions` renders the borrow structure of a type as nested text. It replaces a named type parameter with its substitution and keeps a stack of parameters being expanded to refuse cycles (`capture/semantics/types/lifetimes.rs:74-206`). No depth budget other than the cycle check. It serves public signature identity, so that changing which input owns an output borrow changes the identity (`capture/semantics/types/identity.rs:4-8`).
- **Lifetime names to ordinals.** A lifetime identifier becomes its position in the declaration's binder list, after applying lifetime substitutions newest first (`capture/semantics/types/lifetimes.rs:208-241`). This makes the identity independent of the lifetime's name.
- **Recursive validation of a type's leaves and index expressions.** `validate_package_type_identity_input_inner` walks the same type tree and carries one flag, "a value is allowed here", which it sets per argument from the declared parameter kind (`capture/semantics/types/validation.rs:38-199`). `validate_package_index_expression` walks expressions with an optional "exposure" that turns on calls, casts and builtin operators (`capture/semantics/types/validation.rs:252-430`).
- **Scratch copy of the type tables.** `SignatureProjection` clones eighteen tables once, then on each later request resets three of them (type references, data type parameters, state parameters) from the source so that one declaration's substitutions cannot be read by the next (`capture/semantics/signatures/projection.rs:44-110`).
- **Family head derivation.** For a bodiless machine that heads a target family, the code recomputes the head's interface from all members: a set union for invocation targets (`capture/source/invocations.rs:75-112`) and a Boolean OR for suspension and blocking (`capture/source/suspension.rs:35-55`). It compares the result with the checker's fact for the head.
- **Service-reach closure.** The authored `reaches` targets are closed over parent services by `extend_closure`, then sorted and deduplicated, and compared with the stored row (`capture/source/service_reach.rs:148-174`).
- **Measure, then emit.** A row is encoded twice, once to measure and once to write, under byte, sequence and depth limits; the two sizes must agree (`encoding/encode/policy_rows.rs:72-92`). Contract text has a 64 KiB writer (`encoding/encode/mod.rs:54`).
- **Strict canonical order as duplicate detection.** `ordered_by` refuses any list where a neighbour pair is not strictly ascending (`record/public_policy/validation.rs:88-100`); component assumptions do the same on strings (`record/baseline/component_assumptions.rs:41`).
- **(README) Probe machine.** A const-generic argument that contains calls is typed on a placeholder carrier, appended to the program as a probe machine, excluded from ordinary checking, and evaluated by the scalar evaluator (`build-time-evaluation/README.md:70-84`).
- **(README) Three-interval sign analysis with a rational lattice.** To prove a divisor nonzero across `match` arms, the evaluator keeps at most three closed intervals (negative, positive, possibly zero) and a lattice "offset plus integer multiples of a stride"; it excludes zero when the offset is not a multiple of the spacing. It does not enumerate arm combinations. Stated limits: "Wider nonconstant divisor intervals still need stronger divisibility evidence" and "Nonzero proofs still lose gaps not captured by the lattice and correlated result facts" (`build-time-evaluation/README.md:174-194`).
- **(README) Layered evaluation to a fixed point.** Scalar declarations evaluate in dependency layers, "one frontend pass per layer" (`build-time-evaluation/README.md:214-225`). Shared probe preparation re-prepares bodies when provisional types block it; "No-progress retains the admission failure" (`build-time-evaluation/README.md:86-91`).
- **(README) Result accounting.** One cell per scalar, unit, Text or aggregate root plus recursive fields, payloads and elements; overflow refuses (`build-time-evaluation/README.md:374-380`).

## Identity by text

- A type's review identity is a string. `PackageReviewTypeIdentity` has one field, `canonical: String` (`record/signatures/signature_vocabulary.rs:11-14`). The capture code fills it from `type_identity_text` (`capture/semantics/types/identity.rs:55-61`, `130`) and wraps it with `framed_identity("signature-type", ...)` (`capture/semantics/types/identity.rs:140-142`). ## Surprises

- **This package is a second consumer of the old checker's facts, not part of the checker.** Its rules compare the checker's fact tables with authored rows and with a custody copy of the same compilation. Deleting the old checker removes the tables these files read: `facts.synchronous_invocations` (`capture/source/invocations.rs:29-34`), `facts.service_reaches` (`capture/source/service_reach.rs:64-73`), `facts.suspensions` and `facts.blocking` (`capture/source/suspension.rs:86-105`), `checking_input`, and `checked_trees::CheckedTrees` (`capture/source/suspension.rs:83`).
- **The checker stored some facts twice and this code cross-checks the copies.** An invocation fact has exact targets and a separately "rendered" plan; the review refuses when they disagree (`capture/source/invocations.rs:42-52`, "contradictory exact and rendered synchronous-invocation facts"). The authored `suspends` flag and its keyword spans are also two copies checked against each other (`capture/source/suspension.rs:143`).
- **A refusal that cannot fire.** `resolve_services` refuses when `service_declarations` is `None` (`capture/terminal_authority_permissions/declarations.rs:52-54`). Its only caller in the package fills that field first (`capture/terminal_authority_permissions/policy.rs:26-34`, `45`); a search found no other caller.
- **Empty identity text is accepted silently.** See `unwrap_or_default` at `capture/semantics/types/identity.rs:60` and `130`. The surrounding code refuses every other missing piece with a diagnostic, so this default stands out.
- **Asymmetry between unary and binary operators in array lengths.** Binary operators need a checked selection; unary operators need none (`capture/semantics/types/validation.rs:302` against `303-334`).
- **Asymmetry between two toolchain origins.** `Toolchain` and `ToolchainContract` sources get the same owner (`capture/source/locations.rs:40-45`), but only `Toolchain` may use a virtual path outside the package root (`capture/source/locations.rs:63-64`). A `ToolchainContract` file outside its root is refused.
- **Asymmetry between family heads and ordinary machines for suspension.** The head's checked behaviour is compared with its published flag; an ordinary machine's is not (`capture/source/suspension.rs:48-52` against `109-133`). A family head also publishes the OR of what the checker inferred for its members, not what the members declared (`45-46`).
- **Diagnostics for a family member name the head.** The member lookups pass `machine.name`, the head's name, as the subject of the message (`capture/source/invocations.rs:82`, `88`; `capture/source/family_interfaces.rs:67`).
- **Canonical order of invocation targets uses a compilation-local index.** The union is sorted by `symbol.arena_index()` (`capture/source/invocations.rs:109-112`). The result is compared only with facts from the same compilation.
- **The contract expression vocabulary has no arithmetic negation.** The unary operators are `BitwiseNot` and `LogicalNot` only (`record/contracts/expressions.rs:72-75`), while the binary list has eighteen operators (`50-69`).
- **A one-variant enum.** `PackageReviewProviderFamilyCoverage` has only `CompleteDeclarationFamily` (`record/package/providers.rs:78-80`).
- **Empty `impl` blocks left behind.** `record/calling/application.rs:95-97`, `record/contracts/expressions.rs:212` and `324`, `record/signatures/signature_vocabulary.rs:37` and `46`, `record/signatures/traits.rs:28`.
- **High schema version numbers.** The baseline format is at version 30 and the selected-provider format at 22 (`encoding/mod.rs:22`, `34`), which shows how often these record shapes changed.
- **Location result discarded.** `let _ = canonical_source_span_location(...)?` computes a location only to see whether it fails (`capture/source/service_reach.rs:138-142`); the suspension code does the same without the `let _` (`capture/source/suspension.rs:149`).
- **The README describes a numeric analysis that is more general than a per-case check.** The three-interval sign analysis with a rational lattice proves nonzero divisors and integral landing across `match` arms without enumerating arm combinations (`build-time-evaluation/README.md:174-194`). It lives in a private module the README names as `value/match_dispatch/rational_bounds.rs`.
- **The README states that part of the evaluator had already been removed before this pull request.** Jobs that needed the tree interpreter were refused with "no product route yet" (`build-time-evaluation/README.md:9-13`). So some programs were refused by the deleted crate itself, for lack of an engine and not because a rule failed.
- **The README records the name hazard the brief describes.** "runtime parameters and locals cannot become same-spelled constants" (`build-time-evaluation/README.md:144`) and "Aggregate arguments ... pass the same original-owner lexical check before the separate legacy materializer can erase their names" (`147-149`) show that the probe worked on names and needed a guard against name capture.
- **The README cites test paths under `tests/omega/pass/`** (`build-time-evaluation/README.md:206`, `241`, `258`), a directory the project instructions say was deleted earlier.
