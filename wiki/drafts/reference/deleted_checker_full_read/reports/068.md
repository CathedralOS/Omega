## What this code is for

This file builds the "check facts" that the old checker published for later stages after it had typed a program (published_facts.rs:1-14). It mostly does not accept or refuse source programs by a language rule; it derives records (capability flows, carry policy, cleanup obligations, contract plans, crash plans, declaration descriptions, identity formations, index-instance labels) and refuses when a record it expects is missing or inconsistent. The one large language rule in the slice is automatic cleanup: when an owned value dies, its cleanup hook's `requires` clauses must hold at that exact edge, and for generic code an unproven clause becomes a prerequisite published to callers (published_facts.rs:826-1779). The slice also assembles each machine's public contract identity (a fingerprint and a commitment) from supply mode, services, invocations, suspension, blocking, termination, declared contract structure and crash interface (published_facts.rs:2498-2530, 2588-2963). It builds the crash side of that contract: published crash buckets from `crashes` clauses, crash sites from crash transitions, and "trapping sites" from planned scalar computations (published_facts.rs:3311-3731, 3739-4536). It freezes per-machine "declaration descriptions" so later consumers need not reopen source (published_facts.rs:4577-4877). It prepares the `Id` formation plan as proof-kernel declarations for a later independent check (published_facts.rs:4888-5006). The last part collects "indexed instances" (a domain family applied to index arguments, such as `Resident<SlotPlacement, Slot>`) from types, casts and call `ensures`, with the labels the index-compatibility diagnostics print (published_facts.rs:5007-5837).

## Mechanisms

- **Capability verb fixpoint** (published_facts.rs:261-312). Loops over all call edges and the three verbs `Returns`, `Derives`, `Acquires` until no new fact is added. Facts are deduplicated per state in a `Vec<Vec<Handle>>` indexed by the state symbol's arena slot (203-239). No budget; it ends because the fact set is finite and only grows. Serves capability/authority flow reports.
- **Cleanup hook sequencing** (published_facts.rs:1148-1394, 1803-1958). For each death edge it groups dispositions by machine, state, event source, exit, root, statement and contexts (1228-1251), orders hooks by declaration geometry (2090-2116, 1264-1271), then walks the hooks keeping a `CurrentCleanupFacts`: live fact contexts, guarantees from earlier hooks' `ensures`, the set of places written so far, and an `opaque_write` flag. Each hook's `requires` is collected against the current facts; then `advance` removes facts overlapping the hook's writes and adds its `ensures` split into conjuncts (1967-1981). A selected hook that might be skipped is joined with the pre-hook facts (1328, 1387-1389). Limits: predicate lowering budget `4096` (2031, 2040); writes unknown means all facts dropped (1931-1935). Serves automatic cleanup `requires`.
- **Entry-requirement inference** (published_facts.rs:871-1024). Returns `bool` "changed" so a caller can iterate it to a fixed point (the loop is outside this slice; 1019-1023). It turns an unproven requirement in generic code into a row `antecedent => consequence` on the machine, and transports rows from callee to caller with `conjunction(path_condition, callee_condition)` (1010). Serves generic cleanup.
- **Range/index cover test** `covers` (published_facts.rs:1500-1519): a symbolic path covers a concrete one if it is a prefix where a `FixedRange` contains the concrete `FixedIndex` or sub-range.
- **Trapping-operation search** (published_facts.rs:3459-3731). A worklist (`pending`) over scalar computation nodes plus an inner worklist over structural value dependencies (3510-3629). Two modes: `Physical` (a trapping primitive is present) and `Possible` (it may trap) (3440-3453). No budget; no visited set on the scalar worklist (3632-3729). Serves crash contracts (`Trap` cause).
- **Per-machine parallel assembly** (published_facts.rs:2619-2771, 2817-2829, 2859-2953). Rayon `par_iter` over machines builds contract plans and realized envelopes; fingerprints are filled in a second parallel pass after crash envelopes settle.
- **Crash bucket normalisation** (published_facts.rs:4258-4384). A `BTreeMap<CrashCause, Bucket>`; routes are sorted and deduplicated; an unconditional flag replaces all routes with `Truth`.
- **Indexed-instance collection** (published_facts.rs:5522-5558). Recursive walk through `Reference` and `Constrained` type nodes with a visited list, collecting domain constraints that have arguments.
- **Id formation closure** (published_facts.rs:4969-4987). Wraps each formation's term in one `Lambda` and its type in one `Pi` per captured subject, innermost last, and appends it as a new kernel `Declaration`.
- **Parenthesising index-expression printer** (published_facts.rs:5735-5768). Adds parentheses by operator strength for `* /` over `+ -`.

## Identity by text

- Receiver provenance is decided by the first identifier of the receiver path as a `String`: `is_self_receiver(&head)` means machine-owned, `parameter.name.as_str() == head` means caller-provided (published_facts.rs:421-454).
- A machine state is matched to a boundary trait signature by name: `signature.name == state.name` (published_facts.rs:631).
- "Assigned to a field" is decided for a Name by the count of path members being greater than one (published_facts.rs:551-553).
- Contract identity inputs are strings: `services: Vec<String>` and `published_invocations: Vec<String>` (published_facts.rs:2502-2504), filled from `definition.name` (2638-2644, 3864-3870).

A `requires` clause that cannot be lowered becomes `None` in the list (3270). Bound clauses are skipped (3266-3268); outcome-specific `ensures` are only flagged (3259-3265). Cannot tell from this slice how consumers treat `None`.
- Result memberships are skipped when the result owner is neither the callable nor its entry state, when no carrier path resolves, or when the whole carrier is primitive (published_facts.rs:3206-3231).
- `build_structural_runtime_requirements` returns `None` for the whole machine when any clause is a proposition, a bound non-proposition, or unlowerable (published_facts.rs:4063-4066, 4080, 4083-4093, 4102, 4108); bound machine-owned propositions and restated structural qualifications are skipped (4067, 4069-4071). `build_structural_runtime_guarantees` is likewise all-or-nothing (4146-4156).
- Crash routes: when the scalar form cannot be lowered the route "keeps its identity only, so downstream lowering still fails closed on it" (comment 4229-4230; code 4342-4348). The fail-closed consumer is outside this slice.

- `build_checked_crash_sites` marks coverage only by unconditional buckets; guarded coverage is left empty here (`Vec::new()`, 4416).
- `retain_declaration_descriptions` turns any failure of `describe` into a stored `Unavailable { reason }` row rather than a diagnostic (published_facts.rs:4631-4637, 4666-4671); invocation-target failure is stored as an `Err` string in the header (4609-4610, 4644-4656). Refusal, if any, is deferred to consumers.
- `StateCallIndex::new` drops calls whose site cannot be found (`filter_map`, 5185-5194); `contexts_after_value` falls back to the caller-supplied contexts (5216).
- `append_call_result_ensured_instances` reads instances from the call's contract row "before `call_contract_evidence` decides whether the promise is admitted as establishment: ... the declared instance is what the value is, whatever its evidence" (comment 5407-5410; code 5448-5505). ## Surprises

- **Property 1, evidence for.** Every accept/refuse in the slice is the code's own comparison or a call into sibling checker modules (`proves_captured_predicates`, `cleanup_predicates`, `calls::proves`). The proof kernel appears once, as data: `identity_formations::record` imports `proof_admission::{Declaration, Term}` (4902) and builds `Lambda`/`Pi` terms (4972-4979), but it does not call a verifier; the comment says a later stage "independently checks the mathematical judgment" (4892-4894). The variant name `ClosedScalarContractValue::SourceCheckedGuarantee` (3246) states the trust model directly: an `ensures` that cannot be expressed in the lowered scalar vocabulary is published as "the source checker checked this".
- **A published-facts builder changes borrow facts.** `retain_selected_receiver_loans` overwrites `last_use_statement_index` on loans (821) so they outlive lexical last use up to the cleanup hook. The rule "a loan on a value with a cleanup hook lives until the hook runs" is implemented as an after-the-fact edit of another analysis's output, and returns `changed` for an outer fixpoint (819-823).
- **`canonical_crash_path_predicate` and `canonical_crash_contract_predicate` are the same function twice** (4430-4452, 4492-4514), although the comment on the second says "executable guard keys remain in their independent namespace" (4489-4490). In this slice both produce the same `CrashPredicateIdentity`.
- **The resource-envelope "second gate" recomputes what was built a few lines earlier from the same inputs.** Envelopes are created by `from_checked_contract_entries(machine, fingerprint, commitment, states)` (2943-2949) and then compared with `from_checked_contract(machine, entry, fingerprint, commitment)` over the same states (2996-3013). It can catch a count or order mismatch between two constructors but has no independent source.
- **Contradiction check is narrow.** `append` reports contradictory prerequisites only for the constant-true antecedent (1479). The diagnostic says "for the same invocation-entry place", but the code compares whole boolean expressions and their negation, not places (1475-1478).
- **`order.position(death).is_some_and(|position| position < order.indices().len())`** (759-762): if `position` returns an index into `indices`, the inner test is always true, so the fallback to the last statement fires only when the death statement is absent from the order. The extra comparison looks redundant.
- **Comment and code disagree in `state_has_capability_parameter`.** The comment says "non-self capability-typed parameter" (372); the code tests every parameter with no self exclusion (377-380).
- **Comment and code disagree in `is_capability_type`.** The comment says a capability is a type "carried through boundary surfaces" (573-575); the code accepts any non-primitive resolved type (581-587). Every data type therefore counts as a capability for `returns`/`derives`/`acquires`.
- **`stores` is recorded for any boundary call through a `self`-rooted receiver** (123), even when nothing is stored at that statement.
- **Unstable handle numbers enter published identities.** `"service:#{arena_index}"` is a fallback in a contract-identity input (3880), and `"invocation-declaration({arena_index}:{generation})"` is the owner of an invocation-local `Id` publication (4932-4936).
- **`lower_closed_clause` recognises only a tautology.** It accepts `literal == literal` where both sides are the same Boolean or the same Integer literal, with the builtin `==` (3116-3168), and publishes the literal as the clause's "closed scalar value". A clause such as `requires true == true` gets a dedicated representation; any other clause falls through to the general lowering.
- **The budget `4096` is a bare literal in three places** (2031, 2040, 3174) with no named constant or stated reason.
- **Parameter invocation targets are "retired" in one place and still published in another.** `synchronous_target` refuses `InvocationTarget::Parameter` as a "retired runtime boundary-binding parameter" (4733-4740), while `build_signature_crash_capsule` still renders `"parameter:{index}"` into the capsule identity (3874-3876).
- **Missing per-machine facts panic.** Ten `expect` calls (2651-2672, 2871-2919) and one on statement ordinals (4412) abort the compiler inside a rayon pool rather than refusing with a diagnostic, in a function that otherwise returns `Result<_, Vec<Diagnostic>>`.
- **Positional indexing with symbol fallback.** Facts are looked up by `machine_index` and only then by symbol (for example 2630-2634); the code assumes every fact table is in machine order and silently corrects when it is not.
- **Orphaned and duplicated comments.** Line 5666 is a cut-off comment ("Whether the declared family carries no predicate body. An unresolved symbol") sitting above `compatibility_name`, which it does not describe. The header at 3296-3310 repeats its first sentence at 3307.
- **The `Id` formation plan ends with a fixed term.** Every `CheckedIdentityFormationPlan` ends with `term = Term::TwoZero`, `ty = Term::Two` (4996-5003), a fixed pair unrelated to the formations; its purpose is not explained in the slice.
- **Property 3, mixed evidence.** The cleanup rule is not rewritten per value placement: it works on `CanonicalPlace` with segments and a single predicate algebra. The per-placement copies are in how fact contexts are found for each kind of death event (1559-1778) and in the per-owner crash code. So in this slice the repetition is by event source and by declaration kind (machine / signature / operator / data / domain / trait), more than by local/field/parameter.
- **A capability nobody may expect:** automatic cleanup in generic code infers preconditions and publishes them upward to callers as conditional entry requirements (`antecedent => consequence`) (862-869, 1007-1014, 1489-1496). This is inference of contract clauses the author did not write, bounded only by the "entry-stable" and "symbolic origin" tests.
