## What this code is for

This slice is the second half of the "statement sequence" planner of stage 05. For one state of a machine it walks the authored statements in execution order and builds the list of checked operations (`CheckedUnitEffectOperationPlan`) that the later stages lower: local establishment, calls, stores, cleanups and reference releases (`build`, seq.rs:9032-9493).

About half of the slice (seq.rs:4868-7659) decides when a borrow ends physically. A "loan" is a recorded borrow; its "holder" is the storage that keeps the reference descriptor. The code decides at which statement each holder has died, emits one `ReleaseReference` operation per loan group, and orders those releases so children end before parents. It runs once before each statement (`append_reference_releases`, seq.rs:6786-7216) and once at state exit (`append_exit_reference_releases`, seq.rs:7224-7659).

The next part (seq.rs:7661-8131) does ownership bookkeeping for structural (non-scalar) results: when an operation consumes an earlier result, the producer's "discard on return" flag is cleared so the value is not dropped twice. `statement_call::plan` (seq.rs:8187-8543) plans the single call a statement performs. `storage_initializer` (seq.rs:8568-8620) and `scalar_computation_local_at` (seq.rs:9686-9743) pick the checked initializer of a scalar local. `wire_codec` (seq.rs:8622-8862) replaces a derived `Schema::encode` call by a constant store. The tail (seq.rs:9495-9684) finds the statement that ends the state and builds the scalar return plan.

Every function returns `Option`. `None` means "this plan could not be built"; there is no user diagnostic anywhere in the slice, only trace phase strings and debug prints.

## Mechanisms

- **Dependency walk over loans with cycle refusal.** `children_retired` (seq.rs:5051-5097) uses an explicit stack with `active` and `completed` lists; `retains_parent` (seq.rs:5099-5128) and `holder_retired_following` (seq.rs:5503-5527) recurse with an `active` list of `RetirementNode`. A cycle returns `false` ("not retired"). There is no depth or work budget. Membership is tested with `Vec::contains`. Serves borrow lifetimes.
- **Producer index.** `capturing_operations` (seq.rs:5137-5202) builds a `BTreeMap` from a loan's `(arena_index, generation)` to the operations that produced or captured it, so that `captures_holder` does not rescan all operations. It is rebuilt on every `children_retired` call (seq.rs:5057).
- **Execution order.** Everything compares statements through `StatementExecutionOrder` (`precedes`, `at_or_before`, `latest`, `successor`, `position`, `prefix_end`) obtained from `admitted_execution_order` (seq.rs:6817-6819, 7267-7269, 9088-9090). Statements are not assumed to run in textual order.
- **Per-statement release pass.** `append_reference_releases` (seq.rs:6786-7216) walks all operations in reverse before each statement. For each operation it rescans the operation list several times (`complement_completions`, `stores::releases`, `whole_result_discarded`, `release_matches`, `transferred_paths`). Then it loops on `backing_releases` until no new release appears (seq.rs:7157-7168). No budget.
- **Exit scheduling loop.** `append_exit_reference_releases` (seq.rs:7420-7563) is a topological scheduler: it repeatedly takes the first pending release whose dependencies have retired; when none is ready it collects backing and stored releases; when that also yields nothing and releases remain, it refuses. No budget; progress depends on each round adding something.
- **Value-graph worklist.** `consume_value_places` (seq.rs:8037-8131) walks a structural value graph carrying a `projected` flag down through projections, subslices, dispatch arms and adaptations, and refuses on a node reached twice.
- **Wire length calculator.** `framed_length` and `varint_len` (seq.rs:8726-8756, 8851-8861) compute the encoded byte length at compile time: one varint for era 0, then for each byte-slice field a tag varint, a length varint and the payload; a varint longer than 10 bytes is refused.
- **Prefix / walk / rest partition.** `build` (seq.rs:9088-9133) splits the execution order into a construction prefix already handled elsewhere, the statements this sequence walks, and a rest that the completion must own.

## Identity by text

- `wire_codec::written_store` recognises the operation by `call.target.as_str() != "encode"` (seq.rs:8647).
- The wire schema is found by comparing its name string with the last member of the call's receiver path (seq.rs:8732-8739).
- A struct literal's field is matched to a wire field by name string (seq.rs:8746, 8793-8797).
- `struct_literal` finds the encoded value by reading another statement's source: it takes the name in the argument, finds the `LocalData` statement with that symbol, and requires its initializer expression to be a struct literal (seq.rs:8758-8786). `slice_len` and `constant_u64` then require the syntax `x[a..b]` with integer literals (seq.rs:8801-8832). Meaning is decided by source shape, not by a checked value.
- `aliases_established_home` decides by the initializer's syntactic shape, `Name` or `Borrow(Name)` with one path member (seq.rs:5443-5467). Its comment names the synthetic local `__transition_subject#N` as the motivating case (seq.rs:5440-5441); the code does not compare that string.
- `statement_phase` maps statement kinds to trace strings (seq.rs:8999-9010); these label traces only.

Everywhere else in the slice identity is by handle, not text: `SymbolHandle`, expression handle, loan `Handle`, `binding_ordinal`. But a value is identified by where it was written: a loan is matched by the triple owner symbol, formation statement index and owner path (seq.rs:5600-5603, 5831-5834, 5876-5880), and a result by `(binding, PlaceRoot)` where the root is a local's symbol or an expression handle (seq.rs:8883-8889). An invalid default symbol serves as the "no uncommitted owner" marker (seq.rs:5545, 5760, 5855, 6844, 7412).

## Surprises

1. **This "checker" file schedules code, it does not judge contracts.** Nothing in the slice touches `requires`, `ensures`, domains, invariants or termination measures. It decides where reference releases and discards go and who owns a result. A wrong answer here does not accept a false proof; it produces a double release, a missing release or a refused plan. Acceptance is the planner's own yes or no throughout, with no kernel evidence (property 1 holds, in a planning rather than proving sense).

2. **Refusal has no diagnostic.** All 56 `return None` sites and 133 `?` sites give the user nothing. The only explanations are trace phase strings and 16 `eprintln!("CHECKSITE ...")` debug prints gated by `trace_flags::check_sites()` or `trace_flags::trace_completion()` (for example seq.rs:4978-4983, 6613-6633, 7278-7321, 7455-7557, 7795-7840). Two different flags gate similar prints. The comment at seq.rs:8996-8998 calls a `None` an "omission", so a `None` may mean "this unit is not built locally" and not "the program is rejected"; the slice does not show which.

3. **Compile-time evaluation of `Schema::encode` from source syntax.** `wire_codec` (seq.rs:8640-8861) replaces the call with one store of a `u64` literal into `written`. The length is computed by reading the struct literal that initialised the value local and the integer literals of each slice range. The `out` argument is bound as `_out` and never used (seq.rs:8651), and no operation in this slice writes the encoded bytes. The era is fixed at 0 (`varint_len(0)`, seq.rs:8741) and any `Version` member or non-byte-slice field refuses (seq.rs:8752). This is source re-analysis inside the planner and the clearest case of meaning decided by a name string (`"encode"`).

4. **The wire path returns after side effects.** Before the `encode` early return at seq.rs:8371-8385, the function has already incremented `call_count` (seq.rs:8269), planned the call's structural operands (seq.rs:8271-8287) and possibly computed a replacement and `structural_store_bindings` (seq.rs:8349-8370) that are then dropped.

5. **Cost.** `append_reference_releases` runs before every statement (seq.rs:9243-9256), walks every operation, and for each one rescans the operation list several times; `children_retired` rebuilds a `BTreeMap` on every call (seq.rs:5057) although its comment says "once for this immutable operation prefix" (seq.rs:5131-5132). The work per state grows at least with the cube of the operation count. All membership tests are `Vec::contains`.

6. **Possible ordering slip at exit.** `pending.sort_by_key(|..| order.position(boundary))` (seq.rs:7387) sorts by an `Option`. A boundary that is "one past the last ordinary statement" (the case the comment at seq.rs:7218-7221 describes) may have no position, and `None` sorts before every `Some`, so the latest boundaries would be tried first. The scheduling loop that follows picks by readiness, which may hide this. Cannot tell whether `position` returns `Some` for the exit index.

7. **`returning_terminator` calls `checked_terminator` twice with the same arguments** (seq.rs:9542-9548 and 9582-9588). The second call can only reproduce the first result.

8. **`build` has an unused parameter `_call_frames`** (seq.rs:9048).

9. **Limit in transfer tracking.** `selected_path` in `transferred_holder_retired` converts only field and fixed-index segments (seq.rs:5725-5733). A transfer whose path goes through a case payload or a dynamic index makes the function return `false` (seq.rs:5749-5751), so that holder never retires and the exit pass refuses the plan (seq.rs:7558). Per-field tracking stops at variants and dynamic indices here.

10. **`uncommitted_owner` is always the default symbol in this slice** (seq.rs:6844, 7412), so the three comparisons against it (seq.rs:5545, 5760, 5855) always pass for the `Retirement` values built here. Other constructions before line 4868 may set it.

11. **The exit pass builds its base `Retirement` with `at_exit: false`** (seq.rs:7411) and overrides it to `true` only inside the loop (seq.rs:7421-7426). The later re-check for `normal_call_disposes_backing` reuses the base value (seq.rs:7594-7598), so it asks the "before exit" question on purpose or by accident; the code does not say.

12. **Short-circuit booleans are refused as pure initializers of mutable primitive locals** (seq.rs:8614-8615) but `scalar_computation_local_at` for immutable locals has no such test (seq.rs:9699-9742); it delegates the pure case to `scalar_expression_local_at`, outside this slice.

13. **A mechanical edit left a mis-indented line**: `partition_leaf: Default::default(),` at column 0 (seq.rs:7145), inside otherwise formatted code.

14. **Evidence on the three properties.** Property 1: supported; every decision is the planner's own comparison. Property 2: mostly not supported here; identity is by handles, with the wire codec and the alias shape test as the exceptions, but values are identified by the coordinate where they were written (symbol, statement index, path) and not by a value identity. Property 3: supported in the code (see the repetition section) although the comments repeatedly state the opposite intent.
