## What this code is for
This code answers one question for the old checker: when a machine calls something (a state, a boundary-trait method, a requirement method, a dynamic slot, a transition target, an operator), which caller storage paths may the call write, and which caller storage can a returned exclusive reference point into. The answers are lists of string paths such as `self.a.b` or `x.field` ("write frames") and lists of `FramePlaceOrigin` / `LocalWriteSource` records ("origins") (e.g. 8345-8411, 8537-8610, 8665-8733). The checker uses these so a fact about a caller's storage is dropped exactly when a call might write it. Most functions return `Option`, and `None` means "footprint unknown". Callers turn that into refusal or into a whole-place write. The code covers six areas. First, boundary-trait and requirement-trait signature selection (7601-9020). Second, type-graph queries on whether one type can live inside another (9102-9399). Third, call-target and argument-type lookup (9422-9611). Fourth, a worklist walk over call expressions (9612-10008). Fifth, caller alias and prefix evidence, including assignment destinations (10010-11359). Sixth, the writes performed by automatic cleanup (`dropped by` hooks) when owned values die (11360-12089). After those come a fixpoint over cyclic state transitions (12090-12955) and `demand`, the resolver (`CallFrameResolver`) with its caches (12956-15135). No proof kernel is used anywhere in the slice. Everything is the code's own computation over the typed tree, and its only outputs are path lists, origin lists or `None`/`false`.

## Mechanisms
- **Write-footprint inference per call (signature driven).** `known_boundary_call_written_paths_for_parts` (8537), `known_requirement_call_written_paths_for_parts` (8345), `signature_state_call_written_paths` (8414) pair callee parameters with argument expressions and, via `boundary_written_argument_paths` (8170), emit a path for each exclusive-reference argument origin and each owned write-carrying aggregate. Serves calls through traits, dynamic slots and states. No explicit budget; generic substitution is threaded through a `TypeBindings` vector (truncated with `bindings.truncate(mark)`, 9192-9221).
- **Exclusive-result origin routing.** `exclusive_boundary_result_origins` (8827) classifies the result of a function returning `&mut T` as Named (origins from the parameters that may hold T), Unrelated (fresh result), or Opaque (unknown). Serves reference-returning calls.
- **Type containment search.** `owned_storage_may_hold_inner` (9119) and `storage_member_may_hold` (9315): recursive walk over arrays, slices, data fields and variant payloads with a `visiting` stack for recursion and a `TypeIdentityMemo`. `Some(true)`, `Some(false)` and `None` (unknown). Recursion detection returns `None` (9185-9191) or `Some(true)` (9347-9355 and 9370-9372). `array_shape_is_closed` (9238) requires literal array lengths and no open type parameters (worklist with visited list). Serves the question "could the exclusive result alias this parameter".
- **Worklist expression/call-frame walk.** `complete_expression_tree` (9768): stack of `PendingNode` (Expression, Receiver, CallFrame). Each call is visited twice (first push children and frame, then resolve written paths), with an admission callback (Reject/Leaf/Traverse). No budget. Serves "does this expression preserve the origin of its place".
- **Prefix evidence for a call/assignment site.** `caller_prefix_site` / `caller_prefix_entry` (11123-11187) decide whether a machine is tracked at all (any parameter/local that may carry a write and is not caller isolated); if not, the site is "Untracked" and carries no alias evidence. Results memoized by (machine, site kind, generation, id) (11130-11134). Serves alias tracking for loans/writes.
- **Closure of write paths over aliases.** `close_over_origins` / `close_observer_aliases` (10945-11043): for every written path, adds each alias spelling whose origin path is a prefix or extension of it, widening to the whole alias (`alias.clone()`) when the origin is coarse or recast. Serves reference-through-alias invalidation.
- **Cleanup write summary.** `push_value_cleanup_writes` (11861) walks an owned type graph, recursion depth bound `MAXIMUM_OWNED_DEPTH = 32` (11413), re-roots a hook's completed write summary (`hook_relative_writes`, 12019, with an `inference.active_states` recursion guard 12035-12042) at the dying place, otherwise charges the whole place. Statement-level death is over-approximated (11386-11391, 11624-11639).
- **Cyclic transition fixpoint.** `summarize_state_written_paths_for_cycles` (12137): collects one `CycleFrameEquation` per reachable state (direct writes, locals, aliases, stored origins, edges with arguments), then a semi-naive delta iteration (12199-12253): for each edge, instantiate the target's newly found paths in the source's namespace (`instantiate_written_path`), expand through aliases, keep only visible ones, add if new. Terminates only because `substitutions_are_finite` was checked first; no iteration counter. Serves recursive/looping state machines (`transition` cycles).
- **Finiteness check of parameter substitution.** `Substitutions` (12745-12819) is a graph over (state, root) nodes (receiver, parameter, local, parameter leaf). An edge target->source is marked `grows` if the argument spelling adds a suffix, a recast or is collection coarse. `is_finite` runs SCC (`component_ids`) and rejects a growing edge inside one component. Unit test at 12920-12954.
- **Saved-reference producer resolution.** `saved_reference_operand_origins` (13741): follows Borrow/Member/SavedSubject chains back to the producer, with `active_captures` cycle guard and a hard cap of 64 (13806).
- **Memoization.** `memoized(...)` over `Mutex<HashMap>` fields in `CallFrameCaches` (14965-15003), `OnceLock` for call plans (15002, 15029-15035: `infer_operational_may` and `infer_service_reaches`).

## Surprises
- No call into the proof kernel, no `ProofNode`/`verify_obligation`/certificate in 7565 lines. The code's output is its own boolean/Option/paths; the only "evidence" is data structures (`LocalWriteSource`, `FramePlaceOrigin`, `CollectedStatementPrefix`).
- Refusal reasons exist (`Err(&'static str)`, `StatementReferenceTransferRefusal` 14808-14828) but they are only printed under `struct_trace()`/`call_write_trace()` env-style flags; `assignment_write_paths` throws the reason away with `.ok()?` (10376). No user diagnostic is created in this slice.
- Opposite defaults for the same failed lookup: missing data definition is `Some(true)` in `owned_storage_may_hold_inner` (9179-9181) and `None` in `storage_member_may_hold` (9346); `Constrained` is `None` in one (9234) and `Some(false)` in the other (9397).
- `#[allow(clippy::too_many_arguments)]` sits on an enum (`ExclusiveResultRoute`, 8820), not a function.
- The cycle walk uses `std::collections::HashMap` locally (12194-12198) while the surrounding module aliases `symbols::SymbolKeyMap as HashMap` (14801), so a name `HashMap` means two different types in this file. `CallFrameCaches` is a pile of `Mutex<HashMap<...>>` memo tables (14965-15003), which is the pattern the repository's dense-id rule later forbids.
- Memo keys use raw pointer addresses of statement/call nodes (11076-11078), so identity of a call site is the address in the typed tree.
- `invocation_result_transport` fabricates a result home with an invalid call handle (14709) for bodyless/requirement callees.
- Placeholder "`self`" and "`invocation result @i:g`" strings are fed through the same prefix-by-string machinery as real paths (12219, 12688, 8906).
- A fixpoint without a counter: the cyclic iteration (12203-12253) ends only if `substitutions_are_finite` (12821) was correct; the two are far apart and share only the equations.
- `build_cycle_frame_equation` does not visibly handle assembly statement effects (12381-12383), and `substitutions_are_finite` skips local-rooted sources (12898-12900).
- `boundary_trait_signature_and_receiver_inner` (7826-8027) checks eleven separate conditions in one function and returns `None` for each; the same selection is invoked under three binder modes (`Monomorphic`, `AppliedStorageParameters`, `CallBinders`) from different entry points (7650, 7668, 7688, 7707, 7724, 8809), so which mode a given caller gets is decided by which wrapper it calls.
- Scalar-local detection (14914-14946) lists builtin atoms by hand (Bool, Address, I8..U64, F32, F64); a new primitive would be silently excluded.
- Attached to every `CallFrameResolver` lookup are separately maintained caches for statements, expressions, assignments, local origins, reference results, binding replacements and so on (14965-15003): about 18 cache tables whose invalidation story is not visible in this slice.
