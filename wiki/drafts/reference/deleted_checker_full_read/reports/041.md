## What this code is for
This is the second half of the old checker's index and subslice bounds check. For every `collection[index]` and `collection[a..b]` in a state body it decides whether the index or window provably lies inside the collection, and refuses the program when it cannot. The entry is `check_indexed_accesses` (10980-11177); it walks each state's statements in order, carrying a per-state store of facts (`RangeFacts`, defined in another file, `checks_ranges_facts.rs`, pulled in at 8859-8860). The slice holds: the bounds judgment itself (`mod indexes`, 5368-7166), the statement-by-statement fact transfer shared by the checking pass and a second "state argument" replay pass (`mod statement_transfer`, 7168-7566), the per-statement seeders for aliases, windows, call results and stores (`mod statements`, 7567-8337), array-type helpers (`mod arrays`, 8343-8429), failure classification for messages (`mod diagnostics`, 8430-8595), constant folding and length queries (`mod expressions`, 8596-8858), the guard-to-fact pattern table (`mod guards`, 8861-9951), the proofs for unknown-length and const-parameter extents (`mod proofs`, 9952-10476), and type queries (`mod types`, 10477-10964). The check has four lanes chosen by what the collection's extent is: a known number, an unknown slice length, a const generic parameter, or a "constant recipe" (`[T; call()]`) whose value is fixed later. Its output is a list of index expressions it proved, some fixed coordinates, and recipe obligations for a later stage, or a list of diagnostics (11172-11176). It also re-validates the user-declared `[]` / `[..]` operator chosen at each occurrence and reads that operator's `requires` clauses structurally (5705-6136).

## Mechanisms
- **Forward per-state fact transfer** (11095-11151, 7265-7524). For each state that contains an indexed expression, a fresh `RangeFacts` is seeded from the state's `requires`, state-argument facts, incoming guards and loop invariants (11117-11134; those collectors are outside this slice), then statements are replayed in order. Transition edges clone the fact store and narrow it by the guard (7493, 7507). There is no fixpoint inside this slice.
- **One statement transfer, two sinks** (7213-7256). `transfer_statement_facts` fixes the order (visit expressions, extent-window decision, invalidation, seeds, call edge, write-frame invalidation, ensured-result seeds, guard narrowing; 7258-7264). The checking pass and the state-argument collection pass plug in different `StatementTransferSink`s.
- **Two-pass deferred collection bounds** (11092-11163). Pass one runs with empty `CollectionBoundsDemands`; the demands it raised go to `collection_bounds.resolve_deferred`; if that returns true the whole machine is checked again with the resolved table and the first pass's diagnostics are discarded. Budget: exactly two passes.
- **Provisional diagnostics with rollback** (6219-6220, 6348-6349, 6365-6366). A failed extent-specific attempt pushes diagnostics and obligations; a later independent proof (`captured_fixed_index_bounds` or `CollectionBoundsObservations::proves`) truncates both vectors back and returns proven.
- **Operator selection replay** (6105-6135). Builds a scratch `CheckedOperatorFacts` with the live candidates, status `DomainPending`, reruns the selector, and compares with the retained choice.
- **Structural clause reader with coverage bits** (5767-5799, 5802-5923). Each recognised `requires` clause sets a bit (1 strict/ordering, 2 end <= len, 4 and 8 non-negativity); completeness is `coverage & required == required`. Recursion budget 128 (5809, 5885).
- **Constant folding** (8672-8727). `expression_integer_value` folds literals, binaries (`validation::folded_integer_binary`), calls whose ensured low and high are equal, locals and fields with a recorded integer, and matches whose arms all fold to the same value; a checked-call "immutable integer value" is consulted first (8681-8685). All in i64.
- **Minimum over upper-bound sources** (6448-6458, 9452-9467) and intersection of declared domain bounds (10727-10749).
- **Zero-offset reduction** (6564-6596): strips `+ 0`, `0 +`, `- 0` built only from literals before proving.
- **Length derivation** (8754-8849): string literal length, window length `end - start`, field and local lengths, through borrows.
- **Verdict aggregation** (7018-7043): sort by handle position, all-of per handle, keep a coordinate only when every verdict agrees.
- **Parallelism** (11003-11166): rayon over machines; state-argument facts are collected once per machine-family root (11017-11048).
- **Type peeling loops**: bounded 128 in `has_builtin_collection_geometry` (6079); unbounded recursion elsewhere (6883-6910, 8372-8397, 10607-10619, 10917-10934).

## Accepts or skips without proof
1. **Arrival judged impossible** (6203-6209): if `facts.closed_integer_arrival_is_impossible` is true, the access is returned as proven with no bounds check, before the collection kind is even examined. The decision is `validation::scoped_arithmetic_comparisons_unsatisfiable` over guard comparisons retained at 9655 (`checks_ranges_facts.rs:509-536`). Own engine, no kernel evidence. I cannot see another check.
2. **`Unsupported` is silent** (6277, 6291). No diagnostic is pushed and the occurrence is recorded as not proven (7161). What a consumer does with an unproven, unrefused index is outside this slice; cannot tell.
3. **`has_builtin_collection_geometry` returns true** when the type reference is not in the table (6080-6085) and after 128 peels (6097); `ranges_seam_owns` returns true when the collection's operand type is unknown (6068-6072). "True" tells the operator-`requires` check that this check discharges the occurrence. If this check then returns `Unsupported`, neither has proven it; cannot tell whether something else catches it.
4. **No operator applies** (5947-5957, 5976-5989, 6026-6033): `obligation` returns `Ok(None)`, meaning builtin indexing with no `requires` attribution; for a non-builtin collection the `requires` is left to the selected-operator discharge named in the comment at 6057-6062 (outside this slice).
5. **Recipe extents are deferred** (6425-6434, 6469-6478): the comparison with the extent is not decided here.
6. **Recipe extent, open-ended window** (6424-6436): for `collection[start..]` with a constant start, the code checks `start >= 0` and pushes no obligation, so `start <= extent` is neither proven nor recorded. I cannot see another check.
7. **Fallback proofs erase diagnostics** (6334-6351, 6360-6372): trusts `checked_calls.captured_fixed_index_bounds` and `CollectionBoundsObservations::proves` (other modules).
8. **Callee `ensures` is a premise everywhere** (`ensured_call_result_bounds`: 5680, 6444, 6641, 7150, 8696, 10007, 10179, 10223, 10395, 10472, 10657). Comments say it "is discharged at every callee exit" (7713-7716) and "checking their formation and each callee's return remains an independent duty" (10633-10635). The discharge is not in this slice.
9. **Boundary-trait `ensures`** seeds upper bounds on `&mut` arguments (8286-8336); a boundary callee's body is external. Cannot tell where, or whether, that contract is established. Comparisons other than `<=` and `<` are skipped (8329); an unresolved signature or missing origins seeds nothing (8294-8301), which is the safe direction.
10. **Declared types are trusted**: declared domain range (10637-10679, Exact shells only), unsigned type (10533-10544), fixed array length from the type (6214-6217, 7419, 8108-8114, 11113).
11. **Assembly statements change no facts** (7275) and are never searched for indexes (11200). If inline assembly can write a tracked place, no fact is retired here; cannot tell.
12. **Call write paths may be absent** (7398-7406): when `call_frames` is `None` or the frame is incomplete, `invalidate_call_writes` receives `None`; what it then retires is in the facts file. Cannot tell.
13. **Guards**: a guard that is not read-only, or with no `call_frames`, seeds nothing (7481-7488); a guard without builtin decomposed meaning seeds nothing (9368-9370); operators with no pattern seed nothing (9819-9830, 9947). All refuse-leaning.
14. **`x <= base - k` taken as `x < base`** with no arithmetic-domain check at `seed_at_most_fact` (9269-9283), `len_bound_minus_offset` (8900-8915) and, for addition, `positive_offset_base` / `seed_successor_at_most_len_fact` (9059-9085, 9122-9143). A wrapping or saturating `base - k` or `i + k` would not justify these facts. Other sites in the same file do guard against this (8191-8195 and 8233-8239 for stores; 10359-10363 for `len - k`; 9619 for const binders). The only gate on the guard path is `has_builtin_decomposed_guard_meaning` (9368); cannot tell whether it excludes non-exact domains.
15. **`place == K` on a member** records the integer under the member symbol and name with no receiver (9851-9853); member reads fold from the same key (8706-8708). See Surprises.
16. **Empty declared range** becomes the sentinel `(1, 0)` (10745-10746), which then satisfies `high < length` and `low >= 0` at 6660-6662 and 6682. Vacuous if the type is truly uninhabited; no check here that it is.
17. **Absent range endpoint** counts as non-negative (5655-5657) and full range `[..]` is accepted (10102, 10339). Both are correct by definition.
18. **States with no indexed expression are skipped** (11100-11102), and transition targets whose arguments have no "sink effect" are not visited by the checking pass (7960-7976). Safe as far as this slice shows, because facts are rebuilt per state.
19. **`align_of` proof discards obligations** (7107: `&mut Vec::new()`): a recipe obligation raised while proving `view[0]` would be dropped. The view is a slice, so the recipe lane should not be reached; noted for completeness.
20. **`type_reference_for_symbol`** falls back to the parameter of any other state of the machine carrying that symbol (10908-10914).

## Surprises
1. **No proof kernel anywhere.** A search of the 5,900 lines finds no `proof_admission`, `ProofNode`, `verify_obligation` or certificate. Every acceptance is a `bool` or a `BoundsCheckResult` computed here or returned by a `validation::` helper. The published result is a bare list of expression handles (10989-10996, 11172-11176). This supports property 1.
2. **Field integer facts ignore the receiver.** `expression_integer_value` folds `a.count` from `facts.field_integer(member.member_symbol, name)` (8706-8708), and a guard `a.count == 3` or a store `a.count = 3` records under the same key (9851-9853, 7366). The key is the field's declaration symbol with a name fallback (`checks_ranges_facts.rs:4816-4834`, 4865-4871, looked up outside the slice). As written, `a.count == 3` would let `b.count` fold to 3 when `a` and `b` share a data type, and the folded value then decides an index at 6707-6708. Whether invalidation or an earlier restriction prevents two receivers of one type in scope, I cannot tell from this slice. The module comment at 10478-10484 warns against exactly this kind of borrowing "another record's range".
3. **Subtraction and addition in guards are read as exact.** See item 14 under "Accepts or skips": `x <= base - k` is recorded as `x < base`, and `i + k <= c.len` as `i < c.len`, with no arithmetic-domain test at those sites, although the authors spell out the wrapping and saturating hazards for the equivalent store rule (8191-8195) and for `len - k` endpoints (10359-10363).
4. **Recipe extent with an open-ended window records nothing about the start** (6424-6436).
5. **Greater-than guards lose the literal upper bound.** `Less` calls `seed_index_less_than_integer_fact` (9663) and `LessOrEqual` calls `seed_index_at_most_integer_fact` (9709); the mirrored `Greater` and `GreaterOrEqual` arms (9676-9690, 9722-9751) do not. So `5 > i` and `!(5 <= i)` seed no `i < 5` bound while `i < 5` does. This is a completeness gap, not an unsoundness, and it shows what hand-mirroring costs.
6. **The message classifier can disagree with the proof.** `diagnostics::range_bound_is_proven` (8562-8572) has two alternatives; `proofs::range_bound_is_proven` (10459-10475) has four. The label in a "start bound / end bound / ordering / bounds" message is computed by the weaker copy. `unknown_length_range_failure` is also used for const-extent failures (6795-6797), where it tests the unknown-length facts, not the const-extent ones.
7. **`ReferentExtent.minimum` without `exact` is unreachable.** In `bound_reference_referent_extent` the match at 8121-8125 returns `None` unless every origin yields an extent, so `exact` is always `Some` on return. The comment at 8029-8033 says variable-fill carriers "hold their live length in this lane — their capacity says nothing about the current extent", but a floor alone can never be returned, and when it is returned it accompanies an `exact` taken first from the declared fixed-array length (8108-8114).
8. **Two different "caller" arguments.** `ensured_call_result_bounds` is called with `facts.caller` at 5680, 6444, 6641, 7728, 8696, 10007 and with `machine.symbol` at 7152 and 10657. `RangeFacts::new(machine.symbol, ...)` (11104) suggests they are equal in the checking pass; the state-argument replay may differ. Cannot tell.
9. **Empty declared range is handled two ways.** Without a callee contract `expression_enforced_declared_range` returns the `(1, 0)` sentinel (10659, 10746); with one, the same empty range returns `None` (10678).
10. **A large share of the judgment re-checks another stage.** About 430 lines (5705-6136) re-derive the operator selection and compare it with the retained row, with ten distinct "custody" errors. That is consistency checking between two of the old checker's own tables, not a language rule a user can violate by writing a program.
11. **User operators over builtin geometry are confined to five clause shapes.** Any other `requires` on a `[]` / `[..]` operator whose collection is a builtin array or slice is refused with "bounds alone cannot discharge it" (5776-5782), even if it could be proven. The reader also requires the completeness bits (5786-5795), so an operator with no `requires` is refused as not stating "the complete collection-relative bounds obligation".
12. **Naming conventions of an earlier stage are load-bearing.** `__hoist_` (6523) and the `__transition_subject` copy described at 7540-7546 are recovered here by string prefix or by following a boolean alias. `hoist_temp_initializer` takes the first `let` in the whole state with that name and does not check its position relative to the index (6526-6536), although the comment says it is "immediately before".
13. **The module header contradicts its helper.** The `types` header says field identities never come from a same-spelling search (10478-10484); `data_definition_by_symbol_or_name` in the same module compares names when the symbol is invalid (10956-10962).
14. **A dead statement**: `let _ = bound_lookup.immutable_binding_type(symbols::SymbolHandle::invalid());` (10999) computes nothing that is used.
15. **The extent-window diagnostic has no location** (8013-8015): no source span, no expression name, no machine or state.
16. **Discarded provisional diagnostics.** When `resolve_deferred` returns true, all first-pass diagnostics for the machine are thrown away and only the second pass counts (11154-11162).
17. **Unchecked `upper - 1`** at 10219 and 10471 on i64 values that come from `checked_add` results elsewhere; it overflows only for `i64::MIN`, which no seeder in this slice produces.
18. **Property 3 holds here mostly by extent kind and operand order rather than by source placement.** The placement split that does exist is the assignment target (local name, member, anything else: 7336-7392) and the separate `LocalData` arm. A fact stored to an indexed target (`a[i] = v`) gets no value seeding at all.
