## What this code is for

These three files are the data model that the old checker (pipeline stage `05_typed-trees-to-checked-trees`) wrote its results into, and that later stages read. They are almost entirely record and enum definitions; they contain very few checks of their own.

`flow.rs` defines the per-state "flow facts": one row per state, statement, call, exit, operand, storage snapshot, invalidation and borrow event (flow.rs:1-5). It also defines the "store plan" for an assignment (flow.rs:1675-1892) and small query helpers.

`roots.rs` defines the arenas that hold those rows (`FlowFacts` and its six groups, roots.rs:20-509), the ownership records (permission events, owned selections, claim joins; roots.rs:1737-2099), and one real algorithm: counting how many times an owned value is definitely handed to a call along every normal path (`computation_custody`, roots.rs:670-1735).

`terminal.rs` defines the "checked Terminal lowering plans" (terminal.rs:1-6): the instructions the checker hands to lowering for cleanup of affine values, atomic access, boundary machines, calling signatures, place loans, result bindings, scalar state terminators, structural arguments, control transfers, returns and type shapes.

The checker's verdicts arrive in this model as plain fields (booleans, enum tags, handles to "decision" rows). Nothing in the slice calls a proof kernel.

## Mechanisms

**Counting definite call transfers** (roots.rs:670-1623). Given a producer operation that binds a structural result (roots.rs:971-998) and optionally the local that holds it, `CallTransfers` walks a consumer plan and returns how many times the whole owned value is handed over. It recurses over operations (roots.rs:1529-1607), structural value trees (`structural`, roots.rs:1397-1508, and `constructed`, roots.rs:1069-1153), scalar computation trees (`computation`, roots.rs:1257-1395), byte-sequence values (roots.rs:1510-1527), completion expressions (roots.rs:1214-1255) and scalar state terminators (roots.rs:905-969). It sums along sequences and takes the minimum over alternatives, so the answer is a lower bound that holds on every normal path. Two lists, `established_values` and `completed_computations`, stop a subject or operand that was already evaluated from being counted again (roots.rs:774-775, 1075, 1230-1247, 1258, 1295-1311, 1402); they are searched linearly. There is no budget or depth limit; the comment at roots.rs:1088-1090 records one cycle the authors had to break by hand. It serves affine ownership: the callers are in `execution_terminal_unit_state_graph.rs` of stage 05 (outside this slice).

**Chasing a local back to its result binding** (roots.rs:694-731). Walks the operation list backwards through owned-rebind stores, one local at a time, sharing one iterator so each step continues where the last one stopped. Gives up on any partial path.

**Storage snapshots** (flow.rs:1093-1121). A snapshot is a linked list node (`previous`) with one operation: unknown, a set of writes with completeness flags, a store, a preserved binding, or a join of predecessors. This slice only defines the data.

**Paged arenas with generations** (roots.rs:511-662). The macro `paged_flow_roots!` gives each of the six root groups `share_pages`, `reset_pages`, `begin_page`, `take_additional_pages`, `adopt_additional_pages`, `latest_page_generation` and `take_pages_from(generation, baseline)`. A worker can add rows on its own page and the owner can adopt or remove them. It serves per-state parallel or speculative checking; `WalkGuard` (roots.rs:71-119) tells the owner whether the worker read another state's rows (used at `checks_multiplicity_permission_events.rs:687, 739`, outside this slice).

**Lazily built grouped indexes** (flow.rs:1170-1389; roots.rs:144-148, 189-238, 268-269, 298-314). `KeyedRows` groups arena rows by a key (machine, state, call page generation, expression). `FlowStateTable` drops its groupings on any mutable access (flow.rs:1287-1295) and keeps them on `update_row` when the three grouping keys are unchanged (flow.rs:1270-1284).

**Descriptor observation index** (flow.rs:417-566). A vector sorted by context (generation, arena index), searched by binary search, rebuilt after page moves.

**Cleanup partition tree** (terminal.rs:38-115). A tree of `Scope`, `Leaf` and `Cases` nodes that says which cleanup actions are per case and which are common; each case arm has a reachability tag (`Runtime`, `Selected`, `Inactive`). Data only in this slice.

**Result-action iterator** (terminal.rs:176-213). Depth-first walk with an explicit stack over a result completion tree (`NoNormal`, `Value`, `Dispatch`), yielding the cleanup actions at each value leaf.

**Return-path enumeration** (terminal.rs:1079-1182). For each returning exit of a scalar state it gives the destination and the guards evaluated before it (guard `i` sees arms `0..=i`; the fallback sees all).

**Total orders for canonical sorting** (terminal.rs:1209-1236, 2355-2408) on reference storage and on path segments.

**Pattern macros** (flow.rs:202-224; terminal.rs:2299-2305). Macros that expand to a list of enum variants so a `match` can stay exhaustive without naming each one.

## Accepts or skips without proof

- **Entry constraints fall back.** `state_call_entry_constraints` returns the call's entry constraints; if the call is not found it returns the statement's; if the statement is not found it returns the state's (flow.rs:2146-2167). A failed lookup therefore answers with constraints from an earlier point. I cannot tell from this slice whether a later check catches a missing call row.
- **First match wins.** `state_by_symbol` and `state` return the first row when several rows share a state symbol (flow.rs:1339-1346, 1360-1367), though the test at flow.rs:1396-1428 shows duplicates do occur. `call_at`, `call_position` and `retire_calls` use the first-match versions (roots.rs:396, 408, 433). `value_completion`, `for_machine`, `for_state`, `for_edge` and `checked_structural_type_by_identity` also take the first match (terminal.rs:215-229, 289-296, 311-316, 1699-1719, 2475-2480, 2544-2549). `for_edge` keys an edge by statement ordinal alone (terminal.rs:1709-1719). Cannot tell whether uniqueness is checked where the rows are written.
- **Transfer count defaults to zero.** `definite_call_transfers` returns 0 when the producer has no structural result binding (roots.rs:749-750, 762-763, 807-811, 825-829), when the plan is not `Exits` (roots.rs:804-806), when a completion is malformed or has no normal continuation (roots.rs:839-842, 1618-1621), when the guard roster span is stale (roots.rs:911-913, 951), when a scalar root is missing (roots.rs:875-878), and when a call schedule is missing (`unwrap_or(&[])`, roots.rs:1064, 1205, 1306, 1364, 1379; `map_or(0, ..)`, roots.rs:1411-1427). Zero means "not handed to any call". Whether zero is the safe answer depends on the caller in stage 05; cannot tell from this slice.
- **Catch-all arms in the count.** `source_is_retained` returns `true` for every source that is not an expression with a value dependency (roots.rs:1019). `constructed` sends every other value kind to `structural` (roots.rs:1151). `argument_transfer` returns "not the owner" for every other source (roots.rs:1038). `for_producer` uses an invalid expression handle for any other producer (roots.rs:985-987). `current_result_binding` returns `None` for any other source (roots.rs:708).
- **A store counts as a transfer only from a structural local.** A place store whose source is a call result or an evaluated expression counts only its index computations (roots.rs:1567-1576). A case-literal store counts 0 (roots.rs:1577). Cannot tell whether another path covers those.
- **Missing argument order means left to right** (roots.rs:379-382). Accepts without a recorded order.
- **Retiring a call with no authored expression** matches on "statement root and call ordinal 0" (roots.rs:441-445). A positional guess; cannot tell whether other calls can lack an authored expression.
- **Filter arms with `_ => None`** (flow.rs:1984-1987, 1996-1999) while sibling filters match exhaustively through the macros (flow.rs:1912-1915, 2025-2030). They only filter, so nothing is accepted, but a new constraint kind would be silently skipped by two of the four.
- **Fixed index accepts any computation.** In `projection_evaluations_match` a `FixedIndex` segment accepts any valid child handle (terminal.rs:1459); only `ComputedIndex` is compared (terminal.rs:1460-1462).
- **Saturating count.** `call_selector_positions` uses `saturating_sub` when there are more kept evaluations than index segments (terminal.rs:1390), where `projection_evaluations_match` and `selector_computation` refuse (terminal.rs:1449-1451, 1501-1503).
- **Continuation not checked on one path.** `returning_exits` requires `is_continuation: false` on guarded arms (terminal.rs:1113-1119). `returning_paths` only requires `Return { .. }` for the two arms of a conditional (terminal.rs:1142-1153, 1172-1179), so a continuation return passes there.
- **Boundary machines expose no erased parameters or entry claims.** `callable_entry` hard-codes three empty slices (terminal.rs:759-761).
- **Pending requirements are carried, not decided.** `pending_scalar_requires` and `pending_scalar_recipes` sit beside the closed `scalar_requires` (terminal.rs:740-742). The deciding code is elsewhere.
- **Trusting a valid handle.** `is_partial_affine_field_type` answers `true` for any structural field with a valid type identity (terminal.rs:2444-2446). `cleanup_type_identity` returns the invalid identity for all other field types (terminal.rs:2175).
- **Zero-value defaults that read as real answers.** Many records derive or implement `Default` with a meaningful value: `FlowPermissionEvaluation::Statement` (roots.rs:1784-1785), invalidation and transfer source "statement 0" (flow.rs:682-686; roots.rs:1749-1753), `FlowCallResult::Operand`, `FlowCallDispatchRole::Ordinary` (flow.rs:310-311, 318-319), `CheckedNormalCompletion::Possible` (terminal.rs:475-476), `CheckedCleanupCaseReachability::Runtime` (terminal.rs:119-120), `CheckedReferenceStorage::Declared` (terminal.rs:1196-1197), access `Owned` (terminal.rs:928, 1370), cleanup action `Discard` (terminal.rs:399-403), partition node `Leaf { ordinal: 0 }` (terminal.rs:104-108), guarded exit "return at statement 0" (terminal.rs:1031-1041), scalar argument type `Bool` (terminal.rs:1830-1838). Other enums default to an explicit `Unknown`, `Unbound`, `Unresolved`, `Unavailable` or `Inactive` (flow.rs:172-173, 301-302, 735-736, 868-869, 1101-1102; roots.rs:1816-1817, 1982-1983, 2051-2052). `FlowOperandFact` overrides its evaluation default to `Unknown` by hand (flow.rs:942). An unset row of the first group is indistinguishable from a set one.
- **Guard that does nothing when unset.** `WalkGuard::note` returns at once when no guard is installed (roots.rs:89-92), and `WalkGuard` equality is always `true` (roots.rs:113-117).

## Surprises

1. **The slice is the checker's output format, and it shows no proof kernel at all.** A grep of the three files for `proof_admission`, `ProofNode`, `verify_obligation` and "certificate" finds nothing. Proof-related data here is `ContractProofFactRef` spans (flow.rs:280-281, 382), a `ContractProofFact` handle in a "receipt" (roots.rs:2093-2099), `CheckedProofTerm` for erased proof arguments (terminal.rs:1689, 1753), a `MachineContractCommitment` and a 64-bit fingerprint (terminal.rs:745-746). The words "receipt", "decision", "custody" and "proof" name rows that the checker itself wrote. This supports property 1 for this slice: a consumer of these records gets booleans and handles, not evidence it can re-check.

2. **The same value can be named in many incompatible ways.** There are two path vocabularies (`facts::PlaceSegment` in flow facts, `CheckedUnitStructuralPathSegment` in plans) with a bridge enum whose default is `Unresolved` (roots.rs:1814-1821), and at least seven "root" encodings (listed under repetition). Parameters are a `position` in store roots and a dense `parameter_index` in argument sources, converted by a linear search that can fail (flow.rs:1724-1734). This is the placement-per-case property showing up as types rather than as code.

3. **Flow facts point back into source trees.** `FlowCallFact` carries `authored_expression`, `authored_arguments`, `authored_receiver`, `authored_target`, `authored_source_span` and a flag `authored_source_custody_valid` (flow.rs:254-265, 286-287) beside the resolved `receiver_symbol`, `target_symbol` and `has_receiver`. The receiver is recorded three ways (expression handle, symbol, boolean), and `argument_operands` trusts the expression handle (flow.rs:291-296). The checked form is not self-contained.

4. **`constructed` and `structural` disagree on the same value kinds** (roots.rs:1069-1153 against 1397-1508). For a `Projection`, `constructed` counts the index computations along the path (roots.rs:1122-1128); `structural` does not (roots.rs:1454-1457). For a `Place`, `constructed` can count a transfer (roots.rs:1091); `structural` never does (roots.rs:1500-1503). For a record field, `constructed` passes `consumes_whole = true` (roots.rs:1103) while a fixed-array element also gets `true` (roots.rs:1109), but a projection passes it only when the path is empty and the value is not copied (roots.rs:1121). Which walk runs depends on how the caller reached the value, so the count for one value can depend on its placement. I cannot tell from this slice whether any program reaches the differing cases.

5. **"Call transfers" also counts stores.** `operation` counts a `Store` of a place whose source is a structural local as an argument transfer (roots.rs:1567-1575), though every public name says "call transfers".

6. **`take_additional_pages` moves the whole retired-call list.** The macro does `taken.$list = std::mem::take(&mut self.$list)` (roots.rs:541, 562), so after a page split the source keeps none of its retired calls, including those that belong to pages it kept. `adopt_additional_pages` appends them back (roots.rs:547). If a split is not followed by an adopt, retired calls reappear as live. Not covered by a test in this slice.

7. **`WalkGuard` compares equal to everything** (roots.rs:113-117) and is skipped when encoding (roots.rs:149-150), so two `FlowOwnershipFacts` that differ only in whether a walk crossed states are equal. The `crossed` flag is an atomic written through a shared reference by read-only query methods (roots.rs:89-104, 194, 208, 222): reading a fact has a side effect.

8. **A call's owner is found by arena page generation.** `call_rows` groups states by the generation of the first handle in their call span (flow.rs:1256-1262, 1298-1324). Ownership of a call is therefore tied to which page it was allocated on. The test at flow.rs:1478 shows two states can own the same call span.

9. **Equal revision numbers do not mean equal content.** The tests assert that two different arenas have the same revision and then check the index is still rebuilt (flow.rs:1497-1502, 1606-1609). The index is correct only because `DerefMut` clears it (flow.rs:1287-1295); a comment at roots.rs:266-267 says another index "follows the operand arena's exact mutation revision", which these tests show is not enough by itself.

10. **Continuation returns are checked on guarded exits but not on conditionals** (terminal.rs:1113-1119 against 1142-1153 and 1172-1179). See "Accepts or skips".

11. **Errors stored as data in a checked plan.** `CheckedCallingSignaturePlan` holds `Result<_, String>` twice (terminal.rs:782-783). A calling signature can be published as "checked" while carrying a failure message for a later stage to act on.

12. **"Unsupported" is a checked result.** `CheckedTerminalSignatureEligibility::Unsupported` (terminal.rs:2535) and the re-exported `CheckedUnitPlanGap` / `CheckedUnitPlanGapReason` (terminal.rs:2662) show the checker recorded, per machine, that lowering could not handle it. Acceptance by the checker and ability to lower were separate answers.

13. **Path-segment sort order depends on allocation.** `ComputedIndex` segments are ordered by arena index and generation (terminal.rs:2385-2388), so a canonical sort of paths changes with the order in which computations were allocated. The kind order (terminal.rs:2358-2370) does not follow the declaration order (`AllElements` is declared first and sorts last), which suggests variants were added over time with the old order kept.

14. **Byte-sequence root lookup by scan.** `completed_call_binding_ordinal` and `literal_bytes` find the root node by iterating the arena and comparing handles (terminal.rs:946-969), while `computation_custody::bytes` calls `nodes.get(root)` directly (roots.rs:1515). The scan tolerates an invalid root; the direct call does not.

15. **An awkward empty iterator.** `result_actions` starts with `self.actions.span_or_empty(HandleSpan::empty()).iter()` (terminal.rs:185-188) only to get an empty iterator of the right type.

16. **Two types lack the storage derive their siblings have.** `CheckedUnitNominalAffineCleanupRequirementPlan` (terminal.rs:360-364) and `CheckedReferenceResultSourcePlan` (terminal.rs:1938-1942) do not derive `compiler_storage::Record`, so they cannot be part of the stored checked form. Both are still used elsewhere in the old tree (stage 05 cleanup code and `validation/src/reference_result_custody.rs`), so they are transient, not dead.

17. **The reference-origin model is very large for what it says.** `FlowOperandFact` has 22 fields (flow.rs:909-933) and `FlowOperandRetention` 14 (flow.rs:751-767), with separate records for reborrow sources, retained regions, suppliers, stored sources, leaves, alternatives, lifetime contracts and output lifetime sources (flow.rs:769-864). `FlowControlFacts` needs 36 arenas to hold it (roots.rs:253-295). These are overlapping ways to say where a reference came from; the slice holds no code that reconciles them.

18. **Capabilities I did not expect in a checker's output:** atomic compare-exchange with a "once" variant that carries result custody (terminal.rs:574-580); static interrupt operations as a boundary execution kind (terminal.rs:722); register access and a global descriptor table as effect operations (roots.rs:1588-1593); service reach, suspension and blocking summaries on every call and state (flow.rs:282-285, 411-413); natural-number rank measures for termination, re-exported from another file (terminal.rs:2601-2604).
