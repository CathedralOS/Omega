## What this code is for

This file builds the tables the old checker published next to the typed program ("What checking publishes beside the typed program", 1-7). The slice holds three parts. `labels` (11-611) turns machines, symbols, places, facts and operator contract expressions into text, and one of its functions decides whether a retained fact proves a requirement by comparing that text. `places` (612-637) is a one-function wrapper that asks `validation` which storage place an expression denotes. The start of `proof` (638-5348) builds "checked proof facts": which contract clauses belong to which machine, state, trait signature, call site or operator use (`contracts`, 653-2090); how named evidence is forwarded from `requires` bindings to `ensures` bindings and whether every named `ensures` evidence output is assigned exactly once on every exit (`evidence_forwarding`, 2091-3102); the rows that record float "meaning" projections and equalities in contracts (`float_meaning`, 3103-4570); a conversion of proof obligations to their checked-tree form (`obligations`, 4571-4733); and the facts a caller gains in a `when result is Case` arm from a callee's outcome-specific guarantees (`outcome_arms`, 4734-5348). Most of the code records identity and ownership of facts; a smaller part actually refuses programs, and when it does it decides by its own comparison. Nothing in the slice calls a proof kernel.

## Mechanisms

- **Text instantiation of operator contracts** (284-436). Renders an expression tree to a string, replacing each formal parameter by a caller-supplied operand label. One arm per `ExpressionNode` variant (20 variants). The result is stored as the "instantiated expression" of operator `ensures` facts and compared against fact text for operator `requires` (comment 276-283). No budget; recursion follows the tree.
- **Polarity decomposition** (444-470). General over `!`, `and`, `or`, literals; leaves delegated. Used by "operator-use discharge and the statement-entry discharge" (438-443).
- **Trait contract inheritance** (1361-1511). Depth-first walk of a machine's conformances and each trait's parent requirements, with a `visited_traits` stack as cycle guard (1401-1405, 1510) and `validation::compose_forwarded_trait_arguments` composing type arguments at each step. A mirror walk only counts capacity (1513-1585).
- **Machine-parameter evidence signature walk** (1894-1949). Iterative stack over nested type parameters, deduplicated by a `HashSet` of raw `*const TypeParameter` pointers (1908-1911). The comment says this makes "a malformed cyclic signature span terminate" (1890-1892).
- **Definite assignment of evidence outputs** (2441-2703). Per machine, a breadth-first worklist of `(state, assigned map, known label set)` starting at the entry state with the machine's `requires` proposition labels (2487-2497). Each state adds its own `requires` labels (2518-2523), then walks statement coordinates `0..=len`, taking in proof-output propositions (2548-2554), applying assignments (2555-2577), taking in call `ensures` (2582-2584), and at the first run of transitions either pushing same-machine targets or reporting at exits. A `seen` set keyed on the whole triple stops revisits (2501-2513). There is no budget; the number of triples is bounded only by the combinations of assignments and label sets. Serves named `ensures` evidence and outcome-specific guarantees.
- **Callee result-case summary** (2917-2991). Recursively collects the `(data, case)` pairs a machine's ordinary exits can produce: every ordinary transition target value, every trailing expression, and a callee's cases for calls. A machine already on the `visiting` stack contributes an empty set (2925-2927). Any exit that is neither an exact constructor nor a call to a checked machine makes the whole answer `None` (unknown). Named in the comment as `callee-result-body-summary` (2912). Used to let a caller skip a guarantee for a case the callee cannot produce (3053-3059).
- **Terminal-call discharge** (2858-2906, 2999-3087). Instantiates the callee's guarantees at the call's arguments into rendered labels, then matches caller guarantees to them by label equality and case.
- **Float projection canonicalization** (3668-3805). Hash-consing by linear search over two vectors: one id per distinct transitional source key, one proof value per `(source, operation, contract)`. Literals key on their exact bits (3261-3267, 3678-3683).
- **Contract carrier index** (3299-3357). One walk over every machine and state contract expression to record which contracts contain each validated projection invocation.
- **Post-order binding of semantic applications** (4353-4390). Visits children first, binds each `FloatSemantics::*` call to a row, then emits an equality for each `==` with an application operand; `visited` list stops revisits.
- **Per-use-site instantiation of transported `ensures`** (3947-4065). For every contract call and every operator use, re-binds `result` to that use's produced value and each callee parameter to the argument expression at that use.
- **Saved-result chase** (4984-5014). Follows a name back through immutable local initializers, each strictly earlier in the admitted execution order, until it reaches a call. Mutable locals, missing initializers and later bindings end the search with `None`.

## Identity by text

- The module header says so: "Most uses are diagnostic text, but some labels are compared" (31-35), naming operator `ensures` facts, the operator `requires` check, named operator crash routes, and `semantic::places` matching "parameters by `symbol_name`".
- A fact proves a requirement when two rendered strings are equal (132, 83-84); domain clauses are compared after being rendered onto a place label, with two candidate labels, canonical and display (109-121).
- `call_target_label`: a state named `"entry"` on a machine without attached data is labelled with the machine's name (202).
- `symbol_name` returns `"unknown"` for an invalid symbol (232-234); fallback strings "unknown domain membership", "unknown carry permission", "unknown boolean expression", "unknown proposition application", "unknown contract fact" (507, 526, 537, 542, 543).
- Operator contract instantiation: a name is taken to be a formal parameter when the first path member's text equals the parameter's name, or a symbol matches (412-414). A saved subject is rendered `"$saved-subject#{index}:{generation}"` (300-304). Member access is joined with `PLACE_MEMBER_SEPARATOR` (377-382).
- A machine selects a trait requirement by the requirement's name (1627).
- Evidence terms are found by name: `evidence_term_named` (3089-3101), `evidence_term_in_scope` (2349-2372), proof-output terms (2147-2149), contract binding versus term name (3032).
- Named implementation: alias string equals source name (2384); the trait is found by `candidate.name == conformance.trait_name` (2387-2390).
- Evidence projection: interface requirement found by `symbols.name(row.requirement) == projection.member` (2283); the normalized argument is found by `diagnostic_label == format!("{}.{}", term, member)` (2302, 2314), and the label is then cleared (2315).
- Definite assignment's `known` is a `BTreeSet<String>` of labels (2487-2497, 2713); proof is `known.contains(label)` (5304, 5314). Labels are `"boolean:" + rendered expression` or a normalized proposition identity string (5260-5283).
- Terminal-call discharge compares `row.label == label` (3013); diagnostic messages themselves are deduplicated as strings in a `BTreeSet` (2448, 2698-2701).
- `result` is recognized by spelling: `name.as_str() != "result"` (3446), `name.is_reserved_result()` (3842), `names_reserved_result` (3859); whether `result` means the return value or a parameter is decided from the parameter names (`language_core::signature_reserves_result`, 3460-3465, 3835-3841). Substitution triples carry `"result".to_owned()` with an invalid symbol, so the substitution is by name (5147-5151, 5298, 5334).
- Float projection operation is recovered from two strings, operator namespace and name (3597-3603).
- Outcome selectors: binding names in a string set (4853-4856); `public_selector == output_field` (4863-4866, 4925-4929).
- Outcome arm rows store `instantiated_label` and `captured_argument_identities` as strings (4887-4902, 5163-5227).

Evidence against the property in this slice: `call_signatures` identifies an invocation by symbols, statement index, call ordinal, arena handles and the full signature, and its comment rules out the name: "a nominal requirement symbol alone is never a fallback owner" (779-783). Float projection keys use symbols, bit patterns and expression handles (3152-3207). Forwarding compatibility compares structured propositions and interfaces, not strings (2165-2166, 5346).

## Surprises

- **No proof kernel anywhere.** In 5,348 lines of a module named `proof` there is no call to `proof_admission`, `ProofNode`, `verify_obligation` or a certificate check. The only `validate` calls are structural self-checks of a row just built (3795, 4283). The float module says of itself: "Binding records identity; it does not itself prove equality" (3113). Supports property 1.
- **Evidence definite assignment is a real dataflow analysis with an interprocedural part.** The path exploration (2441-2703), the terminal-call discharge (2999-3087) and the callee body summary (2917-2991) are general algorithms, not per-placement rules. A caller is excused from a guarantee because of what the callee's bodies syntactically return (3053-3059), which makes the caller's acceptance depend on the callee's implementation, not only its contract.
- **Dead distinction in operand indexing** (400-410). `operands_include_self` chooses between `operand_labels.get(parameter_index)` and a separate counter that starts at 0 and increases by one on every iteration. The counter always equals `parameter_index`, so both branches read the same operand. The flag has no effect; it looks like the remains of a case that once skipped the `self` parameter.
- **A possible hole for outcome evidence from a named implementation** (2559-2566, 2804-2813): described above; the inhabitation check is skipped for `ProducerConformance` sources, and the forwarding-time proposition check is skipped for guarded outputs (2166). I can see no check in this slice that covers that combination.
- **Inherited trait evidence terms are borrowed from the machine's own lanes** (1437-1451): the term is looked up under `ContractProofFactOwner::Machine` by kind and lane position, so it assumes the machine's own named bindings line up, position by position, with the trait signature's. Nothing here checks that alignment, and a miss is silent.
- **The same validated facts are re-checked for "drift"** (3575-3654, 4470-4534): twelve separate diagnostics say that something validation already produced "drifted before checked binding" or "is no longer" what it was. The stage re-derives and compares instead of trusting its input, inside one compile.
- **`"result"` is spelled three ways** for the same test: a raw string compare (3446), `is_reserved_result()` (3842) and `names_reserved_result` (3859).
- **Trait lookup by name then symbol check** (2387-2400): the first trait with the conformance's trait name is taken and then compared with the expected symbol. Two traits with one name would make this return `None` and report that the implementation "does not provide the exact ... evidence interface", which fails closed but with a misleading message.
- **Panics instead of diagnostics**: `.expect("typed machine-parameter contract must retain a valid requirement identity")` (1938); `unreachable!` at 2649, 3768, 3923, 4323, 5177; vector indexing with `unwrap_or(usize::MAX)` that would panic on overflow (4140, 4325-4326).
- **Pointer identity** is used to deduplicate type parameters (1911), an identity that is neither a symbol nor a handle.
- **Unused parameter** `_caller_state_symbol` in `outcome_call_substitutions` (5129).
- **Equality rows are normalized by id order** (`left = min`, `right = max`; 3930-3931, 4338-4339, 4529-4530), so `a == b` and `b == a` produce the same pair but are still pushed as separate rows; there is no dedup of equality rows.
- **Operator-use sites use `call_ordinal: 0`** (4056), so two operator uses in one statement share a use-site coordinate and are told apart only by `use_expression` (3178-3186 explains this).
- **No budget on the definite-assignment search.** The `seen` key includes the full assignment map and the full label set (2501-2513); the search is finite but can grow with the product of states, assignment combinations and label sets.
- **Against property 2 in part:** the call-signature code (661-875) is a deliberate move away from name identity, with a comment recording why.
