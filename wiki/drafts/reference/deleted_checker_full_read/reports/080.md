## What this code is for
This slice is mostly storage and vocabulary, not checking logic. `facts/lib.rs` defines `FactPlan`, the store the old checker filled while it checked: storage places, facts attached to places, fact contexts per program point, qualification evidence, and predicates (`facts/lib.rs:3-24`, `1138-1157`). It also holds the function that turns a source expression into a place (`append_place_from_expression`, `facts/lib.rs:1432-1504`) and the two functions that decide when two places are the same (`places_equal`, `places_match`, `facts/lib.rs:1823-1872`). `predicates.rs` defines the canonical boolean, scalar and integer-math expression trees that facts and contracts were stored as, plus a scan that says whether such a tree can trap. `a_b.rs` has two halves. The `admissibility` half (`a_b.rs:7-1048`) is a read-only reporting view: for a state, statement, call, exit or operator use it counts recorded rows and returns an "acceptance summary" over seven dimensions (borrow, proof, service reach, suspension, blocking, boundaries, termination). The `borrow` half (`a_b.rs:1050-2181`) defines the records the borrow checker wrote (loans, reborrow resources, restoration obligations, supplied-output resources) and a set of lookup and ownership-consistency queries over them. About 1,080 lines of `facts/lib.rs` are unit tests; `a_b.rs` ends with two index tests; `predicates.rs` has no tests.

## Mechanisms
- **Copy-on-write paged fact store.** `fact_plan_root_roster!` lists 16 arenas (`facts/lib.rs:31-40`); `fact_plan_root_impls!` generates `clone`, `clone_from`, `share_pages`, `begin_page(generation)`, `take_additional_pages`, `adopt_additional_pages` for all of them plus `contexts` (`facts/lib.rs:1199-1257`). A sealed "declaration baseline" is shared by per-flow workers; each worker writes new pages under its own generation, and the baseline adopts them in publication order (tests `facts/lib.rs:945-1124`). Two global atomic counters record shared versus copied forks (`facts/lib.rs:1259-1281`). Serves parallel per-flow checking.
- **Expression-to-place conversion.** Recursive walk over `Borrow`, `Name`, `Member`, `Indexed` (`facts/lib.rs:1432-1504`). No depth budget. Serves every fact, loan and write.
- **Place bucket index.** `fact_place_bucket_hash` hashes root and segments (`facts/lib.rs:1724-1743`); `PlaceBucketIndex` narrows candidates before full comparison in `first_owned_qualification_positions` (`facts/lib.rs:1750-1797`) and `group_fact_refs_by_place` (`facts/lib.rs:1799-1821`). A test pins 1,024 comparisons against 262,656 without buckets (`facts/lib.rs:337-339`).
- **Per-context assignment index.** `append_context` collects assignment-kind facts, sorts them by root group key and stores them beside the context (`facts/lib.rs:1536-1571`); `assignments_with_root` binary-searches the group and iterates (`facts/lib.rs:1573-1587`).
- **Domain implication search.** Depth-first search with a `Vec` visited list, no budget (`facts/lib.rs:1662-1692`). Serves `domain` refinement.
- **Trap scan.** Recursive scan of predicate trees; the integer-math form is iterative with a 4096-term budget that answers "trapping" when exhausted (`predicates.rs:198-226`, `479-543`, `712-745`).
- **Acceptance summary.** Seven per-dimension row counts folded into one verdict (`a_b.rs:794-935`); a trait gives every view the same accessors (`a_b.rs:942-976`).
- **Keyed state index.** `with_state_borrows` looks rows up by state symbol through `KeyedRows`, then filters by machine symbol, allocating a `Vec` only when a foreign machine shares the state symbol (`a_b.rs:2009-2037`).

## Identity by text
- **`places_match` falls back to comparing rendered labels.** If two places are not structurally equal and neither is an invocation referent or output, the function writes each place's canonical label into a thread-local `String` and returns `left_label == right_label` (`facts/lib.rs:1849-1871`). Two places with different roots or segments are the same place whenever their text is the same.
- **`place_label`** renders a place to a `String` (`facts/lib.rs:1874-1881`); it is the re-entrancy fallback inside `places_match` (`facts/lib.rs:1870`).
- **Member resolution by name.** When a member has no recorded symbol, the place builder calls `resolve_place_member_symbol(program, self, place, member_name.as_str())` (`facts/lib.rs:1467-1469`, `1482`). Test `expression_places_resolve_attached_data_members` pins that a member with an invalid symbol and the name "player" resolves to the field through the parameter's declared type (`facts/lib.rs:744-766`).
- **Instantiated contract expressions are stored as text only.** `InstantiatedExpression { label }` holds one `String` (`facts/lib.rs:1359-1365`). `boolean_fact_label` and `proposition_fact_label` return that string for an instantiated contract fact, and otherwise `expression_table.display_name(expression)` or `formula.identity_label()` (`facts/lib.rs:1367-1412`). The slice does not show who compares these labels.
- **`u64_integer_literal` builds a literal by formatting the number to decimal text and re-parsing it** (`predicates.rs:410-415`).
- `AcceptanceDimension::as_str` gives the seven dimension names ("borrow", "proof", "service_reach", "suspension", "blocking", "boundaries", "termination") (`a_b.rs:781-789`); these are labels, not identity.
- Evidence against property 2: every borrow record identifies storage by `PlaceRoot`, segment handles and `SymbolHandle`s, never by string (`a_b.rs:1060-1694`), and every query in the borrow half compares handles.

## Accepts or skips without proof
- **Every acceptance view answers Accepted.** All five `summary()` implementations call `AcceptanceSummary::accepted(...)` (`a_b.rs:38`, `203`, `306`, `438`, `626`). `AcceptanceCheck::accepted` sets verdict Accepted and provenance `AcceptedByEvidence` for any count, including zero (`a_b.rs:707-718`). `AcceptanceCheck::rejected` (`a_b.rs:730-745`) has no caller in this slice. So `is_accepted()` on a state, statement, call, exit or operator view is true whenever the view exists. I cannot tell from this slice whether another file builds a rejected summary.
- **Termination counts as satisfied with no evidence.** Zero `MachineDecrease` values gives NotApplicable, which `is_satisfied` accepts (`a_b.rs:873-875`, `747-752`). The count is per machine, so every state of a machine reports the same termination evidence (`a_b.rs:172-190`, `453`).
- **Unresolved members still produce a place.** A member that resolves by neither symbol nor name is pushed as `Field { symbol: SymbolHandle::invalid() }` (`facts/lib.rs:1470-1471`, `1483-1486`). Two different unresolved members of the same root then have structurally equal places. Test `expression_places_resolve_exact_local_and_collection_element_types` pins this for a stale root generation and for a local parented under another state (`facts/lib.rs:930-938`). Cannot tell whether a later check refuses such places.
- **Invalid expression gives an `Unknown`-rooted place** rather than an error (`facts/lib.rs:1437-1442`); a name with no valid symbol becomes an expression-rooted place (`facts/lib.rs:1454-1456`); any unlisted expression form becomes an expression-rooted place (`facts/lib.rs:1502`). ## Surprises
1. **The acceptance views cannot say no.** The module header calls them "acceptance verdicts" (`a_b.rs:1-5`), and the types carry `Rejected`, `DiagnosticPending` and `RejectedByDiagnostic` (`a_b.rs:681-695`), but every `summary()` in the file builds its result with `AcceptanceSummary::accepted` (`a_b.rs:38`, `203`, `306`, `438`, `626`). The "evidence" is a count of rows the checker wrote. A view with zero rows in the borrow and proof dimensions still reports Accepted with provenance `AcceptedByEvidence` (`a_b.rs:707-718`). This is direct evidence for property 1: the published verdict is the checker's own bookkeeping, and here it is not even a decision.
2. **Place matching by rendered text sits beside exact structural matching.** `places_equal` is exact (`facts/lib.rs:1823-1829`). `places_match` adds a label-equality fallback and explicitly excludes invocation referent and output roots from it (`facts/lib.rs:1840-1848`). The exclusion shows the authors knew the textual fallback was unsafe for some roots.
3. **Unresolved fields collapse to one place.** `x.a` and `x.b`, both unresolved, become root `x` plus `Field{invalid}` and are structurally equal (`facts/lib.rs:1470-1471`). A test asserts the invalid segment as the expected result for malformed input (`facts/lib.rs:933-937`).
4. **"Certificates" in the trap scan are a boolean.** `contains_trapping_operation_with_certificates(use_certificates)` reads `trap_free: bool` from the node (`predicates.rs:487-502`). No certificate object, obligation or kernel call is involved.
5. **A borrow expression and its referent share one place** (`facts/lib.rs:1445-1447`). Facts recorded against `&x` and against `x` land on structurally equal places.
