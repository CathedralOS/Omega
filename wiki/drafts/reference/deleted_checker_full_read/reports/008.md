## What this code is for
This file evaluates constant expressions at build time: const-generic arguments of data types and machines, fixed-array lengths ("extents"), range endpoints, and scalar constant initializers (header, cge.rs:1-9). The top-level `evaluate` (cge.rs:5757-6001) takes the syntax trees, wraps each pending const argument in a synthetic one-state machine called a "probe" (cge.rs:6078-6182), has the rest of the front end resolve and type that probe, evaluates the probe's single returned expression, and writes the result back into the syntax tree as a generated type name whose text is the number (cge.rs:5978-5998). The evaluator proper (`mod value`, cge.rs:2548-5742) is an explicit-stack interpreter over typed expression nodes for Booleans, fixed-width integers under exact/wrapping/saturating policy, f32/f64, and "anonymous" (not yet typed, exact rational) numbers, with lazy `match` and short-circuit `&&`/`||`. A sub-module (`rational_bounds`, cge.rs:2792-3444) proves, for anonymous expressions containing `match`, that every arm is an integer, fits the carrier, and that divisors are never zero, using intervals plus an arithmetic-progression lattice plus a bounded exact point set. The largest part by line count (`mod call_custody`, cge.rs:18-2165) is not evaluation: it walks everything a constant's initializer can reach (calls, callee machine bodies, types, contracts, other constants) and checks that what the typed program calls is the same declaration the author's source selected; the code calls this record "custody". `mod lexical_selection` (cge.rs:2167-2547) does the same job one stage earlier, on syntax trees, to make sure names in a const argument select constants from the scope where they were written. The file contains no tests and makes no call into the proof kernel.

## Mechanisms
- **Probe evaluation** (cge.rs:5757-6001, 6078-6182, 6613-6727). For each pending const argument the code appends a private machine named `@const-argument-N` (or `@array-extent-G-I`) whose one state returns the expression, runs normalization, deferred resolution and call-free typing over the cloned syntax, finds the probe again, evaluates it, and replaces the argument with a generated name. It serves const-generic arguments and array lengths. Limits: scalar destinations only; arguments with calls are skipped here.
- **Closure collection with a worklist** (`collect_in_context`, cge.rs:1062-1119). Two stacks (expressions with a context, machines) and two visited lists; each expression is visited once per (expression, machine, state, lexical owner, initializer flag). It reaches callee bodies, their contracts, owned-data initializers, statements, transitions, static machine arguments, other constants' initializers, and types (through `type_dependencies`, cge.rs:476-554, which itself has a worklist over data declarations). No budget; visited lists are searched linearly.
- **Mapping a specialized call target back to its template** (`authored_target`, cge.rs:1135-1216). Follows `executable_application_template` until none, uses a single captured machine application when present, otherwise maps a state to the template state at the same position; a visited list refuses cycles.
- **Trait inheritance search** (`trait_supplies_requirement`, cge.rs:203-232). Depth-first over `trait_requirements` with a visited list.
- **Explicit-stack evaluator** (`evaluate_expression`, cge.rs:4343-4842). A `Step` enum drives a value stack; `match` tests patterns in order and evaluates only the selected arm; `&&`/`||` skip the right operand; the list `selected_arms` records which arm each match took so that later exact evaluation of anonymous sub-expressions follows the same arms. A type pass with the same shape (`validate_shapes`, cge.rs:4850-5203) runs first and produces a plan per match and a carrier per call.
- **Rational bounds lattice** (cge.rs:2842-3443). For an anonymous expression made of literals, `+ - * /` and `match`, it computes up to three cells (negative, positive, containing zero), each an exact rational interval with an optional arithmetic progression `offset + k*stride`, plus an optional exact set of possible values. A join of match arms unions intervals and takes the gcd of strides and offset differences (cge.rs:3289-3297). An interval that straddles zero is split at the two progression points next to zero when the progression misses zero (cge.rs:3012-3040, 3227-3246), which is how it proves a divisor nonzero. Division enumerates the divisor's possible values when few. Budgets: 256 exact points (cge.rs:3205), 4096 point products (cge.rs:3206), 256 enumerated lattice points (cge.rs:3329); going over a budget drops the exact set and falls back to interval and lattice, which can then cause a refusal. It serves integer landing and division inside anonymous matches. It joins all arms and never looks at the match subject or patterns (cge.rs:2860-2869).
- **Landing summaries** (cge.rs:3762-3949). Enumerates every combination of arm choices through nested anonymous matches, with the value and the first non-integer intermediate result, so each combination can be landed separately to produce "fractional" warnings; bounded at 4096 distinct summaries, above which the program is refused.
- **Policy lookup** (`reference_policy`, cge.rs:5557-5595). Walks nested constrained types collecting the single arithmetic-domain constraint; cycle-checked.

## Identity by text
- Conformance row matched by requirement name text when the handle does not match: `row.requirement_name.as_str() == call.target.as_str()` (cge.rs:138).
- A refusal reason is recognised by comparing it to the literal "selected call has no exact applied public signature" to decide whether to add detail (cge.rs:443).
- For a constant selection, the code takes the last `::` segment of the symbol's name and uses its length in span arithmetic to decide which source span is the reference (cge.rs:1818-1840).
- A machine const argument written as a named type is turned into a name expression by splitting its text on `::` (cge.rs:5795-5816).
- Routing by destination type spelling: `"i8" | "i16" | ... | "bool"` (cge.rs:6003-6010).
- Probe machines are named `@const-argument-{ordinal}` and `@array-extent-{generation}-{index}` (cge.rs:6087, 6102-6106) and found again by name string plus span (cge.rs:6194-6197).
- The evaluated value is written back as a type reference named by the decimal digits or Boolean atom: `TypeReferenceNode::Named(Identifier::generated(replacement))` (cge.rs:5978-5998).
- Final type agreement is a string comparison of type names (cge.rs:6713).
- Canonical values carry their type as a name string and their value as text: `CanonicalConstIdentity::integer(carrier.name(), value)` with `value.to_string()` (cge.rs:4316-4322, 5252); floats as `float:f32:{bits:08x}` / `float:f64:{bits:016x}` (cge.rs:4142, 4146, 4163, 4167); a range endpoint is rebuilt from a decimal string (cge.rs:5709-5714).
- Identity by source position rather than handle is the main key throughout: calls are `(SourceSpan, SourceSpan)` pairs and origins are span records (cge.rs:676-680); "same authored declaration" is same kind and same span (cge.rs:192-201); resolved calls and constants are found by scanning every resolved expression for an equal span (cge.rs:2380-2389, 2454-2474); probe owners by span (cge.rs:6511, 6592, 6626); the const item for an origin by `definition.name.source_span() == origin.declaration` (cge.rs:2255-2262).
- Identity by position: a specialized state is mapped to the template state with the same index (cge.rs:1210-1214).
- Counter-evidence: inside the typed program most comparisons are on `SymbolHandle` and `ExpressionHandle`, and builtin types are recognised by `builtin_type_atom`, not by name (cge.rs:2770-2775, 6021).

## Surprises
- **No proof kernel anywhere.** The words "proof" and "evidence" appear only in diagnostics ("nonzero divisor proof", "all-arm integral result proof", "checked partial-conversion evidence"). The "proof" is this file's own interval and lattice arithmetic (cge.rs:2801-2840). Acceptance of a constant is the evaluator's own result plus equality checks between lists of source spans. This supports property 1.
- **More than a third of the file is bookkeeping, not evaluation.** `call_custody` (cge.rs:18-2165) and `lexical_selection` (cge.rs:2167-2547) exist because the expression is cloned into a probe and resolved and typed again; the code then has to check that the second resolution selected the same declarations as the first. Dozens of "lost its ...", "changed its ...", "stale ..." errors are checks on the compiler's own intermediate data, not on the user's program.
- **Values travel as text.** The result of evaluating a const argument is stored in the syntax tree as a type name whose spelling is the decimal number (cge.rs:5995-5998), and a named-type argument is re-read as an expression by splitting its text on `::` (cge.rs:5799).
- **Routing by spelling.** Whether a const argument is evaluated here depends on the destination type being spelled `i8`...`bool` before name resolution (cge.rs:6003-6010). A destination reached by another spelling takes the other route (cge.rs:5817-5820).
- **A real abstract interpretation.** The rational-bounds code tracks arithmetic progressions and splits intervals around zero using lattice neighbours (cge.rs:3012-3040, 3227-3246). It is a general mechanism, stronger than plain intervals, serving one narrow case: untyped numeric `match` arms inside const arithmetic.
- **All arms are judged, not the selected arm.** Landing and nonzero-divisor checks require every arm of an anonymous `match` to qualify even when the subject is a known constant (cge.rs:2860-2869, 3705-3711), while evaluation itself is lazy (cge.rs:4564-4621). A program can be refused for an arm that evaluation would never take.
- **"nonnegative" is claimed but not checked here.** The fixed-array length message says "must evaluate to a nonnegative integer count" (cge.rs:6706), but `evaluate_probe_internal` has no sign test; a signed carrier with a negative value returns `Ok` from this function. Cannot tell whether a caller checks.
- **Narrowing casts are refused before evaluation could admit them.** The type pass allows only same-or-wider integer casts (cge.rs:5001-5003); the value pass has code for value-fitting casts (`exact_cast_value_to`, cge.rs:4679-4685) that the type pass makes unreachable for narrowing.
- **Mixed-carrier integer comparison is allowed.** Comparisons are exempt from the same-carrier rule and go through `compare_with` (cge.rs:5111-5120, 5473-5492), so this file's own carrier rule lets `i8` be compared with `u64` in a constant. Cannot tell whether the builtin-meaning test asked of `validation` (cge.rs:4942) refuses it first.
- **Shift policy gaps found only at run of the evaluator.** Left shift under the saturating policy has no case and fails with "unsupported builtin integer constant operation policy" (cge.rs:5525-5537); right shift under saturating silently uses the exact operation (cge.rs:5531-5533). The type pass does not refuse either.
- **Closed-context operator rule is global.** A closed constant operator is refused if any machine specialization anywhere in the program selects a trait operator for the same operand types (cge.rs:2706-2718). Adding an unrelated specialization elsewhere can change whether a constant compiles.
- **Two private-constant rules that differ.** The initializer route requires `public && context.initializer && !owns` (cge.rs:1613-1617); the index route requires `public && !owns` (cge.rs:6310-6311).
- **Literals are read through 64-bit accessors.** `landed_literal` uses `value_i64` / `value_u64` (cge.rs:5327-5338) although values are held as 128-bit; the routed carriers stop at 64 bits, so this is consistent but fixed.
- **Summary de-duplication drops arm selections.** `push_landing_summary` treats two paths with the same value and fractional step as one and keeps the first path's arm selections (cge.rs:3917-3935); binary joins concatenate left and right selections without checking that a shared match took the same arm on both sides (cge.rs:3882-3883). Cannot tell whether expression handles are ever shared so that this matters.
- **Oddities.** The macro `inner!` only forwards eight arguments to `collect_internal` with `=>` separators (cge.rs:862-866). `expression_custody` takes a `std::collections::HashSet` of admitted calls, and the only call in this file passes an empty one (cge.rs:6240, 6682). `Custody.dependency_values` is filled only when no syntax is supplied (cge.rs:1643-1665). Visited sets are `Vec`s searched linearly everywhere (for example cge.rs:1094, 1100, 732-736).
