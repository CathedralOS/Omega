## What this code is for

This file decides which facts a state of a machine may assume about its parameters and reachable storage when control arrives there. It is part of the old checker's flow builder (`crate::flow`), which ran a fixed point over the states of a group of machines. Each arrival at a state (a named transition, a call of the machine, a "callable input" taken from a `requires` signature, or a caller of a compiler-extracted or private nested machine) delivers one `StateValues` row (fsv:2774-2802). The function `join` (fsv:2851-2966) merges that row into the stored row for the destination state and marks the state dirty when something changed. `append_entry_context` (fsv:3507-3596) then writes the settled row into the `FactPlan` as facts at the program point `ProgramPoint::State`, where later checks read them.

A row carries seven kinds of information: an exact scalar per parameter, an integer interval per parameter, per-field facts (a literal, byte-sequence predicates, an integer interval), "qualifications" (domain memberships and float predicates with a provenance record), boolean predicates over parameters, selected `case` variants, and "entry paths". Each kind has its own capture, join, height and publish code.

The file emits no diagnostic and refuses no program. Its effect on acceptance is indirect: a fact it publishes can let a later check pass, and a fact it drops can make a later check fail. It contains no call to the proof kernel.

The last 220 lines (fsv:3598-3822) are not about facts: they record each delivery so that a part of a machine group can be converged alone and replayed into the whole group later, with a guard that detects when the replay would differ from a serial run.

## Mechanisms

- **Per-state join for the flow fixed point** (fsv:2851-2966). `join` merges one arrival into the stored row, sets a `changed` flag and pushes the state onto `build.dirty_state_value_inputs`. It also adds to `build.new_state_field_input_height`, a counter the builder uses outside this file; the `height` functions (fsv:741-750, 1113-1131, 2259-2276) compute how many times a row can still change. Serves every state-parameter and field fact.
- **Interval widening with thresholds, parameters** (fsv:702-811). Union of ranges; a `growth` counter; from the 4th growth (`WIDENING_DELAY`, fsv:723) the moved endpoint jumps to the nearest program literal inside the primitive type's range, or to the type's range. A missing bound is absorbing. Serves integer state parameters in loops.
- **Per-edge delivery store and recomputed join, fields** (fsv:1014-1108, 1254-1435). Each field row keeps the latest delivery of every predecessor edge, keyed by `BoundsSource` (transition, invocation or callable input, fsv:975-989). `rejoin` recomputes literal, predicates and interval from all deliveries, so the stored value can become stronger again when an edge later delivers more. Widening after 4 growths (`BOUNDS_WIDENING_DELAY`, fsv:1110); after 8 shrinks (`BOUNDS_NARROWING_LIMIT`, fsv:1111) the stored endpoints are held.
- **Threshold collection** (fsv:1202-1235). Scans every expression once for integer literals that are operands of `<`, `<=`, `>`, `>=`, `==`, `!=`; sorts and dedups. The builder memoizes it (`integer_literal_thresholds_at`, fsv:2870).
- **Fact capture by place prefix** (fsv:1570-1770, 2319-2376, 3372-3425). Walk the live fact contexts, turn each fact's place into a `CanonicalPlace`, keep those whose root and leading segments equal the argument's place, strip the prefix, re-root at the destination parameter symbol.
- **Predicate rebasing and folding** (fsv:836-940). Rebinds each operand of a retained boolean predicate from the caller's place to the parameter's place; substitutes known values for operands that do not travel.
- **Qualification lattice** (fsv:2010-2096, 2209-2251). Two predicate kinds (domain, float) with `implies` and `common_consequence`; a provenance record (`QualificationEvidence`) joined beside the predicate. A 64-bit mix of root and segment keys groups claims by place before exact comparison (fsv:2126-2190).
- **Record and replay of deliveries** (fsv:3598-3773). While a part of a group converges alone, `delivers_here` records each delivery (a clone of the row) and applies it only if the destination's machine belongs to the part. `replay_delivery` repeats a recorded delivery through `join`. `ReplayGuard` marks the replay broken when a machine outside a part, or a different part, or no writer, delivers into a part's row, or when a destination does not resolve; the comment says the group must then be built serially (fsv:3714-3720).

## Identity by text

- The attached data record of a machine is found by name string: `program.data_definition_by_name_str(attached.as_str())` (fsv:1147-1148). This is the only string lookup in the file.
- No string literal comparison, rendered label or joined path string appears. Places are `CanonicalPlace` (a root plus a segment list) compared structurally; declarations are `SymbolHandle`.

Identity by source-tree handle rather than by value, which is the same weakness in another form:

- A field literal is an `ExpressionHandle`; two arrivals agree on a literal only if they deliver the same handle (fsv:1326-1337, 1546-1548). Two assignments of the same constant written at two source positions do not agree.
- A caller is authenticated by comparing lists of argument expression handles (fsv:557-564, 567-570), and an operand matches an argument by expression handle, state symbol and statement index (fsv:3296-3306).
- A predecessor edge is keyed by source state and transition-target handle, or state, statement index and call ordinal (fsv:975-989).
- A compiler-extracted region is "identified by [its] retained lexical origin" (fsv:516-518, 553-565).
- A machine calling itself is named by its machine symbol while its declarer's call resolves to the entry state, and both are accepted as the same target (fsv:546-552).
- `delivers_here` decides that a destination "resolves" by comparing addresses with `std::ptr::eq` (fsv:3658-3662).

## Accepts or skips without proof

Most failure paths here return `Unknown`, an empty list or `continue`, which removes facts. The places that keep or create a fact without establishing it in this file:

- **`requires` clauses become entry facts** (fsv:262-332): predicates, constants, intervals, domain memberships and cases. This is the callee assuming its precondition. The caller's obligation is a `StaticMachineContractObligation` handled outside this slice; cannot tell from here that every caller is checked.
- **Declared parameter types become domain qualifications** with `propagated_evidence(entry)` (fsv:243-261, 2103-2119). Trusts the declared type. Cannot tell where the membership is established.
- **First arrival stored as delivered** (fsv:2938-2961). Until other predecessors arrive, the state holds one predecessor's facts. The comment at fsv:713-716 says final materialization and "the builder's fail-closed fallback" are responsible for publishing only settled facts; both are outside this slice.
- **A transition into the entry state delivers nothing** (fsv:3051-3053). For a closed private machine, whose entry row is published from caller facts (fsv:3516), this function does not weaken the entry row with the back edge's values. `record_invocation` shows named transitions also appear as call facts (fsv:3198-3211), so `lexical_regions::record` may see the same edge; cannot tell from this slice whether it does.
- **Field literal: last fact wins** (fsv:1713-1715). Intervals for one field are ranked by program point (fsv:1716-1731); the literal is overwritten by whichever fact the loop meets last, and byte predicates from all facts at that place are unioned (fsv:1733-1738). This is correct only if a context never holds two facts for one place from different versions; cannot tell.
- **Byte predicates from interval endpoints** (fsv:1661-1674). The code tests `holds_for(&[minimum, maximum])`, two values, to conclude the predicate for every value in the range. This is valid only if every subslice-preserving predicate is true on a whole range whenever it is true on both ends. The variant names seen elsewhere are `ValidUtf8`, `NoNul`, `AsciiOnly`, `NonEmpty`; the definition of `is_subslice_preserving` is not in the deleted tree, so I could not confirm which qualify.
- **Field facts are published with `QualificationEvidence::default()` and origin `StatementTransfer`** (fsv:1966-1972); scalars, intervals and cases with `append_transfer_at_point` (fsv:3550-3554, 3565-3569, 3585-3592). No evidence record accompanies them.
- **Isolated qualifications skip the binding-stability test** (fsv:2575, comment 2199-2203). The isolation verdict comes from `proof_value_is_caller_isolated` (fsv:2332).
- **Field interval published when the type range is unknown** (fsv:1943-1944, `is_none_or`).
- **`_ => (0, 0)`** in `bound_point_rank` (fsv:1591): an interval fact at any other kind of program point gets the lowest rank and can be replaced or, at rank equality with another such fact, unioned.
- **`ProofFact::Proposition(_) => {}`** (fsv:329) and the `continue` arms at fsv:295-307 drop a `requires` clause the code cannot lower. This weakens the callee's assumptions, so it cannot accept more.
- **Unreplayable sentinel** (fsv:3672-3680): a delivery recorded with no open visit pushes a visit with an invalid state and `pass: usize::MAX`; whether the consumer treats that as "do not replay" is outside this slice.

Property 1, direct evidence: the file has no call into a proof kernel and no certificate. Its decisions are handle, place and range comparisons. It does keep provenance: `QualificationEvidence` is joined with `common_consequence`, `available_alternative` and `at_invocation_input` (fsv:2223-2232, 2440-2442), and facts with origin `CallRequires` are refused as evidence (fsv:2029-2031). That is bookkeeping about where a claim came from, checked by this code's own comparisons.

## Surprises

- **The file enforces nothing and reports nothing.** 3,822 lines exist to compute what later checks may assume at state entry. Every later verdict that depends on a loop counter's range or a field's class at a state depends on this join being right, and the join has no test in the file.
- **The field join is deliberately not monotone** (fsv:1087-1093). A row can strengthen when an edge re-delivers. Termination then rests on two counters and a height budget rather than on the lattice; the authors say so ("scheduling scratch", fsv:713-714).
- **Two widening implementations disagree.** The parameter version only picks thresholds inside the type range and turns an out-of-range join into unknown (fsv:781-805). The field version picks any literal beyond the endpoint without checking the type range (fsv:1399-1411), so a field interval can end at a literal outside its type. The field version has a narrowing limit; the parameter version has none. The parameter version can never recover from a missing bound (fsv:759-761); the field version treats a missing bound as the type range and can retighten.
- **Parameter intervals have no per-edge memory.** `ParameterBounds::join` unions into one stored range (fsv:766-769), so the wedge the authors fixed for fields (fsv:1087-1093) still applies to parameters.
- **Inconsistent treatment of a predicate that says nothing about a place.** For a parameter, `?` inside the loop discards the whole bound if any one `requires` predicate gives no interval at that place (fsv:356-358). For a field, `filter_map` skips such predicates (fsv:393-396). Unless `integer_interval_at_place` returns the full type range for an unrelated predicate, two `requires` clauses about two different parameters would leave both parameters without an entry interval.
- **Same-point interval facts union, guard-derived intervals intersect.** Two `AssignedIntegerBounds` facts of equal rank for one field are unioned as if alternatives (fsv:1721-1726); the guard path intersects with the result (fsv:1894-1901). The code does not say why equal-rank facts are alternatives and not both true.
- **Misplaced comment and attribute** (fsv:1437-1449). The comment about a named edge's arguments and the `#[allow(clippy::too_many_arguments)]` sit above `point_range_point`, which has one argument; they describe `capture` at fsv:1467, which has eight arguments and no attribute of its own.
- **Domains have no order.** `common_consequence` for two domain memberships returns a result only when both name the same domain (fsv:2071 with 2047-2060); a membership never weakens to a wider domain, it only disappears (confirmed by the comment at fsv:2253).
- **Receiver calls are never authenticated** (fsv:580), although the field code treats `&mut self` as an ordinary argument (fsv:1075-1081).
- **A capability I did not expect:** split convergence. The flow builder can converge part of a machine group alone, record every delivery with a full clone of the row (fsv:2859-2863), and replay it into the group, with a guard and a serial fallback (fsv:3598-3773). This is a performance mechanism inside the checker whose correctness condition ("the solo run ... saw no other writer", fsv:3717) is itself checked only by `ReplayGuard`.
- **Transitions have a second target.** `capture_argument` distinguishes `transition.target` from `transition.continuation` and gives each its own scalar role (fsv:96-102).
- **Performance history is recorded in comments**: "hundreds of thousands of sweeps" (fsv:707), "183 passes" (fsv:1197). The widening constants 4 and 8 have no stated derivation.
- **Address comparison for identity** (`std::ptr::eq`, fsv:3660-3661) in a file that otherwise uses handles.
