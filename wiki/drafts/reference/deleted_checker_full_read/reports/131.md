## What this code is for
`traits.rs` is the part of the old source checker that judges traits, "named implementations" (conformances) and the places that apply them (header at traits.rs:1-5). It checks that a machine really satisfies the trait requirement it claims to: same parameters, return type, lifetimes, borrow contracts, contracts (through `contract_entailment`), effects ceiling (services reached, `suspends`, `blocks`, invoked machines, termination promise). It checks every application of a trait or conformance (argument counts, kinds, bounds, proposition families, implementation slots and forwarded evidence binders). It "closes" a conformance application into one canonical record with a hash commitment (traits.rs:4429-5202). It collects and describes `dyn Trait` selections and dynamic call slots, and rewrites qualified calls to their exact requirement symbol (traits.rs:5503-6336). It validates top-level boundary requirements (a machine realizing a generic top-level requirement), external leaf native shapes and `via` producers. It also checks trait refinement fit, trait parent lists and cycles, duplicate operator bindings, and the consistency of "retained" implementation demands. Almost every check pushes a `Diagnostic::error` into a vector; there is no proof-kernel call in this file (grep of `proof_admission|ProofNode|verify_obligation|certificate` returns 0 hits).

## Mechanisms
- **Trait-type binding matcher** (traits.rs:2734-3200). `type_references_match_for_trait_bindings` compares an actual type to a required type while growing a list of `TraitTypeBinding { parameter_symbol, parameter_name, target, scope_start }`. A required trait type parameter not yet bound is bound on first sight to the actual type (2780-2786), so it is a one-way unification (no occurs check, no backtracking). Structural cases: references (same access), constrained types, fixed arrays, slices, generic/dyn trait with same base symbol, named-vs-generic via `generic_instance`, const expressions via normalized index identity. `scope_start` records which prefix of the binding list is visible to an argument (nested application scopes). Anything else falls to `type_references_match`. Limits: none stated; recursion depth unbounded.
- **Region correspondence** (traits.rs:7109-7286, 1959-2055). `provider_region_correspondence_in_scope` solves for which of the provider conformance's lifetime parameters map to which receiving-application regions: `constrain_slot` assigns each provider slot once (`Option<LifetimeParameterIdentity>`), `applications` is a vector of candidate assignments that is filtered (`retain_mut`) as constraints arrive; result requires exactly one distinct complete assignment (7256-7258). This serves lifetime-parametrized conformances. No budget.
- **Closed conformance application identity** (traits.rs:4429-5202). Builds a canonical description (strings for lifetimes, types, constants, machine arguments, trait arguments, row requirement signatures as canonical bytes) and hashes it (`source_identity_commitments`) into a 64-bit report fingerprint and a digest commitment. Serves named implementations / generic conformances.
- **Provider application derivation** (traits.rs:6907-7069). Enumerates checked-body machines and implementations, cross-matches closed requirement applications with providers, sorts by symbol arena index/generation, deduplicates. Memoized per frozen program (6756-6759). Serves selecting which implementation supplies a generic top-level requirement.
- **Dynamic call target resolution** (traits.rs:5963-6336). Two-phase: collect `(site, symbol)` updates over all machines/statements/expression trees using a hand-written recursive walker (6089-6208), refuse all if any diagnostic, then apply the updates in place (6067-6084). It consults the lexical conformance scope to prefer the unique row of the selecting implementation (6227-6272).
- **Reachability over trait parents** (traits.rs:6880-6905): worklist DFS over `trait_requirements` plus `refines`; returns `None` if any trait symbol is missing.
- **Trait requirement cycle detection** (traits.rs:7747-7798): DFS with a path vector and a "reported" vector so each cycle is reported once.
- **Finite-family expansion** (traits.rs:5374-5419, 6359-6405): requirement-local generics are allowed only when `finite_signature_family` enumerates a finite tuple set; one dynamic row/slot per tuple.
- **Private native carrier search** (traits.rs:381-441): recursive type walk with a `visiting` symbol list to cut cycles through records.

## Surprises
- No call to the proof kernel appears in this file (0 hits for `proof_admission|ProofNode|verify_obligation|certificate`). Every verdict is either a count/equality comparison in this file or a boolean/Option from another module (`contract_entailment`, `type_regions`, `borrow_contracts`). The only "proof"-like operations are `CallableContractRefinement::...proves(...)` (7541-7546) and `normalize_nominal_proposition_application` equality (1748-1757). Property 1 is therefore supported for this slice, with the caveat that the called modules are not visible.
- Strings used as identities that are then hashed into a commitment: the `ConformanceIdentityDescription` encoding takes rendered strings (type texts, `Owner::State` names, `display_path`), so the "commitment" at 5192-5200 binds to names, not symbols. A machine argument that fails to resolve becomes the literal text "<unresolved-machine>" (5150) and is committed without error.
- `normalized_type_identity` equality is used as a stand-in for "same type" in many places (e.g. 57-58, 3088-3097, 5641-5643, 5545-5546), together with symbol equality; text identity (`normalized_type_identity_text`) is used for closed operator tuples and conformance identities. Two identity systems coexist in the file.
- `traits.rs:1788-1790` and `3711-3714` accept a match by NAME when the symbol does not match, which means a same-named different parameter could be taken for the right one; 3711-3714 is `(valid && symbol equals) || name equals`, so a valid but different symbol still passes if the names are equal.
- `trait_definition_by_symbol` has a name-based fallback in `close_selected_conformance` (4558-4565) but not elsewhere; the local wrapper at 8327-8336 only adds an `is_valid()` check.
- `validate_conformance_bounds` and the `validate_trait_implementation_arguments` loop (7876-7934) both validate bounds of the same machine/trait through different paths (the latter via `validate_implementation_application`), so a bad bound can produce two messages; `refinement_fit_diagnostics` takes `dedup_by` on rendered text (7606) to hide duplicates within its own list.
- `authored_conformance_machine` recovers the template machine by searching for another machine whose `type_parameters` equal the specialization's `template_parameters` and whose conformance list `==` the instance's (2165-2173). That is structural equality of whole conformance lists used as identity.
- `closed_requirement::resolve` returns the same single message for ten different failure causes (548-551), so a user cannot tell which uniqueness property failed.
- `validate_machine_top_level_requirement_conformance` for a machine with `via`/external binding skips contract refinement completely (1120): contracts of externally bound or `via`-realized providers are not compared with the requirement here.
- `collect_dynamic_expression_call_updates` (6089-6208) and `collect_call_demands_in` (5787-5808) use two different traversal mechanisms for the same expression forest; the hand-written one has a closing arm listing `TypeExpression | SavedSubject | literal pattern` as leaves, so a new `ExpressionNode` variant would be a compile error there but a silent skip nowhere (exhaustive match).
- `#[allow(clippy::too_many_arguments)]` on a struct at 5067 is misplaced (dead attribute).
- `type_references_match_for_trait_bindings` mutates the bindings list during a comparison (2780-2786): a failed comparison of an enclosing type can leave bindings added by an earlier successful sub-comparison. Whether callers rely on this I cannot tell from this slice.
- Reference lifetimes are explicitly ignored in the structural match (`lifetime: _`, 2809, 2813) and checked in a separate pass (1060-1095) which is skipped when lifetime-parameter counts differ (1060): the count mismatch is reported at 916-922 but does not return, and the lifetime pass is then silently omitted.
