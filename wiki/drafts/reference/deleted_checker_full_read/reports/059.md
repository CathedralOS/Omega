## What this code is for

This slice is the part of the old checker's "flow" builder that decides which facts are known before and after a call, on each arm of a guarded transition, and at each exit of a state. It issues no diagnostics at all: it only publishes, keeps or drops facts (`Fact` rows in a `FactPlan`) and constraint references that later checks read. `flow_calls.rs` builds one `FlowCallFact` per call: entry facts, `requires` facts, the set of places the call may write, the facts that survive those writes, and the `ensures` facts afterwards (flow_calls.rs:39-262). `flow_call_phases.rs` holds the phases that function runs: it works out which of the caller's storage each argument actually denoted when it was evaluated (`ArgumentSources`), which facts the call's writes retire, which callee guarantees may be stated about caller storage, and which domain-membership facts are re-published on `&mut` referents after the call. `flow_exits.rs` turns a transition guard or match arm into facts (Boolean value, integer bounds, case tag, byte class, float predicate, a variant's `requires`), and records one `FlowExitFact` per contract exit. `flow_context.rs` is the mutable state of one flow build: output arenas, memo tables that survive between fixpoint sweeps, and helper lookups. A fact produced here carries either `QualificationEvidence::default()` (guards) or `propagated_evidence(target)` (calls); nothing here calls a proof kernel. Places are mostly structural (`CanonicalPlace { root, segments }`), with a few string-based exceptions listed below.

## Mechanisms

- **Captured argument sources** (flow_call_phases.rs:376-516, 579-645). For each parameter, `retain_capture` copies the evaluated operand, its type, its referent places and the writes that happened between its evaluation and the call (`writes_after_capture`, 400-438, computed as the suffix of the invocation's write list after checking the capture's list is a prefix). It recurses through constructed children with an `active` stack that refuses cycles (486). Any failure returns `None` for the whole call, which later code treats as "no evidence". Serves by-value versus by-reference argument semantics.
- **Enclosure intersection** (flow_call_phases.rs:246-302). Intersects two segment paths in one storage root: runtime index with fixed index gives the fixed index, fixed index inside fixed range gives the index, two ranges give their overlap, anything else gives `None`. No budget. Serves narrowing a callee write to the captured array element or window.
- **Conditional occurrence identity** (flow_call_phases.rs:1640-1686). A concrete `FixedIndex` matches a captured runtime `Index` (not a range). The reasoning in the comment (1636-1638): if the writer wrote that element the guarantee covers it, otherwise the element is untouched. This is a case split done without a solver.
- **Bucket join of guarantees** (flow_call_phases.rs:1563-1633). Returned guarantees with fully static places go in a `PlaceBucketIndex` keyed by `place_bucket_hash`; candidates are re-compared by full place equality. Rows with runtime selectors are scanned linearly.
- **Grouping by place identity** (flow_call_phases.rs:1501-1531). Sorts `(place, fact)` rows by `compare_identity`, groups equal places into one context, then restores first-appearance order.
- **Guard interval analysis** (flow_exits.rs:229-426). Splits `&&`, peels `== true`, turns each comparison with a literal endpoint into a `BigIntInterval`, intersects per place, fills missing ends from the carrier range, meets with live bounds, and drops an empty result. Place-versus-place comparisons are not handled here (comment 222-224).
- **Memo tables that outlive a sweep** (flow_context.rs:232-292, 999-1039). Call sites, callee parameters and return types, result and parameter identity rows, referent type paths, lowered guard expressions (sorted `Vec` with binary search, 583-629) and stored-reference effects (linear scan, 334-338) are computed once. `discard_output` clears only output arenas between fixpoint sweeps; `take_output_pages` publishes a machine group's pages and clears per-group inputs. Comments mention a "nonconvergent fallback" that replaces the state-value inputs wholesale (551-569) and a dirty set that triggers re-sweeps (224, 861-867).
- **Parallel origin solve** (flow_context.rs:112-148). Solves every machine's parameter-origin and storage-origin fixed point once with rayon before flow groups run; a machine the table does not cover is solved on the spot (815-859).
- **Dense symbol position tables** (flow_context.rs:69-105, 528-569). Indexed by arena position with the stored handle compared so another generation finds nothing.
- **Widening thresholds** (flow_context.rs:892-904). The program's integer literals are collected once as `BigInt` thresholds for a widening step that lives outside this slice.
- **Budgets**: none algorithmic in this slice. The only cap is 8 trace rows per call (flow_call_phases.rs:1255-1259). A comment refers to a "work budget" owned by the predicate reader elsewhere (flow_context.rs:761).

## Identity by text

- **Carry transfer matches by rendered label.** `source_label = expression_table.display_name(argument)` and `fact_label = semantic.place_label(...)`; a carry fact transfers when the places match **or** the two strings are equal (flow_calls.rs:389, 420-424).
- **Variant `requires` rebased by string substitution.** The subject is rendered to text, each payload and common field maps to `"{subject_label}.{field.name}"`, and the clause is re-rendered and stored as an instantiated string in the fact (flow_exits.rs:500-535). The comment calls this "the same canonical-term renderer call contracts use" (434-437).
- **Parameter of an `ensures` subject found by spelling.** `parameter.name.as_str() == name.as_str()` is accepted alongside symbol equality (flow_calls.rs:1067-1071).
- **Reserved name `result`.** `names_reserved_result` and `signature_reserves_result(parameter names)` (flow_calls.rs:948-953, 1064); literal `"result"` comparisons (flow_context.rs:1120, 1127).
- **Instruction effect chosen by intrinsic name.** `AsmRegisterOperation::from_intrinsic_name(builtin.name())` (flow_call_phases.rs:916-920).
- **Diagnostics only**: an environment variable compared with `"1"` or the machine's name selects trace output (flow_call_phases.rs:1711-1713).
- **Not text, but not a stable identity either**: memo keys use the address of the selected signature, `std::ptr::from_ref(s) as usize`, with 0 for "none" (flow_calls.rs:489, 612, 664; flow_call_phases.rs:1744).

Evidence against property 2: everything else in the slice identifies storage by `CanonicalPlace { root, segments }`, symbol handles and `SemanticDomainId`, and several comments reject spelling outright: "Writer identity comes from its callee-relative formal, never selector spelling" (flow_call_phases.rs:1479-1481); "The completed reference's actual backing, not the source spelling" (520-521); "an unresolved copy never falls back to newer storage at the source spelling" (flow_context.rs:685-686).

## Accepts or skips without proof

- **No proof kernel anywhere.** A search of the four files for `proof_admission`, `ProofNode`, `verify_obligation`, `certificate` finds nothing. Every fact is published on this code's own decision with `QualificationEvidence::default()` (flow_exits.rs:416, 540, 806, 1249, 1263) or `propagated_evidence(target)` (flow_calls.rs:511, 685; flow_call_phases.rs:2144).
- **Callee promises published as caller facts.** Result memberships, parameter memberships and referent field memberships are stated because the signature or type declares them; comments say the callee's own exit check proved them (flow_calls.rs:449-452; flow_call_phases.rs:1472-1475) and that "the content checker independently rejoins routed parameter claims" (flow_calls.rs:630-632). Those checks are outside this slice; cannot tell from here.
- **Bodyless or boundary-crossing callee: no issuer fence.** `result_identity_is_available` returns true when there is no checked realization (flow_calls.rs:547-549; comment 593-594 "absence denotes a crossing or bodyless provider and adds no fence"). The declared signature is trusted. Cannot see another check here.
- **`retain_guarantees` keeps a guarantee when a lookup fails.** An occurrence with no canonical place, or whose root is not a symbol, counts as surviving (flow_call_phases.rs:836-843); a symbol that is not a parameter counts as surviving (854). Cannot tell whether another check covers these.
- **Expression temporaries always survive** (flow_call_phases.rs:775-777) and live views always survive (762-764) in `observation_survives`.
- **Alias closure failure falls back to the declared place alone.** If `close_storage_places_over_aliases` returns `None` for a `Declared` write, the observation list is just that place (flow_call_phases.rs:1186-1197). If `None` means "unknown aliases", facts seen through aliases are not retired. Cannot tell what `None` means from this slice.
- **Captured-alias invalidation skips on failed lookups.** No place for the capture, no ownership place, or unknown later writes each `continue` without adding an alias (flow_call_phases.rs:56-71, 125-136). Fewer aliases means fewer retired facts. Cannot tell whether an unknown write is caught elsewhere.
- **`install_returned_reference_custody` returns unchanged if the borrow call handle is not found** (flow_call_phases.rs:1364-1369); replaced loans then stay active. The loan-row consistency checks are `debug_assert_eq!` only (1391, 1397).
- **`ParameterReferent` incoming references always survive a call** (flow_call_phases.rs:1409-1414).
- **A matched case contributes the variant's `requires` as facts** (flow_exits.rs:444-556). This trusts that the value was constructed with those constraints established. Non-expression clauses are skipped (527-530) and the comment says "membership and proposition-application clauses still wait for their carriers" (439-441).
- **Guard with no place occurrences publishes a fact at `FactPlace::Unknown`** (flow_exits.rs:1239-1244).
- **Contradictory bounds produce no fact** rather than marking the arm unreachable (flow_exits.rs:408-410).
- **More than one matching outgoing edge at an exit silently yields invalid handles** for returned value and storage (flow_exits.rs:1433-1436).
- **`build_dynamic_conformance_facts(program).ok()`** discards the error and continues without the table (flow_context.rs:185-187).
- **Many early `return`/`continue` on failed lookups in the publishers** (for example flow_calls.rs:328-387, 469-486, 646-655; flow_exits.rs:242-253, 347-362, 465-499). These withhold a fact, which is the conservative direction.
- **Conservative defaults that go the safe way**: unknown write set drops all facts (flow_call_phases.rs:1261-1262); `source_survives` needs both write lists known (799-801); `ArgumentSources::new` returns `None` on any mismatch (603-610); a contract-position `Err` marks the fact stale (855); `source_transfer_cases_selected` returns false for a non-statement point (flow_context.rs:1239-1241).

## Surprises

- **The slice issues no diagnostic.** These 6454 lines never refuse a program; they only decide which facts exist. Soundness of everything here depends on a fact being absent when it should be, which nothing in the slice checks.
- **A text fallback sits in an otherwise structural function.** Carry permissions cross a call when the place handles differ but the rendered labels match (flow_calls.rs:420-424). Two different storages with the same rendered name would pass this test.
- **Comment and code disagree on spelling.** The module comment says no "source spelling can manufacture execution" (flow_call_phases.rs:897-899), yet the instruction effect is selected from the builtin's name string (916-920).
- **Misplaced comment.** The "P1a mapping" comment (flow_calls.rs:265-271) and its `#[allow]` (264) sit above `memoized_call_target_return_type`, but describe `append_one_to_one_call_carry_facts` at 318.
- **Dead duplicate check.** `return_type.is_valid()` is tested twice with nothing between that could change it (flow_calls.rs:857-859 and 865-867).
- **Memo keys use a pointer address** of a signature reference (flow_calls.rs:489, 612, 664; flow_call_phases.rs:1744). The comment at flow_context.rs:251-254 explains why two calls to one requirement need different rows, but address identity is used to tell them apart.
- **`retain_guarantees` drops whole contexts.** If any fact in a context comes from a stale `ensures`, the whole context is removed, including unrelated facts in it (flow_call_phases.rs:871-890).
- **`affected` can be set for a write that turns out not to touch the fact.** `affected = true` is set at flow_call_phases.rs:2085; the later re-match against captured places can return "not affected" (2099-2104). The fact is then re-published as "preserved" although no writer changed it. This looks harmless (the fact was true) but the flag does not mean what its name says.
- **`FlowCallFact` is created with about twenty fields defaulted** (`authored_expression`, `authored_site`, `operands`, `service_reach`, `suspension`, `blocking`, and others; flow_calls.rs:216-256). Something outside this slice must fill them; cannot tell from here.
- **Unused parameters.** `with_shared_tables` takes `_borrow`, `_proof`, `_semantic` and ignores them (flow_context.rs:412-414); `machine_index` and `state_location` ignore `_program` (507, 577).
- **Hard-coded `U64`** when a guard endpoint is a member expression lowered to a literal (flow_exits.rs:305-319). A constant of another integer type either fails to lower or is read as `U64`; cannot tell which from here.
- **Panics.** `append_state_exit_facts` uses `.expect("exit machine")` and `.expect("exit state")` (flow_exits.rs:1497, 1501), where sibling functions return early on the same lookups (242-253).
- **`append_outgoing_state_fact` is called with `active_constraints` for both the operand-entry and the final constraint lists** on the implicit exit (flow_exits.rs:1466-1467).
- **A `Vec` of zero or one element is built to loop over an `Option`** (flow_calls.rs:698-701).
- **Unexpected capabilities.** (1) Interprocedural byte-class summaries: the caller keeps "all bytes are class C" across a callee's indexed write by asking a per-callee normal-return predicate table (flow_call_phases.rs:1948-1992, 2184-2207). (2) A solver-free case split on an unknown array index (1673-1686). (3) Narrowing a callee's whole-array write to the one element the caller passed, using the argument's captured referent rather than the source expression (205-238). (4) Replay of earlier saved guard observations at a later guard (`saved_guard_observations`, flow_exits.rs:150-165), so an inner branch can recover an enclosing tag test.
- **Property summary for this slice.** Property 1 holds without exception (no kernel call; evidence is a tag). Property 2 holds in five specific places and is contradicted by the bulk of the code, which is structural and says so in comments. Property 3 holds for post-call membership publication (result, by-value argument, `&mut` referent, handback, carry each have their own function) and for case-tag facts, but Boolean guards and match arms share one path.
