## What this code is for

The slice has three parts. The first (`values_and_views.rs`) is not a checker: it is the data model the old checker wrote its results into. It defines "checked" scalar computations, proof terms, Unit-result completion plans, structural values, per-expression value facts, and borrowed read/write views over the whole fact store (`values_and_views.rs:1-5`). Every record is addressed by a source coordinate: machine symbol, state symbol, statement ordinal, a role enum, and often an expression handle. The file carries a few small judgments of its own: whether two guards are exact complements, whether a structural value completes normally, and which retained value a saved match subject refers to.

The second part (`lowered-psi/lib.rs`) is the carrier type between lowering and Terminal Psi publication. It keeps side tables that tie Terminal operations back to source statements and calls so later stages can "join source proof and contract obligations" (`lowered-psi/lib.rs:9-16`). Its own header says nothing produces it any more (`lowered-psi/lib.rs:19`).

The third part is the opaque-representation admission crate (`rp/lib.rs`, `representation_selection.rs`, `selections/lib.rs`). A build machine may select `Build::select_representation<Opaque, Conformance>`; this crate checks that the conformance implements the compiler-owned `OpaqueRepresentation<Opaque, Carrier>` trait, that the carrier's whole by-value type graph is inert storage, records the selection with a 32-byte commitment, and re-derives the selections against the final typed program.

The four Markdown files are the old checker's own description of what the `validation` crate enforced and where it stopped: source proof automation, arithmetic and arrival analysis, write frames, quotients, structural algebra, numeric proofs, recasts, and opaque representations. They state the limits of the code more candidly than the code does.

## Mechanisms

- **Coordinate-keyed row stores.** Each plan table is an arena plus `KeyedRows` indexes by state or machine symbol (`values_and_views.rs:136-156`, `1022-1034`, `2166-2174`). A lookup takes the rows for the key, filters by statement ordinal, role and expression, and demands uniqueness. `seal` builds the indexes (`158-164`, `1467-1471`, `2200-2209`). The completion table instead sorts its roots by a seven-part numeric coordinate and uses a binary search (`945-977`, `988-999`). This serves every construct: it is how one stage finds what an earlier stage decided about a source position.
- **Normal-completion walk** (`values_and_views.rs:1231-1340`). A depth-first walk over a structural value's children. It keeps a stack `active`; meeting a value already on the stack answers `Normal` (`1255-1257`). There is no visited set, so a value shared by two parents is walked twice. A caller may supply `prepared_root` to short-circuit known values. No budget. Serves calls that do not return, and match dispatch.
- **Dependency closure** (`values_and_views.rs:1342-1396`). Worklist over the same child relation; `values.contains` is a linear scan, so the cost is quadratic in the number of values. Returns `None` on any invalid handle.
- **Saved-subject resolution** (`values_and_views.rs:1605-1675`). A loop that replaces a saved alias by its source until a retained root is found, with a list of captures already followed to refuse cycles. Serves `match` payload bindings that read the matched subject.
- **Guard polarity normalization** (`values_and_views.rs:1984-2006`). Strips any chain of `Not` and comparisons with a Boolean constant, tracking a polarity bit. Serves the exact-complement test for two-way guards.
- **Carrier closure** (`representation_selection.rs:54-222`). A recursive walk of the carrier's type graph with three lists: `visiting` (type identities on the stack), `validated` (memo), and `applications` (ancestor data applications, pruned of those the current type is a strict type argument of, `175-185`). It has no depth or work budget; termination relies on the cycle and family checks. Serves opaque boundary data.
- **Selection commitment** (`selections/lib.rs:73-102`, `140-147`). A 32-byte value computed by `selected_application_commitment` from the conformance application commitment, lifecycle, copy disposition and origin. Re-derivation recomputes it and compares (`representation_selection.rs:658-662`).
- **Harvest and re-derivation** (`representation_selection.rs:570-676`). The same collection function runs once during build evaluation and again on the final typed program; the second result must equal the retained list.
- **Bounded diagnostic dump** (`representation_selection.rs:254-428`). At most 4 detail rows (`ROW_LIMIT`, `261`) and 4,096 bytes (`TEXT_LIMIT`, `262`), with full counts kept.
- **Mechanisms the documents describe (code elsewhere):** descending arrival fixpoint (`validation/README.md:150-152`); complete-or-opaque may-write analysis with a finite worklist (`validation/README.md:311-349`); result-origin state equations (`validation/README.md:379-386`); bounded predicate-machine exploration with a work budget (`validation/README.md:92-117`); polynomial expansion capped at 64 terms per product (`validation/README.md:454-456`); rational evaluation of anonymous arithmetic (`validation/README.md:287-289`, `numeric_proofs.md:10-14`); quotient/remainder interval rules (`numeric_proofs.md:25-33`).

## Accepts or skips without proof

- **A structural call with no call record is judged to complete normally.** `call.is_some_and(|call| !call.has_normal_continuation())` is false when no record matches, so the answer is `Normal` (`values_and_views.rs:1262-1271`). Cannot tell whether another check catches a missing record.
- **A cycle in a structural value is judged `Normal`** (`values_and_views.rs:1255-1257`). Cannot tell.
- **Scalar children are not examined for completion.** `Scalar`, `ScalarArray`, `Case`, record fields holding scalars, and `ViewSubslice` start/end all fall to `_ => Normal` or are skipped (`1296-1306`, `1327`). A scalar computation that contains a non-returning call is not seen by this function. Cannot tell whether scalar plans are checked elsewhere.
- **A dispatch with no arms is `Normal`** (`all_stop = !arms.is_empty()`, `1285`).
- **`expression_at` returns the first match** and does not check for a second (`values_and_views.rs:2272-2300`), unlike `bound_expression_at` beside it, which returns `None` on a duplicate (`2238-2240`, `2254-2256`).
- **`scalar_type_refinement_predicates` returns the first row for a type**; `retain_scalar_type_refinement` appends without checking for an existing row (`2103-2128`). A second, different refinement for the same type would be ignored silently.
- **`roots_for_statement_role` returns every match** where `root_at` demands one (`232-258` versus `211-230`).

- **`matches_checked_origin` ignores the call ordinal, the machine and the role.** Any call occurrence in the same state and statement matches (`lowered-psi/lib.rs:80-94`). Cannot tell whether callers narrow further.

## Surprises

1. **The proof kernel appears in this slice only as a stored handle.** `CheckedProofTerm::Mathematical` and `MathematicalApplication` hold `proof_admission::TermHandle` values (`values_and_views.rs:769-770`, `774-775`). No code in the slice calls a kernel function. Every decision in the tables above is the code's own comparison or a call to another source-level module. The documents confirm this was known and intended as a stage: `validation/README.md:79-80`, `126-131`; `numeric_proofs.md:5-6`.

2. **`lowered-psi` had no producer when it was deleted.** Its header says the stage that produced it "is deleted" (`lowered-psi/lib.rs:19`), while `numeric_proofs.md:63-64` still describes "the lowering join" in `06_checked-trees-to-lowered-psi/src/proofs.rs`, and `recasts.md:158-166` describes Psi 06 lowering in the present tense. So the old pipeline was already cut in the middle before PR #2823, and these documents were stale against the code beside them.

3. **The validation documents point at files that had been merged away.** `validation/README.md` links five differently named owners to the same file (`program_validation.rs`, lines `10-14`), links `structural_judgment.rs` to `src/contract_entailment.rs` (`434`), and `quotients/request_admission.rs` to `src/quotients.rs` (`412`). `numeric_proofs.md` uses a different layout again (`src/proof_contracts/contract_entailment/arithmetic_judgment.rs`, line `25`). In `rp/README.md` the link text `carrier_closure.rs` points at `representation_selection.rs` (`20`) and `representation_trait.rs` at `lib.rs` (`22`); the code confirms both are inline modules (`representation_selection.rs:22`, `rp/lib.rs:28`). The module paths named in prose (`arithmetic_domains/guard_narrowing/arrivals.rs`, `ranking_range/telescope.rs`, and so on) may therefore not exist as files.

4. **The exact-complement test is purely syntactic and narrow.** `x < 5` and `x >= 5` are not complements unless one is written as `Not` of the other; integer comparisons have no case in the match (`values_and_views.rs:1915-1973`). Case-membership complements are recognized only when the subject is a parameter field (`1963-1965`); the same test on a local or a call result returns false. The IEEE case accepts only `Equal`/`NotEqual`, which is correct in the presence of NaN.

5. **`completion_with` answers `Normal` in three situations where it has no information:** no call record (`1267-1271`), a cycle (`1255-1257`), and any scalar child (`1327`). In the same function two call records give `None`. Missing evidence is treated as the permissive answer and surplus evidence as "cannot decide".

6. **A test name promises more than the test does.** `expression_lookup_observes_same_length_state_mutation` never seals the index (`2458-2485`), so it exercises only the linear scan. On the sealed path, `expression_at` first looks up `by_state.get(&state)?` (`2281-2282`); after an in-place state change with the same length, the new state has no bucket and the lookup would return `None`. The length check at `2241-2242` and `2278-2279` detects only appended or removed rows. `expressions` is a public field (`2167`).

7. **Sibling lookups disagree on duplicates.** `bound_expression_at` gives `None` for two matches; `expression_at` gives the first (`2221-2300`). `root_at` gives `None`; `roots_for_statement_role` gives all (`211-258`). `scalar_type_refinement_predicates` gives the first (`2123-2126`).

8. **About a quarter of `representation_selection.rs` is one diagnostic.** `representation_resolution_context` (`254-428`, 175 lines of 676) builds text for the single "does not resolve to one visible named conformance" error. It prints Rust `Debug` output of handles, spans and internal tables into a user-facing message (`268-279`, `304-321`, `350-359`, `391-405`). It reads like debugging instrumentation for one hard-to-find failure that was left in. It inserts the count lines at position 0 (`417`), so they come before the "representation lookup context" header line. The row limit of 4 is shared by candidates, sources and symbols (`293`, `345`, `367`), so four candidate rows suppress every source and symbol row, and `conformance_membership` counts are written only for symbols that were shown (`367-386`).

9. **`collect_opaque_representation_selections` returns `Vec<Diagnostic>` but never more than one diagnostic** (`584`, `592`, `602`, `611`, `620`, `631`).

10. **Executing the same selection twice is reported as selecting the opaque "more than once"** (`627-638`), because uniqueness is by opaque symbol among executed events; the code cannot tell a repeated identical request from a conflicting one.

11. **Re-derivation compares with full `Vec` equality** (`668`), so a change in source span or in order is reported as a disagreement, although `rp/README.md:57-58` calls span and build-machine identity "audit provenance rather than semantic identity".

12. **`FormedOpaqueRepresentation` keeps an unused `_program` reference** only to tie its lifetime to the typed program (`representation_selection.rs:227`, `561`).

13. **A capability worth noting:** the representation already separates a value from the place that holds it in some spots. `CheckedStructuralValueKind` distinguishes `Place`, `CopiedStructuralPlace`, `Reference` with a `source_value`, and `Projection` with `copies_selected_value` (`1117-1168`), and `root_for_value_home` exists to stop an alias from relabelling a value (`1704-1721`). The addressing, though, is still by source position: every root is keyed by state, statement ordinal and expression.

14. **The documents list many refusals that are placement limits, not language rules,** and say so: field intervals only for immutable owned parameters (`validation/README.md:161-164`), rank fields only for builtin `u64` direct fields of immutable owned parameters (`262-277`), float-meaning sources only below a top-level structural parameter (`numeric_proofs.md:66-70`), recasts validated only in listed positions with contract-only positions "fenced" (`recasts.md:118-122`), domain-issuer rejections that are "implementation limits" (`validation/README.md:64-65`). This is direct evidence for property 3 in the authors' own words.

15. **A known unsound-looking exception is documented, not hidden:** across unknown effects, "legacy code-only `dyn` selectors retain their private value" (`validation/README.md:332-334`). The text gives no reason why that is safe.

16. **A recorded concealed mistake:** a literal-suffix query made before the loan join "loses its descriptor", and for a runtime suffix a conservative whole-backing loan "happens to conceal the same mistake" (`recasts.md:145-146`). The document describes the correct order but does not say the mistaken order was removed everywhere.

17. **Test corpus references.** `validation/README.md:119-121` and `recasts.md:33-34`, `267-268` name `tests/omega/pass/proofs`, `tests/omega/fail/proofs`, `tests/omega/pending/atomics/standalone_reference_access` and `tests/omega/{pass,fail}/recast/` as the tests of these rules. Those are the only statements in the slice of where the documented rules were tested; the slice itself contains six unit tests, none of them for a language rule.
