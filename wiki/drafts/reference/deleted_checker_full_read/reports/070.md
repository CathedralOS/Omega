## What this code is for

BP is the old checker's store and small prover for Boolean facts that relate several storage places ("relational formulas", BP:1-5). A guard such as `a < b` becomes a `BoundPredicate`: a checked Boolean expression plus a list of bindings that say which exact storage place (`CanonicalPlace`) each operand of the expression reads (BP:1296-1370). BP publishes such predicates as facts, retrieves the ones still live at a program point, expands a "value is a member of domain D" fact into D's own predicates, and answers four questions from them: is this required formula true (`proves`/`truth`, BP:2477-2532), are the premises contradictory (`unsatisfiable`, BP:2023), what Boolean value does a place have (BP:1944), and what integer interval or exact constant does a place have (BP:434, BP:1328). It also keeps "entry path conditions": the guards, written over a machine's original entry arguments, that must have held for execution to reach a point (BP:651-983).

CC decides which declared crash conditions of a callee are still possible at each call site. A callee's crash contract is a list of buckets, one per crash cause, each with alternative guards. For each call CC substitutes the call's arguments into the guards, tries to decide each guard true, false or unknown, and keeps the buckets that survive (CC:2727-2940, CC:5152-5517). For private machines that publish no crash contract it infers a summary from the body, iterating to a fixed point across the call graph (CC:473-789). For generated "target family" interfaces it computes the union of crash causes of all members and refuses a family whose members are incomplete (CC:240-304, CC:1078-1147). It also contains a compile-time evaluator for IEEE float operands so that float guards can be decided (CC:4313-4980).

Neither file calls the proof kernel. Both decide by their own evaluation and write the result into fact tables or `CheckedCrashCallSite` records.

## Mechanisms

- **Unit propagation to a fixed point** (`formula_closure`, BP:2030-2172). Collects every sub-formula of the premises and queries, seeds truths with the premises and with any sub-formula that evaluates from resolved leaf values, then repeats: propagate through `Not`, `And`, `Or`, Boolean `Equal`, and symmetry of integer `==`. A conflict returns `Contradiction`. No transitivity, no arithmetic. No explicit budget; the truth table is bounded by the number of sub-formulas plus the swapped equalities. Serves requires/ensures discharge and guard inference.
- **Observation normalization** (BP:557-585). Renumbers every operand of several predicates into one namespace keyed by (exact place, kind), so formulas from different frames compare by structure. Clears `formation_decided` and `trap_free` flags on the clones so that the same operation compares equal whether or not a stage had decided its overflow (BP:587-649).
- **Entry path conditions as clause sets** (`EntryPaths`, BP:660-843). Disjunctive normal form over signed guard atoms, with subsumption on insert (BP:686-698), union at joins, pairwise product for conjunction. A `known: false` state absorbs everything. No size bound on the clause product.
- **Integer interval consequence** (BP:462-545). Recursive walk with a negation flag; De Morgan by `matches!(And) != negated` (BP:477).
- **Retention with domain templates** (BP:1030-1214). Per query, domain predicates are lowered once per (domain symbol, semantic id) and re-rooted onto each subject place; duplicates are removed by sort-group-compare while restoring first-appearance order.
- **Cause-set fixed point** (CC:125-150). Unbounded `loop` over monotone sorted cause vectors.
- **Viability pruning** (CC:440-469). Repeatedly removes summary nodes whose dependencies are not viable until nothing changes.
- **Private summary fixed point** (CC:729-789). Dirty-flag sweeps, at most `equations.len() + 1` sweeps. Recursive edges are widened to unconditional causes before the path guard is applied. When the sweep bound is reached the function returns the current state without an error.
- **Reachability search** (CC:1015-1066) decides whether a dependency is recursive.
- **Guard and bucket normalization** (CC:3457-3505). `Truth` absorbs all alternatives; otherwise sort and merge equal predicates; buckets group by cause in a `BTreeMap`.
- **Guard conjunction** (CC:2956-3016). Flattens `And` trees, sorts and dedups conjuncts, refolds.
- **Closed literal folding** (CC:3072-3244). Folds Boolean literals, `!`, `&&`, `||`, `==`/`!=` on Booleans and floats, and six integer comparisons on integer literals parsed from text.
- **Entry equation substitution and complement exclusion** (CC:3676-3835). Depth limit 64.
- **Set-valued IEEE evaluation** (CC:4345-4474, 4524-4638). Carries every possible completed value; evaluates the Cartesian product of operand value sets. No bound on set size.
- **Budgets seen**: lowering budget `&mut 4096` (BP:1839, BP:1856, CC:2230, CC:3952); recursion depth 8 (CC:2032); depth 64 (CC:3683, CC:4166, CC:4252).
- **Parallelism**: `rayon` over plans, nodes and flow states (CC:389-424, CC:506-694, CC:5209-5482).

## Identity by text

BP identifies everything by handles and `CanonicalPlace` (root symbol plus segments); I found no string that decides identity there. BP:1821 copies `domain.subject_name` into a synthetic parameter, but lookup is by `subject_symbol`. Formula identity in BP is structural equality of expression trees (BP:690, BP:725, BP:853, BP:2037, BP:2055, BP:2522).

CC builds crash-guard identity as a tree that carries text (`CrashPredicateExpression`), in `predicate_expression` (CC:5009-5110):
- A name is a parameter if its single member's spelling equals an entry in `parameter_names`; the first matching name wins (CC:5061-5071). Otherwise it is `Name(Vec<String>)` (CC:5072-5077).
- Integer literals are stored as their decimal or source text (CC:5058, CC:1799, CC:4267-4269, CC:4304); float literals as source text (CC:5059, CC:4286-4287).
- Members are stored by name, with a payload field rendered as `format!("{case}::{field_name}")` (CC:5079-5086, CC:5604-5628).
- A call is stored by the spelled callee name `call.target.as_str()` (CC:5096-5104).
- Any other expression is stored as `Opaque(program.expression_table.display_name(expression))`, a rendered label (CC:5105-5108).

Places where that text decides something:
- Parameter name lists are produced and passed in: `declared_parameter_names` (CC:649, CC:3618, CC:5183, CC:5377), `machine_entry_parameter_names` (CC:569-573), parameters `parameter_names: &[String]` (CC:1199, CC:2738, CC:5003).
- The published route's typed expression is found again by rebuilding its identity from text and looking it up in a `BTreeMap` (CC:1196-1227, CC:2789-2791).
- Guard equality, ordering, dedup and conjunction use the text-bearing identity (CC:3026-3046, CC:2992-2993, CC:3463-3476).
- Caller requirements exclude a route by `excluded.contains(&substituted)` on that identity (CC:3663), and equations substitute by equality on it (CC:3796).
- Field projection through a call compares member names as strings: `if member != *expected` (CC:1918-1926), with `members: &[String]` (CC:1891).
- Integer comparison parses the stored text, handling `-`, `0x`, `0o`, `0b` prefixes (CC:3220-3243). Float equality parses both texts and compares `value_f64()` (CC:3192-3196).
- A float observation is returned as a `String` spelling (CC:4506, CC:4955-4968) and then compared through the same parse.
- Constant decoding passes a type name string: `type_name: expected.name().to_owned()` (CC:4795).
- Operators inside identities are compared as `u8` codes of the source operator (`BinaryOperator::And as u8`, CC:2985, CC:3087-3131, CC:3699-3727), not text, but the identity still follows the authored syntax tree.

Text used only for messages: `display_path(.., "::")` (CC:347, CC:355, CC:909, CC:1103), `spelled_callee` (CC:904-912). The test compares results by `format!("{actual:?}")` (CC:1351).

## Accepts or skips without proof

BP:
- `&mut |_, _| Some(())` is passed as the per-step callback when resolving a structural path for a result (BP:199-201, BP:259), so every step is accepted. The comment at BP:271-274 says formation, tag selection and access proof "remain at the actual checked observation and load". Cannot tell from this slice that they do.
- Scalar compatibility compares only the primitive (BP:348-350, BP:281-283); the declared type reference (for example a domain over `u64`) is not compared. Cannot tell if another check uses the reference.
- Facts are appended with `evidence: Default::default()` (BP:904, BP:1776, BP:1786). No evidence object is attached to a published predicate or its storage dependencies.
- An unknown entry path is stored with expression `Constant(false)` and distinguished only by its role (BP:889-898). `EntryPaths::retained_with_knowledge` checks the role (BP:828-839); a reader of `expression` alone would see `false`.
- Under `PathKnowledge::Necessary` an unknown path condition is skipped (BP:830-834). Documented as an over-approximation for crash reasoning (BP:865-871).
- Facts with invalid handles, unreadable binding spans or invalid places are skipped with `continue` (BP:1065-1095). As premises this only loses information.
- Domain proof facts that cannot be lowered are dropped by `filter_map` (BP:1828-1878); `Proposition` facts are always dropped (BP:1859); a membership that refers to the subject is dropped (BP:1843-1848); a parent domain or alias constituent that fails expansion is skipped (BP:1881-1899). The comment at BP:1794-1797 says the result "supplies goals, not membership premises". Where it is used as the list of goals for admitting a membership claim, a dropped fact is a goal this path never checks. Cannot tell whether another check covers the dropped goals.

## Surprises

1. **Float values may be compared in the wrong width.** Float equality in a guard is decided by parsing two texts and comparing `value_f64()` (CC:3192-3196); no float format is passed. The argument side is produced by `FloatLiteral::from_f64(first.to_f64()).text()` (CC:4963-4966), which widens an `f32` value to `f64` before spelling it. The contract side is the literal's source text (CC:5059). For an `f32` parameter with guard `x == 0.1` and an actual equal to `0.1f32`, the two texts would denote different `f64` values, the fold would return `false`, and the route would be erased (CC:2883-2886). The entry-path code spells a literal from its bits with the format (CC:4277-4288), so the two producers differ. I could not confirm how `FloatLiteral::parse` treats width from this slice; note that CC:4597-4598 uses a different accessor, `landed_f64()`.

2. **Two implementations of "the result equals a formal", with different trust.** The integer one requires a live `CallEnsures` fact for the exact call, a builtin-meaning check and an overwrite check (CC:3886-4023). The Boolean one reads the callee's declared `ensures` from the declaration and has none of those checks (CC:2202-2285).

3. **The float evaluator reads a callee's body.** `produced` decides a call returns its argument by inspecting the callee's entry-state return statements (CC:4698-4757). Everywhere else in the slice a call is known only through its contract or its inferred summary.

4. **The two copies of the guard decision ladder disagree.** For a guard without builtin meaning, the call-site copy tries `boolean_value()` and then `summary_closed_float_relation` (CC:2877-2880); the summary copy tries only `boolean_value()` (CC:3363-3367).

5. **Guard equality ignores the scalar annotation.** `SummaryCrashPredicate` compares and orders by `identity` and `builtin_meaning` only (CC:3026-3046). Two guards with the same text identity and different checked scalar forms are merged and one scalar is kept (CC:2970-2975, CC:3466-3475).

6. **Two notions of a machine's entry state.** BP finds it with `validation::activation_target_state_index` (BP:310, 959, 1431, 1480). CC takes `machine_states(machine).first()` (CC:1098, 1109, 3614, 4082, 5182), and BP does too for `ProgramPoint::Machine` (BP:117).

7. **`Trap` is counted differently in two places.** The public cause envelope adds `Trap` when any trapping site exists (CC:69-71); the body summary adds it only for sites with `may_trap` (CC:978-988). The comment at CC:18-23 says the public envelope is deliberately not narrowed by proofs.

8. **Caller `requires` remove callee crash routes by syntactic complement.** `entry_equations::refine` walks the checked form and the text identity of each `requires` in parallel and assumes they have the same shape (CC:3686-3748). Any shape mismatch falls to `_ => Vec::new()`, so it loses precision rather than soundness.

9. **`&&` and `||` folding is order dependent.** `false && unknown` folds to `false`, but `unknown && false` is unknown (CC:3087-3091, CC:3157-3166).

10. **The family output omits the family's own direct causes.** `potential_causes::infer` returns, for each family, only the union of its dependencies' causes (CC:159-171), which the comment at CC:21-23 explains as "only inferred member causes need an additional unconditional permission". The fixed point at CC:129-150 computes more than is returned.

11. **Evidence against property 2 in BP, and for it in CC.** BP never uses a name; places are exact (`CanonicalPlace`) and formulas are placement-independent once bound. CC's whole guard identity is a source-syntax tree with names and literal spellings (see "Identity by text"). The same subsystem therefore has both designs side by side: a checked scalar form (`scalar`) and a text identity (`identity`) travel together in `SummaryCrashPredicate` (CC:3019-3024), and code repeatedly reconciles them.

12. **Evidence on property 1.** No call to `proof_admission`, `ProofNode`, `verify_obligation` or any certificate type appears. `ProofFacts` is read only as a table of retained call signatures (CC:1450-1470). The outputs are called "entirely checked data" (CC:5148) and carry a contract fingerprint and commitment (CC:5461-5475), which identify the callee's contract, not a proof of the refinement.

13. **Evidence on property 3.** BP's comments aim at one mechanism (bind an observation to a place, then reason on the formula), and its prover has no per-placement cases. The per-placement code is in the binding and traversal layers. CC repeats per target kind and per expression variant rather than per source placement.

14. **Capabilities I did not expect:** compile-time IEEE arithmetic with trapping and saturating policies and both signed zeros (CC:4345-4474, 4607-4614); a path-condition domain in disjunctive normal form (BP:660-843); an interprocedural crash-effect fixed point with recursion widening (CC:729-789); a rule that a byte proved to be 0 or 1 can be read as a `bool` through copies, borrows, matches and calls (CC:2020-2183).

15. **Small oddities.** `call_argument_substitution` finds the caller's machine by scanning every machine for the state (CC:1631-1635) although `state_flow.machine_symbol` is available and used later (CC:1858); the same scan is at CC:2797-2812. The internal-state-transfer check in `attach_checked_crash_calls` runs after all target resolution (CC:5392-5395). `crash_predicate_from_expression` and `substitute_structural_parameter_field` are one-line wrappers (CC:5000-5007, CC:2591-2596). `let _ = other;` does nothing (CC:5106). Lines CC:5373-5390 and CC:5444-5446 are not formatted like the rest of the file, which suggests the formatter did not process `attach_checked_crash_calls`.
