# Cross-check G01

## Summary

I classified 66 rows: inventory rows 13-78. I skipped row 79, which covers the old code's internal bookkeeping. Paths below are relative to `source-rust/subsystems/compiler/` unless they start with `package-manager/`.

- **Enforced: 37**
- **Refused wholesale: 13**
- **Unclear: 9**
- **Not found: 2 whole rules, plus 3 sub-rules of enforced rows**
- **Not looked up: 5**

The deleted G01 code did not judge programs itself; it read the old checker's output. Its rules now live in five places:
- the Psi layout owner (`psi/layouts`, `psi/semantics/src/references/reference_storage_geometry.rs`);
- Build's provider plans and selections (`build/providers/`);
- the native target-bound program (`psi-to-native/representations/target-bound-program/`);
- the source driver's provider choices (`source-to-psi/driver/compile_product/`);
- a rewritten package review (`build/planning/package_review/` and `package-manager/review/evidence/`).

Layout, provider-plan coverage, entry-slot settlement, accepted bindings and terminal-authority permissions all have current checks.

Several old rule families are now refused outright rather than checked. Stage 05 (the stage that reads source into a lowered program) refuses these:
- user boundary operators and operator-family selections;
- `match` on a float;
- target-family machines;
- termination premises;
- quotient data;
- assumed bindings (a Build product declaration);
- public refinement evidence in package review.

Two old name-matching weaknesses are gone. The compiler now recognizes intrinsics and dangerous core services through toolchain catalogs that authenticate the declaring source (`foundation/language-core/src/sealed_intrinsics.rs`, `language_core::core_vocabulary`). Before, it matched bare names.

The most worrying gap is row 46. I found no analysis that proves a checked-body provider of the process-exit requirement never returns normally and passes its status unchanged to a real exit leaf. Only native leaves are checked: their completion class must equal the requirement's.
