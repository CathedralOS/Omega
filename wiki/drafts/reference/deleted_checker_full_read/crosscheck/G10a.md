The numeric rules and the recursion rules survive, and in a stronger form: each one is now an obligation (`OperationSafety`, `CallRequirement`, `DataDomain`, `CrashCoverage`, `RankComparison`) that stage 06 accepts only with a certificate the proof kernel checked, where the old code accepted on its own interval verdict. The whole `@write` surface is refused at the parameter (`S5/read/machine.rs:4097`), so its eleven rules are not checked but cannot be reached; two residual read checks remain for write-only references that reach the lowered form another way. The gap that stands out is the custody agreement (R1–R5): the specification and the bundled library both say "the compiler checks" an `AccessCustody<C, P, T>` implementation against its schema, and no Rust file in `source-rust/` mentions `AccessCustody` at all. Three smaller holes sit beside it in the access area: accessor package privacy (R12), the destructive-read refusal (R13) and the proof that a value fits a narrowed laid-out integer field (R50). Proof-only recursion (R93–R95) has no code of its own; it is safe today only because every non-tail recursive call is refused. Two old rules changed on purpose rather than vanished: integer comparisons may now mix carriers (R26), and a clause may use a clause formed later in authored order (R74).
