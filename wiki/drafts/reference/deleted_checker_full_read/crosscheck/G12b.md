What stands out:

- Most of this group's rules about calls survive, but in other stages than a reader of stage 05 and 06 would expect. Overload choice and operator choice are made in stage 03 and stage 02. Callback and static-argument fit is checked in stage 04 (`S4/specialization/callable_binder.rs`) and in the typed-trees crate (`TT/callables/static_operand_binding/`). Contract refinement between a callback or implementation and its requirement is now a proof the kernel accepts (a "conformance witness": a machine with the requirement's contract whose body is one call of the implementation), not a comparison of rendered text.
- A large block is refused wholesale: inline assembly, interrupt installation, quotient data and `Quotient::lift`/`define`, propositions and evidence arguments, `operator`/`proposition`/`measure` declarations in the package being checked, machine-owned data, data with an erased field, and carry lists. The old rules for these have no construct to apply to today.
- The most worrying "not found" is R2: I found no declaration-time refusal of two machines (or two trait requirements) with the same callable identity. A call is refused only when its argument types select more than one machine, so a duplicate nobody calls, or one called through a path where selection gives up, appears to be accepted.
- `ProofOnlyClassification::classify` (`TT/proofs/evidence_and_inspection.rs:463`) still computes which data is proof-only, but nothing calls it. The constructs it guarded are refused by the type reader instead, so I count R91 as refused, not lost. It is dead code that looks like a check.
- Several rules are enforced through `refuse` ("not supported yet") where the specification makes the program wrong, not unsupported: `[copy]` data with an owned field (`S5/read/places.rs:485`) and a runtime read of an erased binding (`S5/read/expressions.rs:483`; stage 05 README finding 34 says so itself). The program is still not accepted, but the user is told the wrong thing.
- The theorem-citation rule (R16) has no counterpart because the current compiler erases no call: a call of a Unit machine is an ordinary call that runs.

## Unclear and not looked up

**Unclear** (related code found, verdict not reached):

- R7, compiler-owned x86 primitives keep their exact declaration. The old flag-by-flag test is gone. A primitive is now recognised only as the exact bundled file bytes plus declaration name (`source-to-psi/representations/source-files/bundled-declarations/src/core_vocabulary.rs:112-140`) and through `compiler_primitive_schema` (`TT/definitions/compiler_intrinsics.rs:26-67`). I did not confirm what stage 05 does with a call of the descriptor-table, segment or task-register primitives; the extent bounds (1..=8192, 2..=8192) appear nowhere in the source compiler.

- R48, the scope order for operator meaning. Selection is now "one candidate, or ambiguous, or builtin" (`S3/operator_calls.rs:61-104`). I could not tell whether the old order (trait scope, bound trait, selected trait, declared) is kept inside `resolve_spelling_for_operands`.
