What stands out:

1. Ownership did not disappear with the old checker. It is one walk over the lowered program, `plain_affine` in the Psi semantics crate. Stage 05 runs it to plan cleanup (`S05/lib.rs:2020`), and stage 06 runs it again to check the plan and the claim rows (`S06/verdict.rs:1070`, `S06/minted.rs:768`). The six copies of use-after-move in the old code are one function now (`PA:4282-4307`).
2. Most ownership refusals carry the reason `Unsupported`, which the user sees as "not supported yet", and not a statement that the program breaks a rule. A program that leaves a linear value unconsumed at a return is refused (`CL:134-141`), but with the same wording as a construct the compiler has not reached yet. The exceptions are use after move (`Unestablished`, `PA:38-49`) and overwriting a live linear value (`Violation`, `S05/lib.rs:2105-2113`).
3. The one real gap I found is in R13. While an owned value is moved out of `&mut` storage, the old code refused boundary calls, service calls and blocking calls. The current walk refuses only a call that may suspend (`PA:2457-2477`) and any use of the vacant storage itself. I found no check on a boundary or blocking call that does not name that storage, and `wiki/spec/language/ownership.md:248-249` says those fences "remain in force".
4. The range rules have no counterpart file. Every index and window owes an `OperationSafety` obligation (`S06/minted.rs:897-935`) that one prover decides with a kernel-checked certificate. Facts are rows about values, available where their program point dominates the use (`S06/graph.rs:253`), so "retire a fact on a write" (R55) has no code to compare: a write creates a new value and the old rows stay true of the old one.
5. Three whole areas are refused before any rule applies: machines with more than one state (`S05/read/machine.rs:1509-1515`), assembly (`S05/read/machine.rs:4383-4394`) and termination under a progress premise (`S05/read/machine.rs:3826-3831`). That removes R50, R64, R30, R76 and R78 as live questions for now, and they return when those constructs are served.
6. One old behavior was dropped on purpose and I agree with it: the old code took every `c[i]` in a `requires` as in bounds (R51, second half, which the synthesis lists as a suspected defect). The current checker proves the index of a clause before the clause supplies a fact (`S06/formation.rs:620-640`, test `T06/indexed_contracts.rs:183`).

## Unclear and not looked up

**Unclear** (I found related code and cannot tell whether the rule holds):

- **R17, R18, R19** (every return gives the same source for each claim path; a forwarded input keeps the caller's claim identity; a path absent from the callee's outcome map owes nothing). The current design has no outcome maps. A call takes the caller's claims (`CL:858-880`) and its result gets fresh identities (`CL:770-791`); each return's rows must equal what the returned place holds (`CL:1257-1268`), and the set of result paths must match the declared type (`CL:1378-1389`). I think these three rules were consequences of the old identity scheme and are replaced, but I did not prove that no program depends on a claim keeping its identity across a call.
- **R27** (overwriting a stored loan descriptor ends the loan under four conditions). Related: `S06/places/loans.rs`, tests `T06/stored_references.rs`, `T06/stored_views.rs` and `T06/borrowed_restoration.rs` `a_field_replacement_keeps_the_old_loan_during_rhs_evaluation`. I did not check the four conditions one by one.
- **R31** (content conservation). No stage from 03 to 07 produces a `TransformContent` operation or mentions `ContentTransformation` (grep), and the prover refuses a conservation goal (`S06/prove.rs:2060`, "goal form outside this prover"). The validation code exists only for the native compiler's input (`psi/semantics/src/content_transformations.rs`). So I believe a source program that needs this is refused, but I did not find the reader site that refuses the source form.
- **R32** (boundary custody of backing addresses). Related: `S06/places/backing.rs`, `psi/semantics/src/content_transformations/boundary_correspondence.rs`, receipts at `CL:885-907`. I did not confirm the one-to-one address test.
- **R40** (an observed Boolean proves a float predicate only if both reduce to the same term). Related: `S06/prove/ieee_float_order.rs`, `S06/prove/float_meaning.rs`, refusal `S05/read/contracts.rs:703`. Not compared in detail.
- **R41** (an operator `requires` is known false only from an exact evaluated `false`). A closed false comparison is `NoDerivation` and rejects the call (stage 06 `README.md:143`). I could not tell whether anything else now treats a requirement as known false for crash routes.
- **R52, R53** (a bound for a loop counter at the loop head; chains of `requires` bounding a counter). These add proving power and refuse nothing. State loops are refused (R50). For call-cycle loops stage 05 says "nothing here infers a loop invariant" (stage 05 `README.md:1122-1123`), yet stage 06 infers input conditions for private members (`S06/entry_inputs/recursive.rs`) and chains orders (R60).
