Paths are shortened: `s05/` is `source-rust/subsystems/compiler/source-to-psi/pipeline/05_prepared-typed-trees-to-lowered-program/src/`, `s06/` is `.../pipeline/06_lowered-program-to-checked-program/src/`, `s02/` is `.../pipeline/02_syntax-trees-to-symbol-resolved-trees/`, and `sem/` is `source-rust/subsystems/compiler/psi/semantics/src/`.

What stands out:

- **I found no rule that is silently unenforced.** Three of the four "not found" rules were ways the old checker could accept a program (float routes, known array runs, deferral for target constants). Without them the current compiler rejects the program, because an unproved obligation is a compile error (`s06/README.md` "The route's verdict"). The fourth, R20, is the one to look at.
- **R20 is now the opposite rule.** The old checker gave a storage read no domain membership from its declared type. The current one requires a field read to carry exactly the field's declared domains (`sem/scalar_qualifications.rs:415-453`). That is sound only if every operation that stores into such a field is checked, which is the design the old code used for ranges (R67).
- **The domain rules (R11-R31) are no longer route ladders.** A domain is part of a value's declared type. Two validators in `sem/` check every transfer (argument, result, store, return, cast), one flow analysis follows memberships through storage, and a domain's predicates become ordinary `requires`/`ensures` clauses that the prover and proof kernel decide. The two validators and the flow analysis decide by their own yes or no, with no certificate, and stage 06 reports their failures as `ForeignIdentity`, a compiler fault (`s06/formation.rs:70-130`). The program-facing error has to come from stage 05's typing (`s05/read/rejections.rs`).
- **Several rules hold "by construction".** By that I mean no check exists because the lowered form cannot express the violation: a fact names an immutable value, never a place, so a later write cannot make it stale (R2, R3, R41, R44, R52, R64).
- **Ten rules are refused wholesale**, mostly the proof surface: evidence arguments, named propositions, assembly, case tests in machine contracts, machines with several states, recursion outside terminal position.
- **The stage 05 README is behind the code on domains.** It lists "type constrained by a domain that is not one arithmetic policy" as refused; the code serves declared domains (`s05/read/predicates.rs`, `s05/read/casts.rs:403-607`). I classified from the code.

## Unclear and not looked up

Nothing was left unlooked. These seven I found related code for and could not settle.

- **R9, cleanup prerequisite at a call.** Generated cleanup calls owe ordinary `CallRequirement` rows (`s06/owned_cleanup.rs:1-2`; `s06/lib.rs:2223-2235`). I did not confirm that this is the old rule and not only cleanup on scope exit.
- **R32, a boundary obligation must not be refuted at an exit.** The old check passed "unknown". Now boundary memberships are validated (`sem/membership_facts.rs:1142-1250`) and a boundary call that needs a structural qualification proof is refused (`s06/call_contracts.rs:545-552`). That looks stricter, but I could not map it one to one.
- **R40, `result.len` relations.** Fixed-array lengths are decided (`s06/tests/array_lengths.rs:31, 53`). I did not find the rule for slices selected through `match` arms.
- **R43, content conservation.** `old(...)` terms exist (`s05/read/contracts.rs:1702`), and boundary content guarantees are refused (`s06/call_contracts.rs:560`). I did not trace an accepted program.
- **R46, transparent propositions.** A proposition fact is refused (`s05/read/contracts.rs:264-268`), while a transparent mathematical predicate called in a premise is unfolded and proved (`s05/read/mathematics.rs:138-140, 248`). Which of the two the old rule's programs use, I cannot tell.
- **R49, an activation claim may not be returned.** `sem/storage/activation_storage/flow.rs:534` refuses an owned claim entering another activation, and publication runs that validator (`source-to-psi/representations/checked-program/checked_program.rs:332`). `s06/operational.rs:347-350` says a resource claim "is refused before it could be live here". Stage 05 emits no claim operation. I found no check worded as "returned".
- **R59, carry permission and origin requirements.** No such fact kind in stages 05 or 06. Carry policy is judged at suspension crossings (`s06/operational.rs:340-350`).
