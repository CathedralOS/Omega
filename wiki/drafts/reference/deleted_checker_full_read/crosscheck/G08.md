Paths are abbreviated. `S05/` is `source-rust/subsystems/compiler/source-to-psi/pipeline/05_prepared-typed-trees-to-lowered-program/` and `S06/` is `source-rust/subsystems/compiler/source-to-psi/pipeline/06_lowered-program-to-checked-program/`. ## Summary

Counts: **Enforced 40**, **Refused wholesale 12**, **Not found 2**, **Unclear 6**. I classified 60 of the 66 inventory rows. I skipped six as the old code's internal mechanism rather than language rules: 47 (backward entry-identity walk), 57 (rebuilding the boundary operator application), 74 (unit-propagation prover), 75 (entry path conditions in DNF), 76 (interval narrowing) and 78 (float result-adapter audit, which production never ran).

The current compiler covers the core contract rules through obligations that the proof kernel must accept. These rules are call `requires`, `ensures` at every exit, crash coverage at sites and calls, operation safety, data and domain clauses, loans, cleanup `requires` and payload access. The whole named-evidence and outcome-guarantee family is refused rather than checked: named contract bindings, evidence forwarding, proof-output packages, outcome-specific `ensures`, `when` proof selectors and static named-witness dispatch. The refusal comes from one place for each piece, mainly `S05/src/read/machine.rs:3569-3575` and `:3627-3631`. Stage 05 never reads the typed trees' `proof_output_calls` or `evidence_forwardings` tables. A program that uses those tables is still refused, because every proof-output callee and forwarding target carries a named `ensures` binding, which the signature reader refuses. That refusal is indirect, so it deserves a direct test.

The only rules I could not find are the inferred capability-flow verbs and the "byte known to be 0 or 1 reads as `bool`" inference. Neither appears to be a written language rule today. The more worrying item is Unclear row 58. `complete_operator` returns without a check when an operator expression has no recorded selection occurrence (`S05/src/read/source_operators.rs:446-482`). That repeats the old "a missing record counts as builtin" pattern, if typing can leave such an expression unrecorded.

## Unclear and not looked up

Unclear:
- **28. A qualified type argument makes the caller owe its domain on the actual.** A generic check form refuses a domain on a type parameter (`S05/src/read/types.rs:1157-1163`, `:1365`). A specialization at a qualified type would presumably turn the domain into entry `requires` (row 68). But type parameters are served "only where `T` is a scalar type" (`S06/README.md:1695-1700`), and I did not trace a specialization at `u8 in D`.
- **34. Loans stay live until the cleanup hook runs.** Cleanup actions run through the storage walk with real edge epochs (`S06/src/places/cleanup.rs:1-30`). I did not confirm that a loan on a value disposed through cleanup is held live until that action.
- **38. Public contract identity covers supply, services, termination and crash interface; nominal uses must match.** I found related checks: nominal calls are authenticated (`S06/src/nominal_calls.rs:1-30`) and template commitments are compared (`S06/src/static_reach.rs:262-282`). I could not tell whether every component the old fingerprint covered is part of today's identity.
- **45. An operator use with `crashes` needs an exact operand capture; a route is removed when proved false; a statement-form named operator call with crashes is refused.** An operator's declaration is read "by the same path" as a call (`S05/src/read/machine.rs:1557-1561`), so crash coverage at calls should apply. I found no specific handling of operator crash routes, and nothing on the statement-form refusal.
- **54. Qualification origins are classified and a cast commits its policy domain.** `as +D` owes the clauses as an `ArrivalInvariant` (`S05/README.md:1330-1340`), and `S05/src/qualifications.rs:1-30` publishes establishment routes. I found no counterpart to the per-callee origin classification.
- **58. Builtin laws only when the operator's selection is builtin, never from a missing record.** `complete_operator` (`S05/src/read/source_operators.rs:446-482`) checks every recorded `Operator` selection. When an expression has no such occurrence, `pending` stays false and the function returns `Ok(())` with no check. If typing can leave an operator expression unrecorded while the reader lowers it with builtin meaning, this repeats the old defect. I did not trace whether typing always records one.
