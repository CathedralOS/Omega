The current compiler does not contain a structural judge. Stage 05 reads source into a lowered program and refuses what it cannot read; stage 06 states each obligation as a proposition over single-assignment values and accepts it only when the proof kernel accepts a certificate (`R6md:3-16`, `S6/verdict.rs:891`). So most rows map to a different mechanism, not to a copy of the old one, and "Enforced" here means "I found the check that now decides the same question", usually by locating the function a README names; I did not trace each check end to end.

Every one of the 15 "not found" rows is a rule that gave the old judge an extra fact or an extra way to accept (ring rearrangement, body-derived result fields, shared values for repeated calls, the constant-Boolean fallback, placement geometry). Their absence makes today's compiler stricter, not looser: a program that needed one is `Unproved` or refused. I found no row where the old code restricted programs and the current compiler neither checks nor refuses.

Three things stand out. First, two of the synthesis's suspected wrong-accepts are gone by construction: the caller no longer learns `result == true` from a callee whose `requires` failed (R24), and a window now owes `start <= end <= N` (`S5/read/arrays.rs:406-410`). Second, the current clause reader does look through a shared stored reference (`S5/read/contracts.rs:2476-2489`), where the old rule R56 was "nothing looks through a reference"; I could not tell whether loan tracking makes that safe, so it is listed as unclear. Third, the old distinction between a refuted and an unprovable `ensures` (R120) is deliberately gone: the verdict "never [says] that the obligation is false" (`R6md:1253-1257`).
