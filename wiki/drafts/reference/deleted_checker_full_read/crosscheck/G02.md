## Summary

Counts over the 55 language rules (inventory rows 15-69; row 70 is stage-05 prose outside this group and row 71 is bookkeeping): **Enforced 33, Refused wholesale 9, Not found 4, Unclear 9**. Row 70 is listed as not looked up.

Most of the old build-time rules now hold, but a different mechanism enforces them. The current compiler turns each constant initializer, const argument and computed array length into a generated zero-argument machine (`CTI/constants/arguments.rs:206-226`). It turns each build-time call into a generated caller with the arguments written as literals (`CTI/calls/typed_call.rs:1-2`). Ordinary stages 03-06 check that machine (`CTI/calls.rs:235-253`). `ADM:105-218, 840-864` then applies the evaluation floor: termination, no linear carrier, no services, no suspend or block, selection authority and crash freedom. The Terminal interpreter runs the result under the 100,000-unit budget (`build/evaluation/scalars/receipts.rs:5`, `CTI/calls/execution.rs:351-367`). A fast exact folder in stage 02 (`S02`) handles closed scalar constants and const arguments. It refuses out-of-range values, division by zero, bad shifts, inexact anonymous landings, cycles and private cross-package selections.

Several constant-only restrictions are gone because the spec now says ordinary rules apply. Examples are "builtin operator meaning only", "casts only widening" and "array length by a zero-argument call" (`wiki/spec/language/evaluation.md:84-98`, `constants.md:26-29, 42-46`). I classify the first two as enforced in their spec form.

The four rules I did not find are the domain-fact machine signature, the Build-selected provider body rules (no `crashes`, matching signature, non-generic, one conformance), the stability of runtime index descriptors, and the determined storage type of a match subject. Of these, the provider-body rule is the most likely real gap.

One old pattern survives: an evaluated const argument is still written back into the type table as a name with no symbol, `Named { symbol: invalid, name: "<digits>" }`, and parsed back from that text (`source-to-psi/representations/typed-trees/type_records/data_applications.rs:103-109`, `source-to-psi/representations/typed-trees/expressions/values.rs:73-77`).

## Unclear and not looked up

**Unclear**

- **Row 18, a length computed by a call needs a zero-argument machine.** Today any closed expression, including a call with arguments, becomes the body of a zero-argument `@array-extent` machine (`CTI/constants/arguments.rs:214-222`). The old restriction no longer applies, and the spec does not state it (`constants.md:26-29`). I cannot tell whether that change was intended.
- **Row 38, `size_of`/`align_of` refuse proof-only types, unresolved extents and const expressions.** Unresolved carriers are refused (`S05/read/calls.rs:1126-1128`). I did not establish what `value_type` does with a proof-only type.
- **Row 40, float part: a float constant must be exactly representable.** The spec now says floating landing rounds (`constants.md:44-45`), so the old rule seems superseded. Casts still demand exactness (`S05/read/casts.rs:195`).
- **Row 48, schema reflection.** Quotients are refused (`source-to-psi/representations/typed-trees/definitions/declaration_reflection.rs:1309`). Recursive storage is now admitted as a graph with a self-edge (same file, test at `:1669-1720`). The field-key collision rule has no subject, because keys are now positions (`CTI/fixed_layouts/reflection.rs:40`).
- **Row 54, explicit lifetime arguments on a conformance agree with the call's borrows.** Related code: `source-to-psi/representations/typed-trees/type_records/type_identity.rs:7216`. Not traced.
- **Row 58, cleanup, domain, `dyn` and operator-provider tuples are complete and of the right arity.** Domain arity is enforced (`S02/domains.rs:324`, `source-to-psi/pipeline/03_symbol-resolved-trees-to-typed-trees/src/type_reference.rs:228`). I did not look up cleanup, `dyn` or operator providers.
- **Row 59, a finite-family provider binds exactly the requirement's const binders.** `S05/read/contracts.rs:2593-2604` admits a different set of binder kinds (type, const, machine), so this seems to be a different concept.
- **Row 62, user operators, match-by-equality and range indexing.** Range expressions are refused wholesale (`S05/read/expressions.rs:857`). Value patterns are read at `S05/read/expressions.rs:1200, 1478`. I did not check the wildcard requirement or the binary/indexed-only rule.
- **Rows 68-69, `build.omg` requests and the three build-time jobs that were refused.**
  - Assumed bindings are refused wholesale in package review (`build/planning/package_review/policy.rs:50-52`) and in evaluation (`ADM:128-139`).
  - Executed requests are matched against their declared occurrence (`source-to-psi/driver/compile_product/declaration_lookup/authored_requests.rs:144`), and composition mode is read (`source-to-psi/driver/compile_product/provider_choices/authored_defaults.rs:148`).
  - Layout and access plans now run (`CTI/fixed_layouts/`, `CTI/domain_access_plans.rs`), so two of the three jobs are no longer refused.
  - Wire schemas with an encoding are refused (`CTI/frontier.rs:104-113`).
  - I did not check provider uniqueness, test-group registration or native-binding uniqueness.

- Explicit static arguments compared with inferred ones (an old defect at CC:1581-1602). I did not check whether typing now compares them.
