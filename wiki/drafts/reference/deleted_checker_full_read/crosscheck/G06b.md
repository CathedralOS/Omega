# Cross-check G06b

## Summary

Of the 87 inventory rows: **Enforced 52**, **Refused wholesale 8**, **Not found 0**, **Unclear 11**. I skipped another **16** rows as the old planner's internal bookkeeping or plan-shape limits rather than language rules: R4, R9, R10, R12, R14, R15, R27, R29, R32, R37, R41, R45, R46, R50, R55 and R63. Every row was looked up, so the "Not looked up" list is empty.

The old planners decided these rules silently, by returning `None`. Today two places decide them in the open. The stage 05 reader rejects violations by name with `reject(...)` (`Violation`). The stage 06 checker refuses with `Conflict`, `Unestablished` or an unproved obligation. Four mechanisms in the current tree cover most of the old planners' ownership and loan rules (R42-R58), each in one place rather than per producer kind:
- the stage 06 loan judgment (`places/loans.rs`: `competing_borrows`, `ChangeWhileBorrowed`, `ReleaseBeforeChildren`);
- the affine-ownership replay (`psi/semantics/src/plain_affine.rs`);
- the payload-access walk;
- the dispatch roster check (`places.rs`).

The state-graph half of the old code (fusing several states into one graph, edge arguments between states, R64 and R87) has no counterpart. The reader refuses every machine with more than one state (`read/machine.rs:1513`). Calls between machines become calls, or loops when they form a cycle. The weakest spots are the Unclear rows on cleanup scheduling (R52-R54, R59) and scalar-field interval restriction (R83). I found related machinery for each of them, but no check that clearly matches the old rule.

The stage 05 README is out of date. It still says references, slices, floats and domains are refused, but `read/references.rs`, `read/arrays.rs`, `read/bytes.rs`, `read/float_meaning.rs` and the domain path in `read/types.rs` now serve them. I classified every row from the code, not from the README.

Paths below are relative to `source-rust/subsystems/compiler/source-to-psi/pipeline/`, with `05/` = `05_prepared-typed-trees-to-lowered-program/` and `06/` = `06_lowered-program-to-checked-program/`. `psi/semantics/` means `source-rust/subsystems/compiler/psi/semantics/`.

## Unclear and not looked up

**Unclear (11):**
- **R13 float operations.** The old rule refused pure float operations. Today same-format float arithmetic is served, and mixed formats are rejected (`05/src/read/expressions.rs:2066-2084`). The old rule was a limitation, so nothing has been lost, but I did not check how float values reach stores.
- **R33 returned formal keeps access, qualifications and linear claims.** Qualifications are kept (`06/src/tests/structural_domains.rs:494`). Linear claims are published by `psi/semantics/src/plain_affine/claims.rs` (`publish_contract_claims`). I did not confirm that a returned linear formal must give back exactly its entry claims.
- **R52, R53 anonymous-owner cleanup and the single whole release.** The cleanup frontier in `psi/semantics/src/plain_affine.rs` (discard actions near 2652, 2837-2874, 3601-3616) is related, but I did not find a check that matches "exactly one whole release".
- **R54 every pending release can be scheduled at exit.** The current producer places reference ends (`05/src/reference_ends.rs:127-239` refuses an end with no boundary). I did not find a scheduling check in stage 06; `06/src/places/cleanup.rs` checks the order of cleanup actions.
- **R59 a Unit return drops unmoved owned affine parameters.** This is probably the plain_affine exit frontier, but I did not confirm it.
- **R72 a state `requires` lowers to a closed predicate under a budget.** Contracts on states are refused (R73). I did not check whether lowering a domain requirement has a budget.
- **R80, R81 admitted result and contents kinds.** The supported kinds now differ (references and views are served). I did not find one admission function to compare against the old one.
- **R83 scalar field restriction intervals (intersect, clamp, 64-bit fit, empty range).** `scalar_restriction` exists (`06/src/minted.rs:99`, `05/src/lower/places.rs:836`), but I did not find the interval arithmetic. This row could be unenforced. It could also be moot if interval-restricted fields are refused upstream (`05/src/read/types.rs:382` refuses `Constrained` type references on one path), but I could not confirm which.
- **R87 machines fused into one graph by recursion, moved claims or overlapping borrows.** Call cycles are found and lowered as loops (`05/src/components.rs`, `05/src/components_graph.rs`). I found no fusion triggered by moved claims or overlapping non-shared borrows. In the current design those calls stay ordinary calls checked by the loan judgment, so this is probably a design change rather than a lost rule.
