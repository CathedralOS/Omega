## Summary

Of the 89 inventory rows, 9 are the old planner's own bookkeeping and are skipped (L41 rebuild-and-compare, L43 call-fact coordinates, L46 target resolution order, L64 structural result content classes, L65 signature erasure, L69 reborrow value identity, L70 `&mut` local erasure, L102 successor argument positions, L103 declaration ABI storage). Of the 80 language rules:

- **Enforced: 52**
- **Refused wholesale: 9**
- **Not found: 3**
- **Unclear: 9**
- **Not looked up: 7**

The old planners re-decided ownership, borrow and cleanup rules. Today those rules are checked in three places. Stage 05 rejects type and access errors as it reads source (`reject`, `Unserved::Typing`). The Psi semantics crate verifies affine and linear custody: `plain_affine::verify_in`, called from `S06/src/verdict.rs:1070`, and `owned_structure::validate_claim_transfers` at `S06/src/minted.rs:603`. The stage 06 checker proves contract and bounds obligations with the kernel (call requirements, index bounds, cleanup-hook `requires`, rankings). Where the old code compared stored fingerprints, the current compiler proves the claim.

Several rules are now stricter or changed:
- A record literal that omits a field is refused, not zero-filled.
- A `terminates by` rank is proved statically rather than observed at run time, and authored measure bodies are refused.
- A cleanup hook now takes the value owned, not through an exclusive reference.
- A refusal anywhere refuses the whole compilation, which replaces the old transitive body-dropping.

Two old surfaces, descriptor-table operations and activation-storage Establish/Split/Release, have no source route into the current compiler at all. Nothing in stage 05 produces them; the native compiler and the Psi validator know the operations. The one rule that may really be unenforced is L44: a call inside a transition guard may not complete a transition arm.
