A FIELD GUIDE FOR THE AGENT ERA

Learn to read
Omega

Omega is a proof-checked systems language whose programs are data-oriented state machines. There is no if statement, no loop keyword, and no implicit self: a program is explicit states, exhaustive transitions, fixed-layout data, and contracts the compiler refuses to guess.

In practice, an agent will write most of your Omega. Your job is to specify the state graph, data bounds, and service reach up front, and to know when to send the agent's work back.

CHAPTER I

A Program Is a Machine

An Omega program has no main function and no ambient OS access. It starts in a machine that declares which outside services it reaches.

The smallest whole program

1use omega::​language::​core::​process_exit;1
2use omega_language_std::​process_exit;
3use omega_language_std::​console;2
4
5machine start() reaches Console + ProcessExit {3
6Console::​write_line("Hello, Omega.");4
7ProcessExit::​exit_process(0);5
8}
1

Process exit is its own boundary service, ProcessExit, separate from printing. The first two use lines bring in the contract and its standard-library binding.

2

Brings in the Console boundary trait. build.omg selects the platform provider that answers it.

3

machine declares a state machine with no implicit state or self. reaches Console + ProcessExit is its service ceiling: without that clause, it cannot touch the outside world.

4

Console::write_line calls the boundary contract statically. The source never names a platform handle or syscall.

5

ProcessExit::exit_process(0) terminates the process domain with status 0. Printing never implies permission to exit, so the signature names both services.

What the supervisor reads

Review agent-written Omega in three passes: first the reaches clause (what outside services it can touch), then the data declarations (what memory it owns and its bounds), and finally the state graph (how control moves). If those three are honest, the implementation inside each state is boxed in by the checker.

Capabilities first, data layout second, state transitions third. Every review in this guide follows that order.

CHAPTER II

States, Not Ifs

Omega has no if, while, or for statements. Branching and looping are explicit state transitions without hidden call frames.

A guard picks the next state

1machine choose(flag: bool) -> u64 {
2transition flag {1
3true -> yes()
4_ -> no()2
5}
6state yes() -> u64 { 70u64 }3
7state no() -> u64 { 71u64 }
8}
9
10machine main() -> u64 { choose(true) }4
1

transition evaluates its subject once and jumps to the matching state. Internal state jumps transfer control directly without pushing a call frame.

2

_ covers every remaining value. Transition arms must be exhaustive so every path has a proven destination.

3

A state is a named control point inside the machine with its own parameter frontier, not a closure that captures surrounding locals.

4

A machine that holds no persistent state needs no data declaration. Its inputs and return type are its entire interface.

A state that jumps to itself is a loop

1machine countdown(n: u64) -> u64 {
2transition n > 0u64 {
3true -> tick(n)
4_ -> n
5}
6state tick(n: u64) -> u64 {
7let next: u64 = n - 1;1
8transition next > 0u64 {2
9true -> tick(next)3
10_ -> next
11}
12}
13}
14
15machine main() -> u64 { countdown(5u64) }
1

Unsigned n - 1 is legal here because the incoming guard proved n > 0 before jumping to tick. Remove the guard and exact-arithmetic checking rejects the subtraction.

2

A state only sees its own parameters and the facts carried across its incoming edge, so tick tests next > 0 explicitly before looping.

3

tick(next) jumps back to tick with a smaller argument. Cycles in the state graph replace while and for loops.

When reviewing a loop, check two things: the guard that proves the step cannot underflow, and the value that strictly decreases on every back-edge.

Reading the graph

Ask the agent for the state list and transitions before asking for code. Good state names describe stages of the domain workflow (scan, wipe, done); vague names (step2, helper, process) mean the control flow has not been designed yet.

State names are the cheapest design review you can run, and the fastest way to catch a muddled machine.

CHAPTER III

Fields Are the Memory

Machines do not own hidden fields. Persistent state lives in explicit data declarations with fixed layouts and is passed in by value or reference.

The data block is the data model

1data Room {
2label: [u8; 4];1
3}
4
5data Level {
6rooms: [Room; 2];2
7ticks: i32 in Wrapping;3
8}
9
10machine rename(level: &mut Level) {4
11level.rooms[1].label[0] = 82; // 'R'5
12level.ticks = level.ticks + 1;
13}
14
15machine main() {
16let mut level: Level = Level {6
17rooms: [
18Room { label: "room" },
19Room { label: "hall" }
20],
21ticks: 0,
22};
23rename(&mut level);
24}
1

[u8; 4] is a fixed-length array of four bytes stored inline. Capacity is part of the type, not a runtime allocation.

2

[Room; 2] nests two Room records contiguously inside Level. Every byte of Level is accounted for at compile time.

3

i32 in Wrapping qualifies the field with modular two's-complement arithmetic, allowing level.ticks + 1 without an upper-bound proof.

4

&mut Level lends mutable access to level for the duration of the call. There is no implicit self parameter.

5

Constant indices 1 and 0 are statically in bounds against [Room; 2] and [u8; 4], so the checker discharges both array bounds automatically.

6

Record construction initializes every field explicitly. let mut permits mutation, and &mut level borrows the storage in place.

If an agent starts threading five loose parameters through every state, stop and have it group that state into a data record with explicit field types.

CHAPTER IV

Choice Is a Value Too

Sum types are data declarations with case members. You inspect them through exhaustive transition dispatch, and payloads can carry their own where invariants.

Three cases, one value

1data Phase [copy] {1
2case Red;2
3case Green;
4case Yellow;
5}
6
7data Light [copy] {
8phase: Phase;
9advances: i32 in Wrapping;
10}
11
12machine next(phase: Phase) -> Phase {
13transition {3
14phase == Phase::​Red -> Phase::​Green
15phase == Phase::​Green -> Phase::​Yellow
16_ -> Phase::​Red4
17}
18}
19
20machine advance(light: Light) -> Light {
21Light {5
22phase: next(light.phase),
23advances: light.advances + 1,6
24}
25}
26
27machine main() {
28let light: Light = Light {
29phase: Phase::​Red,
30advances: 0,
31};
32let once: Light = advance(light);
33let twice: Light = advance(once);
34let again: Light = advance(light);7
35}
1

Owned data is affine by default (move at most once). Marking a pure value type [copy] makes it unrestricted so passing it does not consume the binding.

2

case Red; declares one variant of Phase. A Phase value is always one of its declared cases.

3

Guard-list transition { ... } tests boolean conditions in order and evaluates only the chosen arm.

4

The _ fallback completes exhaustive coverage and returns Phase::Red when phase is Yellow.

5

Omega has no struct-update shorthand (..old), so advance constructs the new Light with every field named.

6

Because advances carries i32 in Wrapping, the addition uses modular wrapping semantics automatically.

7

light was already passed on line 32, and [copy] lets line 34 use it again. Without [copy], the checker rejects the second use because a moved affine binding holds no value.

Value-position match is only for comparing plain scalar values. When branching on case shapes or extracting payloads, use transition dispatch.

Cases carry cargo

1data Reply {
2case Hit(value: i32) where value in 0..=255;1
3case Miss;
4}
5
6machine read(reply: Reply) -> i32 {2
7transition reply {3
8Reply::​Hit { value } -> keep(value)4
9Reply::​Miss -> miss()
10}
11state keep(value: i32) -> i32 { value }
12state miss() -> i32 { 0 }
13}
14
15machine main() -> i32 {
16let reply: Reply = Reply::​Hit { value: 66 };5
17read(reply)
18}
1

A case-local where clause attaches an invariant to that variant's payload. Constructing Reply::Hit requires proving value in 0..=255; matching Hit recovers that fact.

2

Subject-form transition reply dispatches on the active case of reply. Every declared case must be handled.

3

Reply::Hit { value } destructures the payload by field name and passes value into keep(value) along with its 0..=255 range fact.

4

Reply::Miss has no payload fields, so the variant path alone matches it.

5

Case construction names the payload field explicitly (Reply::Hit { value: 66 }), and the literal 66 satisfies 0..=255 at compile time.

Standard-library ByteRead uses this exact pattern: case Eof; and case Byte(value: i32) where value >= 0 && value <= 255;.

CHAPTER V

Writing for the Prover

Default integer arithmetic is Exact: every operation, index, and narrowing cast is a proof obligation. If the checker cannot prove a step fits, compilation stops.

Contracts are part of the signature

1machine bounded(input: u16) -> u16
2requires input <= 255u161
3ensures result <= input2
4{
5transition { _ -> finish(input) }3
6state finish(saved: u16) -> u16 { saved }
7}
1

requires states a precondition the caller must establish before invoking bounded. It is checked statically at the call site, never turned into a runtime assert.

2

ensures states the postcondition guaranteed on normal return, using the reserved name result for the returned value.

3

Flow facts travel across state transitions: finish receives saved knowing it equals input, which discharges result <= input.

When the prover refuses an expression, do not fight the syntax. Tighten a precondition, hoist an intermediate value into a guarded transition, or declare an explicit overflow policy.

An empty body is a claim

1machine less_than_transitive(a: u64, b: u64, c: u64)
2requires
3a < b1
4b < c
5ensures
6a < c
7{
8}2
1

Multiple requires rows combine as premises that hold on entry.

2

A machine with an empty body is a pure compile-time lemma: the checker must derive a < c directly from a < b and b < c.

samples/cli/proofs/math_proofs builds an entire chain of arithmetic lemmas this way, without emitting a single runtime instruction.

CHAPTER VI

The Boundary Wall

Machines never call OS syscalls or globals directly. Every external effect crosses a boundary trait, appears in reaches, and is wired to a provider by the build.

Reach is declared, then checked

1use omega::​language::​core::​process_exit;
2use omega_language_std::​process_exit;
3use omega_language_std::​console;
4
5machine start() reaches Console + ProcessExit {1
6Console::​write_line("through one wall");2
7ProcessExit::​exit_process(0);3
8}
1

reaches Console + ProcessExit is a conservative upper bound on the external services this machine (and anything it calls) may touch.

2

Console::write_line targets the portable Console contract. A desktop build, a serial UART, and an in-memory test harness all satisfy the same call.

3

Hosted ProgramEntry machines do not return an exit status value; they exit explicitly through ProcessExit::exit_process.

Audit reaches first during code review. A sorting helper or parser that asks to reach FileSystem or ProcessExit is a design bug.

A contract, and who fills it

1

2

Requirements can also publish operational envelopes (suspends, blocks, crashes Trap); callers must acknowledge them at the call site with suspend or block.

3

A boundary requirement explicitly names Clock in its own reaches row. The trait name is never added implicitly.

4

5

In source/library/std/console.omg, Console::read_byte declares blocks; crashes Trap; — which is why callers write block Console::read_byte().

CHAPTER VIII

Text Is a Block

Omega has no format strings or heap-grown String in core. Fixed [u8; N] byte arrays and borrowed &[u8] slices make every buffer size and index proof explicit.

Pad it yourself

1use omega::​language::​core::​process_exit;
2use omega_language_std::​process_exit;
3use omega_language_std::​console;
4
5machine clear(line: &mut [u8; 28]) {1
6transition { _ -> scan(line, 0u64) }
7
8state scan(line: &mut [u8; 28], k: u64) {2
9transition k < 28u64 {3
10true -> wipe(line, k)
11_ -> done()
12}
13}
14
15state wipe(line: &mut [u8; 28], k: u64) {
16line[k] = 32;4
17transition { _ -> scan(line, k + 1u64) }5
18}
19
20state done() { }
21}
22
23machine main() reaches Console + ProcessExit {
24let mut line: [u8; 28] =6
25"this text is about to vanish";
26clear(&mut line);
27Console::​write_line(&line[..]);7
28ProcessExit::​exit_process(0);
29}
1

&mut [u8; 28] borrows a mutable 28-byte array. Its static length 28 travels with the type.

2

States do not capture enclosing locals, so scan takes both the borrowed line and the current index k explicitly.

3

The guard k < 28u64 is the bounds proof: on the true edge into wipe, the checker knows k is a valid index into [u8; 28].

4

line[k] = 32 writes ASCII space (0x20). Zero-initialized bytes are NUL (0x00), so fixed-width output buffers are padded with spaces before printing.

5

Because k < 28u64 holds in wipe, k + 1u64 is provably <= 28 and cannot overflow u64.

6

An ASCII string literal initializes a [u8; N] array of the exact matching byte length (here 28 bytes).

7

&line[..] borrows the full [u8; 28] array as a &[u8] byte slice for Console::write_line.

Formatting integers works the same way: divide by 10, take % 10, add 48 ('0'), and write into a space-padded [u8; N] buffer.

CHAPTER IX

--check Is the Floor

omega --check proves type, domain, ownership, and reach contracts. It does not prove your algorithm computed the intended answer — run both the interpreter and native binary.

What the check does and doesn't say

Verification stepWhat it actually establishes
omega --check passesTypes, range proofs, affine moves, exhaustive transitions, and reaches ceilings all hold statically.
omega run --both passesThe Terminal Psi reference interpreter and the compiled native binary execute and agree on the outcome.
Output bytes inspectedStdout bytes, space padding, line endings, and the exit code match the specification.
--check aloneProves the program is safe to run, not that a constant return or wrong formula solved the problem.

Choose test inputs whose expected result can only appear if the state machine genuinely ran its loop.

In the Omega repository, every capability fact row must pass omega run --both (Terminal Psi + native execution agreement), not --check alone.

The exit code is an answer

1use omega::​language::​core::​process_exit;
2use omega_language_std::​process_exit;
3use omega_language_std::​console;
4
5// Expected exit: 70.1
6machine start() reaches Console + ProcessExit {
7let sorted: u64 in Wrapping = 64 + 6;2
8Console::​write_line("ten shelves, sorted");
9ProcessExit::​exit_process(sorted as i32);3
10}
1

Executable samples declare an // Expected exit: N oracle comment at the top of main.omg, and the test harness verifies the exact status code.

2

u64 in Wrapping opts into modular addition, and as i32 converts the computed value for exit_process.

3

Real samples encode their computed result in the exit status (bubble_sort exits with 10, collatz_sequence with 111, and generic_counters uses 3 on failure).

When an agent writes a sample that always exits 0 without checking its computed result against the oracle, send it back.

CHAPTER X

Working With the Agent

An agent can write Omega quickly once the state graph, data bounds, and capabilities are pinned. Your job is to specify those three up front and verify the run.

A brief that produces real Omega

Give the agent a four-part brief before it writes code: (1) the state names and transitions between them, (2) the data records with exact array lengths and range/overflow domains, (3) the allowed reaches services, and (4) the non-trivial expected exit code or output bytes. When the checker rejects a line, require the agent to reshape the state graph or tighten a contract rather than papering over the expression with Wrapping.

Most agent failures come from inventing fields mid-state or slapping in Wrapping onto a loop counter whose termination depends on not wrapping.

Require both omega --check and an actual execution check (omega run --both) before accepting the task.

The review checklist

SurfaceQuestion to ask
reaches ceilingDoes each machine declare only the external services it genuinely needs?
data layoutAre all persistent values stored in fixed-size records with explicit where or domain bounds?
Borrowing (& / &mut)Are parameters borrowed &mut only when the machine actually mutates them?
State frontierDo state names reflect domain steps, and does every loop edge shrink a clear measure?
Transition coverageAre case dispatches exhaustive without silent catch-all arms hiding unhandled variants?
Proof obligationsAre bounds the true domain range rather than arbitrary buffer capacities or lazy Wrapping?
Execution oracleDid the compiled binary run, and do the stdout bytes and exit code match the oracle?

Seven checks. If the code clears all seven and passes omega run --both, the machine is solid.

CHAPTER XI

One Whole Program

Everything in one twenty-line program: it counts the base-10 digits of 2026 across a two-state loop and exits with status 4.

The program, whole

1use omega::​language::​core::​process_exit;
2use omega_language_std::​process_exit;
3use omega_language_std::​console;
4
5// Expected exit: 4.
6machine start() reaches Console + ProcessExit {1
7transition { _ -> count(2026u64, 0u8) }2
8
9state count(n: u64, digits: u8 in Wrapping) {3
10transition n >= 10u64 {4
11true -> count(n / 10u64, digits + 1u8)5
12_ -> report(digits + 1u8)
13}
14}
15
16state report(digits: u8 in Wrapping) {
17Console::​write_line("counted the digits");
18ProcessExit::​exit_process(digits as i32);6
19}
20}
1

Read the capability ceiling first: start may write to Console and terminate via ProcessExit, and nothing else.

2

Setup finishes with an unconditional transition into count(2026u64, 0u8), seeding the loop's initial state parameters.

3

digits: u8 in Wrapping qualifies the accumulator with wrapping arithmetic, and every u8 widens losslessly into i32 at exit.

4

n >= 10u64 partitions the loop: values with at least two digits left continue; single-digit remainders finish in report.

5

The back-edge count(n / 10u64, digits + 1u8) divides n by 10u64 (a nonzero constant divisor), strictly shrinking n on every iteration.

6

Exits with 4 — the four digits of 2026 — matching the // Expected exit: 4 oracle at the top of the file.

Because n and digits travel as state parameters across the loop, the program needs no data block at all.

What the check did not tell you

omega --check proved that 10u64 is a nonzero divisor, digits + 1u8 has a defined overflow policy, digits as i32 is in range, every transition arm lands in a valid state, and only Console and ProcessExit are reached. It did not prove that 2026 has 4 digits rather than 5 — running the binary and checking exit code 4 against the oracle closes that loop.

Static proof guarantees the machine's invariants and safety boundaries; execution against an oracle verifies its domain answer.

END MATTER

Glossary

The core vocabulary used by the Omega language guide, specification, and compiler diagnostics.

machine
A state machine with explicit inputs, an optional return type, and a declared service ceiling (reaches). Entry points, helpers, and loops are all machines; there is no implicit self receiver.
state
A named internal control point inside a machine with its own parameter frontier. Jumping to a state transfers control without pushing a call frame.
transition
The control-transfer statement that ends a setup block or state body. Arms test a subject or guard list and jump to a state or return a value.
guard
A boolean condition or pattern on a transition arm. Guard facts propagate into the target state, and all arms together must be exhaustive.
data
A nominal record or sum-type declaration with a fixed compile-time layout and no hidden fields or default initializers.
case
One named variant of a data sum type (case Red; or case Hit(value: i32)). Inspected exhaustively through transition dispatch.
payload
The fields carried by a case variant, optionally constrained by a case-local where clause (case Hit(value: i32) where value in 0..=255;).
[copy]
Marks a pure value type as unrestricted so passing or assigning it duplicates the bits instead of consuming the binding.
affine
The default ownership multiplicity for data: an owned value may move at most once, after which the old binding holds no value.
reaches
A machine's conservative external-service ceiling, written reaches Console + ProcessExit. Calling a service outside that ceiling is rejected.
boundary trait
A portable external interface declared by machine signatures (public boundary trait Clock). Each member states its own reaches row and any suspends, blocks, or crashes envelope.
provider
A stateless type whose satisfies machines implement a boundary trait for a target or test harness (FakeClock::now satisfies Clock::now).
static boundary call
Calling a boundary requirement directly by trait path (Console::write_line(...)); the build selects the concrete provider for each target.
domain
A zero-cost static theory or policy attached to a value (i32 in Wrapping, Player::Alive), checked at compile time with no runtime tag.
arithmetic policy
The overflow contract on an integer type. Plain integers are Exact (every operation must be proven in range); in Wrapping, in Saturating, and in Trapping select defined overflow behavior.
proof obligation
A static requirement the compiler must discharge — array bounds, exact arithmetic range, exhaustive dispatch, or precondition entailment — before accepting the program.
requires / ensures
Machine contract clauses: requires states preconditions the caller must establish; ensures states postconditions guaranteed about result on normal return.
build machine
machine build(builder: &mut Build) in build.omg: ordinary checked Omega code that declares the package kind, dependencies (Build::depend), and per-target ProgramEntry bindings (Build::bind).
ProcessExit
The core boundary service (ProcessExit::exit_process(code: i32)) that ends the process domain with an explicit status code, separate from Console.
