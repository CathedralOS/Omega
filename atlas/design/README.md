# Atlas design kit

Any model can make an atlas page with this kit, whether that is GPT, Codex or
Claude, without special tools. A page is one static HTML file in
`atlas/pages/` that links `../design/tokens.css`, draws its figures as
inline SVG, and opens in any browser. The architecture overview progressively enhances
its static SVG to a Canvas2D workspace with the same model and a DOM text
outline. This file holds the rules; `tokens.css`,
`tokens.json` and `fonts/` hold the values; `page-template.html` is a page to
copy.

The rules come from the Omega design system (owner's design-system artifact)
and from the diagrams already published in the atlas. The established pages,
`pages/pipeline-map.html` and `pages/foundation-backend-plan.html`, are worked
examples. They and the subsystem maps are generated by `atlas/build_pages.py`
and link `tokens.css`; page styles do not copy token values. The shared
renderer uses explicit node, edge and caption metadata in
`artifacts/diagrams.json` so colors describe a reviewed meaning rather than a
guess from a label.

## The look in one paragraph

Omega looks like masonry. Build every page from flat, square-edged blocks on
`--ground`, separated by space and hairlines, never by shadows. Words are set
in Omega Serif, code in IBM Plex Mono, nothing else. Color carries meaning,
never decoration: green (`--checked`) means proven or passing, red (`--trap`)
means a rejection, a trap or a reach-around. The full architecture map also
uses the named family colors below to distinguish subsystem ownership. The
owner requested this categorical color extension on 2026-11-17; it does not
assign proof status to a subsystem.

## Page contract

- One `.html` file per page in `atlas/pages/`, named for its subject
  (`psi-stages.html`, not `page3.html`). It must open from disk with no build
  step and no network requests; the three Omega Serif weights ship locally, and
  code uses the available monospace fallback.
- Start the file with `<!doctype html>`, `<meta charset="utf-8">`,
  `<meta name="viewport" content="width=device-width, initial-scale=1">`, a
  `<title>` that names the page in two to four words, and
  `<link rel="stylesheet" href="../design/tokens.css">`.
- Use only the tokens for color, type, space and shape. Never write a hex
  value in a page; if a color is missing, it does not belong on the page.
- Both themes must read. `tokens.css` switches them; give `body` an explicit
  `background: var(--ground)`, and give every SVG mark a token color.
- No JavaScript is required. A page may add a small inline script for a
  theme toggle, navigation, diagram selection or a controlled walkthrough.
  The map and its source notes must remain usable without it.
- Running text stays under 68 characters a line. Wide tables and figures
  scroll inside their own frame (`overflow-x: auto`); the page itself never
  scrolls sideways. Check it at 400px wide.

## Voice

- Lead with what the reader can now do or decide and why it matters; put
  evidence after.
- Use real words and define each term once: `expression`, not `expr`.
- Give measured results with denominators: "9 of 9 places pass", not "all
  green". Mark anything not checked *unverified* and every classification
  choice *judgment*.
- Sentence case for headings and labels. No emoji, no exclamation marks, no
  hype words.

## Color

| Token | Use it for |
| --- | --- |
| `--ground` | The page background |
| `--surface` | Panels, code, figures, tables |
| `--ink` | Text and solid marks; realized (Omega) things |
| `--ink-muted` | Secondary text, labels, control and outline edges |
| `--rule` | Decorative hairlines between sections; never the only edge of anything |
| `--checked` | Proven, passing, closed; the checker's verdict |
| `--trap` | Rejections, traps and reach-arounds; keep it small |

The architecture canvas uses these family token pairs, each with an explicit
legend label: `--family-psi`, `--family-native`, `--family-build`,
`--family-runtime`, `--family-library`, `--family-omega-source`,
`--family-bootstrap` and `--family-support`. Each has a `-surface` companion
for its box fill. Family color says who owns the work, not whether a claim was
proved. Selection and keyboard focus use neutral ink. Keep JSON and CSS values
in sync; review both themes and preserve readable text contrast.

Never show status by color alone: pair `--checked` with a word or check mark,
`--trap` with a word or cross. No gradients, no opacity tints, no shadows.

## Type

| Role | Token | Use |
| --- | --- | --- |
| display | `--type-display` | The page title, once |
| heading | `--type-heading` | Section headings |
| subheading | `--type-subheading` | Subsections, tile titles |
| body | `--type-body` | All running text |
| label | `--type-label` (+ `letter-spacing: .02em`) | Status words, counts, captions, eyebrows |
| code | `--type-code` | Code, commands, file paths, on `--surface` |

Use `font-variant-numeric: tabular-nums` wherever digits line up.

## Space and shape

- Space doubles: `--space-2` inside controls, `--space-3` tile padding,
  `--space-4` between groups, `--space-5` between sections. Lay out siblings
  with `gap`, not margins.
- Corners are square (`--radius-stone`). Only buttons and inputs get
  `--radius-chamfer`; `--radius-arch` rounds top corners only. No pills.
- Hairlines (`--border-hairline` in `--rule`) between sections; control and
  outline edges are `--border-control` (2px).

## Diagram grammar

Atlas figures show mechanisms: what flows, which boundary it crosses, what
changes between before and after. A figure that only names boxes is a list;
write the list instead.

| Mark | Meaning |
| --- | --- |
| Outlined box (`--surface` fill, 2px `--ink-muted` edge) | A target-neutral thing: source, a Psi representation |
| Solid box (`--ink` fill, `--ground` text) | A realized thing: a native form, an executable |
| Heavy outline (2.5px `--ink`) | A hub: Terminal Psi, where Psi and Omega meet |
| Dashed outline | A proposed package or form that does not exist yet |
| Thin box on `--ground`, 1.5px `--rule` edge | Something around the pipeline (CLI, Build, packages) |
| Solid arrow in `--ink`, labeled | One numbered stage, or a named hand-off; label it with the stage number and verb (`03 select`) |
| Loop arrow on a box | A stage that rewrites its own representation |
| Green arrow or text (`--checked`) | The checker and its verdict |
| Dashed red arrow or box (`--trap`) | Code that reaches around the pipeline today |
| Dotted line across the figure | A firewall (Psi never depends on Omega) |

The full architecture canvas uses a second, explicit grammar: a named family
color identifies each owner, while the edge legend identifies the relationship.
Solid means data or transformation; dashed means invocation; dotted means a
Cargo declaration; dash-dot means construction or implementation correspondence.
Heavy dotted edges mean validation or measurement, and long heavy dashes mean
normative contracts. Red marks the observed separate `EmissionFacts` path. The
legend is rendered from the same stroke rules as the edges. None of these
relationships is a measured execution trace. Exact handoff labels and citations
appear on selection and in the static text outline, rather than overlapping
short arrows in the overview.

Drawing rules:

- Inline `<svg viewBox="0 0 W H" role="img" aria-label="...">` inside
  `<figure>` with a `<figcaption>` that states the figure's claim. The
  `aria-label` says the same claim.
- Flows read left to right. A long figure may continue right to left on the
  next row or scroll within a labeled frame; keep its text at drawn scale.
- Arrowheads are `<marker>` paths filled with the arrow's own token color.
- Small static figures use text 11.5–14px at drawn scale. The full canvas uses
  20px labels at natural scale, a readable default camera, a minimap and explicit Fit all/zoom
  controls. Canvas buffers follow devicePixelRatio; redraw on camera, size,
  selection, theme and font readiness, without a standing animation loop. Selecting any box restores at least natural scale. Give arrow labels a halo so lines never cut
  them: `paint-order: stroke; stroke: var(--surface); stroke-width: 4px`.
- Align boxes to a grid with equal gaps; give every box the same height in a
  row.
- Before publishing, look at the page once in light and once in dark, at full
  width and at 400px. Fix overlaps; do not ship a label crossing a line.

## Evidence on a page

- Every number comes from a script in `atlas/evidence/scripts/` or a line
  count anyone can rerun; say which in the caption or a "How far to trust it"
  note.
- Quotes carry `file:line`.
- A page's source revision is stated near the top.

## Checklist before a page is done

- [ ] Opens from disk; no console errors; fonts load from `../design/fonts/`.
- [ ] Reads in light and dark; no hard-coded colors.
- [ ] No horizontal page scroll at 400px.
- [ ] Every figure has a caption that states its claim and an `aria-label`.
- [ ] Every number and quote has its evidence; *unverified* and *judgment*
      are marked.
- [ ] The page is linked from the table in `atlas/README.md`.

## The custom parts

### Omega Serif, the custom font

Omega Serif is generated, not drawn. Every glyph is assembled from a few
shapes (stems, rings cut into arches, stone-cut wedge serifs) whose sizes come
from one weight setting in [font-source/build.py](font-source/build.py), so
changing one number changes every letter. The three files in `fonts/` (Light
300, Regular 400, Medium 500) are its output. Change the font by editing
`build.py`, never the `.woff2` files.

```bash
python3 -m pip install fonttools skia-pathops ttfautohint-py brotli
cd /tmp && python3 /path/to/Omega/atlas/design/font-source/build.py Light Regular Medium
python3 /path/to/Omega/atlas/design/font-source/check_pieces.py OmegaSerif-Regular.ttf
```

`build.py` writes `.otf`, `.ttf` and `.woff2` for each weight into the current
directory; copy the `.woff2` files into `fonts/`. `check_pieces.py` reports
letters whose outline falls into the wrong number of pieces. The font covers
ASCII, Western European accents, Greek, and the proof and logic notation
Omega's docs use (− ≤ ≥ ≠ ≡ ∧ ∨ ∈ ⊆ ∀ ∃ ⊢ ↦ ⇒ ⟨ ⟩ …); anything else falls back
to Georgia.

*Unverified:* rebuilding the fonts from this copy of `build.py` has not been
run yet in this repository (installing the font tools was blocked in the
session that copied it), so whether a rebuild reproduces the shipped files
byte for byte is untested.

### Components

The design system defines five components. [components/bundle.js](components/bundle.js)
is the React 18 version (`window.Omega`); [components/bundle.css](components/bundle.css)
styles them and works on plain HTML too, so a page without React can use the
same classes. Link it after `tokens.css`:
`<link rel="stylesheet" href="../design/components/bundle.css">`.

| Component | Use | Plain HTML |
| --- | --- | --- |
| Status | One result, never color alone | `<span class="om-status om-status-checked"><span class="om-pip" aria-hidden="true">✓</span><span class="om-status-word">Checked</span></span>`; states `checked`, `trap`, `open` |
| Tile | One idea; `outline` for target-neutral (Psi), `solid` for realized (Omega) | `<section class="om-tile om-tile-outline"><span class="om-tile-label">Psi</span><h3 class="om-tile-title">Checked source</h3><div class="om-tile-body">…</div></section>` |
| CodeBlock | Code or a command | `<figure class="om-code"><figcaption class="om-code-caption">Expected exit: 0</figcaption><pre class="om-code-pre"><code>omega run --both main.omg</code></pre></figure>` |
| PlaceGrid | One fact across the nine places, 3×3, in place order | `<ol class="om-place-grid">` with nine `<li class="om-place om-place-checked">` items in order: local, field, parameter, call result, match join, const name, nested machine, another machine, another target |
| Button | One action: `solid` runs, `outline` checks, `quiet` navigates | `<button class="om-button om-button-solid">Run natively</button>` |

Each component's own rules are in `components/<Name>/README.md`, and
`components/Cover/preview.html` is the system's cover: an ink slab with three
arched openings, a green column and a small red stone.

### The source system, for reference

[system-reference/](system-reference/) is an untouched copy of the design
system's own README, token cards, component cards and manifest, as published
in the owner's design-system artifact. Use it to check where a rule came from.

One inconsistency there: the system's generated `tokens.generated.css` and
`tokens.md` set body text in IBM Plex Sans and labels in IBM Plex Mono, while
its README ("Omega Serif for words, IBM Plex Mono for code. Nothing else.")
and its `tokens.json` set both in Omega Serif. This kit follows the README and
`tokens.json`; the owner should settle which is meant.
