Bootstrap asks how to construct the Omega compiler from a declared, auditable seed and then reproduce its self-rebuild. It is a construction problem with competing implementations, separate from the product compiler's numbered representation pipeline. The governing mandate permits different stage counts, languages, interpreters, VMs, native targets and documented accelerators.

This page maps source at 3f9ce43f0c9d179048911d18faa91ba93f60176d. No bootstrap compiler or customer was executed for this map. Historical observations below are attributed to their records; a fresh run is unverified. No peer has demonstrated the full Omega compiler construction and reproducible self-rebuild required by the completion rule.

One concrete route: native Gamma construction

The implemented entrance is:

python3 bootstrap/independent/source_test.py

The source route requires Linux x86-64 and a positive watchdog. It uses the audited Alpha seed, separately admitted Beta tape, host OS, Python and shell invocation machinery. Python copies and frames source bytes on this route; --accelerated additionally uses the Python Gamma compiler to supply language meaning. These are distinct trust profiles. Dispatcher; trust boundary.

Current code route. The rebuilt compiler here compiles Gamma; this is an intermediate construction check, not the Omega compiler's self-rebuild.

  1. reconstruct stamps the admitted Beta tape into the Alpha seed, recompiles Beta source, compares the tape with the bound artifact, then uses the reconstructed Beta compiler to produce and compare the Gamma evaluator.
  2. The native source is the explicit composition of the shared Gamma compiler, frontend and native emitter. source_test.py retains those bytes and a framed request, then runs the constructed evaluator to produce compiler0.elf on the reference route.
  3. The rebuild loop runs each resulting native compiler on the same compiler source and requires successful byte-identical results. This is a gate chosen by this implementation; the general mandate defines reproducibility without requiring every first/self-compiled generation to be byte-identical. Comparison rule.
  4. The harness records source/artifact identities and control results. Malformed source must return its designated refusal with no output. Boundary controls distinguish image capacity and returned OS-call failures. A watchdog expiration is an incomplete observation, not a language rejection. Execution limits.

The retained native construction record reports compiler rebuilds, semantic controls and a real Alpha-targeting compiler customer. Its successor record then follows native Delta and native Epsilon execution to an Omega fixture. It explicitly says Epsilon is still the evaluator and does not establish a standalone compiled bootstrap compiler or Omega self-rebuild. Those source and artifact identities qualify the historical results; this atlas does not convert them into current test passes or performance comparisons.

Ownership and useful next measurements

The product being constructed remains source/psi and source/omega, outside every variant. A small Omega program, a Gamma fixed point, or a compiled lexical-classification module proves only the named customer. The independent native backend also records an auditability failure in its numeric operation identities and sizing ladder; passing controls do not discharge it.

The later receiver/view milestone matters when reading the independent README: its earlier scalar-only coverage paragraph is not the whole current capability. Storage compilation code supports scalar and view parameters while refusing nominal parameter types; the latest recorded customer compiles the real request/UTF-8 module and reports that full bootstrap-compiler source still stops at a nominal diagnostic parameter. Console text output also remains unfinished. This is progress through an actual successor, not full acceptance.

tools/bootstrap/paths.sh names source owners; it supplies no translation semantics. A tool that does supply source-language meaning must be accounted for as an implementation stage or accelerator. Byte transport, source composition, stamping, observation and language implementation should therefore have different edges in the map. Mandate distinction.

Judgment: compare peers using the same real successor where possible, recording exact source, seed, accelerator profile, runtime prerequisites, actual output, refusal controls, cold construction and iteration cost. Keep the remaining Omega product customer explicit instead of assigning construction variants to the Rust product's stage numbers. These recommendations apply the mandate's whole-chain comparison rules; no architecture selection is made here.
