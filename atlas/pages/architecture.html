Provider closure

Settlement follows reached exact bodies and Build bindings. When reach changes, it prepares policy inputs from the retained accepted publication and checked source custody, then realizes target supplies. It repeats until bindings stabilize; this loop does not restart source compilation. Available, demanded and retained code are different sets.

        Native compilation

        Current program flow — how to read this map

        Source trace of the Rust reference producer. Arrows name values or requests, not measured execution. Some paths are condensed; open a subsystem for its full account.

        A guided reading, not execution timing. Starts paused and stops at the last step.

        All handoffs and source notes
        1. Begin with a Build request — Source choices, target and provider bindings enter through Build. This map follows selected handoffs in the Rust reference producer.
        2. Prepare and check the program — Psi source stages prepare the portable program. The lowered-form checker establishes acceptance; publication retains its code and evidence.
        3. Close the provider choices — Reached requirements meet Build's bindings. A selected provider can expose more requirements, so settlement repeats policy-input preparation from retained accepted code until bindings stabilize. It does not restart source compilation. The loop is conditional, not one measured iteration.
        4. Admit and lower the root — Settled native inputs reach Omega 00–02. This is the beginning of the root body's native route, not the end of provider-related admission.
        5. Pause for handlers, if needed — When handlers are required, the root waits after 02. Their objects are compiled, possibly recursively, to obtain full installation requirements. This conditional detour interleaves root and handler work; not every compile takes it.
        6. Bind measured installation facts — Prepared root obligations and measured handler requirements meet here, before root 03. Early settlement cannot supply values that later native work has yet to measure.
        7. Continue the root and emit objects — Bound facts enter root 03. Later stages select, allocate, encode and lay out machine forms before emission. This overview omits the separate EmissionFacts path; open the Omega page for it.
        8. Construct the image and its bridges — Objects and entry plans enter image construction, which still creates entry/adapter machine code. This walkthrough describes source order, not successful execution or elapsed time.

        A guided reading, not execution timing. Starts paused and stops at the last step.

        All handoffs and source notes
        1. Begin with a Build request — Source choices, target and provider bindings enter through Build. This map follows selected handoffs in the Rust reference producer.
        2. Prepare and check the program — Psi source stages prepare the portable program. The lowered-form checker establishes acceptance; publication retains its code and evidence.
        3. Close the provider choices — Reached requirements meet Build's bindings. A selected provider can expose more requirements, so settlement repeats policy-input preparation from retained accepted code until bindings stabilize. It does not restart source compilation. The loop is conditional, not one measured iteration.
        4. Admit runtime provisions — The Psi product route requests runtime admission. The result supplies runtime capabilities, rather than an emitted native image.
        5. Bring code and capabilities together — The retained Psi artifact and admitted provisions meet when the runtime loads and binds an instance. Neither an artifact decode nor a provider name alone authorizes execution.
        6. Invoke under a work meter — The interpreter invokes the bound instance and accounts for its work. The detailed interpreter page shows the embedding and host adapter boundaries.
        7. Observe the result — The caller receives status and output. These arrows explain the source route; they do not report that a sample succeeded.
