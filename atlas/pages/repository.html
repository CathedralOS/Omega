Native compilation

Current program flow — how to read this map

Source trace of the Rust reference producer. Arrows name values or requests, not measured execution. Some paths are condensed; open a subsystem for its full account.

A guided reading, not execution timing. Starts paused and stops at the last step.

All handoffs and source notes
  1. Begin with a Build request — Source choices, target and provider bindings enter through Build. This map follows selected handoffs in the Rust reference producer.
  2. Prepare and check the program — Psi source stages prepare the portable program. The lowered-form checker establishes acceptance; publication retains its code and evidence.
  3. Close the provider choices — Reached requirements meet Build's bindings. A selected provider can expose more requirements, so source preparation and settlement can repeat until choices stabilize. The loop is conditional, not one measured iteration.
  4. Admit and lower the root — Settled native inputs reach Omega 00–02. This is the beginning of the root body's native route, not the end of provider-related admission.
  5. Pause for handlers, if needed — When handlers are required, the root waits after 02. Their objects are compiled, possibly recursively, to obtain full installation requirements. This conditional detour interleaves root and handler work; not every compile takes it.
  6. Bind measured installation facts — Prepared root obligations and measured handler requirements meet here, before root 03. Early settlement cannot supply values that later native work has yet to measure.
  7. Continue the root and emit objects — Bound facts enter root 03. Later stages select, allocate, encode and lay out machine forms before emission. This overview omits the separate EmissionFacts path; open the Omega page for it.
  8. Construct the image and its bridges — Objects and entry plans enter image construction, which still creates entry/adapter machine code. This walkthrough describes source order, not successful execution or elapsed time.

Handlers, if needed

Required handler objects are compiled only when needed, and that compilation may recurse. Their requirements include transitive body demand, bridge bytes, call bias and fault evidence, not just the local frame size. Cyclic resource dependencies are refused.

A Rust crate graph covers the first implementation; it cannot stand in for the whole repository. AGENTS.md names these owners explicitly.

    Owners and boundaries

    Owner Entrance and result Authority and status
    Rust reference producer, omega-rust/ The omega application routes compilation, execution, inspection and package commands. See Psi, Omega, CLI, interpreter, and Build/packages. Maintained reference producer and differential comparator. Its output is implementation evidence; the specification owns required language behavior. Repository roles; specification status.
    Omega-written product, source/psi/ and source/omega/ Psi owns target-neutral source processing. Omega's construction application calls a shared compilation library and currently emits Alpha tapes for its supported subset. One product split by responsibility, outside the bootstrap variants. Self-compilation is unfinished; its source exceeds its own supported backend. Psi status; Omega status.
    Bundled library, source/library/ Core declarations, ordinary package dependencies, checked helpers, target providers and sealed compiler operations. See library. Inclusion in this tree does not admit a package or prove support on a target. Library contract.
    Bootstrap construction, bootstrap/ Peer interpreted, compiled-VM and independent native paths construct successors from declared seeds. See bootstrap. Governed by MINIMIZATION.md; no peer is selected. A completed path must construct the actual Omega compiler and reproduce its self-rebuild. Architecture mandate; completion rule.
    Tests, tests/ and crate-local tests An owning test selects a program, observes its specified result, or requires the intended refusal. tests/fixtures/ supplies Rust-owned programs; tests/psi/ and tests/product/ exercise Omega-written source. tests/omega/ and its corpus runner are retired. Test ownership; retirement.
    Samples, samples/ Miniature projects with Build entries and authored output/exit expectations enter sample-gate. Discovery roles control test selection, not package trust. A library-only sample is exercised through a consumer. A directory is not automatically one executable. Sample rules.
    Documentation, wiki/, root guidance and atlas/ Specification, guide, proposals, drafts, operating instructions and planning pages. wiki/spec/ states current contracts; proposals are not current rules. Atlas is a planning workspace, not a compiler input. Documentation roles; Atlas rules.
    Product tools and repository tools Inspection/package commands ship in omega; tools/xtask, CI, benchmarking, bootstrap helpers and agent coordination maintain or assess the repository. See tools. A diagnostic, benchmark, source packer or claim has its own limited authority; none substitutes for language checking. Product dispatch; repository tools.

    One concrete route: materializing the Omega compiler's source

    source/omega/construct.py is a useful entrance because it names exactly what the Omega-written compiler must eventually compile. Its package list contains the construction application, compilation library, Psi, std and core. Its dependency edges and toolchain roles are explicit invocation inputs. It records Build files but does not execute them. Inputs.

    The current mechanism is:

    Current route from source; the arrow through a constructor is conditional on supplying an executable. This diagram is not a completed self-rebuild claim.

    1. compiler_input collects sorted .omg sources from the explicit roots, excluding Build declarations and invocation build directories. It preserves package ownership and unit bytes, selects the declared entry and records byte intervals and hashes. Filenames do not synthesize modules.
    2. entry_start reads the framed source set, retains packages, edges and units, selects the entry name, then calls compilation_finish. The shared Compilation pipeline resolves, types, checks and lowers before the Alpha emitter. This is an early closed-input interface; it neither acquires packages nor authenticates an untrusted graph. Interface limit.
    3. The application publish writes bytes only after a successful compilation status and an output-capacity check. The host wrapper separately requires exit zero, nonempty output and unchanged source/producer identities before replacing the requested output artifact. It retains the actual result even when publication fails. Wrapper publication.

    Fresh validation for this map ran:

    python3 source/omega/construct.py --input /tmp/omega-atlas-worker5-construction/input.bin

    That command completed and wrote the input and manifest at the pinned revision. No --compiler was supplied, so no compiler execution or self-compilation was tested. The observed input SHA-256 was 49db8b2280bb8a963d9425f8c5ef2e0aacfb2a73b5965a5a5d624d84d9cd1b2d. The corresponding execution and rejection cases live in the Alpha product gate; their current pass status is unverified here.
