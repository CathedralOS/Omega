# Symbol-resolved trees to typed trees: generated-source continuation

The contract is [build execution](../../../../../wiki/spec/build/execution.md).
This note maps its Rust implementation; supported append cohorts are compiler
limits, not a different generated-source language.

## Entry points

- [filesystem_scope.rs](../../../../omega/packages/package-compilation/src/build_execution/filesystem_scope.rs) binds request staging and sponsor
  inputs to the package/root filesystem scope. It checks canonical Source metadata
  before reopening review-only replay; it does not admit or execute the build.
- [build_continuation.rs](../../../../omega/compilation/compiler/src/checked/checking/build_continuation.rs):
  `evaluate_build_and_continue` evaluates Build, then
  `complete_product_frontend` admits and parses its generated bytes.
  [CompletedSource::extend](../../psi-compiler/src/source_compilation.rs) owns
  resolution and typing against the retained frontend rather than reconstructing it.
- [build-settings](../../../../omega/build-system/build-settings/src/build_evaluation.rs):
  `evaluate_build` owns declaration admission, filesystem preparation, exact
  machine admission, consent and execution. Its private `AdmittedBuildProgram`
  retains the prepared program, selected machine, scope and sponsor; the
  coordinator receives the completed result, not an executable checkpoint.
- [source assembly](../../../../omega/packages/package-compilation/src/source/source_assembly.rs): generated units and
  dependency bundles retain source bytes, logical paths, and producer custody.
  `GeneratedSourceExtension::parse` joins the exact base and produces separate
  syntax forests through Psi 00/01 before this continuation resolves them.
- [seeded resolution](../02_syntax-trees-to-symbol-resolved-trees/src/resolution.rs)
  appends the later stratum and rebases only extension-owned selections.
- [typed continuation](src/lowerer.rs)
  validates append cohorts and preserves the base. It consumes the
  [representation-owned continuation records](../../representations/symbol-resolved-trees/src/continuations.rs),
  not resolver state. The Psi driver retains pending syntax and coordinates
  resolution, source activation and typing; their exact predecessor pairings
  are exercised by `resolution_handoff_tests` in `source_compilation.rs`.

## One typing route

Every appended declaration family uses ordinary `type_resolved_cohort` and
`close_typed_cohort`: data, domains, machines, mathematical declarations,
propositions, measures, operators, traits, named implementations and wire
schemas. Constants retain their declaration-side initializer and selection
custody. There is no separate generated-source shape whitelist or recursive
type admissibility checker. Unsupported source still rejects in its ordinary
resolution, typing, proof, ownership or realization owner.

The continuation keeps the exact resolved/typed predecessor. Resolution may
append semantic domains, service definitions and rows, external binding
identities and evidence forwardings; each retained ID still names the same
value. The typed join preserves prepared domain instances, appends declaration
ceilings by owner, and translates only new evidence forwardings after typing
has recorded erased proof calls.

Signature-free static requirement operands retain resolution's selected trait,
declaring trait and exact requirement, or its refusal. Typing consumes that
outcome rather than resolving the path again with a different context.

Both the continuation and fresh typing close through `close_typed_cohort`.
Declaration identities, written contracts, progress premises, domain constraints
and concrete literal receiving types remain typed data. They establish no body
verdict. Requests that still depended on the retired checker—closed const
admission/replay, unresolved membership carriers, domain-entry accounting,
legacy target-family contracts, projected/dynamic call binding and callable
transition normalization—refuse with `no product route yet` until their
surviving owner supplies the required judgment or correspondence.
Typing does not create empty facts or reuse an old checker verdict.

Source activation (`SeededTypingBase::activate_sources`) narrows a retained
typing to the program written in the selected sources. It reads no verdict: the
typed representation's own
[declaration projection](../../representations/typed-trees/src/declaration_projection.rs)
keeps the selected files' declarations and the declarations the compiler derived
for them, and the resolved roots follow what remains.

The matching post-typing evaluator consumes the completed candidate; wire-plan
publication starts at the extension wire-schema frontier. The structural prefix
gate returns the owned base unchanged on failure, and orchestration rejects.
Admission compares retained resolved declaration roots and shared semantic IDs;
ordinary typing operations own preservation of their retained storage. Compilation
does not replay a whole typed-tree comparison after its own producer runs.

Legacy target-scoped units finish their independent pre-resolution evaluation before
the ordinary target filter. The filter consumes the retained base selection
into a combined selection, then settles selected origins and target-owned
`provider_defaults` against the final typed continuation. Only extension
declarations are mutable during this process.
This describes current migration machinery, not accepted source syntax.
`BUILD-OWNED-TARGET-SELECTION` in [the task board](../../../../../TASKS.md#pipeline-route)
replaces target prefixes and family selection with ordinary named implementations
and explicit target-keyed Build provider rows.
Units share one immutable package-selection authority for this continuation;
sharing it neither makes sibling declarations visible nor admits transitive-only
package selections.

There is no combined-syntax rebuild switch, second frontend reconstruction, or
source-span/name recovery of the admitted entry. New cohorts must extend the
transactional continuation rather than restore one of those routes.

Constant initializers remain detached roots in the resolved base, not runtime
constant storage or decoded review strings. Only newly authored initializers
undergo name resolution; later imports cannot reinterpret retained constructors.
Typing discards the initializer link while keeping declaration/use custody.
