# Provider planning

This crate takes canonical Terminal declarations, kept native plan data and
explicit Build supplies. It does not read source IR, inspect source
applications or rebuild acceptance. Source nomination belongs to the source coordinator;
unsupported product preparation refuses with `no product route yet`.

Calling-policy execution and storage use the real canonical artifact. Native
locator normalization keeps the completed Build evaluation and authored target
without granting provider, signature, package or execution admission. Their
existing owners still check canonical callback geometry, ABI, placement,
movement and receipts. [Target supply](src/target_supply.rs) chooses and settles
providers for the boundary requirements the accepted module reaches. The
`provider-selection` crate admits boundary applications against chosen plans.

`products` keeps explicit source inspection, with the same frozen source
allocation and inventory. It is not another proof or native planning path.
