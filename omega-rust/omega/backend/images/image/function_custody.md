# Function and final-image custody

The [native product contract](../../../../../wiki/spec/build/component_publication.md)
requires exact object/image and publication relationships. The
[footprint note](footprint_replay.md) separately states the test-only certificate
path; function/byte checks must not be reported as that missing production join.

Function identities keep source, wrapper, and private-callback roles distinct.
Direct calls resolve in the complete assigned identity set. Every encoded
function rejoins one exact object function symbol and text interval. A callback
cannot stand in for the process entry or an ordinary source function; its private
symbol is recomputed from callback placement rather than trusted as stored text.
Non-entry source/wrapper names retain machine/state generations and segment
identity, preventing stale handles from sharing a live linkage name.
Final replay also rederives the canonical public entry name and rejects a renamed
entry symbol; arbitrary object spelling cannot supply linkage authority.

The object-to-image copy preserves entry and every identity-owned function's
name, text classification, offset, size, and kind. After format placement, replay
joins each function and object symbol to one compiler-function region. Import
thunks retain their separate origin. Inventory replay checks ordered intervals,
addresses, byte identities, complementary gaps, origins, and the inventory's own
identity before consuming a summary.

Retained selected instructions have one function owner. A duplicate owner,
cross-function instruction relocation, or origin without a retained instruction
rejects. Semantic-operation, semantic-edge, and materialization origins keep
their independent namespaces.

Strong compiler-text identities distinguish encoded bytes, relocated prefix,
ordered relocation envelope, and the derivation joining them. The function
validation summary has its own strong commitment; compact fields remain reports.
Footprint attachment additionally needs the sealed entry/function-region join,
prior inventory, composed footprint, and resulting inventory. This is the
required receipt for the certificate's inventory mutation, not evidence that
the current publication route performs it.
