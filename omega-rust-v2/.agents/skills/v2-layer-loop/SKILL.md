# Run a V2 layer to its agreed stopping point

An explicit request such as “Use v2-layer-loop on L5 through sign-off” starts this procedure in the active session. Take the layer, outcome, worker permissions, budgets and publication authority from the request and standing project instructions. If the request specifies one wave, finish that wave. Otherwise continue within the requested layer while an authorized action can advance it. The two procedures linked below are part of this workflow and can also be used separately.

1. **Establish the starting point.** Work through the authorized V2 junction. Read [PLAN.md](../../../PLAN.md), the relevant canonical spec clauses, the layer contract and its current lock evidence. Record the source fingerprint, baseline report directory, measured blockers and outstanding sign-off obligations. On resume, reconcile the last checkpoint with the actual tree, live workers and published head before assigning work.
2. **Choose which problem to solve.** If the measurements are incomplete, contradict a replay, or lose an original case, use the [measurement procedure](../v2-layer-measurement/evidence.md). If a reproducible source contradicts the specified handoff, use the [repair procedure](../v2-layer-lock/handoff.md). If the observed refusal appears correct, establish the owning rule, verify its location and run a lawful neighbor. If the spec leaves a decision unsettled, collect the minimal example and the competing consequences for the owner.
3. **Assign one owner per independent decision.** Group cases by the fact the compiler needs, who first has it, and which consumer uses it. A common diagnostic is a lead. Vary one input to check whether two cases have the same cause. Give each owner the case IDs, baseline inputs, predicted output, nearest control, editable paths and completion condition. The owner follows the decision through implementation and consumer verification. Parallelize independent groups with the authorized worker tool and cap. Coordinate shared representation and registry edits centrally. If parallel work is unavailable, perform the same assignments sequentially. Keep an independent reviewer’s challenge separate from the repair owner’s examples where the claim needs it.
4. **Integrate and measure.** Check each proposed repair against its baseline witness and control. Integrate compatible changes and run readiness on a stable tree. Compare the two reports by case ID. Account for original cases closed, still blocking or missing, previously passing cases that regressed and newly exposed blockers. Replay each new blocking input on the baseline. If a report groups extra fixtures with a change to the compiler, repair that distinction in the tool and repeat the comparison.
5. **Choose the next wave immediately.** Repair verified regressions and measurement errors before interpreting the counts. When the evidence is sound, take the next independent decisions with reproducible inputs. When ordinary fixes repeatedly reach into a locked layer, trace the first lost fact and apply the reopening rules in the repair procedure. Continue independent work while an owner decision is pending. At sign-off, apply the plan’s full criteria and existing approval requirements.
6. **Leave a resumable checkpoint.** Use the current run directory to record the scope, source fingerprint and revision, report paths, original and new case IDs, completed decisions, outstanding owners or worker session IDs, and next action. Reuse the case ledger and comparison output. Send a concise update for a material finding, a verified wave, a decision needing the user, or completion. Publish a verified change when authorized.

End at the requested outcome or limit. If no work can advance within scope, report the smallest remaining decision or missing input, what was tried, and what would make the next attempt different. An unchanged blocker count alone says little about progress. If a wave reproduces the same failures with the same evidence, change the experiment before dispatching more workers.
