# How quickly did model-assisted work converge in V1 and V2?

On November 22, V1 was the faster route to a working Build continuation. Fable repaired its existing driver in two iterations over **23m 36s**. The original eight public behaviors went from **5 passing to 8**, and a follow-up caught a defect the original eight missed. V2 went from **0 to 0 on the same eight** during the experiment. Its checker and interpreter gained verified behavior, but the public driver still could not run the authored Build. For a team that needs this feature today, the evidence favors V1. [Paired compiler comparison](V1_V2_COMPARISON.md)

For the next compiler investment, the wider history favors hardening V1 in place. The timed Build experiment alone covered one shared feature with very different starting points. We also have a longer V2 record in which five of seven named blockers closed in **2h 43m 32s**. The first experiment measures time to deliver a user-visible feature. The second measures how fast a known queue shrank. All times below are Pacific.

The dependency survey covers every stage. The behavioral examples below exercise selected guarantees.

**Why the models could make progress.** The byte-read producer already supplied the four relevant operands. A model could alter each operand at the checker boundary and replay the real Build. For a direct wait, resolution already represented the selected call in a temporary for the transition subject. The planner could use that established decision. The alias failure is the contrasting case where the producer itself had to change. Holding the resolved base and the new file fixed, then removing the old syntax, exposed exactly what was missing. These are three different repair shapes with observable answers. Only the first two were replayed in the timed local comparison.

The production evidence supports investing in V1 for a customer path it already runs. It establishes neither a general productivity advantage over V2 nor blanket sign-off for V1. For a scoped sign-off, the decisive evidence is whether an independent consumer can make the specified decision from the published input, accept the right case, and reject a one-fact change for the right reason.


## Which compiler should get the next implementation work?

**Use V1 as the primary compiler and harden its boundaries in place. Keep V2 as a source of contract tests and as a reference for specific redesigns.** The November 20–22 history answers the practical investment question. Models repeatedly took a failing V1 customer program, isolated the owner, changed the handoff and demonstrated the result through execution. They also changed several of V1’s stage APIs in place. V2’s strongest demonstrated advantage is how precisely it can test what crosses a handoff. V1 already supports that method on important paths.

### V1 changed its architecture while continuing to deliver behavior

The November 18 rationale for V2 recorded **11h 24m and 34 commits** into a V1 stage split, with only lexing and parsing compiling independently at that checkpoint. Reading forward changes the conclusion. The V1 pipeline now documents Cargo entry points for all six stages from lexing through lowering. On November 20, four commits landed between 02:06 and 02:52 Pacific. They gave resolution a single representation root, unified the checked forest used by typing and preparation, made preparation return a frozen input for lowering, and moved publication of accepted inputs to the checker. The preparation change passed 58 unit tests and both doctests, including a compile-fail test for forging the prepared input. The checker change still reported **39 failures in 1,227 cases**, 28 reproduced on an earlier binary. This was real movement in ownership with a visible regression burden. The 45-minute interval measures commit spacing, not time spent implementing the split. ### A second V1 customer exposes both the advantage and its limit

The dungeon room lookup gives us a separate sequence with a concrete answer. A search must mutate the room with the requested identifier and preserve its neighbor. On November 21, **2h 09m 49s** separated the recorded commits for #5012 and #5031. Several changes proceeded in parallel. Their records let us follow the observable result as each obstacle moved.

| V1 checkpoint | What the program could now do | What still failed in that record |
| --- | --- | --- |
| [#5012](https://github.com/CathedralOS/Omega/commit/a2cccc62c825) | A helper returned a borrowed slice element. Both engines read 34 from the selected cell, and a conflicting write was refused. | The dungeon still failed when forwarding an exclusive loan. |
| [#5026](https://github.com/CathedralOS/Omega/commit/14dc8a9f4859) | The returned reference still selected the correct cell after the caller changed its index. A recursive search worked in Psi. | Native instruction selection refused the recursive edge. The original eight-file lookup still hit a parent-loan refusal. |
| [#5028](https://github.com/CathedralOS/Omega/commit/0e2e863b96d1) | Both engines ran the recursive search, wrote 42 into room two, and left room one at zero. | The full lookup’s sum-tag path needed separate work. |
| [#5031](https://github.com/CathedralOS/Omega/commit/2601ee048234) | Both engines ran the caller with the eight unchanged room modules, selected room two by its identifier, changed its flag, and preserved room one. | Reopening the emitted Psi through the independent artifact checker still failed in the recorded run. |

That last failure is where V2’s discipline pays off. An engine can produce the right answer while an independent consumer still rejects the published artifact. V1’s own artifact checker exposed that discrepancy down to the operation and obligation. The proportionate investment is to keep the real program and give the saved artifact its own acceptance test. This evidence supports neither abandoning the running compiler nor signing off every boundary it crossed. ### What V2 buys and what its queue misses

One V2 interval held 323 cases fixed for **1h 15m 37s**. The blocker count stayed **35 → 35**. Two access-policy cases advanced from refusing the domain member to requesting the package owner for its semantic schema. That localized the next decision but delivered neither program. A separate wave assigned 12 author/reviewer pairs. Its recursive-field test caught both a swapped binder and swapped actual arguments. Several other pairs could identify precisely where a handoff stopped without producing Psi. That is valuable diagnostic work, and the records tell us exactly when to count a delivered behavior. [Fixed-cohort comparison](target/layer-readiness-1905-to-2020.md) · [Paired review outcomes](target/sample-yield-parallel-06/results.md)

There were also substantive repairs **after** the five-checkpoint table below. At #5041 V2 recovered the backing of loans in parked sums and compared the actual Psi of the failing package and its control. At #5042 it lowered structural results of suspending calls and used a Psi-only reader to reject a storage home that appeared before the call completed. The registered blocker count was **one at both commits**, even as both fixes landed. This is the strongest V2 practice to transfer into V1. Change only the fact crossing a boundary and require the independent consumer to distinguish the two products. V1’s continuation suite already does this for changed declarations, completed byte reads and borrowed returns. [V2 parked loans](https://github.com/CathedralOS/Omega/commit/c110d2b74ac8) · [V2 structural results](https://github.com/CathedralOS/Omega/commit/11d76229aea4) · [V1 direct consumer tests](../source-rust/subsystems/compiler/psi-semantics/tests/checked_continuation.rs)

The repository supports a choice today even though it cannot give a universal speed multiplier. Most of the dungeon commits lack usable model-cost receipts, and implementation maturity differs. I would fund a V2 production replacement if it repeatedly took real behaviors that force V1 to reconstruct the same information across owners and delivered those behaviors with less repair work all the way through an independent consumer. For the cases in hand, V1 has already demonstrated the cheaper first move in engineering scope. Repair the owner and reuse the working rest of the pipeline.


## The same Build on both compilers

The Build registers a dependency, waits for it, then calls an imported machine. One source form binds a helper’s return to a local. The other uses the call directly as a transition subject. The expected answers specify which effects run, how often, and where evaluation must stop. For example, returning a Boolean to an integer binding must report the type error after the prefix runs once and before the suffix runs. An early refusal fails that row even if the process exits with an error. [Original paired matrix](.agents/worktree/paired-build-wait-1795367560/results.json)

| Public cases held fixed across builds | Before | After first repair | After second repair |
| --- | ---: | ---: | ---: |
| V1, eight original rows | 5/8 | 8/8 | 8/8 |
| V1, same eight plus the two arm-read rows replayed on all three binaries | 6/10 | 9/10 | 10/10 |
| V2, eight original rows | 0/8 | — | 0/8 |

The three recovered original rows all exercised the direct call spelling. Moving a dependency read into a helper called by the selected arm exposed the fourth failure. Fable’s second change preserved the dispatch so its arms could be checked after the wait. The final independent replay covered 14 positive and branch-selection variants plus four refusal controls. The extra rows improved confidence. Counting each as a separate bug would inflate the repair rate. ## How to measure a per-model speed difference

Choose a behavior both compilers already expose, demonstrate the same public failure on both, and freeze the source, expected effects, refusal timing, and a withheld variant before editing. Give the same model and effort setting a fresh, equally briefed session on each codebase. Reverse the order on the next independent defect family. Run missing-feature work as a separate comparison with its own common starting milestone.

For each attempt, record time to reproduce, time to the first public pass, time to pass the withheld case while retaining all earlier passes, build time, human interventions, and total model usage across helpers. Keep unfinished attempts in the results with their elapsed time and last verified boundary. Compare retained **independent defect families** per wall hour and per recorded dollar. That would tell us whether V2’s explicit handoffs repay their implementation cost as models make repeated changes.
