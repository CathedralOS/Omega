# L2 Resolver

L2 answers “which declaration can this name refer to in this file?” For `draw(x)`, it binds `x` to its parameter or local. If the file can see two overloads of `draw`, L2 returns both declaration identities. L3 selects one when it knows the type of `x`. [Overloads](../../wiki/spec/language/domains.md#result-domain-overloads)

## Running it

Run `cargo test -p omega-resolver` from the repository root. To resolve an actual package, run `omega source resolve <file> [<file> ...]` from its root and supply its source files as relative paths. Success exits with status zero. A refusal reports the file, line, byte column and offending name. These two fixtures differ only in the directory that declares `score`. ## Stage interface

`resolve_stage` takes parsed files, their logical package-relative paths and the direct dependency aliases admitted for each requesting package. `resolve_stage_for_target` also takes the selected architecture's register and instruction names. The CLI supplies one package and an empty dependency graph and target vocabulary. The build driver owns discovery, dependency admission and target selection. [Public interface](src/stage/model.rs) · [Stage model](../../PLAN.md#v2s-build-model-a-chain-of-stages)

L2 returns `SymbolResolvedTrees`. It retains each indexed syntax tree with its own occurrence and declaration bindings. The original source text and logical paths back the borrowed spellings. The parser events, token vectors and input list can be released before typing. The result contains declarations, definition sites, bound occurrences, generic applications and operator uses and declarations. Each occurrence carries its tree node, role, package, logical file and byte span. A shorthand field initializer exposes both the member and the value binding on its node. Operators and generic argument sections expose their resolved records by node. For type equality, the operator records the two type nodes inside any grouping parentheses. L2 refuses a type/value mixture at the equality expression. A source declaration identity carries its owning package, qualified path and kind. Machines also carry their authored operand shapes, result-domain selections, nominal signature owners and enclosing machine shapes. Moving declarations between files in the same directory preserves these identities. On failure the resolver returns the first deterministic diagnostic. [Nested machines and identity](../../wiki/spec/language/machines.md#nested-machines-and-identity) · [Implementation](src/stage.rs)

## Binding rules

| Rule | Accepted and refused cases | Specification |
| --- | --- | --- |
| Namespaces and imports | Forward references and sibling declarations bind. Child directories introduce their own namespace. File declarations and imports take precedence over siblings. A qualified path such as `combat::score` and the import `use combat::score` both start at the package root or a dependency alias, never at a child directory of the caller. Repeated imports of one declaration coalesce. Competing origins, malformed logical paths and conflicting package aliases reject. | [Modules](../../wiki/spec/language/modules.md#directory-namespaces) |
| Dependency authority | Each file uses its own imports and its package's direct alias edges. An alias may select different packages for different requesters. A path whose first segment is both an alias and a root directory or declaration of the requester rejects. Importing a module exposes its direct declarations. A transitive dependency and another file's imports grant no lookup authority. | [Import scope](../../wiki/spec/language/modules.md#import-scope-and-exposure) |
| Visibility | A consumer can name public declarations and inherited fields, cases, nested data and trait requirements. Public signatures must expose consumer-nameable types. Private helpers can implement a public machine or conformance. Nested machines are visible within their lexical scope. A top-level qualified machine head such as `machine f::helper` rejects when `f` is a machine or data carrier or names nothing; a module, trait, named implementation or domain can own one. | [Visibility](../../wiki/spec/language/modules.md#visibility) |
| Lexical scope | A local enters scope after its initializer. Arm bindings end at the arm. A bare word in an arm pattern binds a new name unless it names a constant that no local, parameter or generic binder of that spelling hides ([open owner question](../../../OWNER_QUESTIONS.md#open-questions)). Nested helpers can call sibling helpers and use enclosing static binders. Capturing an enclosing machine's runtime parameter rejects. A record shorthand also reads the lexical value it names. | [Nested machines](../../wiki/spec/language/machines.md#nested-machines-and-identity) · [Resolution](../../wiki/spec/language/modules.md#resolution) |
| Type and value roles | Builtin types, including the open integer spelling family, occupy the type role. A local may have the same spelling in the value role. Redefining a builtin type rejects. Cases use a qualified carrier. Dot-selected fields carry the field spelling for typing. | [Builtin type names](../../wiki/spec/language/modules.md#builtin-type-names) |
| Domains | An attached declaration binds its carrier in its declaring file. Short carrier-qualified lookup requires that exact carrier and an exposed domain. Importing the carrier alone does not expose the domain. A conflict reports the owners, carrier and exposing import locations. | [Foreign attached declarations](../../wiki/spec/language/modules.md#foreign-attached-declaration-paths) |
| Overloads and operators | Distinct operand shapes or named result-domain sets can identify overload candidates. Identical source declaration shapes reject. Operator declarations retain the token, declaring machine and semantic home where applicable. Duplicate bindings and foreign domain ownership reject. Operator uses retain their spelling and source site for typed selection. | [Operators](../../wiki/spec/language/expressions.md#operator-declarations) · [Result domains](../../wiki/spec/language/domains.md#result-domain-overloads) |
| Generics | An application retains its selected declaration or candidates and the original argument spans. A selected binder determines a name argument's role. A qualified argument such as `u8 in P` takes that role at its head: a qualified type under a type binder, the membership test `N in P` under a value binder. A transparent alias in the bound uses the imports of its declaring file. When overloads disagree on that role, L2 preserves each interpretation for L3. Qualified paths retain the application on the segment where it was written. | [Generics](../../wiki/spec/language/generics.md) |
| Trait requirements | A selection row such as `Logger::write = write_log;` binds both names. The left side must belong to the implemented trait or one of its parents. The right side must name a machine. Inherited requirements retain their original owner. Cycles and ordinary traits inheriting boundary traits reject. | [Conformances](../../wiki/spec/language/conformances.md#implementations-are-operation-records) |
| Assembly | Register and instruction names bind against the supplied vocabulary. An assembly transfer names an assembly declaration. An unavailable target name rejects at its source site. The target checker determines whether the instruction and operands are valid together. | [Parser assembly grammar](../01_tokens-to-syntax-trees/GRAMMAR.md) |

## Handoff to typing and preparation

`Buffer<8>` and `Buffer<4 + 4>` bind to the same `Buffer` declaration. L2 preserves both expressions. Typing and evaluation establish the common closed application identity before a build can persist it or reuse it across stages. The same handoff applies to overload selection by operand type, receiver field lookup, requirement signature matching and operator dispatch. [Build decisions](../../PLAN.md#decision-log)

## Verification

The directory and call tests exercise the same resolver as the stage and corpus tests. Stage fixtures exercise the lexer, parser and public resolver. Multi-file fixtures compare forward and reversed inputs. The provenance invariant checks that declaration references occur exactly once in the returned roster and that source, binder, argument and operator spans point back into the originating files. A 10,000-name expression exercises the iterative tree walk. [Stage fixtures](tests/stage.rs) · [Provenance checks](tests/support/mod.rs)

The corpus test resolves all 132 spec fragments individually with an empty dependency graph and target vocabulary. It compares the result for each fragment with a checked-in expectation. 38 bind successfully and 94 report the expected first error. Many examples intentionally omit the surrounding declarations. A successful result here establishes name binding only. [Corpus test](tests/spec_corpus.rs) · [Expected results](fixtures/spec-outcomes.txt)
