# L2 Resolver

L2 answers “which declaration can this name refer to in this file?” For `draw(x)`, it binds `x` to its parameter or local. If the file can see two overloads of `draw`, L2 returns both declaration identities. L3 selects one when it knows the type of `x`. [Overloads](../../wiki/spec/language/domains.md#result-domain-overloads)

## Running it

Run `mbx test --locked -p omega-resolver --tests` from the V2 workspace. To resolve an actual package, run `omega source resolve <file> [<file> ...]` from its root and supply its source files as relative paths. Success exits with status zero. A refusal reports the file, line, byte column and offending name. These two fixtures differ only in the directory that declares `score`. [CLI process tests](../../application/tests/cli.rs)

## Stage interface

`resolve_stage` takes parsed files, their logical package-relative paths and the direct dependency aliases admitted for each requesting package. `resolve_stage_for_target` also takes the selected architecture's register and instruction names. The CLI supplies one source package, its direct `omega` alias to the standard toolchain package, and an empty target vocabulary. The [production package profile](../../toolchain/src/lib.rs) supplies the corresponding interface exports. The build driver owns discovery, dependency admission and target selection. [Public interface](src/stage/model.rs) · [Stage model](../../PLAN.md#v2s-build-model-a-chain-of-stages)

L2 returns `SymbolResolvedTrees`. It retains each indexed syntax tree with its own occurrence and declaration bindings. The original source text and logical paths back the borrowed spellings. The parser events, token vectors and input list can be released before typing. The result contains declarations, definition sites, bound occurrences, generic applications and operator declarations. Each tree can export its public source declarations with their defining namespaces. File-local imports grant lookup authority without adding declarations to that interface. Each occurrence carries its tree node, role and byte span. Its tree supplies the package and logical file. A shorthand field initializer exposes both the member and the value binding on its node. At each generic argument list, `application_name` gives the bound occurrence that owns it. The list’s syntax children are its arguments. The indexed syntax supplies each operator’s spelling and span. An equality carries its operator site and the bindings of its operands. L3 selects type or value equality and reports mixed operands. A source declaration identity carries its owning package, qualified path and kind. An overload's identity includes its authored operand shapes, result-domain spellings, nominal signature owners and a reference to its enclosing machine. Occurrences, exports and typed calls share that identity. Independently resolved interfaces compare its contents. Moving declarations between files in the same directory preserves these identities. On failure the resolver returns the first deterministic diagnostic. [Nested machines and identity](../../wiki/spec/language/machines.md#nested-machines-and-identity) · [Implementation](src/stage.rs)

## Binding rules

| Rule | Accepted and refused cases | Specification |
| --- | --- | --- |
| Namespaces and imports | Forward references and sibling declarations bind. Child directories introduce their own namespace. File declarations and imports take precedence over siblings. A qualified path such as `combat::score` and the import `use combat::score` both start at the package root or a dependency alias, never at a child directory of the caller. Repeated imports of one declaration coalesce. Competing origins, malformed logical paths and conflicting package aliases reject. | [Modules](../../wiki/spec/language/modules.md#directory-namespaces) |
| Dependency authority | Each file uses its own imports and its package's direct alias edges. An alias may select different packages for different requesters. A path whose first segment is both an alias and a root directory or declaration of the requester rejects. Importing a module exposes its direct declarations. A transitive dependency and another file's imports grant no lookup authority. | [Import scope](../../wiki/spec/language/modules.md#import-scope-and-exposure) |
| Visibility | A consumer can name public declarations and inherited fields, cases, nested data and trait requirements. Public signatures must expose consumer-nameable types. Private helpers can implement a public machine or conformance. Nested machines are visible within their lexical scope. A top-level qualified machine head such as `machine f::helper` rejects when `f` is a machine or data carrier or names nothing; a module, trait, named implementation or domain can own one. | [Visibility](../../wiki/spec/language/modules.md#visibility) |
| Lexical scope | A local enters scope after its initializer. Arm bindings end at the arm. Each pattern that introduces a local publishes its binding span at the pattern node. L3 assigns that binding its type. An ordinary bare name in a subject arm introduces a binding even when a constant shares its spelling. A qualified constant pattern selects its declaration. Boolean literals test their values, and subjectless guards read their conditions. See [bare names in dispatch arms](../../wiki/spec/language/patterns.md#bare-names-in-dispatch-arms). Nested helpers can call sibling helpers and use enclosing static binders. Capturing an enclosing machine's runtime parameter rejects. A record shorthand also reads the lexical value it names. A qualified static member retains the lexical binder and member spelling. When another static root is visible, L2 records the competing binder at the prefix. L3 checks eligibility from its normalized bound before selecting a requirement or projecting a callable guarantee. | [Nested machines](../../wiki/spec/language/machines.md#nested-machines-and-identity) · [Resolution](../../wiki/spec/language/modules.md#resolution) |
| Type and value roles | Builtin types, including the open integer spelling family, occupy the type role. A local may have the same spelling in the value role. Redefining a builtin type rejects. Cases use a qualified carrier. Dot-selected fields carry the field spelling for typing. | [Builtin type names](../../wiki/spec/language/modules.md#builtin-type-names) |
| Domains | An attached declaration binds its carrier in its declaring file. The domain head binds each declared index to its own parameter. For a qualified use, each argument list identifies the declaration or binder it applies to. Short carrier-qualified lookup requires that exact carrier and an exposed domain. If a binder and a named carrier share a spelling, L2 records which candidate or access check depends on the binder’s role. The same rule applies to a qualified machine owner. Importing the carrier alone does not expose the domain. A conflict reports the owners, carrier and exposing import locations. | [Foreign attached declarations](../../wiki/spec/language/modules.md#foreign-attached-declaration-paths) |
| Overloads and operators | Distinct operand shapes or named result-domain sets can identify overload candidates. Identical source declaration shapes reject. Operator declarations retain the token, declaring machine, effective visibility and any explicit home or enclosing trait. A qualified home must resolve to one visible declaration. Each binding identifies its operator-token node. L3 infers an implicit home from the typed operands, checks the declaring package for both forms and rejects duplicate normalized bindings. Operator spellings and sites come directly from the indexed L1 syntax. | [Operators](../../wiki/spec/language/expressions.md#operator-declarations) · [Result domains](../../wiki/spec/language/domains.md#result-domain-overloads) |
| Generics | An application binds its selected declaration or candidates to the original argument list. When an argument name has multiple visible bindings, L2 records them in lexical precedence order. L3 uses the receiving declaration’s public parameters and their applied bounds to choose the type or value binding. A qualified generic argument retains the bindings for its head and domains. Qualified paths retain the application on the segment where it was written. | [Generics](../../wiki/spec/language/generics.md) |
| Trait requirements | A selection row such as `Logger::write = write_log;` binds both names. The left side must belong to the implemented trait or one of its parents. The right side must name a machine. Inherited requirements retain their original owner. The handoff exposes each trait’s resolved ancestors by package and path. Every authored row reaches L3, which checks duplicates against the selected requirement overload. Trait inheritance cycles reject during lookup. L3 checks whether an ordinary trait may inherit its resolved parent. | [Conformances](../../wiki/spec/language/conformances.md#implementations-are-operation-records) |
| Assembly | Register and instruction names bind against the supplied vocabulary. A transition binds one visible local assembly continuation and retains its declaration identity. An unavailable target name rejects at its source site. The target checker determines whether the instruction and operands are valid together. | [Parser assembly grammar](../01_tokens-to-syntax-trees/GRAMMAR.md) |

## Handoff to typing and preparation

The compiled interface carries package directories and their public declarations. A client can import a directory containing only private declarations. Lookup orders overloads by declaration identity, so changing the order of compiled exports preserves the result and its diagnostic.

L2 binds an explicitly written machine qualifier at its source span. When a public contract calls an overload, L2 identifies the visible candidates and which are private. L3 checks the one its operands select. A public termination promise may have a private ranking witness. An applied machine such as `id::<u8>` retains its arguments when passed as a static callback. [Package exposure](../../wiki/spec/packages/boundaries.md#exposure-and-declaration-selection)

An exported trait carries the identities of its direct parents. The resolver follows those edges for source and compiled packages. For `Child: Parent<u8>`, it can bind `Child::read` to the requirement declared by `Parent` even after the library's source trees have been released. The checked library carries the applied type `u8`, which L3 uses to check an implementation of that requirement.

An exported domain carries the carrier bound in its defining file. When a library attaches `Point::Ready` to another package's `Point`, a client must have authority to name that same carrier. A same-spelled type in the client cannot redirect the attachment. If an annotated binder can stand for the carrier, L2 preserves its parameter position and the named alternative so L3 can use the binder's checked type.

`Buffer<8>` and `Buffer<4 + 4>` bind to the same `Buffer` declaration. L2 preserves both expressions. Typing and evaluation establish the common closed application identity before a build can persist it or reuse it across stages. The same handoff applies to overload selection by operand type, receiver field lookup, requirement signature matching and operator dispatch. [Build decisions](../../PLAN.md#decision-log)

## Verification

The directory and call tests exercise the same resolver as the stage and corpus tests. Stage fixtures exercise the lexer, parser and public resolver. Multi-file fixtures compare forward and reversed inputs. The provenance invariant checks that declaration references occur exactly once in the returned roster and that source, binder, argument and operator spans point back into the originating files. A 10,000-name expression exercises the iterative tree walk. [Stage fixtures](tests/stage.rs) · [Provenance checks](tests/support/mod.rs)

The corpus test resolves all 132 spec fragments individually with an empty dependency graph and target vocabulary. It compares the result for each fragment with a checked-in expectation. 38 bind successfully and 94 report the expected first error. Many examples intentionally omit the surrounding declarations. A successful result here establishes name binding only. [Corpus test](tests/spec_corpus.rs) · [Expected results](fixtures/spec-outcomes.txt)
