# L3 Typer

L3 checks the declarations and expressions in one resolved Omega stage. Its product records what each expression means, which declarations were selected and which facts later layers must establish. The command `omega source type <file> [<file> ...]` uses this library. Success is silent. A refusal identifies the package-relative file, line, column and source operation.

Follow [the stage driver](src/typing/type_stage.rs) for pass order, [call selection](src/expressions/calls.rs) for overload resolution, and [the typed stage](src/typed_tree/typed_stage.rs) for the product handed to later layers.

## Stage boundary

L3 is locked after review of the static integer handoff on 2026-11-19. The original signoff was at `4baf1e5f5e9`. L3 publishes the selected call, its operands, the destination carrier and any closed owner arguments before L4 computes the value. A computation needed to finish typing is marked pending. Resuming with evaluated values rechecks the original package, including comparisons that require a closed identity. The ordinary type command retains its missing-result diagnostic.

The producer tests inspect the selected declaration and operands at the requested node. The consumer tests change each overload body independently and check that only the selected body changes the resulting index. Two constant initializers at the same span and node number in different files also produce their own values in either input order. [Typed handoff tests](tests/exposure.rs) · [Overload selection tests](../04_typed-trees-to-prepared-trees/tests/closed_indices.rs) · [Constant occurrence tests](../04_typed-trees-to-prepared-trees/tests/integer_constants.rs)

L2 supplies the packages each requester may select from. L3 applies that authority when a typed receiver identifies a field or operator. A value returned through a dependency can still be carried when the caller has no direct dependency on its type's owner. L3 checks the visibility of the overload chosen in a public contract and preserves an explicitly applied static callback's arguments through signature refinement and invocation. [Package selections](../../wiki/spec/packages/boundaries.md#selection-versus-carrying-a-type)

Supply the `SymbolResolvedTrees` issued by L2 to `type_stage`. L3 reads the indexed nodes and bindings directly. L2 owns lexical scope, visibility and candidate identity. L3 uses a parameter’s normalized bound to select a visible type or value at a generic argument. It classifies equality from the bound operands and reports a mixed type and value at the equality expression. L3 indexes signatures across files before checking bodies. Each declaration with generic parameters owns an ordered list of their kinds, normalized bounds and multiplicity restrictions. That declaration also owns its private witness count and type equations. Selection, specialization and conformance consult this record. `type_stage_for_target` additionally takes the admitted instruction signatures and register types. `type_stage_in_environment` also accepts the exact admitted access-plan requirement and ranking views. The CLI passes the admitted `SourcePackage` directly to `type_source_package`. The standard package profile owns admission. Raw L2 inputs must also respect the package identity reserved for sealed collection operations. The [toolchain package profile](../../toolchain/src/lib.rs) supplies the standard exports and [library declarations and predicates](../../toolchain/core/). L3 checks the bundled Omega declarations once. Each importing package shares the checked machine signatures, ordered record fields and inferred machine effects. Calls in the importing package specialize the library’s pause, reach and synchronous invocation effects at the call site. A signature includes its precondition and guarantee flags, declared pause, reach and crash bounds, termination, and the exact requirement the machine satisfies. Source-local expression requests stay with their producing forest. The source stage retains the library’s typed forest in `TypedStage::library`, where each predicate has its own resolved operands and typed operations. A Build can additionally supply target instructions and the directions of applied boundary slots. [Resolver contract](../02_syntax-trees-to-symbol-resolved-trees/CONTRACT.md) · [Typed trees](src/typed_tree/typed_trees.rs)

L3 normalizes anonymous arithmetic, literal integer constants and primitive expressions over static binders. It records each constant’s initializer node and carrier, the exact value of a numeric landing, and the selected declaration at a constant reference. Constant initializers and static indices both require effect-free calls. An expression that requires running a machine crosses the preparation boundary. The typed tree records the selected machine and operands at its call node. A deferred index carries that node and its owner’s substitutions. The type command reports a missing evaluation result when closing the application requires a value.

The static-index checker matches supplied results to checked requests. Each request discovered during typing keeps its node in the resolved forest. The stage environment supplies results by exact node in the resolved forest and destination carrier. Specialized results also identify the closed owner arguments. The source site accompanies the node for diagnostics. Each supplied result must match a static index in the typed program. A field uses the arguments of its enclosing data declaration. A nested data declaration includes its outer arguments in that tuple. L3 checks static expressions with the ordinary typer, including calls found inside generic arguments. It retains each selected type application through alias normalization and checks its integer widths and intermediate results once declaration typing is complete. Open widths produce a positivity obligation at the type occurrence. A closed use also checks the applications made by its fields. When a recursive edge changes the arguments of a declaration with formation requirements, L3 checks the next application’s local constraints and hands its exact arguments to the verifier in `FormRecursiveApplication`. Preparation owns execution of the selected body under its admitted contract. [Applications and specialization](../../wiki/spec/language/generics.md#applications-and-specialization) · [Closed application identity](../../wiki/spec/language/generics.md#closed-applications-and-canonical-identity)

A downstream pass can walk `TypedTrees::trees` in file order, visit a node's children in source order, and use `semantics_at` to inspect its expression type, selected calls and operations. Each record identifies the exact node in its file. Each selected call pairs its formal parameters with actual operand nodes, source sites, value subjects and any known callback targets. A consumer uses `TypedCall::instantiate` to substitute the static arguments and those value subjects in a fact from the declaration. Record fields retain their declaration, source site and declared type in order. A field access identifies its selected declaration at the access node. A collection's length or address access records the selected metadata operation with the descriptor's type at the same node. Place typing carries the access and backing storage through each field and collection receiver. The selected parameter determines whether a borrowed field supplies a loan or requires a value read. An omitted field carries that declaration and its instantiated type to the checker. Proof obligations retain their source sites. The [handoff test](tests/source_package_order.rs) releases the parser products before typing, then uses the typed result alone to inspect both arms of a match, the selected overload, its operand and an indexing precondition.

| Calls | Select using typed operands and the destination's normalized result domains. Check the selected result against the destination's carrier. Retain declaration, static arguments, enclosing substitutions, evidence and acknowledgements. Reject ambiguous or duplicate normalized signatures. A reference argument or operand must match its parameter exactly: whether a copy read may admit `v: @u8` at `take(n: u8)` or `v + 1u8` is an [open owner question](../../../OWNER_QUESTIONS.md#open-questions). | [Expressions](../../wiki/spec/language/expressions.md) · [Result-domain overloads](../../wiki/spec/language/domains.md#result-domain-overloads) |
| Numbers and operators | Preserve literal suffixes. Fold wholly anonymous arithmetic as exact rationals. Check range, integrality and fractional-history acknowledgement at landing. Retain operand and result carriers, including cross-width comparisons, and the contract of each typed arithmetic operation. Preserve an explicitly selected trait or domain operator. An unqualified operator takes its home from a unique domain on its normalized operands. Nested type arguments contribute no operand-domain constraint. | [Numeric values](../../wiki/spec/language/numeric_values.md) · [Operator declarations](../../wiki/spec/language/expressions.md#operator-declarations) |
| Applications | Normalize transparent aliases and closed widths. A direct or aliased binder kind selects the same type arguments and enforces the same universe level. Infer type parameters and array extents structurally, retain symbolic widths, require positive widths and check multiplicity bounds. Resolve captured owner arguments for nested data and indexed domain equations. | [Generics](../../wiki/spec/language/generics.md) · [Width-indexed integers](../../wiki/spec/language/numeric_values.md) |
| Data and bindings | Refuse an unannotated binding or constant whose initializer holds an unsuffixed number, such as `let count = 5;` or `const pair = (5, 6);`, even when a later call would supply a type. A match arm binder is refused the same way at its subject, as in `match 5 { a -> send(a), }`. Check fields, shorthand, omissions, case payloads, arrays, local mutability and annotated constants. Infer concrete constant types through forward references. Local record construction can infer omitted lifetime arguments. L3 checks that record and case fields have a uniform representation in each hidden type, including the inputs and result of a stored callable. Construction infers one sized witness for each hidden type. Opening the record ties its witnesses to the subject and storage version. [Packages](../../wiki/spec/language/some_packages.md) · [Lifetimes](../../wiki/spec/language/lifetimes.md). | [Data and literals](../../wiki/spec/language/data_and_literals.md) · [Literal landing](../../wiki/spec/language/numeric_values.md#literal-landing-and-destinations) · [Generics](../../wiki/spec/language/generics.md) |
| Patterns and places | Check arm result types, Boolean and case coverage, tuple patterns and case-field access. A value pattern on a readable reference subject compares the referent and records the copy read at the subject, as in `match v { true -> 1, false -> 0, }` with `v: @bool`. Preserve assignment authority, lifetime and borrow occurrences. Carry each value's storage origin through bindings, patterns, moves, casts, construction and projections, and reject a returned reference that may expose invocation-local storage however it is spelled. A binding that a pattern takes from borrowed storage names that storage in place. Reading a field out of borrowed storage, by selection, by a pattern binding or by comparing a dispatch subject, requires a copy type and records the copy read where it happens; a non-copy field needs an explicit borrow, or an explicit or implicit move-out through `@mut`. For a non-copy move through `@mut`, L3 emits `RestoreBorrowed` at the value read. Its typed place identifies the evaluated receiver, reference crossings and field declarations, including a place captured by a pattern. The checker proves restoration on the required paths. A dispatch or destructuring `let` inspects its subject in place. | [State contracts](../../wiki/spec/language/state_contracts.md) · [Ownership](../../wiki/spec/language/ownership.md) |
| Domains | Use the normalized binder kind to select the applicable declaration and check access to its carrier. Follow the selected declaration when ordering definitions. Normalize the applied carrier and compare it with the subject. Carry the resolved parent declaration and its arguments through inheritance, including imported parents. Check written ancestor arguments against the inherited application. Check membership against its carrier, require an explicit domain cast with complete accounting, and record establishment obligations. Preserve indexed domain arguments at calls. | [Domains](../../wiki/spec/language/domains.md) |
| Evidence and effects | Check direct and inherited conformance signatures, selected rows, missing rows, explicit satisfaction edges and static callback bounds. An inferred callback takes its bound from the receiving callable parameter. L2 supplies the argument list and visible names for each argument. L3 selects the value binding in a callable slot. For a static member call, the normalized binder type determines whether the member names an inherited requirement or projects a callable guarantee. A trait token requires one applicable evidence binder. Transparent refinement checks selected rows against its reach and pause ceilings and retains proof obligations. Infer finite service reach, pause effects and synchronous callback entries through calls. Preserve the identity of forwarded runtime and static callback parameters. Record crash causes, typed route guards and coverage obligations. | [Conformances](../../wiki/spec/language/conformances.md) · [Effects](../../wiki/spec/language/effects.md) |
| Collection access | Select the authorized core element read, borrow or range declaration. Attach the selected declaration and result to the index node and emit its precondition. The node retains the collection and selector. L1 supplies the written endpoints and inclusive spelling. An indexed write requires exclusive access. A by-copy read requires a copy element. Authored bracket operations adapt the collection operand to an authorized shared or exclusive borrow and reject competing selections. | [Collection access](../../wiki/spec/language/expressions.md) · [Primitive contracts](../../toolchain/core/indexing.omg) |
| Cleanup | Select an exact machine that consumes one owned carrier and returns no value. Reject competing selections on one qualified subject and declared pause or crash behavior incompatible with cleanup. | Access plans and progress | Check the selected policy implementation against the Build-admitted plan requirement. Retain its domain, arguments, plan machine and evaluation obligation. | Mathematical terms and assembly | Check explicit and inferred generic arguments on mathematical definitions. Check the register identities supplied by L2 and instruction operands against the supplied target model. Retain the selected target and typed instruction operands. | [Mathematical bindings](../../wiki/spec/proofs/mathematical_bindings.md) · [Machines](../../wiki/spec/language/machines.md) |

## L3 handoff and cross-layer verification

A `terminates by` clause exposes its selected view and the type of rank that view produces through `semantics_at`. The clause’s syntax identifies the subject, view arguments and ordered bounds. Consumers can walk those nodes to retrieve their typed expressions and literal destinations. A bare `terminates` clause carries the promise alone. [Ranking witness tests](tests/calls/contracts_and_effects.rs) · [Standard ranking views](tests/standard.rs)

A consumer walking a typed tree can ask the producing node for its proof obligations and its selected assembly instruction. This distinguishes expressions from enclosing syntax with the same source span. Obligations imported from a checked library belong to the library’s typed forest. [Typed tree consumer tests](tests/source_package_order.rs) · [Assembly handoff](tests/calls/assembly.rs)

A static integer evaluation request identifies the exact expression node and its carrier. Preparation can follow that node to the selected machine or operator. L3 checks that a returned value matches a requested expression, carrier and specialization. A selected generic callback must satisfy its own binders before L3 checks its applied signature and requirement against the receiving callback slot. [Evaluation interface tests](tests/standard.rs) · [Callback handoff tests](tests/exposure.rs)

L3 checks operator ownership against the normalized operands at the declaration. Importing a checked library preserves operator visibility and the operators a local trait inherits from it. Typing an integer index through an inherited trait retains the evidence binder and the selected declaration for preparation. [Checked-library equivalence tests](tests/support/checked_library.rs)

When a client calls a guarded library machine, `crash_route` retrieves the guard from the typed tree where it was declared. If a library machine forwards a callback supplied by the client, `guarded_invocation` retrieves the invocation and operands from the library. The specializing call identifies where the client supplied that callback. [Direct and forwarded library calls](tests/support/checked_library.rs)

- **Dependent applications.** For a closed integer index, the applied type uses the value and carrier as its key. An open index retains its typed computation. A trait-selected operator retains the evidence binder. During type formation, only operators declared by the bound trait or its ancestors can defer primitive arithmetic through that binder. L3 checks operand types and refuses missing or conflicting closed evaluation results. General proof-static execution and publication of the resulting identity belong to L4. [Index representation](src/evaluation/integer_index.rs) · [Evaluation interface tests](tests/standard.rs) · [Evaluation spec](../../wiki/spec/language/evaluation.md)
- **Mathematical evidence.** L3 checks binders, dependent arrows, strict propositions, universe levels and machine-shaped logical hypotheses. It records premise and conclusion sites, expected evidence types, assumption dependencies and proof obligations. A named theorem or projected evidence field can supply a hypothesis. The checker must still prove the implication and discharge any assumptions. The witness theorem test checks the complete published signature and its goal. [Hypothesis checking](src/contracts/logical_hypotheses.rs) · [Mathematical tests](tests/calls/mathematical_evidence.rs) · [Mathematical bindings](../../wiki/spec/proofs/mathematical_bindings.md)
- **Policies, cleanup, ranking and callbacks.** The CLI resolves the standard core access and ranking declarations by package identity. L3 selects the implementation and emits obligations for policy evaluation, cleanup and termination. Each guarded call references its crash route and the direct or indirect call that supplies its operands. A forwarded callback also references the call that supplies its implementation. An imported crash route and an indirect invocation in a checked library keep indices in their producing forest. The client retains the call that supplies the callback. The enclosing body, proof clause or static argument determines how L3 records a call. Effect inference uses one graph of executing calls to propagate reach, pause and synchronous invocation, and to connect guards to their callers. Build supplies provider direction for an applied slot. Execution of access plans, proof of cleanup and termination, and crash coverage in a running program need subsequent stages.
