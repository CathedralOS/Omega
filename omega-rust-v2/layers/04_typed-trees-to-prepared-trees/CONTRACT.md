# L4 Preparation

Preparation evaluates the static values a package needs and hands their typed values to later compiler stages. For example, if `enabled()` returns true, `Flag<enabled()>` and `Flag<true>` share an identity. Changing the body to return false makes a return or call that requires `Flag<true>` fail at that use. [Static identities](../../wiki/spec/language/evaluation.md#canonical-static-identities) · [Consumer tests](tests/closed_indices.rs)

L3 supplies the typed occurrence, its result type, the selected machine, its operands and any closed specialization arguments. L4 evaluates that request and returns its owned value. L3 then checks the identities of the original package with those answers. Integer and Boolean computations over generic parameters retain their recipes until the required arguments are known. [Preparation entry point](src/lib.rs) · [Typing handoff](../03_symbol-resolved-trees-to-typed-trees/src/typing/typing_progress.rs)

A prepared constant can contain an integer, a Boolean, a fixed array, a record or a sum case. L3 supplies the chosen constructor, exact case, applied field types and initializer positions. L4 evaluates field expressions in source order and stores their values in declaration order. Eligibility covers the complete type, including inactive payloads. A quoted byte literal in a fixed byte array copies its decoded bytes when the length matches. Preparation follows named dependencies, rejects cycles and checks unused constants as well. [Frozen values](src/owned_values.rs) · [Records, cases and byte arrays](tests/owned_records.rs)

For the supported operations, L4 evaluates selected calls on a heap stack, checks their arguments against their preconditions and checks every declared crash alternative. Each primitive also checks the concrete operation it executes. Boolean short-circuiting and Boolean dispatch evaluate only the chosen operand or arm. A repeated call on the active path needs checked termination evidence. Integer arithmetic uses the same primitive meanings as static index formation. A value that fits a wide carrier can be prepared without constructing its endpoints. [Call admission](src/invocation/admission.rs) · [Control flow](src/invocation/statements.rs) · [Arithmetic tests](tests/integer_constants.rs)

For a closed fixed-array parameter, lowering needs the element type and concrete element count. The prepared signature carries both in `ValueType::Array`. A test consumer reads this signature and emits the Psi fixed-array shape using fixture element type IDs. Changing the selected body changes the emitted length for a direct extent and a named constant. An exact overflow prevents preparation from handing off a product. Production lowering and type ID assignment remain open. [Consumer test](tests/closed_indices.rs) · [Psi structural type encoding](../../wiki/spec/terminal-psi/encoding.md)

Build can pass its selected boundary slots to `prepare_source_package_with_boundary_slots`. Preparation preserves the directions through typing retries. A runtime boundary cannot execute to compute a static integer. [Preparation entry point](src/lib.rs) · [Boundary tests](tests/closed_indices.rs)

Run `omega source prepare <files>` from the package root. The command reports an evaluation or typing refusal with the source location. Successful preparation exits silently. The [corpus test](tests/spec_corpus.rs) checks all 132 published fragments and separately supplies the type omitted by the published constants example so it can verify the resulting values.

## Remaining scope before signoff

- **Invocation admission.** Consume the proof and effect evidence for selected callees, including general proof predicates for crash routes, mutable and recursive bodies, and selected providers. Check termination, resource sponsorship and trust for the demanded computation. L4 can test its admission decisions with supplied evidence. Verifying actual charges against the checked Psi operations requires later integration. L5 and L6 remain at probe scope. [Admission and termination](../../wiki/spec/language/evaluation.md#invocation-admission)
- **Owned values.** Prepare eligible scalars and composite constants, including floating-point values with target-selected semantics and types that require proof of eligibility. Hand off their semantic values and the evidence needed when a consumer requests runtime materialization. [Constant materialization](../../wiki/spec/language/constants.md#materialization)
- **Target dependencies.** Preserve symbolic applications while target inputs are open. For the specified core queries `size_of<T>()` and `align_of<T>()`, L4 needs the exact target and validated layout selected for `T`. A dynamic layout may determine alignment while leaving size open. Record the observations and selected realizations that affected the value, including a selected provider whose body returns a literal. The [layout query specification](../../wiki/spec/layouts/plans.md#size-and-alignment-queries) fixes these two source forms. The source API for an address-space bound remains open. [Target-semantic capsule](../../wiki/spec/language/evaluation.md#target-semantic-capsule)
- **Frozen stage.** Supply lowering with the prepared values and identities for all closed demands and retain the recipes for open applications. Carry the semantic dependencies and usage evidence required for reuse and publication. Check each handoff with a consumer that uses the carried result.
