# L4 Preparation

L4 computes the values that typing and lowering need. It consumes L3's selected calls, typed operands, constant initializers and application arguments. Its frozen product carries the typed package, owned constants, closed static identities and the inputs that determined them. For example, a machine returning `3u64` can determine an array extent. Lowering can read the element type and count directly from the prepared signature. [Frozen handoff](tests/frozen_handoff.rs) · [Fixed-array consumer](tests/closed_indices.rs)

## Typing and target closure

L3 publishes the operations ready to evaluate. L4 returns an answer for the exact source occurrence and enclosing arguments. L3 uses those answers to finish overload selection and check type identities. One field recipe can therefore yield different identities for two closed applications. The public preparation round accepts checked evidence for its immutable typing pass and collects each result into the same frozen product as ordinary source preparation. [Preparation rounds](src/lib.rs) · [Pass results](src/typing_pass.rs)

When a public type depends on an unselected target, the open package carries the provisional typed forest, pending requests, settled answers and their dependencies. Selecting a target resumes these requests. An otherwise complete package can retain an open constant's typed initializer. L4 takes `size_of<T>()` and `align_of<T>()` from the selected layout for exactly `T`. A dynamic extent can still have known alignment. A checker receipt can also record the exclusive bound of an address space, the endianness of a selected layout or the stack guarantee of a selected entry profile. These typed inputs retain their exact subjects and versions. [Layout tests](tests/target_layout.rs) · [Layout queries](../../wiki/spec/layouts/plans.md#size-and-alignment-queries)

## Invocation admission

L4 specializes the selected body's published effects and checks the obligations for the actual operands. It rejects runtime service reach, suspension, blocking, escaping mutation and unhandled crash routes. A private scalar local can change inside the invocation. Preconditions and crash guards run before the body, and postconditions check its result. Proofs supplied by the checker must identify the typed occurrence, body, concrete application and the operands or result they justify. A changed target plan invalidates dependent proofs even when the value is unchanged. [Calls and contracts](src/invocation/admission.rs) · [Boolean calls](tests/boolean_calls.rs) · [Invocation admission](../../wiki/spec/language/evaluation.md#invocation-admission)

A static callback selects an ordinary machine at a closed application. Its caller must respect the callback bound, and the selected body must satisfy its own contract. A provider selected for an outbound boundary needs the checked requirement-to-implementation mapping and the matching target selection. The package records that selection even when the implementation returns a literal. [Static callbacks](tests/static_callbacks.rs) · [Provider evidence](src/invocation/admission/providers.rs)

Acyclic local calls can establish termination from their closed call graph. A recursive component requires a checked ranking covering the actual members, specializations and internal calls. L4 validates the certificate's applicability at entry, including when the invocation will take the base case. Tests supply a single countdown, a two-machine cycle with one rank-preserving edge, and two independent recursive groups. [Termination tests](src/invocation/termination/tests.rs) · [Termination and sponsorship](../../wiki/spec/language/evaluation.md#termination-and-sponsorship)

A bounded preparation compares a certified ceiling for the exact inputs with the root's grant before evaluating any demand. Work and peak live cells must each fit. The frozen package retains the grant, checked subject, work-schedule version and certified maxima. The checker owns the judgment establishing those maxima. [Sponsorship](src/sponsorship.rs) · [Logical work](../../wiki/spec/resources/logical_work.md)

## Frozen values and reuse

L4 evaluates integers, Booleans, floating-point values, fixed arrays, tuples, records and sum cases. It walks the complete type for copy eligibility, including inactive payloads, and stores the active record or case fields in declaration order. The target selects floating operations. An unspecified NaN can survive evaluation, but materializing it reports the active component and its producer. A constrained construction and a canonical type index require separate judgments. [Frozen values](src/owned_values.rs) · [Record tests](tests/owned_records.rs) · [Float tests](tests/owned_floats.rs) · [Constants](../../wiki/spec/language/constants.md)

Named reads connect each prepared constant or static index to the constants it consumed. A target observation identifies the subject, projection and selected plan or realization. A provider that returns a literal still depends on its selection. A materialization request checks the package's recorded observations under the given target, then pairs the value with the selected layout for its declared carrier. The receiving layer owns field placement and byte emission. [Dependencies](src/dependencies.rs) · [Materialization](src/materialization.rs) · [Target-dependent applications](../../wiki/spec/language/evaluation.md#target-dependent-applications)

## Evidence at the layer boundary

The L4 handoff was signed off on 2026-11-19 after the 151 preparation tests passed. The preparation tests supply checked judgments bound to an actual typed forest. They exercise successful and refused outcomes through the public preparation round. In the ordinary source command, the absence of a required judgment produces a refusal. Producing portable checker certificates, selecting validated target plans in Build, and emitting a Psi or native program are separate integration milestones. [Preparation evidence](src/typing_pass.rs) · [Sponsored recursive invocation](src/sponsorship.rs) · [Callable contracts](src/invocation/static_callbacks.rs)

`omega source prepare <files>` reports typing or evaluation refusals at their source locations. The producer and consumer tests run directly against the V2 preparation crate. The [spec corpus test](tests/spec_corpus.rs) reports which published fragments it covers.
