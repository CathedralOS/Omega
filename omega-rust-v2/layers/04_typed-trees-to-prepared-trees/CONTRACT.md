# L4 Preparation

Preparation freezes local Boolean and fixed-width integer values and fixed arrays of those values. It computes the integers used in closed type identities. If the selected `width` adds one, `const SIZE:u8 = width(7)` freezes at 8. Both `Buffer<SIZE>` and `Buffer<width(7)>` then have the same identity as `Buffer<8>`. Changing the body to add two changes both computed indices to 9. [Static identities](../../wiki/spec/language/evaluation.md#canonical-static-identities) · [Constant and index tests](tests/integer_constants.rs)

`prepare_source_package` drives typing of one admitted package. For a pending integer computation, L3 identifies the expression node, result carrier, selected machine, actual operands and any closed specialization arguments. L4 checks whether it supports that invocation, evaluates it, and returns the value for that request. L3 then rechecks the original resolved package. `PreparedTrees` is returned only when strict typing has accepted the resulting identities. Open generic templates still describe computations for future specializations. [Preparation entry point](src/lib.rs) · [Typed handoff](../03_symbol-resolved-trees-to-typed-trees/src/typing/typing_progress.rs)

L3 supplies each constant’s typed initializer, its numeric landings, and the declaration selected at each constant reference. L4 follows those references, including forward references, and refuses cycles. Preparation checks every local initializer even when no type mentions it. Unsupported values refuse preparation. A consumer can read a frozen value by declaration using `PreparedTrees::constant`. A fixed array carries its elements in index order. Boolean operations short-circuit where their selected operator requires it. [Constant evaluation](src/constant_evaluation.rs)

The evaluator handles plain signed and unsigned integer carriers 1 through 128 bits wide, exact numeric landings, and local direct calls with a single return expression. It evaluates addition, subtraction, multiplication, division and remainder using the primitive and overflow policy that L3 selected at each node. Exact results must fit, wrapping reduces modulo the carrier width’s power of two, and saturation clamps to the carrier’s endpoints. Integer quotient truncates toward zero. Every division and remainder needs a nonzero divisor, and exact remainder also requires a representable quotient. [Integer arithmetic](src/integer_arithmetic.rs) · [Numeric specification](../../wiki/spec/language/numeric_values.md#integer-quotient-and-remainder)

A closed call may take the enclosing machine’s single specialized integer parameter. Before executing its return expression, L4 checks each supported `requires` clause against the bound operands. A primitive integer comparison uses each operand’s selected carrier and compares the mathematical values. A machine may return a direct call to another local integer machine. L4 evaluates the operands in the caller, binds them to the selected helper, and checks its contract before continuing. For a machine with declared crash causes, L4 joins each typed route to its guard in the defining tree and evaluates it with the entry arguments. Every alternative for each cause must be false. The body still checks the divisor and quotient for trapping division and remainder. A repeated declaration on this path requires a termination proof. A failed helper reports its call site and the chain from the original invocation. A predicate outside this fragment requires further proof support. [Evaluator](src/integer_invocation.rs) · [Invocation admission](../../wiki/spec/language/evaluation.md#invocation-admission)

For a closed fixed-array parameter, lowering needs the element type and concrete element count. The prepared signature carries both in `ValueType::Array`. A test consumer reads this signature and emits the Psi fixed-array shape using fixture element type IDs. Changing the selected body changes the emitted length for a direct extent and a named constant. An exact overflow prevents preparation from handing off a product. Production lowering and type ID assignment remain open. [Consumer test](tests/closed_indices.rs) · [Psi structural type encoding](../../wiki/spec/terminal-psi/encoding.md)

Build can pass its selected boundary slots to `prepare_source_package_with_boundary_slots`. Preparation preserves the directions through typing retries. A runtime boundary cannot execute to compute a static integer. [Preparation entry point](src/lib.rs) · [Boundary tests](tests/closed_indices.rs)

Run `omega source prepare <files>` from the package root. The command reports an evaluation or typing refusal with the source location. Successful preparation exits silently.

## Remaining scope before signoff

- **Invocation admission.** Consume the proof and effect evidence for selected callees, including calls inside arithmetic operands or predicates, general proof predicates for crash routes, and selected providers. Check termination, resource sponsorship and trust for the demanded computation. L4 can test its admission decisions with supplied evidence. Verifying actual charges against the checked Psi operations requires later integration. L5 and L6 remain at probe scope. [Admission and termination](../../wiki/spec/language/evaluation.md#invocation-admission)
- **Owned values.** Prepare eligible scalars and composite constants, including further numeric carriers, records and active sum cases. Hand off their semantic values and the evidence needed when a consumer requests runtime materialization. [Constant materialization](../../wiki/spec/language/constants.md#materialization)
- **Target dependencies.** Preserve symbolic applications while target inputs are open. Evaluate closed target-dependent requests using the validated target information and record which observations and realizations affected the value. [Target-semantic capsule](../../wiki/spec/language/evaluation.md#target-semantic-capsule)
- **Frozen stage.** Supply lowering with the prepared values and identities for all closed demands and retain the recipes for open applications. Carry the semantic dependencies and usage evidence required for reuse and publication. Check each handoff with a consumer that uses the carried result. [Canonical identities](../../wiki/spec/language/evaluation.md#canonical-static-identities) · [Result and usage evidence](../../wiki/spec/language/evaluation.md#result-caching-and-published-evidence)
