# L5 handoff evidence

L5 stays open. A test can pass because the compiler refused a valid program at a known line. The tables distinguish those cases from sources whose lowered Psi can already be inspected. The seventeen pinned sample configurations currently produce eight witnessed Psi packages and nine required rejections before L5. One of those packages, `false-abstract-premise-v2`, still expects an L6 refusal that no checker has run. [Sample expectations](tests/sample_baseline/observations.tsv)

The [decision map](DECISIONS.md) records the decision, owner and distinguishing control for each of the 31 cases open at the start of the November 21 pass.

## What a consumer can distinguish

Run `mbx test --locked -p omega-lowering --no-fail-fast -- --include-ignored` to collect failures across L5 test binaries. The [field-read acceptance tests](tests/field_read_acceptance.rs) require valid programs to produce Psi. They inspect the returned field, its receiver, the chosen branch or call operands, and the edge that disposes an owned receiver. A lowering refusal fails the corresponding case. Existing diagnostic fixtures elsewhere still include known limitations, so the total failure count covers the acceptance cases exercised by this run.

## Typed obligations to reconcile before sign-off

Its summary counts examples that stopped before L5, fragments missing package context, declarations and executable products separately. The workspace test requires the recorded outcome for each example. The readiness report counts each open lowering gap as a blocker, including those whose diagnostic matches the baseline.

## What the tests caught

The [negative controls](tests/negative_controls.rs) run in the normal suite. Each control lowers the source of a positive test and checks that the test's witness accepts the actual Psi. It then applies one corruption that still passes the graph check and requires the same witness to reject it. The witnesses live in [`product_witness`](tests/psi-consumer/src/product_witness.rs) and are shared with the positive tests, so weakening one fails its control. The controls swap the branch targets of a returned-input match and swap the two arms of the branch that selects a runtime-dispatch descriptor. In the dispatch control, the call keeps its contract and argument types. Only the witness's assignment of formals to edges can see that `flag` false now invokes `right`. Other controls swap two equal-typed boundary scalars and turn a restoring store into an unrestricted or disposing replacement. They point residual cleanup at the transferred field or the whole root, or drop it. They dispose an arm's remainder before a join or move the same field in both arms. Finally, they flip or bypass the entry clause that justifies a premised element store. Each control prints `OMEGA_NEGATIVE_CONTROL` under the layer report. The readiness runner checks the 19 labels registered in [`product_controls.py`](../../tools/spec-corpus/product_controls.py): a label counts only from its own passing test, and a passing test without its line is a measurement error. The graph controls also exercise a duplicate operation ID and a result pointing back to a different operation. The positive tests run against the correct product in the normal suite.
