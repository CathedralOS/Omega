# L5 handoff evidence

L5 stays open. A test can pass because the compiler refused a valid program at a known line. The tables distinguish those cases from sources whose lowered Psi can already be inspected. The ten pinned sample configurations currently produce three witnessed Psi packages, six diagnostics before L5 and one missing Build configuration. [Sample expectations](tests/sample_baseline/observations.tsv)

## What a consumer can distinguish

Run `mbx test --locked -p omega-lowering --no-fail-fast -- --include-ignored` to collect failures across L5 test binaries. The [field-read acceptance tests](tests/field_read_acceptance.rs) require valid programs to produce Psi. They inspect the returned field, its receiver, the chosen branch or call operands, and the edge that disposes an owned receiver. A lowering refusal fails the corresponding case. Existing diagnostic fixtures elsewhere still include known limitations, so the total failure count covers the acceptance cases exercised by this run.

## Typed obligations to reconcile before sign-off

The [spec corpus test](tests/spec_corpus.rs) runs each published example independently and reports all observed L5 open gaps and unexpected outcomes together. Its summary counts examples that stopped before L5, fragments missing package context, declarations and executable products separately. The workspace test requires the recorded outcome for each example. The readiness report counts each open lowering gap as a blocker, including those whose diagnostic matches the baseline.

The prepared package exposes the following [typed obligation kinds](../../representations/typed/src/typed_tree/proofs/obligation_kind.rs). Some facts reach Psi through a declaration, type or edge. A row below identifies a place to verify that meaning. A nearby positive test alone cannot close all the obligations on its row.

## What the tests caught

The [negative controls](tests/negative_controls.rs) run in the normal suite. Each control lowers the source of a positive test and checks that the test's witness accepts the actual Psi. It then applies one corruption that still passes the graph check and requires the same witness to reject it. The witnesses live in [`product_witness`](tests/psi-consumer/src/product_witness.rs) and are shared with the positive tests, so weakening one fails its control. The controls swap the branch targets of a returned-input match and swap two equal-typed boundary scalars. They also turn a restoring store into an unrestricted or disposing replacement. Finally, they point residual cleanup at the transferred field or the whole root, or drop it. Each control prints `OMEGA_NEGATIVE_CONTROL` under the layer report, but the readiness runner does not yet require these lines. Earlier manual checks also corrupted the runtime-dispatch branch in [dispatch](tests/runtime_callable.rs). That check is not automated. The graph controls also exercise a duplicate operation ID and a result pointing back to a different operation. The positive tests run against the correct product in the normal suite.
