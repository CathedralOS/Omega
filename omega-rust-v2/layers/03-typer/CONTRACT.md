# L3 Typer

L3 checks the declarations and expressions in one resolved Omega stage. Its product records what each expression means, which declarations were selected and which facts later layers must establish. The command `omega source type <file> [<file> ...]` uses this library. Success is silent. A refusal identifies the package-relative file, line, column and source operation.

## Stage boundary

Supply the same admitted files and resolution result to `type_stage`. L2 owns lexical scope, visibility, candidate identity and the meaning of names. L3 indexes signatures across files before checking bodies. `type_stage_for_target` additionally takes the admitted instruction signatures and register types. `type_stage_in_environment` also accepts the exact admitted access-plan requirement and ranking views. The CLI has no target or Build vocabulary. [Resolver contract](../02-resolver/CONTRACT.md) · [Typed product](src/model.rs)

`type_stage_with_evaluator` can obtain a closed proof-static integer from the evaluator for the current stage. L3 checks its expression, carrier and representability before returning the product. Identical normalized arguments identify the same applied type. Evaluation receipts retain the source occurrence separately. Without an evaluator, closed anonymous arithmetic such as `4 + 4` still works. The CLI reports a computation that needs L4 at its source location. ## Checked rules

| Subject | What L3 checks and retains | Governing specification |
| --- | --- | --- |
| Calls | Select using typed operands and the destination's normalized result domains. Check the selected result against the destination's carrier. Retain declaration, static arguments, enclosing substitutions, evidence and acknowledgements. Reject ambiguous or duplicate normalized signatures. | [Expressions](../../wiki/spec/language/expressions.md) · [Result-domain overloads](../../wiki/spec/language/domains.md#result-domain-overloads) |
| Numbers and operators | Preserve literal suffixes. Fold wholly anonymous arithmetic as exact rationals. Check range, integrality and fractional-history acknowledgement at landing. Retain operand and result carriers, including cross-width comparisons, and the contract of each typed arithmetic operation. Preserve an explicitly selected trait or domain operator. | [Numeric values](../../wiki/spec/language/numeric_values.md) · [Operator declarations](../../wiki/spec/language/expressions.md#operator-declarations) |
| Applications | Normalize transparent aliases and closed widths. Infer type parameters and array extents structurally, retain symbolic widths, require positive widths and check multiplicity bounds. Resolve captured owner arguments for nested data and indexed domain equations. | [Generics](../../wiki/spec/language/generics.md) · [Width-indexed integers](../../wiki/spec/language/numeric_values.md) |
| Data and bindings | Refuse an unannotated binding or constant whose initializer is an unsuffixed number, such as `let count = 5;`, even when a later call would supply a type. Check fields, shorthand, omissions, case payloads, arrays, local mutability and annotated constants. Infer concrete constant types through forward references. Construct existential records from consistent witnesses and keep opened witnesses tied to their subject and version. | [Data and literals](../../wiki/spec/language/data_and_literals.md) · [Generics](../../wiki/spec/language/generics.md) |
| Patterns and places | Check arm result types, Boolean and case coverage, tuple patterns and case-field access. Preserve assignment authority, lifetime and borrow occurrences. Reject a return that directly exposes invocation-local storage or its projections. | [State contracts](../../wiki/spec/language/state_contracts.md) · [Ownership](../../wiki/spec/language/ownership.md) |
| Domains | Normalize aliases and ancestry. Check membership against its carrier, require an explicit domain cast with complete accounting, and record establishment obligations. Preserve indexed domain arguments at calls. | [Domains](../../wiki/spec/language/domains.md) |
| Evidence and effects | Check direct and inherited conformance signatures, selected rows, missing rows, explicit satisfaction edges and static callback bounds. A trait token requires one applicable evidence binder. Transparent refinement checks selected rows against its reach and pause ceilings and retains proof obligations. Infer finite service reach, pause effects and synchronous callback entries through calls. Preserve the identity of forwarded runtime and static callback parameters. Record crash causes, typed route guards and coverage obligations. | [Conformances](../../wiki/spec/language/conformances.md) · [Effects](../../wiki/spec/language/effects.md) |
| Collection access | Select the authorized core element read, borrow or range declaration. Record the collection, endpoints, inclusive spelling, access mode, result and precondition. An indexed write requires exclusive access. A by-copy read requires a copy element. Authored bracket operations adapt the collection operand to an authorized shared or exclusive borrow and reject competing selections. | [Collection access](../../wiki/spec/language/expressions.md) · [Embedded contracts](core/collections.omg) |
| Cleanup | Select an exact machine that consumes one owned carrier and returns no value. Reject competing selections on one qualified subject and declared pause or crash behavior incompatible with cleanup. Retain the hook's complete-contract obligation. | [Domain-selected cleanup](../../wiki/spec/language/domains.md#domain-selected-automatic-cleanup) · [Consumers and cleanup](../../wiki/spec/language/ownership.md#consumers-and-cleanup) |
| Access plans and progress | Check the selected policy implementation against the Build-admitted plan requirement. Retain its domain, arguments, plan machine and evaluation obligation. Bind an explicit or canonical ranking view, type its subject, parameters and bounds, and emit the termination obligation. | [Access plans](../../wiki/spec/resources/access.md#plans-and-admitted-supply) · [Ranking](../../wiki/spec/language/termination.md#ranking) |
| Mathematical terms and assembly | Check explicit and inferred generic arguments on mathematical definitions. Apply ordinary arguments by prefix, including chained applications, and retain the selected arguments and the remaining function type. Check register bindings and instruction operands against the supplied target model. Retain the selected target and typed instruction operands. | [Mathematical bindings](../../wiki/spec/proofs/mathematical_bindings.md) · [Machines](../../wiki/spec/language/machines.md) |

L3 records source-level obligations for call preconditions, exact conversions, width positivity, domain establishment, cleanup, reference lifetime, copy and move, crash coverage and contract refinement. The later verifier owns their proofs. Execution and publication depend on those later judgments. [Layer plan](../../PLAN.md#layers)

## Verification

Run `cargo test --locked -p omega-typer --tests` from the V2 workspace. The accept and reject directories use the workspace golden runner. `OMEGA_BLESS=1` rewrites expectations within their declared verdict class. The expected files specify the typed operands and results, selections, literal landings or precise refusal. They include expressions from V1's rational argument landing, mixed-width comparison and guarded crash probes. Integration tests also inspect evidence, storage origins, normalized identities, effects and target instructions. An independent signed/unsigned endpoint oracle checks representability. Long binary, field and alias chains exercise stack use. All six permutations of a three-file package must yield the same typed product. [V1 rational probe](../../../samples/cli/probes/rational_arg_landing/main.omg) · [V1 comparison probe](../../../samples/cli/probes/cross_width_compare/main.omg) · [V1 crash guard](../../../samples/cli/facts/crash_entry_representation_view/target_body/main.omg) · [Expected fixtures](fixtures) · [Semantic tests](tests/calls.rs) · [CLI tests](../../application/tests/cli.rs)

The corpus test reads all 132 published fragments. With an empty dependency graph and no target, 35 reach L3. Of those, 28 type successfully and seven have reviewed L3 refusals. Five contain a language error. The other two omit a Boolean body or show a bodyless primitive outside its authorized package. The remaining 97 stop at the exact L2 verdict recorded for each fragment. ## Open before sign-off

- Open exact integer additions and multiplications retain their authored checks and use the fixed core normalization rules. `Buffer<N + 1>` and `Buffer<1 + N>` match, and specializing `N` to 7 yields `Buffer<8>`. Other dependent computations, including user-selected static machines, need further specialization support and the production L4 evaluator. [Evaluation](../../wiki/spec/language/evaluation.md)
- The mathematical application tests cover nondependent arrows and generic type substitution. Machine-shaped logical hypotheses, universe formation, and result types that depend on ordinary term values still need the admitted mathematical core and a typed evidence handoff to Psi. [Logical hypotheses](../../wiki/spec/proofs/mathematical_bindings.md#logical-hypotheses-and-machine-use)
- Access policies and ranking views have positive and negative tests using exact declarations supplied by a test Build. The production driver must admit the real core declarations and evaluate the access plan. The embedded catalog currently supplies the collection family. V1-style crash guards are typed as total facts over the inputs. Provider entry direction, guarded crash coverage through specialized callbacks and the proofs for cleanup, ranking and policy execution still need end-to-end coverage.
