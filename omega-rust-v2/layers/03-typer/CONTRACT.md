# L3 Typer

L3 checks the declarations and expressions in one resolved Omega stage. Its product records what each expression means, which declarations were selected and which facts later layers must establish. The command `omega source type <file> [<file> ...]` uses this library. Success is silent. A refusal identifies the package-relative file, line, column and source operation.

## Stage boundary

Supply the same admitted files and resolution result to `type_stage`. L2 owns lexical scope, visibility, candidate identity and the meaning of names. L3 indexes signatures across files before checking bodies. `type_stage_for_target` additionally takes the admitted instruction signatures and register types. `type_stage_in_environment` also accepts the exact admitted access-plan requirement and ranking views. The CLI admits the standard toolchain package. A Build can additionally supply target instructions and the directions of applied boundary slots. [Resolver contract](../02-resolver/CONTRACT.md) · [Typed product](src/model.rs)

`type_stage_with_evaluator` can obtain a closed proof-static integer from the evaluator for the current stage. L3 checks its expression, carrier and representability before returning the product. Identical normalized arguments identify the same applied type. Evaluation receipts retain the source occurrence separately. The CLI computes anonymous arithmetic and acyclic first-order integral definitions, including local bindings. Open calls retain their selected machine. L3 rechecks the original intermediate operations at specialization, including those removed by a licensed normalization. For more general computations L4 can supply a result for the selected machine and inputs or for the resolved expression under its exact substitutions. A missing closed result produces a diagnostic. | Calls | Select using typed operands and the destination's normalized result domains. Check the selected result against the destination's carrier. Retain declaration, static arguments, enclosing substitutions, evidence and acknowledgements. Reject ambiguous or duplicate normalized signatures. | [Expressions](../../wiki/spec/language/expressions.md) · [Result-domain overloads](../../wiki/spec/language/domains.md#result-domain-overloads) |
| Numbers and operators | Preserve literal suffixes. Fold wholly anonymous arithmetic as exact rationals. Check range, integrality and fractional-history acknowledgement at landing. Retain operand and result carriers, including cross-width comparisons, and the contract of each typed arithmetic operation. Preserve an explicitly selected trait or domain operator. | [Numeric values](../../wiki/spec/language/numeric_values.md) · [Operator declarations](../../wiki/spec/language/expressions.md#operator-declarations) |
| Applications | Normalize transparent aliases and closed widths. Infer type parameters and array extents structurally, retain symbolic widths, require positive widths and check multiplicity bounds. Resolve captured owner arguments for nested data and indexed domain equations. | [Generics](../../wiki/spec/language/generics.md) · [Width-indexed integers](../../wiki/spec/language/numeric_values.md) |
| Data and bindings | Refuse an unannotated binding or constant whose initializer is an unsuffixed number, such as `let count = 5;`, even when a later call would supply a type. Construct existential records from consistent witnesses and keep opened witnesses tied to their subject and version. | [Data and literals](../../wiki/spec/language/data_and_literals.md) · [Generics](../../wiki/spec/language/generics.md) |
| Patterns and places | Check arm result types, Boolean and case coverage, tuple patterns and case-field access. Preserve assignment authority, lifetime and borrow occurrences. | Domains | Normalize aliases and ancestry. Check membership against its carrier, require an explicit domain cast with complete accounting, and record establishment obligations. Preserve indexed domain arguments at calls. | [Domains](../../wiki/spec/language/domains.md) |
| Evidence and effects | Check direct and inherited conformance signatures, selected rows, missing rows, explicit satisfaction edges and static callback bounds. A trait token requires one applicable evidence binder. Transparent refinement checks selected rows against its reach and pause ceilings and retains proof obligations. Infer finite service reach, pause effects and synchronous callback entries through calls. Preserve the identity of forwarded runtime and static callback parameters. Record crash causes, typed route guards and coverage obligations. | [Conformances](../../wiki/spec/language/conformances.md) · [Effects](../../wiki/spec/language/effects.md) |
| Collection access | Select the authorized core element read, borrow or range declaration. Record the collection, endpoints, inclusive spelling, access mode, result and precondition. An indexed write requires exclusive access. A by-copy read requires a copy element. Authored bracket operations adapt the collection operand to an authorized shared or exclusive borrow and reject competing selections. | [Collection access](../../wiki/spec/language/expressions.md) · [Embedded contracts](core/collections.omg) |
| Cleanup | Select an exact machine that consumes one owned carrier and returns no value. Reject competing selections on one qualified subject and declared pause or crash behavior incompatible with cleanup. Retain the hook's complete-contract obligation. | [Domain-selected cleanup](../../wiki/spec/language/domains.md#domain-selected-automatic-cleanup) · [Consumers and cleanup](../../wiki/spec/language/ownership.md#consumers-and-cleanup) |
| Access plans and progress | Check the selected policy implementation against the Build-admitted plan requirement. Retain its domain, arguments, plan machine and evaluation obligation. Bind an explicit or canonical ranking view, type its subject, parameters and bounds, and emit the termination obligation. | [Access plans](../../wiki/spec/resources/access.md#plans-and-admitted-supply) · [Ranking](../../wiki/spec/language/termination.md#ranking) |
| Mathematical terms and assembly | Check explicit and inferred generic arguments on mathematical definitions. Apply ordinary arguments by prefix, including chained applications, and retain the selected arguments and the remaining function type. Check register bindings and instruction operands against the supplied target model. Retain the selected target and typed instruction operands. | [Mathematical bindings](../../wiki/spec/proofs/mathematical_bindings.md) · [Machines](../../wiki/spec/language/machines.md) |

L3 records source-level obligations for call preconditions, exact conversions, width positivity, domain establishment, cleanup, reference lifetime, copy and move, crash coverage and contract refinement. The later verifier owns their proofs. Execution and publication depend on those later judgments. [Layer plan](../../PLAN.md#layers)

## Verification

Run `mbx test --locked -p omega-typer --tests` from the V2 workspace. The accept and reject directories use the workspace golden runner. `OMEGA_BLESS=1` rewrites expectations within their declared verdict class. The expected files specify the typed operands and results, selections, literal landings or precise refusal. They include expressions from V1's rational argument landing, mixed-width comparison and guarded crash probes. Integration tests also inspect evidence, storage origins, normalized identities, effects and target instructions. An independent signed/unsigned endpoint oracle checks representability. Long binary, field and alias chains exercise stack use. All six permutations of a three-file package must yield the same typed product. Five contain a language error. The other two omit a Boolean body or show a bodyless primitive outside its authorized package. The remaining 94 stop at the exact L2 verdict recorded for each fragment. ## L3 handoff and cross-layer verification

- **Dependent applications.** For a closed integer index, the applied type uses the value and carrier as its key. An open index retains its typed computation. A trait-selected operator retains the evidence binder. L3 checks operand types and refuses missing or conflicting closed evaluation results. General proof-static execution and publication of the resulting identity belong to L4. [Index representation](src/index_terms.rs) · [Evaluation interface tests](tests/standard.rs) · [Evaluation spec](../../wiki/spec/language/evaluation.md)
- **Mathematical evidence.** L3 checks binders, dependent arrows, strict propositions, universe levels and machine-shaped logical hypotheses. It records premise and conclusion sites, expected evidence types, assumption dependencies and proof obligations. A named theorem or projected evidence field can supply a hypothesis. The checker must still prove the implication and discharge any assumptions. The witness theorem test checks the complete published signature and its goal. [Hypothesis checking](src/hypotheses.rs) · [Mathematical tests](tests/calls.rs) · [Mathematical bindings](../../wiki/spec/proofs/mathematical_bindings.md)
- **Policies, cleanup, ranking and callbacks.** The CLI resolves the embedded core access and ranking declarations by package identity. L3 selects the implementation and emits obligations for policy evaluation, cleanup and termination. The typed product links guarded crash routes to their operands and to calls that specialize forwarded callbacks. Build supplies provider direction for an applied slot. Execution of access plans, proof of cleanup and termination, and crash coverage in a running program need subsequent stages.
