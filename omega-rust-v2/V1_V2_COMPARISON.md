## November 22 · The same activation across a Build wait

A Build can register a dependency in one internal stage and use it in the next. The two stages belong to the same authored activation. A driver may extend the continuation’s compilation scope after preparation. The interpreter has to keep the actual stack and mutable Build alive. This follows from the shared Build contract and preserves the November 18 restriction on what the registering stage can see. It requires no new source programs or owner ruling. [Stage contract](../wiki/spec/build/scoped_execution.md#checked-build-stages) · [V2 driver plan](PLAN.md#v2s-build-model-a-chain-of-stages)

## What would establish an architectural advantage?

The measured Build matrix answers a readiness question. V1 executed the bound form and exposed a defect in the direct form. V2 stopped at package capture. There is no architectural winner for this workload yet. Give V2 a production path for the same authored program and give V1 the opportunity to repair its known defect. Record the cost of reaching parity separately from the cost of a change once both implementations work.

**The case that pressures V2 is continuity.** A helper emits a visible effect, parks inside a nested call, and can learn the type and value of an imported declaration only after the dependency is prepared. Require both compilers to accept 7, reject the wrong type before the next effect, and take the other branch for 8. Count effects. Keep an already-completed byte read in the prefix. At the checker boundary, accept a successor that changes only future work and reject one that changes that completed read from index 1 to index 0. Both indices are valid and produce different bytes. V2 can choose its internal representation; the authored program, checked result and observable effects stay fixed. [Shared execution contract](https://github.com/CathedralOS/Omega/blob/e1c9fb0255e4f5d1c53af74b37773aca6b09f5a9/wiki/spec/build/execution.md#admission-before-execution)

**The same case pressures V1 on ownership.** Move the suspended helper call from a named local into the transition subject. Add an unrelated helper with the same leaf name in another module. Verify the exact selected declaration, parked call and branch in both forms. A driver that rediscovers a call by scanning spelling has to prove it still selects the right one. Apply this change after both baselines pass; retain the baseline revision and use the same fixtures and acceptance criteria for both compilers.

Judge the follow-up by which producer already had the deciding fact, whether its consumer used that fact, which contracts had to change, and whether a direct test caught a deliberately wrong selection. Record rebuild time and existing implementation coverage independently. If both designs satisfy those checks with a local change, this experiment yields a tie. A missing entry point leaves the architectural question untested.

**V2 prerequisite checked.** With all declarations available from the start, both the named-local and direct-transition versions of a nested suspending helper passed V2 parse, resolve, type, prepare and lower. The open work starts where the dependency is unavailable until the wait. The interpreter currently admits closed policy execution, and the default package entry explicitly refuses an authored Build. This control exercised neither resumption nor the runtime effects. ## Does V1 decide too much early?

**Build must run before every dependency is known.** An authored machine can compute which dependency to request. Once it waits, the host prepares that dependency and the compiler checks the continuation against what arrived. The interpreter resumes the same activation. V1 exercises this whole path. V2’s public source commands handle packages through lowering, but the authored Build probe stops at package capture. Counting that single missing workflow as six separate stage failures would give the wrong diagnosis. [Execution rule](https://github.com/CathedralOS/Omega/blob/e1c9fb0255e4f5d1c53af74b37773aca6b09f5a9/wiki/spec/build/execution.md#admission-before-execution) · [Observed public behavior](.agents/worktree/build-continuation-evidence-1795363765717/README.md)

**The strongest concern is how V1 discovers the wait.** The Build driver walks source syntax, while normal resolution also processes suspended calls. An earlier report found that binding a suspended helper’s result and branching on the local worked, while branching directly on the same call failed. The syntax walk exists in the inspected checkout. The paired run above reproduced this failure on the checkout-built executable. [Driver source](https://github.com/CathedralOS/Omega/blob/e1c9fb0255e4f5d1c53af74b37773aca6b09f5a9/source-rust/subsystems/compiler/source-to-psi/driver/compile_build/waits/mod.rs#L318) · [Original report](https://github.com/CathedralOS/Omega/blob/e1c9fb0255e4f5d1c53af74b37773aca6b09f5a9/OWNER_CODE_CONCERNS.md#build-preparation-misses-a-suspended-helper-used-as-a-transition-subject)

**The byte-read repair gives a different result.** V1 read byte 1 of `"kit"` after a wait, but refused to resume if the same read had already run. The direct checker reproduced the public failure. One production line enabled its existing operand and storage checks. All 17 continuation tests passed, including refusal of a changed index. The rebuilt CLI passed both placements. That local source edit still caused 98 packages to compile in 66 seconds on this machine. Source ownership and rebuild cost merit separate judgments. [Before-and-after record](.agents/worktree/v1-byte-read-1795366174/README.md)

## Experiment design

Use one authored Build that does observable work, waits for a dependency inside a helper, and branches on the returned value. Compare binding that helper’s result to a local with branching directly on the call. Run each spelling with the dependency returning `i32` 7, `bool` true, and `i32` 8. Require the success path, the type error before the next effect, and the alternate branch respectively. Count prefix effects so replay cannot masquerade as success.

For each compiler record the public outcome, the first stage that distinguishes the cases, which production owners changed, any signed handoff reopened, and the focused test and rebuild times. Record an unavailable entry point explicitly. This distinguishes an investment in implementing missing capability from an investment in repairing an existing boundary.
